# Стандартный шаблон README

> Какую задачу решает этот файл: предоставляет универсальный шаблон README, который можно сразу скопировать и применить, заменив заполнители, охватывающий представление главной страницы на всём жизненном цикле проекта, с таблицей соответствия заполнителей, описанием необязательных разделов и контрольным списком самопроверки перед сдачей, чтобы любой разработчик мог быстро адаптировать его под свой проект.

## 1. Указания по использованию

1. Скопировать всё содержимое раздела 3 «Текст шаблона» и создать в корне проекта файл `README.md`.
2. Заменить заполнители `{{...}}` по одному согласно таблице соответствия заполнителей из раздела 4; неиспользуемые элементы удаляются вместе со всей строкой или всем разделом, где они находятся.
3. Подразделы раздела 3 соответствуют 20 главам [спецификации разделов README](./readme-sections-specification.md) и упорядочены по жизненному циклу «изнутри наружу»; при удалении главы следует синхронно удалить соответствующую ссылку в навигации первого экрана.
4. Согласно [спецификации бейджей](./badge-specification.md) унифицировать стиль, цвет и количество бейджей; согласно [спецификации визуальной вёрстки README](./readme-visual-layout-specification.md) проверить размещение скриншотов, таблиц и блоков кода.
5. Согласно [руководству по адаптации README к категориям](./readme-category-adaptation-guide.md) отбирать разделы по типу проекта.
6. Перед сдачей выполнить контрольный список самопроверки из раздела 6 и убедиться в отсутствии остаточных заполнителей.

## 2. Принципы настройки

- **Обязательные элементы**: название проекта, описание репозитория, позиционирование в одну фразу, установка, быстрый старт, лицензия.
- **Фиксированный порядок**: порядок разделов совпадает с [спецификацией разделов README](./readme-sections-specification.md), китайская и английская версии соответствуют друг другу поглавно.
- **Приоритет доказательств**: для ключевых особенностей, показателей производительности и инженерных компромиссов следует приводить проверяемые доказательства; качественные похвалы запрещены.
- **Прозрачное раскрытие**: неприменимые сценарии, ограничения, известные проблемы и нереализованные функции должны быть явно перечислены, скрывать их нельзя.
- **Отсутствие обязательств**: дорожная карта помечается как «не обязательство», конкретные сроки поставки не указываются.
- **Достоверность**: все команды, примеры, ссылки и бейджи должны быть реально работоспособны; контакты и каналы сообщений должны быть реально доступны.

## 3. Текст шаблона

Данный раздел организован по жизненному циклу проекта «изнутри наружу» и содержит 20 подразделов, которые взаимно однозначно соответствуют 20 главам [спецификации разделов README](./readme-sections-specification.md). Текст внутри блока кода каждого подраздела и есть готовое к копированию содержание.

Соответствие разделов и этапов жизненного цикла приведено ниже для удобной навигации:

| Этап жизненного цикла | Соответствующие подразделы | Акцент представления |
| --- | --- | --- |
| Запуск проекта | 3.1–3.2 | Позиционирование, предыстория, применимые сценарии и ограничения |
| Анализ требований | 3.2–3.3 | Границы функций, применимые сценарии, неприменимые сценарии |
| Проектирование архитектуры | 3.5–3.6, 3.11 | Инженерные компромиссы, технологический стек, структура каталогов |
| Разработка и реализация | 3.3–3.4, 3.9–3.10 | Функции, особенности, конфигурация, API |
| Тестирование и проверка | 3.8, 3.12 | Пример быстрого старта, доказательства производительности |
| Развёртывание и запуск | 3.7, 3.14 | Установка и развёртывание, матрица совместимости |
| Эксплуатация и мониторинг | 3.13, 3.15 | Безопасность и приватность, известные проблемы и ограничения |
| Итерационное сопровождение | 3.15–3.17 | Нереализованные функции, журнал изменений, дальнейшая дорожная карта |

Пояснение: README — это главная страница проекта; процессные документы каждого этапа (полные записи требований, проектирования, тестирования, развёртывания, эксплуатации) ведутся соответствующими спецификациями, см. [матрицу документации](./document-matrix.md); в данном разделе представлены только видимые пользователю выводы.

## 5. Описание необязательных разделов

В разделе 3 приведено готовое к копированию содержание 20 глав. Ниже даны дополнения о добавлении и удалении разделов по типу проекта; при удалении раздела следует синхронно удалить ссылку в навигации первого экрана.

| Раздел | Типы, для которых рекомендуется сохранять | Условия удаления |
| --- | --- | --- |
| Ключевые особенности | Все | Можно удалить при отсутствии проверяемых доказательств, замена качественным описанием не допускается |
| Детали проектирования и инженерные компромиссы | Фреймворки, приложения, сервисы | Можно удалить при отсутствии ключевых компромиссов |
| Технологический стек и перечень зависимостей | Библиотеки, фреймворки | Можно удалить при отсутствии внешних зависимостей |
| Показатели производительности | CLI, библиотеки, сервисы | Можно удалить при отсутствии данных тестирования, оценочные цифры запрещены |
| Безопасность и приватность | Сервисы, приложения, проекты, обрабатывающие персональные данные | Для чисто локальных инструментов можно сократить |
| Описание совместимости | Библиотеки, SDK, кроссплатформенные приложения | При единственной среде выполнения можно сократить |
| Журнал изменений | Все | Только при отсутствии CHANGELOG заменяется встроенной выжимкой изменений |
| Дальнейшая дорожная карта | Все | Можно удалить при отсутствии публичных планов |
| Заявление о соответствии NOTICE | Содержащие сторонние зависимости | Можно удалить при отсутствии сторонних зависимостей |

## 6. Контрольный список самопроверки перед сдачей

- [ ] Отсутствуют остаточные заполнители `{{...}}`.
- [ ] Первый экран содержит описание репозитория 【китайский | английский】 и теги, оба соответствуют метаданным репозитория.
- [ ] Китайское и английское описания репозитория не превышают 120 символов каждое.
- [ ] Теги заполнены в количестве 20, все на английском в нижнем регистре, соединены через `-`.
- [ ] Позиционирование в одну фразу содержит слово категории, китайская версия не длиннее 60 иероглифов, английская — не длиннее 25 слов.
- [ ] Каждая ключевая особенность содержит структуру из пяти частей и проверяемые доказательства.
- [ ] Преимущества и ограничения приведены раздельно, ограничения содержат область влияния и способ обхода.
- [ ] Известные проблемы содержат ссылку на отслеживание; нереализованные функции содержат причину и статус плана.
- [ ] Дорожная карта помечена как «не обязательство», конкретные сроки поставки отсутствуют.
- [ ] Неприменимые сценарии и явно не поддерживаемые позиции перечислены.
- [ ] Заголовок первого уровня единственный, уровни заголовков второго уровня непрерывны, порядок разделов совпадает с 20 главами спецификации.
- [ ] Стиль бейджей единообразен, ссылки действительны, `alt`-текст ясен.
- [ ] Команды установки и пример быстрого старта проверены на работоспособность.
- [ ] Все блоки кода имеют языковую разметку, все изображения имеют `alt`-текст.
- [ ] Относительные пути работоспособны при форке и в офлайн-режиме.
- [ ] Файл LICENSE присутствует, идентификатор SPDX совпадает с README.
- [ ] Порядок разделов китайской и английской версий соответствует друг другу.
