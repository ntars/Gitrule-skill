# Контрольная точка качества

> Какую задачу решает этот файл: определяет условия допуска трёхуровневых контрольных точек, шаблон и поля контрольного перечня решений, чтобы решение о допуске пуша было единообразным, исполнимым и проверяемым.

## 1. Три уровня контрольных точек

| Уровень | Значение | Условия допуска |
| --- | --- | --- |
| Gate A · Контрольная точка безопасности | Ключи, приватность, лицензия, большие файлы | Ноль P0 |
| Gate B · Контрольная точка качества | Сборка, тесты, lint, правила коммитов, защита ветки | Ноль P0, P1 зафиксированы как задача |
| Gate C · Контрольная точка главной страницы | README, метаданные, матрица документации, бейджи, ссылки | Ноль P0, P1 ≤ 3 и запланированы |

Только при полностью зелёных A, B и C выводится `✅ ALLOW PUSH`. Непройденные пункты должны быть исправлены или снабжены указанием причины; результат записывается в [формат отчёта о проверке](./audit-report-format.md).

## 2. 14 пунктов оценки перед сдачей

Перед сдачей документации каждый пункт оценивается отдельно; непройденные пункты должны быть исправлены или снабжены указанием причины.

| Номер | Проверяемый пункт | Критерий оценки |
| --- | --- | --- |
| G1 | Разговорные выражения и двусмысленность | Сквозной поиск разговорных слов и расплывчатых указаний даёт 0 совпадений |
| G2 | Полнота разделов | Китайская и английская версии содержат по 20 разделов в одинаковом порядке |
| G3 | Соответствие функций и каталогов | Для каждой функции, описанной в README, в структуре каталогов находится соответствующий модуль |
| G4 | Подтверждение особенностей | Каждая особенность имеет подтверждение либо помечена как «будет дополнено» |
| G5 | Охват деталей проектирования | Все 10 категорий раздела 8 имеют пункты либо отмечены как неприменимые |
| G6 | Полнота зависимостей | Число прямых и косвенных зависимостей совпадает с деревом зависимостей |
| G7 | Точность лицензии | Идентификатор SPDX каждой зависимости совпадает с официальным заявлением |
| G8 | Полный текст лицензии | Для лицензий, требующих полного текста, приложен английский оригинал |
| G9 | Уведомление об авторских правах | Уведомления об авторских правах как проекта, так и третьих сторон присутствуют полностью |
| G10 | Двуязычная синхронность | Разделы, таблицы, термины и блоки кода совпадают в обеих версиях |
| G11 | Исполнимость команд | Команды установки, быстрого старта и пуша выполняются напрямую |
| G12 | Сводка требующего подтверждения | Все пункты, требующие подтверждения, сведены, их расположение определяется |
| G13 | Источники материалов | Для всех материалов зафиксированы источник и лицензия |
| G14 | Чувствительная информация | Отсутствуют ключи, токены, внутренние адреса и персональные данные |

## 4. Определения полей

| Поле | Обязательно | Тип | Ключевые моменты заполнения | Пример |
| --- | --- | --- | --- | --- |
| Решение принял | Да | Текст | Единственное лицо, указывать «команда» запрещено | `Ван У` |
| Заключение | Да | Перечисление | PASS / FAIL / SKIP | `PASS` |
| Доказательство | Да | Текст | Путь + номер строки либо вывод команды; решение без доказательства запрещено | `gitleaks: 0 findings` |
| Уровень | Обязательно условно | Перечисление | При FAIL обязательно P0 / P1 / P2 | `P0` |
| Действие | Обязательно условно | Текст | При FAIL обязательны конкретное действие и ответственный | `ротировать ключ и очистить историю` |
| Причина SKIP | Обязательно условно | Текст | Обязательно при SKIP; пропуск без причины запрещён | `нет скрипта сборки` |
| Решение о допуске | Да | Перечисление | ALLOW PUSH / BLOCK PUSH | `BLOCK PUSH` |
| Причина блокировки | Обязательно условно | Текст | Обязательно при BLOCK; перечисляются пункты P0 | `A2: найдены ключи в истории` |

## 5. Указания по заполнению

1. **Обязательность доказательств**: каждое решение должно иметь доказательство; PASS без доказательства считается недействительным — следует заменить его на SKIP с указанием причины.
2. **Соответствие уровней**: при FAIL уровень указывается обязательно; P0 напрямую блокирует допуск, P1 требует регистрации задачи, P2 вносится в рекомендации.
3. **Порог Gate C**: PASS допускается только при P1 ≤ 3 и наличии планирования; при превышении требуется понижение уровня либо блокировка.
4. **Использование SKIP**: при невозможности проверки ставится SKIP + причина, писать PASS запрещено; проверка дополняется после появления условий.
5. **Согласованность**: решение по контрольным точкам должно соответствовать уровням P0/P1/P2 из [матрицы измерений проверки](./review-dimension-matrix.md) и правилам блокировки из [абсолютных правил](./hard-rules.md).
6. **Допуск**: только при полностью зелёных A, B и C выводится `✅ ALLOW PUSH`; при любом FAIL выводится `⛔ BLOCK PUSH` с перечислением причин блокировки.
7. **Формат сдачи**: результат решения выводится по [формату отчёта о проверке](./audit-report-format.md); после прохождения выполняется [спецификация пуша и релиза](./push-and-release-specification.md).

Типичные ошибки:

| Ошибочная формулировка | Проблема | Способ исправления |
| --- | --- | --- |
| Заключение PASS при пустом доказательстве | Решение недействительно | Дополнить доказательство или заменить на SKIP |
| `ALLOW PUSH` при ненулевом P0 | Нарушение абсолютных правил | Заменить на `BLOCK PUSH` |
| SKIP без причины | Предположительно пропущена проверка | Дополнить причину |
| Gate C при 5 пунктах P1 содержит PASS | Превышение порога | Понизить уровень или заблокировать |
| Результат решения изложен текстом без перечня | Невозможно проверить повторно | Заполнить шаблон по пунктам |

## 6. Полный пример

```markdown
# Решение по контрольным точкам: markdown-lint-cli v1.0.0

Дата решения: 2026-11-20 ｜ Решение принял: Ван У ｜ Репозиторий: example/markdown-lint-cli

## Gate A · Контрольная точка безопасности
| Номер | Проверяемый пункт | Заключение | Доказательство | Уровень | Действие |
| --- | --- | --- | --- | --- | --- |
| A1 | Ключи в рабочей области | PASS | gitleaks detect: 0 findings | — | — |
| A2 | Ключи в истории | PASS | gitleaks --log-opts=--all: 0 findings | — | — |
| A4 | Наличие и тип LICENSE | PASS | LICENSE, строка 1: MIT | — | — |
| A5 | Большие файлы и LFS | PASS | find -size +50M: нет | — | — |

Заключение: PASS, открытые пункты: нет

## Gate B · Контрольная точка качества
| Номер | Проверяемый пункт | Заключение | Доказательство | Уровень | Действие |
| --- | --- | --- | --- | --- | --- |
| B1 | Сборка проходит | PASS | run #128 | — | — |
| B2 | Тесты проходят | PASS | 132/132 passed | — | — |
| B4 | Правила сообщений коммитов | PASS | git log --oneline: все соответствуют | — | — |

Заключение: PASS, открытые пункты: нет

## Общее решение
- A: PASS ｜ B: PASS ｜ C: PASS
- Решение о допуске: ✅ ALLOW PUSH
- Причина блокировки: нет
```
