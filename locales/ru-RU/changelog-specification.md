# Спецификация журнала изменений

> Какую задачу решает этот файл: определяет шаблон, поля и правила написания ориентированной на пользователя записи об изменениях версии, чтобы каждое изменение было прослеживаемым, версии соответствовали друг другу, а путь обновления поддавался оценке.

## 1. Положения спецификации

1. Журнал изменений следует структуре Keep a Changelog, номера версий соответствуют семантическому версионированию согласно [спецификации управления версиями](./version-management-specification.md).
2. Каждая версия должна иметь дату выпуска в формате `YYYY-MM-DD`; невыпущенное содержание помещается в раздел `Unreleased`.
3. Записи группируются по шести категориям: `Added` «добавлено» / `Changed` «изменено» / `Deprecated` «устарело» / `Removed` «удалено» / `Fixed` «исправлено» / `Security` «безопасность».
4. Каждое изменение ориентировано на пользователя: указываются влияние и способ миграции; внутренние детали рефакторинга не описываются.
5. Несовместимые изменения должны помечаться `BREAKING CHANGE:` с указанием шагов миграции (см. [спецификацию руководства по миграции](./migration-guide-specification.md)).
6. Номер версии должен совпадать с тегом и Release Notes; несовместимое изменение должно соответствовать `feat!:` или `BREAKING CHANGE:` в сообщении коммита.

## 2. Шаблон журнала изменений

```markdown
# Журнал изменений

Настоящий файл фиксирует все изменения, ориентированные на пользователя. Формат основан на Keep a Changelog, версии следуют семантическому версионированию.

## [Unreleased]

### Added
- {{新增能力，说明对使用者的价值}}

### Changed
- {{行为变更，说明影响范围}}

### Deprecated
- {{即将移除的能力，说明替代方案与移除版本}}

### Removed
- {{已移除的能力，说明迁移路径}}

### Fixed
- {{缺陷修复，说明触发条件}}

### Security
- {{安全修复，说明影响与升级建议}}

## [{{X.Y.Z}}] - {{YYYY-MM-DD}}

### {{类型}}
- {{变更条目}}
- {{BREAKING CHANGE: 原行为 → 新行为；迁移步骤见链接}}

[Unreleased]: https://github.com/{{owner}}/{{repo}}/compare/v{{X.Y.Z}}...HEAD
[{{X.Y.Z}}]: https://github.com/{{owner}}/{{repo}}/compare/v{{prev}}...v{{X.Y.Z}}
```

## 3. Шаблон записи

```markdown
- {{动词开头的一句话变更描述}}（{{关联 REQ 编号}}）
  - Влияние: {{哪些使用者或场景受影响}}
  - Миграция: {{需要执行的动作；无则省略此行}}
  - Ссылка: {{Issue / PR 链接}}
```

## 4. Определение полей

| Поле | Обязательно | Тип | Ключевые моменты заполнения | Пример |
| --- | --- | --- | --- | --- |
| Номер версии | Да | `X.Y.Z` | Полностью совпадает с тегом; префикс `v` допустим, но используется единообразно по всему тексту | `1.2.0` |
| Дата выпуска | Да | `YYYY-MM-DD` | Определяется датой установки тега | `2026-11-18` |
| Тип группы | Да | Перечисление | Одна из шести категорий; при отсутствии записей категория опускается целиком | `Fixed` |
| Описание изменения | Да | Текст | Начинается с глагола, ориентировано на пользователя, отражает ценность | `добавлена проверка таблиц GFM` |
| Влияние | Условно обязательно | Текст | Обязательно при изменении поведения, устаревании, удалении и несовместимом изменении | `старый файл конфигурации требуется переименовать` |
| Миграция | Условно обязательно | Текст | Обязательно при несовместимом изменении, указывает на руководство по миграции | `см. руководство по миграции v1.0` |
| BREAKING CHANGE | Условно обязательно | Метка | Обязательно при несовместимом изменении, размещается в начале записи | `BREAKING CHANGE:` |
| Ссылка для сравнения | Да | URL | Для каждого раздела версии предоставляется ссылка compare | `compare/v1.1.0...v1.2.0` |
| Связанное REQ | Нет | Список | Упрощает сопоставление с матрицей прослеживаемости требований | `REQ-007` |

## 5. Указания по заполнению

1. **Гранулярность записей**: одно изменение описывает один наблюдаемый пользователем результат; несколько результатов разделяются на несколько записей.
2. **Начало с глагола**: используются «добавлено», «поддерживается», «исправлено», «удалено», «устарело», «скорректировано»; «обновлено», «кое-что сделано» не применяются.
3. **Запрещённое содержание**: записи без даты, внутренний рефакторинг, планы разработки, содержание дорожной карты, расплывчатые формулировки («оптимизирован опыт», «исправлен ряд проблем»).
4. **Несовместимые изменения**: одновременно требуются метка `BREAKING CHANGE:`, описание влияния, шаги миграции и ссылка на руководство по миграции; отсутствие любого из четырёх недопустимо.
5. **Устаревшие элементы**: указываются альтернативное решение и номер версии планируемого удаления, например «будет удалено в v2.0».
6. **Unreleased**: запись вносится сразу после слияния и не откладывается до дня выпуска.
7. **Согласованность**: номер версии и дата выпуска должны совпадать в трёх местах — тег, Release Notes и запись о развёртывании; при расхождении приоритет имеет тег, остальные три места исправляются.

Типичные ошибки:

| Ошибочная формулировка | Проблема | Способ исправления |
| --- | --- | --- |
| «Переработана структура внутренних модулей» | Относится к внутренним деталям, пользователь этого не замечает | Удалить или переписать в наблюдаемый эффект |
| «Исправлен ряд проблем» | Непроверяемо | Перечислить исправления по пунктам |
| Для несовместимого изменения указано только «есть изменения» | Нет пути миграции | Дополнить влиянием, шагами миграции и ссылкой на руководство |
| Номер версии не совпадает с тегом | Связь версий нарушена | Унифицировать по тегу |
| Отсутствует ссылка compare | Невозможно посмотреть различия | Добавить URL compare GitHub |

## 6. Полный пример

```markdown
## [1.0.0] - 2026-11-20

### Added
- Добавлено правило проверки пробелов между китайским и английским текстом (REQ-001), поддержан прямой вызов из командной строки.
- Добавлен вывод отчёта в формате JSON для интеграции со статистикой CI.

### Changed
- BREAKING CHANGE: имя файла конфигурации изменено с `.mdlint.json` на `.mdlintrc.json`. Старый файл больше не читается; шаги миграции см. в [руководстве по миграции](./migration-guide-specification.md).

### Deprecated
- Параметр `--format=table` будет удалён в v2.0, используйте `--reporter=table`.

### Fixed
- Исправлено ложное срабатывание при соседстве китайской пунктуации с английским словом.

### Security
- Исправлена возможность переопределения пути загрузки плагинов правил внешним вводом; всем пользователям рекомендуется обновиться до v1.0.0.

[1.0.0]: https://github.com/example/markdown-lint-cli/compare/v0.9.3...v1.0.0
```
