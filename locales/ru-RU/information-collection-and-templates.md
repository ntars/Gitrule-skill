# Сбор информации и шаблоны

> Какую задачу решает этот файл: определяет поля информации о проекте, которые необходимо собрать перед написанием документации, правила маркировки неподтверждённой информации, а также предоставляет индекс заполнителей, шаблон глоссария терминов, шаблон перечня зависимостей и готовый к копированию текст сбора информации о проекте.

## 1. Обязательные поля (отсутствие блокирует работу)

| Поле | Описание | Затрагиваемые разделы |
| --- | --- | --- |
| Название проекта | Имя репозитория и отображаемое имя; при расхождении требуется пояснение | Весь документ |
| Позиционирование в одной фразе | Не более 60 символов; указывает, что представляет собой проект и какую задачу для кого решает | Раздел 1 |
| Описание репозитория (национальный язык и английский) | Не более 120 символов на каждом языке; раздельно указываются тип проекта и основное назначение | Раздел 1 |
| Теги тем | Заполняются все 20 строчных английских слов, соединяемых через `-`; смешение регистра или неанглийские слова считаются пропуском | Раздел 1 |
| Предпосылки проекта | Причины инициации, недостатки существующих решений | Раздел 2 |
| Перечень ключевых функций | Группировка по модулям, включая наблюдаемое пользователем поведение | Раздел 3 |
| Технологический стек | Язык, фреймворк, ограничения версии среды выполнения | Раздел 6 |
| Перечень зависимостей | Название, версия, лицензия, правообладатель, адрес источника | Раздел 6, NOTICE |
| Тип лицензии | Собственная лицензия проекта, должна быть идентификатором SPDX | Раздел 19 |
| Правообладатель | Имя физического лица или полное наименование организации и год | Раздел 19, NOTICE |
| Установка и запуск | Требования к окружению, команды, ожидаемый результат | Разделы 7, 8 |

## 2. Необязательные поля

Перечень параметров конфигурации, определение API, структура каталогов, данные нагрузочного тестирования, матрица совместимости, известные проблемы, журнал изменений, дорожная карта, процесс внесения вклада, политика безопасности, скриншоты и адрес демонстрации, источники внешних материалов.

## 3. Указания по заполнению полей и примеры

| Поле | Указания по заполнению | Пример |
| --- | --- | --- |
| Название проекта | В имени репозитория используются строчные буквы, цифры и `-`; отображаемое имя может использовать брендовое написание; при расхождении указывается причина | Имя репозитория `markdown-lint-cli`, отображаемое имя `Markdown Lint CLI` |
| Позиционирование в одной фразе | Содержит категорию и уточняющие слова, без нагромождения прилагательных, не более 60 символов | `инструмент командной строки для проверки соответствия Markdown в командах технической документации` |
| Описание репозитория (национальный язык и английский) | Национальный язык и английский оформляются отдельными предложениями, каждое не более 120 символов; лозунг не заменяет описание | `Русский: инструмент командной строки для проверки структуры документов Markdown` / `English: A CLI tool for checking Markdown document structure` |
| Теги тем | Только строчные английские слова, соединяемые через `-`, всего 20, полностью покрывающие язык, форму, назначение, экосистему и сценарии | `go cli markdown linter developer-tools` |
| Технологический стек | Указываются основной язык, фреймворк и ограничения версии среды выполнения; «последняя версия» не пишется | `Go >= 1.22; Cobra v1.8.x` |
| Перечень зависимостей | Каждый пункт содержит версию, лицензию, правообладателя и официальный адрес; при неизвестном источнике ставится отметка неподтверждённого пункта | См. шаблон таблицы перечня зависимостей в приложении C |
| Тип лицензии | Используется идентификатор SPDX; расплывчатые формулировки «открытый исходный код», «свободное использование» не применяются | `MIT` |
| Установка и запуск | Приводятся текущий рабочий каталог, полная команда и проверяемый ожидаемый вывод | В корне репозитория выполнить `go install ./cmd/mdlint`, выводится номер версии |
| Неподтверждённый пункт | Используется фиксированная отметка с указанием отсутствующего содержания и ответственного за дополнение; «предварительно» не используется как замена | `【Требует подтверждения: тип лицензии зависимости foo, ответственный: Чжан Сань】` |

## 4. Правила маркировки неподтверждённой информации

1. Единый формат: `【Требует подтверждения: что конкретно отсутствует】`; расплывчатые формулировки «предварительно», «примерно», «возможно» в качестве замены не допускаются.
2. Место отметки: одно в соответствующем месте основного текста и ещё раз в перечне «Сводка пунктов, требующих подтверждения» в конце документа.
3. Неподтверждённые пункты, касающиеся лицензий, авторских прав и источников зависимостей, должны быть явно отмечены в NOTICE; пропуск всей записи не допускается.
4. Сводка пунктов, требующих подтверждения, должна содержать номер, поле, отсутствующее содержание, ответственного за дополнение и планируемый срок; записи без ответственного или срока не допускаются к этапу 0 (см. [процесс исполнения](./execution-process.md)).

## 5. Приложение A · Индекс заполнителей

`{{项目名称}}`, `{{一句话定位}}`, `{{当前版本}}`, `{{维护状态}}`, `{{许可证 SPDX}}`, `{{著作权人}}`, `{{年份}}`, `{{分支名}}`, `{{仓库地址}}`, `{{最低运行时版本}}`

Правила использования:

1. Настоящий индекс содержит только базовые поля этапа сбора; полный набор заполнителей README и их описания определяются таблицей соответствия заполнителей в [стандартном шаблоне README](./readme-standard-template.md).
2. Официальные заполнители записываются единообразно как `{{纯名}}`; вложение в фигурные скобки пояснительного текста, обратных кавычек или второго заполнителя не допускается; содержимое фигурных скобок на естественном языке в примерах спецификации не считается официальным заполнителем.
3. Поля на естественном языке в таблице сбора не используют заполнители напрямую; при генерации README они сопоставляются с соответствующими заполнителями по таблице соответствия, и в итоговом документе не должно оставаться никакого пояснительного содержимого в фигурных скобках.

## 9. Приложение D · Готовый к копированию текст сбора информации о проекте

Скопируйте приведённое ниже содержимое в файл `项目信息采集表.md` целевого проекта и последовательно замените содержимое после «Заполнить:». Поля, которые невозможно подтвердить, маркируются по правилам раздела 4 и сводятся в разделе 8.

# Таблица сбора информации о проекте

> Настоящий файл служит для однократного сбора информации, необходимой для генерации документации. После заполнения на основе собранных данных формируются README, NOTICE и другие документы поставки.

| Поле | Вводимое содержимое |

| Целевая ветка | Заполнить: имя ветки по умолчанию |

| Текущая версия | Заполнить: номер версии по семантическому версионированию или «не выпущено» |
| Состояние сопровождения | Заполнить: активное сопровождение / низкочастотное сопровождение / архивировано |
