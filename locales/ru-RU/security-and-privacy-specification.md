# Спецификация безопасности и приватности

> Какую задачу решает этот файл: определяет защиту конфиденциальной информации, перечень обработки персональных данных, шаблон SECURITY.md и поля сообщения об уязвимостях, чтобы до публикации не было утечек, обработка данных соответствовала требованиям, а канал сообщения об уязвимостях был доступен.

## 1. Нормы спецификации

1. Запрещается коммитить ключи, токены, закрытые ключи, `.env`, AK/SK облачных провайдеров, строки подключения к базам данных (соответствует абсолютному правилу H3).
2. Сканирование ключей должно охватывать рабочую область и полную историю и выполняться до пуша (см. [спецификацию пуша и релиза](./push-and-release-specification.md)).
3. Внутренние домены, IP-адреса, персональные данные и остатки в журналах должны быть удалены до публикации (соответствует измерению D1).
4. Если ключ уже был отправлен пушем, необходимо немедленно выполнить ротацию и очистку истории; ограничиваться коммитом с удалением запрещено (соответствует H12).
5. Указывается, какие данные собираются, с какой целью, где хранятся и каков срок хранения; передача и хранение шифруются, при отображении выполняется маскирование.
6. Модель прав доступа следует принципу минимальной необходимости; данные, передаваемые через границу, оцениваются отдельно.
7. Предоставляется канал сообщения об уязвимостях с прямой связью до сопровождающих, с обязательством конфиденциальности и указанием срока реагирования; известные риски описываются достоверно, абсолютная безопасность не обещается.

## 5. Определения полей

| Поле | Обязательно | Тип | Ключевые моменты заполнения | Пример |
| --- | --- | --- | --- | --- |
| Охват истории | Да | Перечисление | Для вывода о прохождении необходимо выбрать «Да» | `да` |
| Проверяемый пункт.Результат | Да | Число | Указывается число совпадений; «наверное, ничего нет» запрещено | `0` |
| Перечень ротированных ключей | Обязательно условно | Список | Обязательно при обнаружении ключей; перечисляются ротированные учётные данные | `API_KEY ротирован` |
| Элемент данных.Срок хранения | Да | Текст | Конкретная длительность; «длительно» недопустимо | `30 дней после удаления аккаунта` |
| Элемент данных.Передача третьим сторонам | Да | Текст | При отсутствии указывается «нет» | `нет` |
| Поддерживаемые версии | Да | Таблица | Явно указано, для каких версий принимаются сообщения | `2.x: да` |
| Каналы сообщения | Да | Текст | Не менее одного непубличного канала | `Security Advisories` |
| Срок реагирования | Да | Длительность | Для каждого этапа указано числовое значение | `2 рабочих дня` |

## 6. Указания по заполнению

1. **Сканирование истории**: сканирование ключей должно включать полную историю git; сканирование только рабочей области считается недействительным.
2. **Обнаружение ключа**: при обнаружении уже отправленного ключа сначала выполняется ротация, затем очистка истории; порядок не должен нарушаться (соответствует H12).
3. **Маскирование**: конфиденциальные поля в отображении и журналах должны маскироваться; полная печать токенов, номеров удостоверений и телефонов запрещена.
4. **Срок хранения**: «хранить постоянно» недопустимо; указывается явный срок или событие, запускающее удаление.
5. **Поддерживаемые версии**: перечисляется как минимум текущая мажорная версия; при отказе в поддержке старых версий это указывается явно, чтобы избежать ошибочных сообщений от пользователей.
6. **Каналы сообщения**: канал должен быть непубличным; раскрытие уязвимости в публичном Issue увеличивает риск.
7. **Известные риски**: перечисляются достоверно; формулировка «эта система абсолютно безопасна» относится к запрещённым.

Частые ошибки:

| Ошибочная формулировка | Проблема | Способ исправления |
| --- | --- | --- |
| Удалён только коммит с ключом, ротация не выполнена | Нарушение H12 | Сначала ротация, затем очистка истории |
| Самопроверка охватывает только рабочую область | Утечки в истории не обнаружены | Добавить сканирование истории |
| Срок хранения данных указан как «постоянно» | Отсутствие границ | Указать конкретный срок |
| Уязвимость сообщается в публичном Issue | Расширение поверхности раскрытия | Перейти на непубличный канал и зафиксировать его в SECURITY.md |
| Обещание «абсолютной безопасности» | Недостоверная формулировка | Заменить достоверным описанием известных рисков |

## 7. Полный пример

```markdown
## Самопроверка конфиденциальной информации: markdown-lint-cli

Дата проверки: 2026-11-18 ｜ Исполнитель: Ван У ｜ Охват истории: да

| Проверяемый пункт | Инструмент / команда | Результат | Действие |
| --- | --- | --- | --- |
| Ключи в рабочей области | gitleaks detect | 0 | нет |
| Ключи в истории коммитов | gitleaks detect --log-opts=--all | 0 | нет |
| `.env` и файлы учётных данных | git ls-files | 0 | нет |
| Внутренние домены / IP | Регулярное выражение | 0 | нет |

Вывод: пройдено
- Перечень ротированных ключей: нет
- Проверяющий: Ли Сы
```
