# Спецификация стиля кода

> Какую задачу решает этот файл: определяет шаблон конфигурации стиля кода, таблицу соглашений об именовании, правила комментариев и указания по заполнению, чтобы сократить расхождения в стиле, повысить читаемость и эффективность ревью.

## 1. Положения спецификации

1. Правила стиля определяются автоматизированными инструментами; вручную обрабатываются только те части, которые инструменты не покрывают.
2. Конфигурация форматирования должна поставляться вместе с репозиторием (например, файл конфигурации форматтера), чтобы обеспечить единообразие в разных окружениях.
3. CI должен включать проверку форматирования; при непрохождении слияние запрещено (см. [спецификацию тестов](./testing-specification.md)).
4. Запрещается использовать магические числа и жёстко закодированные константы; они должны выноситься в именованные константы.
5. Окончания строк унифицируются как LF, файл завершается переводом строки (соответствует измерению D3 «гигиена репозитория»).

## 2. Шаблон конфигурации стиля

```markdown
# Соглашение о стиле кода: {{项目名称}}

Версия конфигурации: {{v1.0}} ｜ Применимые языки и версии: {{如 TypeScript 5.x}} ｜ Инструмент форматирования: {{如 Prettier 3.x}}

## Правила форматирования (принудительно инструментом)
| Правило | Значение | Параметр конфигурации инструмента | Допускает согласование |
| --- | --- | --- | --- |
| Отступ | {{2 空格 / 4 空格 / Tab}} | {{配置项名}} | Нет |
| Ширина строки | {{100 字符}} | {{配置项名}} | Нет |
| Кавычки | {{单引号 / 双引号}} | {{配置项名}} | Нет |
| Окончание строки | LF | `endOfLine: lf` | Нет |
| Перевод строки в конце файла | Обязателен | По умолчанию инструмента | Нет |
| Точка с запятой | {{有 / 无}} | {{配置项名}} | Нет |

## Соглашения об именовании (инструмент не принуждает, проверяется вручную)
| Объект | Правило | Верный пример | Контрпример |
| --- | --- | --- | --- |
| Переменная | {{camelCase}} | `userName` | `UserName` |
| Константа | {{UPPER_SNAKE_CASE}} | `MAX_RETRY` | `maxRetry` |
| Функция | {{动词开头 camelCase}} | `parseConfig` | `configParse` |
| Класс / тип | {{PascalCase}} | `ConfigLoader` | `config_loader` |
| Имя файла | {{kebab-case}} | `config-loader.ts` | `ConfigLoader.ts` |
| Логическое значение | {{is/has/can 前缀}} | `isValid` | `valid` |
| Коллекция | {{复数名词}} | `items` | `itemList` |

## Правила комментариев
- Случаи, где комментарий обязателен: {{公开 API 的契约、非直观算法、绕开限制的临时方案}}
- Запрещённые комментарии: {{复述代码、无信息量、失效的旧注释、情绪化表述}}
- Язык комментариев: {{与项目主语言一致}}
- Формат TODO: `// TODO({{负责人}}): {{事项}} — {{计划版本}}`

## Организация файлов
1. Порядок импортов: {{标准库 → 第三方 → 本地模块，组内字典序}}
2. Порядок объявлений: {{常量 → 类型 → 函数 → 导出}}
3. Предел строк в файле: {{300 行，超出须拆分}}

## Перечень исключений
| Случай | Правило исключения | Утверждающий | Срок действия |
| --- | --- | --- | --- |
| {{如生成代码}} | {{不参与格式化}} | {{姓名}} | {{至 v2.0}} |
```

## 3. Определение полей конфигурации

| Поле | Обязательно | Тип | Ключевые моменты заполнения | Пример |
| --- | --- | --- | --- | --- |
| Версия конфигурации | Да | Текст | Увеличивается при изменении правил стиля | `v1.0` |
| Применимые языки и версии | Да | Текст | Указывается основная версия во избежание дрейфа правил | `TypeScript 5.x` |
| Инструмент форматирования | Да | Текст | Совпадает с версией в lockfile | `Prettier 3.2` |
| Правило.Значение | Да | Перечисление / число | Должно быть однозначным; «зависит от ситуации» запрещено | `2 пробела` |
| Допускает согласование | Да | Перечисление | Нет / Да; при «Да» указываются условия согласования | `Нет` |
| Верный пример именования | Да | Код | Выбирается из существующего кода проекта | `parseConfig` |
| Контрпример именования | Да | Код | Должен быть реальным и легко воспроизводимым | `configParse` |
| Ответственный за TODO | Да | Текст | Запись «команда» запрещена | `Чжан Сань` |
| Срок действия исключения | Да | Версия / дата | По истечении требуется пересмотр | `до v2.0` |

## 4. Указания по заполнению

1. **Приоритет инструментов**: все правила, которые можно принудительно обеспечить инструментом, записываются в конфигурацию форматирования, а не полагаются на память человека; вручную контролируются только именование, комментарии и организация файлов.
2. **Значение ширины строки**: устанавливается с учётом ширины интерфейса ревью, обычно 100 или 120; после определения переопределение в отдельных файлах запрещено.
3. **Верный пример именования**: выбирается из реально существующих имён в коде проекта; использование учебных заполнителей запрещено.
4. **Именование логических значений**: префиксы `is`/`has`/`can` должны соответствовать семантике; `isReady` не должен обозначать действие.
5. **TODO**: должен содержать ответственного, суть и планируемую версию; TODO без плана не допускается в основную ветку.
6. **Перечень исключений**: каждое исключение должно иметь утверждающего и срок действия; по истечении срока без пересмотра оно автоматически теряет силу.

Типичные ошибки:

| Ошибочная формулировка | Проблема | Способ исправления |
| --- | --- | --- |
| «Код должен быть максимально кратким» | Непроверяемо | Заменить проверяемым правилом, например пределом длины функции |
| В таблице именования только правила без контрпримеров | Невозможно сопоставить при ревью | Дополнить реальными типичными контрпримерами |
| Комментарий «здесь раньше был баг» | Неинформативен и быстро устаревает | Описать текущее поведение и причину |
| TODO без ответственного | Некому отслеживать | Дополнить ответственным и планируемой версией |
| Исключение без срока действия | Бессрочное освобождение | Дополнить сроком действия и проверяющим |

## 5. Полный пример

```markdown
# Соглашение о стиле кода: markdown-lint-cli

Версия конфигурации: v1.0 ｜ Применимые языки и версии: TypeScript 5.x ｜ Инструмент форматирования: Prettier 3.2

## Правила форматирования (принудительно инструментом)
| Правило | Значение | Параметр конфигурации инструмента | Допускает согласование |
| --- | --- | --- | --- |
| Отступ | 2 пробела | `tabWidth: 2` | Нет |
| Ширина строки | 100 символов | `printWidth: 100` | Нет |
| Кавычки | Одинарные | `singleQuote: true` | Нет |
| Окончание строки | LF | `endOfLine: lf` | Нет |
| Точка с запятой | Есть | `semi: true` | Нет |

## Соглашения об именовании (проверяются вручную)
| Объект | Правило | Верный пример | Контрпример |
| --- | --- | --- | --- |
| Функция | camelCase, начинающийся с глагола | `parseRules` | `rulesParser` |
| Константа | UPPER_SNAKE_CASE | `DEFAULT_RULES` | `defaultRules` |
| Имя файла | kebab-case | `rule-loader.ts` | `RuleLoader.ts` |

## Правила комментариев
- Случаи, где комментарий обязателен: семантика сопоставления правил, обход поведения вышестоящего API.
- Запрещённые комментарии: пересказ кода, «исправлен баг», TODO без ответственного.
- Формат TODO: `// TODO(Ван У): заменить временный парсер — v2.0`

## Перечень исключений
| Случай | Правило исключения | Утверждающий | Срок действия |
| --- | --- | --- | --- |
| Каталог fixtures | Не участвует в форматировании | Ли Сы | До v2.0 |
```
