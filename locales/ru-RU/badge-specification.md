# Спецификация бейджей

> Какую задачу решает этот файл: определяет синтаксис URL бейджей (Badge) в README, параметры стиля, цветовое кодирование, отбор информации, порядок расположения и контроль количества, с Shields.io в качестве основной реализации, и приводит готовые к копированию примеры формата и рекомендуемые конфигурации параметров.

Все параметры, приведённые в настоящем файле, проверены по официальной документации Shields.io (страницы Static Badge и Logos, описание формата badge-maker); данные о частоте встречаемости получены из выборочной статистики README ведущих проектов открытого исходного кода, выполненной в рамках этого проекта, и помечены как «измерено».

## 1. Основной синтаксис

### 1.1 Структура URL статического бейджа

Статический бейдж передаёт параметры через путь URL; стандартная структура выглядит так:

```text
https://img.shields.io/badge/<метка>-<сообщение>-<цвет>?style=<стиль>&<прочие параметры запроса>
```

Три сегмента пути разделяются дефисом `-`:

| Сегмент | Название | Обязателен | Пояснение |
| --- | --- | --- | --- |
| 1-й сегмент | Метка (label) | Нет | Текст слева, называет показатель |
| 2-й сегмент | Сообщение (message) | Да | Текст справа, показывает значение показателя |
| 3-й сегмент | Цвет (color) | Да | Цвет фона справа |

Двухсегментная запись (метка опускается, остаются только сообщение и цвет) также допустима:

```text
https://img.shields.io/badge/<сообщение>-<цвет>
```

### 1.2 Правила экранирования символов

Пробелы и специальные символы в пути URL должны экранироваться; правила таковы:

| Входной символ | Запись в URL | Пример |
| --- | --- | --- |
| Пробел | `_` или `%20` | `v0.1 prototype` → `v0.1%20prototype` |
| Подчёркивание `_` | `__` (двойное подчёркивание) | `my_label` → `my__label` |
| Дефис `-` | `--` (двойной дефис) | `dev-build` → `dev--build` |

Предоставленный пользователем пример прототипа соответствует этому синтаксису и может использоваться напрямую:

```markdown
![Status](https://img.shields.io/badge/status-v0.1%20prototype-8957e5?style=flat-square)
```

Его смысл: метка `status`, сообщение `v0.1 prototype` (пробел передан как `%20`), цвет `8957e5` (шестнадцатеричный фиолетовый), стиль `flat-square`.

### 1.3 Формат вставки в Markdown

```markdown
![Версия](https://img.shields.io/badge/version-1.2.0-blue?style=flat-square)
```

Если требуется переход по щелчку, изображение оборачивается ссылкой:

```markdown
[![Лицензия](https://img.shields.io/badge/license-MIT-blue.svg)](./LICENSE)
```

## 2. Параметр стиля (style)

`style` определяет общий визуальный дизайн бейджа, принимает пять значений, по умолчанию используется `flat`.

| Значение | Визуальные особенности | Сценарий применения | Измеренное число появлений (N=120) |
| --- | --- | --- | --- |
| `flat` | Прямые углы, плоский стиль, значение по умолчанию Shields.io | Универсальный первый выбор, совместим с большинством тем | 32 |
| `flat-square` | Прямые углы, без скруглений, чуть компактнее | Для аккуратной, строгой главной страницы | 60 |
| `for-the-badge` | Крупный жирный шрифт, высокий контраст | Верхний главный визуальный блок, акцентные бейджи | 65 |
| `social` | Скруглённые углы, разделение цветов слева и справа, плоский стиль | Главная страница в социальном стиле | 12 |
| `plastic` | Блики и градиент, объёмный вид | Ретро-стиль, ныне используется редко | 1 |

**Рекомендуемая конфигурация**:

- В одном README все бейджи должны иметь единый `style`; смешивание запрещено. Это первостепенное требование визуальной согласованности.
- Универсальным проектам следует предпочитать `flat` или `flat-square`; при необходимости усилить брендовую главную страницу используется единый `for-the-badge`.
- По результатам измерений наиболее популярны `for-the-badge` (65 раз) и `flat-square` (60 раз); оба могут быть выбраны по умолчанию.

Примеры формата:

```markdown
![build](https://img.shields.io/badge/build-passing-brightgreen?style=for-the-badge)
![build](https://img.shields.io/badge/build-passing-brightgreen?style=flat-square)
```

## 3. Параметр цвета (color / labelColor)

### 3.1 Три способа записи цвета

Согласно описанию badge-maker, `color` (справа) и `labelColor` (фон слева) поддерживают следующие три способа записи:

**Способ первый: именованные цвета Shields.io**

| Семантика | Именованные цвета |
| --- | --- |
| Успех | `brightgreen`, `green`, `success` |
| Подсказка | `yellow`, `yellowgreen`, `orange`, `important` |
| Предупреждение | `red`, `critical` |
| Информация | `blue`, `informational` |
| Нейтральный | `grey` / `gray`, `lightgrey` / `lightgray`, `inactive` |

Примечание: значение `labelColor` по умолчанию — `grey`, значение `color` по умолчанию — `lightgrey` (в документации также отмечено, что `inactive` входит в число цветов по умолчанию); значения некоторых именованных цветов незначительно отличаются от одноимённых цветов CSS, приоритет имеет результат отрисовки Shields.io.

**Способ второй: шестнадцатеричный цвет**

Поддерживается трёх- или шестизначный шестнадцатеричный код, префикс `#` можно опустить или сохранить:

```text
?color=8957e5
?color=007fff
?color=%23007fff    ← при сохранении # требуется кодирование как %23
```

**Способ третий: значение цвета CSS**

Поддерживаются `rgb(...)`, `rgba(...)`, `hsl(...)`, `hsla(...)` и именованные цвета CSS (например, `aqua`, `fuchsia`, `lightslategray`); при использовании требуется URL-кодирование.

### 3.2 Семантическое соответствие цветов (рекомендуемая конфигурация)

| Тип информации | Рекомендуемый цвет | Пример сообщения |
| --- | --- | --- |
| Сборка пройдена, тесты пройдены | `brightgreen` / `success` | `passing` |
| Сборка не пройдена | `red` / `critical` | `failing` |
| Стабильная версия | `blue` | `v1.2.0` |
| Предрелиз, прототип | Собственный фиолетовый `8957e5` / `orange` | `v0.1 prototype` |
| Лицензия | `blue` / `green` | `MIT` |
| Состояние документации | `yellowgreen` | `docs` |
| Устарело, поддержка прекращена | `red` / `inactive` | `deprecated` |

**Рекомендуемая конфигурация**: цвета бренда и цвета состояний фиксируются в проекте по одному набору и не меняются произвольно; одна семантика во всём репозитории передаётся одним и тем же цветовым кодом.

Примеры формата:

```markdown
![Покрытие](https://img.shields.io/badge/coverage-95%25-orange?style=flat-square)
![Статус](https://img.shields.io/badge/status-v0.1%20prototype-8957e5?style=flat-square)
![Лицензия](https://img.shields.io/badge/license-MIT-blue?style=flat-square)
```

## 4. Параметры значка (logo / logoColor / logoSize)

### 4.1 Использование Simple Icons

Параметр `logo` принимает slug значка из Simple Icons в формате `?logo=<slug>`. Часто используемые slug:

| Назначение | slug | Измеренное число появлений (N=120) |
| --- | --- | --- |
| Репозиторий GitHub | `github` | 35 |
| Сообщество Discord | `discord` | 20 |
| Пакет npm | `npm` | 4 |
| Платформы Apple | `apple` | 3 |
| Docker | `docker` | 3 |
| Социальная платформа X | `x` | 3 |
| Пакет Python | `pypi` | 2 |

Полный перечень slug определяется сайтом Simple Icons или файлом `slugs.md` репозитория simple-icons.

### 4.2 Цвет и размер значка

- `logoColor`: задаёт цвет значка Simple Icons, поддерживает шестнадцатеричный код, rgb, hsl, именованные цвета CSS; действует только для значков Simple Icons и не действует для собственных значков.
- `logoSize`: при значении `auto` значок масштабируется по содержимому, что удобно для широких значков; также действует только для Simple Icons.

Примеры формата:

```markdown
![repo](https://img.shields.io/badge/github-repo-blue?logo=github)
![цвет значка](https://img.shields.io/badge/logo-javascript-blue?logo=javascript&logoColor=f5f5f5)
```

Собственный значок можно передать через `logo=data:image/svg+xml;base64,...`, однако URL получается крайне длинным и неудобным в сопровождении, поэтому без особой необходимости это не рекомендуется.

## 5. Прочие параметры запроса

| Параметр | Назначение | Пример |
| --- | --- | --- |
| `label` | Переопределяет текст слева по умолчанию (пробелы требуют кодирования) | `?label=healthiness` |
| `labelColor` | Цвет фона слева | `?labelColor=abcdef` |
| `color` | Цвет фона справа | `?color=fedcba` |
| `cacheSeconds` | Время кэширования HTTP (в секундах); значения ниже значения по умолчанию игнорируются | `?cacheSeconds=3600` |
| `link` | Задаёт адреса перехода для левой и правой половин при щелчке | действует только внутри тега `<object>`, для изображений Markdown не действует |

## 6. Динамические бейджи

Динамические бейджи получают данные в реальном времени из внешних сервисов через Shields.io и не требуют ручного обновления значений. Часто используемые типы:

| Категория | Шаблон URL | Назначение |
| --- | --- | --- |
| Состояние сборки | `https://img.shields.io/github/actions/workflow/status/<owner>/<repo>/<workflow>` | Состояние CI |
| Версия | `https://img.shields.io/npm/v/<package>` | Последняя версия npm |
| Лицензия | `https://img.shields.io/npm/l/<package>` | Лицензия пакета |
| Число звёзд | `https://img.shields.io/github/stars/<owner>/<repo>` | Популярность |
| Число Issue | `https://img.shields.io/github/issues/<owner>/<repo>` | Открытые вопросы |
| Число загрузок | `https://img.shields.io/npm/dt/<package>` | Суммарные загрузки |

К динамическим бейджам можно добавлять параметры `?style=`, `?logo=` и другие; правила совпадают со статическими бейджами. Образцовые проекты повсеместно применяют сочетание «динамические бейджи показывают реальные показатели + статические бейджи дополняют собственными состояниями».

## 7. Отбор информации и порядок расположения

### 7.1 Отбор информации

Бейджи должны передавать «проверяемую и полезную для читателя» информацию о состоянии. Рекомендуется сохранять только следующие категории:

1. состояние сборки / тестов;
2. версия или последний релиз;
3. лицензия;
4. состояние документации;
5. каналы сообщества (Discord, обсуждения);
6. собственное состояние проекта (прототип, в сопровождении, устарело).

Не допускается размещать: число загрузок без источника, маркетинговые метки, не связанные с проектом, непроверяемые рейтинги, чисто декоративные цветные блоки.

### 7.2 Порядок расположения

Рекомендуется порядок «состояние → версия → лицензия → платформа/сообщество → собственное состояние», важность убывает слева направо. Обоснование: состояние сборки определяет, будет ли читатель использовать проект, версия определяет оценку совместимости, лицензия определяет возможность использования — все три относятся к информации, предшествующей принятию решения.

### 7.3 Контроль количества

- Обычные проекты: 4–6 бейджей.
- Сборники ресурсов или экосистемные проекты: допустимо расширить до 8–10 бейджей.
- Все бейджи размещаются после названия проекта и однострочного позиционирования, перед основным текстом, в отдельной строке или в центрированном контейнере, а не разбросаны по тексту.

### 7.4 Статический бейдж состояния поставки

Стандартной реализацией пункта 6 статьи 7.1 «собственное состояние проекта» является статический бейдж состояния поставки: значения обновляет автор проекта вручную; он применим для прогресса поставки и состояния сопровождения при отсутствии внешних источников данных:

```text
![Status](https://img.shields.io/badge/status-4%20of%204%20delivered-brightgreen?style=flat-square)
```

1. Стандартная структура — `badge/<метка>-<сообщение>-<цвет>`, стиль единообразно задаётся как `?style=flat-square`; смысл примера — «все 4 результата поставки переданы».
2. Пробелы в тексте сообщения записываются как `%20`, дефисы как `--`, подчёркивания как `__`; переносы строк и прочие неэкранированные специальные символы не допускаются.
3. Соглашение о семантике цветов: `brightgreen` означает завершено, `yellow` — в процессе, `red` — заблокировано, `lightgrey` — не начато.
4. При изменении значения бейдж и основной текст обновляются синхронно; бейдж не должен длительно отставать от фактического состояния; если синхронность гарантировать невозможно, следует перейти на динамический бейдж.
5. В тексте `alt` указывается фактический смысл, например `![Статус поставки]`; допускается ссылка на перечень результатов поставки или соответствующий раздел индекса.

## 8. Доступность и адаптация к темам

- Текст `alt` каждого бейджа должен указывать фактический смысл, например `![Статус сборки]`, а не `![badge]`.
- В тёмной и светлой темах источник изображения бейджа можно переключать через `<picture>`; использование `for-the-badge` с `labelColor=000` обеспечивает стабильный контраст в обеих темах.
- Бейдж должен вести по щелчку к соответствующему источнику данных (состояние сборки — к CI, версия — к странице пакетного менеджера, лицензия — к файлу LICENSE).
