# Спецификация многоязычности

> Какую задачу решает этот файл: определяет раскладку файлов по каталогам языковых кодов, переключение языка, согласованность переводов, согласованность кода и правила синхронизации при односторонних правках.

## 1. Раскладка каталогов

1. Файл `README.md` в корне репозитория несёт только функции главной страницы проекта и языковой навигации и не содержит текста конкретных спецификаций.
2. Конкретные спецификации размещаются плоско в каталоге `locales/<language-code>/`, например `locales/zh-CN/角色与职责.md`.
3. Языковые коды используются в стиле BCP 47, например `zh-CN`, `en-US`, `ja-JP`, `ko-KR`; языковой код встречается только в имени каталога и не пишется в имени файла.
4. **Имена файлов должны использовать сам этот язык**: в китайском каталоге — китайские имена файлов (`角色与职责.md`), в английском каталоге — английские имена в нижнем регистре через дефис (`roles-and-responsibilities.md`), аналогично для остальных языков; использовать китайские имена файлов в некитайских каталогах запрещено.
5. Имена файлов в каталогах разных языков не обязаны совпадать дословно, но должны образовывать взаимно однозначное соответствие: одна и та же спецификация в каталогах разных языков имеет одинаковую содержательную ответственность, а соответствие регистрируется в поле `paths` файла перечня (см. [спецификацию машиночитаемых метаданных](./machine-readable-metadata-specification.md)).
6. Упрощённый китайский и английский — первые завершённые версии; для остальных языков в языковой таблице корневого `README.md` указывается «будет дополнено» или «завершено», а для языков без созданного каталога пустые ссылки недопустимы.
7. При добавлении языка создаётся только каталог этого языка и выполняется постатейный перевод; существующие языковые файлы не изменяются. Остальные завершённые языки обновляются только тогда, когда правка исходного языка требует синхронизации.

## 2. Переключение языка

1. В верхней части `README.md` каждого языкового каталога должна присутствовать ссылка переключения языка.
2. Ссылки используют путь относительно текущего языкового каталога, например запись в каталоге упрощённого китайского:
   `[English](../en-US/README.md) | [简体中文](./README.md)`.
3. Текст ссылки использует самоназвание целевого языка, например `English`, `简体中文`, `日本語`; сокращения вида `CN`, `EN` не пишутся.
4. Ссылки переключения указывают только на созданные языковые каталоги; для несозданных языковых каталогов пометка даётся централизованно в языковой таблице корневого `README.md`, а в тексте битые ссылки не оставляются.

## 3. Согласованность переводов

1. Перевод должен быть полным: количество разделов, порядок разделов, число столбцов таблиц и число блоков кода совпадают с исходным языком; сокращённые или непроверенные машинные переводы недопустимы.
2. Команды, пути, имена ключей конфигурации, имена заполнителей и значения параметров внутри блоков кода остаются неизменными; переводятся только комментарии и пояснительный текст. Например, в блоке дерева каталогов `├── SKILL.md   обязательно: метаданные + основной процесс` символы ветвления и пути остаются как есть, а идущее следом описание переводится.
3. **Поля шаблонов, обращённые к пользователю, должны быть локализованы**: в конфигурации `yaml` форм Issue поля `name`, `label`, `description`, `placeholder` и варианты выпадающих списков отображаются непосредственно на веб-странице GitHub и должны переводиться на целевой язык; структурные поля `type`, `id`, `labels`, `required`, `render` и подобные остаются на английском. Критерий различения — «будет ли этот элемент показан человеку», а не «находится ли он внутри блока кода». Аналогично, текст копируемых шаблонов внутри блоков `markdown` переводится всегда.
4. Термины унифицируются по китайско-английской таблице соответствия терминов в [сборе информации и шаблонах](./information-collection-and-templates.md); один и тот же концепт во всех языках использует одну и ту же пару соответствия.
5. Любая односторонняя правка должна синхронизироваться во все завершённые языки, а в журнале обновлений фиксируются языковые коды и версии синхронизации; без завершённой синхронизации правка не считается выполненной.
6. Проверка согласованности относится к контрольной точке G10, см. [контрольную точку качества](./quality-gate.md).

## 4. Юридические тексты

1. NOTICE по умолчанию предоставляется в китайской версии; юридические тексты, касающиеся исходного текста лицензии, заявления об авторских правах и отказа от ответственности, сохраняются на английском языке без перевода и без переписывания.
2. Юридические тексты, требующие китайско-английского сопоставления, должны приводить оригинал и перевод параллельно с пометкой «перевод приводится только для справки, приоритет имеет оригинал».
3. Обработку языков юридических текстов см. в [спецификации NOTICE](./notice-specification.md) и [отказе от ответственности](./disclaimer.md).
