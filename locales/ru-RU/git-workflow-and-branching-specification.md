# Спецификация рабочего процесса Git и ветвления

> Какую задачу решает этот файл: определяет модель ветвления, правила именования, шаблон описания пул-реквеста и стратегию слияния, обеспечивая стабильность основной линии, упорядоченность совместной работы и прослеживаемость изменений.

## 1. Положения спецификации

1. Ветка по умолчанию (`main` или `master`) должна быть защищена; прямой push запрещён (соответствует абсолютному правилу H7).
2. Все изменения попадают в основную ветку через личную ветку + пул-реквест.
3. Долговременные и кратковременные ветки должны быть явно разграничены, чтобы избежать длительного неслияния веток.
4. Для публичных веток `git push --force` запрещён; для перезаписи личной ветки используется `--force-with-lease` (соответствует H8).
5. Выполнять rebase/amend для уже отправленных пушем публичных веток запрещено; перед слиянием должны быть пройдены CI и ревью кода.

## 2. Модель ветвления

| Тип ветки | Жизненный цикл | Откуда создаётся | Куда сливается | Формат имени | Пример |
| --- | --- | --- | --- | --- | --- |
| Ветка по умолчанию | Долговременная | — | — | `main` | `main` |
| Функциональная ветка | Кратковременная, ≤2 недель | `main` | `main` | `feat/<краткое описание>` | `feat/user-login` |
| Ветка исправления | Кратковременная, ≤1 недели | `main` | `main` | `fix/<краткое описание>` | `fix/token-expiry` |
| Ветка документации | Кратковременная | `main` | `main` | `docs/<краткое описание>` | `docs/api-guide` |
| Ветка релиза | Среднесрочная | `main` | `main` + tag | `release/<версия>` | `release/1.2.0` |
| Экстренное исправление | Кратковременная, ≤24 часов | тег релиза | `main` + tag | `hotfix/<краткое описание>` | `hotfix/payment-error` |

Правила именования: строчные буквы, kebab-case, краткое описание должно выражать намерение; имена `test`, `temp`, `wip`, `my-xxx` запрещены; при связи с требованием добавляется номер требования, например `feat/spacing-rule-req001`.

## 3. Шаблон описания пул-реквеста

```markdown
## Цель изменения
{{一句话说明为什么需要此变更，关联需求编号}}

## Содержание изменения
- {{具体改动 1}}
- {{具体改动 2}}

## Область влияния
- Затронутые модули: {{模块名}}
- Нарушает ли совместимость: {{是 / 否；是则给出迁移说明}}
- Затрагивает ли конфигурацию или миграцию данных: {{是 / 否；是则说明}}

## Способ проверки
- Команда самопроверки: {{命令}}
- Добавленные или изменённые тесты: {{TC 编号}}
- Адрес запуска CI: {{URL}}

## Связи
- Требование: {{REQ-NNN}}
- Матрица прослеживаемости: {{已更新 / 待更新}}
- Документация: {{docs/api.md#章节 / 无}}
- Issue: {{#编号 / 无}}

## Самопроверка
- [ ] Сообщение коммита соответствует спецификации
- [ ] Секретные сведения не включены
- [ ] Матрица прослеживаемости требований обновлена
- [ ] Несовместимые изменения внесены в журнал изменений
```

## 4. Определение полей

| Поле | Обязательно | Тип | Ключевые моменты заполнения | Пример |
| --- | --- | --- | --- | --- |
| Краткое описание ветки | Да | kebab-case | Самостоятельно выражает намерение, неинформативные слова запрещены | `spacing-rule` |
| Связанное требование | Да | `REQ-NNN` | Соответствует номеру инициации проекта | `REQ-001` |
| Цель изменения | Да | Текст | Описывает «почему», а не «что изменено» | `Исправлено ложное срабатывание на китайскую пунктуацию` |
| Область влияния | Да | Текст | Должна явно указывать, нарушается ли совместимость | `нет` |
| Команда самопроверки | Да | Команда | Готова к копированию и исполнению | `npm test -- -t spacing` |
| Номер теста | Да | `TC-NNN` | Соответствует номеру в спецификации тестов | `TC-001` |
| Адрес CI | Да | URL | Удобен для сверки ревьюером | `https://github.com/.../runs/123` |
| Чек-лист самопроверки | Да | Отметка | Отмечается по пунктам, отмечать весь список сразу запрещено | — |

## 5. Пояснения по заполнению

1. **Жизненный цикл ветки**: функциональная ветка, не слитая более 2 недель, должна быть объяснена в ретроспективе итерации и разделена или закрыта.
2. **Именование краткого описания**: из цели изменения берутся ключевое существительное + действие; расплывчатые имена вроде `fix2`, `new-feature` запрещены.
3. **Цель изменения**: описываются проблема и ценность; формулировки «обновлён код», «оптимизирована логика» недопустимы.
4. **Область влияния**: при отметке нарушения совместимости необходимо одновременно указать `BREAKING CHANGE:` в журнале изменений.
5. **Команда самопроверки**: ревьюер должен иметь возможность скопировать её и получить тот же вывод; при сложных шагах указывается путь к скрипту.
6. **Матрица прослеживаемости**: перед слиянием PR должны быть обновлены поля реализующего PR и статуса в [спецификации матрицы прослеживаемости требований](./requirements-traceability-matrix-specification.md).
7. **force push**: `--force-with-lease` применяется только к собственной ветке, не проверенной другими, и с обязательным пояснением причины в PR.

Типичные ошибки:

| Ошибочная запись | Проблема | Способ исправления |
| --- | --- | --- |
| Имя ветки `test`, `temp` | Нет информации о намерении | Заменить на `feat/<конкретная возможность>` |
| В описании PR только «исправлен баг» | Невозможно оценить влияние | Дополнить целью, влиянием, способом проверки |
| Прямой push в `main` | Нарушение H7 | Слияние через PR |
| Принудительный push после перезаписи проверенной ветки | Результаты ревью теряют силу | Добавить новый коммит в ответ на замечания |
| Исходная ветка не удаляется после слияния | Разрастание списка веток | Удалить сразу после слияния |

## 6. Полный пример

```markdown
## Цель изменения
Исправлено ложное срабатывание правила пробелов при соседстве китайской пунктуации с английскими словами (REQ-004).

## Содержание изменения
- В движок правил добавлено определение границ пунктуации
- Добавлены соответствующие регрессионные случаи

## Область влияния
- Затронутые модули: правило spacing
- Нарушает ли совместимость: нет
- Затрагивает ли конфигурацию или миграцию данных: нет

## Способ проверки
- Команда самопроверки: `npm test -- -t "中文标点"`
- Добавленные или изменённые тесты: TC-007-regression-142
- Адрес запуска CI: https://github.com/example/markdown-lint-cli/actions/runs/128

## Связи
- Требование: REQ-004
- Матрица прослеживаемости: обновлена
- Документация: отсутствует
- Issue: #142

## Самопроверка
- [x] Сообщение коммита соответствует спецификации
- [x] Секретные сведения не включены
- [x] Матрица прослеживаемости требований обновлена
- [x] Несовместимые изменения внесены в журнал изменений (данное изменение не является несовместимым)
```
