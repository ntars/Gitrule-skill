# Спецификация именования проектов

> Какую задачу решает этот файл: определяет жёсткие правила символов, регистра, разбиения на слова, длины и семантики имени репозитория, а также формулу именования, принятые суффиксы, процесс проверки и требования к сопутствующим метаданным.

## 1. Жёсткие правила

| Правило | Требование | Контрпример |
|---|---|---|
| Набор символов | Только `a-z`, `0-9`, `-` | `My_Proj`, `我的项目` |
| Регистр | Полностью строчные буквы | `MyProject` |
| Разбиение на слова | kebab-case, соединение через `-` | `myproject`, `my_project` |
| Длина | 2–25 символов | Слишком длинные склеенные имена |
| Окончание | Существительное или формообразующий суффикс в конце | Окончание на `-project`, `-test` |
| Версия | Без номера версии, года и даты | `tool-v2`, `app2024` |
| Неинформативные слова | Запрещены `my`/`demo`/`test`/`new`/`tmp` | `my-new-demo` |
| Уникальность | По одной проверке в GitHub / npm / PyPI | Совпадение с известной библиотекой |
| Семантика | Из самого имени читается «что оно делает» | `xyz`, `abc123` |

## 2. Формула именования (выбрать одну из четырёх)

```text
<技术>-<对象>          vue-virtual-table      go-ratelimit
<对象>-<形态>          note-cli   image-api   config-loader
<动词>-<对象>          parse-markdown   sync-dotfiles
<领域>-<子领域>        web-ui-kit   data-pipeline
```

## 3. Принятые суффиксы

`-cli` командная строка / `-sdk` клиентская библиотека / `-api` `-server` серверная часть / `-template` `-boilerplate` каркас проекта / `-loader` `-parser` промежуточный слой / `-kit` набор компонентов / `-notes` `-guide` документация / `dotfiles` конфигурационный репозиторий / `awesome-xxx` подборка ресурсов.

## 4. Процесс именования

1. Одним предложением записать «какую задачу проект решает и для кого».
2. Взять из этого предложения ключевое существительное и форму, применить любую формулу из раздела 2.
3. Сгенерировать 3 варианта и поочерёдно проверить каждый на совпадение имён.
4. Выбрать тот, который понятен без чтения README.
5. Китайское имя не вписывается в имя репозитория, а указывается после заголовка первой строки README.

## 5. Сопутствующие метаданные

### 5.1 Описание репозитория (description)

- Имеет тот же источник, что и имя репозитория; конструкция: `<что делает> for <для кого>`.
- Двуязычный объединённый формат: `национальный язык | английский` — сначала записывается версия на национальном языке, затем полуширинная вертикальная черта (по одному пробелу с каждой стороны), затем английская версия. Пример для китайского проекта:

```text
轻量级 Go 命令行 JSON 处理工具 | A lightweight Go CLI for JSON processing
```

- Длина: версия на национальном языке и английская версия — не более 120 символов каждая, суммарно двуязычная запись — не более 350 символов (ограничение GitHub).
- Выбор при превышении суммарного двуязычного лимита: в первую очередь сжимается английская версия, а не версия на национальном языке — информационная плотность китайского выше, и сжатие китайского теряет больше информации; при сжатии сначала удаляются модификаторы и повторяющиеся уточнения, затем объединяются синонимичные формулировки, и в последнюю очередь сохраняется целостная субъектно-предикатная структура каждой из двух языковых версий.
- Без переносов строк, синтаксиса Markdown и Emoji; стиль конечной пунктуации в обоих языках должен быть единым (либо точка ставится в обоих, либо не ставится ни в одном).

### 5.2 Темы (topics)

- Заполнить все 20 (ограничение GitHub), обеспечить полный охват, не оставлять пустых мест.
- Только английский язык; использование китайского или других языков недопустимо; всё в нижнем регистре, соединение через `-`, без пробелов и специальных символов.
- Полностью охватить пять категорий: язык, домен, форма, экосистема, сценарий; дополнительно можно добавить общие слова вроде documentation и open-source.
- Устанавливать при создании репозитория, не оставлять пустыми; один раз перепроверять после переименования или перепозиционирования репозитория.
