# Шаблон SECURITY

> Какую задачу решает этот файл: предоставляет готовый к копированию шаблон политики безопасности, по которому проект создаёт SECURITY.md и в котором определяются поддерживаемые версии, канал сообщения об уязвимостях, процесс реагирования и принципы раскрытия; сопутствующие указания по заполнению охватывают выбор канала сообщения и обработку чувствительной информации.

## 1. Указания по использованию

1. Скопировать всё содержимое раздела 3 «Текст шаблона» и создать в корне проекта файл `SECURITY.md`.
2. Заменить заполнители согласно разделу 4; канал сообщения должен быть реально доступным адресом, не раскрывающим публично поверхность атаки.
3. Урезать шаблон под сценарий согласно разделу 5: проекты без сопровождения нескольких версий удаляют строки старых версий из таблицы поддерживаемых версий.
4. Правила безопасности и требования к чувствительной информации см. в [спецификации безопасности и приватности](./security-and-privacy-specification.md); аспекты управления сообществом см. в [матрице измерений проверки](./review-dimension-matrix.md).

## 2. Принципы настройки

- **Приоритет приватного канала**: сообщения об уязвимостях идут по приватному каналу; требовать от сообщающего раскрытия подробностей в публичном обсуждении запрещено.
- **Ясные сроки**: указываются сроки первого ответа и исправления, чтобы избежать бессрочных обещаний.
- **Минимизация информации**: от сообщающего требуется минимальная информация, необходимая для воспроизведения; отправка реальных производственных данных запрещена.
- **Согласованность с правом**: принципы раскрытия должны соответствовать применимому праву и политикам платформы; в регулируемых отраслях требуется юридическая экспертиза.

## 3. Текст шаблона

```markdown
# Политика безопасности

> Данный файл описывает объём поддержки безопасности {{项目名称}} и способы сообщения об уязвимостях; он предназначен для исследователей безопасности, участников и пользователей.

## Поддерживаемые версии

| Версия | Принимаются ли сообщения о безопасности |
| --- | --- |
| {{当前版本}} | Да |
| {{上一版本}} | {{是否接受}} |
| Более ранние версии | Нет |

## Канал сообщения

Не сообщайте об уязвимостях безопасности через публичные обсуждения, форумы или социальные каналы. Используйте следующие приватные каналы:

- Почта безопасности: {{真实可达的安全邮箱}}
- Портал приватных сообщений: {{私有漏洞报告地址}}

При отсутствии указанных каналов свяжитесь с сопровождающими через {{备用私有联系方式}}.

## Содержание сообщения

Для повышения эффективности обработки следует по возможности указать:

- затронутые версии и компоненты;
- тип уязвимости и потенциальное влияние;
- минимальные шаги воспроизведения или концептуальное доказательство;
- предлагаемое направление исправления (опционально).

Не отправляйте реальные производственные данные, секреты или персональные данные.

## Процесс реагирования

| Этап | Срок | Пояснение |
| --- | --- | --- |
| Подтверждение получения | {{首次响应时限}} | Сопровождающие подтверждают получение сообщения |
| Первичная оценка | {{评估时限}} | Определяется, относится ли вопрос к безопасности, и объём влияния |
| Исправление и проверка | {{修复时限}} | Выполняется исправление и проверка; сложные вопросы согласуются отдельно |
| Публикация | Через {{发布延迟}} после исправления | Публикуются уведомление безопасности и исправленная версия |

## Принципы раскрытия

- Сопровождающие сохраняют конфиденциальность личности сообщающего и содержания сообщения до публикации исправления.
- Без согласия сопровождающих сообщающий не должен раскрывать подробности уязвимости до публикации исправления.
- После публикации исправления сопровождающие выражают благодарность сообщающему в уведомлении безопасности (с его согласия).
- Добросовестные исследования безопасности, соответствующие данной политике, не влекут ответственности.

## Исключения и отказ от ответственности

Данная политика не является обещанием каких-либо гарантий безопасности; содержание проекта предоставляется «как есть», подробнее см. в [отказе от ответственности](./DISCLAIMER.md) и [LICENSE](./LICENSE).
```

## 5. Указания по заполнению и варианты для сценариев

| Сценарий | Обязательные разделы | Разделы, которые можно урезать | Ключевые корректировки |
| --- | --- | --- | --- |
| Проект с одной версией | Канал сообщения, содержание сообщения, процесс реагирования, принципы раскрытия | Из таблицы поддерживаемых версий удаляются строки старых версий | Текущая версия указывается как `main` или последний tag |
| Сопровождение нескольких версий | Все | Нет | Построчно перечисляются версии, по которым сообщения всё ещё принимаются |
| Личный проект | Все | Таблицу поддерживаемых версий можно упростить | В качестве приватного канала используется долговременно удерживаемый почтовый ящик |
| Корпоративный проект | Все | Нет | Сроки должны соответствовать внутренним правилам безопасности и пройти юридическую экспертизу |
| Регулируемая отрасль | Все | Нет | Дополняются обязанности уведомления регулятора и требования к хранению данных |

Сопоставление типичных ошибок:

| Ошибочная формулировка | Последствие | Правильная формулировка |
| --- | --- | --- |
| «Сообщайте об уязвимостях в Issue» | Публичное раскрытие подробностей, расширение риска | Использовать приватный канал |
| «Мы обработаем как можно скорее» | Нет ясных ожиданий, сообщающий не может судить о сроках | Поэтапно указывать сроки |
| Срок сформулирован как «исправление в течение 24 часов» | Избыточное обещание, которое невозможно выполнить | Указать разумный срок и отметить, что сложные вопросы согласуются отдельно |
| Не требуется обезличивание | Сообщающий может отправить реальные производственные данные | Явно запретить отправку реальных данных и секретов |

## 6. Полный пример

Ниже приведён заполненный пример раздела о канале сообщения, служащий только образцом формата.

```markdown
## Канал сообщения

Не сообщайте об уязвимостях безопасности через публичные обсуждения, форумы или социальные каналы. Используйте следующие приватные каналы:

- Почта безопасности: security@example.com
- Портал приватных сообщений: https://github.com/example/democli/security/advisories/new

Не отправляйте реальные производственные данные, секреты или персональные данные.
```
