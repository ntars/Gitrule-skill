# Контрольный список выравнивания существующих проектов

> Какую задачу решает этот файл: при применении этого набора спецификаций к уже существующему проекту даёт контрольный список для постатейной проверки, способы оценки и критерии прохождения, охватывая шесть этапов: метаданные, именование файлов, структура разделов, двуязычная синхронизация, ссылки и пуш.

## 1. Область применения

Контрольный список применяется в двух ситуациях:

1. первичное включение существующего репозитория в управление по этому набору спецификаций;
2. регрессионная проверка уже выровненных репозиториев после обновления набора спецификаций.

Контрольный список выполняется в порядке «сначала метаданные, затем структура, в конце пуш». Если предыдущая группа не пройдена, переход к следующей не выполняется, чтобы избежать массовой перезаписи на ошибочной основе.

## 2. Проверяемые пункты

### 2.1 Метаданные (соответствует разделу 5 [спецификации именования проектов](./project-naming-specification.md))

| Номер | Проверяемый пункт | Способ оценки | Критерий прохождения |
| --- | --- | --- | --- |
| A1 | Соответствие имени репозитория | Сверка с формулой именования и правилами набора символов | Только строчные буквы, kebab-case, 2–25 символов, без номера версии и информационных слов |
| A2 | Описание в двуязычном объединённом формате | Чтение блока About репозитория или `gh repo view --json description` | `национальный язык \| английский`, по одному пробелу с каждой стороны вертикальной черты |
| A3 | Длина описания | Подсчёт символов отдельно для китайского и английского | Не более 120 символов каждое, суммарно не более 350 символов |
| A4 | Количество и язык тем | `gh repo view --json repositoryTopics` | Ровно 20, только английский, только строчные буквы, разделение дефисами |
| A5 | Охват тем | Проверка по пяти классам: язык, предметная область, форма, экосистема, сценарий | Все пять классов охвачены, нет тем, не соответствующих технологическому стеку |

Порядок действий при превышении лимитов: сначала сжимается английская версия, затем китайская; при сжатии сначала удаляются модификаторы и повторяющиеся уточнения, затем объединяются синонимичные формулировки.

### 2.2 Именование файлов (соответствует [спецификации многоязычности](./multilingual-specification.md))

| Номер | Проверяемый пункт | Способ оценки | Критерий прохождения |
| --- | --- | --- | --- |
| B1 | Именование основного README | Просмотр каталога | Для китайского — `README.md`, для английского — `README_EN.md` |
| B2 | Именование прочих языков | Просмотр каталога | `README_<языковой код в верхнем регистре>.md`, например `README_JA.md` |
| B3 | Единообразие именования | Поиск старых имён по всему репозиторию | Не осталось старых имён вроде `README.en.md`, `README.ja.md` |
| B4 | Синхронизация ссылок | Поиск старых имён файлов | Навигационные ссылки, примеры дерева каталогов и белые списки в скриптах обновлены |
| B5 | Ссылки переключения | Открытие первой строки каждой языковой версии | В каждой языковой версии из первой строки доступен переход на все остальные языки |

Переименование файлов должно выполняться через `git mv` с сохранением истории файла. Скрипты репозитория (предварительная проверка, упаковка, валидация документации) часто используют строки имён файлов как белый список; их необходимо изменить одновременно, иначе после пуша валидация завершится ошибкой.

### 2.3 Структура разделов (соответствует [спецификации разделов README](./readme-sections-specification.md))

| Номер | Проверяемый пункт | Способ оценки | Критерий прохождения |
| --- | --- | --- | --- |
| C1 | Полнота разделов | Извлечение заголовков второго уровня и сверка со списком из 20 разделов | Все 20 разделов присутствуют, отсутствующих нет |
| C2 | Именование разделов | Постатейная сверка текста заголовков | Совпадение с терминологией спецификации, без вариантов вроде «ключевые преимущества», «детали дизайна и небольшие находки» |
| C3 | Порядок разделов | Сверка по порядку появления | Совпадение с порядком в спецификации |
| C4 | Дополнительные разделы | Проверка наличия лишних разделов | Дополнительное содержимое оформляется как «приложение» после 20 разделов и не вставляется в основной порядок |
| C5 | Соответствие языковых версий | Сверка количества и порядка заголовков второго уровня в китайской и английской версиях | Однозначное взаимное соответствие двух языков |

Если в тексте встречаются названия разделов, не соответствующие спецификации, они приводятся к терминологии спецификации; при большом объёме существующего содержимого внутри раздела приоритет отдаётся переименованию, а не переписыванию текста.

### 2.4 Двуязычная синхронизация (соответствует [спецификации многоязычности](./multilingual-specification.md))

| Номер | Проверяемый пункт | Способ оценки | Критерий прохождения |
| --- | --- | --- | --- |
| D1 | Совпадение номера версии | Поиск строки версии | В обеих языковых версиях указаны одинаковые номер версии и статус |
| D2 | Совпадение чисел | Сверка числа функций, тестов, платформ | Один и тот же показатель имеет одинаковое значение в обеих версиях |
| D3 | Совпадение ссылок | Сверка набора относительных ссылок | Обе версии указывают на один и тот же набор файлов |
| D4 | Совпадение терминов | Выборочная проверка профессиональных терминов | Одно понятие передаётся в обеих версиях одним и тем же переводом |
| D5 | Совпадение структуры | Сверка количества таблиц и списков | Количество таблиц и списков внутри разделов одинаково |

После изменения фактического содержания в одной версии другая версия должна быть обновлена в том же коммите; доперевод отдельными коммитами не допускается.

### 2.5 Ссылки и содержание (соответствует [общей спецификации письма](./general-writing-specification.md))

| Номер | Проверяемый пункт | Способ оценки | Критерий прохождения |
| --- | --- | --- | --- |
| E1 | Доступность относительных ссылок | Последовательное разрешение и проверка существования файлов | Число битых ссылок равно 0 |
| E2 | Языковой идентификатор блоков кода | Поиск ограждений кода | Все блоки имеют языковой идентификатор, блоков без него нет |
| E3 | Число столбцов таблиц | Постатейная сверка разделительной и содержательных строк | Число столбцов совпадает |
| E4 | Запрещённые выражения | Поиск разговорных слов, восклицательных знаков, многоточий, эмодзи | Совпадений нет; при цитировании оригинала текст помещается в кавычки с указанием источника |
| E5 | Непроверенные данные | Поиск числовых показателей производительности | Для каждого числа указаны тестовая среда и метод тестирования |
| E6 | Обещающие формулировки | Поиск слов вроде «гарантирует», «навсегда», «полностью» | Технические ограничители допустимы, обещающие формулировки для внешней аудитории должны быть удалены |

### 2.6 Файлы сообщества и пуш (соответствует [матрице документации](./document-matrix.md), [спецификации пуша и релиза](./push-and-release-specification.md))

| Номер | Проверяемый пункт | Способ оценки | Критерий прохождения |
| --- | --- | --- | --- |
| F1 | Наличие обязательных файлов | Просмотр каталога | `LICENSE`, `NOTICE`, `CONTRIBUTING.md`, `SECURITY.md` присутствуют |
| F2 | Согласованность лицензии и NOTICE | Сверка таблицы маршрутизации по уровням | Лицензия уровня каталога согласована с заявлением в NOTICE |
| F3 | Правила игнорирования | Проверка `.gitignore` | Артефакты сборки, каталоги зависимостей, `.DS_Store`, `.workbuddy/` игнорируются |
| F4 | Сообщения коммитов | Просмотр `git log` | Соответствуют `<type>(<scope>): <subject>` |
| F5 | Согласованность с удалённым репозиторием | Сверка локального `HEAD` и `origin/main` | Они совпадают, рабочая область чиста |

## 3. Дополнительные проверки для многоязычных репозиториев

Если в репозитории три и более языковых версий, помимо перечисленных проверок добавляются три:

1. **Поязыковая сверка заголовков разделов**: заголовки 20 разделов в каждом языке должны совпадать по смыслу с китайским или английским эталоном; отсутствие раздела в каком-либо языке не допускается;
2. **Совпадение числа строк таблиц**: перечень проектов, таблица состояний, таблица параметров имеют одинаковое число строк во всех языковых версиях;
3. **Синхронизация глоссария**: таблица соответствия терминов размещается в отдельном файле, общем для двух языков, и все языковые версии ссылаются на один и тот же файл.

## 4. Частые ошибки и действия

| Ошибка | Проявление | Действие |
| --- | --- | --- |
| Ошибочное распознавание китайских числительных при массовой замене номеров разделов | «十、» распознаётся как «二十、», заголовок раздела 10 перезаписывается заголовком раздела 20 | Перейти к явной постатейной замене «старая строка → новая строка» с проверкой попадания перед записью |
| Изменён путь ссылки, но не её отображаемый текст | Ссылка работает, но в тексте остаётся старое название раздела | Поиск старого названия раздела по всему документу, одновременное обновление пути и отображаемого текста |
| Файл переименован без синхронизации скриптов | Локально документация в порядке, после пуша скрипт валидации выдаёт ошибку | Поиск всех строк имён файлов в репозитории, включая скрипты, конфигурацию и примеры в документации |
| Обновлена только одна сторона двуязычной пары | Факты в двух версиях расходятся | Ориентироваться на фактическое состояние репозитория, сначала исправить основную версию, затем в том же коммите — другую |
| Не обновлена страница индекса | Новый файл отсутствует в индексе и считается изолированным | Сразу после добавления файла обновить счётчик и запись индекса, затем перепроверить сумму счётчиков по доменам |
| Описание репозитория расходится с текстом | В блоке About указано семь проектов, в тексте — девять | Обновить описание по перечню в тексте и отметить это в сообщении коммита |

## 6. Определения полей

| Поле | Значение | Допустимые значения |
| --- | --- | --- |
| Имя репозитория | Полное имя проверяемого репозитория | `владелец/репозиторий` |
| Версия спецификации | Состояние набора спецификаций, на основании которого выполняется проверка | Номер коммита или номер версии |
| Пройдено | Пункт соответствует критерию прохождения | Логическое значение |
| Решение о допуске | Решение по результатам проверки | Пройдено / пройдено условно / заблокировано |
