# Руководство по выбору спецификаций

> Какую задачу решает этот файл: приводит основания для адаптации спецификаций по типу проекта, размеру команды и этапу релиза, предлагает минимально достаточный набор и полный набор соответствия, чтобы «выбор по потребности» имел явные критерии решения, а не зависел от личного суждения.

Настоящий файл описывает адаптацию всего набора спецификаций; различия по типам на уровне разделов README см. в [руководстве по адаптации README к категориям](./readme-category-adaptation-guide.md), полное соответствие этапам — в [таблице соответствия жизненного цикла](./lifecycle-mapping-table.md).

## 1. Принципы выбора

1. **Обязательные ограничения не подлежат адаптации**: [абсолютные правила](./hard-rules.md) и [запрещённые практики](./prohibited-practices.md) применяются в полном объёме в любом проекте и на любом этапе.
2. **Контрольные точки этапа определяют нижнюю границу**: до перехода к этапу должны быть пройдены контрольные точки выхода, отмеченные для этого этапа в [таблице соответствия жизненного цикла](./lifecycle-mapping-table.md), а соответствующие ключевые спецификации не должны быть опущены.
3. **Различия по типам влияют только на глубину**: тип проекта определяет, какие спецификации усилить и какие детали упростить, но не служит основанием для пропуска контрольных точек качества.
4. **Понижение уровня должно быть явно объявлено**: приватный репозиторий временных скриптов может исполнять только контрольные точки P0, но в поставляемых материалах должен быть объявлен «пониженный режим» с перечнем невыполненных пунктов.

## 2. Измерения адаптации

| Измерение | Значение | Основное влияние |
| --- | --- | --- |
| Тип проекта | Библиотека / SDK, приложение, инструмент командной строки, фреймворк, коллекция ресурсов | Определяет, какие спецификации усилить и какие детали можно упростить |
| Размер команды | Один человек, небольшая команда, организация | Определяет необходимость спецификаций управления и взаимодействия |
| Этап релиза | Проверка прототипа, первый публичный релиз, стабильная поддержка | Определяет момент введения спецификаций соответствия и эксплуатации |

При совмещении трёх измерений значения берутся в порядке приоритета «обязательные ограничения → контрольные точки этапа → этап релиза → тип проекта → размер команды»; адаптация измерения с низким приоритетом не должна ослаблять требования измерения с высоким приоритетом.

## 3. Адаптация по типу проекта

| Тип проекта | Следует усилить | Можно упростить | Обязательные поставляемые материалы |
| --- | --- | --- | --- |
| Библиотека / SDK | [спецификация дизайна API](./api-design-specification.md), [спецификация документации API](./api-documentation-specification.md), [спецификация управления версиями](./version-management-specification.md), [спецификация журнала изменений](./changelog-specification.md) | Развёртывание и откат, наблюдаемость (только при распространении артефактов), визуальные спецификации для скриншотов | README, документация API, LICENSE, CHANGELOG |
| Приложение | [спецификация визуальной вёрстки README](./readme-visual-layout-specification.md), [спецификация доступности](./accessibility-specification.md), [спецификация развёртывания и отката](./deployment-and-rollback-specification.md), [спецификация наблюдаемости](./observability-specification.md), [спецификация устранения неполадок](./troubleshooting-specification.md) | Документация API, проектирование базы данных (при использовании управляемых сервисов) | README, скриншоты, инструкция по развёртыванию, SECURITY |
| Инструмент командной строки | [спецификация сообщений коммитов](./commit-message-specification.md), [руководство по описанию особенностей и инженерных компромиссов](./features-and-engineering-tradeoffs-guide.md), [руководство по адаптации README к категориям](./readme-category-adaptation-guide.md), [спецификация доступности](./accessibility-specification.md) (вывод в терминал) | Проектирование базы данных, развёртывание и откат (при распространении преимущественно пакетами) | README, примеры использования, демонстрационная анимация, LICENSE |
| Фреймворк | [матрица документации](./document-matrix.md), [спецификация документации API](./api-documentation-specification.md), [спецификация руководства по участию](./contribution-guide-specification.md), [спецификация кодекса поведения](./code-of-conduct-specification.md), [спецификация наблюдаемости](./observability-specification.md) | Проектирование базы данных (при отсутствии встроенного хранилища) | README, точка входа в документацию, руководство по участию, кодекс поведения |
| Коллекция ресурсов | [матрица документации](./document-matrix.md), [шаблон руководства по участию](./contribution-guide-template.md), [спецификация многоязычности](./multilingual-specification.md), [общая спецификация письма](./general-writing-specification.md) | Тесты, развёртывание, API, база данных, наблюдаемость | README, каталог категорий, руководство по участию, LICENSE |

Проекты типа коллекции ресурсов обычно не содержат исполняемого кода, поэтому [спецификация тестов](./testing-specification.md) и [спецификация рабочих процессов CI](./ci-workflow-specification.md) могут быть отмечены как неприменимые; однако [общая спецификация письма](./general-writing-specification.md) и [спецификация доступности](./accessibility-specification.md) по-прежнему должны соблюдаться, чтобы текст ссылок и структура списков оставались пригодными к использованию.

## 4. Адаптация по размеру команды

| Размер команды | Обязательно добавить | Можно опустить |
| --- | --- | --- |
| Один человек | [абсолютные правила](./hard-rules.md), [спецификация именования проектов](./project-naming-specification.md), [стандартный шаблон README](./readme-standard-template.md), [спецификация LICENSE](./license-specification.md) | Кодекс поведения, владение кодом, ретроспектива итерации, метрики качества (можно дополнить до первого публичного релиза) |
| Небольшая команда | В дополнение к уровню одного человека: [спецификация владения кодом](./code-ownership-specification.md), [спецификация руководства по участию](./contribution-guide-specification.md), [спецификация рабочих процессов CI](./ci-workflow-specification.md), [контрольная точка качества](./quality-gate.md) | Реагирование на инциденты, наблюдаемость (можно дополнить после запуска сервиса) |
| Организация | Применяется всё; дополнительно должны быть реализованы [спецификация NOTICE](./notice-specification.md), [шаблон SECURITY](./security-template.md), [отказ от ответственности](./disclaimer.md), [спецификация реагирования на инциденты](./incident-response-specification.md), [спецификация метрик качества](./quality-metrics-specification.md), [спецификация матрицы прослеживаемости требований](./requirements-traceability-matrix-specification.md) | Нет |

При расширении команды спецификации управления должны быть дополнены до того, как репозиторий станет публично видимым, и не могут быть добавлены уже после первого релиза.

| Этап релиза | Следует ввести | Можно отложить | Требования к объявлению |

| Первый публичный релиз | В дополнение к уровню прототипа: [контрольная точка качества](./quality-gate.md), [спецификация соответствия требованиям открытого исходного кода](./open-source-compliance-specification.md), [спецификация LICENSE](./license-specification.md), [шаблон отказа от ответственности](./disclaimer-template.md), [шаблон руководства по участию](./contribution-guide-template.md), [шаблон кодекса поведения](./code-of-conduct-template.md), [шаблон SECURITY](./security-template.md), [спецификация бейджей](./badge-specification.md) | Руководство по миграции, ретроспектива итерации (можно дополнить после первой итерации версии) | Пункты контрольных точек P0 не должны быть опущены |
| Стабильная поддержка | В дополнение к уровню первого публичного релиза: [спецификация журнала изменений](./changelog-specification.md), [спецификация управления версиями](./version-management-specification.md), [спецификация руководства по миграции](./migration-guide-specification.md), [спецификация наблюдаемости](./observability-specification.md), [спецификация реагирования на инциденты](./incident-response-specification.md), [спецификация устранения неполадок](./troubleshooting-specification.md), [спецификация ретроспективы итерации](./iteration-retrospective-specification.md), [спецификация матрицы прослеживаемости требований](./requirements-traceability-matrix-specification.md) | Нет | Изменения, ломающие совместимость, должны иметь путь миграции и быть объявлены |

## 6. Комбинированные наборы

### 6.1 Минимально достаточный набор

Применяется для личного прототипа или приватного репозитория проверки, всего 10 документов:

| Назначение | Спецификации |
| --- | --- |
| Ограничения | [абсолютные правила](./hard-rules.md), [запрещённые практики](./prohibited-practices.md) |
| Инициация проекта | [спецификация инициации проекта и требований](./project-initiation-and-requirements-specification.md), [спецификация именования проектов](./project-naming-specification.md) |
| Главная страница | [стандартный шаблон README](./readme-standard-template.md), [общая спецификация письма](./general-writing-specification.md) |
| Инженерия | [спецификация стиля кода](./code-style-specification.md), [спецификация сообщений коммитов](./commit-message-specification.md), [спецификация тестов](./testing-specification.md) |
| Релиз | [спецификация пуша и релиза](./push-and-release-specification.md), [спецификация LICENSE](./license-specification.md) |

При использовании этого набора в поставляемых материалах обязательно объявляется пониженный режим, а до первого публичного релиза набор дополняется до полного состава (раздел 6.3).

### 6.2 Стандартный публичный набор

На основе минимально достаточного набора дополняются базовые пункты качества, соответствия, управления и эксплуатации: добавляются [контрольная точка качества](./quality-gate.md), [спецификация разделов README](./readme-sections-specification.md), [спецификация визуальной вёрстки README](./readme-visual-layout-specification.md), [спецификация бейджей](./badge-specification.md), [матрица документации](./document-matrix.md), [спецификация соответствия требованиям открытого исходного кода](./open-source-compliance-specification.md), [шаблон отказа от ответственности](./disclaimer-template.md), [шаблон SECURITY](./security-template.md), [шаблон руководства по участию](./contribution-guide-template.md), [шаблон кодекса поведения](./code-of-conduct-template.md), [спецификация журнала изменений](./changelog-specification.md), [спецификация управления версиями](./version-management-specification.md), [спецификация доступности](./accessibility-specification.md), [спецификация рабочих процессов CI](./ci-workflow-specification.md), [спецификация шаблонов Issue и PR](./issue-and-pr-template-specification.md), [спецификация безопасности и приватности](./security-and-privacy-specification.md).

Этот набор удовлетворяет всем условиям допуска Gate A, B и C для публичного репозитория и является рекомендуемой отправной точкой для большинства проектов.

### 6.3 Полный набор соответствия

Применяются все спецификации; используется для проектов уровня организации, проектов, распространяемых в регулируемых сценариях, либо проектов, требующих программного подключения expert / Skill / MCP / командной строки. Число документов определяется по [указателю на упрощённом китайском](./README.md); при включении следует пункт за пунктом проверять контрольные точки этапов по [таблице соответствия жизненного цикла](./lifecycle-mapping-table.md).

## 7. Обработка конфликтов

1. При конфликте внутри одного измерения приоритет имеют требования более позднего этапа релиза; упрощения этапа прототипа не должны переноситься на публичный этап.
2. При конфликте разных измерений применяется приоритет раздела 2; обязательные ограничения и контрольные точки этапов не могут быть перекрыты ни одним измерением.
3. Если проект действительно имеет особые обстоятельства и требует отступления от настоящего руководства, в поставляемых материалах должны быть зафиксированы спецификация, от которой сделано отступление, причина и компенсирующие меры, а также направлен запрос на ревью.
4. Пониженный режим не должен применяться к публичным репозиториям и не может служить основанием для пропуска контрольных точек лицензии или безопасности.
