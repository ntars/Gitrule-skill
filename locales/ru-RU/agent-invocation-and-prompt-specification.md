# Спецификация вызова агентов и промптов

> Какую задачу решает этот файл: определяет контракт распределения задач при вызове агентом набора спецификаций и правила написания промптов, обеспечивая проверяемость вызовов, отсутствие превышения полномочий и отсутствие дрейфа.

## 1. Принципы вызова

1. Единственная ответственность: один вызов выполняет только одну задачу; выполнять «заодно» другие задачи запрещено.
2. Разделение чтения и записи: подагент только читает и анализирует, запись файлов и операции git единообразно выполняет главный контроллер (см. [контракт распределения подагентов](./sub-agent-dispatch-contract.md)).
3. Требование доказательности: вывод должен сопровождаться доказательством (путь + номер строки / вывод команды); вывод без доказательств считается недействительным.
4. Отсутствие взаимодействия: подагенты не общаются друг с другом напрямую, всё сводится через главный контроллер.

## 2. Структура промпта

Промпт вызова должен содержать четыре обязательных элемента:

```text
TASK:    <一句话任务>
INPUT:   <必要上下文，只给所需部分>
OUTPUT:  <结构化输出格式，表格或 JSON，禁止散文>
FAIL:    <无法完成时的返回约定，不得瞎编>
```

## 3. Правила написания промпта

1. Используется письменная речь и побудительные предложения, информация приводится полностью и не требует догадки из контекста (см. [общую спецификацию письма](./general-writing-specification.md)).
2. Формат вывода и ответ при невозможности выполнения должны быть явно определены, чтобы исключить свободные интерпретации модели.
3. При ссылках на спецификации указывается путь к файлу (см. [спецификацию машиночитаемых метаданных](./machine-readable-metadata-specification.md)).
4. Шаблоны и заполнители используют единый формат (см. [сбор информации и шаблоны](./information-collection-and-templates.md)).

## 4. Абсолютные требования

1. Запрещено требовать от агента выдумывания результатов проверок; непроверяемые пункты помечаются SKIP + причина.
2. Запрещено переносить внутренний ход рассуждений в сдаваемые документы (см. [запрещённые практики](./prohibited-practices.md)).
3. Материалы, связанные с безопасностью, обрабатываются согласно [спецификации безопасности и приватности](./security-and-privacy-specification.md).
