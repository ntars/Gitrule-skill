# Спецификация документации API

> Какую задачу решает этот файл: определяет структуру и поля полной справочной документации API, служит основой для написания docs/api.md и строго отделена от материалов обучающего характера.

## 1. Обязательная структура

Каждый элемент API должен содержать:

| Поле | Требование |
| --- | --- |
| Сигнатура интерфейса | Метод, путь или прототип функции, полностью готовые к копированию |
| Параметры | Имя, тип, обязательность, значение по умолчанию, диапазон значений, описание |
| Возвращаемое значение | Описание типа и структуры |
| Коды ошибок | Код ошибки, условие возникновения, способ обработки |
| Пример вызова | Минимальный работоспособный пример с указанием языка |
| Ограничение частоты и квоты | Ограничение частоты вызовов, квоты, обработка превышения |

## 2. Абсолютные требования

1. Для параметров и возвращаемых значений должны быть указаны типы и ограничения; опускать значения по умолчанию не допускается.
2. Коды ошибок должны быть перечислены полностью; запись «возможна ошибка» недопустима.
3. Блоки кода должны иметь языковой идентификатор, примеры должны исполняться самостоятельно.
4. В этом файле размещается только справочная информация; учебные материалы, предыстория и описание проектных решений не пишутся (учебные материалы и предыстория — см. в [спецификации разделов README](./readme-sections-specification.md)).

## 3. Требования согласованности

Сигнатуры интерфейсов в документации API должны соответствовать фактической реализации в коде; именование параметров должно соответствовать требованиям точности из [общей спецификации письма](./general-writing-specification.md); термины см. в [глоссарии](./glossary.md).
