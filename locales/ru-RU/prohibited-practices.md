# Запрещённые практики

> Какую задачу решает этот файл: сводит воедино все недопустимые действия, формируя итоговый перечень красных линий для ревью и написания документов.

## Красные линии контроля и пуша

1. При необнулённом P0 запрещено выводить «можно сначала запушить, потом дополнить».
2. Запрещено выдумывать результаты проверок; пункты, которые невозможно проверить, помечаются `SKIP + причина`, писать PASS недопустимо.
3. Запрещено объединять несколько документов в один файл при сдаче.
4. Запрещено размещать в README полный API, руководство по вкладу и журнал изменений.
5. Запрещено использовать `--force` для пуша публичных веток — ни при каких обстоятельствах.
6. Запрещено ограничиваться «коммитом с удалением» при обработке уже утёкшего секрета.
7. Запрещено придумывать имена репозиториев в обход [спецификации именования проектов](./project-naming-specification.md).
8. Запрещено переносить внутренний ход рассуждений в сдаваемые документы.

## Красные линии написания документов

1. Не допускается выдумывать название проекта, функциональность, данные о производительности, версии зависимостей, лицензию, сведения об авторах и результаты тестов.
2. Не допускается копировать чужие README, документы, код, изображения и тексты; при действительной необходимости цитирования следует указывать источник и лицензию.
3. Не допускается выбирать тип лицензии без подтверждения.
4. Не допускаются непроверенные цифры производительности, выводы сравнений без источника, обещающие формулировки (например, «гарантируем», «бесплатно навсегда»), уничижительные описания сторонних проектов и рекламные материалы, не связанные с проектом.
5. Не допускается использовать материалы неизвестного происхождения; если у изображений, иконок и шрифтов отсутствуют источник и лицензия, следует помечать их как подлежащие подтверждению и не использовать напрямую.
