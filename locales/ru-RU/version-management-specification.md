# Спецификация управления версиями

> Какую задачу решает этот файл: определяет правила семантического версионирования, запись решения о версии, основания инкремента и связи с другими документами, чтобы номер версии выражал характер изменений, разбирался инструментами и совпадал с артефактами релиза.

## 1. Положения спецификации

1. Номер версии следует семантическому версионированию: `MAJOR.MINOR.PATCH`.
2. Номер версии не содержит год, дату или номер сборки в качестве смысловой основы; повторное использование номера выпущенной версии не допускается.
3. Несовместимые изменения должны обрабатываться централизованно при повышении мажорной версии, и должен быть указан способ миграции.
4. Номер версии совпадает с тегом, формат тега — `vMAJOR.MINOR.PATCH` (см. [спецификацию пуша и релиза](./push-and-release-specification.md)).
5. Предварительные версии используют суффиксы `-alpha`, `-beta`, `-rc`, проверка должна быть завершена до выпуска стабильной версии.

## 2. Формат номера версии и основания инкремента

| Разряд | Условие инкремента | Тип коммита-триггера | Пример |
| --- | --- | --- | --- |
| MAJOR | Несовместимое изменение | `feat!:` / `fix!:` / `BREAKING CHANGE:` | `1.9.2 → 2.0.0` |
| MINOR | Обратно совместимая новая функциональность | `feat` | `1.2.3 → 1.3.0` |
| PATCH | Обратно совместимое исправление дефекта | `fix` | `1.2.3 → 1.2.4` |

Формат предварительной версии: `vMAJOR.MINOR.PATCH-alpha.N` / `-beta.N` / `-rc.N`, номер возрастает с 1; при выпуске стабильной версии суффикс удаляется.

## 3. Шаблон записи решения о версии

```markdown
## Решение о версии: {{X.Y.Z}}

- Дата решения: {{YYYY-MM-DD}}
- Принявший решение: {{姓名}}
- Текущая версия: {{X.Y.Z}}
- Целевая версия: {{X.Y.Z}}
- Разряд инкремента: {{MAJOR / MINOR / PATCH}}
- Основание: {{列举触发的提交类型与变更内容}}

| Изменение | Тип коммита | Связанное требование | Нарушает совместимость |
| --- | --- | --- | --- |
| {{变更描述}} | {{feat / fix / BREAKING CHANGE}} | {{REQ-NNN}} | {{是 / 否}} |

- Обработка несовместимого изменения: {{迁移指南链接 / 不适用}}
- Запись в журнале изменений: {{链接}}
- Тег: {{vX.Y.Z}}
- Проверка перед выпуском: {{已通过 / 待通过}}
```

## 4. Шаблон реестра версий

```markdown
# Реестр версий: {{项目名称}}

| Версия | Дата выпуска | Тип | Основные изменения | Тег | Журнал изменений | Статус |
| --- | --- | --- | --- | --- | --- | --- |
| {{X.Y.Z}} | {{YYYY-MM-DD}} | {{主版本 / 次版本 / 修订}} | {{一句话}} | {{vX.Y.Z}} | {{链接}} | {{当前 / 历史 / 已废弃}} |
| {{X.Y.Z-rc.1}} | {{YYYY-MM-DD}} | предварительная | {{一句话}} | {{vX.Y.Z-rc.1}} | {{链接}} | заменена последующей |

Статус: текущая / архивная / устаревшая / заменена последующей
```

## 5. Определение полей

| Поле | Обязательно | Тип | Ключевые моменты заполнения | Пример |
| --- | --- | --- | --- | --- |
| Текущая версия | Да | `X.Y.Z` | Совпадает с последним тегом | `1.2.3` |
| Целевая версия | Да | `X.Y.Z` | Инкремент только одного разряда | `1.3.0` |
| Разряд инкремента | Да | Перечисление | MAJOR / MINOR / PATCH | `MINOR` |
| Основание | Да | Список | Перечисляются вызвавшие изменения, «плановая правка» запрещена | `добавлена поддержка TOML` |
| Обработка несовместимого изменения | Условно обязательно | Ссылка | Обязательно при инкременте MAJOR | `[руководство по миграции]` |
| Запись в журнале изменений | Да | Ссылка | Указывает на соответствующий раздел версии | `[1.3.0]` |
| Тег | Да | `vX.Y.Z` | Однозначно соответствует номеру версии | `v1.3.0` |
| Дата выпуска | Да | `YYYY-MM-DD` | Определяется датой установки тега | `2026-11-20` |
| Статус | Да | Перечисление | текущая / архивная / устаревшая / заменена последующей | `текущая` |

## 6. Указания по заполнению

1. **Один разряд**: при каждом выпуске повышается только один разряд; при одновременном наличии feat и BREAKING CHANGE берётся старший разряд (MAJOR), остальные изменения включаются в эту версию.
2. **Централизация несовместимых изменений**: несколько несовместимых изменений объединяются в один мажорный выпуск, чтобы избежать последовательных инкрементов MAJOR.
3. **Запрет повторного использования**: номер выпущенной версии занят навсегда; при отзыве релиза повышается PATCH и выпускается исправленная версия, исходный номер не используется повторно.
4. **Предварительные версии**: `alpha` применяется для внутренней проверки, `beta` — для публичного ознакомления, `rc` — для кандидата в релиз; каждый уровень должен проходить CI.
5. **Проверка согласованности**: номер версии должен совпадать в пяти местах — тег, журнал изменений, Release Notes, запись о развёртывании, реестр версий; при расхождении приоритет имеет тег, остальные места исправляются.
6. **Связи**: основание инкремента берётся из типов в [спецификации сообщений коммитов](./commit-message-specification.md); внешнее описание см. в [спецификации журнала изменений](./changelog-specification.md); путь обновления см. в [спецификации руководства по миграции](./migration-guide-specification.md).

Типичные ошибки:

| Ошибочная формулировка | Проблема | Способ исправления |
| --- | --- | --- |
| `v2026.11` | Дата является смысловой основой | Заменить на `v2.1.0` |
| Двойной инкремент в одной версии | Смысловая путаница | Повышать только старший разряд |
| Повторное использование отозванного номера | Невозможно различить артефакты | Повысить PATCH и выпустить исправленную версию |
| Инкремент MAJOR без руководства по миграции | Пользователь не может обновиться | Дополнить руководство по миграции и дать ссылку |
| Номер версии существует только в теге | Реестр и журнал расходятся | Синхронизировать пять мест |

## 7. Полный пример

```markdown
## Решение о версии: 2.0.0

- Дата решения: 2026-12-01
- Принявший решение: Ли Сы
- Текущая версия: 1.9.2
- Целевая версия: 2.0.0
- Разряд инкремента: MAJOR
- Основание: формат файла конфигурации изменён с объекта на путь к файлу, это несовместимое изменение.

| Изменение | Тип коммита | Связанное требование | Нарушает совместимость |
| --- | --- | --- | --- |
| Путь к файлу конфигурации | BREAKING CHANGE | REQ-021 | Да |
| Добавлен разбор TOML | feat | REQ-001 | Нет |

- Обработка несовместимого изменения: [руководство по миграции v2.0]
- Запись в журнале изменений: [2.0.0]
- Тег: v2.0.0
- Проверка перед выпуском: пройдена
```
