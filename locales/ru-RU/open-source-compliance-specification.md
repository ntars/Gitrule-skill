# Спецификация соответствия требованиям открытого исходного кода

> Какую задачу решает этот файл: определяет охват сбора сведений для соответствия требованиям открытого исходного кода, поля перечня зависимостей, методы сбора, оценку совместимости лицензий, маркировку изменений и правила использования материалов, чтобы декларации были полными и проверяемыми.

## 1. Охват сбора

Охват должен включать четыре класса источников: прямые зависимости, косвенные и транзитивные зависимости, инструментальные цепочки сборки и разработки, материалы и ресурсы (иконки, шрифты, изображения, аудио, наборы данных, источники алгоритмов).

## 2. Поля перечня зависимостей

| Поле | Требование |
| --- | --- |
| Название компонента | Совпадает с официальным репозиторием |
| Версия | Фактически зафиксированная версия, а не диапазон |
| Способ подключения | Прямая или косвенная зависимость |
| Правообладатель | Полное наименование правообладателя, заявленное официально |
| Лицензия | Идентификатор SPDX; при нескольких лицензиях указывается способ их сочетания |
| Официальный адрес | Полный URL репозитория или домашней страницы |
| Назначение в проекте | Конкретное место вызова или функция |
| Изменялся ли | Да или нет |
| Описание изменений | Изменённые файлы, содержание изменений, причина; при отсутствии изменений указывается «нет» |
| Расположение исходного текста лицензии | Путь внутри проекта или ссылка на файл |

Шаблон таблицы перечня зависимостей см. в разделе [сбор информации и шаблоны](./information-collection-and-templates.md).

## 3. Методы сбора

В зависимости от технологического стека используется соответствующая команда для построения дерева зависимостей, после чего постатейно дополняются сведения о лицензии и правообладателе: `npm ls --all`, `pip freeze`, `go mod graph`, `cargo tree`, `mvn dependency:tree`, `gradle dependencies`, `composer show --tree`. Для сканирования лицензий могут использоваться инструменты `license-checker`, `pip-licenses`, `cargo-license` и подобные; результаты сканирования подлежат ручной проверке, вывод инструментов не может служить окончательным выводом напрямую.

## 4. Совместимость лицензий

1. Необходимо оценивать совместимость лицензии проекта с лицензиями каждой зависимости, уделяя особое внимание области «заражения» GPL, AGPL, LGPL, MPL.
2. Для зависимостей под Apache-2.0 необходимо убедиться, что требования к файлу NOTICE выполнены.
3. Лицензии материалов (например, шрифты SIL OFL, семейство CC) требуют отдельной проверки требований к указанию авторства и распространению.
4. При невозможности определить совместимость ставится пометка «【Требует подтверждения: совместимость лицензий】» с пояснением причины сомнения.

## 5. Маркировка изменений в чужом коде

1. В заголовке файла сохраняются исходные заявления об авторских правах и лицензии.
2. В NOTICE указываются пути изменённых файлов, краткое содержание изменений и дата изменения.
3. В соответствующем разделе README приводится синхронное пояснение.

## 6. Цитирование и материалы

1. При цитировании чужой документации или фрагментов кода указываются адрес источника, автор и лицензия.
2. Для изображений, иконок и шрифтов фиксируются источник и лицензия; при их отсутствии ставится пометка «требует подтверждения», непосредственное использование не допускается.
3. Использовать материалы неизвестного происхождения запрещается.
