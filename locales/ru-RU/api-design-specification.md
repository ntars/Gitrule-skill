# Спецификация дизайна API

> Какую задачу решает этот файл: определяет принципы и соглашения согласованного проектирования интерфейсов, обеспечивая удобство, предсказуемость и эволюционируемость API.

## 1. Принципы проектирования

1. Единообразие именования: для однотипных ресурсов и операций применяются единые правила именования.
2. Предсказуемость: операции с одинаковой семантикой имеют одинаковую структуру.
3. Явное лучше неявного: значения по умолчанию, обязательные элементы и поведение при ошибках должны быть явными.
4. Обратная совместимость: при изменениях приоритет отдаётся сохранению совместимости, несовместимые изменения должны версионироваться (см. [спецификацию управления версиями](./version-management-specification.md)).

## 2. Обязательные соглашения

1. **Именование**: правила именования ресурсов, методов и полей.
2. **Параметры**: тип, обязательность, значение по умолчанию, диапазон значений.
3. **Ошибки**: единая структура ошибок, коды ошибок, статусы HTTP или эквивалентный механизм.
4. **Пагинация и фильтрация**: соглашения о пагинации, сортировке и фильтрации для сценариев с большим объёмом данных.
5. **Идемпотентность**: гарантии идемпотентности операций записи.
6. **Ограничение частоты и квоты**: ограничения частоты и ответ при превышении.
7. **Версии**: стратегия версионирования API и способ эволюции.

## 3. Абсолютные требования

1. Ответ с ошибкой должен содержать локализуемый код ошибки и пояснение и не должен раскрывать детали внутренней реализации.
2. Несовместимые изменения должны сопровождаться повышением версии и периодом миграции (см. [спецификацию журнала изменений](./changelog-specification.md)).
3. Интерфейс должен иметь соответствующую документацию с полным набором полей (см. [спецификацию документации API](./api-documentation-specification.md)).
