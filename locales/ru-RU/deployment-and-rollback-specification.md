# Спецификация развёртывания и отката

> Какую задачу решает этот файл: определяет шаблоны, поля и критерии выполнения для контрольного списка развёртывания, заявки на изменение и плана отката, чтобы выпуск был управляемым, статус — проверяемым, а сбой — быстро устранимым.

## 1. Положения спецификации

1. Перед развёртыванием должны быть пройдены CI, ревью кода и контрольная точка качества (см. [контрольную точку качества](./quality-gate.md)).
2. Развёртывание выполняется на основе выпущенной версии с проставленным тегом; коммиты без тега не используются (см. [спецификацию управления версиями](./version-management-specification.md)).
3. Конфигурация окружения отделена от кода; чувствительная конфигурация внедряется через систему управления конфигурацией и не попадает в репозиторий (см. [спецификацию безопасности и приватности](./security-and-privacy-specification.md)).
4. Изменения структуры базы данных выполняются через скрипты миграции и должны быть обратно совместимыми (см. [спецификацию проектирования баз данных](./database-design-specification.md)).
5. Каждое развёртывание должно фиксировать номер версии, время, исполнителя и содержание изменений; развёртывание без записи считается несоответствующим требованиям.
6. Для каждой версии должен быть заранее подготовлен план отката; без подготовленного плана отката выпуск не допускается.
7. После развёртывания должны быть выполнены проверка работоспособности и дымовая проверка; релиз завершается только при успешном прохождении обеих.

## 2. Шаблон контрольного списка развёртывания

```markdown
# Контрольный список развёртывания: {{项目名称}} {{版本号}}

Версия: {{vX.Y.Z}} ｜ тег: {{vX.Y.Z}} ｜ Целевое окружение: {{预发布 / 生产}} ｜ Плановое время: {{YYYY-MM-DD HH:MM}}

## Предварительные проверки
- [ ] CI зелёный, адрес запуска рабочего процесса: {{URL}}
- [ ] Ревью кода пройдено, утверждающий: {{姓名}}
- [ ] Контрольные точки качества A/B/C все PASS
- [ ] Журнал изменений и Release Notes готовы
- [ ] План отката отревьюирован, см. конец настоящего раздела
- [ ] Скрипт миграции базы данных отревьюирован и обратно совместим
- [ ] Перечень изменений конфигурации подтверждён (внедряемые элементы, не попадающие в репозиторий)

## Содержание изменений
| Изменение | Тип | Область влияния | Связанное требование | Способ проверки |
| --- | --- | --- | --- | --- |
| {{功能 / 配置 / 数据迁移}} | {{新增 / 修改 / 移除}} | {{受影响模块}} | {{REQ-NNN}} | {{如何确认}} |

## Порядок выполнения
1. {{步骤，含具体命令或平台操作}}
2. {{灰度比例与观察时长}}
3. {{全量放量条件}}

## Проверка работоспособности и дымовая проверка
| Проверка | Условие | Способ выполнения | Результат |
| --- | --- | --- | --- |
| Доступность сервиса | {{HTTP 200}} | {{命令}} | {{通过 / 未通过}} |
| Ключевой сценарий | {{主流程完成}} | {{命令}} | {{通过 / 未通过}} |
| Доля ошибок | {{< X%}} | {{监控面板}} | {{通过 / 未通过}} |

## Запись о развёртывании
| Пункт | Значение |
| --- | --- |
| Фактическое время развёртывания | {{YYYY-MM-DD HH:MM}} |
| Исполнитель | {{姓名}} |
| Утверждающий | {{姓名}} |
| Фактический номер версии | {{vX.Y.Z}} |
| Результат | {{成功 / 回滚 / 中止}} |

## План отката
- Целевая версия отката: {{vX.Y.Z}}
- Условие запуска: {{错误率 > X% 持续 N 分钟 / 冒烟失败 / 数据异常}}
- Принимающий решение: {{姓名}}
- Порядок отката: {{具体命令或操作}}
- Совместимость данных: {{是否需要数据回滚；如果需要，说明方式}}
```

## 3. Шаблон записи о развёртывании

```markdown
## {{YYYY-MM-DD}} {{vX.Y.Z}} → {{环境}}

- Номер версии: {{vX.Y.Z}}
- тег: {{vX.Y.Z}}
- Время: {{HH:MM}}
- Исполнитель / утверждающий: {{姓名 / 姓名}}
- Краткое описание изменений: {{一句话}}
- Проверка работоспособности: {{通过 / 未通过}}
- Результат: {{成功 / 回滚}}
- Связанный релиз: {{Release Notes URL}}
- Примечание: {{异常与处理记录；无则写「无」}}
```

## 4. Определение полей

| Поле | Обязательно | Тип | Ключевые моменты заполнения | Пример |
| --- | --- | --- | --- | --- |
| тег | Да | Текст | Полностью совпадает с тегом по [спецификации управления версиями](./version-management-specification.md) | `v1.2.0` |
| Целевое окружение | Да | Перечисление | Предварительное / продуктивное, смешивать конфигурации запрещено | `продуктивное` |
| Изменение. Тип | Да | Перечисление | Добавление / изменение / удаление | `изменение` |
| Связанное требование | Да | Список | Номер REQ, при отсутствии требований указывается «нет» | `REQ-007` |
| Доля постепенного выпуска | Нет | Процент | Обязательно при поэтапном расширении | `10% → 50% → 100%` |
| Условие | Да | Порог | Наблюдаемое, проверяемое | `HTTP 200` |
| Фактический номер версии | Да | Текст | При отличии от планового требуется указать причину | `v1.2.1` |
| Условие запуска отката | Да | Порог + длительность | Формулировки вроде «ощущение сбоя» запрещены | `доля ошибок >1% в течение 5 минут` |
| Совместимость данных | Да | Текст | Явно указывается необходимость отката данных | `откат данных не требуется` |

## 5. Указания по заполнению

1. **Предварительные проверки**: отметки ставятся по каждому пункту; проставлять весь блок сразу запрещено; при незавершённости любого пункта развёртывание прекращается.
2. **Содержание изменений**: каждая строка должна быть связана с номером REQ; для чисто эксплуатационных изменений без требования указывается «нет» и обоснование изменения.
3. **Проверка работоспособности**: условия должны допускать автоматическую проверку; формулировка «сервис выглядит нормально» не принимается.
4. **Условие запуска отката**: должны быть указаны одновременно порог и длительность, чтобы избежать ложного срабатывания при кратковременных колебаниях.
5. **Поэтапный выпуск**: после каждого этапа требуется наблюдение в течение установленного времени и фиксация вывода, после чего допускается переход к следующему этапу.
6. **Запись о развёртывании**: записи добавляются в хронологическом порядке без перезаписи истории; номер версии совпадает с пушем, тегом и Release Notes.
7. **Выполнение отката**: откат кода выполняется через `git revert` с созданием обратного коммита; принудительный пуш в опубликованную историю не допускается (см. [спецификацию пуша и релиза](./push-and-release-specification.md)).

Типичные ошибки:

| Ошибочная формулировка | Проблема | Способ исправления |
| --- | --- | --- |
| Развёртывание из коммита без тега | Версию невозможно воспроизвести | Сначала проставить тег, затем развернуть |
| В плане отката указано «при проблемах откатиться» | Нет условий запуска и шагов | Дополнить порогом, принимающим решение, шагами |
| Изменение базы данных несовместимо со старой версией | После отката данные недоступны | Применить трёхшаговый метод «расширение — миграция — сжатие» |
| Запись о развёртывании сделана задним числом | Статус недостоверен | Фиксировать непосредственно в момент развёртывания |
| Проверка работоспособности ограничена главной страницей | Ключевой сценарий не проверен | Дополнить дымовыми тестами основного процесса |

## 6. Полный пример

```markdown
# Контрольный список развёртывания: markdown-lint-cli v1.0.0

Версия: v1.0.0 ｜ тег: v1.0.0 ｜ Целевое окружение: продуктивное ｜ Плановое время: 2026-11-20 10:00

## Предварительные проверки
- [x] CI зелёный: https://github.com/example/markdown-lint-cli/actions/runs/123
- [x] Ревью кода пройдено, утверждающий: Ли Сы
- [x] Контрольные точки качества A/B/C все PASS
- [x] Журнал изменений и Release Notes готовы
- [x] План отката отревьюирован
- [x] Миграция базы данных отсутствует
- [x] Перечень изменений конфигурации подтверждён: нет

## Содержание изменений
| Изменение | Тип | Область влияния | Связанное требование | Способ проверки |
| --- | --- | --- | --- | --- |
| Правило пробелов между китайским и английским текстом | Добавление | Движок правил | REQ-001 | Выполнить TC-001 |
| Вывод отчёта CLI | Изменение | Модуль отчётов | REQ-007 | Выполнить TC-012 |

## Порядок выполнения
1. Получить тег v1.0.0 и проверить контрольную сумму
2. Поэтапный выпуск 10%, наблюдение 10 минут
3. После снижения доли ошибок ниже 0.1% расширить до 100%

## Проверка работоспособности и дымовая проверка
| Проверка | Условие | Способ выполнения | Результат |
| --- | --- | --- | --- |
| Доступность сервиса | HTTP 200 | curl /healthz | Пройдено |
| Ключевой сценарий | Проверка 50 документов завершена | shell-скрипт | Пройдено |
| Доля ошибок | <0.1% | Панель мониторинга | Пройдено |

## План отката
- Целевая версия отката: v0.9.3
- Условие запуска: доля ошибок >1% в течение 5 минут
- Принимающий решение: Ли Сы
- Порядок отката: переключить метку развёртывания на v0.9.3 и выполнить проверку совместимости данных
- Совместимость данных: изменений базы данных нет, откат данных не требуется
```
