# Спецификация доступности

> Какую задачу решает этот файл: определяет требования к доступности документации проекта, README и пользовательского интерфейса, чтобы материалы были одинаково пригодны для читателей, использующих программы экранного доступа, управление с клавиатуры и имеющих различные зрительные возможности.

## 1. Область применения

1. Доступность документации: README, сайт документации, примеры кода, таблицы, изображения.
2. Доступность интерфейса: пользовательский интерфейс приложений и веб-проектов.
3. Доступность командной строки: текст справки, сообщения об ошибках и формат вывода.

## 2. Доступность документации

### 2.1 Изображения и медиаматериалы

1. Каждое изображение должно иметь текст `alt`, описывающий содержание и назначение изображения; для декоративных изображений используется пустой `alt`.
2. Не допускается использовать в качестве `alt` неинформативный текст вроде «изображение», «скриншот», «image».
3. Для GIF-анимации содержание должно поясняться в соседнем тексте; передавать информацию только через анимацию не допускается.
4. Диаграммы должны сопровождаться текстовым описанием или таблицей данных; различать серии данных только цветом не допускается.

### 2.2 Заголовки и структура

1. Уровни заголовков идут последовательно, пропуск уровней не допускается (см. [спецификацию визуальной вёрстки README](./readme-visual-layout-specification.md)).
2. В документе допускается только один заголовок первого уровня.
3. Списки оформляются корректным синтаксисом Markdown, чтобы программа экранного доступа распознавала их как списки.
4. Таблицы должны иметь строку заголовка; использовать таблицы без заголовка для вёрстки страницы не допускается.

### 2.3 Ссылки и текст

1. Текст ссылки должен быть понятен сам по себе; использовать «нажмите здесь», «подробнее» запрещено.
2. Цвет не должен быть единственным средством передачи информации — он должен дополняться текстом или значком.
3. При смешанном наборе кириллицы и латиницы пробелы сохраняются, чтобы обеспечивать правильный перенос слов и корректное озвучивание.
4. При первом появлении аббревиатуры приводится её полная форма.

### 2.4 Код и таблицы

1. Блоки кода снабжаются языковым идентификатором для распознавания вспомогательными инструментами (см. [спецификацию визуальной вёрстки README](./readme-visual-layout-specification.md)).
2. Содержимое ячеек таблицы должно быть кратким; объединение ячеек по строкам затрудняет разбор программой экранного доступа.
3. Для длинных команд приводится запись с переносами строк, не рассчитанная на горизонтальную прокрутку.

## 3. Доступность интерфейса

### 3.1 Управление с клавиатуры

1. Все интерактивные элементы должны быть достижимы и управляемы с клавиатуры.
2. Порядок фокуса совпадает с визуальным порядком, состояние фокуса отчётливо видно.
3. Предусматривается быстрый переход к пропуску повторяющегося содержимого (например, переход к основному содержимому).

### 3.2 Семантика и подписи

1. Для выражения структуры и ролей используются семантические теги; имитировать элементы управления несемантическими элементами не допускается.
2. Элементы формы должны иметь связанные подписи, сообщения об ошибках привязываются к соответствующим полям.
3. Динамические изменения состояния передаются вспомогательным технологиям через специальные оповещения о доступности.

### 3.3 Зрительные условия

1. Контрастность текста и фона удовлетворяет требованиям читаемости: контрастность основного текста не ниже 4.5:1, крупного текста — не ниже 3:1.
2. Поддерживаются системные тёмная и светлая темы; переключение темы не изменяет структуру информации (см. [спецификацию визуальной вёрстки README](./readme-visual-layout-specification.md)).
3. Для анимации предусматривается возможность ослабления; автоматически воспроизводимое частое мерцание не допускается.
4. При масштабировании текста до 200% вёрстка остаётся пригодной, содержимое не обрезается.

## 4. Доступность командной строки

1. Сообщение об ошибке поясняет причину и возможное действие по исправлению; выводить только код ошибки не допускается.
2. Вывод `--help` имеет ясную рубрикацию и перечисляет обязательные параметры и значения по умолчанию.
3. Поддерживается переменная окружения, отключающая цветной вывод, для удобства программ экранного доступа и обработки журналов.
4. Интерактивные запросы имеют неинтерактивные эквивалентные параметры для сценариев автоматизации.

## 5. Контрольный список проверки

- [ ] Все изображения имеют информативный текст `alt`.
- [ ] Уровни заголовков последовательны, в документе один заголовок первого уровня.
- [ ] Текст ссылок понятен сам по себе.
- [ ] Таблицы имеют заголовок, цвет не является единственным носителем информации.
- [ ] Блоки кода снабжены языковым идентификатором.
- [ ] Элементы интерфейса управляемы с клавиатуры, фокус виден.
- [ ] Контрастность соответствует минимальным требованиям, текст читается в тёмной и светлой темах.
- [ ] Текст справки и сообщения об ошибках подсказывают следующий шаг.

## 6. Запрещённые практики

1. Запрещается передавать ключевую информацию исключительно изображением без текстовой альтернативы.
2. Запрещается обозначать состояние или ошибку только цветом.
3. Запрещается использовать бессмысленный текст ссылок.
4. Запрещается удалять стилевое оформление индикатора фокуса без замены.
