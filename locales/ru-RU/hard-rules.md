# Абсолютные правила

> Какую задачу решает этот файл: перечисляет незыблемые правила, нарушение любого из которых блокирует пуш и не допускает подхода «сначала запушить, потом исправить».

## Таблица абсолютных правил

| # | Правило |
|---|---|
| H1 | Имя репозитория должно соответствовать [спецификации именования проектов](./project-naming-specification.md); регистр, символы и длина должны быть полностью допустимыми |
| H2 | Файл `LICENSE` должен присутствовать; отсутствие лицензии означает сохранение авторских прав по умолчанию, публикация не допускается |
| H3 | Не должен коммититься ни один секрет, токен, закрытый ключ, `.env`, AK/SK облачного провайдера или строка подключения к базе данных |
| H4 | Не должны коммититься артефакты сборки, каталоги зависимостей, конфигурация IDE и системный мусор |
| H5 | Отдельный файл не должен превышать 100MB; при превышении 50MB обязательны LFS или исключение |
| H6 | Файл `README.md` должен присутствовать и содержать: позиционирование в одном предложении, установку, минимальный рабочий пример, лицензию |
| H7 | Ветка по умолчанию должна быть защищена; прямой push в `main`/`master` запрещён |
| H8 | Для публичных веток запрещён `git push --force`; для личных веток допускается только `--force-with-lease` |
| H9 | Перед пушем `build` и `test` должны проходить; при красном CI слияние в основную ветку не допускается |
| H10 | Сообщения коммитов должны соответствовать Conventional Commits; неинформативные коммиты вида `wip`/`update`/`fix bug` запрещены |
| H11 | Каждый документ должен быть отдельным файлом с отдельной зоной ответственности; сваливать всё содержимое в README запрещено (см. [матрицу документации](./document-matrix.md)) |
| H12 | Как только секрет уже отправлен пушем, необходимо немедленно ротировать секрет и очистить историю; коммит только с удалением недопустим |

## Ограничения исполнения

- Нарушение любого пункта **блокирует пуш**; подход «сначала запушить, потом исправить» не допускается.
- Результаты проверки H1–H12 должны отражаться в перечне проблем [формата отчёта о проверке](./audit-report-format.md), каждый пункт — с доказательством (путь:строка / вывод команды).
- При нарушении H12 следует действовать по процедуре обработки инцидентов из [спецификации пуша и релиза](./push-and-release-specification.md).
