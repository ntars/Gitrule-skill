# Матрица документации

> Какую задачу решает этот файл: определяет единственную ответственность каждого поставляемого документа, содержимое, которое строго запрещено в него включать, и ограничения на разделение, обеспечивая принцип «один файл — одна ответственность» и запрет на объединение.

## 1. Файлы и ответственность

| Файл | Единственная ответственность | Строго запрещено включать |
|---|---|---|
| `README.md` | Главная страница: что это, как установить, как запустить, где смотреть подробности | Полный API, процесс вклада, журнал обновлений |
| `LICENSE` | Полный текст лицензии | Любые пояснительные тексты |
| `CHANGELOG.md` | Изменения версий для пользователей | Детали внутреннего рефакторинга, планы разработки |
| `CONTRIBUTING.md` | Процесс и правила для внешних контрибьюторов | Описание функциональности проекта |
| `CODE_OF_CONDUCT.md` | Кодекс поведения | Техническое содержимое |
| `SECURITY.md` | Каналы сообщения об уязвимостях и стратегия реагирования | Перечень известных уязвимостей |
| `docs/api.md` | Полный справочник API | Обучающие материалы |
| `docs/architecture.md` | Архитектура и границы модулей | Примеры использования |
| `docs/naming.md` | Соглашение об именовании | Прочие спецификации |
| `docs/release.md` | Процесс релиза и стратегия версионирования | Записи об изменениях |
| `.github/PULL_REQUEST_TEMPLATE.md` | Чек-лист самопроверки PR | Описание проекта |
| `.github/ISSUE_TEMPLATE/*.yml` | Структурированные формы issue | Свободный текст |
| `.github/workflows/*.yml` | CI/CD | Пояснительная документация |

> Пояснение: основной текст спецификации `docs/naming.md` см. в [спецификации именования проектов](./project-naming-specification.md); основной текст спецификации `docs/release.md` см. в [спецификации пуша и публикации](./push-and-release-specification.md).

## 2. Ограничения

- Файл объёмом более 300 строк должен быть разделён с переносом в `docs/`; в README остаётся только краткое изложение + ссылка.
- Имена файлов имеют фиксированный верхний регистр, пути фиксированы, самостоятельное создание уровней каталогов запрещено.
- Каждый документ начинается с одного предложения «какую задачу решает этот файл», а в конце приводит перекрёстные ссылки на связанные файлы.
