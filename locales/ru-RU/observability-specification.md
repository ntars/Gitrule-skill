# Спецификация наблюдаемости

> Какую задачу решает этот файл: определяет поля журналов, цели SLI/SLO, правила алертов и шаблон карточки реагирования на алерт, обеспечивая видимость состояния системы, локализуемость сбоев и исполнимость алертов.

## 1. Положения спецификации

1. Наблюдаемость складывается из трёх опор: журналов, метрик и трассировки; все три должны связываться единым идентификатором запроса.
2. Журналы должны быть структурированными и содержать отметку времени, уровень и идентификатор запроса; запись чувствительной информации запрещена, правила обезличивания см. в [спецификации безопасности и приватности](./security-and-privacy-specification.md).
3. Для каждого ключевого сервиса должны определяться SLI и SLO с указанием способа расчёта и окна статистики.
4. Правила алертов должны иметь явный порог, длительность и ответственного; алерты без инструкции по обработке не допускаются к вводу в эксплуатацию.
5. После срабатывания алерт должен связываться с уровнями и процессом обработки [спецификации реагирования на инциденты](./incident-response-specification.md).
6. Способы расчёта метрик должны быть унифицированы с [спецификацией метрик качества](./quality-metrics-specification.md); одинаковые имена с разным смыслом запрещены.

## 2. Три опоры и поля

| Опора | Обязательные поля | Требование | Ключ связи |
| --- | --- | --- | --- |
| Журналы | Отметка времени, уровень, идентификатор запроса, сообщение, контекст | Структурированный вывод, только уровни DEBUG/INFO/WARN/ERROR | `trace_id` |
| Метрики | Имя метрики, метки, значение, время сбора | Явный способ расчёта и целевое значение | `service` |
| Трассировка | Идентификатор трассировки, идентификатор спана, родительский спан, длительность, состояние | Вызовы между сервисами связываются в цепочку | `trace_id` |

## 3. Шаблон полей журнала

```markdown
| Поле | Тип | Обязательно | Описание | Пример |
| --- | --- | --- | --- | --- |
| timestamp | ISO 8601 | Да | Время UTC с часовым поясом | 2026-11-18T10:00:00Z |
| level | Перечисление | Да | DEBUG / INFO / WARN / ERROR | ERROR |
| trace_id | Строка | Да | Уникальный идентификатор сквозной трассировки | 4bf92f3577b34da6 |
| service | Строка | Да | Имя сервиса | lint-api |
| message | Строка | Да | Краткое описание без чувствительной информации | rule load failed |
| context | Объект | Нет | Поля контекста, позволяющие локализовать проблему | {"rule":"spacing"} |
```

## 6. Определение полей

| Поле | Обязательно | Тип | Ключевые моменты заполнения | Пример |
| --- | --- | --- | --- | --- |
| Определение SLI | Да | Текст | Должно быть вычислимой долей или квантилем | Число успешных запросов / общее число запросов |
| Способ расчёта | Да | Текст | Явно указываются условия включения и исключения | Исключить запросы проверки работоспособности |
| Целевое значение SLO | Да | Порог | Значение + единица + процент | `≥99.9%` |
| Окно статистики | Да | Длительность | Скользящее окно; расплывчатое «календарный месяц» запрещено | `скользящие 30 дней` |
| Бюджет ошибок | Да | Значение | Выводится из целевого значения SLO | `допускается 43 минуты недоступности в месяц` |
| Выражение алерта | Да | Запрос | Готово к вставке и выполнению | `rate(http_5xx[5m]) > 0.01` |
| Длительность | Да | Длительность | Предотвращает ложные срабатывания при кратковременных колебаниях | `5 минут` |
| Инструкция по обработке | Да | Список | Не менее 3 шагов, включая условия эскалации | См. шаблон |
| Условия молчания | Да | Текст | Должны иметь срок истечения | `в окне релиза, не более 30 минут` |

## 7. Указания по заполнению

1. **Выбор SLI**: из наблюдаемых пользователем аспектов выбираются 2–5; внутренние ресурсные метрики вроде CPU и памяти не заменяют пользовательские SLI.
2. **Единый способ расчёта**: одноимённая метрика в журналах, панелях мониторинга и выражениях алертов должна рассчитываться одинаково.
3. **Постановка целей**: цели SLO следует устанавливать на основе текущих измеренных значений и терпимости бизнеса; применение «четырёх девяток» без обоснования запрещено.
4. **Бюджет ошибок**: указываются результат пересчёта и действия при разных уровнях расхода; при исчерпании бюджета замораживаются некритичные релизы.
5. **Исполнимость алертов**: каждый алерт должен отвечать на три вопроса: «за чем следить, как диагностировать, когда эскалировать»; отсутствие ответа на любой вопрос блокирует ввод в эксплуатацию.
6. **Борьба с усталостью от алертов**: алерты, не приведшие к результативной обработке в течение 30 дней подряд, понижаются в уровне или удаляются с указанием причины.
7. **Обезличивание**: если в полях контекста журнала могут появиться ключи, токены или персональные данные, обезличивание выполняется до вывода.

Типичные ошибки:

| Ошибочная формулировка | Проблема | Способ исправления |
| --- | --- | --- |
| Использование загрузки CPU в качестве SLI | Не наблюдается пользователем | Перейти к доступности, задержке, доле ошибок |
| В алерте указано только «аномалия сервиса» | Нет порога и инструкции | Дополнить выражением, порогом и шагами обработки |
| Журнал печатает полные заголовки запроса | Риск утечки приватных данных и ключей | Выводить необходимые поля по белому списку |
| У алерта нет срока истечения молчания | Длительное молчание приводит к пропуску срабатываний | Установить максимальную длительность молчания |
| У SLO нет окна статистики | Цель непроверяема | Добавить скользящее окно |

## 8. Полный пример

```markdown
# Определение SLO: lint-api

Версия: v1.0 ｜ Ответственный: Ван У ｜ Период пересмотра: ежеквартально

## Определение SLI
| SLI | Определение | Способ расчёта | Источник данных |
| --- | --- | --- | --- |
| Доступность | Число успешных запросов / общее число запросов | Код <500, без проверок работоспособности | Grafana lint-overview |
| Задержка | P95 длительности запросов проверки | Только путь /check | Grafana lint-overview |

## Цели SLO
| SLI | Целевое значение | Окно статистики | Текущее значение | Состояние достижения |
| --- | --- | --- | --- | --- |
| Доступность | ≥99.9% | Скользящие 30 дней | 99.94% | Достигнуто |
| Задержка P95 | <300ms | Скользящие 7 дней | 268ms | Достигнуто |

## Бюджет ошибок
- Способ расчёта: 0.1% × 30 дней = 43 минуты в месяц
- Алерты о расходовании: при 50% уведомляется ответственный, при 75% — дежурная смена, при 90% замораживаются некритичные релизы
- Политика исчерпания: выпуск функций приостанавливается, допускаются только исправления стабильности

### ALERT-001: доля ошибок 5xx превышает порог
- Связанный SLI: доступность
- Выражение: `rate(http_requests_total{status=~"5.."}[5m]) / rate(http_requests_total[5m])`
- Порог: >0.01
- Длительность: 5 минут
- Уровень серьёзности: P1
- Ответственный: Ван У
- Инструкция по обработке:
  1. Открыть Grafana lint-overview и определить сервис-источник ошибок
  2. Запросить журналы ERROR и связать цепочку вызовов по trace_id; типичная причина — сбой загрузки плагина правил
  3. Если за 10 минут причина не локализована, эскалировать к Ли Сы и перейти в процесс инцидента P1
```
