# Спецификация управления зависимостями

> Какую задачу решает этот файл: определяет шаблоны и поля заявки на добавление зависимости, перечня зависимостей, фиксации версий и обновления, чтобы обеспечить воспроизводимость сборки, прослеживаемость зависимостей и соблюдение лицензий.

## 1. Положения спецификации

1. Добавление новой зависимости требует указания назначения, лицензии и состояния сопровождения (см. [спецификацию соответствия открытому исходному коду](./open-source-compliance-specification.md)).
2. Предпочтение отдаётся зависимостям с совместимой лицензией и активным сообществом; добавление зависимостей неизвестного происхождения или с неясной лицензией запрещено.
3. Версии зависимостей должны записываться в lockfile и передаваться в репозиторий, чтобы обеспечить воспроизводимость сборки в чистом окружении (соответствует абсолютному правилу H9 и измерению D5).
4. Номер версии должен фиксировать фактически разрешённую версию; диапазонные выражения не используются в качестве итоговой поставки.
5. Обновление зависимостей должно выполняться с помощью средств автоматизации; после обновления требуется прохождение CI; уязвимости должны устраняться своевременно либо фиксироваться меры их снижения.
6. Перечень зависимостей должен соответствовать NOTICE (см. [спецификацию NOTICE](./notice-specification.md)).

```markdown
- Оценка альтернатив: {{已评估的替代包及未选原因}}

| Поле | Значение |
| --- | --- |
| Имя пакета | {{包名}} |
| Добавляемая версия | {{精确版本号}} |
| Лицензия | {{SPDX ID}} |
| Совместимость лицензии | {{兼容 / 不兼容 / 需法务确认}} |
| Дата последнего релиза | {{YYYY-MM-DD}} |
| Состояние сопровождения | {{活跃 / 低频 / 停滞}} |
| Загрузок в неделю | {{数值}} |
| Количество транзитивных зависимостей | {{数值}} |
| Известные уязвимости | {{无 / CVE 编号与处置}} |

- Заключение: {{批准 / 拒绝 / 有条件批准}}
- Утверждающий: {{姓名}}
```

## 4. Определение полей

| Поле | Обязательно | Тип | Ключевые моменты заполнения | Пример |
| --- | --- | --- | --- | --- |
| Номер заявки | Да | `DEP-NNN` | Непрерывный, без повторного использования | `DEP-007` |
| Назначение | Да | Текст | Описание решаемой задачи; «удобно для разработки» запрещено | `разбор конфигурации TOML` |
| Оценка альтернатив | Да | Текст | Оценивается как минимум 1 альтернатива | `рассматривался toml-js, отклонён из-за отсутствия сопровождения` |
| Добавляемая версия | Да | Точная версия | Использование `^` или `~` не допускается | `1.2.3` |
| Зафиксированная версия | Да | Точная версия | Совпадает с lockfile | `1.2.3` |
| Лицензия | Да | SPDX ID | Запись совпадает с [спецификацией LICENSE](./license-specification.md) | `MIT` |
| Состояние сопровождения | Да | Перечисление | Активное / низкочастотное / заброшенное; приводится обоснование вывода | `активное (коммиты за последние 30 дней)` |
| Количество транзитивных зависимостей | Да | Число | При большом количестве обосновывается влияние на размер и риски | `12` |
| Известные уязвимости | Да | Текст | При отсутствии указывается «нет», поле не остаётся пустым | `нет` |
| Дата пересмотра | Да | Дата | Для исключений обязательно устанавливается дата пересмотра | `2026-12-31` |

## 5. Указания по заполнению

1. **Оценка возможности самостоятельной реализации**: сначала даётся ответ на вопрос «можно ли реализовать средствами стандартной библиотеки или имеющихся возможностей»; при наличии возможности самостоятельной реализации добавление всё равно требует обоснования.
2. **Лицензия**: должна быть SPDX ID; `UNLICENSED` и нестандартные лицензии переводятся в статус «требуется подтверждение юристов» и не могут добавляться напрямую.
3. **Состояние сопровождения**: определяется по дате последнего релиза и реакции на issue; вывод «кажется, кто-то сопровождает» запрещён.
4. **Фиксация версий**: при поставке в lockfile должна находиться точная разрешённая версия; в `package.json` допускается диапазонное выражение, но lockfile обязан быть точным.
5. **Ритм обновлений**: автоматические обновления включаются на постоянной основе, слияние подтверждается вручную; каждое обновление должно проходить CI с проверкой изменения лицензий.
6. **Работа с уязвимостями**: приоритет отдаётся обновлению до безопасной версии; если обновление невозможно, указываются меры снижения риска и дата пересмотра, а запись вносится в реестр рисков согласно [спецификации реагирования на инциденты](./incident-response-specification.md).
7. **Синхронизация перечня**: после добавления или удаления зависимости синхронно обновляются перечень зависимостей и NOTICE; три источника (lockfile, перечень, NOTICE) должны совпадать.

Типичные ошибки:

| Ошибочная формулировка | Проблема | Способ исправления |
| --- | --- | --- |
| «Использовать библиотеку для работы с конфигурацией» | Нет конкретного имени пакета и назначения | Указать имя пакета, версию и решаемую задачу |
| Лицензия указана как «открытая» | Совместимость невозможно определить | Указать SPDX ID |
| lockfile не передан | Сборка невоспроизводима | Передать lockfile (соответствует H9) |
| Количество транзитивных зависимостей оставлено пустым | Риск не виден | Указать конкретное число |
| Для уязвимости не указаны меры снижения риска | Риск не отслеживается | Дополнить мерами и датой пересмотра |

## 6. Полный пример

```markdown
## Заявка на добавление зависимости: remark

- Номер заявки: DEP-001
- Заявитель: Ван У
- Назначение: слой разбора Markdown для задачи позиционирования узлов в движке правил (REQ-001, REQ-004).
- Возможно ли реализовать самостоятельно: нет; самостоятельная реализация не покроет граничные случаи GFM в пределах доступных ресурсов.
- Оценка альтернатив: рассматривался marked, отклонён из-за недостаточных возможностей позиционирования узлов в китайском тексте.

| Поле | Значение |
| --- | --- |
| Имя пакета | remark |
| Добавляемая версия | 15.0.1 |
| Лицензия | MIT |
| Совместимость лицензии | Совместима |
| Дата последнего релиза | 2026-11-02 |
| Состояние сопровождения | Активное (коммиты за последние 30 дней) |
| Загрузок в неделю | 4,200,000 |
| Количество транзитивных зависимостей | 18 |
| Известные уязвимости | Нет |
| Влияние на размер пакета | +42 KB |

- Заключение: одобрено, реализуется вместе с ADR-0002
- Утверждающий: Ли Сы
```
