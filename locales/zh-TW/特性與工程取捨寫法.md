# 特性與工程取捨寫法

> 本檔案解決什麼問題：定義 README 中「核心特性」與「設計細節與工程取捨」兩章的寫法，分別給出特性的五段結構與工程取捨的十類強制覆蓋項。

## 1. 核心特性寫法

每條特性按以下五段結構書寫，缺任一段落不得作為特性列出。

1. **特性名稱**：不超過 15 字，使用名詞性短語。
2. **價值**：解決的具體問題，以及不解決時的後果。
3. **實現方式**：採用的技術、機制或演算法，指明關鍵檔案或函式。
4. **差異化**：與常見方案的對比維度，須為可客觀判斷的維度。
5. **證據**：測試資料、基準結果、程式碼位置、配置項或可復現步驟。

約束：
1. 證據須可復現；無法提供證據的特性，標註「【待補充：驗證方式】」，不得以定性描述代替。
2. 效能類證據須註明測試環境與測試方法。
3. 對比物件須為具名方案，不得使用「傳統方案」「其他工具」等模糊指代。

## 2. 設計細節與工程取捨寫法

每條按「場景 → 處理方式 → 原因」三段書寫，說明為何這樣設計而非其他方案。

強制覆蓋的類別：
1. 異常輸入與邊界情況（空值、超長、非法字元、極端數值）
2. 超時、重試、退避、熔斷、降級策略
3. 快取層級、失效策略、快取穿透與雪崩防護
4. 併發控制、鎖粒度、資料一致性與冪等性
5. 記憶體與儲存最佳化（分批處理、流式讀寫、壓縮）
6. 安全措施（鑑權、限流、輸入校驗、敏感資訊脫敏）
7. 互動細節（防誤觸、二次確認、可撤銷、載入態與空態）
8. 預設引數取值依據
9. 向後相容與跨平臺適配策略
10. 弱網與離線處理、狀態恢復
