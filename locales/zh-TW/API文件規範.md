# API文件規範

> 本檔案解決什麼問題：定義完整 API 參考文件的結構與欄位，作為 docs/api.md 的撰寫依據，與教程類內容嚴格分離。

## 1. 必備結構

每個 API 條目須包含：

| 欄位 | 要求 |
| --- | --- |
| 介面簽名 | 方法、路徑或函式原型，完整可複製 |
| 引數 | 名稱、型別、是否必填、預設值、取值範圍、說明 |
| 返回值 | 型別與結構說明 |
| 錯誤碼 | 錯誤碼、觸發條件、處理方式 |
| 呼叫示例 | 可執行的最小示例，標註語言 |
| 限流與配額 | 呼叫頻率限制、配額、超限處理 |

## 2. 強制規則

1. 引數與返回值須寫明型別與約束，不得省略預設值。
2. 錯誤碼須完整列出，不得只寫「可能報錯」。
3. 程式碼塊須標註語言標識，示例須可獨立執行。
4. 本檔案只放參考資訊，不寫教程、背景、設計說明（教程與背景見 [README章節規範](./README章節規範.md)）。

## 3. 一致性要求

API 文件中的介面簽名須與程式碼實際實現一致；引數命名須與 [通用寫作規範](./通用寫作規範.md) 的精確性要求一致；術語見 [術語表](./術語表.md)。
