# API設計規範

> 本檔案解決什麼問題：定義介面設計的一致性原則與約定，保證 API 易用、可預測、可演進。

## 1. 設計原則

1. 命名一致：同類資源與操作使用統一命名規則。
2. 可預測：相同語義的操作有相同結構。
3. 顯式優於隱式：預設值、必填項、錯誤行為須明確。
4. 向後相容：變更優先保持相容，破壞性變更須版本化（見 [版本管理規範](./版本管理規範.md)）。

## 2. 必含約定

1. **命名**：資源、方法、欄位的命名規則。
2. **引數**：型別、必填、預設值、取值範圍。
3. **錯誤**：統一錯誤結構、錯誤碼、HTTP 狀態或等價機制。
4. **分頁與過濾**：大資料量場景的分頁、排序、過濾約定。
5. **冪等性**：寫操作的冪等保證。
6. **限流與配額**：頻率限制與超限響應。
7. **版本**：API 版本策略與演進方式。

## 3. 強制規則

1. 錯誤響應須包含可定位的錯誤碼與說明，不暴露內部實現細節。
2. 破壞性變更須升版本並提供遷移期（見 [變更日誌規範](./變更日誌規範.md)）。
3. 介面須有對應文件，欄位完整（見 [API文件規範](./API文件規範.md)）。
