# 可訪問性規範

> 本檔案解決什麼問題：定義專案文件、README 與使用者介面的可訪問性要求，使內容對使用螢幕閱讀器、鍵盤操作與不同視覺條件的讀者同樣可用。

## 1. 適用範圍

1. 文件可訪問性：README、文件站、示例程式碼、表格、圖片。
2. 介面可訪問性：應用程式與 Web 專案的使用者介面。
3. 命令列可訪問性：幫助文字、錯誤提示與輸出格式。

## 2. 文件可訪問性

### 2.1 圖片與媒體

1. 每張圖片須提供 `alt` 文字，描述畫面內容與作用；裝飾性圖片用空 `alt`。
2. 不得使用「圖片」「截圖」「image」等無資訊文字作為 `alt`。
3. GIF 動圖須在鄰近文字中說明其內容，避免僅靠動畫傳達資訊。
4. 圖表須同時提供文字說明或資料表，不得只以顏色區分資料系列。

### 2.2 標題與結構

1. 標題層級連續，不得跳級（見 [README視覺排版規範](./README視覺排版規範.md)）。
2. 全文僅一個一級標題。
3. 列表使用規範的 Markdown 語法，保證螢幕閱讀器可識別為列表。
4. 表格須有表頭行，不得使用無表頭表格佈局頁面。

### 2.3 連結與文字

1. 連結文字須可獨立說明目標，禁止使用「點選這裡」「更多」。
2. 顏色不得作為傳達資訊的唯一手段，須配合文字或圖示。
3. 中外文混排時保留空格，保證斷詞與朗讀正確。
4. 縮寫首次出現時給出全稱。

### 2.4 程式碼與表格

1. 程式碼塊標註語言，便於輔助工具識別（見 [README視覺排版規範](./README視覺排版規範.md)）。
2. 表格單元格內容簡明，避免跨行合併造成閱讀器解析困難。
3. 長命令給出分行寫法，不依賴橫向滾動。

## 3. 介面可訪問性

### 3.1 鍵盤操作

1. 所有互動元素可透過鍵盤到達與操作。
2. 焦點順序與視覺順序一致，焦點狀態清晰可見。
3. 提供跳過重複內容的快捷入口（如跳轉到主內容）。

### 3.2 語義與標籤

1. 使用語義化標籤表達結構與角色，避免用無語義元素模擬控制元件。
2. 表單控制元件須有關聯標籤，錯誤提示與對應欄位繫結。
3. 動態狀態變化透過無障礙提示傳達給輔助技術。

### 3.3 視覺條件

1. 文字與背景對比度滿足可讀性要求；正文對比度不低於 4.5:1，大字不低於 3:1。
2. 支援系統深淺主題，主題切換不改變資訊結構（見 [README視覺排版規範](./README視覺排版規範.md)）。
3. 動畫提供減弱選項，避免自動播放的高頻閃爍內容。
4. 文字縮放至 200% 時佈局仍可用，不出現內容截斷。

## 4. 命令列可訪問性

1. 錯誤提示說明原因與可行的修復動作，不得只輸出錯誤碼。
2. `--help` 輸出分類清晰，列出必填引數與預設值。
3. 支援禁用彩色輸出的環境變數，便於螢幕閱讀器與日誌處理。
4. 互動式提示提供非互動的等價引數，支援自動化場景。

## 5. 驗證清單

- [ ] 所有圖片有資訊明確的 `alt` 文字。
- [ ] 標題層級連續，全文一個一級標題。
- [ ] 連結文字可獨立理解。
- [ ] 表格有表頭，顏色非唯一資訊載體。
- [ ] 程式碼塊標註語言。
- [ ] 介面元素可鍵盤操作，焦點可見。
- [ ] 對比度滿足最低要求，深淺主題均可讀。
- [ ] 幫助文字與錯誤提示可指導下一步操作。

## 6. 禁止事項

1. 禁止用純圖片傳達關鍵資訊而不提供文字替代。
2. 禁止僅用顏色表示狀態或錯誤。
3. 禁止使用無意義的連結文字。
4. 禁止移除焦點指示樣式而不提供替代。
