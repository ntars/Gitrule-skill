# 程式碼風格規範

> 本檔案解決什麼問題：定義程式碼風格配置模板、命名約定表、註釋規則與填寫說明，減少風格分歧、提升可讀性與審查效率。

## 1. 規範條文

1. 風格規則以自動化工具為準，人工只處理工具無法覆蓋的部分。
2. 格式化配置須隨倉庫提交（如格式化配置檔案），保證不同環境一致。
3. CI 須整合格式檢查，不透過則不得合併（見 [測試規範](./測試規範.md)）。
4. 不得使用魔法數字與硬編碼常量，須提取為具名常量。
5. 行尾統一 LF，檔案以換行結尾（對應維度 D3 倉庫衛生）。

## 2. 風格配置模板

```markdown
# 程式碼風格約定：{{项目名称}}

配置版本：{{v1.0}} ｜ 適用語言與版本：{{如 TypeScript 5.x}} ｜ 格式化工具：{{如 Prettier 3.x}}

## 格式規則（工具強制）
| 規則 | 取值 | 工具配置項 | 是否可協商 |
| --- | --- | --- | --- |
| 縮排 | {{2 空格 / 4 空格 / Tab}} | {{配置项名}} | 否 |
| 行寬 | {{100 字符}} | {{配置项名}} | 否 |
| 引號 | {{单引号 / 双引号}} | {{配置项名}} | 否 |
| 行尾 | LF | `endOfLine: lf` | 否 |
| 檔案末尾換行 | 必須有 | 工具預設 | 否 |
| 分號 | {{有 / 无}} | {{配置项名}} | 否 |

## 命名約定（工具無法強制，人工審查）
| 物件 | 規則 | 正例 | 反例 |
| --- | --- | --- | --- |
| 變數 | {{camelCase}} | `userName` | `UserName` |
| 常量 | {{UPPER_SNAKE_CASE}} | `MAX_RETRY` | `maxRetry` |
| 函式 | {{动词开头 camelCase}} | `parseConfig` | `configParse` |
| 類 / 型別 | {{PascalCase}} | `ConfigLoader` | `config_loader` |
| 檔名 | {{kebab-case}} | `config-loader.ts` | `ConfigLoader.ts` |
| 布林值 | {{is/has/can 前缀}} | `isValid` | `valid` |
| 集合 | {{复数名词}} | `items` | `itemList` |

## 註釋規則
- 必須寫註釋的場景：{{公开 API 的契约、非直观算法、绕开限制的临时方案}}
- 禁止的註釋：{{复述代码、无信息量、失效的旧注释、情绪化表述}}
- 註釋語言：{{与项目主语言一致}}
- TODO 格式：`// TODO({{负责人}}): {{事项}} — {{计划版本}}`

## 檔案組織
1. 匯入順序：{{标准库 → 第三方 → 本地模块，组内字典序}}
2. 宣告順序：{{常量 → 类型 → 函数 → 导出}}
3. 單檔案行數上限：{{300 行，超出须拆分}}

## 例外清單
| 場景 | 例外規則 | 批准人 | 有效期 |
| --- | --- | --- | --- |
| {{如生成代码}} | {{不参与格式化}} | {{姓名}} | {{至 v2.0}} |
```

## 3. 配置欄位定義

| 欄位 | 必填 | 型別 | 填寫要點 | 示例 |
| --- | --- | --- | --- | --- |
| 配置版本 | 是 | 文字 | 風格規則變更時遞增 | `v1.0` |
| 適用語言與版本 | 是 | 文字 | 明確主版本，避免規則漂移 | `TypeScript 5.x` |
| 格式化工具 | 是 | 文字 | 與 lockfile 中的版本一致 | `Prettier 3.2` |
| 規則.取值 | 是 | 列舉 / 數值 | 須唯一，禁止「看情況」 | `2 空格` |
| 是否可協商 | 是 | 列舉 | 否 / 是；標「是」須給出協商條件 | `否` |
| 命名正例 | 是 | 程式碼 | 從專案現有程式碼中選取 | `parseConfig` |
| 命名反例 | 是 | 程式碼 | 須為真實易犯寫法 | `configParse` |
| TODO 負責人 | 是 | 文字 | 禁止寫「團隊」 | `张三` |
| 例外有效期 | 是 | 版本 / 日期 | 到期須複核 | `至 v2.0` |

## 4. 填寫說明

1. **工具優先**：能被工具強制的規則一律寫入格式化配置，不靠人工記憶；人工只管命名、註釋、檔案組織。
2. **行寬取值**：須結合審查介面寬度設定，常見為 100 或 120；一旦確定不得在個別檔案中覆蓋。
3. **命名正例**：從專案現有程式碼中選取真實存在的名稱，禁止使用教科書式佔位符。
4. **布林命名**：`is`/`has`/`can` 字首須與語義一致；`isReady` 不得表示動作。
5. **TODO**：必須含負責人、事項與計劃版本；無計劃的 TODO 不得進入主幹。
6. **例外清單**：每項例外須有批准人與有效期；到期未複核自動失效。

常見錯誤：

| 錯誤寫法 | 問題 | 修正方式 |
| --- | --- | --- |
| 「程式碼儘量簡潔」 | 不可判定 | 改為可檢查規則，如函式長度上限 |
| 命名錶只有規則無反例 | 審查時無法對照 | 補真實易犯反例 |
| 註釋寫「這裡之前有 bug」 | 無資訊且易失效 | 改為說明當前行為與原因 |
| TODO 無負責人 | 無人跟進 | 補負責人與計劃版本 |
| 例外無有效期 | 永久豁免 | 補有效期與複核人 |

## 5. 完整示例

```markdown
# 程式碼風格約定：markdown-lint-cli

配置版本：v1.0 ｜ 適用語言與版本：TypeScript 5.x ｜ 格式化工具：Prettier 3.2

## 格式規則（工具強制）
| 規則 | 取值 | 工具配置項 | 是否可協商 |
| --- | --- | --- | --- |
| 縮排 | 2 空格 | `tabWidth: 2` | 否 |
| 行寬 | 100 字元 | `printWidth: 100` | 否 |
| 引號 | 單引號 | `singleQuote: true` | 否 |
| 行尾 | LF | `endOfLine: lf` | 否 |
| 分號 | 有 | `semi: true` | 否 |

## 命名約定（人工審查）
| 物件 | 規則 | 正例 | 反例 |
| --- | --- | --- | --- |
| 函式 | 動詞開頭 camelCase | `parseRules` | `rulesParser` |
| 常量 | UPPER_SNAKE_CASE | `DEFAULT_RULES` | `defaultRules` |
| 檔名 | kebab-case | `rule-loader.ts` | `RuleLoader.ts` |

## 註釋規則
- 必須寫註釋的場景：規則的匹配語義、對上游 API 行為的繞行處理。
- 禁止的註釋：複述程式碼、「修復了一個 bug」、無負責人 TODO。
- TODO 格式：`// TODO(王五): 替换临时解析器 — v2.0`

## 例外清單
| 場景 | 例外規則 | 批准人 | 有效期 |
| --- | --- | --- | --- |
| fixtures 目錄 | 不參與格式化 | 李四 | 至 v2.0 |
```
