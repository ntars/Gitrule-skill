# 術語表

> 本檔案解決什麼問題：集中定義專案全篇使用的專業術語與縮寫，保證中英版本術語一一對應、全文表述一致。

## 1. 維護規則

1. 術語首次出現時須給出定義，格式為「中文術語（English Term，縮寫）」。
2. 同一概念全文只用一種表述；中英版本術語一一對應，共用本表。
3. 新增術語須同步寫入本表，並同步到英文版本對應位置。
4. 縮寫首次出現須展開全稱，之後可直接使用縮寫。

## 2. 術語對照表

| 中文 | English | 縮寫 | 說明 |
| --- | --- | --- | --- |
| 軟體物料清單 | Software Bill of Materials | SBOM | 專案依賴與元件的完整清單 |
| 語義化版本 | Semantic Versioning | SemVer | 版本號格式 `MAJOR.MINOR.PATCH` |
| 架構決策記錄 | Architecture Decision Record | ADR | 記錄重要架構決策及其背景與後果 |
| 行為準則 | Code of Conduct | CoC | 社群參與者行為規範 |
| 持續整合 / 持續交付 | Continuous Integration / Continuous Delivery | CI/CD | 自動化構建、測試與交付流程 |
| 軟體許可證識別符號 | Software Package Data Exchange | SPDX | 許可證的標準識別符號體系 |
| 最小可行產品 | Minimum Viable Product | MVP | 可驗證核心假設的最小版本 |
| 自然語言處理 | Natural Language Processing | NLP | 文字處理相關技術 |
| 大模型 | Large Language Model | LLM | 大規模預訓練語言模型 |
| 模型上下文協議 | Model Context Protocol | MCP | 連線模型與外部工具的協議 |
| 待補充 | To Be Determined | TBD | 資訊尚未確認的佔位標記 |

> 表中條目為通用示例，使用前須按專案實際術語增刪。

- **通用縮寫**：各語種正文中直接使用，不隨語言變化：SBOM、SPDX、ADR、SemVer、CoC、CI/CD、MVP、NLP、LLM、MCP、TBD。

本表給出一詞在各語種的固定譯名，供新增語種與全文替換時直接引用。術語取引用形（主格或不定式）；俄語、德語正文按語法變格，檢索時按詞幹匹配。

收錄口徑：只收正文中有實際用例的術語，下表每一格都能在對應語種目錄內檢索到。SBOM、MVP、NLP、LLM 四詞在十二個語種正文中出現次數為 0，只作為範例存在於上一節的對照表，故不列入矩陣。SPDX 在各語種正文中一律直接用縮寫，全稱從未出現，故與其餘縮寫一併列於上方的縮寫行，不設譯名格。

新增語種時先按本表補齊譯名，再執行 `python3 cli/gitrule.py xcheck --path . --reference zh-CN` 校驗結構一致性。
