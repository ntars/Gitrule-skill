# 貢獻指南模板

> 本檔案解決什麼問題：提供一份可直接複製的貢獻指南模板，供專案生成 CONTRIBUTING.md，覆蓋參與方式、環境搭建、分支模型、提交規範、PR 要求、測試要求、行為準則與許可宣告；配套的填寫說明覆蓋各型別專案的裁剪方式。

## 1. 使用說明

1. 複製第 3 節「模板正文」全部內容，新建為專案根目錄的 `CONTRIBUTING.md`。
2. 按第 4 節替換佔位符；所有命令須為可直接執行的真實命令。
3. 按第 5 節場景變體裁剪：文件型專案刪除測試命令段落，保留 Issue 與 PR 流程。
4. 規則依據見 [貢獻指南規範](./貢獻指南規範.md)；分支與提交細節分別見 [Git工作流與分支規範](./Git工作流與分支規範.md)、[提交資訊規範](./提交資訊規範.md)。

## 2. 定製原則

- **可執行**：命令寫全工作目錄與依賴前提，禁止只寫「安裝依賴」而無具體命令。
- **有觸發條件**：每一步寫明何時執行、預期結果。
- **不空泛**：禁止只寫「歡迎 PR」而無實質流程，對應 [質量門禁](./質量門禁.md) 的社群治理檢查。
- **引用而非複製**：提交與測試規則引用對應規範，不在本檔案重複全文。

## 3. 模板正文

````markdown
# 貢獻指南

> 本檔案說明如何參與 {{项目名称}} 的貢獻，適用於外部貢獻者與首次參與者。

## 參與方式

| 方式 | 適用場景 | 入口 |
| --- | --- | --- |
| 議題討論 | 功能建議、問題反饋 | {{议题入口}} |
| 文件改進 | 錯別字、示例補充、結構最佳化 | 直接提交 PR |
| 程式碼貢獻 | 缺陷修復、功能實現 | 見下方流程 |
| 問題反饋 | 使用受阻、異常復現 | {{问题反馈入口}} |

## 開發環境搭建

前提：{{环境前提}}

```bash
# 複製倉庫
git clone {{仓库地址}}
cd {{项目目录名}}

# 安裝依賴
{{依赖安装命令}}

# 本地執行
{{本地运行命令}}
```

預期結果：{{验证本地环境可用的方式}}

## 分支模型

- 從 {{基准分支}} 切出個人分支，命名格式 `{{分支命名格式}}`（例如 `feat/简短描述`）。
- 每個 PR 只處理一件事，變更範圍過大時請拆分。
- 禁止直接向 {{受保护分支}} 提交，須透過 PR 合併。

## 提交規範

提交資訊遵循 Conventional Commits，格式為 `type(scope): subject`。常用型別：`feat`、`fix`、`docs`、`refactor`、`test`、`chore`。示例：

```text
feat(cli): add config file support
```

完整規則見 [提交資訊規範]({{提交规范链接}})。

## PR 要求

提交 PR 前請完成以下自查：

- [ ] 變更範圍單一，且有對應議題或說明。
- [ ] 提交資訊符合上述格式。
- [ ] 本地執行 `{{测试命令}}` 全部透過。
- [ ] 文件隨程式碼同步更新。
- [ ] 未引入金鑰、私鑰或敏感資訊。
- [ ] 描述中說明變更內容、原因與驗證方式。

## 測試要求

| 檢查項 | 命令 | 透過標準 |
| --- | --- | --- |
| 單元測試 | `{{单元测试命令}}` | 全部透過 |
| 靜態檢查 | `{{lint 命令}}` | 無錯誤 |
| 構建驗證 | `{{构建命令}}` | 構建成功 |

覆蓋率門檻：{{覆盖率要求}}。

## 行為準則

參與本專案即表示同意遵守 [行為準則](./CODE_OF_CONDUCT.md)。

## Issue 規範

- 提問前先檢索已有議題，避免重複。
- 缺陷報告須包含：環境資訊、復現步驟、預期結果、實際結果、錯誤日誌。
- 功能建議須說明使用場景與不採用時的替代方案。

## 許可證宣告

貢獻內容預設遵循本專案許可證 {{许可证名称及 SPDX 标识符}}，全文見 [LICENSE](./LICENSE)。提交即表示你有權以該許可證授權你的貢獻。
````

## 4. 佔位符對照表與欄位定義

| 佔位符 | 必填 | 欄位定義 | 填寫示例 |
| --- | --- | --- | --- |
| `{{项目名称}}` | 是 | 專案對外名稱 | `FooBar` |
| `{{议题入口}}` | 是 | 真實可訪問的議題地址 | `https://github.com/owner/repo/issues` |
| `{{问题反馈入口}}` | 否 | 與議題入口不同時的專用渠道 | `https://github.com/owner/repo/issues/new` |
| `{{环境前提}}` | 是 | 語言版本、包管理器與系統依賴 | `Node.js 20+、pnpm 8+` |
| `{{仓库地址}}` | 是 | 可克隆的倉庫地址 | `https://github.com/owner/repo.git` |
| `{{项目目录名}}` | 是 | 克隆後的目錄名 | `repo` |
| `{{依赖安装命令}}` | 是 | 實際安裝命令 | `pnpm install` |
| `{{本地运行命令}}` | 是 | 實際啟動命令 | `pnpm dev` |
| `{{验证本地环境可用的方式}}` | 是 | 可觀察的成功標誌 | `访问 localhost:3000 出现首页` |
| `{{基准分支}}` | 是 | 切出分支的來源分支 | `main` |
| `{{分支命名格式}}` | 是 | 分支命名規則 | `feat/简短描述` |
| `{{受保护分支}}` | 是 | 禁止直接提交的分支 | `main` |
| `{{提交规范链接}}` | 否 | 專案內或外部提交規範地址 | `./docs/COMMIT_CONVENTION.md` |
| `{{测试命令}}` | 是 | 實際測試命令 | `pnpm test` |
| `{{lint 命令}}` | 是 | 實際靜態檢查命令 | `pnpm lint` |
| `{{构建命令}}` | 是 | 實際構建命令 | `pnpm build` |
| `{{覆盖率要求}}` | 否 | 新增程式碼的覆蓋率門檻 | `新增代码不低于 80%` |
| `{{许可证名称及 SPDX 标识符}}` | 是 | 專案許可證全稱與 SPDX 標識 | `MIT 许可证（MIT）` |

## 5. 填寫說明與場景變體

| 場景 | 必留章節 | 可裁剪章節 | 調整要點 |
| --- | --- | --- | --- |
| 程式碼專案 | 全部 | 無 | 命令須實際執行並透過驗證 |
| 文件專案 | 參與方式、PR 要求、行為準則、許可證 | 測試要求、開發環境搭建 | 刪除測試表格，保留 PR 自查 |
| 個人專案 | 參與方式、PR 要求、行為準則、許可證 | 環境搭建可精簡 | 明確是否接受外部貢獻 |
| 企業專案 | 全部 | 無 | 增加貢獻者許可協議（CLA）連結與法務要求 |

常見錯誤對照：

| 錯誤寫法 | 後果 | 正確寫法 |
| --- | --- | --- |
| 「歡迎任何形式的貢獻」 | 無具體路徑，貢獻者無從下手 | 列出參與方式表與入口 |
| 「執行測試即可」 | 不知命令與透過標準 | 寫明命令、透過標準與覆蓋率門檻 |
| 命令寫 `npm install` 而專案用 pnpm | 命令不可執行 | 與實際 lockfile 一致 |

## 6. 完整示例

以下為命令段落的填好示例，僅作格式參考。

```bash
# 複製倉庫
git clone https://github.com/owner/repo.git
cd repo

# 安裝依賴
pnpm install

# 本地執行
pnpm dev
```

預期結果：訪問 localhost:3000 出現首頁。
