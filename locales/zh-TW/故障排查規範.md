# 故障排查規範

> 本檔案解決什麼問題：定義故障排查文件（Troubleshooting / FAQ）的結構、條目寫法與維護機制，使使用者能按現象定位原因並自行解決常見問題。

## 1. 適用場景

以下情況須提供故障排查文件：

1. 安裝或構建失敗存在多種常見原因。
2. 配置項之間存在衝突，錯誤提示不足以說明解決方法。
3. 特定平臺或版本存在已知限制。
4. 使用者反覆提出同類問題，且答案可標準化。

## 2. 檔案位置與命名

1. 內容較少時，作為 README 的一個章節，標題為「常見問題」或「故障排查」。
2. 內容較多時，單獨建 `docs/troubleshooting.md` 或 `FAQ.md`，README 保留入口連結。
3. 問題按主題分組，如「安裝」「配置」「執行」「效能」「網路」。

## 3. 文件結構

1. **開頭說明**：本文件覆蓋的常見問題範圍與適用版本。
2. **問題索引**：按主題列出問題標題，支援快速跳轉。
3. **問題條目**：按統一結構逐條展開。
4. **仍無法解決**：指向 issue、討論區等求助渠道。

## 4. 條目結構

每個問題條目須包含以下部分：

| 部分 | 內容 | 要求 |
| --- | --- | --- |
| 現象 | 使用者看到的具體表現 | 含完整錯誤資訊，不得只寫「報錯」 |
| 觸發條件 | 何時出現 | 明確版本、平臺、操作 |
| 原因 | 根本原因 | 說明機制，不止給出結論 |
| 解決方案 | 可執行步驟 | 編號列出，含命令或配置 |
| 驗證 | 如何確認已修復 | 給出預期輸出 |
| 關聯 | 相關文件或 issue 連結 | 可選 |

## 5. 條目寫法示例

```markdown
### 安裝時提示 `EACCES: permission denied`

**現象**：執行 `npm install -g <package>` 時提示許可權不足。

**觸發條件**：在 Linux 或 macOS 下以普通使用者安裝全域性包。

**原因**：全域性安裝目錄的寫許可權屬於系統管理員，當前使用者無權寫入。

**解決方案**：

```bash
mkdir -p ~/.npm-global
npm config set prefix '~/.npm-global'
export PATH=~/.npm-global/bin:$PATH
npm install -g <package>
```

**驗證**：執行 `<package> --version` 輸出版本號即成功。

## 6. 寫作要求

1. 問題標題使用使用者會搜尋的表述，而非內部術語。
2. 錯誤資訊原樣保留，便於使用者比對；敏感資訊須脫敏（見 [安全與隱私規範](./安全與隱私規範.md)）。
3. 解決方案給出完整命令，不假設使用者已設定環境變數。
4. 一個條目只解決一個問題，不合並多種原因。
5. 涉及已知缺陷時，說明影響範圍與規避方式，不承諾修復時間。
6. 與遷移相關的問題連結到遷移指南（見 [遷移指南規範](./遷移指南規範.md)）。

## 7. 維護機制

1. 同一問題被重複提問三次以上時，須新增或改寫條目。
2. 版本升級後複核全部條目，刪除已失效內容。
3. 每個條目可標註最後驗證的版本，便於判斷是否仍適用。
4. 問題索引隨條目增減同步更新。

## 8. 禁止事項

1. 禁止把故障排查文件寫成功能介紹。
2. 禁止只寫「重啟試試」等無診斷價值的答案。
3. 禁止省略錯誤資訊與觸發條件。
4. 禁止保留已修復或已失效的條目。
