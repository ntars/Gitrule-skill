# 存量專案對齊檢查清單

> 本檔案解決什麼問題：把本規範集應用到已有專案時，給出可逐項核對的檢查清單、判定方法與透過標準，覆蓋後設資料、檔案命名、章節結構、雙語同步、連結與推送六個環節。

## 1. 適用範圍

本清單用於兩類場景：

1. 首次把既有倉庫納入本規範集管理；
2. 規範集更新後，對已對齊的倉庫做迴歸核對。

清單按「先後設資料、後結構、最後推送」的順序執行。前一組未透過時不進入下一組，避免在錯誤基礎上批次改寫。

## 2. 檢查項

### 2.1 後設資料（對應 [專案命名規範](./專案命名規範.md) 第 5 節）

| 編號 | 檢查項 | 判定方法 | 透過標準 |
| --- | --- | --- | --- |
| A1 | 倉庫名合規 | 對照命名公式與字符集規則 | 全小寫、kebab-case、2–25 字元、無版本號與資訊詞 |
| A2 | 簡介為雙語合併格式 | 讀取倉庫 About 區或 `gh repo view --json description` | `国家语言 \| 英语`，豎線兩側各一個空格 |
| A3 | 簡介長度 | 按字元計數，中文與英文分別計數 | 各不超過 120 字元，合計不超過 350 字元 |
| A4 | 話題數量與語言 | `gh repo view --json repositoryTopics` | 恰好 20 個，全英文、全小寫、連字元分詞 |
| A5 | 話題覆蓋面 | 按語言、領域、形態、生態、場景五類核對 | 五類均有覆蓋，無與技術棧不符的話題 |

超限時的處置順序：先壓縮英文版本，再壓縮中文版本；壓縮時先刪修飾詞與重複限定，再合併同義表述。

### 2.2 檔案命名（對應 [多語言規範](./多語言規範.md)）

| 編號 | 檢查項 | 判定方法 | 透過標準 |
| --- | --- | --- | --- |
| B1 | 主 README 命名 | 列目錄 | 中文為 `README.md`，英語為 `README_EN.md` |
| B2 | 其他語言命名 | 列目錄 | `README_<语言码大写>.md`，如 `README_JA.md` |
| B3 | 命名一致性 | 全倉庫檢索舊名 | 不殘留 `README.en.md`、`README.ja.md` 一類舊命名 |
| B4 | 引用同步 | 檢索舊檔名 | 導航連結、目錄樹示例、指令碼內白名單均已更新 |
| B5 | 切換連結 | 開啟各語言版本首行 | 每種語言版本均可在首行切換到其餘全部語言 |

檔案重新命名必須使用 `git mv`，保留檔案歷史。倉庫內指令碼（預檢、打包、文件校驗）常以檔名字串作白名單，須同步修改，否則推送後校驗失敗。

### 2.3 章節結構（對應 [README章節規範](./README章節規範.md)）

| 編號 | 檢查項 | 判定方法 | 透過標準 |
| --- | --- | --- | --- |
| C1 | 章節齊全 | 提取二級標題與 20 章清單比對 | 20 章全部存在，無缺章 |
| C2 | 章節命名 | 逐條比對標題文字 | 與規範用詞一致，不使用「核心亮點」「設計細節與小巧思」等變體 |
| C3 | 章節順序 | 按出現順序比對 | 與規範順序一致 |
| C4 | 擴充套件章節 | 檢查是否存在額外章節 | 額外內容以「附錄」形式置於 20 章之後，不插入正文順序 |
| C5 | 語言版本對應 | 比對中英二級標題數量與順序 | 兩種語言一一對應 |

正文出現與規範不符的章節名時，以規範用詞為準統一；章節內含大量既有內容時，優先改名而不重寫正文。

### 2.4 雙語同步（對應 [多語言規範](./多語言規範.md)）

| 編號 | 檢查項 | 判定方法 | 透過標準 |
| --- | --- | --- | --- |
| D1 | 版本號一致 | 檢索版本字串 | 兩種語言寫同一版本號與狀態 |
| D2 | 數字一致 | 比對功能數、測試數、平臺數 | 同一指標在兩版數值相同 |
| D3 | 連結一致 | 比對相對連結集合 | 兩版指向同一批檔案 |
| D4 | 術語一致 | 抽查專業術語 | 同一概念在兩版使用同一譯名 |
| D5 | 結構一致 | 比對錶格與列表數量 | 章節內表格、列表數量相同 |

任一版本修改事實性內容後，另一版本須在同一提交內更新，不允許跨提交補譯。

### 2.5 連結與內容（對應 [通用寫作規範](./通用寫作規範.md)）

| 編號 | 檢查項 | 判定方法 | 透過標準 |
| --- | --- | --- | --- |
| E1 | 相對連結可達 | 逐個解析並檢查檔案是否存在 | 斷鏈數為 0 |
| E2 | 程式碼塊語言標識 | 檢索圍欄 | 全部標註語言，無裸圍欄 |
| E3 | 表格列數 | 逐表核對分隔行與資料行 | 列數一致 |
| E4 | 禁用表達 | 檢索口語詞、感嘆號、省略號、表情符號 | 無命中；引用原文時須置於引號內並標註出處 |
| E5 | 未驗證資料 | 檢索效能數字 | 每個數字均有測試環境與測試方法 |
| E6 | 承諾性表述 | 檢索「保證」「永久」「徹底」一類詞 | 技術限定語可保留，對外承諾性表述須刪除 |

### 2.6 社群檔案與推送（對應 [文件矩陣](./文件矩陣.md)、[推送與釋出規範](./推送與釋出規範.md)）

| 編號 | 檢查項 | 判定方法 | 透過標準 |
| --- | --- | --- | --- |
| F1 | 必備檔案齊備 | 列目錄 | `LICENSE`、`NOTICE`、`CONTRIBUTING.md`、`SECURITY.md` 齊備 |
| F2 | 許可與 NOTICE 一致 | 比對分層路由表 | 目錄級許可與 NOTICE 宣告一致 |
| F3 | 忽略規則 | 檢索 `.gitignore` | 構建產物、依賴目錄、`.DS_Store`、`.workbuddy/` 均被忽略 |
| F4 | 提交資訊 | 檢視 `git log` | 符合 `<type>(<scope>): <subject>` |
| F5 | 遠端一致 | 比對本地 `HEAD` 與 `origin/main` | 兩者相同，工作區乾淨 |

## 3. 多語言倉庫的附加檢查

倉庫存在三種以上語言版本時，在上述檢查之外增加三項：

1. **章節標題逐語言核對**：每種語言的 20 章標題均須與其中文或英文基準含義一致，不得出現某語言缺章；
2. **表格行數一致**：專案清單、狀態表、參數列在各語言版本中行數相同；
3. **術語表同步**：術語對照表置於雙語共用的獨立檔案，各語言版本引用同一份。

## 4. 常見錯誤與處置

| 錯誤 | 現象 | 處置 |
| --- | --- | --- |
| 批次改章節號時誤判中文數字 | 「十、」被識別為「二十、」，第 10 章被覆蓋為第 20 章標題 | 改為顯式「舊串 → 新串」一對一替換，逐條斷言命中後再寫入 |
| 只改連結路徑未改顯示文字 | 連結可點，但正文仍寫舊章節名 | 全文檢索舊章節名，路徑與顯示文字同時更新 |
| 重新命名檔案未同步指令碼 | 本地文件正常，推送後校驗指令碼報錯 | 檢索倉庫內全部檔名字串，含指令碼、配置與文件示例 |
| 雙語只改一側 | 兩版事實不一致 | 以倉庫實際狀態為準，先改主版本，再同提交改另一版本 |
| 索引頁未同步 | 新增檔案不在索引中，被判定為孤島 | 新增檔案後立即更新索引計數與條目，並複查域名計數之和 |
| 倉庫簡介與正文口徑不一致 | About 區寫七個專案，正文寫九個 | 以正文清單為準更新簡介，並在提交資訊中註明 |

元数据：A1 {{通过/不通过}} A2 {{通过/不通过}} A3 {{通过/不通过}} A4 {{通过/不通过}} A5 {{通过/不通过}}
文件命名：B1 {{ }} B2 {{ }} B3 {{ }} B4 {{ }} B5 {{ }}

## 6. 欄位定義

| 欄位 | 含義 | 取值 |
| --- | --- | --- |
| 倉庫名 | 被檢查倉庫的全名 | `所有者/仓库` |
| 規範版本 | 本次檢查依據的規範集狀態 | 提交號或版本號 |
| 透過 | 該項符合透過標準 | 布林 |
| 放行結論 | 檢查結果的處置 | 透過 / 有條件透過 / 阻斷 |
