# 硬規則

> 本檔案解決什麼問題：列出違反任意一條即阻斷推送、不允許「先推上去再改」的不可違背規則。

## 硬規則表

| # | 規則 |
|---|---|
| H1 | 倉庫名必須符合 [專案命名規範](./專案命名規範.md)，大小寫、字元、長度全部合規 |
| H2 | 必須有 `LICENSE` 檔案；無許可證 = 預設版權保留，不得公開 |
| H3 | 不得提交任何金鑰、令牌、私鑰、`.env`、雲廠商 AK/SK、資料庫連線串 |
| H4 | 不得提交構建產物、依賴目錄、IDE 配置、系統垃圾檔案 |
| H5 | 單檔案不得超過 100MB；超過 50MB 必須走 LFS 或排除 |
| H6 | 必須有 `README.md`，且包含：一句話定位、安裝、最小可執行示例、許可證 |
| H7 | 預設分支必須受保護，禁止直接 push 到 `main`/`master` |
| H8 | 禁止對公共分支使用 `git push --force`；個人分支只允許 `--force-with-lease` |
| H9 | 推送前 `build` 與 `test` 必須透過；CI 紅則不得合併入主幹 |
| H10 | 提交資訊必須符合 Conventional Commits，禁止 `wip`/`update`/`fix bug` 這類無資訊提交 |
| H11 | 每個文件獨立成檔案、獨立職責；禁止把所有內容堆進 README（見 [文件矩陣](./文件矩陣.md)） |
| H12 | 一旦金鑰已推送，必須立即輪換金鑰 + 清理歷史，不得只做刪除提交 |

## 執行約束

- 違反任意一條即 **阻斷推送**，不允許「先推上去再改」。
- H1–H12 的判定結果須體現在 [稽核報告格式](./稽核報告格式.md) 的問題清單中，每條帶證據（路徑:行 / 命令輸出）。
- 違反 H12 時按 [推送與釋出規範](./推送與釋出規範.md) 的事故處理流程執行。
