# LICENSE規範

> 本檔案解決什麼問題：定義專案許可證的 SPDX 標註、LICENSE 全文要求、版權行位置、GitHub 識別機制、分層許可的檔案佈局與確認流程，以及未經確認不得寫入的規則。

## 1. 基本規則

1. 專案許可證須以 SPDX 識別符號在 README 中明確寫出，並提供對應 LICENSE 檔案。
2. LICENSE 檔案須為該許可證官方英文全文，不得刪改條款；改寫措辭、重排段落或用 Markdown 重新排版都會導致自動識別失敗。
3. 版權行置於檔案頭部或 README 第 19 章，格式見 [README章節規範](./README章節規範.md)。

## 2. GitHub 識別機制

GitHub 用開源的 licensee 判定倉庫許可證，結果決定倉庫頁徽章、API 的 license 欄位，以及按 license 關鍵字搜尋能否命中。規則如下：

1. 只掃描兩個位置：專案根目錄，以及頂層 `LICENSES/` 目錄。`locales/`、`docs/` 等子目錄內的同名檔案不參與判定。
2. 根目錄按檔案名評分，高分優先：`LICENSE` 為 1.00，`LICENSE.md` 為 0.95，`COPYING` 為 0.90，`LICENSE-MIT` 一類帶後綴的為 0.70。
3. 頂層 `LICENSES/` 目錄內的檔案，檔案名符合 SPDX 識別符號格式且副檔名為 `.txt`、`.md`、`.markdown`、`.html` 時得 1.00，其餘為 0.00。
4. 檔案內容須與該許可證官方全文高度一致，僅有「本專案採用某某許可證」這類宣告的檔案不會被識別，被識別出的也是非標準值。
5. 識別到多個互不相同的許可證時，專案級結果可能不返回具體許可證，倉庫頁顯示為 `View license` 或 `Other`。
6. README 中的自然語言宣告不參與判定，寫了「本專案採用 MIT 許可證」不等於被識別為 MIT。

因此：**README 宣告與 LICENSE 檔案是兩套獨立機制，必須同時具備。** 且當根目錄存在多份許可證檔案時，最終報出哪一份受檔案名評分與內容匹配共同影響，不可預期，實測中雙許可證倉庫只報出其中一份。

## 3. 分層許可的檔案佈局

分層許可是指倉庫內不同部分適用不同許可證，例如程式碼用 MIT、文件用 CC BY 4.0。此時按以下順序決定佈局：

| 方案 | 根目錄放什麼 | 自動識別結果 | 適用條件 |
| --- | --- | --- | --- |
| 單層（預設） | `LICENSE` 一份 | 穩定識別為該許可證 | 各層許可證相同，或差異不影響使用者義務 |
| 分層加說明 | `LICENSE` 放主許可證，另建 `LICENSING.md` | 穩定識別為根 `LICENSE` 的許可證 | 需要分層，且希望徽章保持明確 |
| 分層加 REUSE | 頂層 `LICENSES/` 放各許可證全文 | 可能退化為非標準值 | 僅當下游明確要求 REUSE 合規 |

取捨要點：

1. 不要同時放多個根級許可證檔案。實測多個雙許可證倉庫均只被報出其中一個，另一份在倉庫頁與 API 中不可見，等於對外只宣告了一種許可。
2. REUSE 佈局與徽章明確性存在衝突：`LICENSES/` 內放多份許可證會被判為多許可證，換來 `reuse lint` 全綠，代價是自動識別結果可能不明確。二者不能同時完美滿足，須由專案方權衡。
3. 採用「分層加說明」時，`LICENSING.md` 的檔案名不含 `LICENSE` 與 `COPYING` 模式，不會被誤認為許可證檔案，不影響根 `LICENSE` 的識別。
4. 無論選哪種佈局，README 第 19 章都須寫明 SPDX 表達式（如 `MIT AND CC-BY-4.0`）與各層適用範圍，這是唯一在人工閱讀層面不丟失資訊的位置。

## 4. 分層決策與確認流程

分層許可涉及法律含義，編寫或最佳化前必須逐輪確認，禁止臆造。

1. 不得擅自分層。使用者未明確要求時按單層處理，並在報告中說明「如需分層，可選方案與差異如下」。
2. 給出分層建議時必須回報依據：各層實際覆蓋的內容範圍、候選許可證及其義務差異、對下游使用者的影響、以及自動識別結果會如何變化。
3. 寫入前至少二次確認：第一次確認分層組合（哪一層用哪個許可證），第二次確認檔案佈局（根檔案放哪份、是否建 `LICENSES/`）。
4. 推送前再次確認。生成完成後須明確告知「檔案已生成，請檢查後自行提交」，不得代替使用者提交或推送。
5. 未獲確認的候選方案只寫入報告或暫存檔案，不得落盤為 `LICENSE`、`LICENSES/`、`LICENSING.md`。
6. 無法判定某部分屬於哪一層時，標註「【待確認：分層歸屬】」並列出存疑檔案，不得預設歸類。

## 5. 免責宣告要求

許可證文字具有法律效力，模板與工具只提供判定規則與檔案佈局，不構成法律意見。

1. README 第 19 章或 `LICENSING.md` 須包含免責宣告，說明許可證選擇由專案方自行確認。
2. 免責宣告須與 NOTICE 中的免責宣告保持一致，不得一處有一處無。
3. 不得聲稱「已完成合規判定」，只能說明「已按規則檢查檔案佈局與 SPDX 標註是否齊全」。
4. 分層許可的法律效力以各許可證原文為準，倉庫內的說明文字僅作索引，不改變條款。
