# 規範選用指南

> 本檔案解決什麼問題：按專案型別、團隊規模與釋出階段給出規範的裁剪依據，提供最小可用組合與完整合規組合，使「按需取用」具備明確判定標準，而非依賴個人判斷。

本檔案裁剪的物件是整套規範；README 章節層面的型別差異見 [README分類適配指南](./README分類適配指南.md)，階段的完整對映見 [生命週期對映表](./生命週期對映表.md)。

## 1. 選用原則

1. **強制約束不可裁剪**：[硬規則](./硬規則.md) 與 [禁止事項](./禁止事項.md) 在任何專案、任何階段均完整適用。
2. **階段門禁決定下限**：進入某階段前，該階段在 [生命週期對映表](./生命週期對映表.md) 中標註的退出門禁必須透過，對應的核心規範不得省略。
3. **型別差異隻影響深度**：專案型別決定強調哪些規範、簡化哪些細節，不構成跳過質量門禁的理由。
4. **降級須顯式宣告**：私有臨時指令碼倉可僅執行 P0 門禁，但須在交付物中標註「降級模式」並列出未執行項。

## 2. 裁剪維度

| 維度 | 取值 | 主要影響 |
| --- | --- | --- |
| 專案型別 | 類庫 / SDK、應用程式、命令列工具、框架、資源合集 | 決定強化的規範與可簡化的細節 |
| 團隊規模 | 個人、小型團隊、組織 | 決定治理與協作類規範的必要性 |
| 釋出階段 | 原型驗證、首次公開、穩定維護 | 決定合規與運維類規範的引入時機 |

三個維度疊加時，按「強制約束 → 階段門禁 → 釋出階段 → 專案型別 → 團隊規模」的優先順序取值；低優先順序維度的裁剪不得削弱高優先順序維度的要求。

## 6. 組合方案

### 6.1 最小可用組合

適用於個人原型或私有驗證倉，共 10 篇：

| 用途 | 規範 |
| --- | --- |
| 約束 | [硬規則](./硬規則.md)、[禁止事項](./禁止事項.md) |
| 立項 | [專案立項與需求規範](./專案立項與需求規範.md)、[專案命名規範](./專案命名規範.md) |
| 首頁 | [README標準模板](./README標準模板.md)、[通用寫作規範](./通用寫作規範.md) |
| 工程 | [程式碼風格規範](./程式碼風格規範.md)、[提交資訊規範](./提交資訊規範.md)、[測試規範](./測試規範.md) |
| 釋出 | [推送與釋出規範](./推送與釋出規範.md)、[LICENSE規範](./LICENSE規範.md) |

使用此組合時必須在交付物中宣告降級模式，並在首次公開前補齊第 6.3 節的完整組合。

### 6.2 標準公開組合

在最小可用組合基礎上，補齊質量、合規、治理與運維的基礎項：加入 [質量門禁](./質量門禁.md)、[README章節規範](./README章節規範.md)、[README視覺排版規範](./README視覺排版規範.md)、[徽章規範](./徽章規範.md)、[文件矩陣](./文件矩陣.md)、[開源合規規範](./開源合規規範.md)、[免責宣告模板](./免責宣告模板.md)、[SECURITY模板](./SECURITY模板.md)、[貢獻指南模板](./貢獻指南模板.md)、[行為準則模板](./行為準則模板.md)、[變更日誌規範](./變更日誌規範.md)、[版本管理規範](./版本管理規範.md)、[可訪問性規範](./可訪問性規範.md)、[CI工作流規範](./CI工作流規範.md)、[Issue與PR模板規範](./Issue與PR模板規範.md)、[安全與隱私規範](./安全與隱私規範.md)。

該組合滿足公開倉庫的 Gate A、B、C 全部放行條件，是大多數專案的推薦起點。

### 6.3 完整合規組合

適用全部規範，用於組織級專案、面向監管場景分發的專案，或需要 expert / Skill / MCP / 命令列程式化接入的專案。篇數以 [簡體中文索引](./README.md) 為準，啟用時應逐項核驗 [生命週期對映表](./生命週期對映表.md) 的階段門禁。

## 7. 衝突處理

1. 同一維度內出現衝突時，以釋出階段較晚者的要求為準；原型階段的簡化不得延續至公開階段。
2. 不同維度出現衝突時，按第 2 節優先順序處理，強制約束與階段門禁不得被任何維度覆蓋。
3. 專案確有特殊情形需偏離本指南時，須在交付物中記錄偏離的規範、理由與補償措施，並提交審查。
4. 降級模式不得用於對外公開倉庫，亦不得作為跳過許可證或安全門禁的依據。
