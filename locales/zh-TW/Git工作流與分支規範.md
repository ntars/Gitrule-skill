# Git工作流與分支規範

> 本檔案解決什麼問題：定義分支模型、命名規則、拉取請求描述模板與合併策略，保證主線穩定、協作有序、變更可追溯。

## 1. 規範條文

1. 預設分支（`main` 或 `master`）須受保護，禁止直接 push（對應硬規則 H7）。
2. 所有變更經個人分支 + 拉取請求合入主幹。
3. 長期分支與短期分支須明確劃分，避免分支長期不合並。
4. 禁止對公共分支 `git push --force`；改寫個人分支用 `--force-with-lease`（對應 H8）。
5. 禁止對已推送的公共分支做 rebase/amend；合併前須透過 CI 與程式碼審查。

## 2. 分支模型

| 分支型別 | 生命週期 | 從何建立 | 合併到 | 命名格式 | 示例 |
| --- | --- | --- | --- | --- | --- |
| 預設分支 | 長期 | — | — | `main` | `main` |
| 功能分支 | 短期，≤2 周 | `main` | `main` | `feat/<简述>` | `feat/user-login` |
| 修復分支 | 短期，≤1 周 | `main` | `main` | `fix/<简述>` | `fix/token-expiry` |
| 文件分支 | 短期 | `main` | `main` | `docs/<简述>` | `docs/api-guide` |
| 釋出分支 | 中期 | `main` | `main` + tag | `release/<版本>` | `release/1.2.0` |
| 緊急修復 | 短期，≤24 小時 | 釋出 tag | `main` + tag | `hotfix/<简述>` | `hotfix/payment-error` |

命名規則：小寫 kebab-case，簡述須能表達意圖，禁止 `test`、`temp`、`wip`、`my-xxx`；關聯需求時附加需求編號，例如 `feat/spacing-rule-req001`。

## 3. 拉取請求描述模板

```markdown
## 變更目的
{{一句话说明为什么需要此变更，关联需求编号}}

## 變更內容
- {{具体改动 1}}
- {{具体改动 2}}

## 影響範圍
- 受影響模組：{{模块名}}
- 是否破壞相容：{{是 / 否；是则给出迁移说明}}
- 是否涉及配置或資料遷移：{{是 / 否；是则说明}}

## 驗證方式
- 自測命令：{{命令}}
- 新增或修改的測試：{{TC 编号}}
- CI 執行地址：{{URL}}

## 關聯
- 需求：{{REQ-NNN}}
- 追蹤矩陣：{{已更新 / 待更新}}
- 文件：{{docs/api.md#章节 / 无}}
- Issue：{{#编号 / 无}}

## 自查
- [ ] 提交資訊符合規範
- [ ] 未包含敏感資訊
- [ ] 已更新需求追蹤矩陣
- [ ] 破壞性變更已寫入變更日誌
```

## 4. 欄位定義

| 欄位 | 必填 | 型別 | 填寫要點 | 示例 |
| --- | --- | --- | --- | --- |
| 分支簡述 | 是 | kebab-case | 能獨立表達意圖，禁止無資訊詞 | `spacing-rule` |
| 關聯需求 | 是 | `REQ-NNN` | 與立項編號一致 | `REQ-001` |
| 變更目的 | 是 | 文字 | 說明「為什麼」，不是「改了什麼」 | `修复中文标点误报` |
| 影響範圍 | 是 | 文字 | 須明確是否破壞相容 | `否` |
| 自測命令 | 是 | 命令 | 可複製執行 | `npm test -- -t spacing` |
| 測試編號 | 是 | `TC-NNN` | 與測試規範編號一致 | `TC-001` |
| CI 地址 | 是 | URL | 便於審查者核對 | `https://github.com/.../runs/123` |
| 自查清單 | 是 | 勾選 | 逐項勾選，禁止整段一次勾完 | — |

## 5. 填寫說明

1. **分支生命週期**：超過 2 周未合併的功能分支須在迭代回顧中說明原因並拆分或關閉。
2. **簡述命名**：從變更目的中取核心名詞 + 動作，禁止使用 `fix2`、`new-feature` 等模糊名。
3. **變更目的**：寫問題與價值；「更新程式碼」「最佳化邏輯」不合格。
4. **影響範圍**：勾選破壞相容時，須同時在變更日誌中標註 `BREAKING CHANGE:`。
5. **自測命令**：審查者應能直接複製執行並得到相同結論；步驟複雜的寫指令碼路徑。
6. **追蹤矩陣**：PR 合併前須更新 [需求追蹤矩陣規範](./需求追蹤矩陣規範.md) 中的實現 PR 與狀態欄位。
7. **force push**：僅對未被他人審查的本人分支使用 `--force-with-lease`，且須在 PR 中說明原因。

常見錯誤：

| 錯誤寫法 | 問題 | 修正方式 |
| --- | --- | --- |
| 分支名 `test`、`temp` | 無意圖資訊 | 改為 `feat/<具体能力>` |
| PR 描述只寫「修復 bug」 | 無法審查影響 | 補目的、影響、驗證方式 |
| 直接向 `main` push | 違反 H7 | 走 PR 合併 |
| 改寫已審查分支後強推 | 審查結論失效 | 新增提交回應意見 |
| 合併後不刪除源分支 | 分支列表膨脹 | 合併後立即刪除 |

## 6. 完整示例

```markdown
## 變更目的
修復中文標點緊鄰英文單詞時空格規則誤報的問題（REQ-004）。

## 變更內容
- 規則引擎增加標點邊界判斷
- 新增對應迴歸用例

## 影響範圍
- 受影響模組：spacing 規則
- 是否破壞相容：否
- 是否涉及配置或資料遷移：否

## 驗證方式
- 自測命令：`npm test -- -t "中文标点"`
- 新增或修改的測試：TC-007-regression-142
- CI 執行地址：https://github.com/example/markdown-lint-cli/actions/runs/128

## 關聯
- 需求：REQ-004
- 追蹤矩陣：已更新
- 文件：無
- Issue：#142

## 自查
- [x] 提交資訊符合規範
- [x] 未包含敏感資訊
- [x] 已更新需求追蹤矩陣
- [x] 破壞性變更已寫入變更日誌（本變更無破壞性）
```
