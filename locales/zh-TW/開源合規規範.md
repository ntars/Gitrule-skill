# 開源合規規範

> 本檔案解決什麼問題：定義開源合規的採集範圍、依賴清單欄位、採集方法、許可證相容性判斷、修改標註與素材引用規則，保證宣告完整、可核查。

## 1. 採集範圍

須覆蓋四類來源：直接依賴、間接與傳遞依賴、構建與開發工具鏈、素材資源（圖示、字型、圖片、音訊、資料集、演算法來源）。

## 2. 依賴清單欄位

| 欄位 | 要求 |
| --- | --- |
| 元件名稱 | 與官方倉庫一致 |
| 版本 | 實際鎖定版本，非範圍表示式 |
| 引用方式 | 直接依賴或間接依賴 |
| 版權方 | 官方宣告的著作權人全稱 |
| 許可證 | SPDX 識別符號，多許可證須寫明組合方式 |
| 官方地址 | 倉庫或主頁完整 URL |
| 本專案用途 | 具體呼叫位置或功能 |
| 是否修改 | 是或否 |
| 修改說明 | 修改檔案、修改內容、修改原因；未修改填「無」 |
| 許可證原文位置 | 專案內路徑或檔案連結 |

依賴清單表格模板見 [資訊採集與模板](./資訊採集與模板.md)。

## 3. 採集方法

按技術棧使用對應命令生成依賴樹，再逐項補全許可證與版權資訊：`npm ls --all`、`pip freeze`、`go mod graph`、`cargo tree`、`mvn dependency:tree`、`gradle dependencies`、`composer show --tree`。許可證掃描可使用 `license-checker`、`pip-licenses`、`cargo-license` 等工具，掃描結果須人工複核，工具輸出不得直接作為最終結論。

## 4. 許可證相容性

1. 須判斷專案許可證與各依賴許可證的相容性，重點核查 GPL、AGPL、LGPL、MPL 的傳染性範圍。
2. Apache-2.0 依賴須確認其 NOTICE 檔案要求是否已被滿足。
3. 素材類許可證（如 SIL OFL 字型、CC 系列）須單獨核查署名與傳播要求。
4. 無法判定相容性時，標註「【待確認：許可證相容性】」並說明存疑原因。
5. 專案採用分層許可時，須逐層判斷：某依賴被用於哪一層，就按該層的許可證判定相容性，不得用主許可證代表全倉庫。分層佈局與確認流程見 [LICENSE規範](./LICENSE規範.md)。
6. 當同一依賴橫跨多個許可層時，標註該依賴的實際使用範圍，並按最嚴格的適用層判定。

## 5. 修改他人程式碼的標註

1. 在檔案頭部保留原始版權宣告與許可證宣告。
2. 在 NOTICE 中列明修改檔案路徑、修改內容摘要、修改日期。
3. 在 README 對應章節同步說明。

## 6. 引用與素材

1. 引用他人文件或程式碼片段須註明來源地址、作者、許可證。
2. 圖片、圖示、字型須記錄來源與許可證，缺失時標註待確認，不得直接使用。
3. 不得使用來源不明的素材。
