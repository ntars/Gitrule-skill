# NOTICE規範

> 本檔案解決什麼問題：定義 NOTICE 檔案必須包含的七部分、與 README 的一致性要求，確保第三方宣告獨立成檔案且資訊準確。

## 1. 獨立成檔案

NOTICE 獨立成檔案，不得與 README 合併，也不得以 README 列表替代。須包含以下部分：

1. **專案自身宣告**：專案名稱、著作權人、年份、許可證、SPDX 識別符號。
2. **第三方元件清單**：按 [開源合規規範](./開源合規規範.md) 的依賴清單欄位逐項列出。
3. **許可證原文附錄**：許可證要求附全文的，須逐份附上原文；原文保持英文，不翻譯。
4. **修改宣告**：對第三方程式碼的修改位置與內容。
5. **素材與資料來源宣告**。
6. **免責宣告**：保留英文原文，可以附中文對照。
7. **待確認事項**：無法核實許可證或版權歸屬的條目，顯式標註「待確認」。

## 2. 一致性要求

NOTICE 與 README 第 6 章（技術棧與依賴清單）、第 19 章（版權與許可）、第 20 章（NOTICE 合規宣告）的元件與許可證資訊須完全一致，版本、許可證標識、版權方不得出現差異。

## 3. 分層許可的宣告方式

專案採用分層許可時，第 1 節的「專案自身宣告」須按層拆分，不得只寫主許可證。

1. 每一層單獨一行，寫明：適用範圍（如「`cli/`、`mcp/` 下的原始碼」）、許可證名稱、SPDX 識別符號、許可證全文位置。
2. 各層合起來的 SPDX 表達式須與 README 第 19 章逐字一致，不得一處寫 `MIT AND CC-BY-4.0`、另一處只寫 `MIT`。
3. 須寫明分層依據的一句話說明，例如「程式碼與文件的複用訴求不同」，便於後續維護者判斷某檔案歸屬哪一層。
4. 存在無法歸層的內容時，在「待確認事項」中列出檔案路徑，不得預設計入主許可證。
5. 免責宣告須與 README 第 19 章、`LICENSING.md`（若存在）三處措辭一致，說明許可證選擇與分層劃分由專案方自行確認，工具與模板不構成法律意見。
