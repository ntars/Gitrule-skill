# SECURITY模板

> 本檔案解決什麼問題：提供一份可直接複製的安全政策模板，供專案生成 SECURITY.md，明確支援版本、漏洞上報渠道、響應流程與披露原則；配套的填寫說明覆蓋上報渠道選型與敏感資訊處理。

## 1. 使用說明

1. 複製第 3 節「模板正文」全部內容，新建為專案根目錄的 `SECURITY.md`。
2. 按第 4 節替換佔位符；上報渠道必須為真實可達且不公開暴露攻擊面的地址。
3. 按第 5 節場景變體裁剪：無多版本維護的專案刪除支援版本表中的舊版本行。
4. 安全規則與敏感資訊要求見 [安全與隱私規範](./安全與隱私規範.md)；社群治理維度見 [稽核維度矩陣](./稽核維度矩陣.md)。

## 2. 定製原則

- **私有渠道優先**：漏洞上報走私有渠道，禁止要求報告者在公開議題中披露細節。
- **時效明確**：給出首次響應與修復的時間範圍，避免無限期承諾。
- **資訊最小化**：要求報告者提供復現所需最小資訊，禁止提交真實生產資料。
- **法律一致**：披露原則須與適用法律和平臺政策一致，涉監管行業須經法務審定。

## 3. 模板正文

```markdown
# 安全政策

> 本檔案說明 {{项目名称}} 的安全支援範圍與漏洞上報方式，適用於安全研究人員、貢獻者與使用者。

## 支援版本

| 版本 | 是否接受安全報告 |
| --- | --- |
| {{当前版本}} | 是 |
| {{上一版本}} | {{是否接受}} |
| 更早版本 | 否 |

## 上報渠道

請勿透過公開議題、討論區或社交渠道報告安全漏洞。請透過以下私有渠道提交：

- 安全郵箱：{{真实可达的安全邮箱}}
- 私有報告入口：{{私有漏洞报告地址}}

如無上述渠道，請透過 {{备用私有联系方式}} 聯絡維護者。

## 報告內容

為提高處理效率，請儘可能提供：

- 受影響版本與元件；
- 漏洞型別與潛在影響；
- 最小復現步驟或概念驗證；
- 建議的修復方向（可選）。

請勿提交真實的生產資料、金鑰或個人身份資訊。

## 響應流程

| 階段 | 時間範圍 | 說明 |
| --- | --- | --- |
| 確認收到 | {{首次响应时限}} | 維護者確認報告已收到 |
| 初步評估 | {{评估时限}} | 判斷是否屬於安全問題及影響範圍 |
| 修復與驗證 | {{修复时限}} | 完成修復並驗證，複雜問題另行協商 |
| 公開發布 | 修復完成後 {{发布延迟}} | 釋出安全公告與修復版本 |

## 披露原則

- 維護者將對報告者身份與報告內容保密，直至修復釋出。
- 未經維護者同意，報告者不得在修復釋出前公開漏洞細節。
- 修復釋出後，維護者將在安全公告中致謝報告者（經報告者同意）。
- 善意、符合本政策的安全研究不會被追究責任。

## 例外與免責

本政策不構成對任何安全保證的承諾，專案內容按「現狀」提供，詳見 [免責宣告](./DISCLAIMER.md) 與 [LICENSE](./LICENSE)。
```

## 4. 佔位符對照表與欄位定義

| 佔位符 | 必填 | 欄位定義 | 填寫示例 |
| --- | --- | --- | --- |
| `{{项目名称}}` | 是 | 專案對外名稱 | `FooBar` |
| `{{当前版本}}` | 是 | 正在維護的最新版本或 `main` | `v2.3.0` |
| `{{上一版本}}` | 否 | 仍在維護的上一版本 | `v2.2.x` |
| `{{是否接受}}` | 是 | 該版本是否接受安全報告 | `是` |
| `{{真实可达的安全邮箱}}` | 是 | 專用於安全報告的郵箱 | `security@example.com` |
| `{{私有漏洞报告地址}}` | 是 | 私有報告入口 | `https://github.com/owner/repo/security/advisories/new` |
| `{{备用私有联系方式}}` | 否 | 主渠道不可用時的備用方式 | `通过维护者账号私信` |
| `{{首次响应时限}}` | 是 | 確認收到報告的時間範圍 | `3 个工作日` |
| `{{评估时限}}` | 是 | 完成初步評估的時間範圍 | `7 个工作日` |
| `{{修复时限}}` | 是 | 完成修復的時間範圍 | `30 日` |
| `{{发布延迟}}` | 是 | 修復後公開發布的間隔 | `7 日` |

## 5. 填寫說明與場景變體

| 場景 | 必留章節 | 可裁剪章節 | 調整要點 |
| --- | --- | --- | --- |
| 單版本專案 | 上報渠道、報告內容、響應流程、披露原則 | 支援版本表刪除舊版本行 | 當前版本寫 `main` 或最新 tag |
| 多版本維護 | 全部 | 無 | 逐行列出仍接受報告的版本 |
| 個人專案 | 全部 | 支援版本可精簡 | 私有渠道用長期持有的郵箱 |
| 企業專案 | 全部 | 無 | 時限須與內部安全制度一致，經法務審定 |
| 受監管行業 | 全部 | 無 | 增補合規通報義務與資料留存要求 |

常見錯誤對照：

| 錯誤寫法 | 後果 | 正確寫法 |
| --- | --- | --- |
| 「請在 Issue 中報告漏洞」 | 公開披露細節，擴大風險 | 使用私有渠道 |
| 「我們會盡快處理」 | 無明確預期，報告者無法判斷 | 分階段給出時間範圍 |
| 時限寫「24 小時內修復」 | 承諾過度，無法兌現 | 寫合理範圍並註明複雜問題另行協商 |
| 未要求脫敏 | 報告者可能提交真實生產資料 | 明確禁止提交真實資料與金鑰 |

## 6. 完整示例

以下為上報渠道段落的填好示例，僅作格式參考。

```markdown
## 上報渠道

請勿透過公開議題、討論區或社交渠道報告安全漏洞。請透過以下私有渠道提交：

- 安全郵箱：security@example.com
- 私有報告入口：https://github.com/example/democli/security/advisories/new

請勿提交真實的生產資料、金鑰或個人身份資訊。
```
