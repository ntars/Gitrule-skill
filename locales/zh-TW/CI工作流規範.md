# CI工作流規範

> 本檔案解決什麼問題：定義 `.github/workflows/*.yml` 持續整合工作流的觸發條件、任務拆分、快取策略與安全配置，使構建、測試與檢查可復現、可審計。

## 1. 設計原則

1. **單一職責**：每個工作流只負責一類目標（構建、測試、釋出、文件部署），不得把釋出與測試混在一個工作流中。
2. **快速反饋**：輕量檢查（lint、格式）在前，耗時任務（完整測試矩陣）在後。
3. **可復現**：鎖定依賴版本，使用固定版本的 Actions，快取僅用於加速不改變結果。
4. **最小許可權**：工作流按任務授予許可權，預設只讀，釋出任務單獨提權（見 [安全與隱私規範](./安全與隱私規範.md)）。

## 2. 檔案結構

### 2.1 命名與路徑

- 路徑固定為 `.github/workflows/*.yml`。
- 檔名用小寫與連字元，按職責命名，如 `ci.yml`、`release.yml`、`docs.yml`。
- 工作流 `name` 欄位須與檔名語義一致。

### 2.2 必備區塊

| 區塊 | 作用 | 要求 |
| --- | --- | --- |
| `name` | 工作流顯示名稱 | 簡明，能讀出職責 |
| `on` | 觸發條件 | 明確分支、路徑或事件 |
| `permissions` | 許可權宣告 | 顯式宣告，預設最小 |
| `jobs` | 任務集合 | 按職責拆分 |

### 2.3 觸發條件設計

| 觸發事件 | 適用 | 注意 |
| --- | --- | --- |
| `push` | 主幹與釋出分支 | 限制分支範圍，避免全分支觸發 |
| `pull_request` | 所有 PR | 保證合入前檢查 |
| `workflow_dispatch` | 手動觸發 | 用於釋出、回滾等受控操作 |
| `schedule` | 定時任務 | 用於依賴更新檢查、夜間構建 |
| `release` | 釋出後動作 | 用於產物上傳與公告 |

## 3. 任務拆分

推薦的階段順序：

1. **靜態檢查**：格式、lint、型別檢查。
2. **構建**：產出構建物，供後續任務複用。
3. **測試**：單元測試、整合測試，可按矩陣並行。
4. **產物校驗**：檢查構建物大小、簽名或完整性。
5. **釋出**：僅在 CI 全綠且條件滿足時執行（見 [推送與釋出規範](./推送與釋出規範.md)）。

任務間透過 `needs` 宣告依賴，保證失敗即中斷，不得讓後續任務在失敗狀態下繼續。

## 4. 矩陣構建

使用 `strategy.matrix` 覆蓋多版本、多平臺：

```yaml
strategy:
  fail-fast: false
  matrix:
    os: [ubuntu-latest, macos-latest, windows-latest]
    node-version: [18, 20, 22]
```

要求：

- 版本覆蓋專案宣告支援的最低與最新版本（見 [相容性說明](./README章節規範.md) 第 14 章）。
- `fail-fast` 設為 `false`，使各組合完整執行，便於定位相容性問題。
- 矩陣維度不超過三個，避免組合爆炸。

## 5. 快取策略

| 快取物件 | 鍵值建議 | 注意 |
| --- | --- | --- |
| 依賴目錄 | 包管理器鎖檔案雜湊 | 鎖檔案變更即失效 |
| 構建產物 | 原始碼與配置雜湊 | 與構建輸入一致 |
| 工具鏈 | 版本號 | 版本升級即失效 |

快取只加速，不改變構建結果；快取命中時仍須執行完整測試。

## 6. 安全配置

1. 金鑰透過倉庫 Secrets 注入，禁止寫入工作流檔案或日誌。
2. 每個工作流顯式宣告 `permissions`，預設 `contents: read`。
3. 第三方 Action 引用固定版本或提交雜湊，避免浮動標籤。
4. PR 來自 Fork 時，禁止注入 Secrets，防止提權攻擊。
5. 釋出任務與主檢查分離，僅在受保護分支或 tag 觸發。

## 7. 狀態徽章

工作流應為 README 提供狀態徽章，格式為：

```markdown
[![CI](https://github.com/{owner}/{repo}/actions/workflows/ci.yml/badge.svg)](https://github.com/{owner}/{repo}/actions/workflows/ci.yml)
```

徽章引數與排列見 [徽章規範](./徽章規範.md)。

## 8. 禁止事項

1. 禁止在工作流中硬編碼金鑰或內部地址。
2. 禁止使用 `continue-on-error` 掩蓋測試失敗。
3. 禁止對同一條件配置多個相互衝突的觸發規則。
4. 禁止在主幹檢查未透過時執行釋出。
