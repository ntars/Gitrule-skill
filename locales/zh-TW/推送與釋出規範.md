# 推送與釋出規範

> 本檔案解決什麼問題：定義推送前/中/後的動作清單、tag 與釋出規則、事故處理流程，以及完整的 GitHub 推送指引與失敗處置矩陣。

## 1. 推送前

1. `git status` 乾淨，無未跟蹤的敏感檔案。
2. `git log` 無 WIP、無 `fix bug`、無個人資訊洩漏。
3. 確認 `.gitignore` 生效，產物與依賴未被跟蹤。
4. 本地透過 build、test 與 lint。
5. 執行全量金鑰掃描（含歷史提交）。
6. 文件矩陣齊備（見 [文件矩陣](./文件矩陣.md)）。

## 2. 推送動作

7. 推個人分支：`git push -u origin feat/xxx`。
8. 主幹只走 PR，不直接 push。
9. 禁止 `push --force`；改寫自己分支用 `--force-with-lease`。
10. 禁止對已推送的公共分支做 rebase/amend。
11. 單檔案 >50MB 先走 LFS 再推。
12. 首次推送前確認倉庫可見性：預設 private，確需公開再切 public。

## 3. tag 與釋出

13. tag 格式 `vMAJOR.MINOR.PATCH`，必須 annotated：`git tag -a v1.0.0 -m "release: 1.0.0"`。
14. tag 只在 CI 綠、Release Notes 就緒後打。
15. 破壞性變更必須 `feat!:` 或 `BREAKING CHANGE:`，並在 CHANGELOG 給出遷移方式。

## 4. Phase 6 · 推送後（Post-Push）

- 打 annotated tag；
- 寫 Release Notes；
- 校驗徽章與連結可用；
- 確認 CI 綠；
- 確認 About 區資訊正確（description / topics / 連結 / social preview）。

## 5. 事故處理

16. **金鑰已推送**：立即輪換 → `git filter-repo` 清理 → 強推保護分支需走管理員流程 → 公告。
17. **誤推大檔案**：LFS 遷移或歷史重寫，不得只刪檔案。

## 6. GitHub 推送指引規範

指引須包含以下七部分，命令給出完整可執行版本。

### 6.1 前置安全

1. 推送前須完整備份本地倉庫與遠端倉庫，推薦 `git clone --mirror` 生成映象備份。
2. 確認遠端倉庫無協作者，或已通知協作者暫停推送。
3. 確認目標分支未啟用強制推送保護。

### 6.2 本地整理

```bash
git status
git diff --name-status HEAD
git ls-files
```

核對三項輸出，確認待提交變更與本地目錄一致，無臨時檔案、構建產物、舊版文件殘留。`.gitignore` 須覆蓋構建產物與本地配置檔案。

### 6.3 一致性核對

```bash
git fetch origin
git diff --name-status HEAD origin/{{分支名}}
```

該命令列出遠端與本地檔案差異。遠端存在而本地已刪除的檔案，須在本地執行 `git rm` 後提交，使刪除動作進入版本歷史。

### 6.4 提交與推送

```bash
git add -A
git commit -m "docs: 重建项目文档（README、README_EN、NOTICE）"
git push --force-with-lease origin {{分支名}}
```

採用 `--force-with-lease` 而非 `--force`，在遠端存在他人新提交時拒絕推送，避免覆蓋他人工作。刪除遠端倉庫後重建屬於高風險操作，僅在個人倉庫且已完成映象備份時使用，指引中須顯式標註資料丟失風險。

### 6.5 推送後驗證

```bash
git ls-remote --heads origin
gh repo view --web
```

在網頁端逐項確認檔案列表、README 渲染、語言切換連結、NOTICE 連結有效。

### 6.6 失敗處置矩陣

| 錯誤型別 | 典型表現 | 處置方案 | 風險提示 |
| --- | --- | --- | --- |
| 認證失敗 | `Authentication failed`、`Permission denied (publickey)` | 由 HTTPS 切換為 SSH 並配置金鑰，或使用 `gh auth login` 後推送 | 無 |
| 網路中斷 | `Failed to connect`、`RPC failed` | 更換網路、配置代理、執行 `git config --global http.postBuffer 524288000` | 無 |
| 檔案超限 | `remote: error: File exceeds 100 MB` | 從提交歷史移除大檔案或啟用 Git LFS | 改寫歷史後須通知協作者重新克隆 |
| 大小寫衝突 | 檔名大小寫不一致導致重複條目 | 使用 `git mv` 修正並提交 | 無 |
| 歷史衝突 | `non-fast-forward`、`fetch first` | 優先 `git pull --rebase`；確需覆蓋時使用 `--force-with-lease` | 覆蓋他人提交不可恢復 |
| 分支保護 | `protected branch hook declined` | 透過 PR 流程合併，或由管理員臨時調整規則 | 調整規則須記錄 |
| 倉庫損壞 | `fatal: not a git repository`、物件缺失 | 重新克隆後複製工作區改動 | 須先備份工作區 |

### 6.7 回滾

推送完成後如發現問題，使用 `git revert` 生成反向提交；不得再次強制推送覆蓋已公開的歷史。
