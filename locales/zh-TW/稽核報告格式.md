# 稽核報告格式

> 本檔案解決什麼問題：定義稽核報告的唯一交付格式、欄位要求與填寫示例，確保報告可被另一個 agent 直接執行。

報告是稽核環節的唯一交付物。每條問題須同時具備證據、責任方與動作；無法執行的結論不得寫入報告。

## 1. 報告骨架

````markdown
# 推送稽核報告 · {{仓库名}}

結論：{{结论}}
模式：{{模式}}
倉庫：{{仓库名}} · {{可见性}} · {{许可证}} · 預設分支 {{默认分支}}

## 一、門禁狀態
| 門 | 狀態 | 未決項 |
| --- | --- | --- |
| A 安全 | {{门禁状态}} | {{未决项}} |
| B 質量 | {{门禁状态}} | {{未决项}} |
| C 首頁 | {{门禁状态}} | {{未决项}} |

## 二、問題清單
| 等級 | 維度 | 問題 | 證據（路徑:行 / 命令輸出） | 責任 agent | 動作 |
| --- | --- | --- | --- | --- | --- |
| {{等级}} | {{维度}} | {{问题}} | {{证据}} | {{责任agent}} | {{动作}} |

## 三、文件矩陣狀態
| 檔案 | 狀態 | 缺失/待改項 |
| --- | --- | --- |
| {{文件路径}} | {{状态}} | {{待改项}} |

## 四、推送執行清單
- [ ] {{推送规则}}

## 五、放行說明
{{放行说明}}
````

## 2. 欄位定義

| 欄位 | 必填 | 型別 | 填寫要點 | 示例 |
| --- | --- | --- | --- | --- |
| 倉庫名 | 是 | 文字 | 與 GitHub 倉庫名逐字一致 | `markdown-lint-cli` |
| 結論 | 是 | 列舉 | 僅 `ALLOW PUSH` 或 `BLOCK PUSH`；P0 未清零必須為後者 | `BLOCK PUSH` |
| 模式 | 是 | 列舉 | 私有臨時指令碼倉可寫「降級稽核」，其餘為「完整稽核」 | `完整审核` |
| 可見性 | 是 | 列舉 | `private` / `public`；公開前須複核許可證 | `private` |
| 許可證 | 是 | SPDX 識別符號 | 無許可證寫 `NONE`，此時結論必須為 `BLOCK PUSH` | `MIT` |
| 預設分支 | 是 | 文字 | 寫實際分支名，不寫假定的 `main` | `main` |
| 門禁狀態 | 是 | 列舉 ×3 | A/B/C 各一行；`SKIP` 須在「未決項」註明原因 | `FAIL` |
| 未決項 | 條件必填 | 文字 | 狀態為 `FAIL` 或 `SKIP` 時必填，列出阻斷或跳過原因 | `D1 检出 .env` |
| 等級 | 是 | 列舉 | `P0` 阻斷 / `P1` 推送前修或登記 / `P2` 建議 | `P0` |
| 維度 | 是 | `D1`–`D14` | 編號見 [稽核維度矩陣](./稽核維度矩陣.md) | `D1` |
| 問題 | 是 | 文字 | 一句陳述事實，不寫推測或情緒化表述 | `根目录存在 .env` |
| 證據 | 是 | 路徑:行 或命令輸出 | 必須可複核；無法取證寫 `SKIP + 原因` | `.env:3` |
| 責任 agent | 是 | agent 名稱 | 寫具體執行角色，不寫「相關人員」 | `security-auditor` |
| 動作 | 是 | 文字 | 可直接執行的操作，含目標檔案 | `删除 .env、轮换密钥并清理历史` |
| 檔案路徑 | 是 | 文字 | 按 [文件矩陣](./文件矩陣.md) 的清單逐項列出 | `SECURITY.md` |
| 文件矩陣狀態 | 是 | 表格逐行 | 逐檔案標註存在、缺失或待改 | `SECURITY.md 缺失` |
| 推送執行清單 | 是 | 核取方塊列表 | 按 [推送與釋出規範](./推送與釋出規範.md) 的規則逐條展開 | `- [ ] 确认 .gitignore 生效` |
| 放行說明 | 是 | 文字 | 阻斷時寫原因與解除條件；放行時寫已滿足的硬規則 | `P0 清零后可复核` |

## 3. 填寫說明

1. **結論優先**：先判定 P0 數量，再寫結論。任一 P0 未清零時不得輸出 `ALLOW PUSH`。
2. **證據強制**：每條問題必須有 `路径:行号` 或可複製的命令輸出。無證據的結論標 `SKIP` 並寫明原因，不得寫 `PASS`。
3. **責任到角色**：責任 agent 使用 [稽核維度矩陣](./稽核維度矩陣.md) 中的角色名，一項問題對應一個責任方。
4. **動作可執行**：動作須指明目標檔案與操作型別；「後續處理」「自行調整」視為無效。
5. **門禁一致**：A/B/C 三行狀態與問題清單對應；任一門為 `FAIL` 時結論必須為 `BLOCK PUSH`。
6. **文件矩陣逐項**：按清單逐檔案列出，不得只寫「文件基本齊備」。
7. **清單展開**：推送執行清單須逐條展開規則，不得用「按規範執行」代替。

常見錯誤：

| 錯誤寫法 | 問題 | 修正方式 |
| --- | --- | --- |
| 證據欄寫「疑似有問題」 | 無路徑、無輸出，不可複核 | 補 `文件路径:行号` 或命令輸出 |
| P0 未清零卻寫 `ALLOW PUSH` | 違反硬規則 | 改為 `BLOCK PUSH`，列明解除條件 |
| 無法檢查的項寫 `PASS` | 編造結果 | 寫 `SKIP` 並在未決項註明原因 |
| 責任方寫「相關人員」 | 無責任主體 | 寫具體 agent 名稱 |
| 動作寫「後續處理」 | 不可執行 | 寫明目標檔案與具體操作 |
| 預設分支寫 `main` 而未核實 | 與實際不符 | 以 `git branch` 輸出為準 |

## 4. 完整示例

以下為 `BLOCK PUSH` 的完整填寫示例：

````markdown
# 推送稽核報告 · markdown-lint-cli

結論：BLOCK PUSH
模式：完整稽核
倉庫：markdown-lint-cli · private · NONE · 預設分支 main

## 一、門禁狀態
| 門 | 狀態 | 未決項 |
| --- | --- | --- |
| A 安全 | FAIL | D1 檢出 .env、D2 無 LICENSE |
| B 質量 | SKIP | 倉庫未安裝依賴，構建與測試無法執行 |
| C 首頁 | FAIL | README 缺安裝章節與最小示例 |

## 二、問題清單
| 等級 | 維度 | 問題 | 證據（路徑:行 / 命令輸出） | 責任 agent | 動作 |
| --- | --- | --- | --- | --- | --- |
| P0 | D1 | 根目錄存在 .env | `.env:3` 含 DATABASE_URL | security-auditor | 刪除 .env、輪換資料庫憑據並清理歷史 |
| P0 | D2 | 無許可證檔案 | `ls LICENSE` 輸出 `No such file or directory` | license-checker | 由倉庫所有者確認許可證後生成 LICENSE |
| P1 | D13 | README 缺安裝章節 | `README.md:1-28` 無「安裝」標題 | readme-writer | 按 README標準模板補寫安裝與最小示例 |

## 三、文件矩陣狀態
| 檔案 | 狀態 | 缺失/待改項 |
| --- | --- | --- |
| README.md | 待改 | 缺安裝章節與最小示例 |
| LICENSE | 缺失 | 待所有者確認許可證型別 |
| SECURITY.md | 缺失 | 尚未建立 |

## 四、推送執行清單
- [ ] 確認 git status 乾淨
- [ ] 執行全量金鑰掃描（含歷史提交）
- [ ] 本地透過 build、test 與 lint
- [ ] 文件矩陣齊備

## 五、放行說明
阻斷原因：存在 2 項 P0（憑據洩漏、無許可證），且質量門因依賴未安裝無法判定。解除條件：完成金鑰輪換與歷史清理、確定許可證、在可構建環境重跑測試並清零 P0 後複核。
````

`ALLOW PUSH` 時第五節可寫：「已滿足全部硬規則，三層門禁均為 PASS，可執行推送。」其餘各節按實際情況填寫，不得省略證據與清單。

## 5. 交付順序

1. 根 README 語言導航完整內容。
2. 各已完成語言目錄的 README 完整內容，逐個列出語言碼與檔案路徑。
3. NOTICE 檔案內容。
4. LICENSE 方案說明（如使用者未指定許可證，只給候選與差異，不直接生成）。
5. 待確認事項彙總。
6. 稽核報告（本報告）。
7. GitHub 推送指引。
