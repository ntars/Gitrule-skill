# README分類適配指南

> 本檔案解決什麼問題：針對類庫、應用程式、命令列工具、框架、資源合集等不同專案型別，給出 README 章節取捨、視覺側重與徽章配置的差異化建議，並說明每類元素如何提升美觀度與吸引力。

通用模板適用於所有專案，但不同型別專案的讀者關注點不同。本檔案在通用規範之上給出面向型別的調整建議。讀者應以 [README標準模板](./README標準模板.md) 為基礎，按本檔案對應型別裁剪。

## 1. 型別總覽

| 型別 | 讀者首要問題 | 首頁重心 | 必備章節 | 可省略章節 |
| --- | --- | --- | --- | --- |
| 類庫 / SDK | 安裝方式與 API 用法 | 版本與許可證 | 安裝、快速開始、API、相容性 | 部署、截圖 |
| 應用程式 | 應用外觀與核心功能 | 截圖與功能 | 功能、截圖、安裝、快速開始 | API 參考 |
| 命令列工具 | 命令用法與效能 | 命令示例與 Demo | 安裝、用法、命令對照、Demo | 架構、配置（少時） |
| 框架 | 生態與學習成本 | 文件入口與示例 | 定位、快速開始、文件、社群 | 效能細節（可外鏈） |
| 資源合集 | 收錄什麼、如何檢索 | 目錄分類與導航 | 目錄、分類、貢獻指南 | 安裝、API |

## 2. 類庫 / SDK

典型代表：axios 等 HTTP 客戶端、工具函式庫、客戶端 SDK。

### 2.1 章節取捨

- 前置「一句話定位 + 版本 + 許可證」，讀者據此判斷相容性。
- 「安裝」置於最前，給出包管理器命令（npm、pip、cargo 等）。
- 「快速開始」必須是一個可獨立執行的完整示例。
- 「API 參考」詳列在主 README 或連結至 `docs/api.md`；API 條目過多時，README 只放摘要 + 連結。
- 「相容性」說明支援的語言版本、執行時、平臺。

### 2.2 視覺側重

- 徽章重點：版本、構建狀態、許可證、下載量、包大小。
- 圖片使用剋制，通常無需截圖；可用小型 Logo 建立識別。
- API 引數用表格呈現，提升可讀性。

### 2.3 美觀度提升要點

1. 版本與許可證徽章置頂，Instantly 建立可信度。
2. 快速開始程式碼塊位於首屏附近，降低嘗試門檻。
3. API 表格統一列寬與預設值列，減少認知負擔。

## 3. 應用程式

典型代表：編輯器、桌面工具、面向終端使用者的產品。

### 3.1 章節取捨

- 首屏必須包含產品截圖或執行畫面，先展示價值再講實現。
- 「核心功能」以使用者場景組織，而非技術模組。
- 「安裝」覆蓋各平臺安裝包或下載入口。
- 「快速開始」給出最短入門路徑。
- 原始碼構建說明可外鏈至 `CONTRIBUTING.md`。

### 3.2 視覺側重

- 徽章重點：版本、構建狀態、許可證、下載量。
- 截圖置於定位之後，是首頁的核心元素。
- 功能列表配合圖示或短截圖，提升掃描效率。

### 3.3 美觀度提升要點

1. 高質量產品截圖居中展示，深淺主題自適應。
2. 功能點用短句 + 圖示，避免長段描述。
3. 下載入口醒目，使用按鈕式連結。

## 4. 命令列工具

典型代表：fd、ripgrep 等終端工具。

### 4.1 章節取捨

- 「一句話定位」後緊跟章節導航，便於跳轉。
- 「安裝」列出主流包管理器與平臺二進位制。
- 「用法」以任務為導向，給出常用命令示例。
- 「命令對照」或「與同類工具對比」是高頻需求。
- 「Demo」用 GIF 或終端錄製展示真實效果。
- 效能資料須註明測試環境與方法。

### 4.2 視覺側重

- 徽章重點：版本、構建狀態、平臺支援、許可證。
- Demo 動圖是核心視覺資產，展示速度與使用體驗。
- 命令用帶語言標註的程式碼塊，輸出用 `text` 塊。

### 4.3 美觀度提升要點

1. 命令示例置頂，讀者無需滾動即可複製使用。
2. Demo 動圖展示真實終端效果，強化「快」的印象。
3. 多級語言連結（如中文、韓文譯本）放在徽章行附近。

## 5. 框架

典型代表：next.js 等全棧框架。

### 5.1 章節取捨

- 首屏強調定位、生態規模與學習入口。
- 「文件」入口必須醒目，通常指向獨立文件站。
- 「社群」說明討論區、即時通訊渠道與行為準則。
- 「快速開始」給出最小專案建立命令。
- 深度內容（架構、API）外鏈，不在 README 展開。

### 5.2 視覺側重

- 徽章重點：版本、構建狀態、許可證、社群渠道。
- 品牌 Logo 與 `for-the-badge` 風格徽章組合，強化首頁。
- 可用 Showcase 截圖展示生態案例。

### 5.3 美觀度提升要點

1. 居中 Logo + 大號統一風格徽章，形成品牌化首屏。
2. 文件與社群入口以醒目的導航塊呈現。
3. Good First Issues 等新手入口降低貢獻門檻。

## 6. 資源合集

典型代表：awesome 系列列表。

### 6.1 章節取捨

- 首屏以 Logo 與贊助資訊開場是常見做法。
- 正文按主題分類組織目錄，提供清晰導航。
- 「貢獻指南」說明收錄標準與提交格式。
- 無需安裝、API、部署等章節。

### 6.2 視覺側重

- 徽章數量可放寬，但須統一風格。
- 目錄分類用二級標題 + 列表，條目附簡短說明。
- 贊助商 Logo 以表格或網格排列，保持對齊。

### 6.3 美觀度提升要點

1. 目錄結構清晰，分類標題層級一致。
2. 每個條目附一句話說明，避免僅有連結。
3. 贊助與致謝區域對齊規整，不影響正文閱讀。

## 7. 跨型別通用原則

1. **讀者優先**：首屏回答讀者最關心的問題，型別差異隻影響順序，不影響資訊完整性。
2. **統一風格**：同一專案的徽章、標題、程式碼塊風格必須一致。
3. **可複製示例**：任何型別都至少提供一個可直接執行的示例。
4. **連結外鏈**：超出首頁職責的深度內容外鏈至獨立文件。
5. **持續同步**：截圖、版本徽章、功能列表須隨版本更新，避免陳舊資訊損傷可信度。
