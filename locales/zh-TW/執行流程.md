# 執行流程

> 本檔案解決什麼問題：定義從立項到交付的完整階段序列、每階段的進入條件與產出物，以及資訊不足時的阻斷式提問規則。

## 1. 總控推送流程（Phase 0–6）

### Phase 0 · 立項（Project Init）

輸出：專案名候選 3 個 + 選用理由 + 重名檢索結論 + 倉庫後設資料表（description / topics / 預設分支 / 可見性 / license）。命名規則見 [專案命名規範](./專案命名規範.md)。

### Phase 1 · 盤點（Inventory）

掃描倉庫，產出結構化清單：
- 技術棧、入口檔案、包管理器、lockfile
- 已有文件、缺失文件
- 倉庫體積 Top10 大檔案
- 已有 CI / 模板 / 保護規則
- 當前 git 狀態：未跟蹤檔案、未提交改動、歷史中的可疑提交

### Phase 2 · 並行稽核（Audit）

按 [稽核維度矩陣](./稽核維度矩陣.md) 把維度分派給子 agent 並行執行，分派方式見 [子Agent分派契約](./子Agent分派契約.md)。每個子 agent 只返回結構化結論，不返回長篇散文。

### Phase 3 · 修復（Fix）

按 P0 → P1 → P2 順序列出待辦，標註責任 agent 與預計動作。P0 未清零不得進入 Phase 5。

### Phase 4 · 文件生成（Docs）

按 [文件矩陣](./文件矩陣.md) 逐個檔案分派給文件 agent。**一次只寫一個檔案，寫完校驗再下一個。**

### Phase 5 · 推送（Push）

按 [推送與釋出規範](./推送與釋出規範.md) 執行，逐條回顯結果。

### Phase 6 · 推送後（Post-Push）

打 tag、寫 Release Notes、校驗徽章與連結可用、確認 CI 綠、確認 About 區資訊正確。

## 2. 文件生成流程（階段 0–5）

按階段順序推進，前一階段未完成不得進入下一階段。

| 階段 | 名稱 | 進入條件 | 產出 |
| --- | --- | --- | --- |
| 0 | 資訊核驗 | 收到本規範與專案材料 | 已確認資訊清單、缺失資訊清單 |
| 1 | 阻斷式提問 | 存在必填欄位缺失（見 [資訊採集與模板](./資訊採集與模板.md)） | 結構化提問清單，按欄位分組 |
| 2 | 框架確認 | 必填欄位齊備 | README 章節目錄與各章要點提綱，供使用者確認 |
| 3 | 文件生成 | 使用者確認框架，或明確表示無需確認 | 全部交付物 |
| 4 | 質量門禁 | 文件生成完成 | [質量門禁](./質量門禁.md) 逐項判定結果 |
| 5 | 交付 | 門禁全部透過或已標註未透過項 | 按 [稽核報告格式](./稽核報告格式.md) 順序輸出，附推送指引 |

## 3. 階段 1 提問規則

1. 按欄位分組提問，單輪不超過 15 項。
2. 每個問題須說明用途與影響的章節，便於使用者判斷優先順序。
3. 使用者明確表示某項無法提供時，在文件對應位置標註「【待確認：欄位名】」，並在文末彙總。
4. 使用者答覆「按你的判斷」時，可以給出建議值，但須標註「【建議值，待使用者確認】」。
