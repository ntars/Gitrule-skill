# 部署與回滾規範

> 本檔案解決什麼問題：定義部署清單、變更單與回滾預案的模板、欄位和執行標準，保證上線可控、狀態可查、故障可快速恢復。

## 1. 規範條文

1. 部署前須透過 CI、程式碼審查與質量門禁（見 [質量門禁](./質量門禁.md)）。
2. 部署基於已打 tag 的釋出版本，不使用未標記提交（見 [版本管理規範](./版本管理規範.md)）。
3. 環境配置與程式碼分離，敏感配置透過配置管理注入，不入庫（見 [安全與隱私規範](./安全與隱私規範.md)）。
4. 資料庫結構變更透過遷移指令碼執行，且須滿足向前相容（見 [資料庫設計規範](./資料庫設計規範.md)）。
5. 每次部署須記錄版本號、時間、操作人與變更內容；無記錄的部署視為不合規部署。
6. 每個版本須預先準備回滾預案，未準備回滾預案不得上線。
7. 部署後須執行健康檢查與冒煙驗證，兩項均透過方可結束髮布。

## 3. 部署記錄模板

```markdown
## {{YYYY-MM-DD}} {{vX.Y.Z}} → {{环境}}

- 版本號：{{vX.Y.Z}}
- tag：{{vX.Y.Z}}
- 時間：{{HH:MM}}
- 操作人 / 審批人：{{姓名 / 姓名}}
- 變更摘要：{{一句话}}
- 健康檢查：{{通过 / 未通过}}
- 結果：{{成功 / 回滚}}
- 關聯釋出：{{Release Notes URL}}
- 備註：{{异常与处理记录；无则写「无」}}
```

## 4. 欄位定義

| 欄位 | 必填 | 型別 | 填寫要點 | 示例 |
| --- | --- | --- | --- | --- |
| tag | 是 | 文字 | 與 [版本管理規範](./版本管理規範.md) 的 tag 完全一致 | `v1.2.0` |
| 目標環境 | 是 | 列舉 | 預釋出 / 生產，不得混用配置 | `生产` |
| 變更項.型別 | 是 | 列舉 | 新增 / 修改 / 移除 | `修改` |
| 關聯需求 | 是 | 列表 | REQ 編號，無需求變更寫「無」 | `REQ-007` |
| 灰度比例 | 否 | 百分比 | 逐步放量時必填 | `10% → 50% → 100%` |
| 判定條件 | 是 | 閾值 | 可觀測、可判定 | `HTTP 200` |
| 實際版本號 | 是 | 文字 | 與計劃版本號不同時須說明原因 | `v1.2.1` |
| 回滾觸發條件 | 是 | 閾值 + 時長 | 禁止「感覺異常」類表述 | `错误率 >1% 持续 5 分钟` |
| 資料相容性 | 是 | 文字 | 明確是否需要資料回滾 | `无需数据回滚` |

## 5. 填寫說明

1. **前置檢查**：逐項勾選，禁止整段一次性勾選；任一項未完成即中止部署。
2. **變更內容**：每條須關聯 REQ 編號；無需求關聯的純運維變更寫「無」並說明變更依據。
3. **健康檢查**：須為可自動判定的條件；「服務看起來正常」不合格。
4. **回滾觸發條件**：須同時給出閾值與持續時間，避免瞬時抖動誤觸發。
5. **灰度放量**：每檔放量後須觀察規定時長，並記錄觀察結論，方可進入下一檔。
6. **部署記錄**：按時間追加，不覆蓋歷史；與推送、tag、Release Notes 三者版本號一致。
7. **回滾執行**：程式碼回滾用 `git revert` 生成反向提交，不對已公開歷史強推（見 [推送與釋出規範](./推送與釋出規範.md)）。

常見錯誤：

| 錯誤寫法 | 問題 | 修正方式 |
| --- | --- | --- |
| 用未打 tag 的提交部署 | 版本無法復現 | 先打 tag 再部署 |
| 回滾預案寫「有問題就回滾」 | 無觸發條件與步驟 | 補閾值、決策人、步驟 |
| 資料庫變更不相容舊版本 | 回滾後資料不可用 | 採用擴充套件-遷移-收縮三步法 |
| 部署記錄事後補寫 | 狀態不可信 | 部署當時即時記錄 |
| 健康檢查只測首頁 | 關鍵鏈路未驗證 | 補主流程冒煙用例 |

## 6. 完整示例

```markdown
# 部署清單：markdown-lint-cli v1.0.0

版本：v1.0.0 ｜ tag：v1.0.0 ｜ 目標環境：生產 ｜ 計劃時間：2026-11-20 10:00

## 前置檢查
- [x] CI 全綠：https://github.com/example/markdown-lint-cli/actions/runs/123
- [x] 程式碼審查透過，審批人：李四
- [x] 質量門禁 A/B/C 全 PASS
- [x] 變更日誌與 Release Notes 已就緒
- [x] 回滾預案已評審
- [x] 無資料庫遷移
- [x] 配置變更清單已確認：無

## 變更內容
| 變更項 | 型別 | 影響範圍 | 關聯需求 | 驗證方式 |
| --- | --- | --- | --- | --- |
| 中英文空格規則 | 新增 | 規則引擎 | REQ-001 | 執行 TC-001 |
| CLI 報告輸出 | 修改 | 報告模組 | REQ-007 | 執行 TC-012 |

## 執行步驟
1. 拉取 v1.0.0 tag 並校驗校驗和
2. 灰度 10%，觀察 10 分鐘
3. 錯誤率 <0.1% 後放量至 100%

## 健康檢查與冒煙
| 檢查項 | 判定條件 | 執行方式 | 結果 |
| --- | --- | --- | --- |
| 服務存活 | HTTP 200 | curl /healthz | 透過 |
| 關鍵鏈路 | 50 篇文件檢查完成 | shell 指令碼 | 透過 |
| 錯誤率 | <0.1% | 監控面板 | 透過 |

## 回滾預案
- 回滾目標版本：v0.9.3
- 觸發條件：錯誤率 >1% 持續 5 分鐘
- 決策人：李四
- 回滾步驟：切換部署標籤至 v0.9.3 並執行資料相容性檢查
- 資料相容性：無資料庫變更，無需資料回滾
```
