# 免責宣告模板

> 本檔案解決什麼問題：提供一份可直接複製、按佔位符替換即可套用的通用免責宣告模板，使任何專案都能以最小成本界定自身的內容性質、責任邊界與使用者義務；配套的填寫說明與場景變體覆蓋個人、企業、開源與閉源專案。

## 1. 使用說明

1. 複製第 3 節「模板正文」的全部內容，新建為專案根目錄的 `DISCLAIMER.md`，或併入 `README.md` 的獨立章節。
2. 按第 4 節佔位符對照表逐個替換 `{{...}}`；未使用的整節須刪除，不留空佔位符。
3. 按第 5 節場景變體裁剪條款：閉源軟體側重第 3.5 節，開源專案須保留第 3.6 節與許可證的關係說明。
4. 本模板為通用參考文字，不構成法律意見。涉及正式對外發布、跨境分發或受監管行業時，須經法務審定後使用，依據見 [免責宣告](./免責宣告.md) 第 2 節。
5. 提交前核對：佔位符已全部替換、聯絡方式真實可達、與 [LICENSE](../../LICENSE) 條款無衝突。

## 2. 定製原則

- **合法優先**：所有免責條款僅在適用法律允許的範圍內生效，禁止寫「無條件免除一切責任」等絕對化表述，避免整條失效。
- **不越界**：不得撤銷、縮減許可證授予的權利；衝突時以許可證正文為準，原則見 [LICENSE規範](./LICENSE規範.md)。
- **可驗證**：聯絡方式、生效日期、主體名稱須為真實資訊，禁止保留示例值。
- **獨立性**：各條款相互獨立，單條無效不影響其餘條款效力。

## 4. 佔位符對照表與欄位定義

| 佔位符 | 必填 | 欄位定義 | 填寫示例 |
| --- | --- | --- | --- |
| `{{项目名称}}` | 是 | 專案對外名稱，與 README 首行一致 | `FooBar` |
| `{{主体名称}}` | 是 | 承擔或放棄責任的主體全稱，個人專案寫姓名，企業專案寫法定名稱 | `某某科技有限公司` |
| `{{维护主体}}` | 是 | 負責修訂宣告的組織或個人 | `FooBar 维护团队` |
| `{{更新日期}}` | 是 | 本宣告最近一次修訂的日期，格式統一為 YYYY-MM-DD | `2026-11-18` |
| `{{生效日期}}` | 是 | 本宣告開始生效的日期，可與更新日期相同 | `2026-11-18` |
| `{{内容性质描述}}` | 是 | 一句話說明專案是什麼、處於何種成熟度 | `供开发者参考的示例实现，非生产级组件` |
| `{{数据或示例的时点与范围说明}}` | 否 | 示例中資料或引數的採集時點與適用範圍 | `2026 年 10 月对 120 个样本的统计` |
| `{{许可证名称及 SPDX 标识符}}` | 是 | 專案許可證全稱與 SPDX 標識 | `MIT 许可证（MIT）` |
| `{{仓库地址或发布渠道}}` | 是 | 宣告最新版本的權威釋出位置 | `https://github.com/owner/repo` |
| `{{真实可达的联系邮箱或渠道}}` | 是 | 使用者可觸達維護者的真實地址 | `security@example.com` |

## 5. 填寫說明與場景變體

| 場景 | 必留條款 | 可裁剪條款 | 調整要點 |
| --- | --- | --- | --- |
| 個人專案 | 3.1 / 3.2 / 3.3 / 3.5 / 3.7 | 3.4 可精簡 | 主體名稱寫真實姓名；聯絡方式用可長期持有的郵箱 |
| 企業專案 | 全部條款 | 無 | 主體名稱寫營業執照法定名稱；法務審定後方可釋出 |
| 開源專案 | 全部條款，尤其 3.6 | 無 | 保留與許可證的關係說明；不得縮減許可證授予的權利 |
| 閉源軟體 | 3.1 / 3.2 / 3.3 / 3.4 / 3.5 / 3.7 | 3.6 第 2–4 段可刪 | 刪除開源許可證相關表述，改為引用終端使用者許可協議 |
| 實驗性原型 | 3.1 / 3.2 / 3.3 / 3.7 | 3.5 可精簡 | 在內容性質中顯式標註「原型」，避免被當作穩定版本 |
| 涉及個人資訊處理 | 全部條款 | 無 | 增補資料處理角色、留存期限與主體權利渠道，另見 [安全與隱私規範](./安全與隱私規範.md) |

常見錯誤對照：

| 錯誤寫法 | 後果 | 正確寫法 |
| --- | --- | --- |
| 「本專案不承擔任何責任」 | 表述絕對，易被認定無效 | 「在法律允許的最大範圍內，不承擔……」 |
| 「最終解釋權歸作者所有」 | 與許可證授權衝突，引發爭議 | 「衝突時以許可證正文為準」 |
| 聯絡方式留 `test@example.com` | 不可達，失去溝通渠道 | 填寫真實且長期有效的郵箱 |
| 照抄其他專案宣告未改主體 | 主體錯配，宣告失去意義 | 逐個替換佔位符並核對主體一致性 |
