# 需求追蹤矩陣規範

> 本檔案解決什麼問題：定義需求到設計、實現、測試、釋出的雙向追蹤矩陣模板與欄位，保證生命週期各階段的產物相互引用一致、變更影響可評估、覆蓋缺口可發現。

## 1. 規範條文

1. 每條「必須」級需求須在追蹤矩陣中佔一行，並記錄從立項到釋出的全鏈路產物。
2. 追蹤關係須雙向可查：正向由需求查到下游產物，反向由產物查到上游需求。
3. 一條需求對應多個產物時，使用逗號分隔的編號列表；編號須與對應文件中的定義完全一致。
4. 需求變更須在矩陣中留痕，記錄變更原因、影響範圍與決策人，不得直接覆蓋原值。
5. 矩陣須在每次版本釋出前核對，未閉環的「必須」級需求不得釋出。
6. 覆蓋率統計口徑：需求覆蓋率 = 已釋出「必須」級需求數 / 「必須」級需求總數。

```markdown
| 需求 ID | 需求標題 | 優先順序 | 立專案標 | 架構決策 | 設計文件 | 實現 PR | 測試用例 | 釋出版本 | 狀態 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| REQ-001 | {{标题}} | 必須 | G1 | ADR-0002 | docs/api.md#check | #12 | TC-001, TC-002 | v1.0.0 | 已驗證 |
```


## 5. 欄位定義

| 欄位 | 必填 | 型別 | 填寫要點 | 示例 |
| --- | --- | --- | --- | --- |
| 需求 ID | 是 | `REQ-NNN` | 與 [專案立項與需求規範](./專案立項與需求規範.md) 編號一致 | `REQ-001` |
| 優先順序 | 是 | 列舉 | 必須 / 應當 / 可以 | `必须` |
| 立專案標 | 是 | `G-N` | 對應立項書的目標編號 | `G1` |
| 架構決策 | 否 | `ADR-NNNN` | 無架構決策寫「—」，不得留空 | `ADR-0002` |
| 設計文件 | 否 | `路径#锚点` | 精確到章節錨點 | `docs/api.md#check` |
| 實現 PR | 否 | `#数字` | PR 編號，不是提交雜湊 | `#12` |
| 測試用例 | 是 | `TC-NNN` 列表 | 至少一條；無用例時說明原因 | `TC-001` |
| 釋出版本 | 否 | `vX.Y.Z` | 與 tag 一致 | `v1.0.0` |
| 狀態 | 是 | 列舉 | 七態之一，僅前進，廢棄除外 | `已验证` |
| 變更記錄.影響範圍 | 是 | 文字 | 列出受影響的 ADR、PR、TC | `ADR-0002, TC-001` |

## 6. 填寫說明

1. **編號一致**：矩陣中的需求 ID、ADR 編號、TC 編號必須與源文件逐字一致；禁止使用簡稱或別名。
2. **空值規範**：不適用寫「—」，未產生寫「待補」；兩者含義不同，不得混用。
3. **反向索引**：每次更新正向矩陣後同步更新反向索引；兩者不一致時以正向矩陣為準並立即修正。
4. **變更留痕**：修改任何欄位前先在變更記錄中追加一行，寫明原值與新值；禁止直接覆蓋。
5. **釋出核對**：釋出前逐條檢查「必須」級需求是否具備測試用例與釋出版本；缺任一項即阻斷髮布。
6. **已廢棄需求**：保留行不刪除，狀態改為「已廢棄」，並在變更記錄中寫明廢棄原因。

常見錯誤：

| 錯誤寫法 | 問題 | 修正方式 |
| --- | --- | --- |
| 測試用例欄位留空 | 覆蓋缺口不可見 | 填「待補」並在釋出前清零 |
| PR 欄位填提交雜湊 | 無法定位審查記錄 | 改用 PR 編號 |
| 變更時直接改值 | 影響不可追溯 | 先追加變更記錄 |
| 狀態從「已驗證」回退到「已實現」 | 違反僅前進原則 | 新開缺陷並另起追蹤行 |
| 正向與反向索引不一致 | 引用失配 | 釋出前以正向為準同步 |
