# 版本管理規範

> 本檔案解決什麼問題：定義語義化版本規則、版本決策記錄、遞增依據與聯動關係，保證版本號可表達變更性質、可被工具解析、與釋出產物一致。

## 1. 規範條文

1. 版本號遵循語義化版本：`MAJOR.MINOR.PATCH`。
2. 版本號不含年份、日期、構建序號作為語義主體；已釋出版本不得重用版本號。
3. 破壞性變更須在主版本升級時集中處理，並給出遷移方式。
4. 版本號與 tag 一致，tag 格式為 `vMAJOR.MINOR.PATCH`（見 [推送與釋出規範](./推送與釋出規範.md)）。
5. 預釋出版本使用 `-alpha`、`-beta`、`-rc` 字尾，須在穩定版釋出前完成驗證。

## 2. 版本號格式與遞增依據

| 位 | 遞增條件 | 觸發提交型別 | 示例 |
| --- | --- | --- | --- |
| MAJOR | 不相容的破壞性變更 | `feat!:` / `fix!:` / `BREAKING CHANGE:` | `1.9.2 → 2.0.0` |
| MINOR | 向後相容的新功能 | `feat` | `1.2.3 → 1.3.0` |
| PATCH | 向後相容的缺陷修復 | `fix` | `1.2.3 → 1.2.4` |

預釋出格式：`vMAJOR.MINOR.PATCH-alpha.N` / `-beta.N` / `-rc.N`，數字從 1 遞增；穩定版釋出時去除字尾。

## 3. 版本決策記錄模板

```markdown
## 版本決策：{{X.Y.Z}}

- 決策日期：{{YYYY-MM-DD}}
- 決策人：{{姓名}}
- 當前版本：{{X.Y.Z}}
- 目標版本：{{X.Y.Z}}
- 遞增位：{{MAJOR / MINOR / PATCH}}
- 依據：{{列举触发的提交类型与变更内容}}

| 變更 | 提交型別 | 關聯需求 | 是否破壞相容 |
| --- | --- | --- | --- |
| {{变更描述}} | {{feat / fix / BREAKING CHANGE}} | {{REQ-NNN}} | {{是 / 否}} |

- 破壞性變更處理：{{迁移指南链接 / 不适用}}
- 變更日誌條目：{{链接}}
- tag：{{vX.Y.Z}}
- 釋出檢查：{{已通过 / 待通过}}
```

## 4. 版本臺賬模板

```markdown
# 版本臺賬：{{项目名称}}

| 版本 | 釋出日期 | 型別 | 主要變更 | tag | 變更日誌 | 狀態 |
| --- | --- | --- | --- | --- | --- | --- |
| {{X.Y.Z}} | {{YYYY-MM-DD}} | {{主版本 / 次版本 / 修订}} | {{一句话}} | {{vX.Y.Z}} | {{链接}} | {{当前 / 历史 / 已废弃}} |
| {{X.Y.Z-rc.1}} | {{YYYY-MM-DD}} | 預釋出 | {{一句话}} | {{vX.Y.Z-rc.1}} | {{链接}} | 已 superseded |

狀態：當前 / 歷史 / 已廢棄 / 已被替代
```

## 5. 欄位定義

| 欄位 | 必填 | 型別 | 填寫要點 | 示例 |
| --- | --- | --- | --- | --- |
| 當前版本 | 是 | `X.Y.Z` | 與最近 tag 一致 | `1.2.3` |
| 目標版本 | 是 | `X.Y.Z` | 只遞增一位 | `1.3.0` |
| 遞增位 | 是 | 列舉 | MAJOR / MINOR / PATCH | `MINOR` |
| 依據 | 是 | 列表 | 列舉觸發變更，禁止「例行更新」 | `新增 TOML 支持` |
| 破壞性變更處理 | 條件必填 | 連結 | MAJOR 遞增時必填 | `[迁移指南]` |
| 變更日誌條目 | 是 | 連結 | 指向對應版本段 | `[1.3.0]` |
| tag | 是 | `vX.Y.Z` | 與版本號一一對應 | `v1.3.0` |
| 釋出日期 | 是 | `YYYY-MM-DD` | 以 tag 打點日期為準 | `2026-11-20` |
| 狀態 | 是 | 列舉 | 當前 / 歷史 / 已廢棄 / 已被替代 | `当前` |

## 6. 填寫說明

1. **一位遞增**：每次釋出只遞增一位；同時存在 feat 與 BREAKING CHANGE 時取最高位（MAJOR），其餘變更併入該版本。
2. **破壞性集中**：多個破壞性變更合併到同一主版本釋出，避免連續 MAJOR 遞增。
3. **禁止重用**：已釋出版本號永久佔用；撤回釋出時遞增 PATCH 釋出修訂版，不復用原號。
4. **預釋出**：`alpha` 用於內部驗證，`beta` 用於公開試用，`rc` 用於釋出候選；每一級均須透過 CI。
5. **一致性核對**：版本號須在 tag、變更日誌、Release Notes、部署記錄、版本臺賬五處一致；不一致時以 tag 為準並修正其餘。
6. **聯動**：遞增依據來自 [提交資訊規範](./提交資訊規範.md) 的型別；對外說明見 [變更日誌規範](./變更日誌規範.md)；升級路徑見 [遷移指南規範](./遷移指南規範.md)。

常見錯誤：

| 錯誤寫法 | 問題 | 修正方式 |
| --- | --- | --- |
| `v2026.11` | 以日期為語義主體 | 改為 `v2.1.0` |
| 同一版本多次遞增兩位 | 語義混亂 | 只遞增最高位 |
| 複用已撤回的版本號 | 無法區分產物 | 遞增 PATCH 釋出修訂版 |
| MAJOR 遞增無遷移指南 | 使用者無法升級 | 補遷移指南並連結 |
| 版本號僅存在 tag 中 | 臺賬與日誌不一致 | 五處同步 |

## 7. 完整示例

```markdown
## 版本決策：2.0.0

- 決策日期：2026-12-01
- 決策人：李四
- 當前版本：1.9.2
- 目標版本：2.0.0
- 遞增位：MAJOR
- 依據：配置檔案格式由物件改為檔案路徑，屬不相容變更。

| 變更 | 提交型別 | 關聯需求 | 是否破壞相容 |
| --- | --- | --- | --- |
| 配置檔案路徑化 | BREAKING CHANGE | REQ-021 | 是 |
| 新增 TOML 解析 | feat | REQ-001 | 否 |

- 破壞性變更處理：[遷移指南 v2.0]
- 變更日誌條目：[2.0.0]
- tag：v2.0.0
- 釋出檢查：已透過
```
