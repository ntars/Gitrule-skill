# 開源推廣規範

> 本檔案解決什麼問題：定義開源專案在釋出前後的推廣渠道、釋出節奏、首頁物料與社群運營規範，使專案在具備可用文件的基礎上獲得與目標使用者相匹配的曝光。

本檔案的渠道清單與原則參考 phodal《GitHub 漫遊指南》的推廣章節；該專案以 11,362 star 的規模驗證了這些做法在中文開源社群的適用性。

## 1. 基本原則

1. **質量先於推廣**：推廣只放大已有質量，不修復缺失。README、示例、文件、測試未就緒前不得啟動推廣。
2. **專案本身不是推廣的全部**：除程式碼與 README 外，須準備詳細文件、示例程式與問題響應機制。
3. **動機明確**：推廣服務於具體目標（獲取早期使用者、招募貢獻者、收集反饋），不得為追求 star 數而推廣。
4. **渠道匹配**：按專案技術棧與目標使用者選擇渠道，避免無差別投放。
5. **誠實呈現**：不得虛構 star 數、下載量或使用案例；特性對比須基於可驗證事實。

## 2. 釋出前準備清單

| 類別 | 要求 | 判定依據 |
| --- | --- | --- |
| 首頁 | README 透過四問檢查（做什麼/解決什麼/特性/示例） | [README章節規範](./README章節規範.md) |
| 一句話文案 | 明確品類與限定詞，可獨立複述 | 同上 1.1 節 |
| 示例 | 提供兩步內可執行的 hello world | [README標準模板](./README標準模板.md) |
| 文件 | 安裝、配置、API 文件齊備 | [文件矩陣](./文件矩陣.md) |
| 許可證 | LICENSE 存在且與 README 標識一致 | [LICENSE規範](./LICENSE規範.md) |
| 合規 | NOTICE 覆蓋第三方依賴 | [NOTICE規範](./NOTICE規範.md) |
| 社群入口 | Issue 模板、貢獻指南、行為準則就位 | [貢獻指南規範](./貢獻指南規範.md) |
| 響應機制 | 明確問題響應人與響應時限 | [事故響應規範](./事故響應規範.md) |

未完成上述清單即推廣，屬本規範禁止行為。

## 3. 渠道分類

### 3.1 國際技術社群

| 渠道 | 適用內容 | 注意事項 |
| --- | --- | --- |
| Hacker News | 技術實現、有深度的工程設計 | 標題須平實，避免營銷措辭 |
| Reddit 對應版塊 | 類庫、工具、框架 | 遵守各版塊自推廣規則 |
| Lobsters | 系統程式設計、工程實踐 | 社群對營銷敏感 |
| 技術週報（JavaScript Weekly 等） | 類庫與工具 | 提供簡潔的專案摘要 |
| 官方部落格與文件站 | 深度介紹與版本說明 | 作為其他渠道的落點 |

### 3.2 中文技術社群

| 渠道 | 適用內容 |
| --- | --- |
| 掘金 | 前端、移動端、工程實踐 |
| 開發者頭條 | 綜合技術專案 |
| V2EX | 工具、效率軟體、創業專案 |
| 知乎 | 技術解讀與設計取捨 |
| 微信公眾號 | 深度長文、系列教程 |
| 極客頭條 | 綜合技術資訊 |

### 3.3 專案自有渠道

1. 專案 README 中的社群入口（Discussions、Discord）；
2. 專案專屬社交賬號，用於釋出版本與活動；
3. 文件站與示例站，作為外部流量的承接頁。

## 4. 釋出節奏

1. **預熱期**：完成第 2 節清單，準備一句話文案、截圖、Demo 動圖等物料。
2. **首發期**：在 1–2 個最匹配渠道釋出，避免同一內容多平臺刷屏。
3. **響應期**：首發後 72 小時內保持高頻響應，處理 Issue 與反饋。
4. **迭代期**：按版本釋出節奏持續更新，每次釋出附變更說明。
5. **沉澱期**：將高頻問題整理為 FAQ，反哺文件。

## 5. 首頁物料要求

| 物料 | 規格 | 用途 |
| --- | --- | --- |
| 一句話文案 | 中文 60 字內 / 英文 25 詞內；倉庫 Description 採用「國家語言 \| 英語」雙語合併格式，見 [專案命名規範](./專案命名規範.md) 第 5 節 | 倉庫 Description、社交摘要 |
| 截圖 | 深淺主題雙版本，寬度受控 | README 首屏 |
| Demo 動圖 | 壓縮後體積受控，展示核心流程 | README 演示章節 |
| Logo | SVG 格式，含深淺雙版本 | 首屏與社交卡片 |
| 特性對比表 | 基於可驗證事實，含不適用場景 | README 或文件站 |

物料須隨版本同步更新，避免展示舊版介面。

## 6. 社群運營

1. 對首次貢獻者提供明確入口，如 `good first issue` 標籤。
2. 問題響應須有記錄，避免重複問題反覆出現。
3. 行為準則適用於所有社群渠道，見 [行為準則規範](./行為準則規範.md)。
4. 貢獻者致謝集中放置，避免散落在正文各處。
5. 不得透過誘導 star、互贊等方式獲取虛假關注。

## 7. 禁止事項

1. 禁止在質量清單未完成時推廣。
2. 禁止虛構或誇大專案資料與使用案例。
3. 禁止在多渠道重複刷屏同一內容。
4. 禁止貶損同類專案以提升自身形象。
5. 禁止使用誘導手段獲取 star 數。
