# 通用寫作規範

> 本檔案解決什麼問題：定義所有交付文件的語體、準確性、術語一致性、格式細則與禁止內容，保證表述精確、無歧義、可復現。

## 1. 語體

1. 使用書面語，採用陳述句與祈使句。
2. 不得使用口語化表達，例如「咱們」「超簡單」「搞定」「賊快」「一鍵起飛」。
3. 不得使用感嘆號、省略號、網路縮略語、表情符號。
4. 不得使用反問句、設問句作為章節開頭。

## 2. 準確性

1. 每個句子須表達完整語義，不得依賴上下文推測。
2. 不得使用「它」「這個」「相關」「一些」「若干」等模糊指代；確需指代時使用完整名詞。
3. 時間、版本號、路徑、命令、函式名、配置鍵名須精確，且與專案實際情況一致。
4. 命令須可直接執行，包含必要的當前工作目錄說明。
5. 涉及版本號時須寫明版本約束語義，例如 `>=1.2.0 <2.0.0`。

## 3. 術語一致性

1. 術語首次出現時給出定義，格式為「中文術語（English Term，縮寫）」。
2. 同一概念在全文中只使用一種表述，中英文版本術語一一對應。
3. 須維護中英術語對照表，置於 README 附錄或獨立檔案，雙語版本共用同一份對照表（模板見 [資訊採集與模板](./資訊採集與模板.md)）。

## 4. 格式規範

1. 標題層級從 `##` 開始（`#` 保留給專案名稱），層級不得跳級。
2. 每個二級標題對應 [README章節規範](./README章節規範.md) 規定的一個章節，順序不得調整。
3. 表格須有表頭，列數一致；命令、路徑、程式碼、配置鍵名使用行內程式碼標記。
4. 程式碼塊須標註語言標識，多行命令須可整段複製執行。
5. 外部連結使用完整 URL，不使用短連結；內部跳轉使用相對路徑錨點。
6. 中文與英文、數字之間加空格；中英文標點不混用。

## 5. 佔位符約定

1. 可複製模板中的正式佔位符統一寫成 `{{纯名}}`，例如 `{{仓库地址}}`；名稱不得包含「或」「，」等表示多選取一的連線詞，也不得寫成一句說明文字。
2. 正式佔位符須在所屬模板的佔位符對照表中登記，登記項包含含義、示例與是否必填。
3. 規範示例或填寫提示中的自然語言花括號內容僅作示例，不屬於正式佔位符，不納入對照表；生成最終文件時須全部替換為實際內容。
4. 不得使用巢狀花括號、反引號或第二個佔位符作為佔位符名稱。
5. 多語言翻譯時，佔位符名稱須與來源語言逐字一致，不得本地化、音譯或意譯；僅佔位符之外的說明文字可翻譯。佔位符是模板替換的錨點，一旦譯名，跨語言對照與批次替換即失效。

## 6. 禁止清單

不得出現：未經驗證的效能數字、無出處的對比結論、承諾性表述（如「保證相容所有環境」「永久免費」）、對第三方專案的貶損性描述、與專案無關的推廣內容。
