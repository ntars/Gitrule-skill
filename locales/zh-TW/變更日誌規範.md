# 變更日誌規範

> 本檔案解決什麼問題：定義面向使用者的版本變更記錄模板、欄位與寫法，保證每次變更可追溯、版本可對應、升級路徑可判斷。

## 1. 規範條文

1. 變更日誌遵循 Keep a Changelog 結構，版本號遵循 [版本管理規範](./版本管理規範.md) 的語義化版本。
2. 每個版本須有釋出日期，格式 `YYYY-MM-DD`；未釋出內容置於 `Unreleased` 段。
3. 條目按六類分組：`Added` 新增 / `Changed` 變更 / `Deprecated` 廢棄 / `Removed` 移除 / `Fixed` 修復 / `Security` 安全。
4. 每條變更面向使用者，須說明影響與遷移方式，不寫內部重構細節。
5. 破壞性變更須標註 `BREAKING CHANGE:` 並給出遷移步驟（見 [遷移指南規範](./遷移指南規範.md)）。
6. 版本號須與 tag、Release Notes 一致；破壞性變更須與提交資訊中的 `feat!:` 或 `BREAKING CHANGE:` 對應。

## 2. 變更日誌模板

```markdown
# 變更日誌

本檔案記錄所有面向使用者的變更。格式依據 Keep a Changelog，版本遵循語義化版本。

## [Unreleased]

### Added
- {{新增能力，说明对使用者的价值}}

### Changed
- {{行为变更，说明影响范围}}

### Deprecated
- {{即将移除的能力，说明替代方案与移除版本}}

### Removed
- {{已移除的能力，说明迁移路径}}

### Fixed
- {{缺陷修复，说明触发条件}}

### Security
- {{安全修复，说明影响与升级建议}}

## [{{X.Y.Z}}] - {{YYYY-MM-DD}}

### {{类型}}
- {{变更条目}}
- {{BREAKING CHANGE: 原行为 → 新行为；迁移步骤见链接}}

[Unreleased]: https://github.com/{{owner}}/{{repo}}/compare/v{{X.Y.Z}}...HEAD
[{{X.Y.Z}}]: https://github.com/{{owner}}/{{repo}}/compare/v{{prev}}...v{{X.Y.Z}}
```

## 3. 條目模板

```markdown
- {{动词开头的一句话变更描述}}（{{关联 REQ 编号}}）
  - 影響：{{哪些使用者或场景受影响}}
  - 遷移：{{需要执行的动作；无则省略此行}}
  - 參考：{{Issue / PR 链接}}
```

## 4. 欄位定義

| 欄位 | 必填 | 型別 | 填寫要點 | 示例 |
| --- | --- | --- | --- | --- |
| 版本號 | 是 | `X.Y.Z` | 與 tag 完全一致，不帶字首 `v` 亦可，但全文統一 | `1.2.0` |
| 釋出日期 | 是 | `YYYY-MM-DD` | 以 tag 打點日期為準 | `2026-11-18` |
| 分組型別 | 是 | 列舉 | 六類之一；無該類條目時整段省略 | `Fixed` |
| 變更描述 | 是 | 文字 | 動詞開頭，面向使用者，說明價值 | `新增对 GFM 表格的检查` |
| 影響 | 條件必填 | 文字 | 行為變更、廢棄、移除、破壞性變更時必填 | `旧配置文件需重命名` |
| 遷移 | 條件必填 | 文字 | 破壞性變更必填，指向遷移指南 | `见迁移指南 v1.0` |
| BREAKING CHANGE | 條件必填 | 標記 | 破壞性變更必填，置於條目開頭 | `BREAKING CHANGE:` |
| 對比連結 | 是 | URL | 每個版本段均須提供 compare 連結 | `compare/v1.1.0...v1.2.0` |
| 關聯 REQ | 否 | 列表 | 便於與需求追蹤矩陣對照 | `REQ-007` |

## 5. 填寫說明

1. **條目粒度**：一條變更描述一個使用者可感知的結果；多個結果拆為多條。
2. **動詞開頭**：使用「新增」「支援」「修復」「移除」「廢棄」「調整」，不使用「更新了」「做了一些」。
3. **禁止內容**：無日期條目、內部重構、開發計劃、路線圖內容、模糊表述（「最佳化體驗」「修復若干問題」）。
4. **破壞性變更**：須同時具備 `BREAKING CHANGE:` 標記、影響說明、遷移步驟、遷移指南連結，四者缺一不可。
5. **廢棄項**：須寫明替代方案與計劃移除的版本號，例如「將於 v2.0 移除」。
6. **Unreleased**：合併後即時登記，不積壓到發版當天補寫。
7. **一致性**：版本號、釋出日期須與 tag、Release Notes、部署記錄三處一致；不一致時以 tag 為準並修正其餘三處。

常見錯誤：

| 錯誤寫法 | 問題 | 修正方式 |
| --- | --- | --- |
| 「重構內部模組結構」 | 屬內部細節，使用者無感 | 刪除，或改寫為可感知的效果 |
| 「修復若干問題」 | 不可判定 | 逐條列出修復內容 |
| 破壞性變更只說「有變更」 | 無遷移路徑 | 補影響、遷移步驟與指南連結 |
| 版本號與 tag 不一致 | 版本對應關係斷裂 | 以 tag 為準統一 |
| 無 compare 連結 | 無法檢視差異 | 補 GitHub compare URL |

## 6. 完整示例

```markdown
## [1.0.0] - 2026-11-20

### Added
- 新增中英文混排空格檢查規則（REQ-001），支援命令列直接呼叫。
- 新增 JSON 報告輸出，便於接入 CI 統計。

### Changed
- BREAKING CHANGE: 配置檔名由 `.mdlint.json` 改為 `.mdlintrc.json`。舊檔案將不再被讀取；遷移步驟見[遷移指南](./遷移指南規範.md)。

### Deprecated
- `--format=table` 引數將於 v2.0 移除，請改用 `--reporter=table`。

### Fixed
- 修復中文標點緊鄰英文單詞時誤報的問題。

### Security
- 修復規則外掛載入路徑可被外部輸入覆蓋的問題；建議所有使用者升級至 v1.0.0。

[1.0.0]: https://github.com/example/markdown-lint-cli/compare/v0.9.3...v1.0.0
```
