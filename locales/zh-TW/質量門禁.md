# 質量門禁

> 本檔案解決什麼問題：定義三層門禁的放行條件、判定清單模板與欄位，保證推送放行判定統一、可執行、可複核。

## 1. 三層門禁

| 層級 | 含義 | 放行條件 |
| --- | --- | --- |
| Gate A · 安全門 | 金鑰、隱私、許可證、大檔案 | 零 P0 |
| Gate B · 質量門 | 構建、測試、lint、提交規範、分支保護 | 零 P0，P1 已記錄待辦 |
| Gate C · 首頁門 | README、後設資料、文件矩陣、徽章、連結 | 零 P0，P1 ≤ 3 且已排期 |

只有 A、B、C 全綠，才輸出 `✅ ALLOW PUSH`。未透過項須修正或標註原因，結果寫入 [稽核報告格式](./稽核報告格式.md)。

## 2. 交付前 14 項判定

文件交付前逐項判定，未透過項須修正或標註原因。

| 編號 | 檢查項 | 判定標準 |
| --- | --- | --- |
| G1 | 口語化與歧義 | 全文檢索口語詞與模糊指代，命中數為 0 |

## 4. 欄位定義

| 欄位 | 必填 | 型別 | 填寫要點 | 示例 |
| --- | --- | --- | --- | --- |
| 判定人 | 是 | 文字 | 唯一，禁止「團隊」 | `王五` |
| 結論 | 是 | 列舉 | PASS / FAIL / SKIP | `PASS` |
| 證據 | 是 | 文字 | 路徑 + 行號或命令輸出，禁止無證據判定 | `gitleaks: 0 findings` |
| 等級 | 條件必填 | 列舉 | FAIL 時必填 P0 / P1 / P2 | `P0` |
| 處置 | 條件必填 | 文字 | FAIL 時必填具體動作與責任人 | `轮换密钥并清理历史` |
| SKIP 原因 | 條件必填 | 文字 | SKIP 時必填，禁止無理由跳過 | `无构建脚本` |
| 放行結論 | 是 | 列舉 | ALLOW PUSH / BLOCK PUSH | `BLOCK PUSH` |
| 阻斷原因 | 條件必填 | 文字 | BLOCK 時必填，列出 P0 | `A2 历史密钥命中` |

## 5. 填寫說明

1. **證據強制**：每條判定須有證據；無證據的 PASS 視為無效，應改為 SKIP 並說明原因。
2. **等級對應**：FAIL 須標等級；P0 直接阻斷放行，P1 須登記待辦，P2 記入建議。
3. **Gate C 門檻**：P1 ≤ 3 且已排期方可 PASS；超出須降級處理或阻斷。
4. **SKIP 使用**：無法檢查時標 SKIP + 原因，不得寫 PASS；待條件具備後補檢。
5. **一致性**：門禁判定須與 [稽核維度矩陣](./稽核維度矩陣.md) 的 P0/P1/P2 等級、[硬規則](./硬規則.md) 的阻斷規則一致。
6. **放行**：三項全綠方可輸出 `✅ ALLOW PUSH`；任一 FAIL 輸出 `⛔ BLOCK PUSH`，並列出阻斷原因。
7. **交付格式**：判定結果按 [稽核報告格式](./稽核報告格式.md) 輸出；透過後執行 [推送與釋出規範](./推送與釋出規範.md)。

常見錯誤：

| 錯誤寫法 | 問題 | 修正方式 |
| --- | --- | --- |
| 結論 PASS 但證據為空 | 判定無效 | 補證據或改 SKIP |
| P0 未清零仍寫 ALLOW PUSH | 違反硬規則 | 改為 BLOCK PUSH |
| SKIP 無原因 | 疑似漏檢 | 補原因 |
| Gate C 有 5 項 P1 仍 PASS | 超門檻 | 降級或阻斷 |
| 判定結果只寫文字無清單 | 不可複核 | 用模板逐項填寫 |
