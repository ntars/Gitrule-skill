# 徽章規範

> 本檔案解決什麼問題：定義 README 中徽章（Badge）的 URL 語法、樣式引數、顏色編碼、資訊取捨、排列順序與數量控制，以 Shields.io 為主要實現，給出可直接複製的格式示例與推薦引數配置。

本檔案所述引數均依據 Shields.io 官方文件（Static Badge 與 Logos 頁面、badge-maker 格式說明）核實；出現率資料來自本專案對頭部開源專案 README 的抽樣統計，標註為「實測」。

## 1. 基本語法

### 1.1 靜態徽章 URL 結構

靜態徽章透過 URL 路徑傳參，標準結構如下：

```text
https://img.shields.io/badge/<標籤>-<訊息>-<顏色>?style=<樣式>&<其他查詢參數>
```

三段路徑以連字元 `-` 分隔：

| 段 | 名稱 | 是否必填 | 說明 |
| --- | --- | --- | --- |
| 第 1 段 | 標籤（label） | 否 | 左側文字，說明指標名稱 |
| 第 2 段 | 訊息（message） | 是 | 右側文字，展示指標值 |
| 第 3 段 | 顏色（color） | 是 | 右側背景色 |

兩段式寫法（省略標籤，僅訊息與顏色）同樣合法：

```text
https://img.shields.io/badge/<訊息>-<顏色>
```

### 1.2 字元轉義規則

URL 路徑中空格與特殊字元須轉義，規則如下：

| 輸入字元 | URL 寫法 | 示例 |
| --- | --- | --- |
| 空格 | `_` 或 `%20` | `v0.1 prototype` → `v0.1%20prototype` |
| 下劃線 `_` | `__`（雙下劃線） | `my_label` → `my__label` |
| 連字元 `-` | `--`（雙連字元） | `dev-build` → `dev--build` |

使用者提供的原型示例符合該語法，可直接使用：

```markdown
![Status](https://img.shields.io/badge/status-v0.1%20prototype-8957e5?style=flat-square)
```

其含義為：標籤 `status`，訊息 `v0.1 prototype`（空格用 `%20`），顏色 `8957e5`（十六進位制紫），樣式 `flat-square`。

### 1.3 Markdown 嵌入格式

```markdown
![版本](https://img.shields.io/badge/version-1.2.0-blue?style=flat-square)
```

需要點選跳轉時，用連結包裹圖片：

```markdown
[![許可證](https://img.shields.io/badge/license-MIT-blue.svg)](./LICENSE)
```

## 2. 樣式引數（style）

`style` 決定徽章的整體視覺設計，可取五個值，預設值為 `flat`。

| 取值 | 視覺特徵 | 適用場景 | 實測出現次數（N=120） |
| --- | --- | --- | --- |
| `flat` | 直角、扁平，Shields.io 預設 | 通用首選，與多數主題相容 | 32 |
| `flat-square` | 直角、無圓角、略緊湊 | 追求規整、硬朗的首頁 | 60 |
| `for-the-badge` | 大號粗體、高對比 | 頂部主視覺、強調性徽章 | 65 |
| `social` | 圓角、左右分色、扁平 | 社交風格首頁 | 12 |
| `plastic` | 高光漸變、擬物 | 復古風格，現已較少使用 | 1 |

**推薦配置**：

- 同一 README 內所有徽章必須統一 `style`，禁止混用。這是視覺一致性的首要要求。
- 通用專案優先 `flat` 或 `flat-square`；需要強化品牌首頁時統一使用 `for-the-badge`。
- 實測中 `for-the-badge`（65 次）與 `flat-square`（60 次）最為流行，二者均可作為預設選擇。

格式示例：

```markdown
![build](https://img.shields.io/badge/build-passing-brightgreen?style=for-the-badge)
![build](https://img.shields.io/badge/build-passing-brightgreen?style=flat-square)
```

## 3. 顏色引數（color / labelColor）

### 3.1 三種顏色表示法

依據 badge-maker 說明，`color`（右側）與 `labelColor`（左側背景）均支援以下三種寫法：

**方法一：Shields.io 命名色**

| 語義 | 命名色 |
| --- | --- |
| 成功 | `brightgreen`、`green`、`success` |
| 提示 | `yellow`、`yellowgreen`、`orange`、`important` |
| 警示 | `red`、`critical` |
| 資訊 | `blue`、`informational` |
| 中性 | `grey` / `gray`、`lightgrey` / `lightgray`、`inactive` |

注意：`labelColor` 預設值為 `grey`，`color` 預設值為 `lightgrey`（文件另注 `inactive` 亦為預設色之一）；部分命名色取值與 CSS 同名色略有差異，以 Shields.io 渲染結果為準。

**方法二：十六進位制色**

支援三位或六位十六進位制，可省略或保留 `#` 字首：

```text
?color=8957e5
?color=007fff
?color=%23007fff    ← 保留 # 时需编码为 %23
```

**方法三：CSS 顏色值**

支援 `rgb(...)`、`rgba(...)`、`hsl(...)`、`hsla(...)` 及 CSS 命名色（如 `aqua`、`fuchsia`、`lightslategray`），使用時須做 URL 編碼。

### 3.2 顏色語義對映（推薦配置）

| 資訊型別 | 推薦顏色 | 示例訊息 |
| --- | --- | --- |
| 構建透過、測試透過 | `brightgreen` / `success` | `passing` |
| 構建失敗 | `red` / `critical` | `failing` |
| 穩定版本 | `blue` | `v1.2.0` |
| 預釋出、原型 | 自定義紫 `8957e5` / `orange` | `v0.1 prototype` |
| 許可證 | `blue` / `green` | `MIT` |
| 文件狀態 | `yellowgreen` | `docs` |
| 棄用、停止維護 | `red` / `inactive` | `deprecated` |

**推薦配置**：品牌色、狀態色各專案內固定一套，不得隨手更換；同一語義在全倉庫使用同一顏色編碼。

格式示例：

```markdown
![覆蓋率](https://img.shields.io/badge/coverage-95%25-orange?style=flat-square)
![狀態](https://img.shields.io/badge/status-v0.1%20prototype-8957e5?style=flat-square)
![許可證](https://img.shields.io/badge/license-MIT-blue?style=flat-square)
```

## 4. 圖示引數（logo / logoColor / logoSize）

### 4.1 使用 Simple Icons

`logo` 引數取 Simple Icons 的圖示 slug，格式為 `?logo=<slug>`。常用 slug 如下：

| 用途 | slug | 實測出現次數（N=120） |
| --- | --- | --- |
| GitHub 倉庫 | `github` | 35 |
| Discord 社群 | `discord` | 20 |
| npm 包 | `npm` | 4 |
| 蘋果平臺 | `apple` | 3 |
| Docker | `docker` | 3 |
| 社交平臺 X | `x` | 3 |
| Python 包 | `pypi` | 2 |

完整 slug 以 Simple Icons 站點或 simple-icons 倉庫的 `slugs.md` 為準。

### 4.2 圖示配色與尺寸

- `logoColor`：設定 Simple Icons 圖示顏色，支援十六進位制、rgb、hsl、CSS 命名色；僅對 Simple Icons 圖示生效，對自定義圖示無效。
- `logoSize`：設為 `auto` 時圖示按內容自適應縮放，適用於較寬的圖示；同樣僅對 Simple Icons 生效。

格式示例：

```markdown
![repo](https://img.shields.io/badge/github-repo-blue?logo=github)
![logo 配色](https://img.shields.io/badge/logo-javascript-blue?logo=javascript&logoColor=f5f5f5)
```

自定義圖示可透過 `logo=data:image/svg+xml;base64,...` 傳入，但 URL 極長，不利於維護，非特殊需要不推薦。

## 5. 其他查詢引數

| 引數 | 作用 | 示例 |
| --- | --- | --- |
| `label` | 覆蓋預設左側文字（空格須編碼） | `?label=healthiness` |
| `labelColor` | 左側背景色 | `?labelColor=abcdef` |
| `color` | 右側背景色 | `?color=fedcba` |
| `cacheSeconds` | HTTP 快取時長（秒），低於預設值將被忽略 | `?cacheSeconds=3600` |
| `link` | 指定點選左右半區的跳轉地址 | 僅 `<object>` 標籤內生效，Markdown 圖片無效 |

## 6. 動態徽章

動態徽章由 Shields.io 從外部服務實時拉取資料，無需手動更新數值。常用型別：

| 類別 | URL 模式 | 用途 |
| --- | --- | --- |
| 構建狀態 | `https://img.shields.io/github/actions/workflow/status/<owner>/<repo>/<workflow>` | CI 狀態 |
| 版本 | `https://img.shields.io/npm/v/<package>` | npm 最新版 |
| 許可證 | `https://img.shields.io/npm/l/<package>` | 包許可證 |
| Star 數 | `https://img.shields.io/github/stars/<owner>/<repo>` | 受歡迎程度 |
| Issue 數 | `https://img.shields.io/github/issues/<owner>/<repo>` | 待處理問題 |
| 下載量 | `https://img.shields.io/npm/dt/<package>` | 累計下載 |

動態徽章可追加 `?style=`、`?logo=` 等引數，規則與靜態徽章一致。標杆專案普遍採用「動態徽章展示真實指標 + 靜態徽章補充自定義狀態」的組合。

## 7. 資訊取捨與排列順序

### 7.1 資訊取捨

徽章應傳遞「可驗證、對讀者有用」的狀態資訊。建議只保留以下類別：

1. 構建 / 測試狀態；
2. 版本或最新發布；
3. 許可證；
4. 文件狀態；
5. 社群渠道（Discord、討論區）；
6. 專案自定義狀態（原型、維護中、已棄用）。

不得放入：無來源的下載量、與專案無關的營銷標籤、無法驗證的評分、純裝飾性色塊。

### 7.2 排列順序

推薦按「狀態 → 版本 → 許可證 → 平臺/社群 → 自定義狀態」排列，重要性從左到右遞減。理由：構建狀態決定讀者是否採用，版本決定相容性判斷，許可證決定能否使用，二者均屬決策前置資訊。

### 7.3 數量控制

- 常規專案：4–6 枚。
- 資源合集或生態專案：可放寬至 8–10 枚。
- 所有徽章置於專案名與一句話定位之後、正文之前，獨佔一行或居中容器，不在正文中散落。

### 7.4 靜態交付狀態徽章

第 7.1 條第 6 項「專案自定義狀態」的標準實現為靜態交付狀態徽章，由專案作者手工更新數值，適用於無外部資料來源的交付進度與維護狀態：

```text
![Status](https://img.shields.io/badge/status-4%20of%204%20delivered-brightgreen?style=flat-square)
```

1. 標準結構為 `badge/<標籤>-<訊息>-<顏色>`，樣式統一使用 `?style=flat-square`；示例含義為「4 項交付物全部交付」。
2. 訊息文字中的空格寫 `%20`，短橫線寫 `--`，下劃線寫 `__`；不得出現換行與其他未轉義特殊字元。
3. 顏色語義約定：`brightgreen` 表示已完成，`yellow` 表示進行中，`red` 表示受阻，`lightgrey` 表示未開始。
4. 數值變化時須同步更新徽章與正文，徽章不得長期落後於實際狀態；無法保證同步時改用動態徽章。
5. `alt` 文字寫明實際含義，如 `![交付状态]`；可連結到交付物清單或對應索引章節。

## 8. 無障礙與主題適配

- 每枚徽章的 `alt` 文字須寫明實際含義，例如 `![构建状态]` 而非 `![badge]`。
- 深色 / 淺色主題下，可透過 `<picture>` 切換徽章圖片源；使用 `for-the-badge` 並配 `labelColor=000` 可在兩種主題下保持穩定對比。
- 徽章須可點選跳轉到對應資料來源（構建狀態跳 CI、版本跳包管理頁、許可證跳 LICENSE 檔案）。
