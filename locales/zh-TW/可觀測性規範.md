# 可觀測性規範

> 本檔案解決什麼問題：定義日誌欄位、SLI/SLO 目標、告警規則與告警響應卡模板，保證系統狀態可見、故障可定位、告警可執行。

## 1. 規範條文

1. 可觀測性由日誌、指標、鏈路追蹤三支柱構成；三者須以統一的請求標識關聯。
2. 日誌須結構化，含時間戳、級別、請求標識；禁止記錄敏感資訊，脫敏規則見 [安全與隱私規範](./安全與隱私規範.md)。
3. 每個關鍵服務須定義 SLI 與 SLO，並給出計算口徑與統計視窗。
4. 告警規則須有明確閾值、持續時長與負責人；無處置指引的告警不得上線。
5. 告警觸發後須可關聯到 [事故響應規範](./事故響應規範.md) 的分級與處置流程。
6. 指標口徑須與 [質量度量指標規範](./質量度量指標規範.md) 統一，禁止同名不同義。

## 2. 三大支柱與欄位

| 支柱 | 必含欄位 | 要求 | 關聯鍵 |
| --- | --- | --- | --- |
| 日誌 | 時間戳、級別、請求標識、訊息、上下文 | 結構化輸出，級別只用 DEBUG/INFO/WARN/ERROR | `trace_id` |
| 指標 | 指標名、標籤、數值、採集時間 | 有明確口徑與目標值 | `service` |
| 鏈路追蹤 | 追蹤標識、跨度標識、父跨度、耗時、狀態 | 跨服務呼叫可串聯 | `trace_id` |

## 3. 日誌欄位模板

```markdown
| 欄位 | 型別 | 必填 | 說明 | 示例 |
| --- | --- | --- | --- | --- |
| timestamp | ISO 8601 | 是 | UTC 時間，含時區 | 2026-11-18T10:00:00Z |
| level | 列舉 | 是 | DEBUG / INFO / WARN / ERROR | ERROR |
| trace_id | 字串 | 是 | 全鏈路唯一標識 | 4bf92f3577b34da6 |
| service | 字串 | 是 | 服務名 | lint-api |
| message | 字串 | 是 | 不含敏感資訊的簡要描述 | rule load failed |
| context | 物件 | 否 | 可定位的上下文欄位 | {"rule":"spacing"} |
```

## 6. 欄位定義

| 欄位 | 必填 | 型別 | 填寫要點 | 示例 |
| --- | --- | --- | --- | --- |
| SLI 定義 | 是 | 文字 | 須為可計算的比例或分位值 | 成功請求數 / 總請求數 |
| 計算口徑 | 是 | 文字 | 明確納入與排除條件 | 排除健康檢查請求 |
| SLO 目標值 | 是 | 閾值 | 數值 + 單位 + 百分比 | `≥99.9%` |
| 統計視窗 | 是 | 時長 | 滾動視窗，禁止自然月模糊表述 | `滚动 30 天` |
| 錯誤預算 | 是 | 數值 | 由 SLO 目標換算得出 | `月允许 43 分钟不可用` |
| 告警表示式 | 是 | 查詢 | 可直接貼上執行 | `rate(http_5xx[5m]) > 0.01` |
| 持續時長 | 是 | 時長 | 防止瞬時抖動誤報 | `5 分钟` |
| 處置指引 | 是 | 列表 | 至少 3 步，含升級條件 | 見模板 |
| 靜默條件 | 是 | 文字 | 須有到期時間 | `发布窗口内，最长 30 分钟` |

## 7. 填寫說明

1. **SLI 選擇**：從使用者可感知的維度選 2–5 項，不以 CPU、記憶體等內部資源指標替代使用者 SLI。
2. **口徑統一**：同名指標在日誌、監控面板、告警表示式中須使用同一計算口徑。
3. **目標設定**：SLO 目標應基於當前實測值與業務容忍度，禁止直接套用「四個九」而無論證。
4. **錯誤預算**：須寫明換算結果與分級消耗動作；預算耗盡時凍結非關鍵釋出。
5. **告警可執行**：每條告警須回答「關注什麼、如何排查、何時升級」三問；缺一問不得上線。
6. **告警疲勞治理**：連續 30 天未產生有效處置的告警應下調級別或刪除，並說明理由。
7. **脫敏**：日誌上下文欄位中若可能出現金鑰、令牌、個人隱私，須在輸出前脫敏。

常見錯誤：

| 錯誤寫法 | 問題 | 修正方式 |
| --- | --- | --- |
| 用 CPU 使用率作為 SLI | 非使用者可感知 | 改用可用性、延遲、錯誤率 |
| 告警只寫「服務異常」 | 無閾值、無指引 | 補表示式、閾值與處置步驟 |
| 日誌列印完整請求頭 | 隱私與金鑰洩漏風險 | 白名單輸出必要欄位 |
| 告警無靜默到期時間 | 長期靜默導致漏報 | 設定最長靜默時長 |
| SLO 無統計視窗 | 目標不可判定 | 補滾動視窗 |

## 8. 完整示例

```markdown
# SLO 定義：lint-api

版本：v1.0 ｜ 負責人：王五 ｜ 複核週期：每季度

## SLI 定義
| SLI | 定義 | 計算口徑 | 資料來源 |
| --- | --- | --- | --- |
| 可用性 | 成功請求數 / 總請求數 | 狀態碼 <500，排除健康檢查 | Grafana lint-overview |
| 延遲 | 檢查請求耗時 P95 | 僅統計 /check 路徑 | Grafana lint-overview |

## SLO 目標
| SLI | 目標值 | 統計視窗 | 當前值 | 達標狀態 |
| --- | --- | --- | --- | --- |
| 可用性 | ≥99.9% | 滾動 30 天 | 99.94% | 達標 |
| 延遲 P95 | <300ms | 滾動 7 天 | 268ms | 達標 |

## 錯誤預算
- 計算方式：0.1% × 30 天 = 43 分鐘/月
- 消耗告警：50% 通知負責人，75% 通知值班組，90% 凍結非關鍵釋出
- 耗盡策略：暫停功能釋出，僅允許穩定性修復

### ALERT-001：5xx 錯誤率超閾值
- 關聯 SLI：可用性
- 表示式：`rate(http_requests_total{status=~"5.."}[5m]) / rate(http_requests_total[5m])`
- 閾值：>0.01
- 持續時長：5 分鐘
- 嚴重級別：P1
- 負責人：王五
- 處置指引：
  1. 開啟 Grafana lint-overview 確認錯誤來源服務
  2. 查詢 ERROR 日誌並按 trace_id 串聯呼叫鏈；常見原因為規則外掛載入失敗
  3. 10 分鐘內未定位則升級至李四並進入 P1 事故流程
```
