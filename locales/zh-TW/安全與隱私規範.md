# 安全與隱私規範

> 本檔案解決什麼問題：定義敏感資訊防護、資料隱私清單、SECURITY.md 模板與漏洞上報欄位，保證公開前無洩漏、資料處理合規、漏洞渠道可達。

## 1. 規範條文

1. 不得提交金鑰、令牌、私鑰、`.env`、雲廠商 AK/SK、資料庫連線串（對應硬規則 H3）。
2. 金鑰掃描須覆蓋工作區與完整歷史，在推送前執行（見 [推送與釋出規範](./推送與釋出規範.md)）。
3. 內部域名、IP、個人資訊、日誌殘留須在公開前清理（對應維度 D1）。
4. 一旦金鑰已推送，須立即輪換 + 清理歷史，不得只做刪除提交（對應 H12）。
5. 說明收集哪些資料、用途、儲存位置與保留期限；傳輸與儲存加密，展示脫敏。
6. 許可權模型遵循最小必要原則；涉及跨境資料的須單獨評估。
7. 提供可直達維護者的漏洞上報渠道，承諾保密與響應時限；已知風險如實說明，不承諾絕對安全。

## 5. 欄位定義

| 欄位 | 必填 | 型別 | 填寫要點 | 示例 |
| --- | --- | --- | --- | --- |
| 覆蓋歷史 | 是 | 列舉 | 必須選「是」方可判定透過 | `是` |
| 檢查項.結果 | 是 | 數值 | 填命中數，禁止「大概沒有」 | `0` |
| 已輪換金鑰清單 | 條件必填 | 列表 | 命中金鑰時必填，列輪換憑證 | `API_KEY 已轮换` |
| 資料項.保留期限 | 是 | 文字 | 具體時長，不可寫「長期」 | `账号删除后 30 天` |
| 資料項.第三方共享 | 是 | 文字 | 無則寫「無」 | `无` |
| 支援版本 | 是 | 表格 | 明確哪些版本接受報告 | `2.x：是` |
| 上報渠道 | 是 | 文字 | 至少一個非公開渠道 | `Security Advisories` |
| 響應時限 | 是 | 時長 | 每階段均有數值 | `2 个工作日` |

## 6. 填寫說明

1. **歷史掃描**：金鑰掃描必須包含完整 git 歷史；僅掃描工作區視為無效。
2. **金鑰命中**：一旦發現已推送金鑰，先輪換再清理歷史，順序不得顛倒（對應 H12）。
3. **脫敏**：展示與日誌中出現的敏感欄位須掩碼；禁止完整列印令牌、身份證號、手機號。
4. **保留期限**：「長期儲存」不合格，須給出明確期限或觸發刪除的事件。
5. **支援版本**：至少列當前主版本；舊版本不支援時須明確寫出，避免使用者誤報。
6. **上報渠道**：必須是非公開渠道；公開 Issue 中披露漏洞會擴大風險。
7. **已知風險**：如實列出；「本系統絕對安全」屬禁止表述。

常見錯誤：

| 錯誤寫法 | 問題 | 修正方式 |
| --- | --- | --- |
| 只刪金鑰提交不輪換 | 違反 H12 | 先輪換再清理歷史 |
| 自查只掃工作區 | 歷史洩漏漏檢 | 加歷史掃描 |
| 資料保留寫「永久」 | 無邊界 | 給具體期限 |
| 漏洞走公開 Issue | 擴大暴露面 | 改私密渠道並寫入 SECURITY.md |
| 承諾「絕對安全」 | 不實表述 | 改為如實說明已知風險 |

## 7. 完整示例

```markdown
## 敏感資訊自查：markdown-lint-cli

檢查日期：2026-11-18 ｜ 執行人：王五 ｜ 覆蓋歷史：是

| 檢查項 | 工具 / 命令 | 結果 | 處置 |
| --- | --- | --- | --- |
| 工作區金鑰 | gitleaks detect | 0 | 無 |
| 歷史提交金鑰 | gitleaks detect --log-opts=--all | 0 | 無 |
| `.env` 與憑據檔案 | git ls-files | 0 | 無 |
| 內部域名 / IP | 正則檢索 | 0 | 無 |

結論：透過
- 已輪換金鑰清單：無
- 複核人：李四
```
