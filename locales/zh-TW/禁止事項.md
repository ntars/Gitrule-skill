# 禁止事項

> 本檔案解決什麼問題：彙總所有不可違反的禁止行為，作為稽核與撰寫時的最終紅線清單。

## 一、總控與推送紅線

1. 禁止在 P0 未清零時輸出「可以先推，後面補」。
2. 禁止編造檢查結果；無法檢查的項標註 `SKIP + 原因`，不得寫 PASS。
3. 禁止把多個文件合併成一個檔案交付。
4. 禁止在 README 裡塞 API 全量、貢獻指南、變更日誌。
5. 禁止使用 `--force` 推公共分支，任何情況下都不行。
6. 禁止只做「刪除提交」來處理已洩漏的金鑰。
7. 禁止脫離 [專案命名規範](./專案命名規範.md) 自創倉庫名。
8. 禁止把內部思考過程寫進交付文件。

## 二、文件撰寫紅線

1. 不得編造專案名稱、功能、效能資料、依賴版本、許可證、作者資訊、測試結果。
2. 不得複製他人 README、文件、程式碼、圖片、文案；確需引用時須註明來源與許可證。
3. 不得在未獲確認的情況下選擇許可證型別。
4. 不得出現未經驗證的效能數字、無出處的對比結論、承諾性表述（如「保證」「永久免費」）、對第三方專案的貶損性描述、與專案無關的推廣內容。
5. 不得使用來源不明的素材；圖片、圖示、字型缺失來源與許可證時標註待確認，不得直接使用。
