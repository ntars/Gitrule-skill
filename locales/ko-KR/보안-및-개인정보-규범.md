# 보안 및 개인정보 규범

> 이 파일이 해결하는 문제：민감 정보 보호, 데이터 프라이버시 체크리스트, SECURITY.md 템플릿과 취약점 신고 필드를 정의하여 공개 전 유출이 없고 데이터 처리가 컴플라이언스를 준수하며 취약점 채널에 도달할 수 있도록 보장합니다.

## 1. 규범 조항

1. 시크릿, 토큰, 개인 키, `.env`, 클라우드 사업자 AK/SK, 데이터베이스 연결 문자열을 커밋해서는 안 됩니다(하드 룰 H3 대응).
2. 시크릿 스캔은 작업 공간과 전체 이력을 포괄해야 하며, 푸시 전에 수행합니다( [푸시 및 릴리스 규범](./푸시-및-릴리스-규범.md) 참조).
3. 내부 도메인, IP, 개인정보, 로그 잔여물은 공개 전에 정리해야 합니다(차원 D1 대응).
4. 시크릿이 이미 푸시되었다면 즉시 교체 + 이력 정리를 수행해야 하며, 삭제 커밋만으로 처리해서는 안 됩니다(H12 대응).
5. 어떤 데이터를 수집하는지, 용도, 저장 위치와 보존 기간을 설명합니다. 전송과 저장은 암호화하고, 표시 시 마스킹합니다.
6. 권한 모델은 최소 필요 원칙을 따릅니다. 국경을 넘는 데이터가 관련된 경우 별도로 평가해야 합니다.
7. 유지관리자에게 직접 도달할 수 있는 취약점 신고 채널을 제공하고 비밀 유지와 응답 기한을 약속합니다. 알려진 위험은 사실대로 설명하며 절대적 안전을 약속하지 않습니다.

## 2. 민감 정보 자체 점검 템플릿

```markdown
# 민감 정보 자체 점검：{{项目名称}}

점검일：{{YYYY-MM-DD}} ｜ 수행자：{{姓名}} ｜ 이력 포괄：{{是 / 否}}

| 점검 항목 | 도구 / 명령 | 결과 | 조치 |
| --- | --- | --- | --- |
| 작업 공간 시크릿 | {{扫描工具}} | {{命中数}} | {{已清理 / 无}} |
| 이력 커밋 시크릿 | {{扫描工具 --all}} | {{命中数}} | {{已轮换 / 无}} |
| `.env` 와 자격 증명 파일 | `git ls-files \| grep -E ...` | {{文件数}} | {{已移除 / 无}} |
| 내부 도메인 / IP | {{检索命令}} | {{命中数}} | {{已替换 / 无}} |
| 개인정보 | {{检索命令}} | {{命中数}} | {{已脱敏 / 无}} |
| 로그와 스냅샷 잔여물 | {{检查命令}} | {{命中数}} | {{已清理 / 无}} |

결론：{{通过 / 不通过}}
- 교체한 시크릿 목록：{{无 / 列出}}
- 재검증자：{{姓名}}
```

## 3. 데이터 프라이버시 체크리스트 템플릿

```markdown
# 데이터 프라이버시 체크리스트：{{项目名称}}

## 데이터 항목
| 데이터 항목 | 수집 목적 | 수집 방식 | 저장 위치 | 보존 기간 | 암호화 | 마스킹 | 제3자 공유 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| {{如邮箱}} | {{账号识别}} | {{用户填写}} | {{数据库字段}} | {{删除账号后 30 天}} | {{是}} | {{展示时掩码}} | {{无}} |

## 권한 모델
| 역할 | 접근 가능 데이터 | 권한 근거 | 재검토 주기 |
| --- | --- | --- | --- |
| {{角色}} | {{最小必要范围}} | {{业务需要}} | {{每季度}} |

## 컴플라이언스 평가
- 적용 지역 법규：{{列举}}
- 국경 간 데이터 전송：{{无 / 评估结论与措施}}
- 사용자 권리 대응：{{查询 / 更正 / 删除的渠道与时限}}
```

## 4. SECURITY.md 템플릿

```markdown
# 보안 정책

## 지원 버전
| 버전 | 보안 보고 접수 여부 |
| --- | --- |
| {{最新主版本}} | 예 |
| {{旧版本}} | 아니요 / 심각한 문제만 |

## 신고 채널
- 우선：{{私密渠道，如 GitHub Security Advisories}}
- 대체：{{加密邮箱}}
- 공개 Issue 로 취약점을 신고하지 마십시오.

## 응답 약속
| 단계 | 기한 |
| --- | --- |
| 접수 확인 | {{2 个工作日}} |
| 1차 확인 | {{5 个工作日}} |
| 수정과 공개 | {{视严重程度，目标 30 天}} |

## 처리 절차
접수 → 확인 → 수정 → 공개 → 공지

## 알려진 위험
{{如实说明当前已知风险；无则写「暂无已知风险」，不得承诺绝对安全}}
```

## 5. 필드 정의

| 필드 | 필수 | 유형 | 작성 요점 | 예시 |
| --- | --- | --- | --- | --- |
| 이력 포괄 | 예 | 열거 | 반드시 「예」를 선택해야 통과로 판정 가능 | `是` |
| 점검 항목.결과 | 예 | 숫자 | 적중 수를 기재하며 「대략 없음」은 금지 | `0` |
| 교체한 시크릿 목록 | 조건부 필수 | 목록 | 시크릿 적중 시 필수, 교체한 자격 증명 나열 | `API_KEY 교체 완료` |
| 데이터 항목.보존 기간 | 예 | 텍스트 | 구체적 기간, 「장기」로 쓸 수 없음 | `계정 삭제 후 30일` |
| 데이터 항목.제3자 공유 | 예 | 텍스트 | 없으면 「없음」으로 작성 | `없음` |
| 지원 버전 | 예 | 표 | 어떤 버전이 보고를 접수하는지 명확히 | `2.x: 예` |
| 신고 채널 | 예 | 텍스트 | 최소 하나의 비공개 채널 | `Security Advisories` |
| 응답 기한 | 예 | 기간 | 각 단계에 숫자 값이 있어야 함 | `영업일 2일` |

## 6. 작성 설명

1. **이력 스캔**: 시크릿 스캔은 전체 git 이력을 포함해야 하며, 작업 공간만 스캔하면 무효로 간주합니다.
2. **시크릿 적중**: 이미 푸시된 시크릿을 발견하면 먼저 교체한 후 이력을 정리하며, 순서를 바꿔서는 안 됩니다(H12 대응).
3. **마스킹**: 표시와 로그에 나타나는 민감 필드는 마스킹해야 하며, 토큰, 주민등록번호, 휴대전화번호를 전체 출력하는 것은 금지합니다.
4. **보존 기간**: 「영구 보관」은 부적합하며, 명확한 기간이나 삭제를 유발하는 이벤트를 제시해야 합니다.
5. **지원 버전**: 최소한 현재 주 버전을 나열해야 하며, 구 버전을 지원하지 않을 때는 명확히 적어 사용자의 오신고를 방지합니다.
6. **신고 채널**: 반드시 비공개 채널이어야 하며, 공개 Issue 에 취약점을 공개하면 위험이 확대됩니다.
7. **알려진 위험**: 사실대로 나열합니다. 「본 시스템은 절대적으로 안전함」은 금지 표현입니다.

흔한 오류:

| 잘못된 작성 | 문제 | 수정 방식 |
| --- | --- | --- |
| 시크릿 커밋만 삭제하고 교체하지 않음 | H12 위반 | 먼저 교체한 후 이력 정리 |
| 자체 점검이 작업 공간만 스캔 | 이력 유출 누락 | 이력 스캔 추가 |
| 데이터 보존을 「영구」로 작성 | 경계 없음 | 구체적 기간 제시 |
| 취약점을 공개 Issue 로 처리 | 노출 면 확대 | 비공개 채널로 변경하고 SECURITY.md 에 기록 |
| 「절대적 안전」 약속 | 허위 표현 | 알려진 위험을 사실대로 설명하도록 변경 |

## 7. 완전한 예시

```markdown
## 민감 정보 자체 점검：markdown-lint-cli

점검일：2026-11-18 ｜ 수행자：王五 ｜ 이력 포괄：예

| 점검 항목 | 도구 / 명령 | 결과 | 조치 |
| --- | --- | --- | --- |
| 작업 공간 시크릿 | gitleaks detect | 0 | 없음 |
| 이력 커밋 시크릿 | gitleaks detect --log-opts=--all | 0 | 없음 |
| `.env` 와 자격 증명 파일 | git ls-files | 0 | 없음 |
| 내부 도메인 / IP | 정규식 검색 | 0 | 없음 |

결론：통과
- 교체한 시크릿 목록：없음
- 재검증자：李四
```
