# NOTICE 규범

> 이 파일이 해결하는 문제：NOTICE 파일에 반드시 포함해야 하는 7개 부분과 README와의 일관성 요구사항을 정의하여, 제3자 고지가 독립된 파일로 존재하고 정보가 정확하도록 보장합니다.

## 1. 독립 파일 구성

NOTICE는 독립된 파일로 구성하며, README와 병합해서는 안 되고 README 목록으로 대체해서도 안 됩니다. 다음 부분을 포함해야 한다:

1. **프로젝트 자체 고지**: 프로젝트 이름, 저작권자, 연도, 라이선스, SPDX 식별자.
2. **제3자 컴포넌트 목록**: [오픈소스 컴플라이언스 규범](./오픈소스-컴플라이언스-규범.md)의 의존성 목록 필드에 따라 항목별로 나열합니다.
3. **라이선스 원문 부록**: 라이선스가 전문 첨부를 요구하는 경우, 각각의 원문을 첨부해야 하며, 원문은 영어로 유지하고 번역하지 않는다.
4. **수정 고지**: 제3자 코드의 수정 위치와 내용.
5. **소재 및 데이터 출처 고지**.
6. **면책 조항**: 영어 원문을 유지하며, 한국어 대조본을 첨부할 수 있습니다.
7. **확인 대기 항목**: 라이선스나 저작권 귀속을 확인할 수 없는 항목은 「확인 대기」로 명시적으로 표기합니다.

## 2. 일관성 요구사항

NOTICE는 README 제6장(기술 스택 및 의존성 목록), 제19장(저작권 및 라이선스), 제20장(NOTICE 컴플라이언스 선언)의 컴포넌트 및 라이선스 정보와 완전히 일치해야 하며, 버전, 라이선스 식별자, 저작권자에 차이가 있어서는 안 됩니다.

## 3. 계층 라이선스의 선언 방식

프로젝트가 계층 라이선스를 채택할 때 제1절의 「프로젝트 자체 고지」는 계층별로 나누어야 하며, 주 라이선스만 적어서는 안 됩니다.

1. 각 계층을 한 줄씩 두고 적용 범위(예: 「`cli/`, `mcp/` 아래의 소스 코드」), 라이선스 이름, SPDX 식별자, 라이선스 전문 위치를 적습니다.
2. 각 계층을 합친 SPDX 표현식은 README 제19장과 글자 그대로 일치해야 하며, 한쪽은 `MIT AND CC-BY-4.0`, 다른 쪽은 `MIT`만 적는 상태여서는 안 됩니다.
3. 계층화 근거를 한 문장으로 밝혀야 합니다. 예를 들어 「코드와 문서의 재사용 요구가 다르다」이며, 이후 유지보수자가 특정 파일의 소속 계층을 판단하는 근거가 됩니다.
4. 계층에 귀속할 수 없는 내용이 있으면 「확인 대기 항목」에 파일 경로를 나열하고, 기본값으로 주 라이선스에 산입해서는 안 됩니다.
5. 면책 조항은 README 제19장, `LICENSING.md`(있는 경우) 세 곳에서 문구를 일치시켜야 하며, 라이선스 선택과 계층 구분은 프로젝트 측이 스스로 확인하는 것이고 도구와 템플릿은 법적 조언을 구성하지 않는다는 점을 설명합니다.
