# 실행 프로세스

> 이 파일이 해결하는 문제：착수부터 납품까지의 전체 단계 순서, 각 단계의 진입 조건과 산출물, 그리고 정보가 부족할 때의 차단형 질문 규칙을 정의합니다.

## 1. 총괄 푸시 프로세스(Phase 0–6)

### Phase 0 · 착수(Project Init)

출력：프로젝트 이름 후보 3개 + 선택 이유 + 중복 이름 검색 결론 + 리포지터리 메타데이터 표(description / topics / 기본 브랜치 / 공개 범위 / license). 명명 규칙은 [프로젝트 명명 규범](./프로젝트-명명-규범.md)을 참조하십시오.

### Phase 1 · 인벤토리(Inventory)

리포지터리를 스캔하여 구조화된 목록을 산출합니다：
- 기술 스택, 진입 파일, 패키지 관리자, lockfile
- 기존 문서, 누락 문서
- 리포지터리 용량 상위 10개 대용량 파일
- 기존 CI / 템플릿 / 보호 규칙
- 현재 git 상태: 추적되지 않은 파일, 커밋되지 않은 변경, 이력 내 의심스러운 커밋

### Phase 2 · 병렬 감사(Audit)

[감사 차원 매트릭스](./감사-차원-매트릭스.md)에 따라 차원을 서브 에이전트에 위임하여 병렬 실행하며, 위임 방식은 [서브 에이전트 위임 계약](./서브-에이전트-위임-계약.md)을 참조하십시오. 각 서브 에이전트는 구조화된 결론만 반환하고 장문의 산문은 반환하지 않습니다.

### Phase 3 · 수정(Fix)

P0 → P1 → P2 순서로 할 일을 나열하고 담당 에이전트와 예상 조치를 표시합니다. P0가 0건이 되지 않으면 Phase 5로 진입할 수 없습니다.

### Phase 4 · 문서 생성(Docs)

[문서 매트릭스](./문서-매트릭스.md)에 따라 파일별로 문서 에이전트에 위임합니다. **한 번에 하나의 파일만 작성하고, 작성 후 검증한 다음 다음 파일로 넘어갑니다.**

### Phase 5 · 푸시(Push)

[푸시 및 릴리스 규범](./푸시-및-릴리스-규범.md)에 따라 실행하며, 결과를 항목별로 에코 출력합니다.

### Phase 6 · 푸시 후(Post-Push)

태그를 생성하고, Release Notes를 작성하며, 배지와 링크의 사용 가능 여부를 검증하고, CI 녹색을 확인하며, About 영역 정보의 정확성을 확인합니다.

## 2. 문서 생성 프로세스(단계 0–5)

단계 순서대로 진행하며, 이전 단계가 완료되지 않으면 다음 단계로 진입할 수 없습니다.

| 단계 | 이름 | 진입 조건 | 산출 |
| --- | --- | --- | --- |
| 0 | 정보 검증 | 본 규범과 프로젝트 자료를 접수함 | 확인된 정보 목록, 누락 정보 목록 |
| 1 | 차단형 질문 | 필수 필드 누락 존재([정보 수집 및 템플릿](./정보-수집-및-템플릿.md) 참조) | 구조화된 질문 목록, 필드별 그룹화 |
| 2 | 프레임워크 확인 | 필수 필드 완비 | README 섹션 목차와 각 장의 핵심 개요, 사용자 확인용 |
| 3 | 문서 생성 | 사용자가 프레임워크를 확인했거나 확인이 불필요하다고 명시함 | 전체 산출물 |
| 4 | 품질 게이트 | 문서 생성 완료 | [품질 게이트](./품질-게이트.md) 항목별 판정 결과 |
| 5 | 납품 | 게이트 전체 통과 또는 미통과 항목 표시 완료 | [감사 보고서 형식](./감사-보고서-형식.md) 순서대로 출력하고 푸시 가이드 첨부 |

## 3. 단계 1 질문 규칙

1. 필드별로 그룹화하여 질문하며, 한 회차에 15개를 초과하지 않습니다.
2. 각 질문은 용도와 영향을 주는 섹션을 설명해야 하며, 사용자가 우선순위를 판단할 수 있어야 합니다.
3. 사용자가 특정 항목을 제공할 수 없다고 명시하면 문서의 해당 위치에 「【확인 필요: 필드명】」을 표시하고, 문서 말미에 집계합니다.
4. 사용자가 「당신의 판단에 따르라」고 답하면 제안값을 제시할 수 있으나, 반드시 「【제안값, 사용자 확인 필요】」를 표시해야 합니다.

## 관련 파일

- 역할과 책임은 [역할과 책임](./역할과-책임.md)을 참조하십시오
- 필수 필드와 누락 항목 표시는 [정보 수집 및 템플릿](./정보-수집-및-템플릿.md)을 참조하십시오
- 게이트 판정은 [품질 게이트](./품질-게이트.md)를 참조하십시오
