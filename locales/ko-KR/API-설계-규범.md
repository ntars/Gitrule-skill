# API 설계 규범

> 이 파일이 해결하는 문제：인터페이스 설계의 일관성 원칙과 약속을 정의하여 API를 사용하기 쉽고 예측 가능하며 진화 가능하도록 보장합니다.

## 1. 설계 원칙

1. 명명 일관성: 같은 종류의 리소스와 작업에는 통일된 명명 규칙을 사용합니다.
2. 예측 가능성: 같은 의미의 작업은 같은 구조를 가집니다.
3. 명시적이 암묵적보다 우선: 기본값, 필수 항목, 오류 동작을 명확히 해야 합니다.
4. 하위 호환성: 변경은 호환성 유지를 우선하며, 호환성 파괴 변경은 버전화해야 합니다([버전 관리 규범](./버전-관리-규범.md) 참조).

## 2. 필수 약속

1. **명명**: 리소스, 메서드, 필드의 명명 규칙.
2. **파라미터**: 유형, 필수 여부, 기본값, 값 범위.
3. **오류**: 통일된 오류 구조, 오류 코드, HTTP 상태 또는 동등 메커니즘.
4. **페이지네이션과 필터링**: 대용량 시나리오의 페이지네이션, 정렬, 필터링 약속.
5. **멱등성**: 쓰기 작업의 멱등 보장.
6. **속도 제한과 쿼터**: 빈도 제한과 초과 시 응답.
7. **버전**: API 버전 전략과 진화 방식.

## 3. 강제 규칙

1. 오류 응답은 위치를 특정할 수 있는 오류 코드와 설명을 포함해야 하며, 내부 구현 세부사항을 노출하지 않습니다.
2. 호환성 파괴 변경은 버전을 올리고 마이그레이션 기간을 제공해야 합니다([변경 이력 규범](./변경-이력-규범.md) 참조).
3. 인터페이스는 대응하는 문서가 있어야 하며 필드가 완전해야 합니다([API 문서 규범](./API-문서-규범.md) 참조).
