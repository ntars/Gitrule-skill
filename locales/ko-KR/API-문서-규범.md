# API 문서 규범

> 이 파일이 해결하는 문제：완전한 API 레퍼런스 문서의 구조와 필드를 정의하며, docs/api.md 작성 근거로 삼고 튜토리얼류 콘텐츠와 엄격히 분리합니다.

## 1. 필수 구조

각 API 항목은 다음을 포함해야 합니다.

| 필드 | 요구사항 |
| --- | --- |
| 인터페이스 시그니처 | 메서드, 경로 또는 함수 프로토타입, 완전하고 복사 가능 |
| 파라미터 | 이름, 유형, 필수 여부, 기본값, 값 범위, 설명 |
| 반환값 | 유형과 구조 설명 |
| 오류 코드 | 오류 코드, 트리거 조건, 처리 방식 |
| 호출 예시 | 실행 가능한 최소 예제, 언어 표기 |
| 속도 제한과 할당량 | 호출 빈도 제한, 할당량, 초과 시 처리 |

## 2. 강제 규칙

1. 파라미터와 반환값은 유형과 제약을 명시해야 하며, 기본값을 생략해서는 안 됩니다.
2. 오류 코드는 완전히 나열해야 하며, 「오류가 발생할 수 있음」이라고만 작성해서는 안 됩니다.
3. 코드 블록은 언어 식별자를 표기해야 하며, 예제는 독립적으로 실행 가능해야 합니다.
4. 본 파일에는 참고 정보만 두고, 튜토리얼, 배경, 설계 설명은 작성하지 않습니다(튜토리얼과 배경은 [README 섹션 규범](./README-섹션-규범.md) 참조).

## 3. 일관성 요구

API 문서의 인터페이스 시그니처는 코드의 실제 구현과 일치해야 하고, 파라미터 명명은 [범용 작성 규범](./범용-작성-규범.md)의 정확성 요구와 일치해야 하며, 용어는 [용어집](./용어집.md)을 참조하십시오.

## 관련 파일

- 문서 책임 경계는 [문서 매트릭스](./문서-매트릭스.md)를 참조하십시오
- API 설계 규범(인터페이스를 설계하는 방법)은 [API 설계 규범](./API-설계-규범.md)을 참조하십시오
- 문서 품질은 차원 D12에 해당하며, [감사 차원 매트릭스](./감사-차원-매트릭스.md)를 참조하십시오
