# 관측성 규범

> 이 파일이 해결하는 문제：로그 필드, SLI/SLO 목표, 알림 규칙과 알림 대응 카드 템플릿을 정의하여 시스템 상태를 볼 수 있고, 장애를 위치 파악할 수 있으며, 알림이 실행 가능하도록 보장한다.

## 1. 규범 조항

1. 관측성은 로그, 지표, 분산 추적의 세 기둥으로 구성되며, 세 가지는 통일된 요청 식별자로 연결되어야 한다.
2. 로그는 구조화되어야 하며, 타임스탬프, 레벨, 요청 식별자를 포함해야 한다. 민감 정보 기록을 금지하며, 마스킹 규칙은 [보안 및 개인정보 규범](./보안-및-개인정보-규범.md)을 참조한다.
3. 각 핵심 서비스는 SLI와 SLO를 정의하고, 계산 기준과 통계 윈도우를 제시해야 한다.
4. 알림 규칙은 명확한 임계값, 지속 시간, 책임자가 있어야 하며, 처리 지침이 없는 알림은 출시할 수 없다.
5. 알림이 트리거된 후 [인시던트 대응 규범](./인시던트-대응-규범.md)의 등급과 처리 프로세스에 연결될 수 있어야 한다.
6. 지표 기준은 [품질 메트릭 규범](./품질-메트릭-규범.md)과 통일되어야 하며, 같은 이름에 다른 의미를 두는 것을 금지한다.

## 2. 세 기둥과 필드

| 기둥 | 필수 포함 필드 | 요구사항 | 연결 키 |
| --- | --- | --- | --- |
| 로그 | 타임스탬프, 레벨, 요청 식별자, 메시지, 컨텍스트 | 구조화 출력, 레벨은 DEBUG/INFO/WARN/ERROR만 사용 | `trace_id` |
| 지표 | 지표명, 레이블, 값, 수집 시간 | 명확한 기준과 목표값 존재 | `service` |
| 분산 추적 | 추적 식별자, 스팬 식별자, 부모 스팬, 소요 시간, 상태 | 서비스 간 호출 연결 가능 | `trace_id` |

## 3. 로그 필드 템플릿

```markdown
| 필드 | 유형 | 필수 | 설명 | 예시 |
| --- | --- | --- | --- | --- |
| timestamp | ISO 8601 | 예 | UTC 시간, 시간대 포함 | 2026-11-18T10:00:00Z |
| level | 열거형 | 예 | DEBUG / INFO / WARN / ERROR | ERROR |
| trace_id | 문자열 | 예 | 전 구간 고유 식별자 | 4bf92f3577b34da6 |
| service | 문자열 | 예 | 서비스 이름 | lint-api |
| message | 문자열 | 예 | 민감 정보를 포함하지 않는 간략 설명 | rule load failed |
| context | 객체 | 아니오 | 위치 파악 가능한 컨텍스트 필드 | {"rule":"spacing"} |
```

## 4. SLI/SLO 정의 템플릿

```markdown
# SLO 정의: {{서비스 이름}}

버전: {{v1.0}} ｜ 책임자: {{이름}} ｜ 검토 주기: {{매 분기}}

## 서비스 경계
- 서비스 책임: {{한 문장}}
- 의존 서비스: {{업스트림 / 다운스트림}}
- 사용자 핵심 작업: {{2–5개 나열}}

## SLI 정의
| SLI | 정의 | 계산 기준 | 데이터 소스 |
| --- | --- | --- | --- |
| 가용성 | 성공 요청 수 / 전체 요청 수 | HTTP 상태 코드 <500을 성공으로 간주 | {{모니터링 대시보드}} |
| 지연 | 요청 소요 시간 분포 | P95 분위값 | {{모니터링 대시보드}} |
| 오류율 | 실패 요청 수 / 전체 요청 수 | 5xx 집계 | {{모니터링 대시보드}} |

## SLO 목표
| SLI | 목표값 | 통계 윈도우 | 현재값 | 달성 상태 |
| --- | --- | --- | --- | --- |
| 가용성 | ≥99.9% | 롤링 30일 | {{값}} | {{달성 / 미달성}} |
| 지연 P95 | <300ms | 롤링 7일 | {{값}} | {{달성 / 미달성}} |
| 오류율 | <0.1% | 롤링 24시간 | {{값}} | {{달성 / 미달성}} |

## 오류 예산
- 계산 방식: {{1 - SLO 목표값, 통계 윈도우 기준 환산}}
- 소진 알림: {{소진 50% / 75% / 90% 시 각각 통지}}
- 소진 전략: {{비핵심 릴리스 동결, 안정성 수정 우선}}
```

## 5. 알림 규칙 템플릿

```markdown
### ALERT-{{세 자리 일련번호}}: {{알림 이름}}

- 관련 SLI: {{가용성 / 지연 / 오류율}}
- 표현식: {{실행 가능한 쿼리 표현식}}
- 임계값: {{수치 + 단위}}
- 지속 시간: {{N분}}
- 심각도: {{P0 / P1 / P2}}
- 책임자: {{이름 / 당직 그룹}}
- 트리거 예시: {{트리거되는 샘플 데이터 하나 제시}}
- 무음 조건: {{언제 무음이 허용되는지, 만료 시간 필수}}

처리 지침:
1. {{1단계: 현상 확인을 위한 데이터 소스와 명령}}
2. {{2단계: 흔한 원인과 대응 처리}}
3. {{3단계: 에스컬레이션 조건과 대상}}
- 관련 인시던트 등급: {{인시던트 대응 규범의 등급 표 참조}}
```

## 6. 필드 정의

| 필드 | 필수 | 유형 | 작성 요점 | 예시 |
| --- | --- | --- | --- | --- |
| SLI 정의 | 예 | 텍스트 | 계산 가능한 비율 또는 분위값이어야 함 | 성공 요청 수 / 전체 요청 수 |
| 계산 기준 | 예 | 텍스트 | 포함 및 제외 조건 명확화 | 상태 점검 요청 제외 |
| SLO 목표값 | 예 | 임계값 | 수치 + 단위 + 백분율 | `≥99.9%` |
| 통계 윈도우 | 예 | 기간 | 롤링 윈도우, 자연월 모호 표현 금지 | `롤링 30일` |
| 오류 예산 | 예 | 수치 | SLO 목표에서 환산 | `월 43분 불가용 허용` |
| 알림 표현식 | 예 | 쿼리 | 바로 붙여넣어 실행 가능 | `rate(http_5xx[5m]) > 0.01` |
| 지속 시간 | 예 | 기간 | 순간적 변동으로 인한 오탐 방지 | `5분` |
| 처리 지침 | 예 | 목록 | 최소 3단계, 에스컬레이션 조건 포함 | 템플릿 참조 |
| 무음 조건 | 예 | 텍스트 | 만료 시간 필수 | `릴리스 윈도우 내, 최대 30분` |

## 7. 작성 설명

1. **SLI 선택**: 사용자가 인지할 수 있는 차원에서 2–5개를 선택하며, CPU, 메모리 등 내부 자원 지표로 사용자 SLI를 대체하지 않는다.
2. **기준 통일**: 같은 이름의 지표는 로그, 모니터링 대시보드, 알림 표현식에서 동일한 계산 기준을 사용해야 한다.
3. **목표 설정**: SLO 목표는 현재 실측값과 비즈니스 허용도를 기반으로 해야 하며, 근거 없이 「포 나인」을 그대로 적용하는 것을 금지한다.
4. **오류 예산**: 환산 결과와 단계별 소진 조치를 명시해야 한다. 예산 소진 시 비핵심 릴리스를 동결한다.
5. **알림 실행 가능성**: 각 알림은 「무엇을 주시하는지, 어떻게 조사하는지, 언제 에스컬레이션하는지」 세 가지 질문에 답해야 하며, 하나라도 빠지면 출시할 수 없다.
6. **알림 피로 관리**: 연속 30일 동안 유효한 처리가 발생하지 않은 알림은 등급을 하향하거나 삭제하고 이유를 설명해야 한다.
7. **마스킹**: 로그 컨텍스트 필드에 비밀 키, 토큰, 개인정보가 나타날 수 있으면 출력 전에 마스킹해야 한다.

흔한 오류:

| 잘못된 작성 | 문제 | 수정 방식 |
| --- | --- | --- |
| CPU 사용률을 SLI로 사용 | 사용자가 인지할 수 없음 | 가용성, 지연, 오류율로 변경 |
| 알림에 「서비스 이상」만 기술 | 임계값 없음, 지침 없음 | 표현식, 임계값, 처리 단계 보충 |
| 로그에 전체 요청 헤더 출력 | 개인정보와 비밀 키 유출 위험 | 필요한 필드만 화이트리스트 출력 |
| 알림에 무음 만료 시간 없음 | 장기 무음으로 누락 발생 | 최대 무음 시간 설정 |
| SLO에 통계 윈도우 없음 | 목표 판정 불가 | 롤링 윈도우 보충 |

## 8. 완전한 예시

```markdown
# SLO 정의: lint-api

버전: v1.0 ｜ 책임자: 왕오 ｜ 검토 주기: 매 분기

## SLI 정의
| SLI | 정의 | 계산 기준 | 데이터 소스 |
| --- | --- | --- | --- |
| 가용성 | 성공 요청 수 / 전체 요청 수 | 상태 코드 <500, 상태 점검 제외 | Grafana lint-overview |
| 지연 | 검사 요청 소요 시간 P95 | /check 경로만 집계 | Grafana lint-overview |

## SLO 목표
| SLI | 목표값 | 통계 윈도우 | 현재값 | 달성 상태 |
| --- | --- | --- | --- | --- |
| 가용성 | ≥99.9% | 롤링 30일 | 99.94% | 달성 |
| 지연 P95 | <300ms | 롤링 7일 | 268ms | 달성 |

## 오류 예산
- 계산 방식: 0.1% × 30일 = 월 43분
- 소진 알림: 50% 시 책임자 통지, 75% 시 당직 그룹 통지, 90% 시 비핵심 릴리스 동결
- 소진 전략: 기능 릴리스 일시 중지, 안정성 수정만 허용

### ALERT-001: 5xx 오류율 임계값 초과
- 관련 SLI: 가용성
- 표현식: `rate(http_requests_total{status=~"5.."}[5m]) / rate(http_requests_total[5m])`
- 임계값: >0.01
- 지속 시간: 5분
- 심각도: P1
- 책임자: 왕오
- 처리 지침:
  1. Grafana lint-overview를 열어 오류 발생 서비스 확인
  2. ERROR 로그를 조회하고 trace_id로 호출 체인 연결; 흔한 원인은 규칙 플러그인 로드 실패
  3. 10분 내에 위치 파악하지 못하면 이순신에게 에스컬레이션하고 P1 인시던트 프로세스 진입
```
