## 읽기 경로

- **적용 범위 결정**：규범 선택 가이드 → 라이프사이클 매핑 표 → 해당 단계의 규범 파일.
- **라이프사이클 관통**：라이프사이클 매핑 표 → 프로젝트 착수 및 요구사항 규범 → 요구사항 추적 매트릭스 규범 → 아키텍처 설계 문서 규범 → 테스트 규범 → 배포 및 롤백 규범 → 관측성 규범 → 이터레이션 회고 규범.
- **빠른 푸시**：하드 룰 → 품질 게이트 → 푸시 및 릴리스 규범 → 감사 보고서 형식.
- **문서를 처음부터 생성**：역할과 책임 → 실행 프로세스 → 정보 수집 및 템플릿 → 문서 매트릭스 → README 섹션 규범 → 오픈소스 컴플라이언스 규범 → 품질 게이트.

## 용어 약속

- **반드시 / 해서는 안 된다**：강제 요구.
- **해야 한다 / 해서는 안 된다**：권장 또는 금지이며, 벗어날 때는 이유를 설명해야 합니다.
- **할 수 있다**：선택 사항.
- **P0 / P1 / P2**：P0는 푸시를 차단하고, P1은 푸시 전에 수정하거나 반드시 할 일로 등록해야 하며, P2는 개선을 권장합니다.
