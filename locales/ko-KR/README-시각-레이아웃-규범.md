# README 시각 레이아웃 규범

> 이 파일이 해결하는 문제：README의 레이아웃 계층, 문단 구성, 표, 스크린샷과 GIF의 사용 시나리오 및 배치 위치를 정의하여, 문서가 정보 밀도와 시각적 매력 사이에서 균형을 이루도록 합니다.

이 문서의 「실측」 데이터는 본 프로젝트가 상위 오픈소스 프로젝트 README를 표본 통계한 결과(N=120)에서 나왔습니다. 벤치마크 사례는 여러 고스타 프로젝트의 첫 화면 구조에서 채집한 것입니다.

## 1. 레이아웃 계층

### 1.1 제목 계층

README는 명확한 제목 계층을 구축해야 하며, 다음 제약을 따릅니다：

1. 전문에서 1급 제목(`#`)은 하나만 유지하며, 즉 프로젝트 이름이며 파일 첫 줄에 위치합니다.
2. 2급 제목(`##`)은 주요 섹션이며, 개수는 6–12개가 적당하고, 실측 중앙값은 7개입니다.
3. 3급 제목(`###`)은 섹션 내 세분화에 사용하며, 2급 제목 내용이 길 때만 사용합니다.
4. 제목 계층의 도약(예: `#`에서 바로 `###`)이 있어서는 안 됩니다.
5. 제목 텍스트는 간결하게, 명사 또는 명사구를 사용하고 끝에 마침표를 찍지 않습니다.

### 1.2 첫 화면 구조 순서

첫 화면은 독자가 스크롤하지 않고 볼 수 있는 내용을 말하며, 다음 순서로 구성합니다：

1. 가운데 정렬 로고 또는 프로젝트 배너(선택 사항)；
2. 1급 제목(프로젝트 이름)；
3. 배지 행(자세한 내용은 [배지 규범](./배지-규범.md) 참조)；
4. 한 문장 포지셔닝(프로젝트가 무엇이며, 누구를 위해, 무엇을 해결하는지 설명)；
5. 섹션 내비게이션 링크 행(선택 사항, 긴 README에 적용)；
6. 핵심 기능 또는 특성 요약.

벤치마크 채집：`fd`, `ripgrep`는 포지셔닝 직후에 섹션 내비게이션을 배치했고, `next.js`, `rust-lang/rust`는 가운데 정렬 로고와 배너로 시작하며, `vscode`는 포지셔닝 직후에 제품 스크린샷을 삽입합니다.

### 1.3 문단과 여백

- 각 문단은 1–4줄로 제어하여 밀집된 대량의 텍스트를 피합니다.
- 문단 사이에 빈 줄을 하나 두어 렌더링 후의 여유를 확보합니다.
- 핵심 결론을 앞에 두고 설명을 뒤에 둡니다.
- 중국어와 영어, 숫자 사이에 공백 하나를 유지하며, 중국어와 영어 문장부호는 각자의 문맥에 따라 사용합니다.

## 2. 표 사용 규범

### 2.1 사용 시나리오

표는 다차원적이고 비교 가능한 정보에 적합합니다. 실측에서 36.7%의 표본이 표를 사용했으며, 설정 설명, 호환성 매트릭스, 명령 대조에 권장되는 형식입니다. 적용 시나리오는 다음과 같습니다：

- 설정 항목 설명(키 이름, 유형, 기본값, 역할)；
- 플랫폼 / 버전 호환성 매트릭스；
- 명령 또는 매개변수 대조；
- 기능 비교(본 프로젝트와 다른 방안)；
- 로드맵과 상태.

### 2.2 배치 위치

표는 해당 2급 제목 바로 뒤에 두고, 앞에 표의 용도를 설명하는 안내 문장을 둡니다. 표 뒤에 예외 상황이 있으면 별도 문단으로 보충합니다.

### 2.3 작성 요구사항

| 요구사항 | 설명 |
| --- | --- |
| 열 수 제어 | 3–6열, 6열을 초과하면 분할 고려 |
| 표 머리 명확 | 각 열에 짧은 명사 표 머리를 제시하여 빈 표 머리를 피함 |
| 정렬 일관 | 전문의 표 정렬 방식을 통일 |
| 내용 간결 | 셀 안에 긴 문단을 쓰지 않고, 필요 시 각주나 링크로 확장 |
| 빈 셀 없음 | 내용이 없는 곳에는 「없음」 또는 「해당 없음」을 명시 |

## 3. 코드 블록 사용 규범

### 3.1 사용 시나리오

코드 블록은 명령, 설정, API 호출과 예시 출력에 사용합니다. 실측에서 66.7%의 표본이 코드 블록을 포함하며, 「빠른 시작」 섹션의 필수 요소이고 중앙값은 2개입니다.

### 3.2 작성 요구사항

1. 모든 코드 블록에는 언어를 표기해야 하며, 예를 들어 `bash`, `json`, `python`, `javascript`를 사용하여 구문 강조를 돕습니다.
2. 명령 예시는 완전한 실행 가능 명령을 제시하고, 선행 단계를 생략해서는 안 됩니다.
3. 결과를 보여줘야 할 때는 별도 코드 블록에 `text`를 표기하고, 텍스트에서 예상 출력을 설명합니다.
4. 코드 블록 앞뒤에 빈 줄을 각각 하나 둡니다.
5. 단일 블록 내용은 20줄 이내로 제어하고, 너무 긴 예시는 여러 블록으로 나누거나 `examples/` 디렉터리로 옮기고 링크를 제시합니다.
6. 대화형 명령에서 `$` 프롬프트를 사용할 때는 전문에서 통일해야 합니다.

형식 예시：

```bash
npm install <package-name>
```

```text
✓ Installation complete
```

## 4. 스크린샷과 GIF 사용 규범

### 4.1 사용 시나리오와 취사선택

| 요소 | 적용 시나리오 | 주의사항 |
| --- | --- | --- |
| 정적 스크린샷 | 애플리케이션 인터페이스, 실행 결과, 차트 | 실측 사용률 63.3%, 가장 많이 사용됨 |
| GIF / 움직이는 이미지 | 명령줄 데모, 상호작용 흐름, 전후 비교 | 파일 용량이 크므로 압축해야 하며 재생 시간 제어 |
| 로고 / 배너 | 브랜드 인식, 첫 화면 홈 | 밝은/어두운 색상 두 버전 제공 |
| 개념도 | 아키텍처, 흐름, 데이터 흐름 | 문서 버전에 맞춰 동기 업데이트 필요 |

실측에서 63.3%의 표본이 이미지를 포함했습니다. 벤치마크 채집：`fd`는 `doc/screencast.svg`를 데모로 사용하고, `ripgrep`는 검색 결과 스크린샷을 사용하며, `vscode`는 제품 실행 스크린샷을 사용하고, `rust`, `next.js`는 밝은/어두운 테마 적응형 로고 배너를 사용합니다.

### 4.2 배치 위치

1. 로고 / 배너：파일 최상단, 가운데 정렬.
2. 제품 스크린샷：한 문장 포지셔닝 뒤, 「빠른 시작」 앞. 직관적 인지를 형성하기 위함입니다.
3. GIF 데모：독립 「데모 / 시연」 섹션, 「핵심 기능」 바로 뒤.
4. 아키텍처 개념도：「아키텍처」 또는 「설계」 섹션에 넣거나, `docs/architecture.md`로 옮기고 README에서 링크합니다.

### 4.3 작성 요구사항

- 모든 이미지는 `alt` 텍스트를 제공하여 화면 내용을 설명해야 하며, `image`, `스크린샷` 등 의미 없는 텍스트를 사용해서는 안 됩니다.
- 이미지는 상대 경로로 리포지터리 내 리소스를 참조하거나, 안정적인 절대 URL을 사용합니다. 시효성이 있는 임시 링크는 피합니다.
- 테마 적응이 필요한 이미지는 HTML `<picture>`와 `prefers-color-scheme`을 사용하여 밝은/어두운 두 버전을 제공합니다.
- 이미지 용량을 제어합니다. 스크린샷은 WebP 또는 최적화된 PNG를 우선 사용하고, GIF는 숏 비디오나 압축된 움직이는 이미지로 전환하는 것을 우선합니다.
- 이미지 너비 적응：`width` 속성이나 외부 컨테이너 제한을 사용하여 페이지가 깨지는 것을 피합니다.

## 5. 링크와 내비게이션

### 5.1 섹션 내비게이션

README가 200줄을 초과할 때는 첫 화면에 내비게이션 링크 행을 추가하여 주요 섹션을 가리킵니다：

```markdown
[설치](#설치) · [빠른 시작](#빠른-시작) · [문서](#문서) · [기여](#기여-참여)
```

### 5.2 상대 링크 우선

리포지터리 내 문서, 이미지, 라이선스는 모두 상대 경로를 사용하여 Fork 및 오프라인 열람 시에도 사용 가능하도록 보장합니다. 외부 링크는 권위 있는 출처(공식 문서, 패키지 관리 페이지, CI 페이지)여야 합니다.

## 6. 미관과 매력도 실행 체크리스트

1. 첫 화면에 로고 또는 명확한 제목이 있어 3초 이내에 프로젝트 포지셔닝을 전달합니다.
2. 배지 스타일이 통일되고, 의미 기반 배색을 사용하며, 수량이 적당합니다.
3. 1급 제목이 유일하고, 2급 제목이 6–12개이며, 계층에 도약이 없습니다.
4. 복사하여 실행할 수 있는 코드 예시가 최소 하나 있습니다.
5. 제품 가치를 보여주는 스크린샷 또는 데모가 최소 하나 있습니다.
6. 표는 비교류 정보에 사용하고, 열 수가 제어되며 표 머리가 명확합니다.
7. 모든 이미지에 `alt`가 있고, 모든 코드 블록에 언어 표기가 있습니다.
8. 긴 문서에는 섹션 내비게이션이 있습니다.
9. 밝은/어두운 테마에서 이미지와 배지 모두 읽을 수 있습니다.
