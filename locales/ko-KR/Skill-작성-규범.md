# Skill 작성 규범

> 이 파일이 해결하는 문제：규범 집합을 Skill로 패키징할 때의 구조, 트리거 조건, 점진적 로딩 방식을 정의하여, Skill이 발견 가능하고 유지보수 가능하며 내용이 중복되지 않도록 보장합니다.

## 1. 디렉터리 구조

Skill은 「진입점 + 온디맨드 리소스」 구조를 사용한다:

```text
skill-name/
├── SKILL.md          必需：元数据 + 核心流程
├── references/       规范正文，按需加载
└── assets/           模板与素材（可选）
```

## 2. SKILL.md 요구사항

1. 메타데이터에는 `name`과 `description`이 포함되며, 설명에는 반드시 「무엇을 하는지 + 언제 사용하는지」를 명시하여 트리거되도록 합니다.
2. 본문에는 상시 유지되는 핵심 규칙과 프로세스만 남기고, 상세 조회성 내용은 `references/`에 둔다.
3. 명령문/부정형 문체를 사용하고 2인칭을 피합니다.
4. 리소스를 인용할 때는 명확한 경로와 「언제 읽는지」에 대한 조건을 제시합니다.

## 3. 강제 규칙

1. 규범 본문은 한 곳에서만 유지한다: Skill은 이 규범 집합 파일을 인용하고 전문을 복제하지 않아, 이중 관리로 인한 흔들림을 방지합니다.
2. 하나의 Skill은 한 가지 일만 하며, 여러 책임을 동일한 Skill에 넣는 것은 금지합니다.
3. 트리거 조건에는 구체적인 문구를 명시하여 트리거 범위가 지나치게 넓어지지 않도록 합니다.
4. 버전은 규범 집합 버전과 함께 동기화하여 갱신합니다.
