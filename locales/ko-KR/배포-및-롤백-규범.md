# 배포 및 롤백 규범

> 이 파일이 해결하는 문제：배포 체크리스트, 변경 요청서와 롤백 사전 계획의 템플릿, 필드, 실행 기준을 정의하여 배포가 통제 가능하고, 상태를 조회할 수 있으며, 장애를 신속히 복구할 수 있도록 보장한다.

## 1. 규범 조항

1. 배포 전에 CI, 코드 리뷰, 품질 게이트를 통과해야 한다([품질 게이트](./품질-게이트.md) 참조).
2. 배포는 이미 tag가 생성된 릴리스 버전을 기반으로 하며, 표기되지 않은 커밋을 사용하지 않는다([버전 관리 규범](./버전-관리-규범.md) 참조).
3. 환경 설정과 코드를 분리하고, 민감한 설정은 구성 관리로 주입하며 리포지터리에 커밋하지 않는다([보안 및 개인정보 규범](./보안-및-개인정보-규범.md) 참조).
4. 데이터베이스 구조 변경은 마이그레이션 스크립트로 실행하며, 전방 호환성을 충족해야 한다([데이터베이스 설계 규범](./데이터베이스-설계-규범.md) 참조).
5. 각 배포는 버전 번호, 시간, 작업자, 변경 내용을 기록해야 하며, 기록 없는 배포는 비준수 배포로 본다.
6. 각 버전은 롤백 사전 계획을 미리 준비해야 하며, 롤백 사전 계획이 준비되지 않으면 배포할 수 없다.
7. 배포 후 상태 점검과 스모크 검증을 실행하고, 두 가지가 모두 통과해야 릴리스를 종료할 수 있다.

## 2. 배포 체크리스트 템플릿

```markdown
# 배포 체크리스트: {{프로젝트 이름}} {{버전 번호}}

버전: {{vX.Y.Z}} ｜ tag: {{vX.Y.Z}} ｜ 대상 환경: {{스테이징 / 운영}} ｜ 계획 시간: {{YYYY-MM-DD HH:MM}}

## 사전 점검
- [ ] CI 전체 통과, 워크플로 실행 주소: {{URL}}
- [ ] 코드 리뷰 통과, 승인자: {{이름}}
- [ ] 품질 게이트 A/B/C 전체 PASS
- [ ] 변경 이력과 Release Notes 준비 완료
- [ ] 롤백 사전 계획 리뷰 완료, 이 절 말미 참조
- [ ] 데이터베이스 마이그레이션 스크립트 리뷰 완료 및 전방 호환
- [ ] 설정 변경 목록 확인 완료(리포지터리에 커밋되지 않는 주입 항목)

## 변경 내용
| 변경 항목 | 유형 | 영향 범위 | 관련 요구사항 | 검증 방식 |
| --- | --- | --- | --- | --- |
| {{기능 / 설정 / 데이터 마이그레이션}} | {{추가 / 수정 / 제거}} | {{영향받는 모듈}} | {{REQ-NNN}} | {{확인 방법}} |

## 실행 단계
1. {{단계, 구체적 명령 또는 플랫폼 조작 포함}}
2. {{카나리 비율과 관찰 시간}}
3. {{전체 확대 조건}}

## 상태 점검과 스모크
| 점검 항목 | 판정 조건 | 실행 방식 | 결과 |
| --- | --- | --- | --- |
| 서비스 생존 | {{HTTP 200}} | {{명령}} | {{통과 / 미통과}} |
| 핵심 경로 | {{주요 흐름 완료}} | {{명령}} | {{통과 / 미통과}} |
| 오류율 | {{< X%}} | {{모니터링 대시보드}} | {{통과 / 미통과}} |

## 배포 기록
| 항목 | 값 |
| --- | --- |
| 실제 배포 시간 | {{YYYY-MM-DD HH:MM}} |
| 작업자 | {{이름}} |
| 승인자 | {{이름}} |
| 실제 버전 번호 | {{vX.Y.Z}} |
| 결과 | {{성공 / 롤백 / 중단}} |

## 롤백 사전 계획
- 롤백 대상 버전: {{vX.Y.Z}}
- 트리거 조건: {{오류율 > X% N분 지속 / 스모크 실패 / 데이터 이상}}
- 결정권자: {{이름}}
- 롤백 단계: {{구체적 명령 또는 조작}}
- 데이터 호환성: {{데이터 롤백 필요 여부; 필요하면 방식 설명}}
```

## 3. 배포 기록 템플릿

```markdown
## {{YYYY-MM-DD}} {{vX.Y.Z}} → {{환경}}

- 버전 번호: {{vX.Y.Z}}
- tag: {{vX.Y.Z}}
- 시간: {{HH:MM}}
- 작업자 / 승인자: {{이름 / 이름}}
- 변경 요약: {{한 문장}}
- 상태 점검: {{통과 / 미통과}}
- 결과: {{성공 / 롤백}}
- 관련 릴리스: {{Release Notes URL}}
- 비고: {{이상과 처리 기록; 없으면 「없음」으로 기재}}
```

## 4. 필드 정의

| 필드 | 필수 | 유형 | 작성 요점 | 예시 |
| --- | --- | --- | --- | --- |
| tag | 예 | 텍스트 | [버전 관리 규범](./버전-관리-규범.md)의 tag와 완전히 일치 | `v1.2.0` |
| 대상 환경 | 예 | 열거형 | 스테이징 / 운영, 설정을 혼용해서는 안 됨 | `운영` |
| 변경 항목.유형 | 예 | 열거형 | 추가 / 수정 / 제거 | `수정` |
| 관련 요구사항 | 예 | 목록 | REQ 번호, 요구사항 없는 변경은 「없음」으로 기재 | `REQ-007` |
| 카나리 비율 | 아니오 | 백분율 | 단계적 확대 시 필수 | `10% → 50% → 100%` |
| 판정 조건 | 예 | 임계값 | 관측 가능하고 판정 가능해야 함 | `HTTP 200` |
| 실제 버전 번호 | 예 | 텍스트 | 계획 버전 번호와 다르면 이유를 설명해야 함 | `v1.2.1` |
| 롤백 트리거 조건 | 예 | 임계값 + 시간 | 「이상한 느낌」류 표현 금지 | `오류율 >1% 5분 지속` |
| 데이터 호환성 | 예 | 텍스트 | 데이터 롤백 필요 여부를 명확히 함 | `데이터 롤백 불필요` |

## 5. 작성 설명

1. **사전 점검**: 항목별로 체크하며, 전체를 한 번에 체크하는 것을 금지한다. 어느 항목이든 미완료면 배포를 중단한다.
2. **변경 내용**: 각 항목은 REQ 번호와 연결되어야 한다. 요구사항 연결이 없는 순수 운영 변경은 「없음」으로 기재하고 변경 근거를 설명한다.
3. **상태 점검**: 자동으로 판정 가능한 조건이어야 한다. 「서비스가 정상으로 보임」은 불합격이다.
4. **롤백 트리거 조건**: 임계값과 지속 시간을 동시에 제시하여 순간적 변동으로 인한 오작동을 피한다.
5. **카나리 확대**: 각 단계 확대 후 규정된 시간 동안 관찰하고 관찰 결론을 기록한 후 다음 단계로 진행한다.
6. **배포 기록**: 시간순으로 추가하며 이력을 덮어쓰지 않는다. 푸시, tag, Release Notes 세 곳의 버전 번호와 일치해야 한다.
7. **롤백 실행**: 코드 롤백은 `git revert`로 역방향 커밋을 생성하며, 이미 공개된 이력에 강제 푸시하지 않는다([푸시 및 릴리스 규범](./푸시-및-릴리스-규범.md) 참조).

흔한 오류:

| 잘못된 작성 | 문제 | 수정 방식 |
| --- | --- | --- |
| tag가 생성되지 않은 커밋으로 배포 | 버전 재현 불가 | tag를 먼저 생성한 후 배포 |
| 롤백 사전 계획에 「문제가 있으면 롤백」이라고만 기술 | 트리거 조건과 단계 없음 | 임계값, 결정권자, 단계 보충 |
| 데이터베이스 변경이 구버전과 호환되지 않음 | 롤백 후 데이터 사용 불가 | 확장-마이그레이션-축소 3단계 방식 적용 |
| 배포 기록을 사후에 보충 작성 | 상태를 신뢰할 수 없음 | 배포 당시 즉시 기록 |
| 상태 점검에서 첫 페이지만 테스트 | 핵심 경로 미검증 | 주요 흐름 스모크 케이스 보충 |

## 6. 완전한 예시

```markdown
# 배포 체크리스트: markdown-lint-cli v1.0.0

버전: v1.0.0 ｜ tag: v1.0.0 ｜ 대상 환경: 운영 ｜ 계획 시간: 2026-11-20 10:00

## 사전 점검
- [x] CI 전체 통과: https://github.com/example/markdown-lint-cli/actions/runs/123
- [x] 코드 리뷰 통과, 승인자: 이순신
- [x] 품질 게이트 A/B/C 전체 PASS
- [x] 변경 이력과 Release Notes 준비 완료
- [x] 롤백 사전 계획 리뷰 완료
- [x] 데이터베이스 마이그레이션 없음
- [x] 설정 변경 목록 확인 완료: 없음

## 변경 내용
| 변경 항목 | 유형 | 영향 범위 | 관련 요구사항 | 검증 방식 |
| --- | --- | --- | --- | --- |
| 중영문 공백 규칙 | 추가 | 규칙 엔진 | REQ-001 | TC-001 실행 |
| CLI 보고서 출력 | 수정 | 보고서 모듈 | REQ-007 | TC-012 실행 |

## 실행 단계
1. v1.0.0 tag를 가져오고 체크섬 검증
2. 카나리 10%, 10분 관찰
3. 오류율 <0.1% 후 100%로 확대

## 상태 점검과 스모크
| 점검 항목 | 판정 조건 | 실행 방식 | 결과 |
| --- | --- | --- | --- |
| 서비스 생존 | HTTP 200 | curl /healthz | 통과 |
| 핵심 경로 | 50개 문서 검사 완료 | shell 스크립트 | 통과 |
| 오류율 | <0.1% | 모니터링 대시보드 | 통과 |

## 롤백 사전 계획
- 롤백 대상 버전: v0.9.3
- 트리거 조건: 오류율 >1% 5분 지속
- 결정권자: 이순신
- 롤백 단계: 배포 레이블을 v0.9.3으로 전환하고 데이터 호환성 점검 실행
- 데이터 호환성: 데이터베이스 변경 없음, 데이터 롤백 불필요
```
