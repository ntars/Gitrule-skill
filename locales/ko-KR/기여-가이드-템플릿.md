# 기여 가이드 템플릿

> 이 파일이 해결하는 문제：프로젝트가 CONTRIBUTING.md를 생성할 수 있도록 그대로 복사할 수 있는 기여 가이드 템플릿을 제공하며, 참여 방식, 환경 구성, 브랜치 모델, 커밋 규범, PR 요건, 테스트 요건, 행동 강령과 라이선스 선언을 다룹니다. 함께 제공되는 작성 안내는 유형별 프로젝트의 조정 방식을 다룹니다.

## 1. 사용 안내

1. 3절 「템플릿 본문」의 전체 내용을 복사하여 프로젝트 루트 디렉터리에 `CONTRIBUTING.md`로 새로 만듭니다.
2. 4절에 따라 자리표시자를 교체하며, 모든 명령은 그대로 실행 가능한 실제 명령이어야 합니다.
3. 5절의 상황별 변형에 따라 조정합니다. 문서형 프로젝트는 테스트 명령 단락을 삭제하고 이슈 및 PR 프로세스를 유지합니다.
4. 규칙 근거는 [기여 가이드 규범](./기여-가이드-규범.md)을 참조하며, 브랜치와 커밋 세부 사항은 각각 [Git 워크플로 및 브랜치 규범](./Git-워크플로-및-브랜치-규범.md), [커밋 메시지 규범](./커밋-메시지-규범.md)을 참조합니다.

## 2. 맞춤 설정 원칙

- **실행 가능성**: 명령에 작업 디렉터리와 의존성 전제를 모두 적으며, 「의존성을 설치한다」만 쓰고 구체적 명령을 쓰지 않는 것은 금지합니다.
- **발동 조건 명시**: 각 단계마다 언제 실행하는지와 예상 결과를 명시합니다.
- **구체성**: 「PR 환영합니다」만 쓰고 실질적인 프로세스를 쓰지 않는 것은 금지하며, [품질 게이트](./품질-게이트.md)의 커뮤니티 거버넌스 검사에 해당합니다.
- **복사가 아닌 참조**: 커밋과 테스트 규칙은 해당 규범을 참조하고, 이 파일에서 전문을 반복하지 않는다.

## 3. 템플릿 본문

````markdown
# 기여 가이드

> 이 파일은 {{项目名称}}에 기여하는 방법을 설명하며, 외부 기여자와 최초 참여자에게 적용됩니다.

## 참여 방식

| 방식 | 적용 상황 | 진입점 |
| --- | --- | --- |
| 이슈 논의 | 기능 제안, 문제 피드백 | {{议题入口}} |
| 문서 개선 | 오타, 예시 보충, 구조 최적화 | PR 직접 제출 |
| 코드 기여 | 결함 수정, 기능 구현 | 아래 절차 참조 |
| 문제 피드백 | 사용 차단, 이상 현상 재현 | {{问题反馈入口}} |

## 개발 환경 구성

전제: {{环境前提}}

```bash
# 리포지터리 클론
git clone {{仓库地址}}
cd {{项目目录名}}

# 의존성 설치
{{依赖安装命令}}

# 로컬 실행
{{本地运行命令}}
```

예상 결과: {{验证本地环境可用的方式}}

## 브랜치 모델

- {{基准分支}}에서 개인 브랜치를 분기하며, 명명 형식은 `{{分支命名格式}}`입니다(예: `feat/짧은-설명`).
- PR 하나당 하나의 작업만 처리하며, 변경 범위가 너무 크면 분할해 주십시오.
- {{受保护分支}}에 직접 커밋하는 것은 금지되며, PR을 통해 병합해야 합니다.

## 커밋 규범

커밋 메시지는 Conventional Commits를 따르며, 형식은 `type(scope): subject`입니다. 자주 쓰는 유형: `feat`, `fix`, `docs`, `refactor`, `test`, `chore`. 예시:

```text
feat(cli): add config file support
```

전체 규칙은 [커밋 메시지 규범]({{提交规范链接}})을 참조하십시오.

## PR 요건

PR을 제출하기 전에 다음 자체 점검을 완료해 주십시오.

- [ ] 변경 범위가 단일하며, 대응하는 이슈나 설명이 있습니다.
- [ ] 커밋 메시지가 위 형식에 부합합니다.
- [ ] 로컬에서 `{{测试命令}}`을 실행하여 모두 통과했다.
- [ ] 문서를 코드와 함께 동기화하여 갱신했다.
- [ ] 키, 개인 키 또는 민감 정보를 포함하지 않았다.
- [ ] 설명에 변경 내용, 이유와 검증 방식을 명시했다.

## 테스트 요건

| 검사 항목 | 명령 | 통과 기준 |
| --- | --- | --- |
| 단위 테스트 | `{{单元测试命令}}` | 모두 통과 |
| 정적 분석 | `{{lint 命令}}` | 오류 없음 |
| 빌드 검증 | `{{构建命令}}` | 빌드 성공 |

커버리지 기준: {{覆盖率要求}}.

## 행동 강령

본 프로젝트에 참여하는 것은 [행동 강령](./CODE_OF_CONDUCT.md)을 준수하는 데 동의하는 것을 의미합니다.

## 이슈 규범

- 질문하기 전에 기존 이슈를 먼저 검색하여 중복을 피합니다.
- 결함 보고에는 환경 정보, 재현 단계, 예상 결과, 실제 결과, 오류 로그가 포함되어야 합니다.
- 기능 제안에는 사용 상황과 채택하지 않을 경우의 대안을 설명해야 합니다.

## 라이선스 선언

기여 내용은 기본적으로 본 프로젝트의 라이선스 {{许可证名称及 SPDX 标识符}}를 따르며, 전문은 [LICENSE](./LICENSE)를 참조하십시오. 제출하는 것은 해당 라이선스로 자신의 기여를 허여할 권한이 있음을 의미합니다.
````

## 4. 자리표시자 대조표와 필드 정의

| 자리표시자 | 필수 | 필드 정의 | 작성 예시 |
| --- | --- | --- | --- |
| `{{项目名称}}` | 예 | 프로젝트 대외 명칭 | `FooBar` |
| `{{议题入口}}` | 예 | 실제로 접근 가능한 이슈 주소 | `https://github.com/owner/repo/issues` |
| `{{问题反馈入口}}` | 아니오 | 이슈 진입점과 다를 때 쓰는 전용 채널 | `https://github.com/owner/repo/issues/new` |
| `{{环境前提}}` | 예 | 언어 버전, 패키지 관리자와 시스템 의존성 | `Node.js 20+, pnpm 8+` |
| `{{仓库地址}}` | 예 | 클론 가능한 리포지터리 주소 | `https://github.com/owner/repo.git` |
| `{{项目目录名}}` | 예 | 클론 후의 디렉터리 이름 | `repo` |
| `{{依赖安装命令}}` | 예 | 실제 설치 명령 | `pnpm install` |
| `{{本地运行命令}}` | 예 | 실제 시작 명령 | `pnpm dev` |
| `{{验证本地环境可用的方式}}` | 예 | 관찰 가능한 성공 신호 | `localhost:3000 접속 시 첫 화면 표시` |
| `{{基准分支}}` | 예 | 브랜치를 분기하는 원본 브랜치 | `main` |
| `{{分支命名格式}}` | 예 | 브랜치 명명 규칙 | `feat/짧은-설명` |
| `{{受保护分支}}` | 예 | 직접 커밋이 금지된 브랜치 | `main` |
| `{{提交规范链接}}` | 아니오 | 프로젝트 내부 또는 외부 커밋 규범 주소 | `./docs/COMMIT_CONVENTION.md` |
| `{{测试命令}}` | 예 | 실제 테스트 명령 | `pnpm test` |
| `{{lint 命令}}` | 예 | 실제 정적 분석 명령 | `pnpm lint` |
| `{{构建命令}}` | 예 | 실제 빌드 명령 | `pnpm build` |
| `{{覆盖率要求}}` | 아니오 | 신규 코드의 커버리지 기준 | `신규 코드 80% 이상` |
| `{{许可证名称及 SPDX 标识符}}` | 예 | 프로젝트 라이선스 전체 명칭과 SPDX 식별자 | `MIT 라이선스(MIT)` |

## 5. 작성 안내와 상황별 변형

| 상황 | 필수 유지 섹션 | 삭제 가능 섹션 | 조정 요점 |
| --- | --- | --- | --- |
| 코드 프로젝트 | 전체 | 없음 | 명령은 실제로 실행하여 검증을 통과해야 함 |
| 문서 프로젝트 | 참여 방식, PR 요건, 행동 강령, 라이선스 | 테스트 요건, 개발 환경 구성 | 테스트 표를 삭제하고 PR 자체 점검은 유지 |
| 개인 프로젝트 | 참여 방식, PR 요건, 행동 강령, 라이선스 | 환경 구성은 간소화 가능 | 외부 기여 수용 여부를 명확히 함 |
| 기업 프로젝트 | 전체 | 없음 | 기여자 라이선스 계약(CLA) 링크와 법무 요건 추가 |

흔한 오류 대조:

| 잘못된 작성 | 결과 | 올바른 작성 |
| --- | --- | --- |
| 「어떤 형태의 기여든 환영합니다」 | 구체적 경로가 없어 기여자가 시작할 수 없음 | 참여 방식 표와 진입점을 열거 |
| 「테스트를 실행하면 됩니다」 | 명령과 통과 기준을 알 수 없음 | 명령, 통과 기준과 커버리지 기준을 기재 |
| 프로젝트는 pnpm을 쓰는데 명령을 `npm install`로 기재 | 명령 실행 불가 | 실제 lockfile과 일치시킴 |

## 6. 완전한 예시

다음은 명령 단락을 채운 예시로, 형식 참고용으로만 사용합니다.

```bash
# 리포지터리 클론
git clone https://github.com/owner/repo.git
cd repo

# 의존성 설치
pnpm install

# 로컬 실행
pnpm dev
```

예상 결과: localhost:3000 접속 시 첫 화면이 표시됩니다.
