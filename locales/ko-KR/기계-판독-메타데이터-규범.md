# 기계 판독 메타데이터 규범

> 이 파일이 해결하는 문제：전문가, Skill, MCP, 명령줄 등이 프로그램적으로 소비하는 메타데이터 목록 구조를 정의하여, 기계가 안정적으로 가져오고 발견할 수 있도록 보장합니다.

## 1. 설계 목표

1. 안정적 식별자: 모든 문서는 프로그램이 인용할 수 있는 고유하고 변하지 않는 식별자를 가집니다.
2. 언어 독립: 식별자는 언어에 따라 변하지 않으며, 언어는 경로에만 반영됩니다.
3. 발견 가능: 목록은 모든 문서의 유형, 경로, 언어, 요약을 나열합니다.

## 2. 목록 구조

기계 목록(manifest)에는 다음이 포함되어야 한다:

| 필드 | 요구사항 |
| --- | --- |
| id | 안정적 고유 식별자, 소문자 kebab-case, 언어와 버전 미포함 |
| title | 문서 제목 |
| summary | 어떤 문제를 해결하는지 한 문장 설명 |
| domain | 소속 영역(7대 영역 중 하나) |
| paths | 언어 코드에서 상대 경로로의 매핑, 예: `zh-CN`: `./locales/zh-CN/角色与职责.md` |
| version | 규범 집합 버전 |

## 3. 강제 규칙

1. 새 언어 추가 시에는 `paths`에 매핑만 추가하고, `id`와 다른 언어 경로는 변경하지 않는다.
2. 문서 이름을 변경할 때는 `id`를 그대로 유지하고 `paths`만 갱신합니다.
3. 식별자와 경로는 실제 파일과 일치해야 하며, CI가 목록의 유효성을 검증합니다.
4. 본 규범은 복사 가능한 목록 예시를 제공합니다. 대상 프로젝트는 제2절의 필드에 따라 실제 목록 인스턴스를 작성하고, `paths`가 디스크 파일과 일치하도록 보장해야 합니다.

## 4. 목록 예시(복사 가능)

다음 예시는 세 개의 문서 항목을 나열합니다. 실제 목록은 대상 언어 디렉터리의 모든 규범을 포함해야 하며, `id`는 언어에 따라 변하지 않고 `paths`는 언어 코드별로 매핑을 추가합니다.

```json
{
  "version": "1.0.0",
  "entries": [
    {
      "id": "role-and-responsibility",
      "title": "角色与职责",
      "summary": "定义执行者身份、职责边界、触发条件、适用范围与硬性约束",
      "domain": "总纲与治理",
      "paths": {
        "zh-CN": "./locales/zh-CN/角色与职责.md"
      },
      "version": "1.0.0"
    },
    {
      "id": "readme-standard-template",
      "title": "README标准模板",
      "summary": "提供可直接套用的通用 README 模板与占位符对照表",
      "domain": "命名与文档",
      "paths": {
        "zh-CN": "./locales/zh-CN/README标准模板.md"
      },
      "version": "1.0.0"
    },
    {
      "id": "machine-readable-metadata",
      "title": "机器可读元数据规范",
      "summary": "定义供专家、Skill、MCP、命令行消费的元数据清单结构",
      "domain": "AI 与机器适配",
      "paths": {
        "zh-CN": "./locales/zh-CN/机器可读元数据规范.md"
      },
      "version": "1.0.0"
    }
  ]
}
```

새 언어를 추가할 때는 해당 항목의 `paths`에 매핑만 추가합니다. 예를 들어 `"en-US": "./locales/en-US/role-and-responsibility.md"`를 추가하며, `id`는 수정해서는 안 됩니다.
