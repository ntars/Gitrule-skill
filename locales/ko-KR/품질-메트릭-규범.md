# 품질 메트릭 규범

> 이 파일이 해결하는 문제：추적 가능한 품질 지표와 그 산정 기준을 정의하여 근거 없는 숫자로 프로젝트 품질을 평가하는 것을 방지합니다.

## 1. 지표 원칙

1. 지표는 측정 가능하고 재현 가능해야 하며, 수집 방식과 통계 기준을 명시합니다.
2. 지표는 개선을 위해 사용하며, 단순한 순위 매기기나 압박을 조성하는 데 사용하지 않습니다.
3. 각 지표에는 목표값과 현재값을 표기하고 정기적으로 회고합니다.

## 2. 권장 지표

| 범주 | 지표 | 산정 기준 설명 |
| --- | --- | --- |
| 테스트 | 테스트 커버리지 | 테스트된 코드 행의 비율, 통계 도구 명시 |
| 테스트 | 테스트 통과율 | 통과 케이스 수 / 전체 케이스 수 |
| 빌드 | 빌드 성공률 | 성공 빌드 횟수 / 전체 빌드 횟수 |
| 결함 | 결함 밀도 | 단위 규모 코드에서 발견된 결함 수 |
| 결함 | 평균 수정 소요 시간 | 발견부터 수정 완료까지의 평균 소요 시간 |
| 성능 | 응답 시간 | 시나리오와 분위값 명시(예: P95) |
| 의존성 | 고위험 취약점 수 | 미수정 고위험 의존성 취약점 수 |

## 3. 강제 규칙

1. 성능 지표는 테스트 환경과 방법을 명시해야 하며, 조건 없는 숫자는 금지합니다( [범용 작성 규범](./범용-작성-규범.md) 참조).
2. 지표 데이터 수집은 자동화해야 하며, 수동 통계 편향을 줄입니다.
3. 지표 이상에는 후속 조치 기록이 있어야 하며, [로드맵 규범](./로드맵-규범.md) 또는 이슈 트래킹에 포함합니다.
