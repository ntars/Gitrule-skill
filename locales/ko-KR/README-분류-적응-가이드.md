# README 분류 적응 가이드

> 이 파일이 해결하는 문제：라이브러리, 애플리케이션, 명령줄 도구, 프레임워크, 리소스 모음 등 서로 다른 프로젝트 유형에 대해 README 섹션 취사선택, 시각적 중점, 배지 구성의 차별화된 제안을 제시하고, 각 유형의 요소가 미관과 매력도를 어떻게 높이는지 설명합니다.

범용 템플릿은 모든 프로젝트에 적용되지만, 유형이 다른 프로젝트는 독자의 관심 지점이 다릅니다. 이 문서는 범용 규범 위에서 유형별 조정 제안을 제시합니다. 독자는 [README 표준 템플릿](./README-표준-템플릿.md)을 기반으로 하고, 이 문서의 해당 유형에 따라 취사선택해야 합니다.

## 1. 유형 개요

| 유형 | 독자의 첫 번째 질문 | 첫 화면 중점 | 필수 섹션 | 생략 가능 섹션 |
| --- | --- | --- | --- | --- |
| 라이브러리 / SDK | 설치 방식과 API 사용법 | 버전과 라이선스 | 설치, 빠른 시작, API, 호환성 | 배포, 스크린샷 |
| 애플리케이션 | 애플리케이션의 외관과 핵심 기능 | 스크린샷과 기능 | 기능, 스크린샷, 설치, 빠른 시작 | API 참조 |
| 명령줄 도구 | 명령 사용법과 성능 | 명령 예시와 데모 | 설치, 사용법, 명령 대조, 데모 | 아키텍처, 설정(적을 때) |
| 프레임워크 | 생태계와 학습 비용 | 문서 진입점과 예시 | 포지셔닝, 빠른 시작, 문서, 커뮤니티 | 성능 세부 사항(외부 링크 가능) |
| 리소스 모음 | 무엇을 수록했고 어떻게 검색하는지 | 목록 분류와 내비게이션 | 목록, 분류, 기여 가이드 | 설치, API |

## 2. 라이브러리 / SDK

대표 사례：axios 등 HTTP 클라이언트, 유틸리티 함수 라이브러리, 클라이언트 SDK.

### 2.1 섹션 취사선택

- 「한 문장 포지셔닝 + 버전 + 라이선스」를 앞에 두어 독자가 이를 근거로 호환성을 판단하게 합니다.
- 「설치」를 가장 앞에 두고, 패키지 관리자 명령(npm, pip, cargo 등)을 제시합니다.
- 「빠른 시작」은 반드시 독립적으로 실행 가능한 완전한 예제여야 합니다.
- 「API 참조」는 메인 README에 상세히 나열하거나 `docs/api.md`로 링크합니다. API 항목이 너무 많으면 README에는 요약 + 링크만 둡니다.
- 「호환성」은 지원하는 언어 버전, 런타임, 플랫폼을 설명합니다.

### 2.2 시각적 중점

- 배지 중점：버전, 빌드 상태, 라이선스, 다운로드 수, 패키지 크기.
- 이미지 사용은 절제하며, 일반적으로 스크린샷이 필요 없습니다. 작은 로고로 인식을 형성할 수 있습니다.
- API 매개변수는 표로 제시하여 가독성을 높입니다.

### 2.3 미관 향상 요점

1. 버전과 라이선스 배지를 맨 위에 두어 즉시 신뢰도를 형성합니다.
2. 빠른 시작 코드 블록을 첫 화면 근처에 두어 시도 장벽을 낮춥니다.
3. API 표의 열 너비와 기본값 열을 통일하여 인지 부담을 줄입니다.

## 3. 애플리케이션

대표 사례：에디터, 데스크톱 도구, 최종 사용자 대상 제품.

### 3.1 섹션 취사선택

- 첫 화면에 반드시 제품 스크린샷 또는 실행 화면을 포함하여, 가치를 먼저 보여주고 구현을 나중에 설명합니다.
- 「핵심 기능」은 기술 모듈이 아니라 사용자 시나리오로 구성합니다.
- 「설치」는 각 플랫폼의 설치 패키지 또는 다운로드 진입점을 포괄합니다.
- 「빠른 시작」은 가장 짧은 입문 경로를 제시합니다.
- 소스 코드 빌드 설명은 `CONTRIBUTING.md`로 외부 링크할 수 있습니다.

### 3.2 시각적 중점

- 배지 중점：버전, 빌드 상태, 라이선스, 다운로드 수.
- 스크린샷은 포지셔닝 뒤에 두며, 첫 화면의 핵심 요소입니다.
- 기능 목록에 아이콘 또는 짧은 스크린샷을 결합하여 훑어보기 효율을 높입니다.

### 3.3 미관 향상 요점

1. 고품질 제품 스크린샷을 가운데 정렬로 표시하고, 밝은/어두운 테마에 적응시킵니다.
2. 기능 항목은 짧은 문장 + 아이콘을 사용하고, 긴 설명을 피합니다.
3. 다운로드 진입점을 눈에 띄게 하고, 버튼형 링크를 사용합니다.

## 4. 명령줄 도구

대표 사례：fd, ripgrep 등 터미널 도구.

### 4.1 섹션 취사선택

- 「한 문장 포지셔닝」 뒤에 바로 섹션 내비게이션을 두어 이동을 쉽게 합니다.
- 「설치」는 주요 패키지 관리자와 플랫폼 바이너리를 나열합니다.
- 「사용법」은 작업 지향으로, 자주 쓰는 명령 예시를 제시합니다.
- 「명령 대조」 또는 「유사 도구와 비교」는 빈도 높은 요구입니다.
- 「데모」는 GIF 또는 터미널 녹화로 실제 효과를 보여줍니다.
- 성능 데이터는 테스트 환경과 방법을 명시해야 합니다.

### 4.2 시각적 중점

- 배지 중점：버전, 빌드 상태, 플랫폼 지원, 라이선스.
- 데모 움직이는 이미지는 핵심 시각 자산이며, 속도와 사용 경험을 보여줍니다.
- 명령은 언어가 표기된 코드 블록을 사용하고, 출력은 `text` 블록을 사용합니다.

### 4.3 미관 향상 요점

1. 명령 예시를 맨 위에 두어 독자가 스크롤 없이 복사해 사용할 수 있게 합니다.
2. 데모 움직이는 이미지로 실제 터미널 효과를 보여주어 「빠름」 인상을 강화합니다.
3. 다국어 링크(예: 중국어, 한국어 번역본)를 배지 행 근처에 둡니다.

## 5. 프레임워크

대표 사례：next.js 등 풀스택 프레임워크.

### 5.1 섹션 취사선택

- 첫 화면에서 포지셔닝, 생태계 규모, 학습 진입점을 강조합니다.
- 「문서」 진입점은 반드시 눈에 띄어야 하며, 보통 독립 문서 사이트를 가리킵니다.
- 「커뮤니티」는 토론 구역, 메신저 채널, 행동 강령을 설명합니다.
- 「빠른 시작」은 최소 프로젝트 생성 명령을 제시합니다.
- 심화 내용(아키텍처, API)은 외부 링크하고 README에서 펼치지 않습니다.

### 5.2 시각적 중점

- 배지 중점：버전, 빌드 상태, 라이선스, 커뮤니티 채널.
- 브랜드 로고와 `for-the-badge` 스타일 배지를 조합하여 첫 화면을 강화합니다.
- Showcase 스크린샷으로 생태계 사례를 보여줄 수 있습니다.

### 5.3 미관 향상 요점

1. 가운데 정렬 로고 + 대형 통일 스타일 배지로 브랜드화된 첫 화면을 형성합니다.
2. 문서와 커뮤니티 진입점을 눈에 띄는 내비게이션 블록으로 제시합니다.
3. Good First Issues 등 초보자 진입점으로 기여 장벽을 낮춥니다.

## 6. 리소스 모음

대표 사례：awesome 시리즈 목록.

### 6.1 섹션 취사선택

- 첫 화면을 로고와 후원 정보로 시작하는 것은 흔한 관행입니다.
- 본문은 주제별로 목록을 분류하여 명확한 내비게이션을 제공합니다.
- 「기여 가이드」는 수록 기준과 제출 형식을 설명합니다.
- 설치, API, 배포 등의 섹션은 필요 없습니다.

### 6.2 시각적 중점

- 배지 수량은 완화할 수 있으나, 스타일은 통일해야 합니다.
- 목록 분류는 2급 제목 + 리스트를 사용하고, 항목에 짧은 설명을 붙입니다.
- 후원사 로고는 표 또는 그리드로 배열하여 정렬을 유지합니다.

### 6.3 미관 향상 요점

1. 목록 구조가 명확하고, 분류 제목 계층이 일관됩니다.
2. 각 항목에 한 문장 설명을 붙여 링크만 있는 것을 피합니다.
3. 후원과 감사 영역을 정돈하여 정렬하고, 본문 읽기에 영향을 주지 않습니다.

## 7. 유형 공통 원칙

1. **독자 우선**：첫 화면에서 독자가 가장 관심 있는 질문에 답하며, 유형 차이는 순서에만 영향을 주고 정보 완전성에는 영향을 주지 않습니다.
2. **스타일 통일**：같은 프로젝트의 배지, 제목, 코드 블록 스타일은 반드시 일관되어야 합니다.
3. **복사 가능한 예시**：어떤 유형이든 직접 실행 가능한 예시를 최소 하나 제공합니다.
4. **링크 외부화**：첫 화면의 책임을 넘는 심화 내용은 독립 문서로 외부 링크합니다.
5. **지속 동기화**：스크린샷, 버전 배지, 기능 목록은 버전에 맞춰 업데이트해야 하며, 오래된 정보가 신뢰도를 훼손하는 것을 피합니다.
