# 배지 규범

> 이 파일이 해결하는 문제：README에서 배지(Badge)의 URL 문법, 스타일 매개변수, 색상 인코딩, 정보 취사선택, 배열 순서와 수량 제어를 정의하고, Shields.io를 주요 구현으로 삼아 그대로 복사할 수 있는 형식 예시와 권장 매개변수 구성을 제시합니다.

이 문서의 매개변수는 모두 Shields.io 공식 문서(Static Badge 및 Logos 페이지, badge-maker 형식 설명)로 검증했습니다. 출현율 데이터는 본 프로젝트가 헤드 오픈소스 프로젝트 README를 표본 통계한 결과에서 나왔으며, 「실측」으로 표기합니다.

## 1. 기본 문법

### 1.1 정적 배지 URL 구조

정적 배지는 URL 경로로 매개변수를 전달하며, 표준 구조는 다음과 같습니다：

```text
https://img.shields.io/badge/<레이블>-<메시지>-<색상>?style=<스타일>&<기타 쿼리 매개변수>
```

세 구간 경로는 하이픈 `-`으로 구분합니다：

| 구간 | 이름 | 필수 여부 | 설명 |
| --- | --- | --- | --- |
| 제1구간 | 레이블(label) | 아니오 | 왼쪽 텍스트, 지표 이름 설명 |
| 제2구간 | 메시지(message) | 예 | 오른쪽 텍스트, 지표 값 표시 |
| 제3구간 | 색상(color) | 예 | 오른쪽 배경색 |

두 구간 표기(레이블 생략, 메시지와 색상만)도 유효합니다：

```text
https://img.shields.io/badge/<메시지>-<색상>
```

### 1.2 문자 이스케이프 규칙

URL 경로의 공백과 특수 문자는 이스케이프해야 하며, 규칙은 다음과 같습니다：

| 입력 문자 | URL 표기 | 예시 |
| --- | --- | --- |
| 공백 | `_` 또는 `%20` | `v0.1 prototype` → `v0.1%20prototype` |
| 밑줄 `_` | `__`(이중 밑줄) | `my_label` → `my__label` |
| 하이픈 `-` | `--`(이중 하이픈) | `dev-build` → `dev--build` |

사용자가 제공한 프로토타입 예시는 이 문법에 부합하므로 바로 사용할 수 있습니다：

```markdown
![Status](https://img.shields.io/badge/status-v0.1%20prototype-8957e5?style=flat-square)
```

그 의미는 다음과 같습니다：레이블 `status`, 메시지 `v0.1 prototype`(공백은 `%20`), 색상 `8957e5`(16진수 보라), 스타일 `flat-square`.

### 1.3 Markdown 삽입 형식

```markdown
![버전](https://img.shields.io/badge/version-1.2.0-blue?style=flat-square)
```

클릭 시 이동이 필요하면 링크로 이미지를 감쌉니다：

```markdown
[![라이선스](https://img.shields.io/badge/license-MIT-blue.svg)](./LICENSE)
```

## 2. 스타일 매개변수(style)

`style`은 배지의 전체 시각 디자인을 결정하며, 다섯 가지 값을 가질 수 있고 기본값은 `flat`입니다.

| 값 | 시각적 특징 | 적용 시나리오 | 실측 출현 횟수(N=120) |
| --- | --- | --- | --- |
| `flat` | 직각, 플랫, Shields.io 기본 | 범용 선호, 대부분 테마와 호환 | 32 |
| `flat-square` | 직각, 둥근 모서리 없음, 약간 조밀 | 정돈되고 강인한 첫 화면을 추구할 때 | 60 |
| `for-the-badge` | 대형 볼드, 높은 대비 | 상단 주 비주얼, 강조 배지 | 65 |
| `social` | 둥근 모서리, 좌우 분색, 플랫 | 소셜 스타일 첫 화면 | 12 |
| `plastic` | 하이라이트 그라데이션, 스큐어모픽 | 레트로 스타일, 현재는 거의 사용되지 않음 | 1 |

**권장 구성**：

- 같은 README 내의 모든 배지는 반드시 `style`을 통일해야 하며, 혼용은 금지합니다. 이것이 시각적 일관성의 최우선 요구입니다.
- 범용 프로젝트는 `flat` 또는 `flat-square`를 우선하고, 브랜드 첫 화면을 강화할 때는 `for-the-badge`를 통일 사용합니다.
- 실측에서 `for-the-badge`(65회)와 `flat-square`(60회)가 가장 인기 있으며, 둘 다 기본 선택으로 삼을 수 있습니다.

형식 예시：

```markdown
![build](https://img.shields.io/badge/build-passing-brightgreen?style=for-the-badge)
![build](https://img.shields.io/badge/build-passing-brightgreen?style=flat-square)
```

## 3. 색상 매개변수(color / labelColor)

### 3.1 세 가지 색상 표현법

badge-maker 설명에 따르면, `color`(오른쪽)와 `labelColor`(왼쪽 배경) 모두 다음 세 가지 표기를 지원합니다：

**방법 1：Shields.io 명명 색상**

| 의미 | 명명 색상 |
| --- | --- |
| 성공 | `brightgreen`, `green`, `success` |
| 알림 | `yellow`, `yellowgreen`, `orange`, `important` |
| 경고 | `red`, `critical` |
| 정보 | `blue`, `informational` |
| 중립 | `grey` / `gray`, `lightgrey` / `lightgray`, `inactive` |

주의：`labelColor` 기본값은 `grey`, `color` 기본값은 `lightgrey`(문서에 `inactive`도 기본 색상 중 하나로 별도 기재됨)입니다. 일부 명명 색상 값은 CSS 동명 색상과 약간 다르므로 Shields.io 렌더링 결과를 기준으로 합니다.

**방법 2：16진수 색상**

3자리 또는 6자리 16진수를 지원하며, `#` 접두사를 생략하거나 유지할 수 있습니다：

```text
?color=8957e5
?color=007fff
?color=%23007fff    ← # 유지 시 %23으로 인코딩 필요
```

**방법 3：CSS 색상 값**

`rgb(...)`, `rgba(...)`, `hsl(...)`, `hsla(...)` 및 CSS 명명 색상(예: `aqua`, `fuchsia`, `lightslategray`)을 지원하며, 사용 시 URL 인코딩을 해야 합니다.

### 3.2 색상 의미 매핑(권장 구성)

| 정보 유형 | 권장 색상 | 예시 메시지 |
| --- | --- | --- |
| 빌드 통과, 테스트 통과 | `brightgreen` / `success` | `passing` |
| 빌드 실패 | `red` / `critical` | `failing` |
| 안정 버전 | `blue` | `v1.2.0` |
| 사전 릴리스, 프로토타입 | 사용자 정의 보라 `8957e5` / `orange` | `v0.1 prototype` |
| 라이선스 | `blue` / `green` | `MIT` |
| 문서 상태 | `yellowgreen` | `docs` |
| 폐기, 유지보수 중단 | `red` / `inactive` | `deprecated` |

**권장 구성**：브랜드 색상과 상태 색상은 프로젝트 내에서 각각 한 세트로 고정하며, 임의로 교체해서는 안 됩니다. 같은 의미는 전체 리포지터리에서 같은 색상 인코딩을 사용합니다.

형식 예시：

```markdown
![커버리지](https://img.shields.io/badge/coverage-95%25-orange?style=flat-square)
![상태](https://img.shields.io/badge/status-v0.1%20prototype-8957e5?style=flat-square)
![라이선스](https://img.shields.io/badge/license-MIT-blue?style=flat-square)
```

## 4. 아이콘 매개변수(logo / logoColor / logoSize)

### 4.1 Simple Icons 사용

`logo` 매개변수는 Simple Icons의 아이콘 slug를 가지며, 형식은 `?logo=<slug>`입니다. 자주 쓰는 slug는 다음과 같습니다：

| 용도 | slug | 실측 출현 횟수(N=120) |
| --- | --- | --- |
| GitHub 리포지터리 | `github` | 35 |
| Discord 커뮤니티 | `discord` | 20 |
| npm 패키지 | `npm` | 4 |
| Apple 플랫폼 | `apple` | 3 |
| Docker | `docker` | 3 |
| 소셜 플랫폼 X | `x` | 3 |
| Python 패키지 | `pypi` | 2 |

전체 slug는 Simple Icons 사이트 또는 simple-icons 리포지터리의 `slugs.md`를 기준으로 합니다.

### 4.2 아이콘 배색과 크기

- `logoColor`：Simple Icons 아이콘 색상을 설정하며, 16진수, rgb, hsl, CSS 명명 색상을 지원합니다. Simple Icons 아이콘에만 적용되며, 사용자 정의 아이콘에는 효력이 없습니다.
- `logoSize`：`auto`로 설정하면 아이콘이 내용에 따라 자동으로 크기가 조정되어, 비교적 넓은 아이콘에 적합합니다. 마찬가지로 Simple Icons에만 적용됩니다.

형식 예시：

```markdown
![repo](https://img.shields.io/badge/github-repo-blue?logo=github)
![logo 배색](https://img.shields.io/badge/logo-javascript-blue?logo=javascript&logoColor=f5f5f5)
```

사용자 정의 아이콘은 `logo=data:image/svg+xml;base64,...`로 전달할 수 있으나, URL이 매우 길어 유지보수에 불리하므로 특별한 필요가 없으면 권장하지 않습니다.

## 5. 기타 쿼리 매개변수

| 매개변수 | 역할 | 예시 |
| --- | --- | --- |
| `label` | 기본 왼쪽 텍스트 덮어쓰기(공백은 인코딩 필요) | `?label=healthiness` |
| `labelColor` | 왼쪽 배경색 | `?labelColor=abcdef` |
| `color` | 오른쪽 배경색 | `?color=fedcba` |
| `cacheSeconds` | HTTP 캐시 시간(초), 기본값보다 낮으면 무시됨 | `?cacheSeconds=3600` |
| `link` | 클릭 시 좌우 반쪽 영역의 이동 주소 지정 | `<object>` 태그 내에서만 유효, Markdown 이미지에는 무효 |

## 6. 동적 배지

동적 배지는 Shields.io가 외부 서비스에서 실시간으로 데이터를 가져오므로, 값을 수동으로 업데이트할 필요가 없습니다. 자주 쓰는 유형：

| 분류 | URL 패턴 | 용도 |
| --- | --- | --- |
| 빌드 상태 | `https://img.shields.io/github/actions/workflow/status/<owner>/<repo>/<workflow>` | CI 상태 |
| 버전 | `https://img.shields.io/npm/v/<package>` | npm 최신 버전 |
| 라이선스 | `https://img.shields.io/npm/l/<package>` | 패키지 라이선스 |
| Star 수 | `https://img.shields.io/github/stars/<owner>/<repo>` | 인기도 |
| Issue 수 | `https://img.shields.io/github/issues/<owner>/<repo>` | 처리 대기 문제 |
| 다운로드 수 | `https://img.shields.io/npm/dt/<package>` | 누적 다운로드 |

동적 배지에는 `?style=`, `?logo=` 등 매개변수를 추가할 수 있으며, 규칙은 정적 배지와 같습니다. 벤치마크 프로젝트는 보편적으로 「동적 배지로 실제 지표 표시 + 정적 배지로 사용자 정의 상태 보충」의 조합을 채택합니다.

## 7. 정보 취사선택과 배열 순서

### 7.1 정보 취사선택

배지는 「검증 가능하고 독자에게 유용한」 상태 정보를 전달해야 합니다. 다음 분류만 유지할 것을 권장합니다：

1. 빌드 / 테스트 상태；
2. 버전 또는 최신 릴리스；
3. 라이선스；
4. 문서 상태；
5. 커뮤니티 채널(Discord, 토론 구역)；
6. 프로젝트 사용자 정의 상태(프로토타입, 유지보수 중, 폐기됨).

넣어서는 안 되는 것：출처 없는 다운로드 수, 프로젝트와 무관한 마케팅 라벨, 검증 불가능한 평점, 순수 장식성 색상 블록.

### 7.2 배열 순서

「상태 → 버전 → 라이선스 → 플랫폼/커뮤니티 → 사용자 정의 상태」 순으로 배열하고, 중요도는 왼쪽에서 오른쪽으로 감소할 것을 권장합니다. 이유：빌드 상태는 독자의 채택 여부를 결정하고, 버전은 호환성 판단을 결정하며, 라이선스는 사용 가능 여부를 결정하므로, 둘 모두 의사결정의 전제 정보에 속합니다.

### 7.3 수량 제어

- 일반 프로젝트：4–6개.
- 리소스 모음 또는 생태계 프로젝트：8–10개까지 완화 가능.
- 모든 배지는 프로젝트 이름과 한 문장 포지셔닝 뒤, 본문 앞에 두며, 한 줄을 차지하거나 가운데 정렬 컨테이너에 두고, 본문 중간에 흩어 놓지 않습니다.

### 7.4 정적 전달 상태 배지

제7.1조 제6항 「프로젝트 사용자 정의 상태」의 표준 구현은 정적 전달 상태 배지이며, 프로젝트 작성자가 값을 수동으로 업데이트하며, 외부 데이터 소스가 없는 전달 진행률과 유지보수 상태에 적용됩니다：

```text
![Status](https://img.shields.io/badge/status-4%20of%204%20delivered-brightgreen?style=flat-square)
```

1. 표준 구조는 `badge/<레이블>-<메시지>-<색상>`이며, 스타일은 `?style=flat-square`를 통일 사용합니다. 예시의 의미는 「4개 전달물 모두 전달됨」입니다.
2. 메시지 텍스트의 공백은 `%20`, 짧은 줄표는 `--`, 밑줄은 `__`로 씁니다. 줄바꿈과 기타 이스케이프되지 않은 특수 문자가 있어서는 안 됩니다.
3. 색상 의미 약속：`brightgreen`은 완료, `yellow`는 진행 중, `red`는 차단됨, `lightgrey`는 시작 전을 나타냅니다.
4. 값이 변하면 배지와 본문을 동기 업데이트해야 하며, 배지가 실제 상태보다 오래 뒤처져서는 안 됩니다. 동기화를 보장할 수 없으면 동적 배지로 전환합니다.
5. `alt` 텍스트에 실제 의미를 명시합니다(예: `![전달 상태]`). 전달물 목록이나 해당 색인 섹션으로 링크할 수 있습니다.

## 8. 접근성과 테마 적응

- 각 배지의 `alt` 텍스트는 실제 의미를 명시해야 하며, 예를 들어 `![badge]`가 아니라 `![빌드 상태]`로 씁니다.
- 어두운 / 밝은 테마에서 `<picture>`로 배지 이미지 소스를 전환할 수 있으며, `for-the-badge`에 `labelColor=000`을 조합하면 두 테마 모두에서 안정적인 대비를 유지할 수 있습니다.
- 배지는 클릭하여 해당 데이터 소스로 이동할 수 있어야 합니다(빌드 상태는 CI, 버전은 패키지 관리 페이지, 라이선스는 LICENSE 파일로 이동).
