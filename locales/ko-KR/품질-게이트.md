# 품질 게이트

> 이 파일이 해결하는 문제：3계층 게이트의 통과 조건, 판정 체크리스트 템플릿과 필드를 정의하여 푸시 통과 판정이 일관되고 실행 가능하며 재검증 가능하도록 보장합니다.

## 1. 3계층 게이트

| 계층 | 의미 | 통과 조건 |
| --- | --- | --- |
| Gate A · 보안 게이트 | 시크릿, 개인정보, 라이선스, 대용량 파일 | P0 제로 |
| Gate B · 품질 게이트 | 빌드, 테스트, lint, 커밋 규범, 브랜치 보호 | P0 제로, P1 은 할 일로 기록 |
| Gate C · 홈페이지 게이트 | README, 메타데이터, 문서 매트릭스, 배지, 링크 | P0 제로, P1 ≤ 3 이며 일정이 잡혀 있음 |

A, B, C 가 모두 통과해야만 `✅ ALLOW PUSH` 를 출력합니다. 미통과 항목은 수정하거나 사유를 표기해야 하며, 결과는 [감사 보고서 형식](./감사-보고서-형식.md)에 기록합니다.

## 2. 인도 전 14개 항목 판정

문서 인도 전에 항목별로 판정하며, 미통과 항목은 수정하거나 사유를 표기해야 합니다.

| 번호 | 점검 항목 | 판정 기준 |
| --- | --- | --- |
| G1 | 구어체와 모호성 | 전문에서 구어 단어와 모호한 지시어를 검색하여 적중 수가 0 |
| G2 | 섹션 완전성 | 중국어·영어 버전 모두 20장이며 순서가 일치 |
| G3 | 기능과 디렉터리 일치성 | README 에 기술된 기능 모두 디렉터리 구조에서 대응 모듈을 찾을 수 있음 |
| G4 | 기능 근거 | 각 기능에 근거가 있거나 미정으로 표기됨 |
| G5 | 설계 세부 사항 포괄 | 8장의 10개 범주 모두 항목이 있거나 해당 없음으로 명시 |
| G6 | 의존성 완전성 | 직간접 의존성 수가 의존성 트리와 일치 |
| G7 | 라이선스 정확성 | 각 의존성의 SPDX 식별자가 공식 선언과 일치 |
| G8 | 라이선스 원문 | 전문 첨부가 요구되는 라이선스에 모두 영어 원문이 첨부됨 |
| G9 | 저작권 표시 | 프로젝트 자체와 타인의 저작권 표시가 모두 완전 |
| G10 | 이중 언어 동기화 | 섹션, 표, 용어, 코드 블록이 양측에서 일치 |
| G11 | 명령 실행 가능성 | 설치, 빠른 시작, 푸시 명령을 모두 그대로 실행 가능 |
| G12 | 확인 대기 항목 집계 | 모든 확인 대기 항목이 집계되었고 위치를 특정 가능 |
| G13 | 자료 출처 | 모든 자료에 출처와 라이선스 기록이 있음 |
| G14 | 민감 정보 | 시크릿, 토큰, 내부망 주소, 개인정보가 없음 |

## 3. 게이트 판정 체크리스트 템플릿

```markdown

판정일：{{YYYY-MM-DD}} ｜ 판정자：{{姓名}} ｜ 리포지터리：{{owner/repo}}

## Gate A · 보안 게이트
| 번호 | 점검 항목 | 결론 | 근거 | 등급 | 조치 |
| --- | --- | --- | --- | --- | --- |
| A1 | 작업 공간 시크릿 | PASS / FAIL / SKIP | {{命令输出}} | {{P0}} | {{动作}} |
| A2 | 이력 시크릿 | PASS / FAIL / SKIP | {{命令输出}} | {{P0}} | {{动作}} |
| A3 | 민감 정보 정리 | PASS / FAIL / SKIP | {{证据}} | {{P0}} | {{动作}} |

## Gate C · 홈페이지 게이트
| 번호 | 점검 항목 | 결론 | 근거 | 등급 | 조치 |
| --- | --- | --- | --- | --- | --- |
| C1 | README 4요소 | PASS / FAIL / SKIP | {{路径:行号}} | {{P1}} | {{动作}} |
| C2 | 문서 매트릭스 완비 | PASS / FAIL / SKIP | {{清单}} | {{P1}} | {{动作}} |

## 인도 전 14개 항목 판정
| 번호 | 결론 | 근거 | 조치 |
| --- | --- | --- | --- |
| G1 ~ G14 | {{PASS / FAIL / SKIP}} | {{证据}} | {{动作}} |

- A：{{PASS / FAIL}} ｜ B：{{PASS / FAIL}} ｜ C：{{PASS / FAIL}}
- 통과 결론：{{✅ ALLOW PUSH / ⛔ BLOCK PUSH}}
```

## 4. 필드 정의

| 필드 | 필수 | 유형 | 작성 요점 | 예시 |
| --- | --- | --- | --- | --- |
| 판정자 | 예 | 텍스트 | 유일해야 하며 「팀」은 금지 | `王五` |
| 결론 | 예 | 열거 | PASS / FAIL / SKIP | `PASS` |
| 근거 | 예 | 텍스트 | 경로 + 행 번호 또는 명령 출력, 근거 없는 판정 금지 | `gitleaks: 0 findings` |
| 등급 | 조건부 필수 | 열거 | FAIL 시 P0 / P1 / P2 필수 | `P0` |
| 조치 | 조건부 필수 | 텍스트 | FAIL 시 구체적 조치와 책임자 필수 | `키를 교체하고 이력을 정리` |
| SKIP 사유 | 조건부 필수 | 텍스트 | SKIP 시 필수, 사유 없는 생략 금지 | `빌드 스크립트 없음` |
| 통과 결론 | 예 | 열거 | ALLOW PUSH / BLOCK PUSH | `BLOCK PUSH` |
| 차단 사유 | 조건부 필수 | 텍스트 | BLOCK 시 필수, P0 를 나열 | `A2 이력 시크릿 적중` |

## 5. 작성 설명

1. **근거 강제**: 모든 판정에는 근거가 있어야 합니다. 근거 없는 PASS 는 무효로 간주하며 SKIP 으로 바꾸고 사유를 설명해야 합니다.
2. **등급 대응**: FAIL 에는 등급을 표기해야 합니다. P0 은 통과를 직접 차단하고, P1 은 할 일로 등록해야 하며, P2 는 제안에 기록합니다.
3. **Gate C 기준**: P1 ≤ 3 이고 일정이 잡혀 있어야 PASS 할 수 있습니다. 초과 시 등급을 낮추어 처리하거나 차단해야 합니다.
4. **SKIP 사용**: 점검할 수 없을 때는 SKIP + 사유를 표기하며 PASS 로 쓰면 안 됩니다. 조건이 갖추어진 후 재점검합니다.
5. **일관성**: 게이트 판정은 [감사 차원 매트릭스](./감사-차원-매트릭스.md)의 P0/P1/P2 등급 및 [하드 룰](./하드-룰.md)의 차단 규칙과 일치해야 합니다.
6. **통과**: 세 항목이 모두 통과해야만 `✅ ALLOW PUSH` 를 출력할 수 있습니다. 하나라도 FAIL 이면 `⛔ BLOCK PUSH` 를 출력하고 차단 사유를 나열합니다.
7. **인도 형식**: 판정 결과는 [감사 보고서 형식](./감사-보고서-형식.md)에 따라 출력하며, 통과 후 [푸시 및 릴리스 규범](./푸시-및-릴리스-규범.md)을 수행합니다.

흔한 오류:

| 잘못된 작성 | 문제 | 수정 방식 |
| --- | --- | --- |
| 결론은 PASS 인데 근거가 비어 있음 | 판정 무효 | 근거를 보충하거나 SKIP 으로 변경 |
| P0 이 남아 있는데 ALLOW PUSH 로 작성 | 하드 룰 위반 | BLOCK PUSH 로 변경 |
| SKIP 에 사유 없음 | 누락 의심 | 사유 보충 |
| Gate C 에 P1 이 5건인데 PASS | 기준 초과 | 등급 하향 또는 차단 |
| 판정 결과를 문장으로만 쓰고 체크리스트 없음 | 재검증 불가 | 템플릿으로 항목별 작성 |

## 6. 완전한 예시

```markdown
# 게이트 판정：markdown-lint-cli v1.0.0

판정일：2026-11-20 ｜ 판정자：王五 ｜ 리포지터리：example/markdown-lint-cli

## Gate A · 보안 게이트
| 번호 | 점검 항목 | 결론 | 근거 | 등급 | 조치 |
| --- | --- | --- | --- | --- | --- |
| A1 | 작업 공간 시크릿 | PASS | gitleaks detect: 0 findings | — | — |
| A2 | 이력 시크릿 | PASS | gitleaks --log-opts=--all: 0 findings | — | — |
| A4 | LICENSE 존재와 유형 | PASS | LICENSE 1행 MIT | — | — |
| A5 | 대용량 파일과 LFS | PASS | find -size +50M: 없음 | — | — |

결론：PASS, 미결 항목：없음

## Gate B · 품질 게이트
| 번호 | 점검 항목 | 결론 | 근거 | 등급 | 조치 |
| --- | --- | --- | --- | --- | --- |
| B1 | 빌드 통과 | PASS | run #128 | — | — |
| B2 | 테스트 통과 | PASS | 132/132 passed | — | — |
| B4 | 커밋 메시지 규범 | PASS | git log --oneline 전부 준수 | — | — |

결론：PASS, 미결 항목：없음

## 총판정
- A：PASS ｜ B：PASS ｜ C：PASS
- 통과 결론：✅ ALLOW PUSH
- 차단 사유：없음
```
