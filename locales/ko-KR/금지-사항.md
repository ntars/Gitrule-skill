# 금지 사항

> 이 파일이 해결하는 문제：위반할 수 없는 모든 금지 행위를 모아, 리뷰와 작성 시의 최종 레드라인 체크리스트로 삼습니다.

## 1. 총괄 및 푸시 레드라인

1. P0가 0건이 아닌 상태에서 「먼저 푸시하고 나중에 보완해도 된다」고 출력하는 것은 금지됩니다.
2. 검사 결과를 조작하는 것은 금지됩니다. 검사할 수 없는 항목은 `SKIP + 이유`로 표시하며, PASS로 작성해서는 안 됩니다.
3. 여러 문서를 하나의 파일로 병합해 납품하는 것은 금지됩니다.
4. README에 API 전체, 기여 가이드, 변경 이력을 밀어넣는 것은 금지됩니다.
5. `--force`로 공용 브랜치에 푸시하는 것은 어떤 경우에도 금지됩니다.
6. 유출된 키를 「삭제 커밋」만으로 처리하는 것은 금지됩니다.
7. [프로젝트 명명 규범](./프로젝트-명명-규범.md)을 벗어나 임의로 리포지터리 이름을 만드는 것은 금지됩니다.
8. 내부 사고 과정을 납품 문서에 적는 것은 금지됩니다.

## 2. 문서 작성 레드라인

1. 프로젝트 이름, 기능, 성능 데이터, 의존성 버전, 라이선스, 작성자 정보, 테스트 결과를 조작해서는 안 됩니다.
2. 타인의 README, 문서, 코드, 이미지, 문구를 복제해서는 안 됩니다. 인용이 꼭 필요한 경우 출처와 라이선스를 명시해야 합니다.
3. 확인을 받지 않은 상태에서 라이선스 유형을 선택해서는 안 됩니다.
4. 검증되지 않은 성능 수치, 출처 없는 비교 결론, 약속성 표현(예: 「보장」「영구 무료」), 제3자 프로젝트에 대한 폄하성 서술, 프로젝트와 무관한 홍보 내용이 있어서는 안 됩니다.
5. 출처가 불분명한 소재를 사용해서는 안 됩니다. 이미지, 아이콘, 폰트의 출처와 라이선스가 없을 때는 확인 필요로 표시하며, 바로 사용해서는 안 됩니다.

## 관련 파일

- 위반 시 차단되는 하드 룰은 [하드 룰](./하드-룰.md)을 참조하십시오
- 인시던트 처리(키 유출 등)는 [푸시 및 릴리스 규범](./푸시-및-릴리스-규범.md) 제5절을 참조하십시오
- 역할의 강제 제약은 [역할과 책임](./역할과-책임.md)을 참조하십시오
