# README 표준 템플릿

> 이 파일이 해결하는 문제：프로젝트 전체 라이프사이클의 첫 화면 표현을 포괄하면서, 그대로 복사해 자리표시자만 교체하면 적용할 수 있는 범용 README 템플릿을 제공합니다. 자리표시자 대조표, 선택 섹션 설명, 인도 전 자체 점검 체크리스트를 함께 제공하여 어떤 개발자든 자신의 프로젝트에 맞게 빠르게 맞춤 구성할 수 있게 합니다.

## 1. 사용 설명

1. 제3절 「템플릿 본문」의 전체 내용을 복사하여 프로젝트 루트 디렉터리에 `README.md`로 새로 만듭니다.
2. 제4절 자리표시자 대조표에 따라 `{{...}}`를 하나씩 교체합니다. 사용하지 않는 항목은 해당 항목이 있는 행 전체 또는 섹션 전체를 삭제합니다.
3. 제3절의 각 소절은 [README 섹션 규범](./README-섹션-규범.md)의 20개 장에 대응하며, 안에서 밖으로 향하는 라이프사이클 순서로 배열되어 있습니다. 특정 장을 삭제할 때는 첫 화면 내비게이션의 해당 링크도 함께 삭제해야 합니다.
4. [배지 규범](./배지-규범.md)에 따라 배지 스타일, 색상, 수량을 통일합니다. [README 시각 레이아웃 규범](./README-시각-레이아웃-규범.md)에 따라 스크린샷, 표, 코드 블록의 배치를 점검합니다.
5. [README 분류 적응 가이드](./README-분류-적응-가이드.md)에 따라 프로젝트 유형별로 섹션을 취사선택합니다.
6. 커밋 전에 제6절 자체 점검 체크리스트를 실행하여 잔여 자리표시자가 없는지 확인합니다.

## 2. 맞춤 구성 원칙

- **필수 항목**：프로젝트 이름, 리포지터리 설명, 한 문장 포지셔닝, 설치, 빠른 시작, 라이선스.
- **순서 고정**：섹션 순서는 [README 섹션 규범](./README-섹션-규범.md)과 일치하며, 중국어판과 영어판은 장마다 대응합니다.
- **근거 우선**：핵심 특성, 성능, 엔지니어링 트레이드오프는 재검증 가능한 근거를 제시해야 하며, 정성적 찬사는 금지합니다.
- **투명한 공개**：부적합 시나리오, 한계, 알려진 문제, 미구현 기능은 명시적으로 나열해야 하며 은폐해서는 안 됩니다.
- **비약속**：로드맵에는 「비약속」을 표기하고 구체적인 전달 날짜를 쓰지 않습니다.
- **진실성**：모든 명령, 예시, 링크, 배지는 실제로 사용 가능해야 하며, 연락처와 신고 채널은 실제로 도달 가능해야 합니다.

## 3. 템플릿 본문

이 절은 프로젝트 라이프사이클의 「안에서 밖으로」 순서로 구성되었으며, 총 20개 절로 [README 섹션 규범](./README-섹션-규범.md)의 20개 장과 1:1로 대응합니다. 각 절 코드 블록 안의 텍스트가 곧 복사 가능한 본문입니다.

섹션과 라이프사이클 단계의 매핑은 다음과 같으며, 필요에 따라 위치를 찾기 쉽게 하기 위한 것입니다：

| 라이프사이클 단계 | 대응 소절 | 표현 중점 |
| --- | --- | --- |
| 프로젝트 착수 | 3.1–3.2 | 포지셔닝, 배경, 적용 시나리오와 한계 |
| 요구사항 분석 | 3.2–3.3 | 기능 경계, 적용 시나리오, 부적합 시나리오 |
| 아키텍처 설계 | 3.5–3.6、3.11 | 엔지니어링 트레이드오프, 기술 스택, 디렉터리 구조 |
| 개발 구현 | 3.3–3.4、3.9–3.10 | 기능, 특성, 설정, API |
| 테스트 검증 | 3.8、3.12 | 빠른 시작 예시, 성능 근거 |
| 배포 릴리스 | 3.7、3.14 | 설치와 배포, 호환성 매트릭스 |
| 운영 모니터링 | 3.13、3.15 | 보안과 개인정보, 알려진 문제와 제한 |
| 반복 유지보수 | 3.15–3.17 | 미구현 기능, 변경 이력, 향후 로드맵 |

설명：README는 프로젝트의 첫 화면이며, 각 단계의 프로세스 문서(요구사항, 설계, 테스트, 배포, 운영의 전체 기록)는 해당 규범이 담당합니다. [문서 매트릭스](./문서-매트릭스.md)를 참조하십시오. 이 절은 사용자에게 보이는 결론만 제시합니다.

## 4. 자리표시자 대조표

## 6. 인도 전 자체 점검 체크리스트

- [ ] 잔여 `{{...}}` 자리표시자가 없습니다.
- [ ] 첫 화면에 리포지터리 설명【중국어 | 영어】과 토픽 태그가 포함되어 있으며, 둘 다 리포지터리 메타데이터와 일치합니다.
- [ ] 리포지터리 설명의 중국어와 영어가 각각 120자를 초과하지 않습니다.
- [ ] 토픽 태그가 20개를 모두 채우고, 전부 소문자 영어이며 `-`로 연결되어 있습니다.
- [ ] 한 문장 포지셔닝에 카테고리 단어가 포함되어 있고, 중국어는 60자, 영어는 25단어를 초과하지 않습니다.
- [ ] 핵심 특성의 각 항목이 다섯 단락 구조를 포함하고 재검증 가능한 근거가 있습니다.
- [ ] 장점과 한계가 분리되어 나열되었고, 한계에 영향 범위와 회피 방식이 포함되어 있습니다.
- [ ] 알려진 문제에 추적 링크가 포함되어 있고, 미구현 기능에 이유와 계획 상태가 포함되어 있습니다.
- [ ] 로드맵에 「비약속」이 표기되었고 구체적인 전달 날짜가 없습니다.
- [ ] 부적합 시나리오와 명시적 미지원 항목이 나열되어 있습니다.
- [ ] 1급 제목이 유일하고, 2급 제목 계층이 연속적이며, 섹션 순서가 규범의 20개 장과 일치합니다.
- [ ] 배지 스타일이 통일되었고, 링크가 유효하며, alt 텍스트가 명확합니다.
- [ ] 설치 명령과 빠른 시작 예시가 실제로 실행 가능합니다.
- [ ] 모든 코드 블록에 언어가 표기되었고, 모든 이미지에 alt 텍스트가 있습니다.
- [ ] 상대 경로가 Fork 및 오프라인 상태에서도 사용 가능합니다.
- [ ] LICENSE가 존재하고, SPDX 식별자가 README와 일치합니다.
- [ ] 중국어판과 영어판의 섹션 순서가 1:1로 대응합니다.
