# 문서 매트릭스

> 이 파일이 해결하는 문제：각 전달 문서의 고유 책임, 넣어서는 안 되는 내용, 분할 제약을 정의하여 파일 하나에 책임 하나를 보장하고 병합을 금지합니다.

## 1. 파일과 책임

| 파일 | 고유 책임 | 넣어서는 안 되는 내용 |
|---|---|---|
| `README.md` | 첫 페이지: 무엇인지, 어떻게 설치하는지, 어떻게 실행하는지, 상세 내용을 어디서 확인하는지 | 전체 API, 기여 프로세스, 업데이트 로그 |
| `LICENSE` | 라이선스 전문 | 어떠한 설명 문구도 |
| `CHANGELOG.md` | 사용자 대상 버전 변경 | 내부 리팩터링 세부, 개발 계획 |
| `CONTRIBUTING.md` | 외부 기여자의 프로세스와 규범 | 프로젝트 기능 설명 |
| `CODE_OF_CONDUCT.md` | 행동 강령 | 기술 내용 |
| `SECURITY.md` | 취약점 보고 채널과 대응 전략 | 알려진 취약점 목록 |
| `docs/api.md` | 전체 API 레퍼런스 | 튜토리얼 |
| `docs/architecture.md` | 아키텍처와 모듈 경계 | 사용 예시 |
| `docs/naming.md` | 명명 규범 | 다른 규범 |
| `docs/release.md` | 릴리스 프로세스와 버전 전략 | 변경 기록 |
| `.github/PULL_REQUEST_TEMPLATE.md` | PR 자체 점검 체크리스트 | 프로젝트 소개 |
| `.github/ISSUE_TEMPLATE/*.yml` | 구조화된 이슈 양식 | 자유 텍스트 |
| `.github/workflows/*.yml` | CI/CD | 설명 문서 |

> 설명: `docs/naming.md`의 규범 본문은 [프로젝트 명명 규범](./프로젝트-명명-규범.md)을, `docs/release.md`의 규범 본문은 [푸시 및 릴리스 규범](./푸시-및-릴리스-규범.md)을 참조합니다.

## 2. 제약

- 단일 파일이 300줄을 초과하면 반드시 `docs/`로 분할하고, README에는 요약 + 링크만 남깁니다.
- 파일명은 대문자로 고정하고, 경로는 고정하며, 임의로 디렉터리 계층을 만들 수 없습니다.
- 각 문서는 서두에 「이 파일이 해결하는 문제」를 한 문장으로 설명하고, 말미에 관련 파일 상호 링크를 제시합니다.

## 관련 파일

- README의 20개 섹션 구조는 [README 섹션 규범](./README-섹션-규범.md)을 참조합니다
- NOTICE 독립 규범은 [NOTICE 규범](./NOTICE-규범.md)을 참조합니다
- LICENSE 독립 규범은 [LICENSE 규범](./LICENSE-규범.md)을 참조합니다
- 문서 완전성/품질은 차원 D11/D12에 속하며, [감사 차원 매트릭스](./감사-차원-매트릭스.md)를 참조합니다
