# 트러블슈팅 규범

> 이 파일이 해결하는 문제：트러블슈팅 문서(Troubleshooting / FAQ)의 구조, 항목 작성법, 유지보수 메커니즘을 정의하여 사용자가 현상에 따라 원인을 찾고 흔한 문제를 스스로 해결할 수 있도록 한다.

## 1. 적용 시나리오

다음 상황에서는 트러블슈팅 문서를 제공해야 한다:

1. 설치 또는 빌드 실패에 여러 가지 흔한 원인이 존재한다.
2. 설정 항목 간에 충돌이 있으며, 오류 메시지만으로는 해결 방법을 설명하기에 부족하다.
3. 특정 플랫폼 또는 버전에 알려진 제약이 존재한다.
4. 사용자가 같은 유형의 질문을 반복적으로 제기하며, 답변을 표준화할 수 있다.

## 2. 파일 위치와 명명

1. 내용이 적을 때는 README의 한 섹션으로 두고, 제목은 「자주 묻는 질문」 또는 「트러블슈팅」으로 한다.
2. 내용이 많을 때는 `docs/troubleshooting.md` 또는 `FAQ.md`를 별도로 만들고, README에는 진입 링크를 남긴다.
3. 문제는 주제별로 그룹화한다. 예: 「설치」「설정」「실행」「성능」「네트워크」.

## 3. 문서 구조

1. **서두 설명**: 이 문서가 다루는 흔한 문제의 범위와 적용 버전.
2. **문제 색인**: 주제별로 문제 제목을 나열하여 빠른 이동을 지원.
3. **문제 항목**: 통일된 구조로 항목별 전개.
4. **여전히 해결되지 않을 때**: 이슈, 토론 게시판 등 도움 요청 채널을 안내.

## 4. 항목 구조

각 문제 항목은 다음 부분을 포함해야 한다:

| 부분 | 내용 | 요구사항 |
| --- | --- | --- |
| 현상 | 사용자가 보는 구체적 표현 | 완전한 오류 정보 포함, 「오류 발생」만 기재 금지 |
| 발생 조건 | 언제 나타나는지 | 버전, 플랫폼, 조작 명확화 |
| 원인 | 근본 원인 | 메커니즘 설명, 결론만 제시 금지 |
| 해결 방안 | 실행 가능한 단계 | 번호로 나열, 명령 또는 설정 포함 |
| 검증 | 수정되었는지 확인하는 방법 | 예상 출력 제시 |
| 관련 | 관련 문서 또는 이슈 링크 | 선택 사항 |

## 5. 항목 작성 예시

```markdown
### 설치 시 `EACCES: permission denied` 안내

**현상**: `npm install -g <package>` 실행 시 권한 부족 안내가 표시된다.

**발생 조건**: Linux 또는 macOS에서 일반 사용자로 전역 패키지를 설치할 때.

**원인**: 전역 설치 디렉터리의 쓰기 권한이 시스템 관리자에게 있어, 현재 사용자에게는 쓰기 권한이 없다.

**해결 방안**:

```bash
mkdir -p ~/.npm-global
npm config set prefix '~/.npm-global'
export PATH=~/.npm-global/bin:$PATH
npm install -g <package>
```

**검증**: `<package> --version`을 실행하여 버전 번호가 출력되면 성공이다.

## 6. 작성 요구사항

1. 문제 제목은 내부 용어가 아니라 사용자가 검색할 표현을 사용한다.
2. 오류 정보는 원문 그대로 유지하여 사용자가 대조하기 쉽게 한다. 민감 정보는 마스킹해야 한다([보안 및 개인정보 규범](./보안-및-개인정보-규범.md) 참조).
3. 해결 방안은 완전한 명령을 제시하며, 사용자가 환경 변수를 설정했다고 가정하지 않는다.
4. 하나의 항목은 하나의 문제만 해결하며, 여러 원인을 병합하지 않는다.
5. 알려진 결함과 관련된 경우 영향 범위와 회피 방식을 설명하되, 수정 일정을 약속하지 않는다.
6. 마이그레이션과 관련된 문제는 마이그레이션 가이드에 링크한다([마이그레이션 가이드 규범](./마이그레이션-가이드-규범.md) 참조).

## 7. 유지보수 메커니즘

1. 같은 문제가 세 번 이상 반복 제기되면 항목을 신설하거나 다시 작성해야 한다.
2. 버전 업그레이드 후 전체 항목을 검토하고, 효력이 없어진 내용을 삭제한다.
3. 각 항목에 마지막 검증 버전을 표기하여 여전히 적용되는지 판단하기 쉽게 한다.
4. 문제 색인은 항목 증감에 맞추어 동기적으로 갱신한다.

## 8. 금지 사항

1. 트러블슈팅 문서를 기능 소개로 작성하는 것을 금지한다.
2. 「재시작해 보세요」 등 진단 가치가 없는 답변만 작성하는 것을 금지한다.
3. 오류 정보와 발생 조건을 생략하는 것을 금지한다.
4. 이미 수정되었거나 효력이 없어진 항목을 남겨 두는 것을 금지한다.
