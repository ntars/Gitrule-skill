# README 템플릿 조사 보고서

> 이 파일이 해결하는 문제：이번 표준 README 템플릿의 조사 방법, 표본 규모, 정량적 발견을 기록하여 [README 표준 템플릿](./README-표준-템플릿.md)과 각 전문 규범에 데이터 근거를 제공하고, 방법의 경계와 한계를 명확히 합니다.

## 1. 조사 목표와 방법

### 1.1 목표

star 수가 상위인 헤드 오픈소스 프로젝트를 조사하여, 그 README 및 관련 문서의 구조, 섹션 구성, 시각적 표현, 배지 사용 규칙을 정리하고, 재사용 가능한 범용 규범과 템플릿을 형성합니다.

### 1.2 데이터 출처

- 리포지터리 메타데이터：GitHub GraphQL Search API, star 내림차순, `is:public archived:false fork:false` 필터링.
- README 원문：GitHub REST Contents API(`readme` 엔드포인트), base64 또는 raw 형식으로 가져온 후 파싱.
- 배지 매개변수：Shields.io 공식 문서(Static Badge, Logos 페이지)와 badge-maker 형식 설명.
- 중국어 커뮤니티 실천：phodal/github(《GitHub漫游指南》, 11,362 star)의 프로젝트 문서, 커밋 메시지, 홍보 섹션. 기계 판독 통계로 포괄할 수 없는 작성 원칙과 운영 경험을 보충하는 데 사용.

### 1.3 수집 방법

1. **메타데이터**：GitHub Search API는 단일 쿼리에서 최대 1000건을 반환합니다. 표본을 확대하기 위해 star 구간 분할을 사용했습니다. 이분법으로 매 1000개에 해당하는 star 임계값을 찾고, 배치를 차례로 내리며 누적 11개 배치를 수행하여 최종적으로 10,995개 헤드 리포지터리의 메타데이터를 확보했습니다.
2. **README 표본 추출**：헤드 1000개 리포지터리 내에서 주 언어로 층화 표본 추출하여 Python, TypeScript, JavaScript, Rust, Go, C++ 등 주요 언어를 포괄했고, 120개 리포지터리를 표본으로 삼아 전부 README 원문을 성공적으로 확보했습니다.
3. **통계 기준**：리포지터리를 단위로 섹션 출현율과 요소 사용률을 통계했고, 배지 스타일과 logo 매개변수는 URL 내 출현 횟수로 통계했습니다.

### 1.4 방법의 한계(명확히 해야 함)

- GitHub Search API는 단일 쿼리에 1000건 상한이 있습니다. 이 보고서는 분할 누적으로 규모를 확장했으나, 분할 경계는 star 동률의 영향을 받으므로 표본은 근사적 헤드 집합이며 엄격히 연속된 순위가 아닙니다.
- README 표본 규모는 120이며, 결론은 추세와 공통점을 반영할 뿐 전체 헤드 프로젝트의 통계적 유의 분포를 대표하지는 않습니다.
- 섹션 식별은 제목 키워드 매칭에 기반하므로, 표현 차이로 인한 통계 편향이 존재합니다.
- 배지 매개변수 통계는 URL에 명시적으로 나타난 매개변수를 대상으로 하며, 동적 배지의 기본 매개변수는 집계되지 않았습니다.

## 6. 정리 결론

1. 범용 템플릿은 「포지셔닝 → 설치 → 빠른 시작 → 문서 → 기여 → 라이선스」를 주간으로 삼아야 합니다.
2. 배지는 기본적으로 `flat-square` 또는 `for-the-badge`를 사용하고, 전문에서 통일하며, 수량은 4–6개입니다.
3. 이미지와 코드 블록은 매력도 높은 첫 화면의 핵심이며, `alt`와 언어 표기를 갖추어야 합니다.
4. 프로젝트 유형이 섹션 취사선택을 결정합니다. [README 분류 적응 가이드](./README-분류-적응-가이드.md)를 참조하십시오.
5. 컴플라이언스와 커뮤니티 거버넌스(라이선스, 기여 가이드)는 헤드 프로젝트의 공통 인식이며, 필수로 지정합니다.
