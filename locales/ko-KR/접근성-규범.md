# 접근성 규범

> 이 파일이 해결하는 문제：프로젝트 문서, README와 사용자 인터페이스의 접근성 요구사항을 정의하여 화면 읽기 프로그램, 키보드 조작과 다양한 시각 조건을 가진 독자에게도 콘텐츠가 동등하게 사용 가능하도록 합니다.

## 1. 적용 범위

1. 문서 접근성: README, 문서 사이트, 예시 코드, 표, 이미지.
2. 인터페이스 접근성: 애플리케이션과 웹 프로젝트의 사용자 인터페이스.
3. 명령줄 접근성: 도움말 텍스트, 오류 안내와 출력 형식.

## 2. 문서 접근성

### 2.1 이미지와 미디어

1. 모든 이미지는 화면 내용과 역할을 설명하는 `alt` 텍스트를 제공해야 하며, 장식용 이미지는 빈 `alt`를 사용합니다.
2. 「이미지」「스크린샷」「image」 등 정보가 없는 텍스트를 `alt`로 사용해서는 안 됩니다.
3. GIF 움직이는 이미지는 인접한 텍스트에서 그 내용을 설명해야 하며, 애니메이션만으로 정보를 전달하는 것을 피해야 합니다.
4. 차트는 동시에 텍스트 설명 또는 데이터 표를 제공해야 하며, 색상만으로 데이터 계열을 구분해서는 안 됩니다.

### 2.2 제목과 구조

1. 제목 계층은 연속되어야 하며, 단계를 건너뛰어서는 안 됩니다([README 시각 레이아웃 규범](./README-시각-레이아웃-규범.md) 참조).
2. 전체 문서에 1급 제목은 하나만 둡니다.
3. 목록은 규범에 맞는 Markdown 문법을 사용하여 화면 읽기 프로그램이 목록으로 인식할 수 있도록 보장합니다.
4. 표는 반드시 헤더 행이 있어야 하며, 헤더 없는 표로 페이지를 레이아웃해서는 안 됩니다.

### 2.3 링크와 텍스트

1. 링크 텍스트는 대상을 독립적으로 설명할 수 있어야 하며, 「여기를 클릭」「더 보기」는 금지합니다.
2. 색상은 정보를 전달하는 유일한 수단이 되어서는 안 되며, 반드시 텍스트나 아이콘과 함께 사용해야 합니다.
3. 중한 혼용 시 공백을 유지하여 단어 분리와 낭독이 정확하도록 합니다.
4. 약어가 처음 나올 때 전체 이름을 제시합니다.

### 2.4 코드와 표

1. 코드 블록에는 언어를 표기하여 보조 도구가 인식하기 쉽도록 합니다([README 시각 레이아웃 규범](./README-시각-레이아웃-규범.md) 참조).
2. 표 셀 내용은 간결하게 하여 행 병합으로 인한 리더기 파싱 어려움을 피합니다.
3. 긴 명령은 줄바꿈 표기를 제시하며, 가로 스크롤에 의존하지 않습니다.

## 3. 인터페이스 접근성

### 3.1 키보드 조작

1. 모든 상호작용 요소는 키보드로 도달하고 조작할 수 있어야 합니다.
2. 포커스 순서는 시각적 순서와 일치해야 하며, 포커스 상태는 명확히 보여야 합니다.
3. 반복 콘텐츠를 건너뛸 수 있는 바로가기 입구를 제공합니다(예: 주요 콘텐츠로 이동).

### 3.2 시맨틱과 레이블

1. 시맨틱 태그로 구조와 역할을 표현하며, 시맨틱이 없는 요소로 컨트롤을 모방하는 것을 피합니다.
2. 폼 컨트롤에는 반드시 연결된 레이블이 있어야 하며, 오류 안내는 해당 필드와 바인딩되어야 합니다.
3. 동적 상태 변화는 접근성 안내를 통해 보조 기술에 전달합니다.

### 3.3 시각 조건

1. 텍스트와 배경의 대비는 가독성 요구사항을 충족해야 하며, 본문 대비는 4.5:1 이상, 큰 글자는 3:1 이상입니다.
2. 시스템의 라이트/다크 테마를 지원하며, 테마 전환이 정보 구조를 바꾸지 않아야 합니다([README 시각 레이아웃 규범](./README-시각-레이아웃-규범.md) 참조).
3. 애니메이션은 감소 옵션을 제공하며, 자동 재생되는 고빈도 깜빡임 콘텐츠를 피합니다.
4. 텍스트를 200%로 확대해도 레이아웃이 여전히 사용 가능해야 하며, 콘텐츠 잘림이 발생하지 않아야 합니다.

## 4. 명령줄 접근성

1. 오류 안내는 사유와 실행 가능한 수정 동작을 설명해야 하며, 오류 코드만 출력해서는 안 됩니다.
2. `--help` 출력은 분류가 명확해야 하며, 필수 파라미터와 기본값을 나열합니다.
3. 색상 출력을 비활성화하는 환경 변수를 지원하여 화면 읽기 프로그램과 로그 처리에 용이하도록 합니다.
4. 대화형 프롬프트는 비대화형의 동등한 파라미터를 제공하여 자동화 시나리오를 지원합니다.

## 5. 검증 체크리스트

- [ ] 모든 이미지에 정보가 명확한 `alt` 텍스트가 있음.
- [ ] 제목 계층이 연속되며, 전체 문서에 1급 제목이 하나임.
- [ ] 링크 텍스트를 독립적으로 이해할 수 있음.
- [ ] 표에 헤더가 있으며, 색상이 유일한 정보 매체가 아님.
- [ ] 코드 블록에 언어가 표기됨.
- [ ] 인터페이스 요소를 키보드로 조작할 수 있고, 포커스가 보임.
- [ ] 대비가 최저 요구사항을 충족하며, 라이트/다크 테마 모두 읽을 수 있음.
- [ ] 도움말 텍스트와 오류 안내가 다음 동작을 안내할 수 있음.

## 6. 금지 사항

1. 이미지만으로 핵심 정보를 전달하고 텍스트 대체를 제공하지 않는 것은 금지합니다.
2. 색상만으로 상태나 오류를 표시하는 것은 금지합니다.
3. 의미 없는 링크 텍스트를 사용하는 것은 금지합니다.
4. 대체 없이 포커스 표시 스타일을 제거하는 것은 금지합니다.
