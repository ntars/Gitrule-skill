# 코드 소유권 규범

> 이 파일이 해결하는 문제：`.github/CODEOWNERS` 파일의 문법, 소유권 할당과 리뷰 라우팅 규칙을 정의하여 모든 변경이 책임을 가진 리뷰어에게 자동으로 할당되도록 합니다.

## 1. 설계 원칙

1. **경로에서 사람으로의 명확한 매핑**: 각 규칙은 특정 경로를 누가 담당하는지 명시하여 리뷰어가 없거나 리뷰가 중복되는 상황을 피합니다.
2. **최소 필수 owners**: 단일 경로의 소유자는 1–3명으로 제한하며, 과다하면 책임이 분산됩니다.
3. **기본 인계**: 전역 기본 소유자를 설정하여 명시적 규칙에 매칭되지 않는 경로를 포괄합니다.
4. **팀 구조와 동기화**: 구성원이 변경되면 즉시 업데이트하여 유효하지 않은 계정이 리뷰를 막지 않도록 합니다.

## 2. 파일 위치와 문법

### 2.1 경로

`CODEOWNERS` 파일은 다음 위치 중 하나에 둘 수 있으며, 우선순위에 따라 첫 번째로 매칭된 것을 사용합니다:

1. 리포지터리 루트 `CODEOWNERS`;
2. `docs/CODEOWNERS`;
3. `.github/CODEOWNERS`(권장).

### 2.2 문법 규칙

```text
# 注释以 # 开头
<路径模式>  <所有者>  [<所有者>...]
```

- 한 줄에 규칙 하나이며, 경로 패턴 뒤에 하나 이상의 소유자를 씁니다.
- 소유자 형식은 `@사용자명` 또는 `@조직/팀`입니다.
- 이메일을 소유자로 사용하려면 GitHub 계정과 연결되어 있어야 합니다.
- 경로는 대소문자를 구분하며 와일드카드 `*`, `**`를 지원합니다.

### 2.3 예시

```text
# 默认所有者
*                       @org/maintainers

# 按目录分配
/src/core/              @org/core-team
/src/api/               @org/api-team @alice
/docs/                  @org/docs-team

# 按文件类型分配
*.md                    @org/docs-team
/.github/workflows/      @org/devops-team
```

## 3. 매칭 규칙

1. 마지막으로 매칭된 규칙만 적용되며 누적되지 않습니다. 따라서 일반 규칙은 앞에, 특수 규칙은 뒤에 작성해야 합니다.
2. 디렉터리 규칙은 `/`로 시작하여 루트 경로를 한정하지 않는 한 해당 디렉터리와 하위 디렉터리에 매칭됩니다.
3. 규칙 순서가 우선순위를 결정하며, 넓은 것에서 좁은 순으로 배열해야 합니다.
4. 매칭되는 경로가 없으면 기본 소유자가 리뷰 책임을 집니다.

## 4. 소유권 할당 전략

| 차원 | 할당 근거 |
| --- | --- |
| 디렉터리 | 모듈 또는 서브시스템 경계에 따라 할당 |
| 파일 유형 | 문서, 구성, 테스트는 유형별로 통일 할당 가능 |
| 핵심 경로 | 보안, 릴리스, CI 구성은 핵심 메인테이너가 독점 |
| 신규 구성원 | 먼저 비필수 리뷰어로 참여하고, 숙련 후 정식 소유자로 전환 |

## 5. 리뷰 프로세스와의 연동

1. PR이 생성되면 GitHub가 매칭 경로의 소유자에게 자동으로 리뷰를 요청합니다.
2. 필수 리뷰 요구는 브랜치 보호 규칙으로 구성하며, [Git 워크플로 및 브랜치 규범](./Git-워크플로-및-브랜치-규범.md)을 참조합니다.
3. 소유자는 합의된 기한 내에 응답해야 하며, 초과 시 기본 소유자가 인계받습니다.
4. 소유자가 변경되면 파일을 동시에 업데이트하여 유효하지 않은 계정이 프로세스를 막지 않도록 합니다([코드 리뷰 규범](./코드-리뷰-규범.md) 참조).

## 6. 유지보수 요구사항

1. 조직 구조나 팀 책임이 변경될 때마다 한 번씩 재검토합니다.
2. 리포지터리 이관, 구성원 퇴장 시에는 즉시 해당 소유자를 제거해야 합니다.
3. 파일 변경은 최소 한 명의 기존 소유자의 리뷰를 거쳐야 하여 권한이 스스로 확산되는 것을 방지합니다.
4. 소유자를 비활성 계정이나 봇 계정으로 지정해서는 안 됩니다(자동화 전용은 제외).

## 7. 금지 사항

1. 지나치게 넓은 와일드카드 규칙을 사용하여 모든 사람이 소유자가 되게 하는 것은 금지합니다.
2. 민감 경로(릴리스, 키 구성)를 리뷰 역량이 없는 구성원에게 할당하는 것은 금지합니다.
3. 파일에 개인 연락처를 기록하는 것은 금지합니다.
4. 퇴사한 구성원의 소유자 신분을 장기간 유지하는 것은 금지합니다.

- 브랜치 보호는 [Git 워크플로 및 브랜치 규범](./Git-워크플로-및-브랜치-규범.md)을 참조
