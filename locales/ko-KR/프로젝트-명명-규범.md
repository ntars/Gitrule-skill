# 프로젝트 명명 규범

> 이 파일이 해결하는 문제：리포지터리 이름의 문자, 대소문자, 단어 구분, 길이, 의미 등 강제 규칙과 명명 공식, 관례 접미사, 검색 절차 및 부속 메타데이터 요구 사항을 정의합니다.

## 1. 강제 규칙

| 규칙 | 요구 사항 | 반례 |
|---|---|---|
| 문자 집합 | `a-z`, `0-9`, `-`만 허용 | `My_Proj`, `我的项目` |
| 대소문자 | 전부 소문자 | `MyProject` |
| 단어 구분 | kebab-case, `-`로 연결 | `myproject`, `my_project` |
| 길이 | 2–25자 | 지나치게 긴 조합 이름 |
| 끝맺음 | 명사 또는 형태 접미사로 끝맺음 | `-project`, `-test`로 끝맺음 |
| 버전 | 버전 번호, 연도, 날짜를 포함하지 않음 | `tool-v2`, `app2024` |
| 무정보 단어 | `my`/`demo`/`test`/`new`/`tmp` 금지 | `my-new-demo` |
| 고유성 | GitHub / npm / PyPI에서 각각 한 번씩 검색 | 유명 라이브러리와 중복 |
| 의미 | 이름 자체로 「무엇을 하는지」를 읽을 수 있어야 함 | `xyz`, `abc123` |

## 2. 명명 공식(네 가지 중 택일)

```text
<技术>-<对象>          vue-virtual-table      go-ratelimit
<对象>-<形态>          note-cli   image-api   config-loader
<动词>-<对象>          parse-markdown   sync-dotfiles
<领域>-<子领域>        web-ui-kit   data-pipeline
```

## 3. 관례 접미사

`-cli` 명령줄 / `-sdk` 클라이언트 라이브러리 / `-api` `-server` 서버 / `-template` `-boilerplate` 스캐폴드 / `-loader` `-parser` 미들웨어 / `-kit` 컴포넌트 집합 / `-notes` `-guide` 문서 / `dotfiles` 설정 리포지터리 / `awesome-xxx` 리소스 모음.

## 4. 명명 절차

1. 「이 프로젝트가 누구의 어떤 문제를 해결하는가」를 한 문장으로 작성합니다.
2. 이 문장에서 핵심 명사 + 형태를 뽑아 제2절의 임의 공식에 적용합니다.
3. 후보 3개를 생성하고 하나씩 중복 이름을 검색합니다.
4. README를 보지 않고도 가장 잘 이해되는 것을 선택합니다.
5. 중국어 이름은 리포지터리 이름에 쓰지 않고, README 첫 줄 제목 뒤에 씁니다.

## 5. 부속 메타데이터

### 5.1 리포지터리 소개(description)

- 리포지터리 이름과 같은 뿌리를 두며, 문형은 `<무엇을 하는지> for <누구를 위해>`입니다.
- 이중 언어 병합 형식：`국가 언어 | 영어`. 먼저 국가 언어 버전을 쓰고, 반각 세로줄(양쪽에 공백 하나씩)을 붙인 다음 영어 버전을 씁니다. 중국어 프로젝트 예시：

```text
轻量级 Go 命令行 JSON 处理工具 | A lightweight Go CLI for JSON processing
```

- 길이：국가 언어와 영어 각각 120자를 초과하지 않으며, 이중 언어 합계는 350자를 초과하지 않습니다(GitHub 상한).
- 이중 언어 합계가 초과할 때의 절충：국가 언어 버전이 아니라 영어 버전을 우선 압축합니다. 중국어는 정보 밀도가 더 높아 압축 시 손실되는 정보가 더 많기 때문입니다. 압축 시 먼저 수식어와 중복 한정어를 삭제하고, 다음으로 동의 표현을 병합하며, 마지막으로 두 언어 버전 각각의 완전한 주술 구조를 유지합니다.
- 줄바꿈, Markdown 문법, 이모지를 포함하지 않으며, 두 언어의 끝 문장부호 스타일을 일치시킵니다(모두 마침표를 붙이거나 모두 붙이지 않음).

### 5.2 토픽(topics)

- 20개를 가득 채우며(GitHub 상한), 완전히 커버하고 빈자리를 남기지 않습니다.
- 전부 영어를 사용하며, 중국어나 다른 언어를 사용해서는 안 됩니다. 전부 소문자, `-`로 연결하고, 공백과 특수 문자를 포함하지 않습니다.
- 언어, 도메인, 형태, 생태계, 시나리오의 다섯 범주를 완전히 커버하며, 추가로 documentation, open-source 같은 범용 단어를 붙일 수 있습니다.
- 리포지터리 생성 시 바로 설정하고 비워 두어서는 안 되며, 리포지터리 이름 변경 또는 재포지셔닝 후 한 번 재검토합니다.
