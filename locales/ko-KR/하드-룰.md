# 하드 룰

> 이 파일이 해결하는 문제：어느 하나라도 위반하면 푸시가 차단되며, 「일단 올리고 나중에 고친다」가 허용되지 않는 불가침 규칙을 나열합니다.

## 하드 룰 표

| # | 규칙 |
|---|---|
| H1 | 리포지터리 이름은 [프로젝트 명명 규범](./프로젝트-명명-규범.md)을 준수해야 하며, 대소문자·문자·길이 모두 적합해야 합니다 |
| H2 | `LICENSE` 파일이 반드시 있어야 합니다. 라이선스가 없으면 기본적으로 저작권 유보이며 공개해서는 안 됩니다 |
| H3 | 어떤 키, 토큰, 개인 키, `.env`, 클라우드 사업자 AK/SK, 데이터베이스 연결 문자열도 커밋해서는 안 됩니다 |
| H4 | 빌드 산출물, 의존성 디렉터리, IDE 설정, 시스템 임시 파일을 커밋해서는 안 됩니다 |
| H5 | 단일 파일은 100MB를 초과해서는 안 되며, 50MB를 초과하면 반드시 LFS를 사용하거나 제외해야 합니다 |
| H6 | `README.md`가 반드시 있어야 하며, 한 줄 포지셔닝, 설치, 최소 실행 예제, 라이선스를 포함해야 합니다 |
| H7 | 기본 브랜치는 반드시 보호되어야 하며, `main`/`master`에 직접 push하는 것은 금지됩니다 |
| H8 | 공용 브랜치에 `git push --force`를 사용하는 것은 금지되며, 개인 브랜치에서는 `--force-with-lease`만 허용됩니다 |
| H9 | 푸시 전 `build`와 `test`가 통과해야 하며, CI가 빨간불이면 메인라인에 병합해서는 안 됩니다 |
| H10 | 커밋 메시지는 Conventional Commits를 준수해야 하며, `wip`/`update`/`fix bug`처럼 정보가 없는 커밋은 금지됩니다 |
| H11 | 각 문서는 독립된 파일, 독립된 책임으로 구성해야 하며, 모든 내용을 README에 몰아넣는 것은 금지됩니다([문서 매트릭스](./문서-매트릭스.md) 참조) |
| H12 | 키가 이미 푸시되었다면 즉시 키를 교체하고 이력을 정리해야 하며, 삭제 커밋만으로 처리해서는 안 됩니다 |

## 실행 제약

- 어느 하나라도 위반하면 **푸시를 차단**하며, 「일단 올리고 나중에 고친다」는 허용되지 않습니다.
- H1–H12의 판정 결과는 [감사 보고서 형식](./감사-보고서-형식.md)의 문제 목록에 반영되어야 하며, 각 항목에는 증거(경로:줄 / 명령 출력)가 있어야 합니다.
- H12를 위반한 경우 [푸시 및 릴리스 규범](./푸시-및-릴리스-규범.md)의 인시던트 처리 절차에 따라 수행합니다.
