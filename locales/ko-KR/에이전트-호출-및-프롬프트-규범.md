# 에이전트 호출 및 프롬프트 규범

> 이 파일이 해결하는 문제：Agent가 규범 집합을 호출할 때의 위임 계약과 프롬프트 작성법을 정의하여, 호출이 검증 가능하고 권한을 넘지 않으며 흔들리지 않도록 보장합니다.

## 1. 호출 원칙

1. 단일 책임: 한 번의 호출은 한 가지 일만 완료하며, 「겸사겸사」 다른 작업을 하는 것은 금지합니다.
2. 읽기·쓰기 분리: 서브 에이전트는 읽기와 분석만 하며, 파일 쓰기와 git 작업은 주 컨트롤러가 일괄 수행한다([서브 에이전트 위임 계약](./서브-에이전트-위임-계약.md) 참고).
3. 근거 요구: 결론에는 근거(경로 + 행 번호 / 명령 출력)가 있어야 하며, 근거가 없으면 무효로 간주합니다.
4. 비통신: 서브 에이전트 간에는 직접 통신하지 않으며, 모두 주 컨트롤러를 거쳐 종합합니다.

## 2. 프롬프트 구조

호출 프롬프트에는 4요소가 포함되어야 한다:

```text
TASK:    <一句话任务>
INPUT:   <必要上下文，只给所需部分>
OUTPUT:  <结构化输出格式，表格或 JSON，禁止散文>
FAIL:    <无法完成时的返回约定，不得瞎编>
```

## 3. 프롬프트 작성법

1. 서면어와 명령문을 사용하고, 정보를 완전하게 담아 문맥 추측에 의존하지 않는다([범용 작성 규범](./범용-작성-규범.md) 참고).
2. 출력 형식과 실패 반환을 명확히 하여 모델이 임의로 해석하지 않도록 합니다.
3. 규범을 인용할 때는 파일 경로를 제시한다([기계 판독 메타데이터 규범](./기계-판독-메타데이터-규범.md) 참고).
4. 템플릿과 자리표시자는 형식을 통일한다([정보 수집 및 템플릿](./정보-수집-및-템플릿.md) 참고).

## 4. 강제 규칙

1. Agent에게 검사 결과를 꾸며내도록 요구해서는 안 되며, 검사할 수 없는 항목은 SKIP + 사유를 표기합니다.
2. 내부 사고 과정을 산출물에 작성해서는 안 된다([금지 사항](./금지-사항.md) 참고).
3. 보안 관련 내용은 [보안 및 개인정보 규범](./보안-및-개인정보-규범.md)에 따라 처리합니다.
