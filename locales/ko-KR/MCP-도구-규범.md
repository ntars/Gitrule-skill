# MCP 도구 규범

> 이 파일이 해결하는 문제：규범 집합을 모델 컨텍스트 프로토콜(MCP)을 통해 도구로 노출할 때의 인터페이스 설계와 설명 규칙을 정의하여, 도구가 모델에 의해 올바르게 발견되고 호출되도록 보장한다.

## 1. 도구 설계 원칙

1. 단일 책임: 하나의 도구는 한 가지 일을 하며, 만능형 인터페이스를 피한다.
2. 명확한 설명: 도구 설명에 용도와 적용 시나리오를 명시하여 모델이 언제 호출할지 판단하기 쉽게 한다.
3. 명확한 파라미터: 각 파라미터에는 타입, 필수 여부, 값 범위, 설명이 있다.
4. 구조화된 출력: 구조화된 데이터를 반환하고 장문의 산문을 피한다.

## 2. 필수 포함 필드

| 필드 | 요구사항 |
| --- | --- |
| name | 고유 식별자, 소문자 kebab-case |
| description | 용도와 트리거 조건, 구체적으로 판단 가능 |
| inputSchema | 파라미터 타입, 필수 항목, 제약 |
| 반환값 | 구조화 형식과 필드 설명 |
| 오류 | 실패 시 반환 형식, 결과를 꾸며내지 말 것 |

## 3. 규범 집합 관련 도구

1. 문서 검색류: 언어 코드 + 식별자로 규범 내용을 반환한다(식별자는 [기계 판독 메타데이터 규범](./기계-판독-메타데이터-규범.md) 참고).
2. 목록류: 사용 가능한 문서 목록과 그 언어 매핑을 반환한다.
3. 검증류: 문서 매트릭스 완전성([문서 매트릭스](./문서-매트릭스.md) 참고)과 품질 게이트 상태([품질 게이트](./품질-게이트.md) 참고)를 검사한다.

## 4. 강제 규칙

1. 도구는 검사할 수 없는 결과를 PASS로 반환해서는 안 되며, SKIP과 사유를 표기해야 한다([금지 사항](./금지-사항.md) 참고).
2. 출력은 프로그램이 파싱할 수 있어야 하며, 내부 사고 과정을 포함하지 않는다.
3. 보안 관련 내용을 도구를 통해 유출해서는 안 된다([보안 및 개인정보 규범](./보안-및-개인정보-규범.md) 참고).

## 관련 파일

- Skill 패키징은 [Skill 작성 규범](./Skill-작성-규범.md)을 참고한다
