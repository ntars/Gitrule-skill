# 기여 가이드 규범

> 이 파일이 해결하는 문제：외부 기여자가 프로젝트에 참여하는 전체 프로세스와 규범을 정의하여 CONTRIBUTING.md 작성의 근거로 삼는다.

## 1. 필수 내용

기여 가이드는 다음 부분을 포함해야 한다.

1. **참여 방식**: 이슈 논의, 문서 개선, 코드 기여, 문제 피드백 등의 채널.
2. **개발 환경 구성**: 의존성 설치, 환경 요구사항, 로컬 실행 명령.
3. **브랜치 모델**: 브랜치 명명 규칙, 어느 브랜치에서 분기하는지, 대상 브랜치.
4. **커밋 규범**: 커밋 메시지 형식([커밋 메시지 규범](./커밋-메시지-규범.md) 참조).
5. **PR 요건**: 변경 범위, 자체 테스트 항목, 설명 템플릿, 리뷰 기준.
6. **테스트 요건**: 통과해야 하는 테스트 명령과 커버리지 기준([테스트 규범](./테스트-규범.md) 참조).
7. **행동 강령**: CODE_OF_CONDUCT.md를 가리킨다([행동 강령 규범](./행동-강령-규범.md) 참조).
8. **이슈 규범**: 질문과 결함 보고의 작성 요건.
9. **라이선스 선언**: 기여 내용은 기본적으로 프로젝트 라이선스를 따른다([LICENSE 규범](./LICENSE-규범.md) 참조).

## 2. 작성 요건

1. 명령은 필요한 작업 디렉터리 설명을 포함하여 그대로 실행 가능해야 한다.
2. 각 프로세스 단계는 발동 조건과 예상 결과를 설명한다.
3. 「PR 환영합니다」만 쓰고 실질적인 프로세스를 쓰지 않아서는 안 된다([품질 게이트](./품질-게이트.md)의 커뮤니티 거버넌스 검사에 해당).

## 관련 파일

- 문서 책임 경계는 [문서 매트릭스](./문서-매트릭스.md) 참조
- PR 템플릿과 이슈 템플릿은 차원 D14에 속하며, [감사 차원 매트릭스](./감사-차원-매트릭스.md) 참조
- 브랜치와 커밋 규범은 [Git 워크플로 및 브랜치 규범](./Git-워크플로-및-브랜치-규범.md) 참조
