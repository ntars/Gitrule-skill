# 범용 작성 규범

> 이 파일이 해결하는 문제：모든 납품 문서의 문체, 정확성, 용어 일관성, 형식 세칙 및 금지 내용을 정의하여, 표현이 정밀하고 모호함이 없으며 재현 가능하도록 보장합니다.

## 1. 문체

1. 서면어를 사용하며, 서술문과 명령문을 사용합니다.
2. 구어체 표현을 사용해서는 안 됩니다. 예: 「咱们」「초간단」「끝냈다」「엄청 빠름」「원클릭 이륙」.
3. 느낌표, 줄임표, 인터넷 약어, 이모지를 사용해서는 안 됩니다.
4. 반문형, 설문형 문장을 섹션 서두로 사용해서는 안 됩니다.

## 2. 정확성

1. 모든 문장은 완전한 의미를 표현해야 하며, 문맥 추측에 의존해서는 안 됩니다.
2. 「그것」「이것」「관련」「일부」「약간」 등 모호한 지시 표현을 사용해서는 안 되며, 지시가 꼭 필요할 때는 완전한 명사를 사용합니다.
3. 시간, 버전 번호, 경로, 명령, 함수 이름, 설정 키 이름은 정확해야 하며 프로젝트의 실제 상황과 일치해야 합니다.
4. 명령은 바로 실행 가능해야 하며, 필요한 현재 작업 디렉터리 설명을 포함해야 합니다.
5. 버전 번호를 다룰 때는 버전 제약 의미를 명시해야 합니다. 예: `>=1.2.0 <2.0.0`.

## 3. 용어 일관성

1. 용어가 처음 등장할 때 정의를 제시하며, 형식은 「중국어 용어（English Term，약어）」입니다.
2. 동일한 개념은 문서 전체에서 하나의 표현만 사용하며, 중국어·영어 버전의 용어는 일대일로 대응합니다.
3. 중영 용어 대조표를 유지 관리해야 하며, README 부록 또는 독립 파일에 두고 이중 언어 버전이 동일한 대조표를 공유합니다(템플릿은 [정보 수집 및 템플릿](./정보-수집-및-템플릿.md) 참조).

## 4. 형식 규범

1. 제목 계층은 `##`에서 시작하며(`#`은 프로젝트 이름에 유보), 계층을 건너뛰어서는 안 됩니다.
2. 각 2단계 제목은 [README 섹션 규범](./README-섹션-규범.md)이 규정한 하나의 섹션에 대응하며, 순서를 조정해서는 안 됩니다.
3. 표에는 반드시 헤더가 있어야 하고 열 수가 일치해야 하며, 명령, 경로, 코드, 설정 키 이름은 인라인 코드로 표시합니다.
4. 코드 블록에는 언어 식별자를 표시해야 하며, 여러 줄 명령은 통째로 복사하여 실행할 수 있어야 합니다.
5. 외부 링크는 완전한 URL을 사용하고 단축 링크를 사용하지 않으며, 내부 이동은 상대 경로 앵커를 사용합니다.
6. 중국어와 영어, 숫자 사이에는 공백을 넣으며, 중국어와 영어 문장부호를 혼용하지 않습니다.

## 5. 자리표시자 약정

1. 복사 가능한 템플릿의 정식 자리표시자는 통일적으로 `{{纯名}}`으로 작성합니다. 예: `{{仓库地址}}`. 이름에는 「또는」「，」 등 다중 선택을 나타내는 연결어를 포함해서는 안 되며, 설명 문장으로 작성해서도 안 됩니다.
2. 정식 자리표시자는 소속 템플릿의 자리표시자 대조표에 등록해야 하며, 등록 항목에는 의미, 예시, 필수 여부가 포함됩니다.
3. 규범 예시 또는 작성 안내의 자연어 중괄호 내용은 예시일 뿐 정식 자리표시자에 속하지 않으며 대조표에 포함하지 않습니다. 최종 문서를 생성할 때는 전부 실제 내용으로 교체해야 합니다.
4. 중첩 중괄호, 백틱 또는 두 번째 자리표시자를 자리표시자 이름으로 사용해서는 안 됩니다.

## 6. 금지 목록

다음이 있어서는 안 됩니다. 검증되지 않은 성능 수치, 출처 없는 비교 결론, 약속성 표현(예: 「모든 환경에서의 호환 보장」「영구 무료」), 제3자 프로젝트에 대한 폄하성 서술, 프로젝트와 무관한 홍보 내용.
