# 기존 프로젝트 정합성 점검 체크리스트

> 이 파일이 해결하는 문제：본 규범 집합을 기존 프로젝트에 적용할 때 항목별로 확인할 수 있는 체크리스트, 판정 방법과 통과 기준을 제시하며, 메타데이터, 파일 명명, 섹션 구조, 이중 언어 동기화, 링크와 푸시의 여섯 단계를 다룹니다.

## 1. 적용 범위

본 체크리스트는 두 가지 상황에 사용합니다.

1. 기존 리포지터리를 처음으로 본 규범 집합의 관리 대상에 편입할 때;
2. 규범 집합 갱신 후 이미 정합성을 맞춘 리포지터리에 대해 회귀 점검을 수행할 때.

체크리스트는 「메타데이터 먼저, 구조 다음, 마지막으로 푸시」 순서로 실행합니다. 앞 그룹이 통과하지 않으면 다음 그룹으로 넘어가지 않으며, 잘못된 기반 위에서 일괄 수정하는 것을 피합니다.

## 2. 점검 항목

### 2.1 메타데이터([프로젝트 명명 규범](./프로젝트-명명-규범.md) 5절에 대응)

| 번호 | 점검 항목 | 판정 방법 | 통과 기준 |
| --- | --- | --- | --- |
| A1 | 리포지터리 이름 적합성 | 명명 공식과 문자 집합 규칙과 대조 | 전체 소문자, kebab-case, 2–25자, 버전 번호와 정보성 단어 없음 |
| A2 | 소개가 이중 언어 병합 형식인지 | 리포지터리 About 영역 또는 `gh repo view --json description` 읽기 | `국가 언어 \| 영어`, 세로줄 양쪽에 공백 하나씩 |
| A3 | 소개 길이 | 문자 수로 계산하되 중국어와 영어를 각각 계산 | 각각 120자 이내, 합계 350자 이내 |
| A4 | 토픽 수와 언어 | `gh repo view --json repositoryTopics` | 정확히 20개, 전부 영어, 전부 소문자, 하이픈으로 분절 |
| A5 | 토픽 커버리지 | 언어, 분야, 형태, 생태계, 시나리오 다섯 범주로 확인 | 다섯 범주를 모두 포괄하며, 기술 스택과 맞지 않는 토픽 없음 |

한도를 초과할 때의 처리 순서：먼저 영어 버전을 압축하고, 다음으로 중국어 버전을 압축합니다. 압축 시 먼저 수식어와 중복 한정어를 삭제하고, 그다음 동의 표현을 병합합니다.

### 2.2 파일 명명([다국어 규범](./다국어-규범.md)에 대응)

| 번호 | 점검 항목 | 판정 방법 | 통과 기준 |
| --- | --- | --- | --- |
| B1 | 기본 README 명명 | 디렉터리 목록 확인 | 중국어는 `README.md`, 영어는 `README_EN.md` |
| B2 | 그 밖의 언어 명명 | 디렉터리 목록 확인 | `README_<대문자 언어 코드>.md`, 예: `README_JA.md` |
| B3 | 명명 일관성 | 리포지터리 전체에서 구 명칭 검색 | `README.en.md`, `README.ja.md` 같은 구 명명이 남아 있지 않음 |
| B4 | 참조 동기화 | 구 파일명 검색 | 내비게이션 링크, 디렉터리 트리 예시, 스크립트 내 화이트리스트가 모두 갱신됨 |
| B5 | 전환 링크 | 각 언어 버전의 첫 줄 열기 | 모든 언어 버전에서 첫 줄로 나머지 전 언어로 전환 가능 |

파일 이름 변경은 반드시 `git mv`를 사용하여 파일 이력을 보존합니다. 리포지터리 내 스크립트(사전 검사, 패키징, 문서 검증)는 흔히 파일명 문자열을 화이트리스트로 사용하므로 동기화하여 수정해야 하며, 그렇지 않으면 푸시 후 검증이 실패합니다.

### 2.3 섹션 구조([README 섹션 규범](./README-섹션-규범.md)에 대응)

| 번호 | 점검 항목 | 판정 방법 | 통과 기준 |
| --- | --- | --- | --- |
| C1 | 섹션 구비 여부 | 2단계 제목을 추출하여 20개 장 목록과 대조 | 20개 장이 모두 존재하며 누락 없음 |
| C2 | 섹션 명명 | 제목 텍스트를 항목별로 대조 | 규범 용어와 일치하며, 「핵심 하이라이트」「설계 세부와 작은 디테일」 같은 변형을 쓰지 않음 |
| C3 | 섹션 순서 | 등장 순서대로 대조 | 규범 순서와 일치 |
| C4 | 확장 섹션 | 추가 섹션 존재 여부 확인 | 추가 내용은 「부록」 형태로 20개 장 뒤에 두고, 본문 순서에 삽입하지 않음 |
| C5 | 언어 버전 대응 | 중국어와 영어의 2단계 제목 수와 순서 대조 | 두 언어가 일대일로 대응 |

본문에 규범과 맞지 않는 섹션 명칭이 나타나면 규범 용어를 기준으로 통일합니다. 섹션에 기존 내용이 많이 포함된 경우 본문을 다시 쓰기보다 이름을 바꾸는 것을 우선합니다.

### 2.4 이중 언어 동기화([다국어 규범](./다국어-규범.md)에 대응)

| 번호 | 점검 항목 | 판정 방법 | 통과 기준 |
| --- | --- | --- | --- |
| D1 | 버전 번호 일치 | 버전 문자열 검색 | 두 언어가 같은 버전 번호와 상태를 기재 |
| D2 | 숫자 일치 | 기능 수, 테스트 수, 플랫폼 수 대조 | 동일 지표의 값이 두 버전에서 같음 |
| D3 | 링크 일치 | 상대 링크 집합 대조 | 두 버전이 같은 파일 집합을 가리킴 |
| D4 | 용어 일치 | 전문 용어 표본 확인 | 같은 개념이 두 버전에서 같은 역어로 사용됨 |
| D5 | 구조 일치 | 표와 목록 수 대조 | 섹션 내 표, 목록 수가 동일 |

어느 한 버전에서 사실성 내용을 수정하면 다른 버전도 같은 커밋에서 갱신해야 하며, 커밋을 넘겨 번역을 보충하는 것은 허용되지 않습니다.

### 2.5 링크와 내용([범용 작성 규범](./범용-작성-규범.md)에 대응)

| 번호 | 점검 항목 | 판정 방법 | 통과 기준 |
| --- | --- | --- | --- |
| E1 | 상대 링크 도달 가능성 | 하나씩 해석하고 파일 존재 여부 확인 | 끊어진 링크 수 0 |
| E2 | 코드 블록 언어 식별자 | 펜스 검색 | 모두 언어가 표기되었으며, 언어 없는 펜스 없음 |
| E3 | 표 열 수 | 표마다 구분 행과 데이터 행 대조 | 열 수 일치 |
| E4 | 금지 표현 | 구어체, 느낌표, 말줄임표, 이모지 검색 | 검출 없음. 원문을 인용할 때는 인용 부호 안에 두고 출처를 표기 |
| E5 | 미검증 데이터 | 성능 수치 검색 | 모든 수치에 테스트 환경과 테스트 방법이 있음 |
| E6 | 확약성 표현 | 「보장」「영구」「완전」 같은 단어 검색 | 기술적 한정어는 유지 가능하나, 대외 확약성 표현은 삭제 |

### 2.6 커뮤니티 파일과 푸시([문서 매트릭스](./문서-매트릭스.md), [푸시 및 릴리스 규범](./푸시-및-릴리스-규범.md)에 대응)

| 번호 | 점검 항목 | 판정 방법 | 통과 기준 |
| --- | --- | --- | --- |
| F1 | 필수 파일 구비 | 디렉터리 목록 확인 | `LICENSE`, `NOTICE`, `CONTRIBUTING.md`, `SECURITY.md` 구비 |
| F2 | 라이선스와 NOTICE 일치 | 계층 라우팅 표 대조 | 디렉터리 수준 라이선스와 NOTICE 선언이 일치 |
| F3 | 무시 규칙 | `.gitignore` 검색 | 빌드 산출물, 의존성 디렉터리, `.DS_Store`, `.workbuddy/`가 모두 무시됨 |
| F4 | 커밋 메시지 | `git log` 확인 | `<type>(<scope>): <subject>` 형식 준수 |
| F5 | 원격 일치 | 로컬 `HEAD`와 `origin/main` 대조 | 둘이 동일하고 작업 영역이 깨끗함 |

## 3. 다국어 리포지터리의 추가 점검

리포지터리에 세 가지 이상의 언어 버전이 있으면 위 점검 외에 세 가지를 추가합니다.

1. **섹션 제목의 언어별 확인**：각 언어의 20개 장 제목이 중국어 또는 영어 기준의 의미와 일치해야 하며, 어떤 언어에서도 장이 누락되어서는 안 됩니다.
2. **표 행 수 일치**：프로젝트 목록, 상태 표, 파라미터 표가 각 언어 버전에서 같은 행 수를 가져야 합니다.
3. **용어집 동기화**：용어 대조표는 이중 언어가 공용하는 독립 파일에 두고, 각 언어 버전이 같은 파일을 참조합니다.

## 4. 흔한 오류와 처리

| 오류 | 현상 | 처리 |
| --- | --- | --- |
| 섹션 번호를 일괄 변경할 때 중국어 숫자를 오판 | 「十、」이 「二十、」으로 인식되어 10장이 20장 제목으로 덮어써짐 | 명시적 「구 문자열 → 신 문자열」 일대일 치환으로 바꾸고, 항목별로 검출을 확인한 뒤 기록 |
| 링크 경로만 바꾸고 표시 텍스트는 바꾸지 않음 | 링크는 클릭되지만 본문에 여전히 구 섹션명이 표시됨 | 전문에서 구 섹션명을 검색하여 경로와 표시 텍스트를 동시에 갱신 |
| 파일 이름을 바꾸고 스크립트를 동기화하지 않음 | 로컬 문서는 정상이나 푸시 후 검증 스크립트가 오류 | 리포지터리 내 모든 파일명 문자열을 검색하며, 스크립트, 설정과 문서 예시를 포함 |
| 이중 언어 중 한쪽만 수정 | 두 버전의 사실이 불일치 | 리포지터리의 실제 상태를 기준으로 먼저 주 버전을 고치고, 같은 커밋에서 다른 버전을 수정 |
| 색인 페이지를 동기화하지 않음 | 새 파일이 색인에 없어 고립된 항목으로 판정됨 | 새 파일 추가 직후 색인 건수와 항목을 갱신하고, 영역별 건수 합계를 재확인 |
| 리포지터리 소개와 본문 기준 불일치 | About 영역에는 7개 프로젝트, 본문에는 9개로 기재 | 본문 목록을 기준으로 소개를 갱신하고 커밋 메시지에 명시 |

## 6. 필드 정의

| 필드 | 의미 | 값 |
| --- | --- | --- |
| 리포지터리 이름 | 점검 대상 리포지터리의 전체 이름 | `소유자/리포지터리` |
