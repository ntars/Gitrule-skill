# Skill作成規範

> このファイルが解決する問題：規範セットを Skill としてカプセル化する際の構造、トリガー条件、段階的な読み込み方法を定義し、Skill が発見可能で、保守可能で、内容が重複しないことを保証します。

## 1. ディレクトリ構造

Skill は「エントリーポイント + オンデマンドリソース」の構造を採用します：

```text
skill-name/
├── SKILL.md          必需：元数据 + 核心流程
├── references/       规范正文，按需加载
└── assets/           模板与素材（可选）
```

## 2. SKILL.md の要件

1. メタデータには `name` と `description` を含め、説明には「何をするか + いつ使うか」を明記し、トリガーしやすくします。
2. 本文には常駐する核心的なルールとフローのみを残し、詳細な参照表のような内容は `references/` に配置します。
3. 命令形・不定詞の書き方を採用し、二人称を避けます。
4. リソースを参照する場合は明確なパスと「いつ読み込むか」の条件を示します。

## 3. 強制ルール

1. 規範本文は一箇所でのみ保守します：Skill は本規範セットのファイルを参照し、全文をコピーせず、二重管理による逸脱を避けます。
2. 1 つの Skill は 1 つのことだけを行い、複数の責務を同じ Skill に詰め込むことは禁止です。
3. トリガー条件には具体的なフレーズを明記し、広すぎるトリガーを避けます。
4. バージョンは規範セットのバージョンに合わせて同期して更新します。
