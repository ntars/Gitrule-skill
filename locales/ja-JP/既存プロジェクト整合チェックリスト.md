# 既存プロジェクト整合チェックリスト

> このファイルが解決する問題：本規範セットを既存プロジェクトに適用する際に、項目ごとに照合できるチェックリスト、判定方法、合格基準を示し、メタデータ、ファイル命名、セクション構造、バイリンガル同期、リンクとプッシュの六つの環節を網羅する。

## 1. 適用範囲

本チェックリストは二種類の場面で使用します：

1. 既存リポジトリを初めて本規範セットの管理下に組み入れる場合；
2. 規範セットの更新後、整合済みのリポジトリに対して回帰確認を行う場合。

チェックリストは「まずメタデータ、次に構造、最後にプッシュ」の順で実行します。前のグループが通過していない場合は次のグループに進まず、誤った基盤の上で一括改写することを避けます。

## 2. チェック項目

### 2.1 メタデータ（[プロジェクト命名規範](./プロジェクト命名規範.md) 第 5 節に対応）

| 番号 | チェック項目 | 判定方法 | 合格基準 |
| --- | --- | --- | --- |
| A1 | リポジトリ名の準拠 | 命名公式と文字集合規則に照合 | すべて小文字、kebab-case、2–25 文字、バージョン番号と情報語を含まない |
| A2 | 概要がバイリンガル統合形式 | リポジトリの About 欄または `gh repo view --json description` を読む | `母語 \| 英語`、縦棒の両側にそれぞれ半角スペース一つ |
| A3 | 概要の長さ | 文字数で計数し、中国語と英語を別々に計数 | それぞれ 120 文字以内、合計 350 文字以内 |
| A4 | トピックの数と言語 | `gh repo view --json repositoryTopics` | ちょうど 20 個、すべて英語、すべて小文字、ハイフンで分かち書き |
| A5 | トピックの網羅性 | 言語、領域、形態、エコシステム、シナリオの五類で照合 | 五類すべてを網羅し、技術スタックと不整合なトピックがない |

上限を超えた場合の処理順序：まず英語版を圧縮し、次に中国語版を圧縮します。圧縮時はまず修飾語と重複した限定語を削り、次に同義の表現を統合します。

### 2.2 ファイル命名（[多言語規範](./多言語規範.md) に対応）

| 番号 | チェック項目 | 判定方法 | 合格基準 |
| --- | --- | --- | --- |
| B1 | 主 README の命名 | ディレクトリを列挙 | 中国語は `README.md`、英語は `README_EN.md` |
| B2 | その他言語の命名 | ディレクトリを列挙 | `README_<言語コード大文字>.md`、例 `README_JA.md` |
| B3 | 命名の一貫性 | リポジトリ全体で旧名を検索 | `README.en.md`、`README.ja.md` 一类の旧命名が残留していない |
| B4 | 参照の同期 | 旧ファイル名を検索 | ナビゲーションリンク、ディレクトリツリーの例、スクリプト内のホワイトリストがすべて更新済みである |
| B5 | 切り替えリンク | 各言語版の先頭行を開く | 各言語版のいずれも先頭行で残りすべての言語に切り替えられる |

ファイルのリネームには必ず `git mv` を使用し、ファイル履歴を保持しなければなりません。リポジトリ内のスクリプト（事前チェック、パッケージング、ドキュメント検証）はファイル名の文字列をホワイトリストとして使うことが多く、同期して修正しなければならず、そうでなければプッシュ後の検証が失敗します。

### 2.3 セクション構造（[READMEセクション規範](./READMEセクション規範.md) に対応）

| 番号 | チェック項目 | 判定方法 | 合格基準 |
| --- | --- | --- | --- |
| C1 | セクションの網羅 | 二級見出しを抽出し 20 章の一覧と照合 | 20 章すべてが存在し、欠章がない |
| C2 | セクションの命名 | 見出し文字列を逐条照合 | 規範の用語と一致し、「核心ハイライト」「設計詳細と小さな工夫」などの変種を使用していない |
| C3 | セクションの順序 | 出現順に照合 | 規範の順序と一致している |
| C4 | 拡張セクション | 追加のセクションの有無を確認 | 追加内容は「付録」の形式で 20 章の後に置き、本文の順序に挿入していない |
| C5 | 言語版の対応 | 中英の二級見出しの数と順序を照合 | 二言語が一対一で対応している |

本文に規範と異なるセクション名が現れた場合、規範の用語を正として統一します。セクション内に既存の内容が大量にある場合は、本文を書き直すのではなく改名を優先します。

### 2.4 バイリンガル同期（[多言語規範](./多言語規範.md) に対応）

| 番号 | チェック項目 | 判定方法 | 合格基準 |
| --- | --- | --- | --- |
| D1 | バージョン番号の一致 | バージョン文字列を検索 | 二言語が同じバージョン番号と状態を記載している |
| D2 | 数値の一致 | 機能数、テスト数、プラットフォーム数を照合 | 同一指標が二版で同じ値である |
| D3 | リンクの一致 | 相対リンクの集合を照合 | 二版が同一のファイル群を指している |
| D4 | 用語の一致 | 専門用語を抜き取り確認 | 同一概念が二版で同一の訳語を使用している |
| D5 | 構造の一致 | 表とリストの数を照合 | セクション内の表、リストの数が同じである |

いずれかの版が事実的内容を修正した後、もう一方の版は同一コミット内で更新しなければならず、コミットをまたいだ後追い翻訳は認められません。

### 2.5 リンクと内容（[汎用ライティング規範](./汎用ライティング規範.md) に対応）

| 番号 | チェック項目 | 判定方法 | 合格基準 |
| --- | --- | --- | --- |
| E1 | 相対リンクの到達性 | 一つずつ解決しファイルの存在を確認 | リンク切れ数が 0 |
| E2 | コードブロックの言語識別子 | フェンスを検索 | すべて言語を明記し、言語指定のないフェンスがない |
| E3 | 表の列数 | 表ごとに区切り行とデータ行を照合 | 列数が一致している |
| E4 | 禁止表現 | 口語語、感嘆符、省略記号、絵文字を検索 | ヒットなし。原文を引用する場合は引用符内に置き出典を明記する |
| E5 | 未検証のデータ | 性能数値を検索 | すべての数値にテスト環境とテスト方法がある |
| E6 | 約束的表現 | 「保証」「永久」「完全」一类の語を検索 | 技術的限定語は残してよいが、対外的な約束的表現は削除する |

### 2.6 コミュニティファイルとプッシュ（[ドキュメントマトリクス](./ドキュメントマトリクス.md)、[プッシュとリリース規範](./プッシュとリリース規範.md) に対応）

| 番号 | チェック項目 | 判定方法 | 合格基準 |
| --- | --- | --- | --- |
| F1 | 必須ファイルの網羅 | ディレクトリを列挙 | `LICENSE`、`NOTICE`、`CONTRIBUTING.md`、`SECURITY.md` が揃っている |
| F2 | ライセンスと NOTICE の一致 | 階層ルーティング表を照合 | ディレクトリ単位のライセンスと NOTICE の宣言が一致している |
| F3 | 除外規則 | `.gitignore` を検索 | ビルド成果物、依存ディレクトリ、`.DS_Store`、`.workbuddy/` がすべて除外されている |
| F4 | コミットメッセージ | `git log` を確認 | `<type>(<scope>): <subject>` に適合している |
| F5 | リモートの一致 | ローカルの `HEAD` と `origin/main` を照合 | 両者が同一で、作業ツリーがクリーンである |

## 3. 多言語リポジトリの追加チェック

リポジトリに三言語以上の版が存在する場合、上記のチェックに加えて三項目を追加します：

1. **セクション見出しの言語別確認**：各言語の 20 章の見出しがすべてその中国語または英語の基準と意味が一致しなければならず、いずれかの言語で欠章があってはなりません；
2. **表の行数の一致**：プロジェクト一覧、状態表、パラメータ表が各言語版で同じ行数であること；
3. **用語集の同期**：用語対照表をバイリンガル共用の独立ファイルに置き、各言語版が同一のものを参照すること。

## 4. よくある誤りと対処

| 誤り | 現象 | 対処 |
| --- | --- | --- |
| セクション番号の一括変更で漢数字を誤判定 | 「十、」が「二十、」と認識され、第 10 章が第 20 章の見出しで上書きされる | 明示的な「旧文字列 → 新文字列」の一対一置換に変更し、逐条ヒットをアサートしてから書き込む |
| リンクのパスのみ変更し表示文字を変更しない | リンクはクリックできるが、本文は旧セクション名のまま | 全文で旧セクション名を検索し、パスと表示文字を同時に更新する |
| ファイルのリネームをスクリプトに同期しない | ローカルのドキュメントは正常だが、プッシュ後に検証スクリプトがエラーを出す | リポジトリ内のすべてのファイル名文字列を検索する。スクリプト、設定、ドキュメントの例を含む |
| バイリンガルの片側のみ変更 | 二版の事実が不整合になる | リポジトリの実際の状態を正とし、まず主版を修正し、同一コミットで他方の版を修正する |
| 索引ページを同期しない | 新規ファイルが索引に含まれず、孤立として判定される | 新規ファイルの追加後すぐに索引の件数と項目を更新し、ドメイン別件数の合計を再確認する |
| リポジトリ概要と本文の記述が不整合 | About 欄には七つのプロジェクト、本文には九つと書かれている | 本文の一覧を正として概要を更新し、コミットメッセージに明記する |

## 6. フィールド定義

| フィールド | 意味 | 値 |
| --- | --- | --- |
| リポジトリ名 | チェック対象リポジトリの完全名 | `所有者/リポジトリ` |
| 規範バージョン | 本チェックの根拠となる規範セットの状態 | コミット番号またはバージョン番号 |
| 通過 | 当該項目が合格基準に適合している | ブール値 |
| リリース判定 | チェック結果の対処 | 通過 / 条件付き通過 / ブロック |
