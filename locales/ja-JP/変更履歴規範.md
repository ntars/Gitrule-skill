# 変更履歴規範

> このファイルが解決する問題：利用者向けのバージョン変更記録のテンプレート、項目、書き方を定義し、各変更が追跡可能で、バージョンが対応し、アップグレード経路を判断できることを保証する。

## 1. 規範条文

1. 変更履歴は Keep a Changelog の構造に従い、バージョン番号は [バージョン管理規範](./バージョン管理規範.md) のセマンティックバージョニングに従う。
2. 各バージョンには公開日を要し、形式は `YYYY-MM-DD` とする。未リリースの内容は `Unreleased` のセクションに置く。
3. 項目は 6 種類に分類する：`Added` 追加 / `Changed` 変更 / `Deprecated` 非推奨 / `Removed` 削除 / `Fixed` 修正 / `Security` セキュリティ。
4. 各変更は利用者に向けたもので、影響と移行方法を説明しなければならず、内部リファクタリングの詳細は書かない。
5. 破壊的変更は `BREAKING CHANGE:` と注記し、移行手順を示さなければならない（[移行ガイド規範](./移行ガイド規範.md) を参照）。
6. バージョン番号は tag、Release Notes と一致しなければならない。破壊的変更はコミットメッセージの `feat!:` または `BREAKING CHANGE:` に対応しなければならない。

## 2. 変更履歴テンプレート

```markdown
# 変更履歴

本ファイルは利用者に向けたすべての変更を記録する。形式は Keep a Changelog に基づき、バージョンはセマンティックバージョニングに従う。

## [Unreleased]

### Added
- {{新增能力，说明对使用者的价值}}

### Changed
- {{行为变更，说明影响范围}}

### Deprecated
- {{即将移除的能力，说明替代方案与移除版本}}

### Removed
- {{已移除的能力，说明迁移路径}}

### Fixed
- {{缺陷修复，说明触发条件}}

### Security
- {{安全修复，说明影响与升级建议}}

## [{{X.Y.Z}}] - {{YYYY-MM-DD}}

### {{类型}}
- {{变更条目}}
- {{BREAKING CHANGE: 原行为 → 新行为；迁移步骤见链接}}

[Unreleased]: https://github.com/{{owner}}/{{repo}}/compare/v{{X.Y.Z}}...HEAD
[{{X.Y.Z}}]: https://github.com/{{owner}}/{{repo}}/compare/v{{prev}}...v{{X.Y.Z}}
```

## 3. エントリテンプレート

```markdown
- {{动词开头的一句话变更描述}}（{{关联 REQ 编号}}）
  - 影響：{{哪些使用者或场景受影响}}
  - 移行：{{需要执行的动作；无则省略此行}}
  - 参考：{{Issue / PR 链接}}
```

## 4. 項目定義

| 項目 | 必須 | 型 | 記入要点 | 例 |
| --- | --- | --- | --- | --- |
| バージョン番号 | はい | `X.Y.Z` | tag と完全に一致させる。接頭辞 `v` を付けなくてもよいが、全文で統一する | `1.2.0` |
| 公開日 | はい | `YYYY-MM-DD` | tag を打った日付を基準とする | `2026-11-18` |
| 区分の種類 | はい | 列挙 | 6 種類のいずれか。該当項目がない場合はセクションごと省略する | `Fixed` |
| 変更の説明 | はい | テキスト | 動詞で始め、利用者に向けて価値を説明する | `GFM テーブルのチェックを追加` |
| 影響 | 条件付き必須 | テキスト | 振る舞いの変更、非推奨、削除、破壊的変更の場合は必須 | `旧設定ファイルのリネームが必要` |
| 移行 | 条件付き必須 | テキスト | 破壊的変更では必須。移行ガイドを指す | `移行ガイド v1.0 を参照` |
| BREAKING CHANGE | 条件付き必須 | 注記 | 破壊的変更では必須。項目の先頭に置く | `BREAKING CHANGE:` |
| 比較リンク | はい | URL | 各バージョンセクションに compare リンクを必ず用意する | `compare/v1.1.0...v1.2.0` |
| 関連 REQ | いいえ | リスト | 要求トレーサビリティマトリクスとの照合を容易にする | `REQ-007` |

## 5. 記入説明

1. **項目の粒度**：1 つの変更は利用者が認識できる 1 つの結果を説明する。複数の結果は複数の項目に分ける。
2. **動詞で始める**：「追加」「対応」「修正」「削除」「非推奨」「調整」を使い、「更新した」「いくつか対応した」は使わない。
3. **禁止する内容**：日付のない項目、内部リファクタリング、開発計画、ロードマップの内容、曖昧な表現（「体験を最適化」「いくつかの問題を修正」）。
4. **破壊的変更**：`BREAKING CHANGE:` の注記、影響の説明、移行手順、移行ガイドへのリンクの 4 つをすべて備えなければならず、1 つも欠けてはならない。
5. **非推奨項目**：代替案と削除予定のバージョン番号を明記しなければならない。例えば「v2.0 で削除予定」。
6. **Unreleased**：マージ後直ちに登録し、リリース当日にまとめて書き足す形で溜めてはならない。
7. **一貫性**：バージョン番号と公開日は tag、Release Notes、デプロイ記録の 3 か所で一致しなければならない。一致しない場合は tag を基準とし、残りの 3 か所を修正する。

よくある誤り：

| 誤った書き方 | 問題 | 修正方法 |
| --- | --- | --- |
| 「内部モジュールの構造をリファクタリング」 | 内部の詳細であり利用者に伝わらない | 削除するか、認識できる効果として書き換える |
| 「いくつかの問題を修正」 | 判定不能 | 修正内容を項目ごとに列挙する |
| 破壊的変更で「変更あり」とだけ書く | 移行経路がない | 影響、移行手順、ガイドへのリンクを補う |
| バージョン番号が tag と一致しない | バージョンの対応関係が崩れる | tag を基準に統一する |
| compare リンクがない | 差分を確認できない | GitHub の compare URL を補う |

## 6. 完全な例

```markdown
## [1.0.0] - 2026-11-20

### Added
- 中国語と英語の混在時のスペースチェック規則を追加（REQ-001）。コマンドラインから直接呼び出せる。
- JSON レポート出力を追加し、CI への統計連携を容易にした。

### Changed
- BREAKING CHANGE: 設定ファイル名を `.mdlint.json` から `.mdlintrc.json` に変更。旧ファイルは読み込まれなくなる。移行手順は[移行ガイド](./移行ガイド規範.md)を参照。

### Deprecated
- `--format=table` パラメータは v2.0 で削除する。`--reporter=table` に切り替えてほしい。

### Fixed
- 中国語の句読点が英語の単語に隣接する場合の誤検出を修正。

### Security
- ルールプラグインの読み込みパスが外部入力で上書きされうる問題を修正。すべての利用者に v1.0.0 へのアップグレードを推奨する。

[1.0.0]: https://github.com/example/markdown-lint-cli/compare/v0.9.3...v1.0.0
```
