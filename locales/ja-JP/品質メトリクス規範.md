# 品質メトリクス規範

> このファイルが解決する問題：追跡可能な品質指標とその定義を定め、根拠のない数値でプロジェクトの品質を評価することを避ける。

## 1. 指標の原則

1. 指標は測定可能かつ再現可能でなければならず、収集方法と統計の定義を明記する。
2. 指標は改善のために用い、単純な順位付けや圧力の創出には用いない。
3. 各指標には目標値と現在値を示し、定期的に振り返らなければならない。

## 2. 推奨指標

| カテゴリ | 指標 | 定義の説明 |
| --- | --- | --- |
| テスト | テストカバレッジ | テスト対象コードの行の割合。統計ツールを明記する |
| テスト | テスト通過率 | 通過したテストケース数 / 全テストケース数 |
| ビルド | ビルド成功率 | 成功したビルド回数 / 総ビルド回数 |
| 不具合 | 不具合密度 | 単位規模のコードで検出された不具合数 |
| 不具合 | 平均修復時間 | 検出から修復完了までの平均所要時間 |
| 性能 | 応答時間 | シナリオと分位値（P95 など）を明示する |
| 依存関係 | 高リスク脆弱性数 | 未修復の高リスクな依存関係の脆弱性の件数 |

## 3. 強制ルール

1. 性能指標にはテスト環境と方法を明記しなければならず、条件のない数値は禁止する（[汎用ライティング規範](./汎用ライティング規範.md) に対応）。
2. 指標データの収集は自動化しなければならず、手作業による統計の偏りを減らす。
3. 指標の異常にはフォローアップの記録が必要で、[ロードマップ規範](./ロードマップ規範.md) または課題管理に組み込む。
