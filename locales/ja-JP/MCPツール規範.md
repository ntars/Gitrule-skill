# MCPツール規範

> このファイルが解決する問題：規範集をモデルコンテキストプロトコル（MCP）を通じてツールとして公開する際のインターフェース設計と記述ルールを定義し、ツールがモデルから正しく発見・呼び出しされることを保証する。

## 1. ツール設計の原則

1. 単一責務：一つのツールは一つのことを行い、何でも揃った巨大なインターフェースを避ける。
2. 明確な記述：ツールの記述で用途と適用場面を説明し、モデルがいつ呼び出すかを判断しやすくする。
3. 明確なパラメータ：各パラメータに型、必須かどうか、値の範囲、説明を持たせる。
4. 構造化された出力：構造化データを返し、長い散文を避ける。

## 2. 必須フィールド

| フィールド | 要件 |
| --- | --- |
| name | 一意の識別子。小文字の kebab-case |
| description | 用途とトリガー条件。具体的で判断可能なもの |
| inputSchema | パラメータの型、必須項目、制約 |
| 戻り値 | 構造化された形式とフィールドの説明 |
| エラー | 失敗時の戻り形式。結果を捏造してはならない |

## 3. 規範集に関連するツール

1. ドキュメント検索系：言語コード + 識別子で規範の内容を返す（識別子は [機械可読メタデータ規範](./機械可読メタデータ規範.md) を参照）。
2. マニフェスト系：利用可能なドキュメントの一覧と言語マッピングを返す。
3. 検証系：ドキュメントマトリクスの完全性（[ドキュメントマトリクス](./ドキュメントマトリクス.md) を参照）とゲートの状態（[品質ゲート](./品質ゲート.md) を参照）を検査する。

## 4. 強制ルール

1. ツールは検査できない結果を PASS として返してはならない。SKIP と理由を注記すること（[禁止事項](./禁止事項.md) を参照）。
2. 出力はプログラムから解析可能でなければならず、内部の思考過程を含めてはならない。
3. セキュリティに関わる内容をツール経由で漏洩させてはならない（[セキュリティとプライバシー規範](./セキュリティとプライバシー規範.md) を参照）。
