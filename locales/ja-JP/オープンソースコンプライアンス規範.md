# オープンソースコンプライアンス規範

> このファイルが解決する問題：オープンソースコンプライアンスの収集範囲、依存関係マニフェストのフィールド、収集方法、ライセンス互換性の判断、改変の注記、素材引用のルールを定義し、宣言が完全で検証可能であることを保証する。

## 1. 収集範囲

四類の出所を網羅すること：直接依存、間接・推移的依存、ビルドと開発のツールチェーン、素材リソース（アイコン、フォント、画像、音声、データセット、アルゴリズムの出所）。

## 2. 依存関係マニフェストのフィールド

| フィールド | 要件 |
| --- | --- |
| コンポーネント名 | 公式リポジトリと一致させる |
| バージョン | 実際にロックされたバージョン。範囲式ではない |
| 参照方式 | 直接依存または間接依存 |
| 著作権者 | 公式に宣言された著作権者の正式名称 |
| ライセンス | SPDX 識別子。複数ライセンスの場合は組み合わせ方を明記する |
| 公式アドレス | リポジトリまたはホームページの完全な URL |
| 本プロジェクトでの用途 | 具体的な呼び出し箇所または機能 |
| 改変の有無 | はい または いいえ |
| 改変の説明 | 改変ファイル、改変内容、改変理由。未改変の場合は「なし」と記入 |
| ライセンス原文の位置 | プロジェクト内のパスまたはファイルへのリンク |

依存関係マニフェストの表テンプレートは [情報収集とテンプレート](./情報収集とテンプレート.md) を参照。

## 3. 収集方法

技術スタックに応じたコマンドで依存ツリーを生成し、項目ごとにライセンスと著作権情報を補完する：`npm ls --all`、`pip freeze`、`go mod graph`、`cargo tree`、`mvn dependency:tree`、`gradle dependencies`、`composer show --tree`。ライセンスのスキャンには `license-checker`、`pip-licenses`、`cargo-license` などのツールを用いてよいが、スキャン結果は人手で再確認すること。ツールの出力をそのまま最終結論としてはならない。

## 4. ライセンスの互換性

1. プロジェクトのライセンスと各依存関係のライセンスの互換性を判断すること。GPL、AGPL、LGPL、MPL の伝染範囲を重点的に確認する。
2. Apache-2.0 の依存関係は、その NOTICE ファイルの要件が満たされているかを確認すること。
3. 素材系のライセンス（SIL OFL フォント、CC シリーズなど）は、署名と伝播の要件を個別に確認すること。
4. 互換性を判断できない場合は「【要確認：ライセンス互換性】」と注記し、疑義の理由を説明すること。
5. プロジェクトが階層ライセンスを採用する場合は層ごとに判断すること。ある依存関係がどの層に使われるかによって、その層のライセンスで互換性を判定し、主ライセンスでリポジトリ全体を代表させてはならない。階層の配置と確認フローは [LICENSE規範](./LICENSE規範.md) を参照。
6. 同一の依存関係が複数のライセンス層にまたがる場合は、その依存関係の実際の使用範囲を注記し、最も厳格な適用層で判定すること。

## 5. 他者のコードを改変した場合の注記

1. ファイルの先頭に元の著作権表示とライセンス表示を保持する。
2. NOTICE に改変ファイルのパス、改変内容の要約、改変日を明記する。
3. README の該当セクションにも同期して説明する。

## 6. 引用と素材

1. 他者のドキュメントやコード断片を引用する場合は、出所のアドレス、作者、ライセンスを明記すること。
2. 画像、アイコン、フォントは出所とライセンスを記録すること。欠落している場合は要確認と注記し、そのまま使用してはならない。
3. 出所の不明な素材を使用してはならない。
