# READMEテンプレート調査報告

> このファイルが解決する問題：今回の標準 README テンプレートの調査方法、サンプル規模、定量的な発見を記録し、[README標準テンプレート](./README標準テンプレート.md) および各専門規範にデータの根拠を提供するとともに、方法の境界と限界を明示する。

## 1. 調査目標と方法

### 1.1 目標

star 数が上位のトップオープンソースプロジェクトを調査し、その README および関連ドキュメントの構造、セクション構成、視覚的表現、バッジの使用傾向を帰納して、再利用可能な汎用規範とテンプレートを形成する。

### 1.2 データソース

- リポジトリメタデータ：GitHub GraphQL Search API。star 降順で、`is:public archived:false fork:false` で絞り込む。
- README 原文：GitHub REST Contents API（`readme` エンドポイント）。base64 または raw 形式で取得してから解析する。
- バッジパラメータ：Shields.io 公式ドキュメント（Static Badge、Logos ページ）と badge-maker の形式説明。
- 中国語コミュニティの実践：phodal/github（『GitHub 漫遊指南』、11,362 star）のプロジェクトドキュメント、コミットメッセージ、普及の章。機械的な統計では捉えられない執筆原則と運営経験を補うために用いる。

### 1.3 収集方法

1. **メタデータ**：GitHub Search API の単一クエリは最大 1000 件を返す。サンプルを広げるため、star 区間の分割を採用した。二分法で 1000 件ごとに対応する star しきい値を特定し、逐次下方へずらして計 11 バッチ、最終的に 10,995 件のトップリポジトリのメタデータを取得した。
2. **README サンプリング**：トップ 1000 リポジトリ内で主要言語による層化抽出を行い、Python、TypeScript、JavaScript、Rust、Go、C++ などの主要言語を網羅し、120 リポジトリを抽出、すべて README 原文の取得に成功した。
3. **統計の定義**：リポジトリ単位でセクションの出現率と要素の使用率を統計する。バッジのスタイル、logo パラメータは URL 中の出現回数で統計する。

### 1.4 方法の限界（明示すること）

- GitHub Search API は単一クエリに 1000 件の上限がある。本報告は分割により規模を累積的に拡張したが、分割境界は star の同値の影響を受け、サンプルは近似的なトップ集合であり、厳密に連続したランキングではない。
- README のサンプリング規模は 120 であり、結論は傾向と共通性を示すもので、全トッププロジェクトの統計的に有意な分布を表すものではない。
- セクションの識別は見出しのキーワード一致に基づくため、表現の差異による統計上の偏りが存在する。
- バッジパラメータの統計は URL に明示的に現れたパラメータを対象とし、動的バッジの既定パラメータは計上していない。

## 2. トップリポジトリの分布（メタデータ）

### 2.1 サンプル規模

- 単一クエリでトップ 1000 リポジトリを安定して取得でき、star 区間は約 563,574 から 30,857。
- 11 バッチの分割を累積し、10,995 のトップリポジトリまで拡張し、star の下限は 5,452。

### 2.2 言語分布（トップ 1000 に基づく）

| 言語 | 件数 | 割合 |
| --- | --- | --- |
| Python | 223 | 22.3% |
| TypeScript | 178 | 17.8% |
| JavaScript | 112 | 11.2% |
| Rust | 80 | 8.0% |
| 主要言語なし | 74 | 7.4% |
| Go | 68 | 6.8% |
| C++ | 55 | 5.5% |
| Java | 27 | 2.7% |

トッププロジェクトは Python、TypeScript、JavaScript が中心で、三者合計で 50% を超える。Rust、Go などのシステム言語も無視できない割合を占める。このことから、テンプレートは多言語のパッケージマネージャによるインストールコマンドと複数ランタイムのバッジを網羅する必要がある。

### 2.3 ライセンス分布（トップ 1000 に基づく）

| ライセンス | 件数 | 割合 |
| --- | --- | --- |
| MIT | 399 | 39.9% |
| Apache-2.0 | 197 | 19.7% |
| 未識別（NOASSERTION） | 148 | 14.8% |
| ライセンスなし（NONE） | 65 | 6.5% |
| GPL-3.0 | 51 | 5.1% |
| AGPL-3.0 | 50 | 5.0% |

MIT が支配的で、汎用テンプレートの既定の推奨である。同時に Apache-2.0、GPL などの選択肢の SPDX 表記プレースホルダーを残す必要がある。

発見：コントリビューションガイドとライセンスはトッププロジェクトの標準装備であり、コミュニティガバナンスとコンプライアンスの優先度を反映している。インストールとクイックスタートがこれに続く。テンプレートはこの二者を必須項目としている。

### 3.2 視覚要素の使用率

| 要素 | 出現リポジトリ数 | 出現率 | 中央値（1 リポジトリあたり） |

| コードブロック | 80 | 66.7% | 2 |
| 画像 | 76 | 63.3% | 2 |
| バッジ（Shields.io） | 61 | 50.8% | 1 |
| 表 | 44 | 36.7% | 0 |

見出し階層の中央値：2 級見出し 7 個、ファイル長の中央値 171 行。このことから、トップ README は一般に中程度の長さに抑えられ、6〜12 個の 2 級見出しで構成されていることが分かる。

### 3.3 テーマ適応（先頭 40 サンプル）

| 特徴 | 出現リポジトリ数 |
| --- | --- |
| 中央寄せコンテナ（`align="center"`） | 27 |
| `<picture>` 要素 | 12 |
| 明暗テーマ切り替え（`prefers-color-scheme`） | 12 |
| `for-the-badge` と `labelColor` の組み合わせ | 2 |

中央寄せコンテナは主流のトップページ手法である。約三割のプロジェクトが明暗テーマの二バージョン画像を提供している。

| プロジェクト | 類型 | トップページの特徴 |
| --- | --- | --- |
| `sindresorhus/awesome` | リソース集 | 中央寄せロゴ、スポンサー枠、テーマ別カテゴリ目次 |

| `vercel/next.js` | フレームワーク | 中央寄せロゴ、`for-the-badge` バッジ、ドキュメントとコミュニティの入り口 |

共通点：ファーストビューで「何か、どう使うか、詳細はどこか」に答える。バッジは見出しに密着させる。スクリーンショットや Demo は位置づけの直後に置く。コントリビューションとコミュニティの入り口は下方に置くが必須である。

## 6. 帰納した結論

1. 汎用テンプレートは「位置づけ → インストール → クイックスタート → ドキュメント → コントリビューション → ライセンス」を主幹とすること。
2. バッジは既定で `flat-square` または `for-the-badge` とし、全編で統一し、数は 4〜6 枚とする。
3. 画像とコードブロックは訴求力の高いトップページの中核であり、`alt` と言語注記を添えること。
4. プロジェクトの類型がセクションの取捨を決める。[README分類適応ガイド](./README分類適応ガイド.md) を参照。
5. コンプライアンスとコミュニティガバナンス（ライセンス、コントリビューションガイド）はトッププロジェクトの共通認識であり、必須項目とする。

## 7. データ規模の説明

トップリポジトリのメタデータの分割累積結果：10,995 リポジトリ、star 区間は 563,575 から 5,452。この一万規模のサンプルのライセンスと言語の分布は以下のとおりで、トップ 1000 サンプルの結論と一致する。

| 次元 | 分布 |
| --- | --- |
| 言語 | Python 1,995、TypeScript 1,529、JavaScript 1,279、主要言語なし 888、Go 847、C++ 531、Java 528、Rust 507 |
| ライセンス | MIT 4,160（37.8%）、Apache-2.0 2,073（18.9%）、未識別 1,463、ライセンスなし 1,106、GPL-3.0 747 |

README の詳細統計サンプルは 120 件で、すべて取得に成功した。分割は近似的な star しきい値を用いており、規模はトップ集合の近似であり、厳密に連続したランキングではない。
