# API設計規範

> このファイルが解決する問題：インターフェース設計の一貫性原則と約束を定義し、API が使いやすく、予測可能で、進化可能であることを保証する。

## 1. 設計原則

1. 命名の一貫性：同類のリソースと操作には統一した命名規則を用いる。
2. 予測可能性：同じ意味の操作は同じ構造を持つ。
3. 明示は暗黙に優る：既定値、必須項目、エラー時の挙動を明確にすること。
4. 後方互換性：変更は互換性の維持を優先し、破壊的変更はバージョン化すること（[バージョン管理規範](./バージョン管理規範.md) を参照）。

## 2. 必須の約束

1. **命名**：リソース、メソッド、フィールドの命名規則。
2. **パラメータ**：型、必須、既定値、値の範囲。
3. **エラー**：統一したエラー構造、エラーコード、HTTP ステータスまたは同等の仕組み。
4. **ページングとフィルタリング**：大量データの場面におけるページング、並び替え、フィルタリングの約束。
5. **冪等性**：書き込み操作の冪等保証。
6. **レート制限とクォータ**：頻度制限と超過時の応答。
7. **バージョン**：API のバージョン戦略と進化の方式。

## 3. 強制ルール

1. エラー応答には特定可能なエラーコードと説明を含め、内部実装の詳細を露出してはならない。
2. 破壊的変更はバージョンを上げ、移行期間を設けること（[変更履歴規範](./変更履歴規範.md) を参照）。
3. インターフェースには対応するドキュメントがあり、フィールドが完全であること（[APIドキュメント規範](./APIドキュメント規範.md) を参照）。
