# トラブルシューティング規範

> このファイルが解決する問題：トラブルシューティング文書（Troubleshooting / FAQ）の構造、項目の書き方、保守の仕組みを定義し、利用者が現象から原因を特定し、よくある問題を自ら解決できるようにする。

## 1. 適用場面

以下の場合はトラブルシューティング文書を提供しなければならない：

1. インストールまたはビルドの失敗に複数のよくある原因がある。
2. 設定項目どうしが衝突し、エラーメッセージだけでは解決方法を説明できない。
3. 特定のプラットフォームまたはバージョンに既知の制限がある。
4. ユーザーが同種の質問を繰り返し、回答を標準化できる。

## 2. ファイルの位置と命名

1. 内容が少ない場合は README の一セクションとし、見出しを「よくある質問」または「トラブルシューティング」とする。
2. 内容が多い場合は、`docs/troubleshooting.md` または `FAQ.md` を別途作成し、README には入口のリンクを残す。
3. 問題はテーマごとにグループ化する（例：「インストール」「設定」「実行」「性能」「ネットワーク」）。

## 3. ドキュメントの構造

1. **冒頭の説明**：本文書が扱うよくある問題の範囲と対象バージョン。
2. **問題の索引**：テーマごとに問題の見出しを列挙し、素早く移動できるようにする。
3. **問題の項目**：統一した構造で一件ずつ展開する。
4. **それでも解決しない場合**：issue、ディスカッションなどの相談窓口を案内する。

## 4. 項目の構造

各問題の項目は以下の部分を含まなければならない：

| 部分 | 内容 | 要件 |
| --- | --- | --- |
| 現象 | ユーザーが見る具体的な現れ方 | 完全なエラーメッセージを含める。「エラーが出る」とだけ書いてはならない |
| 発生条件 | いつ発生するか | バージョン、プラットフォーム、操作を明示する |
| 原因 | 根本原因 | 仕組みを説明する。結論だけを示さない |
| 解決方法 | 実行可能な手順 | 番号付きで列挙し、コマンドまたは設定を含める |
| 検証 | 修正されたことをどう確認するか | 期待される出力を示す |
| 関連 | 関連ドキュメントまたは issue へのリンク | 任意 |

## 5. 項目の書き方の例

```markdown
### インストール時に `EACCES: permission denied` が表示される

**現象**：`npm install -g <package>` を実行すると権限不足が表示される。

**発生条件**：Linux または macOS で一般ユーザーとしてグローバルパッケージをインストールする場合。

**原因**：グローバルインストールディレクトリの書き込み権限がシステム管理者に属しており、現在のユーザーには書き込む権限がない。

**解決方法**：

```bash
mkdir -p ~/.npm-global
npm config set prefix '~/.npm-global'
export PATH=~/.npm-global/bin:$PATH
npm install -g <package>
```

**検証**：`<package> --version` を実行してバージョン番号が出力されれば成功である。

## 6. 執筆要件

1. 問題の見出しには、内部用語ではなくユーザーが検索する表現を用いる。
2. エラーメッセージはユーザーが照合できるよう原文のまま残す。機密情報はマスクしなければならない（[セキュリティとプライバシー規範](./セキュリティとプライバシー規範.md) を参照）。
3. 解決方法には完全なコマンドを示し、ユーザーが環境変数を設定済みであることを前提としない。
4. 一つの項目では一つの問題だけを解決し、複数の原因を統合しない。
5. 既知の不具合に関わる場合は、影響範囲と回避方法を説明し、修正時期を約束しない。
6. 移行に関わる問題は移行ガイドへリンクする（[移行ガイド規範](./移行ガイド規範.md) を参照）。

## 7. 保守の仕組み

1. 同じ問題が三回以上繰り返し質問された場合は、項目を追加または書き換えなければならない。
2. バージョンアップ後にすべての項目を見直し、無効になった内容を削除する。
3. 各項目には最後に検証したバージョンを付記してよく、なお適用できるかを判断しやすくする。
4. 問題の索引は項目の増減に合わせて同時に更新する。

## 8. 禁止事項

1. トラブルシューティング文書を機能紹介として書くことは禁止する。
2. 「再起動してみてください」など診断価値のない回答だけを書くことは禁止する。
3. エラーメッセージと発生条件の省略は禁止する。
4. 修正済みまたは無効になった項目を残すことは禁止する。
