# 規範選定ガイド

> このファイルが解決する問題：プロジェクト種別、チーム規模、リリース段階に応じた規範の取捨選択の根拠を示し、最小構成と完全準拠構成を提供することで、「必要に応じて取る」ことに明確な判定基準を持たせ、個人の判断に依存させない。

このファイルが取捨選択の対象とするのは規範の全体です。README セクション単位の種別差は [README分類適応ガイド](./README分類適応ガイド.md)、段階の完全なマッピングは [ライフサイクルマッピング表](./ライフサイクルマッピング表.md) を参照してください。

## 1. 選定原則

1. **強制制約は取捨選択できない**：[ハードルール](./ハードルール.md) と [禁止事項](./禁止事項.md) は、あらゆるプロジェクト、あらゆる段階で完全に適用されます。
2. **段階ゲートが下限を決める**：ある段階に入る前に、その段階が [ライフサイクルマッピング表](./ライフサイクルマッピング表.md) で示す退出ゲートを通過していなければならず、対応する中核規範を省略してはならない。
3. **種別の差は深さにのみ影響する**：プロジェクト種別はどの規範を強調しどの詳細を簡略化するかを決めますが、品質ゲートを飛ばす理由にはなりません。
4. **降格は明示的に宣言する**：私有の一時的なスクリプト用リポジトリでは P0 ゲートのみを実行してよいが、成果物に「降格モード」と明記し、未実行の項目を列挙しなければならない。

## 2. 取捨選択の次元

| 次元 | 値 | 主な影響 |
| --- | --- | --- |
| プロジェクト種別 | ライブラリ / SDK、アプリケーション、コマンドラインツール、フレームワーク、リソース集 | 強化する規範と簡略化できる詳細を決める |
| チーム規模 | 個人、小規模チーム、組織 | ガバナンスとコラボレーション系規範の必要性を決める |
| リリース段階 | プロトタイプ検証、初回公開、安定運用 | コンプライアンスと運用系規範の導入時期を決める |

3 つの次元が重なる場合は、「強制制約 → 段階ゲート → リリース段階 → プロジェクト種別 → チーム規模」の優先順位で値を取ります。優先度の低い次元での取捨選択が、優先度の高い次元の要求を弱めてはなりません。

## 3. プロジェクト種別による取捨選択

| プロジェクト種別 | 強化すべき規範 | 簡略化できる規範 | 必須の成果物 |
| --- | --- | --- | --- |
| ライブラリ / SDK | [API設計規範](./API設計規範.md)、[APIドキュメント規範](./APIドキュメント規範.md)、[バージョン管理規範](./バージョン管理規範.md)、[変更履歴規範](./変更履歴規範.md) | デプロイとロールバック、可観測性（成果物を配布する場合のみ）、スクリーンショット系のビジュアル規範 | README、API ドキュメント、LICENSE、CHANGELOG |
| アプリケーション | [READMEビジュアルレイアウト規範](./READMEビジュアルレイアウト規範.md)、[アクセシビリティ規範](./アクセシビリティ規範.md)、[デプロイとロールバック規範](./デプロイとロールバック規範.md)、[可観測性規範](./可観測性規範.md)、[トラブルシューティング規範](./トラブルシューティング規範.md) | API ドキュメント、データベース設計（マネージドサービスを利用する場合） | README、スクリーンショット、デプロイ手順、SECURITY |
| コマンドラインツール | [コミットメッセージ規範](./コミットメッセージ規範.md)、[機能とエンジニアリングトレードオフの書き方](./機能とエンジニアリングトレードオフの書き方.md)、[README分類適応ガイド](./README分類適応ガイド.md)、[アクセシビリティ規範](./アクセシビリティ規範.md)（ターミナル出力） | データベース設計、デプロイとロールバック（パッケージ配布が主体の場合） | README、使用例、デモ GIF、LICENSE |
| フレームワーク | [ドキュメントマトリクス](./ドキュメントマトリクス.md)、[APIドキュメント規範](./APIドキュメント規範.md)、[コントリビューションガイド規範](./コントリビューションガイド規範.md)、[行動規範](./行動規範.md)、[可観測性規範](./可観測性規範.md) | データベース設計（ストレージを内蔵しない場合） | README、ドキュメントの入口、コントリビューションガイド、行動規範 |
| リソース集 | [ドキュメントマトリクス](./ドキュメントマトリクス.md)、[コントリビューションガイドテンプレート](./コントリビューションガイドテンプレート.md)、[多言語規範](./多言語規範.md)、[汎用ライティング規範](./汎用ライティング規範.md) | テスト、デプロイ、API、データベース、可観測性 | README、分類ディレクトリ、コントリビューションガイド、LICENSE |

リソース集系のプロジェクトは通常、実行可能なコードを含まないため、[テスト規範](./テスト規範.md)、[CIワークフロー規範](./CIワークフロー規範.md) は該当しないと明記してかまいません。ただし [汎用ライティング規範](./汎用ライティング規範.md) と [アクセシビリティ規範](./アクセシビリティ規範.md) は引き続き遵守し、リンクテキストとリスト構造の可用性を確保しなければなりません。

## 4. チーム規模による取捨選択

| チーム規模 | 追加必須の規範 | 省略できる規範 |
| --- | --- | --- |
| 個人 | [ハードルール](./ハードルール.md)、[プロジェクト命名規範](./プロジェクト命名規範.md)、[README標準テンプレート](./README標準テンプレート.md)、[LICENSE規範](./LICENSE規範.md) | 行動規範、コードオーナーシップ、イテレーション振り返り、品質メトリクス（初回公開前に補完すれば後回しにできる） |
| 小規模チーム | 個人の項目に加えて [コードオーナーシップ規範](./コードオーナーシップ規範.md)、[コントリビューションガイド規範](./コントリビューションガイド規範.md)、[CIワークフロー規範](./CIワークフロー規範.md)、[品質ゲート](./品質ゲート.md) | インシデント対応、可観測性（サービス公開後に補完してよい） |
| 組織 | すべて適用。さらに [NOTICE規範](./NOTICE規範.md)、[SECURITYテンプレート](./SECURITYテンプレート.md)、[免責事項](./免責事項.md)、[インシデント対応規範](./インシデント対応規範.md)、[品質メトリクス規範](./品質メトリクス規範.md)、[要求トレーサビリティマトリクス規範](./要求トレーサビリティマトリクス規範.md) を実施しなければならない | なし |

チーム規模が拡大する場合、ガバナンス系の規範はリポジトリを外部に公開する前に補完すべきであり、初回リリース後に追加するまで待ってはなりません。

## 5. リリース段階による取捨選択

| リリース段階 | 導入すべき規範 | 遅延できる規範 | 宣言の要件 |
| --- | --- | --- | --- |
| プロトタイプ検証 | [ハードルール](./ハードルール.md)、[プロジェクト命名規範](./プロジェクト命名規範.md)、[README標準テンプレート](./README標準テンプレート.md)、[汎用ライティング規範](./汎用ライティング規範.md) | 品質ゲート、可観測性、インシデント対応、法務文書 | 「降格モード」と明記し、遅延項目を列挙すること |
| 初回公開 | プロトタイプの項目に加えて [品質ゲート](./品質ゲート.md)、[オープンソースコンプライアンス規範](./オープンソースコンプライアンス規範.md)、[LICENSE規範](./LICENSE規範.md)、[免責事項テンプレート](./免責事項テンプレート.md)、[コントリビューションガイドテンプレート](./コントリビューションガイドテンプレート.md)、[行動規範テンプレート](./行動規範テンプレート.md)、[SECURITYテンプレート](./SECURITYテンプレート.md)、[バッジ規範](./バッジ規範.md) | 移行ガイド、イテレーション振り返り（最初のバージョンのイテレーション後に補完してよい） | P0 ゲート項目を省略してはならない |
| 安定運用 | 初回公開の項目に加えて [変更履歴規範](./変更履歴規範.md)、[バージョン管理規範](./バージョン管理規範.md)、[移行ガイド規範](./移行ガイド規範.md)、[可観測性規範](./可観測性規範.md)、[インシデント対応規範](./インシデント対応規範.md)、[トラブルシューティング規範](./トラブルシューティング規範.md)、[イテレーション振り返り規範](./イテレーション振り返り規範.md)、[要求トレーサビリティマトリクス規範](./要求トレーサビリティマトリクス規範.md) | なし | 破壊的変更には移行パスを用意し告知すること |

## 6. 組み合わせ案

### 6.1 最小構成

個人のプロトタイプや私有の検証用リポジトリに適用し、計 10 篇です：

| 用途 | 規範 |
| --- | --- |
| 制約 | [ハードルール](./ハードルール.md)、[禁止事項](./禁止事項.md) |
| 立ち上げ | [プロジェクト立ち上げと要求規範](./プロジェクト立ち上げと要求規範.md)、[プロジェクト命名規範](./プロジェクト命名規範.md) |
| トップページ | [README標準テンプレート](./README標準テンプレート.md)、[汎用ライティング規範](./汎用ライティング規範.md) |
| エンジニアリング | [コードスタイル規範](./コードスタイル規範.md)、[コミットメッセージ規範](./コミットメッセージ規範.md)、[テスト規範](./テスト規範.md) |
| リリース | [プッシュとリリース規範](./プッシュとリリース規範.md)、[LICENSE規範](./LICENSE規範.md) |

この組み合わせを使う場合は、成果物に降格モードを宣言し、初回公開前に第 6.3 節の完全な組み合わせを補完しなければなりません。

### 6.2 標準公開構成

最小構成に加えて、品質・コンプライアンス・ガバナンス・運用の基礎項目を補完します：[品質ゲート](./品質ゲート.md)、[READMEセクション規範](./READMEセクション規範.md)、[READMEビジュアルレイアウト規範](./READMEビジュアルレイアウト規範.md)、[バッジ規範](./バッジ規範.md)、[ドキュメントマトリクス](./ドキュメントマトリクス.md)、[オープンソースコンプライアンス規範](./オープンソースコンプライアンス規範.md)、[免責事項テンプレート](./免責事項テンプレート.md)、[SECURITYテンプレート](./SECURITYテンプレート.md)、[コントリビューションガイドテンプレート](./コントリビューションガイドテンプレート.md)、[行動規範テンプレート](./行動規範テンプレート.md)、[変更履歴規範](./変更履歴規範.md)、[バージョン管理規範](./バージョン管理規範.md)、[アクセシビリティ規範](./アクセシビリティ規範.md)、[CIワークフロー規範](./CIワークフロー規範.md)、[IssueとPRテンプレート規範](./IssueとPRテンプレート規範.md)、[セキュリティとプライバシー規範](./セキュリティとプライバシー規範.md) を追加します。

この組み合わせは公開リポジトリの Gate A、B、C のすべての通過条件を満たし、大多数のプロジェクトで推奨される出発点です。

### 6.3 完全準拠構成

すべての規範を適用し、組織レベルのプロジェクト、規制対象の場面で配布するプロジェクト、または expert / Skill / MCP / コマンドラインによるプログラム的な接続が必要なプロジェクトに用います。件数は [簡体字中国語索引](./README.md) を基準とし、有効化する際は [ライフサイクルマッピング表](./ライフサイクルマッピング表.md) の段階ゲートを項目ごとに検証しなければなりません。

## 7. 競合の処理

1. 同一の次元内で競合が生じた場合は、リリース段階がより後のものの要求を優先します。プロトタイプ段階での簡略化を公開段階まで持ち越してはなりません。
2. 異なる次元で競合が生じた場合は、第 2 節の優先順位で処理し、強制制約と段階ゲートをいずれの次元でも上書きしてはなりません。
3. プロジェクトにやむを得ない事情があり本ガイドから逸脱する必要がある場合は、逸脱する規範、理由、補償措置を成果物に記録し、レビューに提出しなければなりません。
4. 降格モードは外部公開リポジトリに用いてはならず、ライセンスやセキュリティゲートを飛ばす根拠としても用いてはなりません。
