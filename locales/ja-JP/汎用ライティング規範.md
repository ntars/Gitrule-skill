# 汎用ライティング規範

> このファイルが解決する問題：すべての成果ドキュメントの文体、正確性、用語の一貫性、書式の細則、禁止内容を定義し、表現が精確で、曖昧さがなく、再現可能であることを保証します。

## 1. 文体

1. 書き言葉を用い、平叙文と命令文を採用します。
2. 口語的な表現を使用してはなりません。例えば「咱们」「超简单」「搞定」「贼快」「一键起飞」などです。
3. 感嘆符、省略記号、ネット略語、絵文字を使用してはなりません。
4. 反問文、設問文をセクションの冒頭に使用してはなりません。

## 2. 正確性

1. 各文は完全な意味を表さなければならず、文脈からの推測に依存してはなりません。
2. 「それ」「これ」「関連」「いくつか」「若干」などの曖昧な指示表現を使用してはなりません；指示が必要な場合は完全な名詞を用います。
3. 日時、バージョン番号、パス、コマンド、関数名、設定キー名は正確でなければならず、プロジェクトの実際の状況と一致させます。
4. コマンドは直接実行可能でなければならず、必要なカレント作業ディレクトリの説明を含めます。
5. バージョン番号に関わる場合は、バージョン制約の意味を明記します。例えば `>=1.2.0 <2.0.0` です。

## 3. 用語の一貫性

1. 用語が初めて出現する時点で定義を示し、形式は「中文术语（English Term，缩写）」とします。
2. 同一の概念は全文で 1 つの表現のみを使用し、中国語版と英語版の用語は一対一で対応させます。
3. 中英用語対照表を保守しなければならず、README の付録または独立したファイルに配置し、バイリンガル版は同一の対照表を共有します（テンプレートは [情報収集とテンプレート](./情報収集とテンプレート.md) を参照）。

## 4. 書式規範

1. 見出しの階層は `##` から始めます（`#` はプロジェクト名用に予約）、階層を飛ばしてはなりません。
2. 各第二レベル見出しは [READMEセクション規範](./READMEセクション規範.md) が定める 1 つのセクションに対応し、順序を変更してはなりません。
3. 表にはヘッダーが必要で、列数を一致させます；コマンド、パス、コード、設定キー名はインラインコードでマークします。
4. コードブロックには言語識別子を付けなければならず、複数行のコマンドはまとめてコピーして実行できなければなりません。
5. 外部リンクは完全な URL を使用し、短縮リンクは使用しません；内部ジャンプは相対パスのアンカーを使用します。
6. 中国語と英語、数字の間には空白を入れます；中国語と英語の句読点を混用してはなりません。

## 5. プレースホルダーの取り決め

1. コピー可能なテンプレート内の正式なプレースホルダーは `{{纯名}}` と統一して記述します。例えば `{{仓库地址}}` です；名称には「或」「，」など複数からの選択を表す接続詞を含めてはならず、説明文として記述してもなりません。
2. 正式なプレースホルダーは所属テンプレートのプレースホルダー対照表に登録しなければならず、登録項目には意味、例、必須かどうかを含めます。
3. 規範の例や記入ヒントにおける自然言語の波括弧内容はあくまで例であり、正式なプレースホルダーには該当せず、対照表には含めません；最終ドキュメントを生成する際はすべて実際の内容に置き換えなければなりません。
4. ネストした波括弧、バッククォート、2 つ目のプレースホルダーをプレースホルダー名として使用してはなりません。

## 6. 禁止リスト

出現させてはならないもの：検証されていない性能数値、出典のない比較結論、約束的な表現（例えば「すべての環境での互換性を保証」「永久無料」）、サードパーティプロジェクトへの誹謗的な記述、プロジェクトと無関係な宣伝内容。
