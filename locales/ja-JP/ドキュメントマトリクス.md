# ドキュメントマトリクス

> このファイルが解決する問題：各成果ドキュメントの唯一の責務、厳禁とする内容、分割の制約を定義し、1 ファイル 1 責務を確保して統合を禁止します。

## 1. ファイルと責務

| ファイル | 唯一の責務 | 厳禁とする内容 |
|---|---|---|
| `README.md` | トップページ：これは何か、どうインストールするか、どう実行するか、詳細をどこで見るか | 全量の API、コントリビューションの流れ、変更履歴 |
| `LICENSE` | ライセンス全文 | いかなる説明文 |
| `CHANGELOG.md` | 利用者向けのバージョン変更 | 内部のリファクタリングの詳細、開発計画 |
| `CONTRIBUTING.md` | 外部コントリビューターの流れと規範 | プロジェクトの機能説明 |
| `CODE_OF_CONDUCT.md` | 行動規範 | 技術的な内容 |
| `SECURITY.md` | 脆弱性の報告窓口と対応方針 | 既知の脆弱性の一覧 |
| `docs/api.md` | 完全な API リファレンス | チュートリアル |
| `docs/architecture.md` | アーキテクチャとモジュールの境界 | 使用例 |
| `docs/naming.md` | 命名規範 | その他の規範 |
| `docs/release.md` | リリースの流れとバージョン方針 | 変更履歴 |
| `.github/PULL_REQUEST_TEMPLATE.md` | PR のセルフチェックリスト | プロジェクトの紹介 |
| `.github/ISSUE_TEMPLATE/*.yml` | 構造化された issue フォーム | 自由記述 |
| `.github/workflows/*.yml` | CI/CD | 説明ドキュメント |

> 注記：`docs/naming.md` の規範本文は [プロジェクト命名規範](./プロジェクト命名規範.md) を参照。`docs/release.md` の規範本文は [プッシュとリリース規範](./プッシュとリリース規範.md) を参照。

## 2. 制約

- 単一ファイルが 300 行を超える場合は `docs/` へ分割しなければならず、README には摘要 + リンクのみを残す。
- ファイル名は固定で大文字、パスは固定とし、独自のディレクトリ階層を作ってはならない。
- 各ドキュメントの冒頭に「このファイルが解決する問題」を一文で示し、末尾に関連ファイルへの相互リンクを示す。
