# セキュリティとプライバシー規範

> このファイルが解決する問題：機密情報の保護、データプライバシー一覧、SECURITY.md テンプレート、脆弱性報告の項目を定義し、公開前の漏えいがないこと、データ処理がコンプライアンスに適合すること、脆弱性の報告経路が到達可能であることを保証する。

## 1. 規範条文

1. 鍵、トークン、秘密鍵、`.env`、クラウド事業者の AK/SK、データベース接続文字列をコミットしてはならない（ハードルール H3 に対応）。
2. シークレットスキャンはワークスペースと全履歴を対象とし、プッシュ前に実行しなければならない（[プッシュとリリース規範](./プッシュとリリース規範.md) を参照）。
3. 内部ドメイン、IP、個人情報、ログの残留は公開前に除去しなければならない（観点 D1 に対応）。
4. 鍵がすでにプッシュされた場合、直ちにローテーションと履歴のクリーンアップを行わなければならず、削除コミットのみで済ませてはならない（H12 に対応）。
5. どのデータを収集するか、用途、保存場所、保持期間を説明する。伝送と保存は暗号化し、表示はマスキングする。
6. 権限モデルは最小必要の原則に従う。国境を越えるデータに関わる場合は個別に評価しなければならない。
7. メンテナへ直接到達できる脆弱性報告経路を提供し、守秘と応答期限を約束する。既知のリスクはありのままに説明し、絶対的な安全を約束してはならない。

```markdown

| --- | --- |

| {{旧版本}} | いいえ / 重大な問題のみ |

## 報告経路
- 第一候補：{{私密渠道，如 GitHub Security Advisories}}
- 予備：{{加密邮箱}}
- 公開 Issue で脆弱性を報告しないでください。

## 応答の約束
| フェーズ | 期限 |
| --- | --- |
| 受領確認 | {{2 个工作日}} |
| 初期確認 | {{5 个工作日}} |
| 修正と開示 | {{视严重程度，目标 30 天}} |

受領 → 確認 → 修正 → 開示 → 告知
```

## 5. 項目定義

| 項目 | 必須 | 型 | 記入要点 | 例 |
| --- | --- | --- | --- | --- |
| 履歴の対象 | はい | 列挙 | 「はい」を選ばなければ合格と判定できない | `はい` |
| チェック項目.結果 | はい | 数値 | 検出数を記入する。「たぶんない」は禁止 | `0` |
| ローテーション済み鍵の一覧 | 条件付き必須 | リスト | 鍵が検出された場合は必須。ローテーションした認証情報を列挙する | `API_KEY ローテーション済み` |
| データ項目.保持期間 | はい | テキスト | 具体的な期間。「長期」とは書けない | `アカウント削除後 30 天` |
| データ項目.第三者提供 | はい | テキスト | ない場合は「なし」と書く | `なし` |
| サポートバージョン | はい | テーブル | どのバージョンが報告を受け付けるかを明示する | `2.x：はい` |
| 報告経路 | はい | テキスト | 少なくとも 1 つの非公開経路 | `Security Advisories` |
| 応答期限 | はい | 期間 | 各フェーズに数値があること | `2 営業日` |

## 6. 記入説明

1. **履歴スキャン**：シークレットスキャンは完全な git 履歴を含まなければならない。ワークスペースのみのスキャンは無効とみなす。
2. **鍵の検出**：プッシュ済みの鍵を発見した場合、まずローテーションし、その後履歴をクリーンアップする。順序を逆にしてはならない（H12 に対応）。
3. **マスキング**：表示とログに現れる機密フィールドはマスクしなければならない。トークン、身分証明書番号、携帯電話番号を完全に出力することは禁止する。
4. **保持期間**：「長期保存」は不合格であり、明確な期限または削除をトリガーする事象を示さなければならない。
5. **サポートバージョン**：少なくとも現在のメジャーバージョンを列挙する。旧バージョンをサポートしない場合は明確に記載し、ユーザーの誤報告を避ける。
6. **報告経路**：非公開の経路でなければならない。公開 Issue で脆弱性を開示するとリスクが拡大する。
7. **既知のリスク**：ありのままに列挙する。「本システムは絶対に安全である」は禁止表現である。

よくある誤り：

| 誤った書き方 | 問題 | 修正方法 |
| --- | --- | --- |
| 鍵のコミットを削除するだけでローテーションしない | H12 違反 | まずローテーションし、その後履歴をクリーンアップする |
| セルフチェックがワークスペースのみ | 履歴の漏えいを見逃す | 履歴スキャンを追加する |
| データ保持を「永久」と書く | 境界がない | 具体的な期限を示す |
| 脆弱性を公開 Issue で扱う | 露出面の拡大 | 非公開経路に変え、SECURITY.md に記載する |
| 「絶対に安全」を約束する | 不実な表現 | 既知のリスクをありのままに説明する形に変える |

## 7. 完全な例

```markdown
## 機密情報セルフチェック：markdown-lint-cli

チェック日：2026-11-18 ｜ 実施者：王五 ｜ 履歴の対象：是

| チェック項目 | ツール / コマンド | 結果 | 処置 |
| --- | --- | --- | --- |
| ワークスペースの鍵 | gitleaks detect | 0 | 无 |
| 過去コミットの鍵 | gitleaks detect --log-opts=--all | 0 | 无 |
| `.env` と認証情報ファイル | git ls-files | 0 | 无 |
| 内部ドメイン / IP | 正規表現検索 | 0 | 无 |

結論：通过
- ローテーション済み鍵の一覧：无
- 再確認者：李四
```
