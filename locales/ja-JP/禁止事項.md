# 禁止事項

> このファイルが解決する問題：すべての不可違反の禁止行為を集約し、レビューと執筆の際の最終的なレッドライン一覧として機能させる。

## 一、統制とプッシュのレッドライン

1. P0 が未クローズの状態で「先にプッシュして、後で補えばよい」と出力することは禁止する。
2. 検査結果を捏造することは禁止する。検査できない項目は `SKIP + 原因` と記載し、PASS と書いてはならない。
3. 複数のドキュメントを 1 つのファイルに統合して納品することは禁止する。
4. README に API の全量、コントリビューションガイド、変更履歴を詰め込むことは禁止する。
5. 公共ブランチに対して `--force` でプッシュすることは禁止する。いかなる場合も許されない。
6. 漏洩した鍵の処理を「削除コミット」のみで行うことは禁止する。
7. [プロジェクト命名規範](./プロジェクト命名規範.md) を逸脱して独自のリポジトリ名を創作することは禁止する。
8. 内部の思考過程を納品ドキュメントに書き込むことは禁止する。

## 二、ドキュメント執筆のレッドライン

1. プロジェクト名、機能、性能データ、依存関係のバージョン、ライセンス、作者情報、テスト結果を捏造してはならない。
2. 他者の README、ドキュメント、コード、画像、コピーを複製してはならない。引用が必要な場合は出典とライセンスを明記する。
3. 確認を得ないままライセンス種別を選択してはならない。
4. 検証されていない性能数値、出典のない比較結論、約束的な表現（「保証」「永久無料」など）、第三者プロジェクトへの誹謗的記述、プロジェクトと無関係な宣伝内容を記載してはならない。
5. 出所不明の素材を使用してはならない。画像、アイコン、フォントに出所とライセンスがない場合は未確認と記載し、そのまま使用してはならない。
