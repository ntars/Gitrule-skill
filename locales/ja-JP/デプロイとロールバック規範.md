# デプロイとロールバック規範

> このファイルが解決する問題：デプロイチェックリスト、変更票、ロールバック計画のテンプレートとフィールド、実行基準を定義し、リリースを制御可能にし、状態を確認可能にし、障害からの迅速な復旧を可能にする。

## 1. 規範条文

1. デプロイ前に CI、コードレビュー、品質ゲートを通過しなければなりません（[品質ゲート](./品質ゲート.md) を参照）。
2. デプロイは tag を付けたリリースバージョンに基づいて行い、タグのないコミットは使用しません（[バージョン管理規範](./バージョン管理規範.md) を参照）。
3. 環境設定とコードは分離し、機密設定は設定管理を通じて注入し、リポジトリにコミットしません（[セキュリティとプライバシー規範](./セキュリティとプライバシー規範.md) を参照）。
4. データベース構造の変更は移行スクリプトを通じて実行し、前方互換性を満たさなければなりません（[データベース設計規範](./データベース設計規範.md) を参照）。
5. 各デプロイではバージョン番号、日時、作業者、変更内容を記録しなければなりません。記録のないデプロイは非準拠のデプロイとみなします。
6. 各バージョンにはあらかじめロールバック計画を用意しなければならず、ロールバック計画のないリリースは行えません。
7. デプロイ後はヘルスチェックとスモーク検証を実行し、両方が通過してはじめてリリースを終了できます。

## 2. デプロイチェックリストのテンプレート

```markdown
# デプロイチェックリスト：{{项目名称}} {{版本号}}

バージョン：{{vX.Y.Z}} ｜ tag：{{vX.Y.Z}} ｜ 対象環境：{{预发布 / 生产}} ｜ 予定日時：{{YYYY-MM-DD HH:MM}}

## 事前チェック
- [ ] CI がすべてグリーン、ワークフロー実行 URL：{{URL}}
- [ ] コードレビューが通過、承認者：{{姓名}}
- [ ] 品質ゲート A/B/C がすべて PASS
- [ ] 変更履歴と Release Notes が準備済み
- [ ] ロールバック計画がレビュー済み、本節末尾を参照
- [ ] データベース移行スクリプトがレビュー済みで前方互換
- [ ] 設定変更リストを確認済み（リポジトリに入れない注入項目）

## 変更内容
| 変更項目 | 種別 | 影響範囲 | 関連要求 | 検証方法 |
| --- | --- | --- | --- | --- |
| {{功能 / 配置 / 数据迁移}} | {{新增 / 修改 / 移除}} | {{受影响模块}} | {{REQ-NNN}} | {{如何确认}} |

## 実行手順
1. {{步骤，含具体命令或平台操作}}
2. {{灰度比例与观察时长}}
3. {{全量放量条件}}

## ヘルスチェックとスモーク
| チェック項目 | 判定条件 | 実行方法 | 結果 |
| --- | --- | --- | --- |
| サービスの生存 | {{HTTP 200}} | {{命令}} | {{通过 / 未通过}} |
| 主要経路 | {{主流程完成}} | {{命令}} | {{通过 / 未通过}} |
| エラー率 | {{< X%}} | {{监控面板}} | {{通过 / 未通过}} |

## デプロイ記録
| 項目 | 値 |
| --- | --- |
| 実際のデプロイ日時 | {{YYYY-MM-DD HH:MM}} |
| 作業者 | {{姓名}} |
| 承認者 | {{姓名}} |
| 実際のバージョン番号 | {{vX.Y.Z}} |
| 結果 | {{成功 / 回滚 / 中止}} |

## ロールバック計画
- ロールバック先バージョン：{{vX.Y.Z}}
- 発動条件：{{错误率 > X% 持续 N 分钟 / 冒烟失败 / 数据异常}}
- 意思決定者：{{姓名}}
- ロールバック手順：{{具体命令或操作}}
- データ互換性：{{是否需要数据回滚；如果需要，说明方式}}
```

## 3. デプロイ記録のテンプレート

```markdown
## {{YYYY-MM-DD}} {{vX.Y.Z}} → {{环境}}

- バージョン番号：{{vX.Y.Z}}
- tag：{{vX.Y.Z}}
- 日時：{{HH:MM}}
- 作業者 / 承認者：{{姓名 / 姓名}}
- 変更概要：{{一句话}}
- ヘルスチェック：{{通过 / 未通过}}
- 結果：{{成功 / 回滚}}
- 関連リリース：{{Release Notes URL}}
- 備考：{{异常与处理记录；无则写「无」}}
```

## 4. フィールド定義

| フィールド | 必須 | 型 | 記入の要点 | 例 |
| --- | --- | --- | --- | --- |
| tag | はい | テキスト | [バージョン管理規範](./バージョン管理規範.md) の tag と完全に一致 | `v1.2.0` |
| 対象環境 | はい | 列挙 | ステージング / 本番、設定を混用してはならない | `本番` |
| 変更項目.種別 | はい | 列挙 | 追加 / 変更 / 削除 | `変更` |
| 関連要求 | はい | リスト | REQ 番号、要求のない変更は「なし」と記入 | `REQ-007` |
| カナリア比率 | いいえ | パーセント | 段階的に展開する場合は必須 | `10% → 50% → 100%` |
| 判定条件 | はい | しきい値 | 観測可能で判定可能であること | `HTTP 200` |
| 実際のバージョン番号 | はい | テキスト | 予定のバージョン番号と異なる場合は理由を説明 | `v1.2.1` |
| ロールバック発動条件 | はい | しきい値 + 継続時間 | 「異常に感じた」類の表現は禁止 | `エラー率 >1% が 5 分間継続` |
| データ互換性 | はい | テキスト | データのロールバックが必要か明確にすること | `データロールバック不要` |

## 5. 記入説明

1. **事前チェック**：項目ごとにチェックし、まとめて一度にチェックすることは禁止です。いずれかが未完了ならデプロイを中止します。
2. **変更内容**：各行は REQ 番号に関連付けなければなりません。要求に関連しない純粋な運用変更は「なし」と記入し、変更の根拠を説明します。
3. **ヘルスチェック**：自動判定可能な条件でなければなりません。「サービスは正常に見える」は不合格です。
4. **ロールバック発動条件**：しきい値と継続時間を同時に示し、瞬間的な揺らぎによる誤発動を避けます。
5. **カナリア展開**：各段階の展開後、規定の時間観察し、観察結論を記録してから次の段階に進みます。
6. **デプロイ記録**：時系列で追記し、履歴を上書きしません。プッシュ、tag、Release Notes の三者とバージョン番号が一致していること。
7. **ロールバックの実行**：コードのロールバックは `git revert` で逆方向のコミットを生成し、公開済みの履歴に強制プッシュしません（[プッシュとリリース規範](./プッシュとリリース規範.md) を参照）。

よくある誤り：

| 誤った記述 | 問題 | 修正方法 |
| --- | --- | --- |
| tag のないコミットでデプロイ | バージョンを再現できない | 先に tag を付けてからデプロイ |
| ロールバック計画に「問題があればロールバック」と記述 | 発動条件と手順がない | しきい値、意思決定者、手順を補う |
| データベース変更が旧バージョンと非互換 | ロールバック後にデータが使えない | 拡張-移行-縮小の三ステップ法を採用 |
| デプロイ記録を事後に追記 | 状態が信頼できない | デプロイ時にその場で記録 |
| ヘルスチェックがトップページのみ | 主要経路が未検証 | メインフローのスモークケースを追加 |

## 6. 完全な例

```markdown
# デプロイチェックリスト：markdown-lint-cli v1.0.0

バージョン：v1.0.0 ｜ tag：v1.0.0 ｜ 対象環境：本番 ｜ 予定日時：2026-11-20 10:00

## 事前チェック
- [x] CI がすべてグリーン：https://github.com/example/markdown-lint-cli/actions/runs/123
- [x] コードレビューが通過、承認者：李四
- [x] 品質ゲート A/B/C がすべて PASS
- [x] 変更履歴と Release Notes が準備済み
- [x] ロールバック計画がレビュー済み
- [x] データベース移行なし
- [x] 設定変更リストを確認済み：なし

## 変更内容
| 変更項目 | 種別 | 影響範囲 | 関連要求 | 検証方法 |
| --- | --- | --- | --- | --- |
| 日中英の空白規則 | 追加 | ルールエンジン | REQ-001 | TC-001 を実行 |
| CLI レポート出力 | 変更 | レポートモジュール | REQ-007 | TC-012 を実行 |

## 実行手順
1. v1.0.0 tag を取得しチェックサムを検証
2. カナリア 10%、10 分間観察
3. エラー率 <0.1% を確認後に 100% へ展開

## ヘルスチェックとスモーク
| チェック項目 | 判定条件 | 実行方法 | 結果 |
| --- | --- | --- | --- |
| サービスの生存 | HTTP 200 | curl /healthz | 合格 |
| 主要経路 | 50 篇のドキュメントチェックが完了 | シェルスクリプト | 合格 |
| エラー率 | <0.1% | 監視ダッシュボード | 合格 |

## ロールバック計画
- ロールバック先バージョン：v0.9.3
- 発動条件：エラー率 >1% が 5 分間継続
- 意思決定者：李四
- ロールバック手順：デプロイラベルを v0.9.3 に切り替え、データ互換性チェックを実行
- データ互換性：データベース変更なし、データロールバック不要
```
