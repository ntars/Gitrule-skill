# APIドキュメント規範

> このファイルが解決する問題：完全な API リファレンスドキュメントの構造とフィールドを定義し、docs/api.md を執筆する際の根拠とし、チュートリアル系の内容と厳格に分離します。

## 1. 必須の構造

各 API 項目は以下を含まなければなりません。

| フィールド | 要件 |
| --- | --- |
| インターフェースシグネチャ | メソッド、パスまたは関数プロトタイプ。完全でコピー可能であること |
| パラメータ | 名前、型、必須かどうか、既定値、値の範囲、説明 |
| 戻り値 | 型と構造の説明 |
| エラーコード | エラーコード、トリガー条件、対処方法 |
| 呼び出し例 | 実行可能な最小限の例。言語を明記する |
| レート制限とクォータ | 呼び出し頻度の制限、クォータ、超過時の処理 |

## 2. 強制ルール

1. パラメータと戻り値は型と制約を明記し、既定値を省略してはならない。
2. エラーコードは完全に列挙し、「エラーになる可能性がある」とだけ書いてはならない。
3. コードブロックは言語識別子を明記し、例は単独で実行できること。
4. 本ファイルには参照情報のみを置き、チュートリアル、背景、設計の説明は書かない（チュートリアルと背景は [READMEセクション規範](./READMEセクション規範.md) を参照）。

## 3. 一貫性の要件

API ドキュメントのインターフェースシグネチャはコードの実際の実装と一致しなければなりません。パラメータの命名は [汎用ライティング規範](./汎用ライティング規範.md) の正確性の要件と一致すること。用語は [用語集](./用語集.md) を参照。
