# エージェント呼び出しとプロンプト規範

> このファイルが解決する問題：Agent 呼び出し規範セットを利用する際の委譲契約とプロンプトの書き方を定義し、呼び出しが検証可能で、権限を越えず、逸脱しないことを保証します。

## 1. 呼び出しの原則

1. 責務の単一性：1 回の呼び出しでは 1 つのことだけを完了し、「ついでに」他のタスクを行うことは禁止です。
2. 読み書きの分離：サブエージェントは読み取りと分析のみを行い、ファイルの書き込みと git 操作は主制御側が統一的に実行します（[サブエージェント委譲契約](./サブエージェント委譲契約.md) を参照）。
3. 根拠の要求：結論には根拠（パス + 行番号 / コマンド出力）を付けなければならず、根拠のないものは無効とみなします。
4. 非通信：サブエージェント同士は直接通信せず、すべて主制御側が集約します。

## 2. プロンプトの構造

呼び出しプロンプトには四要素を含めなければなりません：

```text
TASK:    <一句话任务>
INPUT:   <必要上下文，只给所需部分>
OUTPUT:  <结构化输出格式，表格或 JSON，禁止散文>
FAIL:    <无法完成时的返回约定，不得瞎编>
```

## 3. プロンプトの書き方

1. 書き言葉と命令文を用い、情報を完全にし、文脈からの推測に依存しません（[汎用ライティング規範](./汎用ライティング規範.md) を参照）。
2. 出力形式と失敗時の返却を明確にし、モデルの自由な解釈を避けます。
3. 規範の引用に関わる場合はファイルパスを示します（[機械可読メタデータ規範](./機械可読メタデータ規範.md) を参照）。
4. テンプレートとプレースホルダーの形式を統一します（[情報収集とテンプレート](./情報収集とテンプレート.md) を参照）。

## 4. 強制ルール

1. Agent に検査結果の捏造を要求してはなりません；検査できない項目は SKIP + 理由を明記します。
2. 内部の思考過程を成果物に書き込んではなりません（[禁止事項](./禁止事項.md) を参照）。
3. セキュリティに関わる内容は [セキュリティとプライバシー規範](./セキュリティとプライバシー規範.md) に従って処理します。
