# バッジ規範

> このファイルが解決する問題：README におけるバッジ（Badge）の URL 構文、スタイルパラメータ、色コード、情報の取捨選択、配置順序と数量制御を定義し、Shields.io を主要な実装として、そのままコピーできる形式例と推奨パラメータ設定を示します。

本ファイルに記載するパラメータは、いずれも Shields.io の公式ドキュメント（Static Badge と Logos のページ、badge-maker の形式説明）に基づいて確認しています。出現率のデータは、本プロジェクトがトップクラスのオープンソースプロジェクトの README を抽出調査した統計に由来し、「実測」と表記します。

## 1. 基本構文

### 1.1 静的バッジの URL 構造

静的バッジは URL パスでパラメータを渡します。標準的な構造は次のとおりです。

```text
https://img.shields.io/badge/<ラベル>-<メッセージ>-<色>?style=<スタイル>&<その他のクエリパラメータ>
```

3 つのパス区間はハイフン `-` で区切ります。

| 区間 | 名称 | 必須か | 説明 |
| --- | --- | --- | --- |
| 第 1 区間 | ラベル（label） | いいえ | 左側のテキストで、指標名を示す |
| 第 2 区間 | メッセージ（message） | はい | 右側のテキストで、指標値を表示する |
| 第 3 区間 | 色（color） | はい | 右側の背景色 |

2 区間形式の記法（ラベルを省略し、メッセージと色のみ）も同様に有効です。

```text
https://img.shields.io/badge/<メッセージ>-<色>
```

### 1.2 文字エスケープ規則

URL パス内の空白と特殊文字はエスケープする必要があります。規則は次のとおりです。

| 入力文字 | URL での記法 | 例 |
| --- | --- | --- |
| 空白 | `_` または `%20` | `v0.1 prototype` → `v0.1%20prototype` |
| アンダースコア `_` | `__`（二重アンダースコア） | `my_label` → `my__label` |
| ハイフン `-` | `--`（二重ハイフン） | `dev-build` → `dev--build` |

ユーザーが提示したプロトタイプ例はこの構文に適合しており、そのまま使用できます。

```markdown
![Status](https://img.shields.io/badge/status-v0.1%20prototype-8957e5?style=flat-square)
```

その意味は、ラベル `status`、メッセージ `v0.1 prototype`（空白は `%20`）、色 `8957e5`（16 進数の紫）、スタイル `flat-square` です。

### 1.3 Markdown への埋め込み形式

```markdown
![バージョン](https://img.shields.io/badge/version-1.2.0-blue?style=flat-square)
```

クリックで遷移させたい場合は、リンクで画像を囲みます。

```markdown
[![ライセンス](https://img.shields.io/badge/license-MIT-blue.svg)](./LICENSE)
```

## 2. スタイルパラメータ（style）

`style` はバッジ全体の視覚デザインを決定し、5 つの値を取ることができ、既定値は `flat` です。

| 値 | 視覚的特徴 | 適用場面 | 実測出現回数（N=120） |
| --- | --- | --- | --- |
| `flat` | 直角、フラット、Shields.io の既定 | 汎用的な第一選択で、多くのテーマと両立する | 32 |
| `flat-square` | 直角、角丸なし、ややコンパクト | 整然として硬質な印象のトップページ | 60 |
| `for-the-badge` | 大サイズの太字、高コントラスト | トップのメインビジュアル、強調用バッジ | 65 |
| `social` | 角丸、左右の色分け、フラット | ソーシャル風のトップページ | 12 |
| `plastic` | ハイライトのグラデーション、リアル志向 | レトロなスタイルで、現在はあまり使われない | 1 |

**推奨設定**：

- 同一 README 内のすべてのバッジは `style` を統一しなければならず、混用は禁止です。これは視覚的一貫性の最重要要件です。
- 汎用プロジェクトでは `flat` または `flat-square` を優先し、ブランド色を強めたいトップページでは `for-the-badge` に統一します。
- 実測では `for-the-badge`（65 回）と `flat-square`（60 回）が最も普及しており、いずれも既定の選択肢として利用できます。

形式例：

```markdown
![build](https://img.shields.io/badge/build-passing-brightgreen?style=for-the-badge)
![build](https://img.shields.io/badge/build-passing-brightgreen?style=flat-square)
```

## 3. 色パラメータ（color / labelColor）

### 3.1 3 種類の色表記法

badge-maker の説明によれば、`color`（右側）と `labelColor`（左側の背景）はいずれも次の 3 通りの記法をサポートします。

**方法 1：Shields.io の名前付き色**

| 意味 | 名前付き色 |
| --- | --- |
| 成功 | `brightgreen`、`green`、`success` |
| 注意喚起 | `yellow`、`yellowgreen`、`orange`、`important` |
| 警告 | `red`、`critical` |
| 情報 | `blue`、`informational` |
| 中立 | `grey` / `gray`、`lightgrey` / `lightgray`、`inactive` |

注意：`labelColor` の既定値は `grey`、`color` の既定値は `lightgrey` です（ドキュメントには `inactive` も既定色の一つと別途記載されています）。一部の名前付き色の値は CSS の同名色とやや異なるため、Shields.io のレンダリング結果を基準とします。

**方法 2：16 進数色**

3 桁または 6 桁の 16 進数をサポートし、`#` 接頭辞は省略しても保持してもかまいません。

```text
?color=8957e5
?color=007fff
?color=%23007fff    ← # を保持する場合は %23 にエンコードする必要がある
```

**方法 3：CSS 色の値**

`rgb(...)`、`rgba(...)`、`hsl(...)`、`hsla(...)` および CSS の名前付き色（`aqua`、`fuchsia`、`lightslategray` など）をサポートし、使用時には URL エンコードが必要です。

### 3.2 色の意味マッピング（推奨設定）

| 情報の種類 | 推奨色 | メッセージ例 |
| --- | --- | --- |
| ビルド成功、テスト成功 | `brightgreen` / `success` | `passing` |
| ビルド失敗 | `red` / `critical` | `failing` |
| 安定版 | `blue` | `v1.2.0` |
| プレリリース、プロトタイプ | カスタム紫 `8957e5` / `orange` | `v0.1 prototype` |
| ライセンス | `blue` / `green` | `MIT` |
| ドキュメントの状態 | `yellowgreen` | `docs` |
| 非推奨、メンテナンス終了 | `red` / `inactive` | `deprecated` |

**推奨設定**：ブランド色と状態色はプロジェクト内でそれぞれ 1 セットに固定し、気軽に変えてはなりません。同じ意味にはリポジトリ全体で同じ色コードを使用します。

形式例：

```markdown
![カバレッジ](https://img.shields.io/badge/coverage-95%25-orange?style=flat-square)
![ステータス](https://img.shields.io/badge/status-v0.1%20prototype-8957e5?style=flat-square)
![ライセンス](https://img.shields.io/badge/license-MIT-blue?style=flat-square)
```

## 4. アイコンパラメータ（logo / logoColor / logoSize）

### 4.1 Simple Icons の使用

`logo` パラメータには Simple Icons のアイコンの slug を指定し、形式は `?logo=<slug>` です。よく使う slug は次のとおりです。

| 用途 | slug | 実測出現回数（N=120） |
| --- | --- | --- |
| GitHub リポジトリ | `github` | 35 |
| Discord コミュニティ | `discord` | 20 |
| npm パッケージ | `npm` | 4 |
| Apple プラットフォーム | `apple` | 3 |
| Docker | `docker` | 3 |
| ソーシャルプラットフォーム X | `x` | 3 |
| Python パッケージ | `pypi` | 2 |

完全な slug は Simple Icons のサイト、または simple-icons リポジトリの `slugs.md` を基準とします。

### 4.2 アイコンの配色とサイズ

- `logoColor`：Simple Icons アイコンの色を設定し、16 進数、rgb、hsl、CSS の名前付き色をサポートします。Simple Icons のアイコンにのみ有効で、カスタムアイコンには無効です。
- `logoSize`：`auto` に設定するとアイコンが内容に応じて自動的に拡縮され、幅の広いアイコンに適します。これも Simple Icons にのみ有効です。

形式例：

```markdown
![repo](https://img.shields.io/badge/github-repo-blue?logo=github)
![ロゴ配色](https://img.shields.io/badge/logo-javascript-blue?logo=javascript&logoColor=f5f5f5)
```

カスタムアイコンは `logo=data:image/svg+xml;base64,...` で渡すこともできますが、URL が極端に長くなり保守しにくいため、特別な必要がない限り推奨しません。

## 5. その他のクエリパラメータ

| パラメータ | 役割 | 例 |
| --- | --- | --- |
| `label` | 既定の左側テキストを上書きする（空白はエンコードが必要） | `?label=healthiness` |
| `labelColor` | 左側の背景色 | `?labelColor=abcdef` |
| `color` | 右側の背景色 | `?color=fedcba` |
| `cacheSeconds` | HTTP キャッシュ時間（秒）。既定値より短い場合は無視される | `?cacheSeconds=3600` |
| `link` | 左右の半区画クリック時の遷移先を指定する | `<object>` タグ内でのみ有効で、Markdown 画像では無効 |

## 6. 動的バッジ

動的バッジは Shields.io が外部サービスからリアルタイムにデータを取得するため、数値を手動で更新する必要はありません。よく使う種類は次のとおりです。

| カテゴリ | URL パターン | 用途 |
| --- | --- | --- |
| ビルド状態 | `https://img.shields.io/github/actions/workflow/status/<owner>/<repo>/<workflow>` | CI の状態 |
| バージョン | `https://img.shields.io/npm/v/<package>` | npm の最新版 |
| ライセンス | `https://img.shields.io/npm/l/<package>` | パッケージのライセンス |
| Star 数 | `https://img.shields.io/github/stars/<owner>/<repo>` | 人気度 |
| Issue 数 | `https://img.shields.io/github/issues/<owner>/<repo>` | 未対応の問題 |
| ダウンロード数 | `https://img.shields.io/npm/dt/<package>` | 累計ダウンロード数 |

動的バッジには `?style=`、`?logo=` などのパラメータを追加でき、規則は静的バッジと同一です。ベンチマークとなるプロジェクトでは「動的バッジで実際の指標を示し、静的バッジでカスタム状態を補う」組み合わせが一般的です。

## 7. 情報の取捨選択と配置順序

### 7.1 情報の取捨選択

バッジは「検証可能で、読み手に有用な」状態情報を伝えるべきです。次のカテゴリのみを残すことを推奨します。

1. ビルド / テストの状態；
2. バージョンまたは最新リリース；
3. ライセンス；
4. ドキュメントの状態；
5. コミュニティチャネル（Discord、ディスカッション）；
6. プロジェクト固有の状態（プロトタイプ、メンテナンス中、非推奨）。

入れてはならないもの：出典のないダウンロード数、プロジェクトと無関係なマーケティング的なラベル、検証できない評価、純粋に装飾的な色ブロック。

### 7.2 配置順序

「状態 → バージョン → ライセンス → プラットフォーム/コミュニティ → カスタム状態」の順に配置することを推奨し、重要度は左から右へ低下します。理由：ビルド状態は読み手が採用するかどうかを決め、バージョンは互換性の判断を決め、ライセンスは利用可否を決めるため、いずれも意思決定に先行する情報だからです。

### 7.3 数量制御

- 通常のプロジェクト：4〜6 枚。
- リソース集約型やエコシステム型のプロジェクト：8〜10 枚まで緩和してよい。
- すべてのバッジはプロジェクト名と一言の位置づけの後、本文の前に置き、単独の行または中央寄せのコンテナに配置し、本文中に散らばらせない。

### 7.4 静的な提供状態バッジ

第 7.1 条第 6 項「プロジェクト固有の状態」の標準的な実装が静的な提供状態バッジであり、プロジェクトの作者が数値を手動で更新し、外部データソースのない提供進捗とメンテナンス状態に適します。

```text
![Status](https://img.shields.io/badge/status-4%20of%204%20delivered-brightgreen?style=flat-square)
```

1. 標準構造は `badge/<ラベル>-<メッセージ>-<色>` で、スタイルは `?style=flat-square` に統一します。例の意味は「4 項目の成果物をすべて提供済み」です。
2. メッセージ本文の空白は `%20`、ハイフンは `--`、アンダースコアは `__` と書き、改行やその他の未エスケープの特殊文字を含めてはなりません。
3. 色の意味の取り決め：`brightgreen` は完了、`yellow` は進行中、`red` は阻害中、`lightgrey` は未着手を表します。
4. 数値が変化したらバッジと本文を同時に更新しなければならず、バッジが実際の状態より長く遅れてはなりません。同期を保証できない場合は動的バッジに切り替えます。
5. `alt` テキストには実際の意味を書き、たとえば `![提供状態]` とします。成果物一覧や対応する索引セクションへリンクしてもかまいません。

## 8. アクセシビリティとテーマ適応

- 各バッジの `alt` テキストには実際の意味を書かなければならず、たとえば `![badge]` ではなく `![ビルド状態]` とします。
- ダーク / ライトテーマでは、`<picture>` でバッジ画像のソースを切り替えられます。`for-the-badge` と `labelColor=000` を組み合わせると、両方のテーマで安定したコントラストを保てます。
- バッジは対応するデータソースへクリック遷移できなければなりません（ビルド状態は CI、バージョンはパッケージ管理ページ、ライセンスは LICENSE ファイルへ）。
