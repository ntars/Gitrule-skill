# ハードルール

> このファイルが解決する問題：いずれかに違反するとプッシュがブロックされ、「先にプッシュしてから直す」ことを許さない、破ってはならないルールを列挙する。

## ハードルール表

| # | ルール |
|---|---|
| H1 | リポジトリ名は [プロジェクト命名規範](./プロジェクト命名規範.md) に適合し、大文字小文字、文字種、長さがすべて準拠していること |
| H2 | `LICENSE` ファイルが必須；ライセンスなし = 既定で著作権留保となり、公開してはならない |
| H3 | 秘密鍵、トークン、秘密鍵ファイル、`.env`、クラウド事業者の AK/SK、データベース接続文字列をコミットしてはならない |
| H4 | ビルド成果物、依存関係ディレクトリ、IDE 設定、OS のゴミファイルをコミットしてはならない |
| H5 | 単一ファイルは 100MB を超えてはならない；50MB を超える場合は LFS を通すか除外しなければならない |
| H6 | `README.md` が必須であり、次の内容を含むこと：一言での位置づけ、インストール、最小の実行可能な例、ライセンス |
| H7 | 既定ブランチは保護されていなければならず、`main`/`master` への直接 push は禁止 |
| H8 | 公共ブランチへの `git push --force` は禁止；個人ブランチでは `--force-with-lease` のみ許可 |
| H9 | プッシュ前に `build` と `test` が通過していること；CI がレッドならメインブランチへマージしてはならない |
| H10 | コミットメッセージは Conventional Commits に適合すること；`wip`/`update`/`fix bug` のような情報のないコミットは禁止 |
| H11 | 各ドキュメントは独立したファイルとし独立した責務を持つこと；すべての内容を README に詰め込むことは禁止（[ドキュメントマトリクス](./ドキュメントマトリクス.md) を参照） |
| H12 | 秘密鍵をプッシュしてしまった場合、直ちに鍵のローテーション + 履歴のクリーンアップを行わなければならず、削除コミットのみで済ませてはならない |

## 実行の制約

- いずれかに違反した時点で **プッシュをブロック** し、「先にプッシュしてから直す」ことは許されません。
- H1–H12 の判定結果は [監査レポート形式](./監査レポート形式.md) の問題リストに反映し、各項目に根拠（パス:行 / コマンド出力）を付けなければなりません。
- H12 に違反した場合は [プッシュとリリース規範](./プッシュとリリース規範.md) のインシデント処理手順に従って実行します。
