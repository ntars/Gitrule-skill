# README 標準テンプレート

> このファイルが解決する問題：そのまま複製し、プレースホルダーを置き換えるだけで使える汎用 README テンプレートを提供する。プロジェクトのライフサイクル全体を網羅するトップページの見せ方を含み、プレースホルダー対照表、任意セクションの説明、納品前のセルフチェックリストを添え、どの開発者でも自分のプロジェクトに合わせて素早くカスタマイズできるようにする。

## 1. 使用説明

1. 第 3 節「テンプレート本文」の内容をすべて複製し、プロジェクトのルートディレクトリに `README.md` として新規作成する。
2. 第 4 節のプレースホルダー対照表に従って `{{...}}` を一つずつ置き換える。使用しない項目は、その行またはそのセクションごと削除する。
3. 第 3 節の各小節は [READMEセクション規範](./READMEセクション規範.md) の 20 章に対応し、内側から外側へというライフサイクルの順に並んでいる。ある章を削除する場合は、ファーストビューのナビゲーションにある対応するリンクも同時に削除しなければならない。
4. [バッジ規範](./バッジ規範.md) に基づいてバッジのスタイル、色、数を統一する。[READMEビジュアルレイアウト規範](./READMEビジュアルレイアウト規範.md) に基づいてスクリーンショット、表、コードブロックの配置を確認する。
5. [README分類適応ガイド](./README分類適応ガイド.md) に基づいて、プロジェクトの種類ごとにセクションを取捨選択する。
6. コミット前に第 6 節のセルフチェックリストを実行し、プレースホルダーの残りがないことを確認する。

## 2. カスタマイズの原則

- **必須項目**：プロジェクト名、リポジトリの説明、一文での位置づけ、インストール、クイックスタート、ライセンス。
- **順序の固定**：セクションの順序は [READMEセクション規範](./READMEセクション規範.md) と一致させ、日本語版と英語版は章ごとに対応させる。
- **エビデンス優先**：中核となる機能、性能の実績、エンジニアリング上のトレードオフには再確認可能なエビデンスを示さなければならず、定性的な賛辞は禁止する。
- **透明な開示**：適さない場面、限界、既知の問題、未実装の機能は明示的に列挙しなければならず、隠してはならない。
- **非約束**：ロードマップには「非約束」と表示し、具体的な提供日を書かない。
- **真正性**：すべてのコマンド、例、リンク、バッジは実際に利用可能でなければならない。連絡先と報告窓口は実際に到達可能でなければならない。

## 3. テンプレート本文

本節はプロジェクトのライフサイクル「内側から外側へ」に沿って構成され、全 20 節であり、[READMEセクション規範](./READMEセクション規範.md) の 20 章と一対一で対応する。各節のコードブロック内のテキストが、そのまま複製できる本文である。

セクションとライフサイクル段階の対応は以下のとおりで、必要に応じて位置を特定しやすくする：

| ライフサイクル段階 | 対応する小節 | 見せ方の重点 |
| --- | --- | --- |
| プロジェクト立ち上げ | 3.1–3.2 | 位置づけ、背景、適用場面と限界 |
| 要求分析 | 3.2–3.3 | 機能の境界、適用場面、適さない場面 |
| アーキテクチャ設計 | 3.5–3.6、3.11 | エンジニアリング上のトレードオフ、技術スタック、ディレクトリ構造 |
| 開発実装 | 3.3–3.4、3.9–3.10 | 機能、特性、設定、API |
| テスト検証 | 3.8、3.12 | クイックスタートの例、性能実績のエビデンス |
| デプロイと公開 | 3.7、3.14 | インストールとデプロイ、互換性マトリクス |
| 運用監視 | 3.13、3.15 | セキュリティとプライバシー、既知の問題と制限 |
| イテレーション保守 | 3.15–3.17 | 未実装の機能、変更履歴、今後のロードマップ |

説明：README はプロジェクトのトップページであり、各段階のプロセス文書（要求、設計、テスト、デプロイ、運用の完全な記録）は対応する規範が担う。[ドキュメントマトリクス](./ドキュメントマトリクス.md) を参照。本セクションは利用者に見える結論のみを示す。

## 5. 任意セクションの説明

第 3 節では 20 章の複製可能な本文を示した。以下はプロジェクトの種類に応じて増減するための補足であり、章を削除する場合はファーストビューのナビゲーションリンクも同時に削除しなければならない。

| セクション | 残すことを推奨する種類 | 削除できる条件 |
| --- | --- | --- |
| 中核となる特性 | すべて | 再確認可能なエビデンスがない場合は削除してよいが、定性的な記述で代替してはならない |
| 設計の詳細とエンジニアリング上のトレードオフ | フレームワーク、アプリケーション、サービス | 重要なトレードオフがない場合は削除してよい |
| 技術スタックと依存関係一覧 | ライブラリ、フレームワーク | 外部依存関係がない場合は削除してよい |
| 性能の実績 | CLI、ライブラリ、サービス | テストデータがない場合は削除してよいが、推定値は禁止する |
| セキュリティとプライバシー | サービス、アプリケーション、個人情報を扱うプロジェクト | 純粋なローカルツールでは簡略化してよい |
| 互換性の説明 | ライブラリ、SDK、クロスプラットフォームアプリケーション | 単一の実行環境では簡略化してよい |
| 変更履歴 | すべて | CHANGELOG が存在しない場合に限り、変更概要の埋め込みに変更する |
| 今後のロードマップ | すべて | 公開の計画がない場合は削除してよい |
| NOTICE コンプライアンス声明 | サードパーティ依存関係を含むもの | サードパーティ依存関係がない場合は削除してよい |
