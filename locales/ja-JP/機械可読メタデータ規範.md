# 機械可読メタデータ規範

> このファイルが解決する問題：エキスパート、Skill、MCP、コマンドラインなどのプログラムから消費されるメタデータマニフェストの構造を定義し、機械からの取得が安定し、発見可能であることを保証する。

## 1. 設計目標

1. 安定した識別子：各ドキュメントは一意で不変の識別子を持ち、プログラムからの参照に供する。
2. 言語非依存：識別子は言語によって変化せず、言語はパスのみに表れる。
3. 発見可能性：マニフェストは全ドキュメントの類型、パス、言語、要約を列挙する。

## 2. マニフェスト構造

マシンマニフェスト（manifest）は以下を含むこと：

| フィールド | 要件 |
| --- | --- |
| id | 安定した一意の識別子。小文字の kebab-case で、言語とバージョンを含まない |
| title | ドキュメントのタイトル |
| summary | 何を解決するかを一言で説明 |
| domain | 所属ドメイン（七大ドメインのいずれか） |
| paths | 言語コードから相対パスへのマッピング。例 `zh-CN`: `./locales/zh-CN/角色与职责.md` |
| version | 規範集のバージョン |

## 3. 強制ルール

1. 言語を追加する場合は `paths` にマッピングを追加するのみとし、`id` と他の言語のパスを変更してはならない。
2. ドキュメントの名称を変更する場合は `id` を不変に保ち、`paths` のみを更新すること。
3. 識別子とパスは実際のファイルと一致すること。CI がマニフェストの有効性を検証する。
4. 本規範は複製可能なマニフェストの例を提供する。対象プロジェクトは第 2 節のフィールドに従って実際のマニフェストの実体を作成し、`paths` がディスク上のファイルと一致することを保証すること。

## 4. マニフェストの例（複製可能）

以下の例は三つのドキュメント項目を列挙している。実際のマニフェストは対象言語ディレクトリの全規範を網羅すること。`id` は言語によって変化せず、`paths` は言語コードごとにマッピングを追加する。

```json
{
  "version": "1.0.0",
  "entries": [
    {
      "id": "role-and-responsibility",
      "title": "角色与职责",
      "summary": "定义执行者身份、职责边界、触发条件、适用范围与硬性约束",
      "domain": "总纲与治理",
      "paths": {
        "zh-CN": "./locales/zh-CN/角色与职责.md"
      },
      "version": "1.0.0"
    },
    {
      "id": "readme-standard-template",
      "title": "README标准模板",
      "summary": "提供可直接套用的通用 README 模板与占位符对照表",
      "domain": "命名与文档",
      "paths": {
        "zh-CN": "./locales/zh-CN/README标准模板.md"
      },
      "version": "1.0.0"
    },
    {
      "id": "machine-readable-metadata",
      "title": "机器可读元数据规范",
      "summary": "定义供专家、Skill、MCP、命令行消费的元数据清单结构",
      "domain": "AI 与机器适配",
      "paths": {
        "zh-CN": "./locales/zh-CN/机器可读元数据规范.md"
      },
      "version": "1.0.0"
    }
  ]
}
```

言語を追加する場合は、該当項目の `paths` にマッピングを追加するのみとする。例えば `"en-US": "./locales/en-US/role-and-responsibility.md"` を追加する。`id` を変更してはならない。
