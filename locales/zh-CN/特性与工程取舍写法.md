# 特性与工程取舍写法

> 本文件解决什么问题：定义 README 中「核心特性」与「设计细节与工程取舍」两章的写法，分别给出特性的五段结构与工程取舍的十类强制覆盖项。

## 1. 核心特性写法

每条特性按以下五段结构书写，缺任一段落不得作为特性列出。

1. **特性名称**：不超过 15 字，使用名词性短语。
2. **价值**：解决的具体问题，以及不解决时的后果。
3. **实现方式**：采用的技术、机制或算法，指明关键文件或函数。
4. **差异化**：与常见方案的对比维度，须为可客观判断的维度。
5. **证据**：测试数据、基准结果、代码位置、配置项或可复现步骤。

约束：
1. 证据须可复现；无法提供证据的特性，标注「【待补充：验证方式】」，不得以定性描述代替。
2. 性能类证据须注明测试环境与测试方法。
3. 对比对象须为具名方案，不得使用「传统方案」「其他工具」等模糊指代。

## 2. 设计细节与工程取舍写法

每条按「场景 → 处理方式 → 原因」三段书写，说明为何这样设计而非其他方案。

强制覆盖的类别：
1. 异常输入与边界情况（空值、超长、非法字符、极端数值）
2. 超时、重试、退避、熔断、降级策略
3. 缓存层级、失效策略、缓存穿透与雪崩防护
4. 并发控制、锁粒度、数据一致性与幂等性
5. 内存与存储优化（分批处理、流式读写、压缩）
6. 安全措施（鉴权、限流、输入校验、敏感信息脱敏）
7. 交互细节（防误触、二次确认、可撤销、加载态与空态）
8. 默认参数取值依据
9. 向后兼容与跨平台适配策略
10. 弱网与离线处理、状态恢复
