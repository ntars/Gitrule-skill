# API文档规范

> 本文件解决什么问题：定义完整 API 参考文档的结构与字段，作为 docs/api.md 的撰写依据，与教程类内容严格分离。

## 1. 必备结构

每个 API 条目须包含：

| 字段 | 要求 |
| --- | --- |
| 接口签名 | 方法、路径或函数原型，完整可复制 |
| 参数 | 名称、类型、是否必填、默认值、取值范围、说明 |
| 返回值 | 类型与结构说明 |
| 错误码 | 错误码、触发条件、处理方式 |
| 调用示例 | 可运行的最小示例，标注语言 |
| 限流与配额 | 调用频率限制、配额、超限处理 |

## 2. 强制规则

1. 参数与返回值须写明类型与约束，不得省略默认值。
2. 错误码须完整列出，不得只写「可能报错」。
3. 代码块须标注语言标识，示例须可独立运行。
4. 本文件只放参考信息，不写教程、背景、设计说明（教程与背景见 [README章节规范](./README章节规范.md)）。

## 3. 一致性要求

API 文档中的接口签名须与代码实际实现一致；参数命名须与 [通用写作规范](./通用写作规范.md) 的精确性要求一致；术语见 [术语表](./术语表.md)。
