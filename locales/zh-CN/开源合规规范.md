# 开源合规规范

> 本文件解决什么问题：定义开源合规的采集范围、依赖清单字段、采集方法、许可证兼容性判断、修改标注与素材引用规则，保证声明完整、可核查。

## 1. 采集范围

须覆盖四类来源：直接依赖、间接与传递依赖、构建与开发工具链、素材资源（图标、字体、图片、音频、数据集、算法来源）。

## 2. 依赖清单字段

| 字段 | 要求 |
| --- | --- |
| 组件名称 | 与官方仓库一致 |
| 版本 | 实际锁定版本，非范围表达式 |
| 引用方式 | 直接依赖或间接依赖 |
| 版权方 | 官方声明的著作权人全称 |
| 许可证 | SPDX 标识符，多许可证须写明组合方式 |
| 官方地址 | 仓库或主页完整 URL |
| 本项目用途 | 具体调用位置或功能 |
| 是否修改 | 是或否 |
| 修改说明 | 修改文件、修改内容、修改原因；未修改填「无」 |
| 许可证原文位置 | 项目内路径或文件链接 |

依赖清单表格模板见 [信息采集与模板](./信息采集与模板.md)。

## 3. 采集方法

按技术栈使用对应命令生成依赖树，再逐项补全许可证与版权信息：`npm ls --all`、`pip freeze`、`go mod graph`、`cargo tree`、`mvn dependency:tree`、`gradle dependencies`、`composer show --tree`。许可证扫描可使用 `license-checker`、`pip-licenses`、`cargo-license` 等工具，扫描结果须人工复核，工具输出不得直接作为最终结论。

## 4. 许可证兼容性

1. 须判断项目许可证与各依赖许可证的兼容性，重点核查 GPL、AGPL、LGPL、MPL 的传染性范围。
2. Apache-2.0 依赖须确认其 NOTICE 文件要求是否已被满足。
3. 素材类许可证（如 SIL OFL 字体、CC 系列）须单独核查署名与传播要求。
4. 无法判定兼容性时，标注「【待确认：许可证兼容性】」并说明存疑原因。

## 5. 修改他人代码的标注

1. 在文件头部保留原始版权声明与许可证声明。
2. 在 NOTICE 中列明修改文件路径、修改内容摘要、修改日期。
3. 在 README 对应章节同步说明。

## 6. 引用与素材

1. 引用他人文档或代码片段须注明来源地址、作者、许可证。
2. 图片、图标、字体须记录来源与许可证，缺失时标注待确认，不得直接使用。
3. 不得使用来源不明的素材。
