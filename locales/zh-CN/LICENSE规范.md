# LICENSE规范

> 本文件解决什么问题：定义项目许可证的 SPDX 标注、LICENSE 全文要求、版权行位置、GitHub 识别机制、分层许可的文件布局与确认流程，以及未经确认不得写入的规则。

## 1. 基本规则

1. 项目许可证须以 SPDX 标识符在 README 中明确写出，并提供对应 LICENSE 文件。
2. LICENSE 文件须为该许可证官方英文全文，不得删改条款；改写措辞、重排段落或用 Markdown 重新排版都会导致自动识别失败。
3. 版权行置于文件头部或 README 第 19 章，格式见 [README章节规范](./README章节规范.md)。

## 2. GitHub 识别机制

GitHub 用开源的 licensee 判定仓库许可证，结果决定仓库页徽章、API 的 license 字段，以及按 license 关键词搜索能否命中。规则如下：

1. 只扫描两个位置：项目根目录，以及顶层 `LICENSES/` 目录。`locales/`、`docs/` 等子目录内的同名文件不参与判定。
2. 根目录按文件名评分，高分优先：`LICENSE` 为 1.00，`LICENSE.md` 为 0.95，`COPYING` 为 0.90，`LICENSE-MIT` 一类带后缀的为 0.70。
3. 顶层 `LICENSES/` 目录内的文件，文件名符合 SPDX 标识符格式且扩展名为 `.txt`、`.md`、`.markdown`、`.html` 时得 1.00，其余为 0.00。
4. 文件内容须与该许可证官方全文高度一致，仅有「本项目采用某某许可证」这类声明的文件不会被识别，被识别出的也是非标准值。
5. 识别到多个互不相同的许可证时，项目级结果可能不返回具体许可证，仓库页显示为 `View license` 或 `Other`。
6. README 中的自然语言声明不参与判定，写了「本项目采用 MIT 许可证」不等于被识别为 MIT。

因此：**README 声明与 LICENSE 文件是两套独立机制，必须同时具备。** 且当根目录存在多份许可证文件时，最终报出哪一份受文件名评分与内容匹配共同影响，不可预期，实测中双许可证仓库只报出其中一份。

## 3. 分层许可的文件布局

分层许可指仓库内不同部分适用不同许可证，例如代码用 MIT、文档用 CC BY 4.0。此时按以下顺序决定布局：

| 方案 | 根目录放什么 | 自动识别结果 | 适用条件 |
| --- | --- | --- | --- |
| 单层（默认） | `LICENSE` 一份 | 稳定识别为该许可证 | 各层许可证相同，或差异不影响使用者义务 |
| 分层加说明 | `LICENSE` 放主许可证，另建 `LICENSING.md` | 稳定识别为根 `LICENSE` 的许可证 | 需要分层，且希望徽章保持明确 |
| 分层加 REUSE | 顶层 `LICENSES/` 放各许可证全文 | 可能退化为非标准值 | 仅当下游明确要求 REUSE 合规 |

取舍要点：

1. 不要同时放多个根级许可证文件。实测多个双许可证仓库均只被报出其中一个，另一份在仓库页与 API 中不可见，等于对外只声明了一种许可。
2. REUSE 布局与徽章明确性存在冲突：`LICENSES/` 内放多份许可证会被判为多许可证，换来 `reuse lint` 全绿，代价是自动识别结果可能不明确。二者不能同时完美满足，须由项目方权衡。
3. 采用「分层加说明」时，`LICENSING.md` 的文件名不含 `LICENSE` 与 `COPYING` 模式，不会被误认为许可证文件，不影响根 `LICENSE` 的识别。
4. 无论选哪种布局，README 第 19 章都须写明 SPDX 表达式（如 `MIT AND CC-BY-4.0`）与各层适用范围，这是唯一在人工阅读层面不丢失信息的位置。

## 4. 分层决策与确认流程

分层许可涉及法律含义，编写或优化前必须逐轮确认，禁止臆造。

1. 不得擅自分层。用户未明确要求时按单层处理，并在报告中说明「如需分层，可选方案与差异如下」。
2. 给出分层建议时必须回报依据：各层实际覆盖的内容范围、候选许可证及其义务差异、对下游使用者的影响、以及自动识别结果会如何变化。
3. 写入前至少二次确认：第一次确认分层组合（哪一层用哪个许可证），第二次确认文件布局（根文件放哪份、是否建 `LICENSES/`）。
4. 推送前再次确认。生成完成后须明确告知「文件已生成，请检查后自行提交」，不得代替用户提交或推送。
5. 未获确认的候选方案只写入报告或临时文件，不得落盘为 `LICENSE`、`LICENSES/`、`LICENSING.md`。
6. 无法判定某部分属于哪一层时，标注「【待确认：分层归属】」并列出存疑文件，不得默认归类。

## 5. 免责声明要求

许可证文本具有法律效力，模板与工具只提供判定规则与文件布局，不构成法律意见。

1. README 第 19 章或 `LICENSING.md` 须包含免责声明，说明许可证选择由项目方自行确认。
2. 免责声明须与 NOTICE 中的免责声明保持一致，不得一处有一处无。
3. 不得声称「已完成合规判定」，只能说明「已按规则检查文件布局与 SPDX 标注是否齐全」。
4. 分层许可的法律效力以各许可证原文为准，仓库内的说明文字仅作索引，不改变条款。
