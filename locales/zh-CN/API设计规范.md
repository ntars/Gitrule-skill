# API设计规范

> 本文件解决什么问题：定义接口设计的一致性原则与约定，保证 API 易用、可预测、可演进。

## 1. 设计原则

1. 命名一致：同类资源与操作使用统一命名规则。
2. 可预测：相同语义的操作有相同结构。
3. 显式优于隐式：默认值、必填项、错误行为须明确。
4. 向后兼容：变更优先保持兼容，破坏性变更须版本化（见 [版本管理规范](./版本管理规范.md)）。

## 2. 必含约定

1. **命名**：资源、方法、字段的命名规则。
2. **参数**：类型、必填、默认值、取值范围。
3. **错误**：统一错误结构、错误码、HTTP 状态或等价机制。
4. **分页与过滤**：大数据量场景的分页、排序、过滤约定。
5. **幂等性**：写操作的幂等保证。
6. **限流与配额**：频率限制与超限响应。
7. **版本**：API 版本策略与演进方式。

## 3. 强制规则

1. 错误响应须包含可定位的错误码与说明，不暴露内部实现细节。
2. 破坏性变更须升版本并提供迁移期（见 [变更日志规范](./变更日志规范.md)）。
3. 接口须有对应文档，字段完整（见 [API文档规范](./API文档规范.md)）。
