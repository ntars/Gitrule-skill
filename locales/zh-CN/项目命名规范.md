# 项目命名规范

> 本文件解决什么问题：定义仓库名的字符、大小写、分词、长度、语义等硬性规则，以及命名公式、约定后缀、检索流程与配套元数据要求。

## 1. 硬性规则

| 规则 | 要求 | 反例 |
|---|---|---|
| 字符集 | 仅 `a-z`、`0-9`、`-` | `My_Proj`、`我的项目` |
| 大小写 | 全小写 | `MyProject` |
| 分词 | kebab-case，用 `-` 连接 | `myproject`、`my_project` |
| 长度 | 2–25 字符 | 超长的拼接名 |
| 结尾 | 名词或以形态后缀收尾 | 以 `-project`、`-test` 结尾 |
| 版本 | 不含版本号、年份、日期 | `tool-v2`、`app2024` |
| 无信息词 | 禁止 `my`/`demo`/`test`/`new`/`tmp` | `my-new-demo` |
| 唯一性 | GitHub / npm / PyPI 各检索一次 | 与知名库重名 |
| 语义 | 名字本身能读出「做什么」 | `xyz`、`abc123` |

## 2. 命名公式（四选一）

```text
<技术>-<对象>          vue-virtual-table      go-ratelimit
<对象>-<形态>          note-cli   image-api   config-loader
<动词>-<对象>          parse-markdown   sync-dotfiles
<领域>-<子领域>        web-ui-kit   data-pipeline
```

## 3. 约定式后缀

`-cli` 命令行 / `-sdk` 客户端库 / `-api` `-server` 服务端 / `-template` `-boilerplate` 脚手架 / `-loader` `-parser` 中间件 / `-kit` 组件集 / `-notes` `-guide` 文档 / `dotfiles` 配置仓 / `awesome-xxx` 资源合集。

## 4. 命名流程

1. 用一句话写出「项目给谁解决什么问题」。
2. 从这句话里取核心名词 + 形态，套用第 2 节任一公式。
3. 生成 3 个候选，逐一做重名检索。
4. 选最能在不看 README 时被理解的那个。
5. 中文名不写进仓库名，写在 README 首行标题后。

## 5. 配套元数据

- description 与仓库名同源，≤120 字符，句式：`<做什么> for <谁>`。
- topics 5–10 个，全小写，用 `-` 连接，覆盖语言、领域、形态三类。
