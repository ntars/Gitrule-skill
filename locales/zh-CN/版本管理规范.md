# 版本管理规范

> 本文件解决什么问题：定义语义化版本规则、版本决策记录、递增依据与联动关系，保证版本号可表达变更性质、可被工具解析、与发布产物一致。

## 1. 规范条文

1. 版本号遵循语义化版本：`MAJOR.MINOR.PATCH`。
2. 版本号不含年份、日期、构建序号作为语义主体；已发布版本不得重用版本号。
3. 破坏性变更须在主版本升级时集中处理，并给出迁移方式。
4. 版本号与 tag 一致，tag 格式为 `vMAJOR.MINOR.PATCH`（见 [推送与发布规范](./推送与发布规范.md)）。
5. 预发布版本使用 `-alpha`、`-beta`、`-rc` 后缀，须在稳定版发布前完成验证。

## 2. 版本号格式与递增依据

| 位 | 递增条件 | 触发提交类型 | 示例 |
| --- | --- | --- | --- |
| MAJOR | 不兼容的破坏性变更 | `feat!:` / `fix!:` / `BREAKING CHANGE:` | `1.9.2 → 2.0.0` |
| MINOR | 向后兼容的新功能 | `feat` | `1.2.3 → 1.3.0` |
| PATCH | 向后兼容的缺陷修复 | `fix` | `1.2.3 → 1.2.4` |

预发布格式：`vMAJOR.MINOR.PATCH-alpha.N` / `-beta.N` / `-rc.N`，数字从 1 递增；稳定版发布时去除后缀。

## 3. 版本决策记录模板

```markdown
## 版本决策：{{X.Y.Z}}

- 决策日期：{{YYYY-MM-DD}}
- 决策人：{{姓名}}
- 当前版本：{{X.Y.Z}}
- 目标版本：{{X.Y.Z}}
- 递增位：{{MAJOR / MINOR / PATCH}}
- 依据：{{列举触发的提交类型与变更内容}}

| 变更 | 提交类型 | 关联需求 | 是否破坏兼容 |
| --- | --- | --- | --- |
| {{变更描述}} | {{feat / fix / BREAKING CHANGE}} | {{REQ-NNN}} | {{是 / 否}} |

- 破坏性变更处理：{{迁移指南链接 / 不适用}}
- 变更日志条目：{{链接}}
- tag：{{vX.Y.Z}}
- 发布检查：{{已通过 / 待通过}}
```

## 4. 版本台账模板

```markdown
# 版本台账：{{项目名称}}

| 版本 | 发布日期 | 类型 | 主要变更 | tag | 变更日志 | 状态 |
| --- | --- | --- | --- | --- | --- | --- |
| {{X.Y.Z}} | {{YYYY-MM-DD}} | {{主版本 / 次版本 / 修订}} | {{一句话}} | {{vX.Y.Z}} | {{链接}} | {{当前 / 历史 / 已废弃}} |
| {{X.Y.Z-rc.1}} | {{YYYY-MM-DD}} | 预发布 | {{一句话}} | {{vX.Y.Z-rc.1}} | {{链接}} | 已 superseded |

状态：当前 / 历史 / 已废弃 / 已被替代
```

## 5. 字段定义

| 字段 | 必填 | 类型 | 填写要点 | 示例 |
| --- | --- | --- | --- | --- |
| 当前版本 | 是 | `X.Y.Z` | 与最近 tag 一致 | `1.2.3` |
| 目标版本 | 是 | `X.Y.Z` | 只递增一位 | `1.3.0` |
| 递增位 | 是 | 枚举 | MAJOR / MINOR / PATCH | `MINOR` |
| 依据 | 是 | 列表 | 列举触发变更，禁止「例行更新」 | `新增 TOML 支持` |
| 破坏性变更处理 | 条件必填 | 链接 | MAJOR 递增时必填 | `[迁移指南]` |
| 变更日志条目 | 是 | 链接 | 指向对应版本段 | `[1.3.0]` |
| tag | 是 | `vX.Y.Z` | 与版本号一一对应 | `v1.3.0` |
| 发布日期 | 是 | `YYYY-MM-DD` | 以 tag 打点日期为准 | `2026-11-20` |
| 状态 | 是 | 枚举 | 当前 / 历史 / 已废弃 / 已被替代 | `当前` |

## 6. 填写说明

1. **一位递增**：每次发布只递增一位；同时存在 feat 与 BREAKING CHANGE 时取最高位（MAJOR），其余变更并入该版本。
2. **破坏性集中**：多个破坏性变更合并到同一主版本发布，避免连续 MAJOR 递增。
3. **禁止重用**：已发布版本号永久占用；撤回发布时递增 PATCH 发布修订版，不复用原号。
4. **预发布**：`alpha` 用于内部验证，`beta` 用于公开试用，`rc` 用于发布候选；每一级均须通过 CI。
5. **一致性核对**：版本号须在 tag、变更日志、Release Notes、部署记录、版本台账五处一致；不一致时以 tag 为准并修正其余。
6. **联动**：递增依据来自 [提交信息规范](./提交信息规范.md) 的类型；对外说明见 [变更日志规范](./变更日志规范.md)；升级路径见 [迁移指南规范](./迁移指南规范.md)。

常见错误：

| 错误写法 | 问题 | 修正方式 |
| --- | --- | --- |
| `v2026.11` | 以日期为语义主体 | 改为 `v2.1.0` |
| 同一版本多次递增两位 | 语义混乱 | 只递增最高位 |
| 复用已撤回的版本号 | 无法区分产物 | 递增 PATCH 发布修订版 |
| MAJOR 递增无迁移指南 | 使用者无法升级 | 补迁移指南并链接 |
| 版本号仅存在 tag 中 | 台账与日志不一致 | 五处同步 |

## 7. 完整示例

```markdown
## 版本决策：2.0.0

- 决策日期：2026-12-01
- 决策人：李四
- 当前版本：1.9.2
- 目标版本：2.0.0
- 递增位：MAJOR
- 依据：配置文件格式由对象改为文件路径，属不兼容变更。

| 变更 | 提交类型 | 关联需求 | 是否破坏兼容 |
| --- | --- | --- | --- |
| 配置文件路径化 | BREAKING CHANGE | REQ-021 | 是 |
| 新增 TOML 解析 | feat | REQ-001 | 否 |

- 破坏性变更处理：[迁移指南 v2.0]
- 变更日志条目：[2.0.0]
- tag：v2.0.0
- 发布检查：已通过
```
