# 可访问性规范

> 本文件解决什么问题：定义项目文档、README 与用户界面的可访问性要求，使内容对使用屏幕阅读器、键盘操作与不同视觉条件的读者同样可用。

## 1. 适用范围

1. 文档可访问性：README、文档站、示例代码、表格、图片。
2. 界面可访问性：应用程序与 Web 项目的用户界面。
3. 命令行可访问性：帮助文本、错误提示与输出格式。

## 2. 文档可访问性

### 2.1 图片与媒体

1. 每张图片须提供 `alt` 文本，描述画面内容与作用；装饰性图片用空 `alt`。
2. 不得使用「图片」「截图」「image」等无信息文本作为 `alt`。
3. GIF 动图须在邻近文本中说明其内容，避免仅靠动画传达信息。
4. 图表须同时提供文字说明或数据表，不得只以颜色区分数据系列。

### 2.2 标题与结构

1. 标题层级连续，不得跳级（见 [README视觉排版规范](./README视觉排版规范.md)）。
2. 全文仅一个一级标题。
3. 列表使用规范的 Markdown 语法，保证屏幕阅读器可识别为列表。
4. 表格须有表头行，不得使用无表头表格布局页面。

### 2.3 链接与文字

1. 链接文字须可独立说明目标，禁止使用「点击这里」「更多」。
2. 颜色不得作为传达信息的唯一手段，须配合文字或图标。
3. 中外文混排时保留空格，保证断词与朗读正确。
4. 缩写首次出现时给出全称。

### 2.4 代码与表格

1. 代码块标注语言，便于辅助工具识别（见 [README视觉排版规范](./README视觉排版规范.md)）。
2. 表格单元格内容简明，避免跨行合并造成阅读器解析困难。
3. 长命令给出分行写法，不依赖横向滚动。

## 3. 界面可访问性

### 3.1 键盘操作

1. 所有交互元素可通过键盘到达与操作。
2. 焦点顺序与视觉顺序一致，焦点状态清晰可见。
3. 提供跳过重复内容的快捷入口（如跳转到主内容）。

### 3.2 语义与标签

1. 使用语义化标签表达结构与角色，避免用无语义元素模拟控件。
2. 表单控件须有关联标签，错误提示与对应字段绑定。
3. 动态状态变化通过无障碍提示传达给辅助技术。

### 3.3 视觉条件

1. 文本与背景对比度满足可读性要求；正文对比度不低于 4.5:1，大字不低于 3:1。
2. 支持系统深浅主题，主题切换不改变信息结构（见 [README视觉排版规范](./README视觉排版规范.md)）。
3. 动画提供减弱选项，避免自动播放的高频闪烁内容。
4. 文本缩放至 200% 时布局仍可用，不出现内容截断。

## 4. 命令行可访问性

1. 错误提示说明原因与可行的修复动作，不得只输出错误码。
2. `--help` 输出分类清晰，列出必填参数与默认值。
3. 支持禁用彩色输出的环境变量，便于屏幕阅读器与日志处理。
4. 交互式提示提供非交互的等价参数，支持自动化场景。

## 5. 验证清单

- [ ] 所有图片有信息明确的 `alt` 文本。
- [ ] 标题层级连续，全文一个一级标题。
- [ ] 链接文字可独立理解。
- [ ] 表格有表头，颜色非唯一信息载体。
- [ ] 代码块标注语言。
- [ ] 界面元素可键盘操作，焦点可见。
- [ ] 对比度满足最低要求，深浅主题均可读。
- [ ] 帮助文本与错误提示可指导下一步操作。

## 6. 禁止事项

1. 禁止用纯图片传达关键信息而不提供文字替代。
2. 禁止仅用颜色表示状态或错误。
3. 禁止使用无意义的链接文字。
4. 禁止移除焦点指示样式而不提供替代。
