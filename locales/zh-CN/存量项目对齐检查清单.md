# 存量项目对齐检查清单

> 本文件解决什么问题：把本规范集应用到已有项目时，给出可逐项核对的检查清单、判定方法与通过标准，覆盖元数据、文件命名、章节结构、双语同步、链接与推送六个环节。

## 1. 适用范围

本清单用于两类场景：

1. 首次把既有仓库纳入本规范集管理；
2. 规范集更新后，对已对齐的仓库做回归核对。

清单按「先元数据、后结构、最后推送」的顺序执行。前一组未通过时不进入下一组，避免在错误基础上批量改写。

## 2. 检查项

### 2.1 元数据（对应 [项目命名规范](./项目命名规范.md) 第 5 节）

| 编号 | 检查项 | 判定方法 | 通过标准 |
| --- | --- | --- | --- |
| A1 | 仓库名合规 | 对照命名公式与字符集规则 | 全小写、kebab-case、2–25 字符、无版本号与信息词 |
| A2 | 简介为双语合并格式 | 读取仓库 About 区或 `gh repo view --json description` | `国家语言 \| 英语`，竖线两侧各一个空格 |
| A3 | 简介长度 | 按字符计数，中文与英文分别计数 | 各不超过 120 字符，合计不超过 350 字符 |
| A4 | 话题数量与语言 | `gh repo view --json repositoryTopics` | 恰好 20 个，全英文、全小写、连字符分词 |
| A5 | 话题覆盖面 | 按语言、领域、形态、生态、场景五类核对 | 五类均有覆盖，无与技术栈不符的话题 |

超限时的处置顺序：先压缩英文版本，再压缩中文版本；压缩时先删修饰词与重复限定，再合并同义表述。

### 2.2 文件命名（对应 [多语言规范](./多语言规范.md)）

| 编号 | 检查项 | 判定方法 | 通过标准 |
| --- | --- | --- | --- |
| B1 | 主 README 命名 | 列目录 | 中文为 `README.md`，英语为 `README_EN.md` |
| B2 | 其他语言命名 | 列目录 | `README_<语言码大写>.md`，如 `README_JA.md` |
| B3 | 命名一致性 | 全仓库检索旧名 | 不残留 `README.en.md`、`README.ja.md` 一类旧命名 |
| B4 | 引用同步 | 检索旧文件名 | 导航链接、目录树示例、脚本内白名单均已更新 |
| B5 | 切换链接 | 打开各语言版本首行 | 每种语言版本均可在首行切换到其余全部语言 |

文件重命名必须使用 `git mv`，保留文件历史。仓库内脚本（预检、打包、文档校验）常以文件名字符串作白名单，须同步修改，否则推送后校验失败。

### 2.3 章节结构（对应 [README章节规范](./README章节规范.md)）

| 编号 | 检查项 | 判定方法 | 通过标准 |
| --- | --- | --- | --- |
| C1 | 章节齐全 | 提取二级标题与 20 章清单比对 | 20 章全部存在，无缺章 |
| C2 | 章节命名 | 逐条比对标题文字 | 与规范用词一致，不使用「核心亮点」「设计细节与小巧思」等变体 |
| C3 | 章节顺序 | 按出现顺序比对 | 与规范顺序一致 |
| C4 | 扩展章节 | 检查是否存在额外章节 | 额外内容以「附录」形式置于 20 章之后，不插入正文顺序 |
| C5 | 语言版本对应 | 比对中英二级标题数量与顺序 | 两种语言一一对应 |

正文出现与规范不符的章节名时，以规范用词为准统一；章节内含大量既有内容时，优先改名而不重写正文。

### 2.4 双语同步（对应 [多语言规范](./多语言规范.md)）

| 编号 | 检查项 | 判定方法 | 通过标准 |
| --- | --- | --- | --- |
| D1 | 版本号一致 | 检索版本字符串 | 两种语言写同一版本号与状态 |
| D2 | 数字一致 | 比对功能数、测试数、平台数 | 同一指标在两版数值相同 |
| D3 | 链接一致 | 比对相对链接集合 | 两版指向同一批文件 |
| D4 | 术语一致 | 抽查专业术语 | 同一概念在两版使用同一译名 |
| D5 | 结构一致 | 比对表格与列表数量 | 章节内表格、列表数量相同 |

任一版本修改事实性内容后，另一版本须在同一提交内更新，不允许跨提交补译。

### 2.5 链接与内容（对应 [通用写作规范](./通用写作规范.md)）

| 编号 | 检查项 | 判定方法 | 通过标准 |
| --- | --- | --- | --- |
| E1 | 相对链接可达 | 逐个解析并检查文件是否存在 | 断链数为 0 |
| E2 | 代码块语言标识 | 检索围栏 | 全部标注语言，无裸围栏 |
| E3 | 表格列数 | 逐表核对分隔行与数据行 | 列数一致 |
| E4 | 禁用表达 | 检索口语词、感叹号、省略号、表情符号 | 无命中；引用原文时须置于引号内并标注出处 |
| E5 | 未验证数据 | 检索性能数字 | 每个数字均有测试环境与测试方法 |
| E6 | 承诺性表述 | 检索「保证」「永久」「彻底」一类词 | 技术限定语可保留，对外承诺性表述须删除 |

### 2.6 社区文件与推送（对应 [文档矩阵](./文档矩阵.md)、[推送与发布规范](./推送与发布规范.md)）

| 编号 | 检查项 | 判定方法 | 通过标准 |
| --- | --- | --- | --- |
| F1 | 必备文件齐备 | 列目录 | `LICENSE`、`NOTICE`、`CONTRIBUTING.md`、`SECURITY.md` 齐备 |
| F2 | 许可与 NOTICE 一致 | 比对分层路由表 | 目录级许可与 NOTICE 声明一致 |
| F3 | 忽略规则 | 检索 `.gitignore` | 构建产物、依赖目录、`.DS_Store`、`.workbuddy/` 均被忽略 |
| F4 | 提交信息 | 查看 `git log` | 符合 `<type>(<scope>): <subject>` |
| F5 | 远程一致 | 比对本地 `HEAD` 与 `origin/main` | 两者相同，工作区干净 |

## 3. 多语言仓库的附加检查

仓库存在三种以上语言版本时，在上述检查之外增加三项：

1. **章节标题逐语言核对**：每种语言的 20 章标题均须与其中文或英文基准含义一致，不得出现某语言缺章；
2. **表格行数一致**：项目清单、状态表、参数表在各语言版本中行数相同；
3. **术语表同步**：术语对照表置于双语共用的独立文件，各语言版本引用同一份。

## 4. 常见错误与处置

| 错误 | 现象 | 处置 |
| --- | --- | --- |
| 批量改章节号时误判中文数字 | 「十、」被识别为「二十、」，第 10 章被覆盖为第 20 章标题 | 改为显式「旧串 → 新串」一对一替换，逐条断言命中后再写入 |
| 只改链接路径未改显示文字 | 链接可点，但正文仍写旧章节名 | 全文检索旧章节名，路径与显示文字同时更新 |
| 重命名文件未同步脚本 | 本地文档正常，推送后校验脚本报错 | 检索仓库内全部文件名字符串，含脚本、配置与文档示例 |
| 双语只改一侧 | 两版事实不一致 | 以仓库实际状态为准，先改主版本，再同提交改另一版本 |
| 索引页未同步 | 新增文件不在索引中，被判定为孤岛 | 新增文件后立即更新索引计数与条目，并复查域名计数之和 |
| 仓库简介与正文口径不一致 | About 区写七个项目，正文写九个 | 以正文清单为准更新简介，并在提交信息中注明 |

文件命名：B1 {{ }} B2 {{ }} B3 {{ }} B4 {{ }} B5 {{ }}

## 6. 字段定义

| 字段 | 含义 | 取值 |
| --- | --- | --- |
| 仓库名 | 被检查仓库的全名 | `所有者/仓库` |
| 规范版本 | 本次检查依据的规范集状态 | 提交号或版本号 |
| 通过 | 该项符合通过标准 | 布尔 |
| 放行结论 | 检查结果的处置 | 通过 / 有条件通过 / 阻断 |
