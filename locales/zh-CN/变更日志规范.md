# 变更日志规范

> 本文件解决什么问题：定义面向使用者的版本变更记录模板、字段与写法，保证每次变更可追溯、版本可对应、升级路径可判断。

## 1. 规范条文

1. 变更日志遵循 Keep a Changelog 结构，版本号遵循 [版本管理规范](./版本管理规范.md) 的语义化版本。
2. 每个版本须有发布日期，格式 `YYYY-MM-DD`；未发布内容置于 `Unreleased` 段。
3. 条目按六类分组：`Added` 新增 / `Changed` 变更 / `Deprecated` 废弃 / `Removed` 移除 / `Fixed` 修复 / `Security` 安全。
4. 每条变更面向使用者，须说明影响与迁移方式，不写内部重构细节。
5. 破坏性变更须标注 `BREAKING CHANGE:` 并给出迁移步骤（见 [迁移指南规范](./迁移指南规范.md)）。
6. 版本号须与 tag、Release Notes 一致；破坏性变更须与提交信息中的 `feat!:` 或 `BREAKING CHANGE:` 对应。

## 2. 变更日志模板

```markdown
# 变更日志

本文件记录所有面向使用者的变更。格式依据 Keep a Changelog，版本遵循语义化版本。

## [Unreleased]

### Added
- {{新增能力，说明对使用者的价值}}

### Changed
- {{行为变更，说明影响范围}}

### Deprecated
- {{即将移除的能力，说明替代方案与移除版本}}

### Removed
- {{已移除的能力，说明迁移路径}}

### Fixed
- {{缺陷修复，说明触发条件}}

### Security
- {{安全修复，说明影响与升级建议}}

## [{{X.Y.Z}}] - {{YYYY-MM-DD}}

### {{类型}}
- {{变更条目}}
- {{BREAKING CHANGE: 原行为 → 新行为；迁移步骤见链接}}

[Unreleased]: https://github.com/{{owner}}/{{repo}}/compare/v{{X.Y.Z}}...HEAD
[{{X.Y.Z}}]: https://github.com/{{owner}}/{{repo}}/compare/v{{prev}}...v{{X.Y.Z}}
```

## 3. 条目模板

```markdown
- {{动词开头的一句话变更描述}}（{{关联 REQ 编号}}）
  - 影响：{{哪些使用者或场景受影响}}
  - 迁移：{{需要执行的动作；无则省略此行}}
  - 参考：{{Issue / PR 链接}}
```

## 4. 字段定义

| 字段 | 必填 | 类型 | 填写要点 | 示例 |
| --- | --- | --- | --- | --- |
| 版本号 | 是 | `X.Y.Z` | 与 tag 完全一致，不带前缀 `v` 亦可，但全文统一 | `1.2.0` |
| 发布日期 | 是 | `YYYY-MM-DD` | 以 tag 打点日期为准 | `2026-11-18` |
| 分组类型 | 是 | 枚举 | 六类之一；无该类条目时整段省略 | `Fixed` |
| 变更描述 | 是 | 文本 | 动词开头，面向使用者，说明价值 | `新增对 GFM 表格的检查` |
| 影响 | 条件必填 | 文本 | 行为变更、废弃、移除、破坏性变更时必填 | `旧配置文件需重命名` |
| 迁移 | 条件必填 | 文本 | 破坏性变更必填，指向迁移指南 | `见迁移指南 v1.0` |
| BREAKING CHANGE | 条件必填 | 标记 | 破坏性变更必填，置于条目开头 | `BREAKING CHANGE:` |
| 对比链接 | 是 | URL | 每个版本段均须提供 compare 链接 | `compare/v1.1.0...v1.2.0` |
| 关联 REQ | 否 | 列表 | 便于与需求追踪矩阵对照 | `REQ-007` |

## 5. 填写说明

1. **条目粒度**：一条变更描述一个使用者可感知的结果；多个结果拆为多条。
2. **动词开头**：使用「新增」「支持」「修复」「移除」「废弃」「调整」，不使用「更新了」「做了一些」。
3. **禁止内容**：无日期条目、内部重构、开发计划、路线图内容、模糊表述（「优化体验」「修复若干问题」）。
4. **破坏性变更**：须同时具备 `BREAKING CHANGE:` 标记、影响说明、迁移步骤、迁移指南链接，四者缺一不可。
5. **废弃项**：须写明替代方案与计划移除的版本号，例如「将于 v2.0 移除」。
6. **Unreleased**：合并后即时登记，不积压到发版当天补写。
7. **一致性**：版本号、发布日期须与 tag、Release Notes、部署记录三处一致；不一致时以 tag 为准并修正其余三处。

常见错误：

| 错误写法 | 问题 | 修正方式 |
| --- | --- | --- |
| 「重构内部模块结构」 | 属内部细节，使用者无感 | 删除，或改写为可感知的效果 |
| 「修复若干问题」 | 不可判定 | 逐条列出修复内容 |
| 破坏性变更只说「有变更」 | 无迁移路径 | 补影响、迁移步骤与指南链接 |
| 版本号与 tag 不一致 | 版本对应关系断裂 | 以 tag 为准统一 |
| 无 compare 链接 | 无法查看差异 | 补 GitHub compare URL |

## 6. 完整示例

```markdown
## [1.0.0] - 2026-11-20

### Added
- 新增中英文混排空格检查规则（REQ-001），支持命令行直接调用。
- 新增 JSON 报告输出，便于接入 CI 统计。

### Changed
- BREAKING CHANGE: 配置文件名由 `.mdlint.json` 改为 `.mdlintrc.json`。旧文件将不再被读取；迁移步骤见[迁移指南](./迁移指南规范.md)。

### Deprecated
- `--format=table` 参数将于 v2.0 移除，请改用 `--reporter=table`。

### Fixed
- 修复中文标点紧邻英文单词时误报的问题。

### Security
- 修复规则插件加载路径可被外部输入覆盖的问题；建议所有使用者升级至 v1.0.0。

[1.0.0]: https://github.com/example/markdown-lint-cli/compare/v0.9.3...v1.0.0
```
