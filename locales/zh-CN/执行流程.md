# 执行流程

> 本文件解决什么问题：定义从立项到交付的完整阶段序列、每阶段的进入条件与产出物，以及信息不足时的阻断式提问规则。

## 1. 总控推送流程（Phase 0–6）

### Phase 0 · 立项（Project Init）

输出：项目名候选 3 个 + 选用理由 + 重名检索结论 + 仓库元数据表（description / topics / 默认分支 / 可见性 / license）。命名规则见 [项目命名规范](./项目命名规范.md)。

### Phase 1 · 盘点（Inventory）

扫描仓库，产出结构化清单：
- 技术栈、入口文件、包管理器、lockfile
- 已有文档、缺失文档
- 仓库体积 Top10 大文件
- 已有 CI / 模板 / 保护规则
- 当前 git 状态：未跟踪文件、未提交改动、历史中的可疑提交

### Phase 2 · 并行审核（Audit）

按 [审核维度矩阵](./审核维度矩阵.md) 把维度分派给子 agent 并行执行，分派方式见 [子Agent分派契约](./子Agent分派契约.md)。每个子 agent 只返回结构化结论，不返回长篇散文。

### Phase 3 · 修复（Fix）

按 P0 → P1 → P2 顺序列出待办，标注责任 agent 与预计动作。P0 未清零不得进入 Phase 5。

### Phase 4 · 文档生成（Docs）

按 [文档矩阵](./文档矩阵.md) 逐个文件分派给文档 agent。**一次只写一个文件，写完校验再下一个。**

### Phase 5 · 推送（Push）

按 [推送与发布规范](./推送与发布规范.md) 执行，逐条回显结果。

### Phase 6 · 推送后（Post-Push）

打 tag、写 Release Notes、校验徽章与链接可用、确认 CI 绿、确认 About 区信息正确。

## 2. 文档生成流程（阶段 0–5）

按阶段顺序推进，前一阶段未完成不得进入下一阶段。

| 阶段 | 名称 | 进入条件 | 产出 |
| --- | --- | --- | --- |
| 0 | 信息核验 | 收到本规范与项目材料 | 已确认信息清单、缺失信息清单 |
| 1 | 阻断式提问 | 存在必填字段缺失（见 [信息采集与模板](./信息采集与模板.md)） | 结构化提问清单，按字段分组 |
| 2 | 框架确认 | 必填字段齐备 | README 章节目录与各章要点提纲，供用户确认 |
| 3 | 文档生成 | 用户确认框架，或明确表示无需确认 | 全部交付物 |
| 4 | 质量门禁 | 文档生成完成 | [质量门禁](./质量门禁.md) 逐项判定结果 |
| 5 | 交付 | 门禁全部通过或已标注未通过项 | 按 [审核报告格式](./审核报告格式.md) 顺序输出，附推送指引 |

## 3. 阶段 1 提问规则

1. 按字段分组提问，单轮不超过 15 项。
2. 每个问题须说明用途与影响的章节，便于用户判断优先级。
3. 用户明确表示某项无法提供时，在文档对应位置标注「【待确认：字段名】」，并在文末汇总。
4. 用户答复「按你的判断」时，可以给出建议值，但须标注「【建议值，待用户确认】」。
