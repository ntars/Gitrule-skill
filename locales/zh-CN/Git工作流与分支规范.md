# Git工作流与分支规范

> 本文件解决什么问题：定义分支模型、命名规则、拉取请求描述模板与合并策略，保证主线稳定、协作有序、变更可追溯。

## 1. 规范条文

1. 默认分支（`main` 或 `master`）须受保护，禁止直接 push（对应硬规则 H7）。
2. 所有变更经个人分支 + 拉取请求合入主干。
3. 长期分支与短期分支须明确划分，避免分支长期不合并。
4. 禁止对公共分支 `git push --force`；改写个人分支用 `--force-with-lease`（对应 H8）。
5. 禁止对已推送的公共分支做 rebase/amend；合并前须通过 CI 与代码审查。

## 2. 分支模型

| 分支类型 | 生命周期 | 从何创建 | 合并到 | 命名格式 | 示例 |
| --- | --- | --- | --- | --- | --- |
| 默认分支 | 长期 | — | — | `main` | `main` |
| 功能分支 | 短期，≤2 周 | `main` | `main` | `feat/<简述>` | `feat/user-login` |
| 修复分支 | 短期，≤1 周 | `main` | `main` | `fix/<简述>` | `fix/token-expiry` |
| 文档分支 | 短期 | `main` | `main` | `docs/<简述>` | `docs/api-guide` |
| 发布分支 | 中期 | `main` | `main` + tag | `release/<版本>` | `release/1.2.0` |
| 紧急修复 | 短期，≤24 小时 | 发布 tag | `main` + tag | `hotfix/<简述>` | `hotfix/payment-error` |

命名规则：小写 kebab-case，简述须能表达意图，禁止 `test`、`temp`、`wip`、`my-xxx`；关联需求时附加需求编号，例如 `feat/spacing-rule-req001`。

## 3. 拉取请求描述模板

```markdown
## 变更目的
{{一句话说明为什么需要此变更，关联需求编号}}

## 变更内容
- {{具体改动 1}}
- {{具体改动 2}}

## 影响范围
- 受影响模块：{{模块名}}
- 是否破坏兼容：{{是 / 否；是则给出迁移说明}}
- 是否涉及配置或数据迁移：{{是 / 否；是则说明}}

## 验证方式
- 自测命令：{{命令}}
- 新增或修改的测试：{{TC 编号}}
- CI 运行地址：{{URL}}

## 关联
- 需求：{{REQ-NNN}}
- 追踪矩阵：{{已更新 / 待更新}}
- 文档：{{docs/api.md#章节 / 无}}
- Issue：{{#编号 / 无}}

## 自查
- [ ] 提交信息符合规范
- [ ] 未包含敏感信息
- [ ] 已更新需求追踪矩阵
- [ ] 破坏性变更已写入变更日志
```

## 4. 字段定义

| 字段 | 必填 | 类型 | 填写要点 | 示例 |
| --- | --- | --- | --- | --- |
| 分支简述 | 是 | kebab-case | 能独立表达意图，禁止无信息词 | `spacing-rule` |
| 关联需求 | 是 | `REQ-NNN` | 与立项编号一致 | `REQ-001` |
| 变更目的 | 是 | 文本 | 说明「为什么」，不是「改了什么」 | `修复中文标点误报` |
| 影响范围 | 是 | 文本 | 须明确是否破坏兼容 | `否` |
| 自测命令 | 是 | 命令 | 可复制执行 | `npm test -- -t spacing` |
| 测试编号 | 是 | `TC-NNN` | 与测试规范编号一致 | `TC-001` |
| CI 地址 | 是 | URL | 便于审查者核对 | `https://github.com/.../runs/123` |
| 自查清单 | 是 | 勾选 | 逐项勾选，禁止整段一次勾完 | — |

## 5. 填写说明

1. **分支生命周期**：超过 2 周未合并的功能分支须在迭代回顾中说明原因并拆分或关闭。
2. **简述命名**：从变更目的中取核心名词 + 动作，禁止使用 `fix2`、`new-feature` 等模糊名。
3. **变更目的**：写问题与价值；「更新代码」「优化逻辑」不合格。
4. **影响范围**：勾选破坏兼容时，须同时在变更日志中标注 `BREAKING CHANGE:`。
5. **自测命令**：审查者应能直接复制执行并得到相同结论；步骤复杂的写脚本路径。
6. **追踪矩阵**：PR 合并前须更新 [需求追踪矩阵规范](./需求追踪矩阵规范.md) 中的实现 PR 与状态字段。
7. **force push**：仅对未被他人审查的本人分支使用 `--force-with-lease`，且须在 PR 中说明原因。

常见错误：

| 错误写法 | 问题 | 修正方式 |
| --- | --- | --- |
| 分支名 `test`、`temp` | 无意图信息 | 改为 `feat/<具体能力>` |
| PR 描述只写「修复 bug」 | 无法审查影响 | 补目的、影响、验证方式 |
| 直接向 `main` push | 违反 H7 | 走 PR 合并 |
| 改写已审查分支后强推 | 审查结论失效 | 新增提交回应意见 |
| 合并后不删除源分支 | 分支列表膨胀 | 合并后立即删除 |

## 6. 完整示例

```markdown
## 变更目的
修复中文标点紧邻英文单词时空格规则误报的问题（REQ-004）。

## 变更内容
- 规则引擎增加标点边界判断
- 新增对应回归用例

## 影响范围
- 受影响模块：spacing 规则
- 是否破坏兼容：否
- 是否涉及配置或数据迁移：否

## 验证方式
- 自测命令：`npm test -- -t "中文标点"`
- 新增或修改的测试：TC-007-regression-142
- CI 运行地址：https://github.com/example/markdown-lint-cli/actions/runs/128

## 关联
- 需求：REQ-004
- 追踪矩阵：已更新
- 文档：无
- Issue：#142

## 自查
- [x] 提交信息符合规范
- [x] 未包含敏感信息
- [x] 已更新需求追踪矩阵
- [x] 破坏性变更已写入变更日志（本变更无破坏性）
```
