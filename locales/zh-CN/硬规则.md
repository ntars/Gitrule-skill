# 硬规则

> 本文件解决什么问题：列出违反任意一条即阻断推送、不允许「先推上去再改」的不可违背规则。

## 硬规则表

| # | 规则 |
|---|---|
| H1 | 仓库名必须符合 [项目命名规范](./项目命名规范.md)，大小写、字符、长度全部合规 |
| H2 | 必须有 `LICENSE` 文件；无许可证 = 默认版权保留，不得公开 |
| H3 | 不得提交任何密钥、令牌、私钥、`.env`、云厂商 AK/SK、数据库连接串 |
| H4 | 不得提交构建产物、依赖目录、IDE 配置、系统垃圾文件 |
| H5 | 单文件不得超过 100MB；超过 50MB 必须走 LFS 或排除 |
| H6 | 必须有 `README.md`，且包含：一句话定位、安装、最小可运行示例、许可证 |
| H7 | 默认分支必须受保护，禁止直接 push 到 `main`/`master` |
| H8 | 禁止对公共分支使用 `git push --force`；个人分支只允许 `--force-with-lease` |
| H9 | 推送前 `build` 与 `test` 必须通过；CI 红则不得合并入主干 |
| H10 | 提交信息必须符合 Conventional Commits，禁止 `wip`/`update`/`fix bug` 这类无信息提交 |
| H11 | 每个文档独立成文件、独立职责；禁止把所有内容堆进 README（见 [文档矩阵](./文档矩阵.md)） |
| H12 | 一旦密钥已推送，必须立即轮换密钥 + 清理历史，不得只做删除提交 |

## 执行约束

- 违反任意一条即 **阻断推送**，不允许「先推上去再改」。
- H1–H12 的判定结果须体现在 [审核报告格式](./审核报告格式.md) 的问题清单中，每条带证据（路径:行 / 命令输出）。
- 违反 H12 时按 [推送与发布规范](./推送与发布规范.md) 的事故处理流程执行。
