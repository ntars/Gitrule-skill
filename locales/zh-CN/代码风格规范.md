# 代码风格规范

> 本文件解决什么问题：定义代码风格配置模板、命名约定表、注释规则与填写说明，减少风格分歧、提升可读性与审查效率。

## 1. 规范条文

1. 风格规则以自动化工具为准，人工只处理工具无法覆盖的部分。
2. 格式化配置须随仓库提交（如格式化配置文件），保证不同环境一致。
3. CI 须集成格式检查，不通过则不得合并（见 [测试规范](./测试规范.md)）。
4. 不得使用魔法数字与硬编码常量，须提取为具名常量。
5. 行尾统一 LF，文件以换行结尾（对应维度 D3 仓库卫生）。

## 2. 风格配置模板

```markdown
# 代码风格约定：{{项目名称}}

配置版本：{{v1.0}} ｜ 适用语言与版本：{{如 TypeScript 5.x}} ｜ 格式化工具：{{如 Prettier 3.x}}

## 格式规则（工具强制）
| 规则 | 取值 | 工具配置项 | 是否可协商 |
| --- | --- | --- | --- |
| 缩进 | {{2 空格 / 4 空格 / Tab}} | {{配置项名}} | 否 |
| 行宽 | {{100 字符}} | {{配置项名}} | 否 |
| 引号 | {{单引号 / 双引号}} | {{配置项名}} | 否 |
| 行尾 | LF | `endOfLine: lf` | 否 |
| 文件末尾换行 | 必须有 | 工具默认 | 否 |
| 分号 | {{有 / 无}} | {{配置项名}} | 否 |

## 命名约定（工具无法强制，人工审查）
| 对象 | 规则 | 正例 | 反例 |
| --- | --- | --- | --- |
| 变量 | {{camelCase}} | `userName` | `UserName` |
| 常量 | {{UPPER_SNAKE_CASE}} | `MAX_RETRY` | `maxRetry` |
| 函数 | {{动词开头 camelCase}} | `parseConfig` | `configParse` |
| 类 / 类型 | {{PascalCase}} | `ConfigLoader` | `config_loader` |
| 文件名 | {{kebab-case}} | `config-loader.ts` | `ConfigLoader.ts` |
| 布尔值 | {{is/has/can 前缀}} | `isValid` | `valid` |
| 集合 | {{复数名词}} | `items` | `itemList` |

## 注释规则
- 必须写注释的场景：{{公开 API 的契约、非直观算法、绕开限制的临时方案}}
- 禁止的注释：{{复述代码、无信息量、失效的旧注释、情绪化表述}}
- 注释语言：{{与项目主语言一致}}
- TODO 格式：`// TODO({{负责人}}): {{事项}} — {{计划版本}}`

## 文件组织
1. 导入顺序：{{标准库 → 第三方 → 本地模块，组内字典序}}
2. 声明顺序：{{常量 → 类型 → 函数 → 导出}}
3. 单文件行数上限：{{300 行，超出须拆分}}

## 例外清单
| 场景 | 例外规则 | 批准人 | 有效期 |
| --- | --- | --- | --- |
| {{如生成代码}} | {{不参与格式化}} | {{姓名}} | {{至 v2.0}} |
```

## 3. 配置字段定义

| 字段 | 必填 | 类型 | 填写要点 | 示例 |
| --- | --- | --- | --- | --- |
| 配置版本 | 是 | 文本 | 风格规则变更时递增 | `v1.0` |
| 适用语言与版本 | 是 | 文本 | 明确主版本，避免规则漂移 | `TypeScript 5.x` |
| 格式化工具 | 是 | 文本 | 与 lockfile 中的版本一致 | `Prettier 3.2` |
| 规则.取值 | 是 | 枚举 / 数值 | 须唯一，禁止「看情况」 | `2 空格` |
| 是否可协商 | 是 | 枚举 | 否 / 是；标「是」须给出协商条件 | `否` |
| 命名正例 | 是 | 代码 | 从项目现有代码中选取 | `parseConfig` |
| 命名反例 | 是 | 代码 | 须为真实易犯写法 | `configParse` |
| TODO 负责人 | 是 | 文本 | 禁止写「团队」 | `张三` |
| 例外有效期 | 是 | 版本 / 日期 | 到期须复核 | `至 v2.0` |

## 4. 填写说明

1. **工具优先**：能被工具强制的规则一律写入格式化配置，不靠人工记忆；人工只管命名、注释、文件组织。
2. **行宽取值**：须结合审查界面宽度设定，常见为 100 或 120；一旦确定不得在个别文件中覆盖。
3. **命名正例**：从项目现有代码中选取真实存在的名称，禁止使用教科书式占位符。
4. **布尔命名**：`is`/`has`/`can` 前缀须与语义一致；`isReady` 不得表示动作。
5. **TODO**：必须含负责人、事项与计划版本；无计划的 TODO 不得进入主干。
6. **例外清单**：每项例外须有批准人与有效期；到期未复核自动失效。

常见错误：

| 错误写法 | 问题 | 修正方式 |
| --- | --- | --- |
| 「代码尽量简洁」 | 不可判定 | 改为可检查规则，如函数长度上限 |
| 命名表只有规则无反例 | 审查时无法对照 | 补真实易犯反例 |
| 注释写「这里之前有 bug」 | 无信息且易失效 | 改为说明当前行为与原因 |
| TODO 无负责人 | 无人跟进 | 补负责人与计划版本 |
| 例外无有效期 | 永久豁免 | 补有效期与复核人 |

## 5. 完整示例

```markdown
# 代码风格约定：markdown-lint-cli

配置版本：v1.0 ｜ 适用语言与版本：TypeScript 5.x ｜ 格式化工具：Prettier 3.2

## 格式规则（工具强制）
| 规则 | 取值 | 工具配置项 | 是否可协商 |
| --- | --- | --- | --- |
| 缩进 | 2 空格 | `tabWidth: 2` | 否 |
| 行宽 | 100 字符 | `printWidth: 100` | 否 |
| 引号 | 单引号 | `singleQuote: true` | 否 |
| 行尾 | LF | `endOfLine: lf` | 否 |
| 分号 | 有 | `semi: true` | 否 |

## 命名约定（人工审查）
| 对象 | 规则 | 正例 | 反例 |
| --- | --- | --- | --- |
| 函数 | 动词开头 camelCase | `parseRules` | `rulesParser` |
| 常量 | UPPER_SNAKE_CASE | `DEFAULT_RULES` | `defaultRules` |
| 文件名 | kebab-case | `rule-loader.ts` | `RuleLoader.ts` |

## 注释规则
- 必须写注释的场景：规则的匹配语义、对上游 API 行为的绕行处理。
- 禁止的注释：复述代码、「修复了一个 bug」、无负责人 TODO。
- TODO 格式：`// TODO(王五): 替换临时解析器 — v2.0`

## 例外清单
| 场景 | 例外规则 | 批准人 | 有效期 |
| --- | --- | --- | --- |
| fixtures 目录 | 不参与格式化 | 李四 | 至 v2.0 |
```
