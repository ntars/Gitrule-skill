# README章节规范

> 本文件解决什么问题：定义各语言目录的 README 必须包含的 20 个章节、各章必须包含与不得出现的内容，以及版权行标准格式。

## 1. 章节总要求

以下 20 章必须全部存在，顺序固定，各语言版本一一对应。

| 序号 | 章节 | 必须包含 | 不得出现 |
| --- | --- | --- | --- |
| 1 | 项目名称与定位 | 项目名、仓库描述（国家语言与英语双语对照）、话题标签（5–10 个）、一句话定位、语言切换链接、当前版本、维护状态 | 空泛形容词；仓库描述超过 120 字符；话题标签大小写混用 |
| 2 | 项目简介 | 背景、待解决问题、核心思路、适用场景、不适用场景，以及分列的优势与局限（局限须含影响范围与规避方式） | 一句话带过；只列优势不列局限 |
| 3 | 核心功能 | 按模块分组的功能条目，每条含触发条件与结果 | 仅列功能名 |
| 4 | 核心亮点 | 按 [亮点与工程取舍写法](./亮点与工程取舍写法.md) 结构展开 | 无证据的夸赞 |
| 5 | 设计细节与工程取舍 | 按 [亮点与工程取舍写法](./亮点与工程取舍写法.md) 结构展开 | 与功能重复的描述 |
| 6 | 技术栈与依赖清单 | 运行时、构建、测试工具链及版本约束；依赖明细指向 NOTICE | 缺版本号 |
| 7 | 安装与部署 | 环境要求、安装步骤、验证命令、升级与卸载方式、容器化说明 | 跳步或省略验证 |
| 8 | 快速开始 | 最小可运行示例，含完整命令与预期输出 | 无法执行的伪代码 |
| 9 | 配置说明 | 配置项表格（键名、类型、默认值、必填、取值范围、作用、示例）、配置优先级、热更新支持 | 缺默认值 |
| 10 | API 或模块说明 | 接口签名、参数、返回值、错误码、调用示例、限流与配额 | 缺错误码 |
| 11 | 目录结构 | 树形结构与每层职责说明 | 逐文件罗列无说明 |
| 12 | 性能表现 | 测试环境、测试方法、指标数据、瓶颈分析、调优建议 | 无测试条件的数字 |
| 13 | 安全与隐私 | 数据收集与存储、传输加密、权限模型、漏洞上报渠道、已知风险 | 承诺绝对安全 |
| 14 | 兼容性说明 | 操作系统、运行时、浏览器、数据库版本矩阵，明确不支持项 | 含糊表述 |
| 15 | 已知问题与限制 | 已知问题（描述、影响范围、临时规避方案、跟踪链接）、当前限制、未实现功能清单（功能、未实现原因、计划状态） | 隐瞒严重缺陷；把未实现功能写成已实现 |
| 16 | 更新日志 | 遵循 Keep a Changelog 结构，版本号遵循语义化版本 | 无日期的条目 |
| 17 | 后续路线图 | 计划项、状态、目标版本，标注「非承诺」 | 承诺交付时间 |
| 18 | 参与贡献 | 开发环境搭建、分支模型、提交规范、PR 要求、行为准则、Issue 模板 | 仅写「欢迎 PR」 |
| 19 | 版权与许可 | 版权行、许可证名称、SPDX 标识符、许可证全文位置 | 缺著作权人 |
| 20 | NOTICE 合规声明 | 第三方依赖摘要、指向 NOTICE 文件的相对链接 | 用本章替代 NOTICE |

## 1.1 门面四问与一句话文案

README 首屏须回答四个问题，顺序固定：

1. 项目做什么；
2. 项目解决什么问题；
3. 项目有什么特性；
4. 最小的 hello world 示例。

其中第 1 问对应「一句话定位」，须同时满足三点：说明项目类型、限定词精确、可被直接复述。成熟项目的公开文案可作参照：

| 项目 | 一句话文案 | 结构分析 |
| --- | --- | --- |
| Angular | One framework. Mobile & desktop. | 品类 + 覆盖范围 |
| React | A declarative, efficient, and flexible JavaScript library for building user interfaces. | 三个限定词 + 品类 + 用途 |
| Vue | A progressive, incrementally-adoptable JavaScript framework for building UI on the web. | 两个特性 + 品类 + 用途 |

写法约束：

- 不得使用「强大」「优秀」「革命性」等无信息形容词；
- 须给出品类词（库、框架、工具、应用），使读者一眼归类；
- 特性限定词不超过三个，避免堆砌；
- 中文版本须控制在 60 字以内，英文版本控制在 25 词以内。

第 3 问「有什么特性」须同时披露不适用场景。有效写法示例：说明某消息中间件「仅支持 QoS 级别 0，需要级别 1 的场景不适用」；无效写法为只罗列优点。特性对比须基于可验证事实，不得贬损同类项目。

第 4 问的 hello world 示例须在两步内完成安装与运行；安装步骤繁琐的项目应提供容器镜像或在线演示环境，避免读者在看完 README 后放弃。
