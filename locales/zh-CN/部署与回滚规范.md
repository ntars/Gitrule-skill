# 部署与回滚规范

> 本文件解决什么问题：定义部署清单、变更单与回滚预案的模板、字段和执行标准，保证上线可控、状态可查、故障可快速恢复。

## 1. 规范条文

1. 部署前须通过 CI、代码审查与质量门禁（见 [质量门禁](./质量门禁.md)）。
2. 部署基于已打 tag 的发布版本，不使用未标记提交（见 [版本管理规范](./版本管理规范.md)）。
3. 环境配置与代码分离，敏感配置通过配置管理注入，不入库（见 [安全与隐私规范](./安全与隐私规范.md)）。
4. 数据库结构变更通过迁移脚本执行，且须满足向前兼容（见 [数据库设计规范](./数据库设计规范.md)）。
5. 每次部署须记录版本号、时间、操作人与变更内容；无记录的部署视为不合规部署。
6. 每个版本须预先准备回滚预案，未准备回滚预案不得上线。
7. 部署后须执行健康检查与冒烟验证，两项均通过方可结束发布。

## 3. 部署记录模板

```markdown
## {{YYYY-MM-DD}} {{vX.Y.Z}} → {{环境}}

- 版本号：{{vX.Y.Z}}
- tag：{{vX.Y.Z}}
- 时间：{{HH:MM}}
- 操作人 / 审批人：{{姓名 / 姓名}}
- 变更摘要：{{一句话}}
- 健康检查：{{通过 / 未通过}}
- 结果：{{成功 / 回滚}}
- 关联发布：{{Release Notes URL}}
- 备注：{{异常与处理记录；无则写「无」}}
```

## 4. 字段定义

| 字段 | 必填 | 类型 | 填写要点 | 示例 |
| --- | --- | --- | --- | --- |
| tag | 是 | 文本 | 与 [版本管理规范](./版本管理规范.md) 的 tag 完全一致 | `v1.2.0` |
| 目标环境 | 是 | 枚举 | 预发布 / 生产，不得混用配置 | `生产` |
| 变更项.类型 | 是 | 枚举 | 新增 / 修改 / 移除 | `修改` |
| 关联需求 | 是 | 列表 | REQ 编号，无需求变更写「无」 | `REQ-007` |
| 灰度比例 | 否 | 百分比 | 逐步放量时必填 | `10% → 50% → 100%` |
| 判定条件 | 是 | 阈值 | 可观测、可判定 | `HTTP 200` |
| 实际版本号 | 是 | 文本 | 与计划版本号不同时须说明原因 | `v1.2.1` |
| 回滚触发条件 | 是 | 阈值 + 时长 | 禁止「感觉异常」类表述 | `错误率 >1% 持续 5 分钟` |
| 数据兼容性 | 是 | 文本 | 明确是否需要数据回滚 | `无需数据回滚` |

## 5. 填写说明

1. **前置检查**：逐项勾选，禁止整段一次性勾选；任一项未完成即中止部署。
2. **变更内容**：每条须关联 REQ 编号；无需求关联的纯运维变更写「无」并说明变更依据。
3. **健康检查**：须为可自动判定的条件；「服务看起来正常」不合格。
4. **回滚触发条件**：须同时给出阈值与持续时间，避免瞬时抖动误触发。
5. **灰度放量**：每档放量后须观察规定时长，并记录观察结论，方可进入下一档。
6. **部署记录**：按时间追加，不覆盖历史；与推送、tag、Release Notes 三者版本号一致。
7. **回滚执行**：代码回滚用 `git revert` 生成反向提交，不对已公开历史强推（见 [推送与发布规范](./推送与发布规范.md)）。

常见错误：

| 错误写法 | 问题 | 修正方式 |
| --- | --- | --- |
| 用未打 tag 的提交部署 | 版本无法复现 | 先打 tag 再部署 |
| 回滚预案写「有问题就回滚」 | 无触发条件与步骤 | 补阈值、决策人、步骤 |
| 数据库变更不兼容旧版本 | 回滚后数据不可用 | 采用扩展-迁移-收缩三步法 |
| 部署记录事后补写 | 状态不可信 | 部署当时即时记录 |
| 健康检查只测首页 | 关键链路未验证 | 补主流程冒烟用例 |

## 6. 完整示例

```markdown
# 部署清单：markdown-lint-cli v1.0.0

版本：v1.0.0 ｜ tag：v1.0.0 ｜ 目标环境：生产 ｜ 计划时间：2026-11-20 10:00

## 前置检查
- [x] CI 全绿：https://github.com/example/markdown-lint-cli/actions/runs/123
- [x] 代码审查通过，审批人：李四
- [x] 质量门禁 A/B/C 全 PASS
- [x] 变更日志与 Release Notes 已就绪
- [x] 回滚预案已评审
- [x] 无数据库迁移
- [x] 配置变更清单已确认：无

## 变更内容
| 变更项 | 类型 | 影响范围 | 关联需求 | 验证方式 |
| --- | --- | --- | --- | --- |
| 中英文空格规则 | 新增 | 规则引擎 | REQ-001 | 执行 TC-001 |
| CLI 报告输出 | 修改 | 报告模块 | REQ-007 | 执行 TC-012 |

## 执行步骤
1. 拉取 v1.0.0 tag 并校验校验和
2. 灰度 10%，观察 10 分钟
3. 错误率 <0.1% 后放量至 100%

## 健康检查与冒烟
| 检查项 | 判定条件 | 执行方式 | 结果 |
| --- | --- | --- | --- |
| 服务存活 | HTTP 200 | curl /healthz | 通过 |
| 关键链路 | 50 篇文档检查完成 | shell 脚本 | 通过 |
| 错误率 | <0.1% | 监控面板 | 通过 |

## 回滚预案
- 回滚目标版本：v0.9.3
- 触发条件：错误率 >1% 持续 5 分钟
- 决策人：李四
- 回滚步骤：切换部署标签至 v0.9.3 并执行数据兼容性检查
- 数据兼容性：无数据库变更，无需数据回滚
```
