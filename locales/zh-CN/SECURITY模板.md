# SECURITY模板

> 本文件解决什么问题：提供一份可直接复制的安全政策模板，供项目生成 SECURITY.md，明确支持版本、漏洞上报渠道、响应流程与披露原则；配套的填写说明覆盖上报渠道选型与敏感信息处理。

## 1. 使用说明

1. 复制第 3 节「模板正文」全部内容，新建为项目根目录的 `SECURITY.md`。
2. 按第 4 节替换占位符；上报渠道必须为真实可达且不公开暴露攻击面的地址。
3. 按第 5 节场景变体裁剪：无多版本维护的项目删除支持版本表中的旧版本行。
4. 安全规则与敏感信息要求见 [安全与隐私规范](./安全与隐私规范.md)；社区治理维度见 [审核维度矩阵](./审核维度矩阵.md)。

## 2. 定制原则

- **私有渠道优先**：漏洞上报走私有渠道，禁止要求报告者在公开议题中披露细节。
- **时效明确**：给出首次响应与修复的时间范围，避免无限期承诺。
- **信息最小化**：要求报告者提供复现所需最小信息，禁止提交真实生产数据。
- **法律一致**：披露原则须与适用法律和平台政策一致，涉监管行业须经法务审定。

## 3. 模板正文

```markdown
# 安全政策

> 本文件说明 {{项目名称}} 的安全支持范围与漏洞上报方式，适用于安全研究人员、贡献者与使用者。

## 支持版本

| 版本 | 是否接受安全报告 |
| --- | --- |
| {{当前版本}} | 是 |
| {{上一版本}} | {{是否接受}} |
| 更早版本 | 否 |

## 上报渠道

请勿通过公开议题、讨论区或社交渠道报告安全漏洞。请通过以下私有渠道提交：

- 安全邮箱：{{真实可达的安全邮箱}}
- 私有报告入口：{{私有漏洞报告地址}}

如无上述渠道，请通过 {{备用私有联系方式}} 联系维护者。

## 报告内容

为提高处理效率，请尽可能提供：

- 受影响版本与组件；
- 漏洞类型与潜在影响；
- 最小复现步骤或概念验证；
- 建议的修复方向（可选）。

请勿提交真实的生产数据、密钥或个人身份信息。

## 响应流程

| 阶段 | 时间范围 | 说明 |
| --- | --- | --- |
| 确认收到 | {{首次响应时限}} | 维护者确认报告已收到 |
| 初步评估 | {{评估时限}} | 判断是否属于安全问题及影响范围 |
| 修复与验证 | {{修复时限}} | 完成修复并验证，复杂问题另行协商 |
| 公开发布 | 修复完成后 {{发布延迟}} | 发布安全公告与修复版本 |

## 披露原则

- 维护者将对报告者身份与报告内容保密，直至修复发布。
- 未经维护者同意，报告者不得在修复发布前公开漏洞细节。
- 修复发布后，维护者将在安全公告中致谢报告者（经报告者同意）。
- 善意、符合本政策的安全研究不会被追究责任。

## 例外与免责

本政策不构成对任何安全保证的承诺，项目内容按「现状」提供，详见 [免责声明](./DISCLAIMER.md) 与 [LICENSE](./LICENSE)。
```

## 4. 占位符对照表与字段定义

| 占位符 | 必填 | 字段定义 | 填写示例 |
| --- | --- | --- | --- |
| `{{项目名称}}` | 是 | 项目对外名称 | `FooBar` |
| `{{当前版本}}` | 是 | 正在维护的最新版本或 `main` | `v2.3.0` |
| `{{上一版本}}` | 否 | 仍在维护的上一版本 | `v2.2.x` |
| `{{是否接受}}` | 是 | 该版本是否接受安全报告 | `是` |
| `{{真实可达的安全邮箱}}` | 是 | 专用于安全报告的邮箱 | `security@example.com` |
| `{{私有漏洞报告地址}}` | 是 | 私有报告入口 | `https://github.com/owner/repo/security/advisories/new` |
| `{{备用私有联系方式}}` | 否 | 主渠道不可用时的备用方式 | `通过维护者账号私信` |
| `{{首次响应时限}}` | 是 | 确认收到报告的时间范围 | `3 个工作日` |
| `{{评估时限}}` | 是 | 完成初步评估的时间范围 | `7 个工作日` |
| `{{修复时限}}` | 是 | 完成修复的时间范围 | `30 日` |
| `{{发布延迟}}` | 是 | 修复后公开发布的间隔 | `7 日` |

## 5. 填写说明与场景变体

| 场景 | 必留章节 | 可裁剪章节 | 调整要点 |
| --- | --- | --- | --- |
| 单版本项目 | 上报渠道、报告内容、响应流程、披露原则 | 支持版本表删除旧版本行 | 当前版本写 `main` 或最新 tag |
| 多版本维护 | 全部 | 无 | 逐行列出仍接受报告的版本 |
| 个人项目 | 全部 | 支持版本可精简 | 私有渠道用长期持有的邮箱 |
| 企业项目 | 全部 | 无 | 时限须与内部安全制度一致，经法务审定 |
| 受监管行业 | 全部 | 无 | 增补合规通报义务与数据留存要求 |

常见错误对照：

| 错误写法 | 后果 | 正确写法 |
| --- | --- | --- |
| 「请在 Issue 中报告漏洞」 | 公开披露细节，扩大风险 | 使用私有渠道 |
| 「我们会尽快处理」 | 无明确预期，报告者无法判断 | 分阶段给出时间范围 |
| 时限写「24 小时内修复」 | 承诺过度，无法兑现 | 写合理范围并注明复杂问题另行协商 |
| 未要求脱敏 | 报告者可能提交真实生产数据 | 明确禁止提交真实数据与密钥 |

## 6. 完整示例

以下为上报渠道段落的填好示例，仅作格式参考。

```markdown
## 上报渠道

请勿通过公开议题、讨论区或社交渠道报告安全漏洞。请通过以下私有渠道提交：

- 安全邮箱：security@example.com
- 私有报告入口：https://github.com/example/democli/security/advisories/new

请勿提交真实的生产数据、密钥或个人身份信息。
```
