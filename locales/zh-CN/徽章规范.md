# 徽章规范

> 本文件解决什么问题：定义 README 中徽章（Badge）的 URL 语法、样式参数、颜色编码、信息取舍、排列顺序与数量控制，以 Shields.io 为主要实现，给出可直接复制的格式示例与推荐参数配置。

本文件所述参数均依据 Shields.io 官方文档（Static Badge 与 Logos 页面、badge-maker 格式说明）核实；出现率数据来自本项目对头部开源项目 README 的抽样统计，标注为「实测」。

## 1. 基本语法

### 1.1 静态徽章 URL 结构

静态徽章通过 URL 路径传参，标准结构如下：

```text
https://img.shields.io/badge/<标签>-<消息>-<颜色>?style=<样式>&<其他查询参数>
```

三段路径以连字符 `-` 分隔：

| 段 | 名称 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| 第 1 段 | 标签（label） | 否 | 左侧文字，说明指标名称 |
| 第 2 段 | 消息（message） | 是 | 右侧文字，展示指标值 |
| 第 3 段 | 颜色（color） | 是 | 右侧背景色 |

两段式写法（省略标签，仅消息与颜色）同样合法：

```text
https://img.shields.io/badge/<消息>-<颜色>
```

### 1.2 字符转义规则

URL 路径中空格与特殊字符须转义，规则如下：

| 输入字符 | URL 写法 | 示例 |
| --- | --- | --- |
| 空格 | `_` 或 `%20` | `v0.1 prototype` → `v0.1%20prototype` |
| 下划线 `_` | `__`（双下划线） | `my_label` → `my__label` |
| 连字符 `-` | `--`（双连字符） | `dev-build` → `dev--build` |

用户提供的原型示例符合该语法，可直接使用：

```markdown
![Status](https://img.shields.io/badge/status-v0.1%20prototype-8957e5?style=flat-square)
```

其含义为：标签 `status`，消息 `v0.1 prototype`（空格用 `%20`），颜色 `8957e5`（十六进制紫），样式 `flat-square`。

### 1.3 Markdown 嵌入格式

```markdown
![版本](https://img.shields.io/badge/version-1.2.0-blue?style=flat-square)
```

需要点击跳转时，用链接包裹图片：

```markdown
[![许可证](https://img.shields.io/badge/license-MIT-blue.svg)](./LICENSE)
```

## 2. 样式参数（style）

`style` 决定徽章的整体视觉设计，可取五个值，默认值为 `flat`。

| 取值 | 视觉特征 | 适用场景 | 实测出现次数（N=120） |
| --- | --- | --- | --- |
| `flat` | 直角、扁平，Shields.io 默认 | 通用首选，与多数主题兼容 | 32 |
| `flat-square` | 直角、无圆角、略紧凑 | 追求规整、硬朗的门面 | 60 |
| `for-the-badge` | 大号粗体、高对比 | 顶部主视觉、强调性徽章 | 65 |
| `social` | 圆角、左右分色、扁平 | 社交风格门面 | 12 |
| `plastic` | 高光渐变、拟物 | 复古风格，现已较少使用 | 1 |

**推荐配置**：

- 同一 README 内所有徽章必须统一 `style`，禁止混用。这是视觉一致性的首要要求。
- 通用项目优先 `flat` 或 `flat-square`；需要强化品牌门面时统一使用 `for-the-badge`。
- 实测中 `for-the-badge`（65 次）与 `flat-square`（60 次）最为流行，二者均可作为默认选择。

格式示例：

```markdown
![build](https://img.shields.io/badge/build-passing-brightgreen?style=for-the-badge)
![build](https://img.shields.io/badge/build-passing-brightgreen?style=flat-square)
```

## 3. 颜色参数（color / labelColor）

### 3.1 三种颜色表示法

依据 badge-maker 说明，`color`（右侧）与 `labelColor`（左侧背景）均支持以下三种写法：

**方法一：Shields.io 命名色**

| 语义 | 命名色 |
| --- | --- |
| 成功 | `brightgreen`、`green`、`success` |
| 提示 | `yellow`、`yellowgreen`、`orange`、`important` |
| 警示 | `red`、`critical` |
| 信息 | `blue`、`informational` |
| 中性 | `grey` / `gray`、`lightgrey` / `lightgray`、`inactive` |

注意：`labelColor` 默认值为 `grey`，`color` 默认值为 `lightgrey`（文档另注 `inactive` 亦为默认色之一）；部分命名色取值与 CSS 同名色略有差异，以 Shields.io 渲染结果为准。

**方法二：十六进制色**

支持三位或六位十六进制，可省略或保留 `#` 前缀：

```text
?color=8957e5
?color=007fff
?color=%23007fff    ← 保留 # 时需编码为 %23
```

**方法三：CSS 颜色值**

支持 `rgb(...)`、`rgba(...)`、`hsl(...)`、`hsla(...)` 及 CSS 命名色（如 `aqua`、`fuchsia`、`lightslategray`），使用时须做 URL 编码。

### 3.2 颜色语义映射（推荐配置）

| 信息类型 | 推荐颜色 | 示例消息 |
| --- | --- | --- |
| 构建通过、测试通过 | `brightgreen` / `success` | `passing` |
| 构建失败 | `red` / `critical` | `failing` |
| 稳定版本 | `blue` | `v1.2.0` |
| 预发布、原型 | 自定义紫 `8957e5` / `orange` | `v0.1 prototype` |
| 许可证 | `blue` / `green` | `MIT` |
| 文档状态 | `yellowgreen` | `docs` |
| 弃用、停止维护 | `red` / `inactive` | `deprecated` |

**推荐配置**：品牌色、状态色各项目内固定一套，不得随手更换；同一语义在全仓库使用同一颜色编码。

格式示例：

```markdown
![覆盖率](https://img.shields.io/badge/coverage-95%25-orange?style=flat-square)
![状态](https://img.shields.io/badge/status-v0.1%20prototype-8957e5?style=flat-square)
![许可证](https://img.shields.io/badge/license-MIT-blue?style=flat-square)
```

## 4. 图标参数（logo / logoColor / logoSize）

### 4.1 使用 Simple Icons

`logo` 参数取 Simple Icons 的图标 slug，格式为 `?logo=<slug>`。常用 slug 如下：

| 用途 | slug | 实测出现次数（N=120） |
| --- | --- | --- |
| GitHub 仓库 | `github` | 35 |
| Discord 社区 | `discord` | 20 |
| npm 包 | `npm` | 4 |
| 苹果平台 | `apple` | 3 |
| Docker | `docker` | 3 |
| 社交平台 X | `x` | 3 |
| Python 包 | `pypi` | 2 |

完整 slug 以 Simple Icons 站点或 simple-icons 仓库的 `slugs.md` 为准。

### 4.2 图标配色与尺寸

- `logoColor`：设置 Simple Icons 图标颜色，支持十六进制、rgb、hsl、CSS 命名色；仅对 Simple Icons 图标生效，对自定义图标无效。
- `logoSize`：设为 `auto` 时图标按内容自适应缩放，适用于较宽的图标；同样仅对 Simple Icons 生效。

格式示例：

```markdown
![repo](https://img.shields.io/badge/github-repo-blue?logo=github)
![logo 配色](https://img.shields.io/badge/logo-javascript-blue?logo=javascript&logoColor=f5f5f5)
```

自定义图标可通过 `logo=data:image/svg+xml;base64,...` 传入，但 URL 极长，不利于维护，非特殊需要不推荐。

## 5. 其他查询参数

| 参数 | 作用 | 示例 |
| --- | --- | --- |
| `label` | 覆盖默认左侧文字（空格须编码） | `?label=healthiness` |
| `labelColor` | 左侧背景色 | `?labelColor=abcdef` |
| `color` | 右侧背景色 | `?color=fedcba` |
| `cacheSeconds` | HTTP 缓存时长（秒），低于默认值将被忽略 | `?cacheSeconds=3600` |
| `link` | 指定点击左右半区的跳转地址 | 仅 `<object>` 标签内生效，Markdown 图片无效 |

## 6. 动态徽章

动态徽章由 Shields.io 从外部服务实时拉取数据，无需手动更新数值。常用类型：

| 类别 | URL 模式 | 用途 |
| --- | --- | --- |
| 构建状态 | `https://img.shields.io/github/actions/workflow/status/<owner>/<repo>/<workflow>` | CI 状态 |
| 版本 | `https://img.shields.io/npm/v/<package>` | npm 最新版 |
| 许可证 | `https://img.shields.io/npm/l/<package>` | 包许可证 |
| Star 数 | `https://img.shields.io/github/stars/<owner>/<repo>` | 受欢迎程度 |
| Issue 数 | `https://img.shields.io/github/issues/<owner>/<repo>` | 待处理问题 |
| 下载量 | `https://img.shields.io/npm/dt/<package>` | 累计下载 |

动态徽章可追加 `?style=`、`?logo=` 等参数，规则与静态徽章一致。标杆项目普遍采用「动态徽章展示真实指标 + 静态徽章补充自定义状态」的组合。

## 7. 信息取舍与排列顺序

### 7.1 信息取舍

徽章应传递「可验证、对读者有用」的状态信息。建议只保留以下类别：

1. 构建 / 测试状态；
2. 版本或最新发布；
3. 许可证；
4. 文档状态；
5. 社区渠道（Discord、讨论区）；
6. 项目自定义状态（原型、维护中、已弃用）。

不得放入：无来源的下载量、与项目无关的营销标签、无法验证的评分、纯装饰性色块。

### 7.2 排列顺序

推荐按「状态 → 版本 → 许可证 → 平台/社区 → 自定义状态」排列，重要性从左到右递减。理由：构建状态决定读者是否采用，版本决定兼容性判断，许可证决定能否使用，二者均属决策前置信息。

### 7.3 数量控制

- 常规项目：4–6 枚。
- 资源合集或生态项目：可放宽至 8–10 枚。
- 所有徽章置于项目名与一句话定位之后、正文之前，独占一行或居中容器，不在正文中散落。

## 8. 无障碍与主题适配

- 每枚徽章的 `alt` 文本须写明实际含义，例如 `![构建状态]` 而非 `![badge]`。
- 深色 / 浅色主题下，可通过 `<picture>` 切换徽章图片源；使用 `for-the-badge` 并配 `labelColor=000` 可在两种主题下保持稳定对比。
- 徽章须可点击跳转到对应数据源（构建状态跳 CI、版本跳包管理页、许可证跳 LICENSE 文件）。
