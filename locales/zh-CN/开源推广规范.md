# 开源推广规范

> 本文件解决什么问题：定义开源项目在发布前后的推广渠道、发布节奏、首页物料与社区运营规范，使项目在具备可用文档的基础上获得与目标用户相匹配的曝光。

本文件的渠道清单与原则参考 phodal《GitHub 漫游指南》的推广章节；该项目以 11,362 star 的规模验证了这些做法在中文开源社区的适用性。

## 1. 基本原则

1. **质量先于推广**：推广只放大已有质量，不修复缺失。README、示例、文档、测试未就绪前不得启动推广。
2. **项目本身不是推广的全部**：除代码与 README 外，须准备详细文档、示例程序与问题响应机制。
3. **动机明确**：推广服务于具体目标（获取早期用户、招募贡献者、收集反馈），不得为追求 star 数而推广。
4. **渠道匹配**：按项目技术栈与目标用户选择渠道，避免无差别投放。
5. **诚实呈现**：不得虚构 star 数、下载量或使用案例；特性对比须基于可验证事实。

## 2. 发布前准备清单

| 类别 | 要求 | 判定依据 |
| --- | --- | --- |
| 首页 | README 通过四问检查（做什么/解决什么/特性/示例） | [README章节规范](./README章节规范.md) |
| 一句话文案 | 明确品类与限定词，可独立复述 | 同上 1.1 节 |
| 示例 | 提供两步内可运行的 hello world | [README标准模板](./README标准模板.md) |
| 文档 | 安装、配置、API 文档齐备 | [文档矩阵](./文档矩阵.md) |
| 许可证 | LICENSE 存在且与 README 标识一致 | [LICENSE规范](./LICENSE规范.md) |
| 合规 | NOTICE 覆盖第三方依赖 | [NOTICE规范](./NOTICE规范.md) |
| 社区入口 | Issue 模板、贡献指南、行为准则就位 | [贡献指南规范](./贡献指南规范.md) |
| 响应机制 | 明确问题响应人与响应时限 | [事故响应规范](./事故响应规范.md) |

未完成上述清单即推广，属本规范禁止行为。

## 3. 渠道分类

### 3.1 国际技术社区

| 渠道 | 适用内容 | 注意事项 |
| --- | --- | --- |
| Hacker News | 技术实现、有深度的工程设计 | 标题须平实，避免营销措辞 |
| Reddit 对应版块 | 类库、工具、框架 | 遵守各版块自推广规则 |
| Lobsters | 系统编程、工程实践 | 社区对营销敏感 |
| 技术周报（JavaScript Weekly 等） | 类库与工具 | 提供简洁的项目摘要 |
| 官方博客与文档站 | 深度介绍与版本说明 | 作为其他渠道的落点 |

### 3.2 中文技术社区

| 渠道 | 适用内容 |
| --- | --- |
| 掘金 | 前端、移动端、工程实践 |
| 开发者头条 | 综合技术项目 |
| V2EX | 工具、效率软件、创业项目 |
| 知乎 | 技术解读与设计取舍 |
| 微信公众号 | 深度长文、系列教程 |
| 极客头条 | 综合技术资讯 |

### 3.3 项目自有渠道

1. 项目 README 中的社区入口（Discussions、Discord）；
2. 项目专属社交账号，用于发布版本与活动；
3. 文档站与示例站，作为外部流量的承接页。

## 4. 发布节奏

1. **预热期**：完成第 2 节清单，准备一句话文案、截图、Demo 动图等物料。
2. **首发期**：在 1–2 个最匹配渠道发布，避免同一内容多平台刷屏。
3. **响应期**：首发后 72 小时内保持高频响应，处理 Issue 与反馈。
4. **迭代期**：按版本发布节奏持续更新，每次发布附变更说明。
5. **沉淀期**：将高频问题整理为 FAQ，反哺文档。

## 5. 首页物料要求

| 物料 | 规格 | 用途 |
| --- | --- | --- |
| 一句话文案 | 中文 60 字内 / 英文 25 词内；仓库 Description 采用「国家语言 \| 英语」双语合并格式，见 [项目命名规范](./项目命名规范.md) 第 5 节 | 仓库 Description、社交摘要 |
| 截图 | 深浅主题双版本，宽度受控 | README 首屏 |
| Demo 动图 | 压缩后体积受控，展示核心流程 | README 演示章节 |
| Logo | SVG 格式，含深浅双版本 | 首屏与社交卡片 |
| 特性对比表 | 基于可验证事实，含不适用场景 | README 或文档站 |

物料须随版本同步更新，避免展示旧版界面。

## 6. 社区运营

1. 对首次贡献者提供明确入口，如 `good first issue` 标签。
2. 问题响应须有记录，避免重复问题反复出现。
3. 行为准则适用于所有社区渠道，见 [行为准则规范](./行为准则规范.md)。
4. 贡献者致谢集中放置，避免散落在正文各处。
5. 不得通过诱导 star、互赞等方式获取虚假关注。

## 7. 禁止事项

1. 禁止在质量清单未完成时推广。
2. 禁止虚构或夸大项目数据与使用案例。
3. 禁止在多渠道重复刷屏同一内容。
4. 禁止贬损同类项目以提升自身形象。
5. 禁止使用诱导手段获取 star 数。
