# README分类适配指南

> 本文件解决什么问题：针对类库、应用程序、命令行工具、框架、资源合集等不同项目类型，给出 README 章节取舍、视觉侧重与徽章配置的差异化建议，并说明每类元素如何提升美观度与吸引力。

通用模板适用于所有项目，但不同类型项目的读者关注点不同。本文件在通用规范之上给出面向类型的调整建议。读者应以 [README标准模板](./README标准模板.md) 为基础，按本文件对应类型裁剪。

## 1. 类型总览

| 类型 | 读者首要问题 | 门面重心 | 必备章节 | 可省略章节 |
| --- | --- | --- | --- | --- |
| 类库 / SDK | 怎么装、API 怎么用 | 版本与许可证 | 安装、快速开始、API、兼容性 | 部署、截图 |
| 应用程序 | 应用外观与核心功能 | 截图与功能 | 功能、截图、安装、快速开始 | API 参考 |
| 命令行工具 | 命令怎么用、快不快 | 命令示例与 Demo | 安装、用法、命令对照、Demo | 架构、配置（少时） |
| 框架 | 生态与学习成本 | 文档入口与示例 | 定位、快速开始、文档、社区 | 性能细节（可外链） |
| 资源合集 | 收录什么、如何检索 | 目录分类与导航 | 目录、分类、贡献指南 | 安装、API |

## 2. 类库 / SDK

典型代表：axios 等 HTTP 客户端、工具函数库、客户端 SDK。

### 2.1 章节取舍

- 前置「一句话定位 + 版本 + 许可证」，读者据此判断兼容性。
- 「安装」置于最前，给出包管理器命令（npm、pip、cargo 等）。
- 「快速开始」必须是一个可独立运行的完整示例。
- 「API 参考」详列在主 README 或链接至 `docs/api.md`；API 条目过多时，README 只放摘要 + 链接。
- 「兼容性」说明支持的语言版本、运行时、平台。

### 2.2 视觉侧重

- 徽章重点：版本、构建状态、许可证、下载量、包大小。
- 图片使用克制，通常无需截图；可用小型 Logo 建立识别。
- API 参数用表格呈现，提升可读性。

### 2.3 美观度提升要点

1. 版本与许可证徽章置顶，Instantly 建立可信度。
2. 快速开始代码块位于首屏附近，降低尝试门槛。
3. API 表格统一列宽与默认值列，减少认知负担。

## 3. 应用程序

典型代表：编辑器、桌面工具、面向终端用户的产品。

### 3.1 章节取舍

- 首屏必须包含产品截图或运行画面，先展示价值再讲实现。
- 「核心功能」以用户场景组织，而非技术模块。
- 「安装」覆盖各平台安装包或下载入口。
- 「快速开始」给出最短上手路径。
- 源码构建说明可外链至 `CONTRIBUTING.md`。

### 3.2 视觉侧重

- 徽章重点：版本、构建状态、许可证、下载量。
- 截图置于定位之后，是门面的核心元素。
- 功能列表配合图标或短截图，提升扫描效率。

### 3.3 美观度提升要点

1. 高质量产品截图居中展示，深浅主题自适应。
2. 功能点用短句 + 图标，避免长段描述。
3. 下载入口醒目，使用按钮式链接。

## 4. 命令行工具

典型代表：fd、ripgrep 等终端工具。

### 4.1 章节取舍

- 「一句话定位」后紧跟章节导航，便于跳转。
- 「安装」列出主流包管理器与平台二进制。
- 「用法」以任务为导向，给出常用命令示例。
- 「命令对照」或「与同类工具对比」是高频需求。
- 「Demo」用 GIF 或终端录制展示真实效果。
- 性能数据须注明测试环境与方法。

### 4.2 视觉侧重

- 徽章重点：版本、构建状态、平台支持、许可证。
- Demo 动图是核心视觉资产，展示速度与使用体验。
- 命令用带语言标注的代码块，输出用 `text` 块。

### 4.3 美观度提升要点

1. 命令示例置顶，读者无需滚动即可复制使用。
2. Demo 动图展示真实终端效果，强化「快」的印象。
3. 多级语言链接（如中文、韩文译本）放在徽章行附近。

## 5. 框架

典型代表：next.js 等全栈框架。

### 5.1 章节取舍

- 首屏强调定位、生态规模与学习入口。
- 「文档」入口必须醒目，通常指向独立文档站。
- 「社区」说明讨论区、聊天渠道与行为准则。
- 「快速开始」给出最小项目创建命令。
- 深度内容（架构、API）外链，不在 README 展开。

### 5.2 视觉侧重

- 徽章重点：版本、构建状态、许可证、社区渠道。
- 品牌 Logo 与 `for-the-badge` 风格徽章组合，强化门面。
- 可用 Showcase 截图展示生态案例。

### 5.3 美观度提升要点

1. 居中 Logo + 大号统一风格徽章，形成品牌化首屏。
2. 文档与社区入口以醒目的导航块呈现。
3. Good First Issues 等新手入口降低贡献门槛。

## 6. 资源合集

典型代表：awesome 系列列表。

### 6.1 章节取舍

- 首屏以 Logo 与赞助信息开场是常见做法。
- 正文按主题分类组织目录，提供清晰导航。
- 「贡献指南」说明收录标准与提交格式。
- 无需安装、API、部署等章节。

### 6.2 视觉侧重

- 徽章数量可放宽，但须统一风格。
- 目录分类用二级标题 + 列表，条目附简短说明。
- 赞助商 Logo 以表格或网格排列，保持对齐。

### 6.3 美观度提升要点

1. 目录结构清晰，分类标题层级一致。
2. 每个条目附一句话说明，避免仅有链接。
3. 赞助与致谢区域对齐规整，不影响正文阅读。

## 7. 跨类型通用原则

1. **读者优先**：首屏回答读者最关心的问题，类型差异只影响顺序，不影响信息完整性。
2. **统一风格**：同一项目的徽章、标题、代码块风格必须一致。
3. **可复制示例**：任何类型都至少提供一个可直接运行的示例。
4. **链接外链**：超出门面职责的深度内容外链至独立文档。
5. **持续同步**：截图、版本徽章、功能列表须随版本更新，避免陈旧信息损伤可信度。
