# 贡献指南模板

> 本文件解决什么问题：提供一份可直接复制的贡献指南模板，供项目生成 CONTRIBUTING.md，覆盖参与方式、环境搭建、分支模型、提交规范、PR 要求、测试要求、行为准则与许可声明；配套的填写说明覆盖各类型项目的裁剪方式。

## 1. 使用说明

1. 复制第 3 节「模板正文」全部内容，新建为项目根目录的 `CONTRIBUTING.md`。
2. 按第 4 节替换占位符；所有命令须为可直接执行的真实命令。
3. 按第 5 节场景变体裁剪：文档型项目删除测试命令段落，保留 Issue 与 PR 流程。
4. 规则依据见 [贡献指南规范](./贡献指南规范.md)；分支与提交细节分别见 [Git工作流与分支规范](./Git工作流与分支规范.md)、[提交信息规范](./提交信息规范.md)。

## 2. 定制原则

- **可执行**：命令写全工作目录与依赖前提，禁止只写「安装依赖」而无具体命令。
- **有触发条件**：每一步写明何时执行、预期结果。
- **不空泛**：禁止只写「欢迎 PR」而无实质流程，对应 [质量门禁](./质量门禁.md) 的社区治理检查。
- **引用而非复制**：提交与测试规则引用对应规范，不在本文件重复全文。

## 3. 模板正文

````markdown
# 贡献指南

> 本文件说明如何参与 {{项目名称}} 的贡献，适用于外部贡献者与首次参与者。

## 参与方式

| 方式 | 适用场景 | 入口 |
| --- | --- | --- |
| 议题讨论 | 功能建议、问题反馈 | {{议题入口}} |
| 文档改进 | 错别字、示例补充、结构优化 | 直接提交 PR |
| 代码贡献 | 缺陷修复、功能实现 | 见下方流程 |
| 问题反馈 | 使用受阻、异常复现 | {{问题反馈入口}} |

## 开发环境搭建

前提：{{环境前提}}

```bash
# 克隆仓库
git clone {{仓库地址}}
cd {{项目目录名}}

# 安装依赖
{{依赖安装命令}}

# 本地运行
{{本地运行命令}}
```

预期结果：{{验证本地环境可用的方式}}

## 分支模型

- 从 {{基准分支}} 切出个人分支，命名格式 `{{分支命名格式}}`（例如 `feat/简短描述`）。
- 每个 PR 只处理一件事，变更范围过大时请拆分。
- 禁止直接向 {{受保护分支}} 提交，须通过 PR 合并。

## 提交规范

提交信息遵循 Conventional Commits，格式为 `type(scope): subject`。常用类型：`feat`、`fix`、`docs`、`refactor`、`test`、`chore`。示例：

```text
feat(cli): add config file support
```

完整规则见 [提交信息规范]({{提交规范链接}})。

## PR 要求

提交 PR 前请完成以下自查：

- [ ] 变更范围单一，且有对应议题或说明。
- [ ] 提交信息符合上述格式。
- [ ] 本地执行 `{{测试命令}}` 全部通过。
- [ ] 文档随代码同步更新。
- [ ] 未引入密钥、私钥或敏感信息。
- [ ] 描述中说明变更内容、原因与验证方式。

## 测试要求

| 检查项 | 命令 | 通过标准 |
| --- | --- | --- |
| 单元测试 | `{{单元测试命令}}` | 全部通过 |
| 静态检查 | `{{lint 命令}}` | 无错误 |
| 构建验证 | `{{构建命令}}` | 构建成功 |

覆盖率门槛：{{覆盖率要求}}。

## 行为准则

参与本项目即表示同意遵守 [行为准则](./CODE_OF_CONDUCT.md)。

## Issue 规范

- 提问前先检索已有议题，避免重复。
- 缺陷报告须包含：环境信息、复现步骤、预期结果、实际结果、错误日志。
- 功能建议须说明使用场景与不采用时的替代方案。

## 许可证声明

贡献内容默认遵循本项目许可证 {{许可证名称及 SPDX 标识符}}，全文见 [LICENSE](./LICENSE)。提交即表示你有权以该许可证授权你的贡献。
````

## 4. 占位符对照表与字段定义

| 占位符 | 必填 | 字段定义 | 填写示例 |
| --- | --- | --- | --- |
| `{{项目名称}}` | 是 | 项目对外名称 | `FooBar` |
| `{{议题入口}}` | 是 | 真实可访问的议题地址 | `https://github.com/owner/repo/issues` |
| `{{问题反馈入口}}` | 否 | 与议题入口不同时的专用渠道 | `https://github.com/owner/repo/issues/new` |
| `{{环境前提}}` | 是 | 语言版本、包管理器与系统依赖 | `Node.js 20+、pnpm 8+` |
| `{{仓库地址}}` | 是 | 可克隆的仓库地址 | `https://github.com/owner/repo.git` |
| `{{项目目录名}}` | 是 | 克隆后的目录名 | `repo` |
| `{{依赖安装命令}}` | 是 | 实际安装命令 | `pnpm install` |
| `{{本地运行命令}}` | 是 | 实际启动命令 | `pnpm dev` |
| `{{验证本地环境可用的方式}}` | 是 | 可观察的成功标志 | `访问 localhost:3000 出现首页` |
| `{{基准分支}}` | 是 | 切出分支的来源分支 | `main` |
| `{{分支命名格式}}` | 是 | 分支命名规则 | `feat/简短描述` |
| `{{受保护分支}}` | 是 | 禁止直接提交的分支 | `main` |
| `{{提交规范链接}}` | 否 | 项目内或外部提交规范地址 | `./docs/COMMIT_CONVENTION.md` |
| `{{测试命令}}` | 是 | 实际测试命令 | `pnpm test` |
| `{{lint 命令}}` | 是 | 实际静态检查命令 | `pnpm lint` |
| `{{构建命令}}` | 是 | 实际构建命令 | `pnpm build` |
| `{{覆盖率要求}}` | 否 | 新增代码的覆盖率门槛 | `新增代码不低于 80%` |
| `{{许可证名称及 SPDX 标识符}}` | 是 | 项目许可证全称与 SPDX 标识 | `MIT 许可证（MIT）` |

## 5. 填写说明与场景变体

| 场景 | 必留章节 | 可裁剪章节 | 调整要点 |
| --- | --- | --- | --- |
| 代码项目 | 全部 | 无 | 命令须实际执行并通过验证 |
| 文档项目 | 参与方式、PR 要求、行为准则、许可证 | 测试要求、开发环境搭建 | 删除测试表格，保留 PR 自查 |
| 个人项目 | 参与方式、PR 要求、行为准则、许可证 | 环境搭建可精简 | 明确是否接受外部贡献 |
| 企业项目 | 全部 | 无 | 增加贡献者许可协议（CLA）链接与法务要求 |

常见错误对照：

| 错误写法 | 后果 | 正确写法 |
| --- | --- | --- |
| 「欢迎任何形式的贡献」 | 无具体路径，贡献者无从下手 | 列出参与方式表与入口 |
| 「运行测试即可」 | 不知命令与通过标准 | 写明命令、通过标准与覆盖率门槛 |
| 命令写 `npm install` 而项目用 pnpm | 命令不可执行 | 与实际 lockfile 一致 |

## 6. 完整示例

以下为命令段落的填好示例，仅作格式参考。

```bash
# 克隆仓库
git clone https://github.com/owner/repo.git
cd repo

# 安装依赖
pnpm install

# 本地运行
pnpm dev
```

预期结果：访问 localhost:3000 出现首页。
