# 推送与发布规范

> 本文件解决什么问题：定义推送前/中/后的动作清单、tag 与发布规则、事故处理流程，以及完整的 GitHub 推送指引与失败处置矩阵。

## 1. 推送前

1. `git status` 干净，无未跟踪的敏感文件。
2. `git log` 无 WIP、无 `fix bug`、无个人信息泄漏。
3. 确认 `.gitignore` 生效，产物与依赖未被跟踪。
4. 本地通过 build、test 与 lint。
5. 执行全量密钥扫描（含历史提交）。
6. 文档矩阵齐备（见 [文档矩阵](./文档矩阵.md)）。

## 2. 推送动作

7. 推个人分支：`git push -u origin feat/xxx`。
8. 主干只走 PR，不直接 push。
9. 禁止 `push --force`；改写自己分支用 `--force-with-lease`。
10. 禁止对已推送的公共分支做 rebase/amend。
11. 单文件 >50MB 先走 LFS 再推。
12. 首次推送前确认仓库可见性：默认 private，确需公开再切 public。

## 3. tag 与发布

13. tag 格式 `vMAJOR.MINOR.PATCH`，必须 annotated：`git tag -a v1.0.0 -m "release: 1.0.0"`。
14. tag 只在 CI 绿、Release Notes 就绪后打。
15. 破坏性变更必须 `feat!:` 或 `BREAKING CHANGE:`，并在 CHANGELOG 给出迁移方式。

## 4. Phase 6 · 推送后（Post-Push）

- 打 annotated tag；
- 写 Release Notes；
- 校验徽章与链接可用；
- 确认 CI 绿；
- 确认 About 区信息正确（description / topics / 链接 / social preview）。

## 5. 事故处理

16. **密钥已推送**：立即轮换 → `git filter-repo` 清理 → 强推保护分支需走管理员流程 → 公告。
17. **误推大文件**：LFS 迁移或历史重写，不得只删文件。

## 6. GitHub 推送指引规范

指引须包含以下七部分，命令给出完整可执行版本。

### 6.1 前置安全

1. 推送前须完整备份本地仓库与远端仓库，推荐 `git clone --mirror` 生成镜像备份。
2. 确认远端仓库无协作者，或已通知协作者暂停推送。
3. 确认目标分支未启用强制推送保护。

### 6.2 本地整理

```bash
git status
git diff --name-status HEAD
git ls-files
```

核对三项输出，确认待提交变更与本地目录一致，无临时文件、构建产物、旧版文档残留。`.gitignore` 须覆盖构建产物与本地配置文件。

### 6.3 一致性核对

```bash
git fetch origin
git diff --name-status HEAD origin/{{分支名}}
```

该命令列出远端与本地文件差异。远端存在而本地已删除的文件，须在本地执行 `git rm` 后提交，使删除动作进入版本历史。

### 6.4 提交与推送

```bash
git add -A
git commit -m "docs: 重建项目文档（README、README_EN、NOTICE）"
git push --force-with-lease origin {{分支名}}
```

采用 `--force-with-lease` 而非 `--force`，在远端存在他人新提交时拒绝推送，避免覆盖他人工作。删除远端仓库后重建属于高风险操作，仅在个人仓库且已完成镜像备份时使用，指引中须显式标注数据丢失风险。

### 6.5 推送后验证

```bash
git ls-remote --heads origin
gh repo view --web
```

在网页端逐项确认文件列表、README 渲染、语言切换链接、NOTICE 链接有效。

### 6.6 失败处置矩阵

| 错误类型 | 典型表现 | 处置方案 | 风险提示 |
| --- | --- | --- | --- |
| 认证失败 | `Authentication failed`、`Permission denied (publickey)` | 由 HTTPS 切换为 SSH 并配置密钥，或使用 `gh auth login` 后推送 | 无 |
| 网络中断 | `Failed to connect`、`RPC failed` | 更换网络、配置代理、执行 `git config --global http.postBuffer 524288000` | 无 |
| 文件超限 | `remote: error: File exceeds 100 MB` | 从提交历史移除大文件或启用 Git LFS | 改写历史后须通知协作者重新克隆 |
| 大小写冲突 | 文件名大小写不一致导致重复条目 | 使用 `git mv` 修正并提交 | 无 |
| 历史冲突 | `non-fast-forward`、`fetch first` | 优先 `git pull --rebase`；确需覆盖时使用 `--force-with-lease` | 覆盖他人提交不可恢复 |
| 分支保护 | `protected branch hook declined` | 通过 PR 流程合并，或由管理员临时调整规则 | 调整规则须记录 |
| 仓库损坏 | `fatal: not a git repository`、对象缺失 | 重新克隆后复制工作区改动 | 须先备份工作区 |

### 6.7 回滚

推送完成后如发现问题，使用 `git revert` 生成反向提交；不得再次强制推送覆盖已公开的历史。
