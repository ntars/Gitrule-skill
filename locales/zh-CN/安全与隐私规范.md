# 安全与隐私规范

> 本文件解决什么问题：定义敏感信息防护、数据隐私清单、SECURITY.md 模板与漏洞上报字段，保证公开前无泄漏、数据处理合规、漏洞渠道可达。

## 1. 规范条文

1. 不得提交密钥、令牌、私钥、`.env`、云厂商 AK/SK、数据库连接串（对应硬规则 H3）。
2. 密钥扫描须覆盖工作区与完整历史，在推送前执行（见 [推送与发布规范](./推送与发布规范.md)）。
3. 内部域名、IP、个人信息、日志残留须在公开前清理（对应维度 D1）。
4. 一旦密钥已推送，须立即轮换 + 清理历史，不得只做删除提交（对应 H12）。
5. 说明收集哪些数据、用途、存储位置与保留期限；传输与存储加密，展示脱敏。
6. 权限模型遵循最小必要原则；涉及跨境数据的须单独评估。
7. 提供可直达维护者的漏洞上报渠道，承诺保密与响应时限；已知风险如实说明，不承诺绝对安全。

| --- | --- |

| --- | --- |

## 5. 字段定义

| 字段 | 必填 | 类型 | 填写要点 | 示例 |
| --- | --- | --- | --- | --- |
| 覆盖历史 | 是 | 枚举 | 必须选「是」方可判定通过 | `是` |
| 检查项.结果 | 是 | 数值 | 填命中数，禁止「大概没有」 | `0` |
| 已轮换密钥清单 | 条件必填 | 列表 | 命中密钥时必填，列轮换凭证 | `API_KEY 已轮换` |
| 数据项.保留期限 | 是 | 文本 | 具体时长，不可写「长期」 | `账号删除后 30 天` |
| 数据项.第三方共享 | 是 | 文本 | 无则写「无」 | `无` |
| 支持版本 | 是 | 表格 | 明确哪些版本接受报告 | `2.x：是` |
| 上报渠道 | 是 | 文本 | 至少一个非公开渠道 | `Security Advisories` |
| 响应时限 | 是 | 时长 | 每阶段均有数值 | `2 个工作日` |

## 6. 填写说明

1. **历史扫描**：密钥扫描必须包含完整 git 历史；仅扫描工作区视为无效。
2. **密钥命中**：一旦发现已推送密钥，先轮换再清理历史，顺序不得颠倒（对应 H12）。
3. **脱敏**：展示与日志中出现的敏感字段须掩码；禁止完整打印令牌、身份证号、手机号。
4. **保留期限**：「长期保存」不合格，须给出明确期限或触发删除的事件。
5. **支持版本**：至少列当前主版本；旧版本不支持时须明确写出，避免用户误报。
6. **上报渠道**：必须是非公开渠道；公开 Issue 中披露漏洞会扩大风险。
7. **已知风险**：如实列出；「本系统绝对安全」属禁止表述。

常见错误：

| 错误写法 | 问题 | 修正方式 |
| --- | --- | --- |
| 只删密钥提交不轮换 | 违反 H12 | 先轮换再清理历史 |
| 自查只扫工作区 | 历史泄漏漏检 | 加历史扫描 |
| 数据保留写「永久」 | 无边界 | 给具体期限 |
| 漏洞走公开 Issue | 扩大暴露面 | 改私密渠道并写入 SECURITY.md |
| 承诺「绝对安全」 | 不实表述 | 改为如实说明已知风险 |

## 7. 完整示例

```markdown
## 敏感信息自查：markdown-lint-cli

检查日期：2026-11-18 ｜ 执行人：王五 ｜ 覆盖历史：是

| 检查项 | 工具 / 命令 | 结果 | 处置 |
| --- | --- | --- | --- |
| 工作区密钥 | gitleaks detect | 0 | 无 |
| 历史提交密钥 | gitleaks detect --log-opts=--all | 0 | 无 |
| `.env` 与凭据文件 | git ls-files | 0 | 无 |
| 内部域名 / IP | 正则检索 | 0 | 无 |

结论：通过
- 已轮换密钥清单：无
- 复核人：李四
```
