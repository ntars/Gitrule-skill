# 代码所有权规范

> 本文件解决什么问题：定义 `.github/CODEOWNERS` 文件的语法、所有权分配与审查路由规则，使每个变更自动分配给具备责任的审查者。

## 1. 设计原则

1. **路径到人的明确映射**：每条规则指明某路径由谁负责，避免无人审查或重复审查。
2. **最小必要 owners**：单个路径的所有者控制在 1–3 人，过多导致责任分散。
3. **默认承接**：设置全局默认所有者，覆盖未被显式规则匹配的路径。
4. **与团队结构同步**：成员变更时及时更新，避免失效账号阻塞审查。

## 2. 文件位置与语法

### 2.1 路径

`CODEOWNERS` 文件可置于以下任一位置，按优先级取第一个命中：

1. 仓库根目录 `CODEOWNERS`；
2. `docs/CODEOWNERS`；
3. `.github/CODEOWNERS`（推荐）。

### 2.2 语法规则

```text
# 注释以 # 开头
<路径模式>  <所有者>  [<所有者>...]
```

- 每行一条规则，路径模式后跟一个或多个所有者。
- 所有者格式为 `@用户名` 或 `@组织/团队`。
- 使用邮箱作为所有者须与 GitHub 账号关联。
- 路径区分大小写，支持通配符 `*`、`**`。

### 2.3 示例

```text
# 默认所有者
*                       @org/maintainers

# 按目录分配
/src/core/              @org/core-team
/src/api/               @org/api-team @alice
/docs/                  @org/docs-team

# 按文件类型分配
*.md                    @org/docs-team
/.github/workflows/      @org/devops-team
```

## 3. 匹配规则

1. 仅最后一条匹配规则生效，不累加；因此通用规则须写在前面，特殊规则写在后面。
2. 目录规则匹配该目录及其子目录，除非以 `/` 开头限定根路径。
3. 规则顺序决定优先级，须从宽到窄排列。
4. 无匹配路径由默认所有者承担审查责任。

## 4. 所有权分配策略

| 维度 | 分配依据 |
| --- | --- |
| 目录 | 按模块或子系统边界分配 |
| 文件类型 | 文档、配置、测试可按类型统一分配 |
| 关键路径 | 安全、发布、CI 配置由核心维护者独占 |
| 新成员 | 先以非必需审查者身份参与，熟悉后转正式所有者 |

## 5. 与审查流程的联动

1. PR 创建时，GitHub 自动请求匹配路径的所有者审查。
2. 必需审查要求通过分支保护规则配置，见 [Git工作流与分支规范](./Git工作流与分支规范.md)。
3. 所有者应在约定时限内响应，超时由默认所有者承接。
4. 所有者变更须同步更新文件，避免失效账号阻塞流程（见 [代码审查规范](./代码审查规范.md)）。

## 6. 维护要求

1. 每次组织架构或团队职责变更后复核一次。
2. 仓库移交、成员离场须立即移除对应所有者。
3. 文件变更须经至少一名现有所有者审查，防止权限自行扩散。
4. 不得将所有者指向不活跃账号或机器人账号（自动化专用除外）。

## 7. 禁止事项

1. 禁止使用过宽的通配规则导致所有人都是所有者。
2. 禁止将敏感路径（发布、密钥配置）分配给无审查能力的成员。
3. 禁止在文件中写入私人联系方式。
4. 禁止长期保留已离职成员的所有者身份。
