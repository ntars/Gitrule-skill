# Agent调用与提示词规范

> 本文件解决什么问题：定义 Agent 调用规范集时的分派契约与提示词写法，保证调用可验证、不越权、不漂移。

## 1. 调用原则

1. 职责单一：一次调用只完成一件事，禁止「顺便」做其他任务。
2. 读写分离：子 agent 只读取与分析，写文件与 git 操作由主控统一执行（见 [子Agent分派契约](./子Agent分派契约.md)）。
3. 证据要求：结论须带证据（路径 + 行号 / 命令输出），无证据视为无效。
4. 不通信：子 agent 之间不直接通信，全部经主控汇总。

## 2. 提示词结构

调用提示词须包含四要素：

```text
TASK:    <一句话任务>
INPUT:   <必要上下文，只给所需部分>
OUTPUT:  <结构化输出格式，表格或 JSON，禁止散文>
FAIL:    <无法完成时的返回约定，不得瞎编>
```

## 3. 提示词写法

1. 使用书面语与祈使句，信息完整，不依赖上下文推测（见 [通用写作规范](./通用写作规范.md)）。
2. 明确输出格式与失败返回，避免模型自由发挥。
3. 涉及规范引用时给出文件路径（见 [机器可读元数据规范](./机器可读元数据规范.md)）。
4. 模板与占位符统一格式（见 [信息采集与模板](./信息采集与模板.md)）。

## 4. 强制规则

1. 不得要求 Agent 编造检查结果；不可检查项标注 SKIP + 原因。
2. 不得把内部思考过程写入交付物（见 [禁止事项](./禁止事项.md)）。
3. 安全相关内容按 [安全与隐私规范](./安全与隐私规范.md) 处理。
