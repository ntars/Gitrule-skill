# 审核维度矩阵

> 本文件解决什么问题：定义 Phase 2 并行审核的 14 个维度、各自检查要点、建议 agent 与失败等级，作为分派与判定的依据。

## 审核维度矩阵

| # | 维度 | 检查要点（关键词，细节由子 agent 展开） | 建议 agent | 失败等级 |
|---|---|---|---|---|
| D1 | 安全与隐私 | 密钥扫描、`.env`、私钥、内部域名/IP、个人信息、日志残留 | security-auditor | P0 |
| D2 | 许可证与法律 | LICENSE 存在与类型、依赖 license 兼容性、NOTICE、第三方声明 | license-checker | P0 |
| D3 | 仓库卫生 | .gitignore 覆盖度、产物与依赖目录、.gitattributes、行尾 LF、可执行位、文件名大小写冲突 | repo-hygienist | P0/P1 |
| D4 | 体积与二进制 | >50MB 文件、图片压缩、LFS 配置、历史膨胀 | repo-hygienist | P1 |
| D5 | 可复现构建 | lockfile 提交、引擎版本声明、构建脚本、干净环境可跑通 | build-verifier | P0 |
| D6 | 测试与静态检查 | 单测通过、覆盖率、lint、format、类型检查 | ci-runner | P0/P1 |
| D7 | 提交历史 | Conventional Commits、原子性、无 WIP、作者信息、无敏感 commit message | commit-reviewer | P1 |
| D8 | 分支与发布 | main 保护、分支命名、tag SemVer、annotated tag、Release Notes | release-manager | P1 |
| D9 | 自动化 | CI 工作流可跑、状态徽章、dependabot、CODEOWNERS、issue/PR 模板 | ci-runner | P1 |
| D10 | 仓库元数据 | description（≤120 字符）、topics（5–10 个）、默认分支、About 链接、social preview | metadata-agent | P1 |
| D11 | 文档完整性 | 文档矩阵逐项存在性校验 | docs-orchestrator | P0/P1 |
| D12 | 文档质量 | 标题层级、代码块语言标注、链接有效性、图片 alt、中英文空格、无占位符 | docs-orchestrator | P1/P2 |
| D13 | README 门面 | 一句话定位、安装、快速开始、徽章 ≤4、截图、无本地绝对路径 | readme-writer | P1 |
| D14 | 社区治理 | CONTRIBUTING、CODE_OF_CONDUCT、SECURITY、Issue 模板、支持渠道 | docs-orchestrator | P2 |

## 等级含义

- **P0**：阻断推送。
- **P1**：推送前应修或必须登记待办。
- **P2**：建议优化。

## 分派与汇总

- 每个维度的分派方式见 [子Agent分派契约](./子Agent分派契约.md)。
- 判定结果汇总到 [审核报告格式](./审核报告格式.md) 的问题清单，每条须带证据。
- D11/D12 的校验依据见 [文档矩阵](./文档矩阵.md) 与 [质量门禁](./质量门禁.md)。
