# 测试规范

> 本文件解决什么问题：定义测试分层、测试计划与用例的模板、字段、覆盖率口径与执行标准，保证每项需求可验证、每次变更可回归。

## 1. 规范条文

1. 测试分为单元、集成、端到端三层；每层须写明被测对象与不测范围，避免重复覆盖。
2. 每条「必须」级需求须至少有一条测试用例对应，追踪关系见 [需求追踪矩阵规范](./需求追踪矩阵规范.md)。
3. 缺陷修复须先补回归用例，再改代码；回归用例须能复现原缺陷。
4. 覆盖率门槛按项目设定并写入 CI，不得低于既定阈值（对应硬规则 H9）。
5. 测试须可重复、无外部状态依赖；依赖外部服务者须隔离或 mock。
6. 测试命名须表达被测行为与预期结果；测试、lint、format、类型检查须在 CI 中自动执行，全绿方可合并（见 [代码审查规范](./代码审查规范.md)）。

## 2. 测试分层

| 层级 | 被测对象 | 须覆盖 | 不覆盖 | 典型工具 |
| --- | --- | --- | --- | --- |
| 单元测试 | 函数、纯逻辑模块 | 核心逻辑、边界条件、异常分支 | 跨模块协作、外部 I/O | 语言自带 runner |
| 集成测试 | 模块间协作 | 关键调用链、适配器、持久化交互 | 完整用户流程 | 测试容器 / mock server |
| 端到端测试 | 完整用户场景 | 主要使用路径、关键业务闭环 | 穷举分支、性能压测 | 浏览器 / CLI 驱动器 |

```markdown
## 测试范围
- 纳入：{{模块 / 需求编号列表}}
- 排除：{{不在本期验证的范围及原因}}
- 关联立项成功标准：{{G1 / G2}}

## 分层策略
| 层级 | 被测对象 | 覆盖目标 | 工具 | 执行时机 |
| --- | --- | --- | --- | --- |
| 单元 | {{对象}} | {{覆盖率阈值}} | {{工具}} | 每次提交 |
| 集成 | {{对象}} | {{关键链路清单}} | {{工具}} | 每次合并 |
| 端到端 | {{场景}} | {{主要路径清单}} | {{工具}} | 每次发布 |

## 环境与数据
- 环境：{{操作系统 / 运行时版本 / 依赖服务版本}}
- 测试数据：{{构造方式；禁止使用生产敏感数据}}
- 外部依赖：{{需 mock 的服务及隔离方式}}

## 准入与准出
- 准入：{{进入测试的前置条件，如开发自测通过}}
- 准出：{{通过率 100%、无 P0/P1 缺陷、覆盖率达标}}
- 暂停条件：{{阻塞性问题清单}}

## 风险与取舍
- 未测范围及理由：{{例如第三方付费接口以 mock 替代}}
- 已知风险：{{例如并发场景仅做 10 路验证}}
```

```markdown
### TC-{{三位序号}}：{{用例标题}}

- 关联需求：{{REQ-001}}
- 层级：{{单元 / 集成 / 端到端}}
- 优先级：{{P0 / P1 / P2}}
- 类型：{{正常 / 边界 / 异常}}
- 前置条件：{{环境与数据准备}}
- 步骤与预期：
  | 步骤 | 操作 | 预期结果 |
  | --- | --- | --- |
  | 1 | {{操作}} | {{可判定的结果}} |
  | 2 | {{操作}} | {{可判定的结果}} |
- 清理：{{恢复环境的操作；无则写「无」}}
```

## 5. 字段定义

### 5.1 测试计划字段

| 字段 | 必填 | 类型 | 填写要点 | 示例 |
| --- | --- | --- | --- | --- |
| 对应需求范围 | 是 | 列表 | 使用 REQ 编号区间 | `REQ-001 ~ REQ-020` |
| 排除范围 | 是 | 文本 | 写明不测原因 | `不测付费接口：无测试账号` |
| 覆盖目标 | 是 | 阈值 | 覆盖率须为数字百分比 | `行覆盖 ≥80%` |
| 执行时机 | 是 | 枚举 | 提交 / 合并 / 发布 | `每次合并` |
| 测试数据 | 是 | 文本 | 声明构造方式，禁止真实敏感数据 | `使用 fixture 生成` |
| 准出条件 | 是 | 文本 | 可判定，含缺陷等级门槛 | `无 P0/P1 未关闭缺陷` |

### 5.2 测试用例字段

| 字段 | 必填 | 类型 | 填写要点 | 示例 |
| --- | --- | --- | --- | --- |
| 编号 | 是 | `TC-NNN` | 连续、不复用 | `TC-007` |
| 关联需求 | 是 | 列表 | 至少一条 REQ 编号 | `REQ-001` |
| 优先级 | 是 | 枚举 | P0 / P1 / P2 | `P0` |
| 类型 | 是 | 枚举 | 正常 / 边界 / 异常 | `边界` |
| 步骤与预期 | 是 | 表格 | 每步须有可判定预期 | 见模板 |
| 清理 | 是 | 文本 | 无清理写「无」，不得留空 | `无` |

### 5.3 覆盖率口径

| 口径 | 定义 | 适用层级 | 推荐门槛 |
| --- | --- | --- | --- |
| 行覆盖 | 被执行语句数 / 总语句数 | 单元 | ≥80% |
| 分支覆盖 | 被执行分支数 / 总分支数 | 单元 | ≥70% |
| 需求覆盖 | 有测试用例的「必须」级需求数 / 「必须」级需求总数 | 全层 | 100% |
| 路径覆盖 | 已验证主要路径数 / 识别出的主要路径总数 | 端到端 | 100% |

口径说明：覆盖率是发现未测区域的手段，不是质量目标本身；高覆盖率不替代断言质量，断言须验证行为而非仅执行代码。

## 6. 填写说明

1. **关联需求**：须填 REQ 编号；无法关联的用例应迁移至探索性测试记录，不纳入正式用例集。
2. **预期结果**：须可判定。「返回正确结果」不合格；「返回状态码 200 且 `name` 字段非空」合格。
3. **类型分布**：每条「必须」级需求至少配一条正常用例与一条边界或异常用例。
4. **清理**：涉及文件、数据库、全局状态的用例必须写清理步骤；未写清理即视为用例不完整。
5. **回归用例**：缺陷修复须以缺陷编号为前缀命名，例如 `TC-007-regression-142`。
6. **隔离**：用例之间不得依赖执行顺序；需共享状态者须在前置条件中重建。

常见错误：

| 错误写法 | 问题 | 修正方式 |
| --- | --- | --- |
| 预期写「功能正常」 | 不可判定 | 写具体返回值或状态 |
| 用例无关联需求 | 追溯链断裂 | 补 REQ 编号 |
| 只测正常路径 | 边界缺陷漏检 | 补异常与边界用例 |
| 用例依赖上一条的执行结果 | 不可重复执行 | 前置条件中重建状态 |
| 用生产数据测试 | 隐私与合规风险 | 改用 fixture |

## 7. 完整示例

```markdown
# 测试计划：markdown-lint-cli v1.0

版本：v1.0 ｜ 对应需求范围：REQ-001 ~ REQ-014 ｜ 负责人：王五

## 测试范围
- 纳入：规则引擎、CLI 参数解析、报告输出（REQ-001 ~ REQ-014）
- 排除：编辑器插件集成（推迟至 v1.1，无对应需求）
- 关联立项成功标准：G1、G2

## 分层策略
| 层级 | 被测对象 | 覆盖目标 | 工具 | 执行时机 |
| --- | --- | --- | --- | --- |
| 单元 | 规则函数 | 行覆盖 ≥85% | 语言自带 runner | 每次提交 |
| 集成 | CLI → 规则引擎 → 报告 | 关键链路 3 条 | 测试容器 | 每次合并 |
| 端到端 | 真实仓库批量检查 | 主要路径 2 条 | shell 驱动 | 每次发布 |

### TC-001：中英文间缺失空格被检出
- 关联需求：REQ-001
- 层级：单元
- 优先级：P0
- 类型：边界
- 前置条件：加载 `spacing` 规则
- 步骤与预期：
  | 步骤 | 操作 | 预期结果 |
  | --- | --- | --- |
  | 1 | 输入「使用Node.js开发」 | 返回 1 条命中，行号 1 |
  | 2 | 输入「使用 Node.js 开发」 | 返回 0 条命中 |
- 清理：无
```
