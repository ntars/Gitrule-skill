# 禁止事项

> 本文件解决什么问题：汇总所有不可违反的禁止行为，作为审核与撰写时的最终红线清单。

## 一、总控与推送红线

1. 禁止在 P0 未清零时输出「可以先推，后面补」。
2. 禁止编造检查结果；无法检查的项标注 `SKIP + 原因`，不得写 PASS。
3. 禁止把多个文档合并成一个文件交付。
4. 禁止在 README 里塞 API 全量、贡献指南、变更日志。
5. 禁止使用 `--force` 推公共分支，任何情况下都不行。
6. 禁止只做「删除提交」来处理已泄漏的密钥。
7. 禁止脱离 [项目命名规范](./项目命名规范.md) 自创仓库名。
8. 禁止把内部思考过程写进交付文档。

## 二、文档撰写红线

1. 不得编造项目名称、功能、性能数据、依赖版本、许可证、作者信息、测试结果。
2. 不得复制他人 README、文档、代码、图片、文案；确需引用时须注明来源与许可证。
3. 不得在未获确认的情况下选择许可证类型。
4. 不得出现未经验证的性能数字、无出处的对比结论、承诺性表述（如「保证」「永久免费」）、对第三方项目的贬损性描述、与项目无关的推广内容。
5. 不得使用来源不明的素材；图片、图标、字体缺失来源与许可证时标注待确认，不得直接使用。
