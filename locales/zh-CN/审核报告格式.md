# 审核报告格式

> 本文件解决什么问题：定义审核报告的唯一交付格式、字段要求与填写示例，确保报告可被另一个 agent 直接执行。

报告是审核环节的唯一交付物。每条问题须同时具备证据、责任方与动作；无法执行的结论不得写入报告。

## 1. 报告骨架

````markdown
# 推送审核报告 · {{仓库名}}

结论：{{结论}}
模式：{{模式}}
仓库：{{仓库名}} · {{可见性}} · {{许可证}} · 默认分支 {{默认分支}}

## 一、门禁状态
| 门 | 状态 | 未决项 |
| --- | --- | --- |
| A 安全 | {{门禁状态}} | {{未决项}} |
| B 质量 | {{门禁状态}} | {{未决项}} |
| C 门面 | {{门禁状态}} | {{未决项}} |

## 二、问题清单
| 等级 | 维度 | 问题 | 证据（路径:行 / 命令输出） | 责任 agent | 动作 |
| --- | --- | --- | --- | --- | --- |
| {{等级}} | {{维度}} | {{问题}} | {{证据}} | {{责任agent}} | {{动作}} |

## 三、文档矩阵状态
| 文件 | 状态 | 缺失/待改项 |
| --- | --- | --- |
| {{文件路径}} | {{状态}} | {{待改项}} |

## 四、推送执行清单
- [ ] {{推送规则}}

## 五、放行说明
{{放行说明}}
````

## 2. 字段定义

| 字段 | 必填 | 类型 | 填写要点 | 示例 |
| --- | --- | --- | --- | --- |
| 仓库名 | 是 | 文本 | 与 GitHub 仓库名逐字一致 | `markdown-lint-cli` |
| 结论 | 是 | 枚举 | 仅 `ALLOW PUSH` 或 `BLOCK PUSH`；P0 未清零必须为后者 | `BLOCK PUSH` |
| 模式 | 是 | 枚举 | 私有临时脚本仓可写「降级审核」，其余为「完整审核」 | `完整审核` |
| 可见性 | 是 | 枚举 | `private` / `public`；公开前须复核许可证 | `private` |
| 许可证 | 是 | SPDX 标识符 | 无许可证写 `NONE`，此时结论必须为 `BLOCK PUSH` | `MIT` |
| 默认分支 | 是 | 文本 | 写实际分支名，不写假定的 `main` | `main` |
| 门禁状态 | 是 | 枚举 ×3 | A/B/C 各一行；`SKIP` 须在「未决项」注明原因 | `FAIL` |
| 未决项 | 条件必填 | 文本 | 状态为 `FAIL` 或 `SKIP` 时必填，列出阻断或跳过原因 | `D1 检出 .env` |
| 等级 | 是 | 枚举 | `P0` 阻断 / `P1` 推送前修或登记 / `P2` 建议 | `P0` |
| 维度 | 是 | `D1`–`D14` | 编号见 [审核维度矩阵](./审核维度矩阵.md) | `D1` |
| 问题 | 是 | 文本 | 一句陈述事实，不写推测或情绪化表述 | `根目录存在 .env` |
| 证据 | 是 | 路径:行 或命令输出 | 必须可复核；无法取证写 `SKIP + 原因` | `.env:3` |
| 责任 agent | 是 | agent 名称 | 写具体执行角色，不写「相关人员」 | `security-auditor` |
| 动作 | 是 | 文本 | 可直接执行的操作，含目标文件 | `删除 .env、轮换密钥并清理历史` |
| 文件路径 | 是 | 文本 | 按 [文档矩阵](./文档矩阵.md) 的清单逐项列出 | `SECURITY.md` |
| 文档矩阵状态 | 是 | 表格逐行 | 逐文件标注存在、缺失或待改 | `SECURITY.md 缺失` |
| 推送执行清单 | 是 | 复选框列表 | 按 [推送与发布规范](./推送与发布规范.md) 的规则逐条展开 | `- [ ] 确认 .gitignore 生效` |
| 放行说明 | 是 | 文本 | 阻断时写原因与解除条件；放行时写已满足的硬规则 | `P0 清零后可复核` |

## 3. 填写说明

1. **结论优先**：先判定 P0 数量，再写结论。任一 P0 未清零时不得输出 `ALLOW PUSH`。
2. **证据强制**：每条问题必须有 `路径:行号` 或可复制的命令输出。无证据的结论标 `SKIP` 并写明原因，不得写 `PASS`。
3. **责任到角色**：责任 agent 使用 [审核维度矩阵](./审核维度矩阵.md) 中的角色名，一项问题对应一个责任方。
4. **动作可执行**：动作须指明目标文件与操作类型；「后续处理」「自行调整」视为无效。
5. **门禁一致**：A/B/C 三行状态与问题清单对应；任一门为 `FAIL` 时结论必须为 `BLOCK PUSH`。
6. **文档矩阵逐项**：按清单逐文件列出，不得只写「文档基本齐备」。
7. **清单展开**：推送执行清单须逐条展开规则，不得用「按规范执行」代替。

常见错误：

| 错误写法 | 问题 | 修正方式 |
| --- | --- | --- |
| 证据栏写「疑似有问题」 | 无路径、无输出，不可复核 | 补 `文件路径:行号` 或命令输出 |
| P0 未清零却写 `ALLOW PUSH` | 违反硬规则 | 改为 `BLOCK PUSH`，列明解除条件 |
| 无法检查的项写 `PASS` | 编造结果 | 写 `SKIP` 并在未决项注明原因 |
| 责任方写「相关人员」 | 无责任主体 | 写具体 agent 名称 |
| 动作写「后续处理」 | 不可执行 | 写明目标文件与具体操作 |
| 默认分支写 `main` 而未核实 | 与实际不符 | 以 `git branch` 输出为准 |

## 4. 完整示例

以下为 `BLOCK PUSH` 的完整填写示例：

````markdown
# 推送审核报告 · markdown-lint-cli

结论：BLOCK PUSH
模式：完整审核
仓库：markdown-lint-cli · private · NONE · 默认分支 main

## 一、门禁状态
| 门 | 状态 | 未决项 |
| --- | --- | --- |
| A 安全 | FAIL | D1 检出 .env、D2 无 LICENSE |
| B 质量 | SKIP | 仓库未安装依赖，构建与测试无法执行 |
| C 门面 | FAIL | README 缺安装章节与最小示例 |

## 二、问题清单
| 等级 | 维度 | 问题 | 证据（路径:行 / 命令输出） | 责任 agent | 动作 |
| --- | --- | --- | --- | --- | --- |
| P0 | D1 | 根目录存在 .env | `.env:3` 含 DATABASE_URL | security-auditor | 删除 .env、轮换数据库凭据并清理历史 |
| P0 | D2 | 无许可证文件 | `ls LICENSE` 输出 `No such file or directory` | license-checker | 由仓库所有者确认许可证后生成 LICENSE |
| P1 | D13 | README 缺安装章节 | `README.md:1-28` 无「安装」标题 | readme-writer | 按 README标准模板补写安装与最小示例 |

## 三、文档矩阵状态
| 文件 | 状态 | 缺失/待改项 |
| --- | --- | --- |
| README.md | 待改 | 缺安装章节与最小示例 |
| LICENSE | 缺失 | 待所有者确认许可证类型 |
| SECURITY.md | 缺失 | 尚未创建 |

## 四、推送执行清单
- [ ] 确认 git status 干净
- [ ] 密钥扫描通跑一遍（含历史）
- [ ] 本地跑通 build + test + lint
- [ ] 文档矩阵齐备

## 五、放行说明
阻断原因：存在 2 项 P0（凭据泄漏、无许可证），且质量门因依赖未安装无法判定。解除条件：完成密钥轮换与历史清理、确定许可证、在可构建环境重跑测试并清零 P0 后复核。
````

`ALLOW PUSH` 时第五节可写：「已满足全部硬规则，三层门禁均为 PASS，可执行推送。」其余各节按实际情况填写，不得省略证据与清单。

## 5. 交付顺序

1. 根 README 语言导航完整内容。
2. 各已完成语言目录的 README 完整内容，逐个列出语言码与文件路径。
3. NOTICE 文件内容。
4. LICENSE 方案说明（如用户未指定许可证，只给候选与差异，不直接生成）。
5. 待确认事项汇总。
6. 审核报告（本报告）。
7. GitHub 推送指引。
