# 可观测性规范

> 本文件解决什么问题：定义日志字段、SLI/SLO 目标、告警规则与告警响应卡模板，保证系统状态可见、故障可定位、告警可执行。

## 1. 规范条文

1. 可观测性由日志、指标、链路追踪三支柱构成；三者须以统一的请求标识关联。
2. 日志须结构化，含时间戳、级别、请求标识；禁止记录敏感信息，脱敏规则见 [安全与隐私规范](./安全与隐私规范.md)。
3. 每个关键服务须定义 SLI 与 SLO，并给出计算口径与统计窗口。
4. 告警规则须有明确阈值、持续时长与负责人；无处置指引的告警不得上线。
5. 告警触发后须可关联到 [事故响应规范](./事故响应规范.md) 的分级与处置流程。
6. 指标口径须与 [质量度量指标规范](./质量度量指标规范.md) 统一，禁止同名不同义。

## 2. 三大支柱与字段

| 支柱 | 必含字段 | 要求 | 关联键 |
| --- | --- | --- | --- |
| 日志 | 时间戳、级别、请求标识、消息、上下文 | 结构化输出，级别只用 DEBUG/INFO/WARN/ERROR | `trace_id` |
| 指标 | 指标名、标签、数值、采集时间 | 有明确口径与目标值 | `service` |
| 链路追踪 | 追踪标识、跨度标识、父跨度、耗时、状态 | 跨服务调用可串联 | `trace_id` |

## 3. 日志字段模板

```markdown
| 字段 | 类型 | 必填 | 说明 | 示例 |
| --- | --- | --- | --- | --- |
| timestamp | ISO 8601 | 是 | UTC 时间，含时区 | 2026-11-18T10:00:00Z |
| level | 枚举 | 是 | DEBUG / INFO / WARN / ERROR | ERROR |
| trace_id | 字符串 | 是 | 全链路唯一标识 | 4bf92f3577b34da6 |
| service | 字符串 | 是 | 服务名 | lint-api |
| message | 字符串 | 是 | 不含敏感信息的简要描述 | rule load failed |
| context | 对象 | 否 | 可定位的上下文字段 | {"rule":"spacing"} |
```

## 4. SLI/SLO 定义模板

```markdown
# SLO 定义：{{服务名}}

版本：{{v1.0}} ｜ 负责人：{{姓名}} ｜ 复核周期：{{每季度}}

## 服务边界
- 服务职责：{{一句话}}
- 依赖服务：{{上游 / 下游}}
- 用户关键操作：{{列出 2–5 项}}

## SLI 定义
| SLI | 定义 | 计算口径 | 数据源 |
| --- | --- | --- | --- |
| 可用性 | 成功请求数 / 总请求数 | HTTP 状态码 <500 为成功 | {{监控面板}} |
| 延迟 | 请求耗时分布 | P95 分位值 | {{监控面板}} |
| 错误率 | 失败请求数 / 总请求数 | 5xx 计数 | {{监控面板}} |

## SLO 目标
| SLI | 目标值 | 统计窗口 | 当前值 | 达标状态 |
| --- | --- | --- | --- | --- |
| 可用性 | ≥99.9% | 滚动 30 天 | {{值}} | {{达标 / 未达标}} |
| 延迟 P95 | <300ms | 滚动 7 天 | {{值}} | {{达标 / 未达标}} |
| 错误率 | <0.1% | 滚动 24 小时 | {{值}} | {{达标 / 未达标}} |

## 错误预算
- 计算方式：{{1 - SLO 目标值，按统计窗口换算}}
- 消耗告警：{{消耗达 50% / 75% / 90% 时分别通知}}
- 耗尽策略：{{冻结非关键发布，优先修复稳定性}}
```

## 5. 告警规则模板

```markdown
### ALERT-{{三位序号}}：{{告警名称}}

- 关联 SLI：{{可用性 / 延迟 / 错误率}}
- 表达式：{{可执行的查询表达式}}
- 阈值：{{数值 + 单位}}
- 持续时长：{{N 分钟}}
- 严重级别：{{P0 / P1 / P2}}
- 负责人：{{姓名 / 值班组}}
- 触发示例：{{给出一个会触发的样例数据}}
- 静默条件：{{何时允许静默，须有到期时间}}

处置指引：
1. {{第一步：确认现象的数据源与命令}}
2. {{第二步：常见原因与对应处理}}
3. {{第三步：升级条件与升级对象}}
- 关联事故级别：{{见事故响应规范的分级表}}
```

## 6. 字段定义

| 字段 | 必填 | 类型 | 填写要点 | 示例 |
| --- | --- | --- | --- | --- |
| SLI 定义 | 是 | 文本 | 须为可计算的比例或分位值 | 成功请求数 / 总请求数 |
| 计算口径 | 是 | 文本 | 明确纳入与排除条件 | 排除健康检查请求 |
| SLO 目标值 | 是 | 阈值 | 数值 + 单位 + 百分比 | `≥99.9%` |
| 统计窗口 | 是 | 时长 | 滚动窗口，禁止自然月模糊表述 | `滚动 30 天` |
| 错误预算 | 是 | 数值 | 由 SLO 目标换算得出 | `月允许 43 分钟不可用` |
| 告警表达式 | 是 | 查询 | 可直接粘贴执行 | `rate(http_5xx[5m]) > 0.01` |
| 持续时长 | 是 | 时长 | 防止瞬时抖动误报 | `5 分钟` |
| 处置指引 | 是 | 列表 | 至少 3 步，含升级条件 | 见模板 |
| 静默条件 | 是 | 文本 | 须有到期时间 | `发布窗口内，最长 30 分钟` |

## 7. 填写说明

1. **SLI 选择**：从用户可感知的维度选 2–5 项，不以 CPU、内存等内部资源指标替代用户 SLI。
2. **口径统一**：同名指标在日志、监控面板、告警表达式中须使用同一计算口径。
3. **目标设定**：SLO 目标应基于当前实测值与业务容忍度，禁止直接套用「四个九」而无论证。
4. **错误预算**：须写明换算结果与分级消耗动作；预算耗尽时冻结非关键发布。
5. **告警可执行**：每条告警须回答「看什么、怎么查、何时升级」三问；缺一问不得上线。
6. **告警疲劳治理**：连续 30 天未产生有效处置的告警应下调级别或删除，并说明理由。
7. **脱敏**：日志上下文字段中若可能出现密钥、令牌、个人隐私，须在输出前脱敏。

常见错误：

| 错误写法 | 问题 | 修正方式 |
| --- | --- | --- |
| 用 CPU 使用率作为 SLI | 非用户可感知 | 改用可用性、延迟、错误率 |
| 告警只写「服务异常」 | 无阈值、无指引 | 补表达式、阈值与处置步骤 |
| 日志打印完整请求头 | 隐私与密钥泄漏风险 | 白名单输出必要字段 |
| 告警无静默到期时间 | 长期静默导致漏报 | 设置最长静默时长 |
| SLO 无统计窗口 | 目标不可判定 | 补滚动窗口 |

## 8. 完整示例

```markdown
# SLO 定义：lint-api

版本：v1.0 ｜ 负责人：王五 ｜ 复核周期：每季度

## SLI 定义
| SLI | 定义 | 计算口径 | 数据源 |
| --- | --- | --- | --- |
| 可用性 | 成功请求数 / 总请求数 | 状态码 <500，排除健康检查 | Grafana lint-overview |
| 延迟 | 检查请求耗时 P95 | 仅统计 /check 路径 | Grafana lint-overview |

## SLO 目标
| SLI | 目标值 | 统计窗口 | 当前值 | 达标状态 |
| --- | --- | --- | --- | --- |
| 可用性 | ≥99.9% | 滚动 30 天 | 99.94% | 达标 |
| 延迟 P95 | <300ms | 滚动 7 天 | 268ms | 达标 |

## 错误预算
- 计算方式：0.1% × 30 天 = 43 分钟/月
- 消耗告警：50% 通知负责人，75% 通知值班组，90% 冻结非关键发布
- 耗尽策略：暂停功能发布，仅允许稳定性修复

### ALERT-001：5xx 错误率超阈值
- 关联 SLI：可用性
- 表达式：`rate(http_requests_total{status=~"5.."}[5m]) / rate(http_requests_total[5m])`
- 阈值：>0.01
- 持续时长：5 分钟
- 严重级别：P1
- 负责人：王五
- 处置指引：
  1. 打开 Grafana lint-overview 确认错误来源服务
  2. 查询 ERROR 日志并按 trace_id 串联调用链；常见原因为规则插件加载失败
  3. 10 分钟内未定位则升级至李四并进入 P1 事故流程
```
