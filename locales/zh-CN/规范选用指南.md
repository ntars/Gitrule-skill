# 规范选用指南

> 本文件解决什么问题：按项目类型、团队规模与发布阶段给出规范的裁剪依据，提供最小可用组合与完整合规组合，使「按需取用」具备明确判定标准，而非依赖个人判断。

本文件裁剪的对象是整套规范；README 章节层面的类型差异见 [README分类适配指南](./README分类适配指南.md)，阶段的完整映射见 [生命周期映射表](./生命周期映射表.md)。

## 1. 选用原则

1. **强制约束不可裁剪**：[硬规则](./硬规则.md) 与 [禁止事项](./禁止事项.md) 在任何项目、任何阶段均完整适用。
2. **阶段门禁决定下限**：进入某阶段前，该阶段在 [生命周期映射表](./生命周期映射表.md) 中标注的退出门禁必须通过，对应的核心规范不得省略。
3. **类型差异只影响深度**：项目类型决定强调哪些规范、简化哪些细节，不构成跳过质量门禁的理由。
4. **降级须显式声明**：私有临时脚本仓可仅执行 P0 门禁，但须在交付物中标注「降级模式」并列出未执行项。

## 2. 裁剪维度

| 维度 | 取值 | 主要影响 |
| --- | --- | --- |
| 项目类型 | 类库 / SDK、应用程序、命令行工具、框架、资源合集 | 决定强化的规范与可简化的细节 |
| 团队规模 | 个人、小型团队、组织 | 决定治理与协作类规范的必要性 |
| 发布阶段 | 原型验证、首次公开、稳定维护 | 决定合规与运维类规范的引入时机 |

三个维度叠加时，按「强制约束 → 阶段门禁 → 发布阶段 → 项目类型 → 团队规模」的优先级取值；低优先级维度的裁剪不得削弱高优先级维度的要求。

## 3. 按项目类型裁剪

| 项目类型 | 应强化 | 可简化 | 必需交付物 |
| --- | --- | --- | --- |
| 类库 / SDK | [API设计规范](./API设计规范.md)、[API文档规范](./API文档规范.md)、[版本管理规范](./版本管理规范.md)、[变更日志规范](./变更日志规范.md) | 部署与回滚、可观测性（仅分发制品时）、截图类视觉规范 | README、API 文档、LICENSE、CHANGELOG |
| 应用程序 | [README视觉排版规范](./README视觉排版规范.md)、[可访问性规范](./可访问性规范.md)、[部署与回滚规范](./部署与回滚规范.md)、[可观测性规范](./可观测性规范.md)、[故障排查规范](./故障排查规范.md) | API 文档、数据库设计（使用托管服务时） | README、截图、部署说明、SECURITY |
| 命令行工具 | [提交信息规范](./提交信息规范.md)、[亮点与工程取舍写法](./亮点与工程取舍写法.md)、[README分类适配指南](./README分类适配指南.md)、[可访问性规范](./可访问性规范.md)（终端输出） | 数据库设计、部署与回滚（以包分发为主时） | README、用法示例、演示动图、LICENSE |
| 框架 | [文档矩阵](./文档矩阵.md)、[API文档规范](./API文档规范.md)、[贡献指南规范](./贡献指南规范.md)、[行为准则规范](./行为准则规范.md)、[可观测性规范](./可观测性规范.md) | 数据库设计（不内置存储时） | README、文档入口、贡献指南、行为准则 |
| 资源合集 | [文档矩阵](./文档矩阵.md)、[贡献指南模板](./贡献指南模板.md)、[多语言规范](./多语言规范.md)、[通用写作规范](./通用写作规范.md) | 测试、部署、API、数据库、可观测性 | README、分类目录、贡献指南、LICENSE |

资源合集类项目通常不含可运行代码，[测试规范](./测试规范.md)、[CI工作流规范](./CI工作流规范.md) 可标注为不适用；但 [通用写作规范](./通用写作规范.md) 与 [可访问性规范](./可访问性规范.md) 仍须遵守，以保证链接文本与列表结构可用。

## 4. 按团队规模裁剪

| 团队规模 | 必增规范 | 可省略规范 |
| --- | --- | --- |
| 个人 | [硬规则](./硬规则.md)、[项目命名规范](./项目命名规范.md)、[README标准模板](./README标准模板.md)、[LICENSE规范](./LICENSE规范.md) | 行为准则、代码所有权、迭代回顾、质量度量指标（可延后至首次公开前补齐） |
| 小型团队 | 在个人基础上增加 [代码所有权规范](./代码所有权规范.md)、[贡献指南规范](./贡献指南规范.md)、[CI工作流规范](./CI工作流规范.md)、[质量门禁](./质量门禁.md) | 事故响应、可观测性（可在服务上线后补齐） |
| 组织 | 全量适用；另须落实 [NOTICE规范](./NOTICE规范.md)、[SECURITY模板](./SECURITY模板.md)、[免责声明](./免责声明.md)、[事故响应规范](./事故响应规范.md)、[质量度量指标规范](./质量度量指标规范.md)、[需求追踪矩阵规范](./需求追踪矩阵规范.md) | 无 |

团队规模扩大时，治理类规范应在仓库对外可见前补齐，不得等到首次发布后再追加。

## 5. 按发布阶段裁剪

| 发布阶段 | 应引入 | 可延迟 | 声明要求 |
| --- | --- | --- | --- |
| 原型验证 | [硬规则](./硬规则.md)、[项目命名规范](./项目命名规范.md)、[README标准模板](./README标准模板.md)、[通用写作规范](./通用写作规范.md) | 质量门禁、可观测性、事故响应、法律文件 | 须标注「降级模式」，列出延迟项 |
| 首次公开 | 在原型基础上增加 [质量门禁](./质量门禁.md)、[开源合规规范](./开源合规规范.md)、[LICENSE规范](./LICENSE规范.md)、[免责声明模板](./免责声明模板.md)、[贡献指南模板](./贡献指南模板.md)、[行为准则模板](./行为准则模板.md)、[SECURITY模板](./SECURITY模板.md)、[徽章规范](./徽章规范.md) | 迁移指南、迭代回顾（可待首个版本迭代后补齐） | 不得省略 P0 门禁项 |

## 6. 组合方案

### 6.1 最小可用组合

适用于个人原型或私有验证仓，共 10 篇：

| 用途 | 规范 |
| --- | --- |
| 约束 | [硬规则](./硬规则.md)、[禁止事项](./禁止事项.md) |
| 立项 | [项目立项与需求规范](./项目立项与需求规范.md)、[项目命名规范](./项目命名规范.md) |
| 门面 | [README标准模板](./README标准模板.md)、[通用写作规范](./通用写作规范.md) |
| 工程 | [代码风格规范](./代码风格规范.md)、[提交信息规范](./提交信息规范.md)、[测试规范](./测试规范.md) |
| 发布 | [推送与发布规范](./推送与发布规范.md)、[LICENSE规范](./LICENSE规范.md) |

使用此组合时必须在交付物中声明降级模式，并在首次公开前补齐第 6.3 节的完整组合。

### 6.2 标准公开组合

在最小可用组合基础上，补齐质量、合规、治理与运维的基础项：加入 [质量门禁](./质量门禁.md)、[README章节规范](./README章节规范.md)、[README视觉排版规范](./README视觉排版规范.md)、[徽章规范](./徽章规范.md)、[文档矩阵](./文档矩阵.md)、[开源合规规范](./开源合规规范.md)、[免责声明模板](./免责声明模板.md)、[SECURITY模板](./SECURITY模板.md)、[贡献指南模板](./贡献指南模板.md)、[行为准则模板](./行为准则模板.md)、[变更日志规范](./变更日志规范.md)、[版本管理规范](./版本管理规范.md)、[可访问性规范](./可访问性规范.md)、[CI工作流规范](./CI工作流规范.md)、[Issue与PR模板规范](./Issue与PR模板规范.md)、[安全与隐私规范](./安全与隐私规范.md)。

该组合满足公开仓库的 Gate A、B、C 全部放行条件，是大多数项目的推荐起点。

### 6.3 完整合规组合

适用全部规范，用于组织级项目、面向监管场景分发的项目，或需要 expert / Skill / MCP / 命令行程序化接入的项目。篇数以 [简体中文索引](./README.md) 为准，启用时应逐项核验 [生命周期映射表](./生命周期映射表.md) 的阶段门禁。

## 7. 冲突处理

1. 同一维度内出现冲突时，以发布阶段较晚者的要求为准；原型阶段的简化不得延续至公开阶段。
2. 不同维度出现冲突时，按第 2 节优先级处理，强制约束与阶段门禁不得被任何维度覆盖。
3. 项目确有特殊情形需偏离本指南时，须在交付物中记录偏离的规范、理由与补偿措施，并提交审查。
4. 降级模式不得用于对外公开仓库，亦不得作为跳过许可证或安全门禁的依据。
