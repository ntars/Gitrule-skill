# 文档矩阵

> 本文件解决什么问题：定义每个交付文档的唯一职责、严禁放入的内容与拆分约束，确保一文件一职责、禁止合并。

## 1. 文件与职责

| 文件 | 唯一职责 | 严禁放入 |
|---|---|---|
| `README.md` | 首页：这是什么、如何安装、如何运行、详情查阅位置 | 全量 API、贡献流程、更新日志 |
| `LICENSE` | 许可证全文 | 任何说明文字 |
| `CHANGELOG.md` | 面向使用者的版本变更 | 内部重构细节、开发计划 |
| `CONTRIBUTING.md` | 外部贡献者的流程与规范 | 项目功能说明 |
| `CODE_OF_CONDUCT.md` | 行为准则 | 技术内容 |
| `SECURITY.md` | 漏洞上报渠道与响应策略 | 已知漏洞列表 |
| `docs/api.md` | 完整 API 参考 | 教程 |
| `docs/architecture.md` | 架构与模块边界 | 使用示例 |
| `docs/naming.md` | 命名规范 | 其他规范 |
| `docs/release.md` | 发布流程与版本策略 | 变更记录 |
| `.github/PULL_REQUEST_TEMPLATE.md` | PR 自查清单 | 项目介绍 |
| `.github/ISSUE_TEMPLATE/*.yml` | 结构化 issue 表单 | 自由文本 |
| `.github/workflows/*.yml` | CI/CD | 说明文档 |

> 说明：`docs/naming.md` 的规范正文见 [项目命名规范](./项目命名规范.md)；`docs/release.md` 的规范正文见 [推送与发布规范](./推送与发布规范.md)。

## 2. 约束

- 单文件超过 300 行必须拆分到 `docs/`，README 只留摘要 + 链接。
- 文件名固定大写，路径固定，不得自创目录层级。
- 每个文档开头一句话说明「本文件解决什么问题」，结尾给出相关文件交叉链接。
