# مواصفة الترويج للمصادر المفتوحة

> المشكلة التي يحلها هذا الملف: يحدد قنوات الترويج قبل إصدار المشروع المفتوح المصدر وبعده، وإيقاع الإصدار، ومواد الصفحة الرئيسية، وقواعد إدارة المجتمع، بحيث يحصل المشروع، بعد اكتمال وثائقه القابلة للاستخدام، على ظهور يوازي جمهوره المستهدف.

تستند قائمة القنوات والمبادئ في هذا الملف إلى فصل الترويج في كتاب «دليل التجوال في GitHub» لـ phodal؛ وقد أثبت ذلك المشروع ملاءمة هذه الممارسات للمجتمع الصيني للمصادر المفتوحة بحجم 11,362 نجمة.

## 1. المبادئ الأساسية

1. **الجودة قبل الترويج**: الترويج يضخّم جودة قائمة ولا يعالج نقصاً. لا يجوز بدء الترويج قبل جاهزية README والأمثلة والوثائق والاختبارات.
2. **المشروع ليس كل الترويج**: إلى جانب الشيفرة وREADME، يجب إعداد وثائق مفصلة وبرامج أمثلة وآلية استجابة للمسائل.
3. **وضوح الدافع**: يخدم الترويج هدفاً محدداً (جذب مستخدمين أوائل، أو استقطاب مساهمين، أو جمع ملاحظات)، ولا يجوز الترويج سعياً وراء عدد النجوم.
4. **ملاءمة القناة**: تُختار القنوات وفق الحزمة التقنية للمشروع وجمهوره المستهدف، تجنباً للنشر غير المتمايز.
5. **العرض الصادق**: لا يجوز اختلاق عدد النجوم أو التنزيلات أو حالات الاستخدام؛ ويجب أن تستند مقارنة الميزات إلى وقائع قابلة للتحقق.

## 2. قائمة التحضير قبل الإصدار

| الفئة | المتطلب | أساس الحكم |
| --- | --- | --- |
| الصفحة الرئيسية | اجتياز README لفحص الأسئلة الأربعة (ماذا يفعل/ماذا يحل/الميزات/المثال) | [مواصفة أقسام README](./readme-sections-specification.md) |
| النص في جملة واحدة | بيان الفئة والمحددات بوضوح، وقابلية إعادة التلاوة مستقلاً | القسم 1.1 نفسه |
| المثال | توفير hello world قابل للتشغيل في خطوتين | [القالب القياسي لـ README](./readme-standard-template.md) |
| الوثائق | اكتمال وثائق التثبيت والإعداد وAPI | [مصفوفة الوثائق](./document-matrix.md) |
| الرخصة | وجود LICENSE واتساقه مع المعرّف في README | [مواصفة LICENSE](./license-specification.md) |
| الامتثال | تغطية NOTICE لتبعيات الأطراف الثالثة | [مواصفة NOTICE](./notice-specification.md) |
| مدخل المجتمع | جاهزية قوالب Issue ودليل المساهمة ومدونة السلوك | [مواصفة دليل المساهمة](./contribution-guide-specification.md) |
| آلية الاستجابة | تحديد مسؤول الاستجابة ومدة الاستجابة | [مواصفة الاستجابة للحوادث](./incident-response-specification.md) |

الترويج قبل إتمام هذه القائمة سلوك محظور بهذه المواصفة.

### 3.3 القنوات الخاصة بالمشروع

1. مداخل المجتمع في README المشروع (Discussions وDiscord)؛
2. حسابات التواصل الخاصة بالمشروع، لنشر الإصدارات والفعاليات؛
3. موقع الوثائق وموقع الأمثلة، كصفحات تستقبل الزيارات الخارجية.

## 4. إيقاع الإصدار

1. **فترة التسخين**: إتمام قائمة القسم 2، وإعداد النص في جملة واحدة ولقطات الشاشة وصور العرض المتحركة وغيرها من المواد.
2. **فترة الإطلاق الأول**: النشر في 1–2 قناة من أكثرها ملاءمة، تجنباً لتكرار المحتوى نفسه على منصات متعددة.
3. **فترة الاستجابة**: الاستجابة بكثافة خلال 72 ساعة من الإطلاق الأول، ومعالجة Issue والملاحظات.
4. **فترة التكرار**: التحديث المستمر وفق إيقاع إصدار الإصدارات، مع بيان التغييرات في كل إصدار.
5. **فترة الترسيخ**: تجميع المسائل المتكررة في وثيقة أسئلة شائعة، وإعادة تغذية الوثائق بها.

## 5. متطلبات مواد الصفحة الرئيسية

| المادة | المواصفة | الغرض |
| --- | --- | --- |
| النص في جملة واحدة | بما لا يتجاوز 60 حرفاً صينياً / 25 كلمة إنجليزية؛ ويستخدم وصف المستودع صيغة مدمجة ثنائية اللغة «اللغة الوطنية \| الإنجليزية»، انظر القسم 5 من [مواصفة تسمية المشاريع](./project-naming-specification.md) | وصف المستودع والملخص الاجتماعي |
| لقطة الشاشة | نسختان للسمة الفاتحة والداكنة، بعرض مضبوط | الشاشة الأولى من README |
| صورة العرض المتحركة | بحجم مضبوط بعد الضغط، تعرض المسار الأساسي | قسم العرض في README |
| الشعار | بصيغة SVG، بنسختين فاتحة وداكنة | الشاشة الأولى وبطاقات التواصل |
| جدول مقارنة الميزات | مبني على وقائع قابلة للتحقق، ويشمل سيناريوهات عدم الملاءمة | README أو موقع الوثائق |

يجب تحديث المواد بالتوازي مع الإصدارات، تجنباً لعرض واجهات قديمة.

## 6. إدارة المجتمع

1. يُوفَّر مدخل واضح للمساهمين لأول مرة، مثل وسم `good first issue`.
2. يجب أن يكون للاستجابة للمسائل سجل، تجنباً لتكرار المسائل ذاتها مراراً.
3. تسري مدونة السلوك على جميع قنوات المجتمع، انظر [مواصفة مدونة السلوك](./code-of-conduct-specification.md).
4. تُجمع شكر المساهمين في موضع واحد، تجنباً لتفرّقها في النص.
5. يُمنع الحصول على متابعة زائفة عبر استدراج النجوم أو التبادل على الإعجابات.

## 7. الممارسات المحظورة

1. يُمنع الترويج قبل إتمام قائمة الجودة.
2. يُمنع اختلاق بيانات المشروع وحالات استخدامه أو المبالغة فيهما.
3. يُمنع تكرار المحتوى نفسه على قنوات متعددة.
4. يُمنع ازدراء مشاريع مماثلة لتحسين صورة المشروع.
5. يُمنع استخدام أساليب استدراجية للحصول على عدد النجوم.
