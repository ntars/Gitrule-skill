# مواصفة توثيق API

> المشكلة التي يحلها هذا الملف: يحدد بنية وثيقة مرجع API الكاملة وحقولها، ليكون أساساً لكتابة `docs/api.md`، مع الفصل الصارم عن المحتوى التعليمي.

## 1. البنية الإلزامية

يجب أن يتضمن كل بند في API ما يلي:

| الحقل | المتطلب |
| --- | --- |
| توقيع الواجهة | الطريقة أو المسار أو النموذج الأولي للدالة، كاملاً وقابلاً للنسخ |
| المعاملات | الاسم والنوع والإلزامية والقيمة الافتراضية ونطاق القيم والوصف |
| القيمة المرجعة | نوع البنية ووصفها |
| رموز الأخطاء | رمز الخطأ وشرط التفعيل وطريقة المعالجة |
| مثال الاستدعاء | مثال أدنى قابل للتشغيل، مع تحديد اللغة |
| تحديد المعدل والحصص | حدود تكرار الاستدعاء والحصص ومعالجة التجاوز |

## 2. القواعد الإلزامية

1. يجب كتابة نوع المعاملات والقيم المرجعة وقيودها، ولا يجوز حذف القيم الافتراضية.
2. يجب سرد رموز الأخطاء كاملة، ولا يجوز الاكتفاء بعبارة «قد يحدث خطأ».
3. يجب وسم كتل الشيفرة بمعرّف اللغة، ويجب أن تكون الأمثلة قابلة للتشغيل بشكل مستقل.
4. يحتوي هذا الملف على المعلومات المرجعية فقط، ولا يتضمن دروساً ولا خلفيات ولا شروح تصميم (انظر [مواصفة أقسام README](./readme-sections-specification.md) للدروس والخلفيات).

## 3. متطلبات الاتساق

يجب أن يتطابق توقيع الواجهة في وثيقة API مع التنفيذ الفعلي في الشيفرة؛ ويجب أن تتوافق تسمية المعاملات مع متطلبات الدقة في [المواصفة العامة للكتابة](./general-writing-specification.md)؛ أما المصطلحات فانظر [معجم المصطلحات](./glossary.md).
