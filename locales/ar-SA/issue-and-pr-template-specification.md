# مواصفة قوالب Issue وطلبات السحب

> المشكلة التي يحلها هذا الملف: يحدد تصميم الحقول والصيغة ومتطلبات الكتابة للنماذج المهيكلة `.github/ISSUE_TEMPLATE/*.yml` وقائمة الفحص الذاتي في `.github/PULL_REQUEST_TEMPLATE.md`، بحيث يصبح الإبلاغ عن المشكلات وإيداع التغييرات مقيَّداً بمدخلات قابلة للتنفيذ.

## 1. مبادئ التصميم

1. **الهيكلة قبل النص الحر**: تُعرَّف نماذج Issue بـ YAML، ويُوجَّه الملء عبر القوائم المنسدلة ومربعات الاختيار والحقول الإلزامية، لتقليل البلاغات غير المفيدة.
2. **تقليل الحقول الإلزامية**: يُحتفظ فقط بالحقول اللازمة لتحديد المشكلة، ويُمنع وسم الحقول الاختيارية كإلزامية.
3. **إظهار الفحص الذاتي**: يسرد قالب طلب السحب بنود الفحص الذاتي القابلة للتحديد في صورة قائمة تحقق، لتجنب تخطي المساهمين خطوات أساسية.
4. **مسؤولية واحدة**: نموذج Issue مسؤول عن جمع المعلومات ولا يحمل تعريف المشروع؛ وقالب طلب السحب مسؤول عن الفحص الذاتي ولا يكرر وصف الوظائف (وفق [مصفوفة الوثائق](./document-matrix.md)).

## 2. بنية نموذج Issue

### 2.1 الملف والتسمية

- المسار ثابت وهو `.github/ISSUE_TEMPLATE/*.yml`، ولكل قالب ملف واحد.
- يُستخدم في اسم الملف أحرف صغيرة وواصلات، مثل `bug-report.yml` و`feature-request.yml` و`question.yml`.
- يُوفَّر قالبان على الأقل: «تقرير العيب» و«طلب الميزة».

### 2.2 الحقول القياسية

| الحقل | النوع | إلزامي | الغرض |
| --- | --- | --- | --- |
| `name` | نص | نعم | اسم عرض القالب |
| `description` | نص | نعم | وصف الغرض من القالب |
| `title` | بادئة نص | نعم | بادئة عنوان الـ issue المولَّد تلقائياً |
| `labels` | مصفوفة | لا | الوسوم المضافة تلقائياً |
| `body` | مصفوفة | نعم | قائمة حقول النموذج |

أنواع الحقول الشائعة في `body`:

| النوع | الحالة المناسبة | مثال |
| --- | --- | --- |
| `markdown` | نص توضيحي بلا إدخال | تعليمات الملء |
| `textarea` | وصف نصي طويل | خطوات إعادة الإنتاج |
| `input` | نص قصير في سطر واحد | رقم الإصدار |
| `dropdown` | خيارات محدودة | نظام التشغيل، درجة الخطورة |
| `checkboxes` | تأكيدات متعددة | هل تم البحث عن بلاغات مكررة |

### 2.3 قائمة حقول تقرير العيب

1. وصف المشكلة (`textarea`، إلزامي): ما حدث.
2. السلوك المتوقع (`textarea`، إلزامي): ما ينبغي أن يحدث.
3. خطوات إعادة الإنتاج (`textarea`، إلزامي): مرقَّمة، وقابلة للإعادة بشكل مستقل.
4. بيئة التشغيل (`input` أو `dropdown`): نظام التشغيل، بيئة التشغيل، إصدار المشروع.
5. السجلات أو لقطات الشاشة (`textarea`): تقديم معلومات الخطأ، مع إخفاء المعلومات الحساسة.
6. تأكيد فحص التكرار (`checkboxes`، إلزامي): تم البحث في الـ issues القائمة.

### 2.4 قائمة حقول طلب الميزة

1. بيان المشكلة (`textarea`، إلزامي): ما القدرة الناقصة حالياً.
2. حالة الاستخدام (`textarea`، إلزامي): من يحتاجها وفي أي حال.
3. الحل المرغوب (`textarea`): كيف يُرغب في تنفيذه.
4. البدائل (`textarea`): الطرق الأخرى التي دُرست.
5. أثر التوافق (`dropdown`): هل يتضمن تغييراً كاسراً.

## 3. بنية قالب طلب السحب

### 3.1 الأقسام الإلزامية

يجب أن يتضمن `PULL_REQUEST_TEMPLATE.md` الأقسام التالية بترتيب ثابت:

1. وصف التغيير: ما الذي غيّره هذا التعديل، ورقم الـ issue المقابل.
2. نوع التغيير: يُحدَّد بمربع اختيار (ميزة، إصلاح، وثائق، إعادة هيكلة، اختبارات، وغيرها؛ الأنواع في [مواصفة رسائل الإيداع](./commit-message-specification.md)).
3. قائمة الاختبار الذاتي: بنود الفحص الذاتي القابلة للتحديد.
4. التغيير الكاسر: يُكتب «لا يوجد» عند عدم وجوده؛ وعند وجوده تُكتب طريقة الترحيل (انظر [مواصفة دليل الترحيل](./migration-guide-specification.md)).
5. الوثائق ذات الصلة: هل تم تحديث README وCHANGELOG ووثائق API بالتزامن.

### 3.2 مثال قائمة الاختبار الذاتي

```markdown
## قائمة الاختبار الذاتي

- [ ] نجاح البناء محلياً
- [ ] نجاح الاختبارات ذات الصلة، وإضافة اختبارات للميزات الجديدة
- [ ] كتابة رسالة الإيداع وفق [مواصفة رسائل الإيداع](./commit-message-specification.md)
- [ ] تحديث الوثائق بالتزامن أو تأكيد عدم الحاجة إلى تحديثها
- [ ] عدم إدراج مفاتيح أو بيانات خصوصية أو ملفات كبيرة
```

## 4. قوالب قابلة للنسخ

### 4.1 نموذج تقرير العيب

يُحفظ باسم `.github/ISSUE_TEMPLATE/bug-report.yml`:

```yaml
name: تقرير العيب
description: الإبلاغ عن خلل وظيفي قابل لإعادة الإنتاج
title: "[Bug]: "
labels: ["bug"]
body:
  - type: markdown
    attributes:
      value: |
        ابحث في الـ issues القائمة قبل الإيداع لتجنب التكرار.
        لا تلصق مفاتيح أو رموز وصول أو معلومات خصوصية شخصية.
  - type: checkboxes
    id: duplicate-check
    attributes:
      label: فحص التكرار
      options:
        - label: بحثت في الـ issues القائمة وأؤكد أن هذا ليس بلاغاً مكرراً
          required: true
  - type: textarea
    id: description
    attributes:
      label: وصف المشكلة
      description: ما حدث فعلياً
      placeholder: بعد تنفيذ أمر install كان رمز خروج البرنامج 1
    validations:
      required: true
  - type: textarea
    id: expected
    attributes:
      label: السلوك المتوقع
      description: ما ينبغي أن يحدث
    validations:
      required: true
  - type: textarea
    id: steps
    attributes:
      label: خطوات إعادة الإنتاج
      description: مرقَّمة، لتمكين الآخرين من الإعادة بشكل مستقل
      placeholder: |
        1. تنفيذ الأمر
        2. ملاحظة المخرجات
        3. ظهور خلل
    validations:
      required: true
  - type: input
    id: version
    attributes:
      label: إصدار المشروع
      placeholder: v1.0.0
    validations:
      required: true
  - type: dropdown
    id: os
    attributes:
      label: نظام التشغيل
      options:
        - macOS
        - Linux
        - Windows
        - أخرى
    validations:
      required: true
  - type: textarea
    id: logs
    attributes:
      label: السجلات أو لقطات الشاشة
      description: تقديم معلومات الخطأ، مع إخفاء المعلومات الحساسة
      render: shell
  - type: checkboxes
    id: security
    attributes:
      label: تأكيد أمن المعلومات
      options:
        - label: تأكدت من عدم تضمين مفاتيح أو رموز وصول أو خصوصية شخصية
          required: true
```

### 4.2 نموذج طلب الميزة

يُحفظ باسم `.github/ISSUE_TEMPLATE/feature-request.yml`:

```yaml
name: طلب ميزة
description: اقتراح قدرة جديدة أو تحسين
title: "[Feature]: "
labels: ["enhancement"]
body:
  - type: textarea
    id: problem
    attributes:
      label: بيان المشكلة
      description: القدرة الناقصة حالياً
    validations:
      required: true
  - type: textarea
    id: scenario
    attributes:
      label: حالة الاستخدام
      description: من يحتاج هذه القدرة وفي أي حال
    validations:
      required: true
  - type: textarea
    id: proposal
    attributes:
      label: الحل المرغوب
      description: كيف يُرغب في تنفيذه
  - type: textarea
    id: alternatives
    attributes:
      label: البدائل
      description: الطرق الأخرى التي دُرست
  - type: dropdown
    id: breaking
    attributes:
      label: هل يتضمن تغييراً كاسراً
      options:
        - لا
        - نعم
        - غير محدد
    validations:
      required: true
```

### 4.3 قالب طلب السحب

يُحفظ باسم `.github/PULL_REQUEST_TEMPLATE.md`:

````markdown
## وصف التغيير

{{变更说明}}

## نوع التغيير

- [ ] ميزة (feat)
- [ ] إصلاح (fix)
- [ ] وثائق (docs)
- [ ] تنسيق (style)
- [ ] إعادة هيكلة (refactor)
- [ ] اختبارات (test)
- [ ] بناء أو سلسلة الأدوات (build / ci)

## قائمة الاختبار الذاتي

- [ ] نجاح البناء محلياً
- [ ] نجاح الاختبارات ذات الصلة، وإضافة اختبارات للميزات الجديدة
- [ ] كتابة رسالة الإيداع وفق مواصفة رسائل الإيداع
- [ ] تحديث الوثائق بالتزامن أو تأكيد عدم الحاجة إلى تحديثها
- [ ] عدم إدراج مفاتيح أو بيانات خصوصية أو ملفات كبيرة

## التغيير الكاسر

{{破坏性变更说明}}

## الوثائق ذات الصلة

- [ ] تم تحديث README أو لا حاجة لتحديثه
- [ ] تم التسجيل في CHANGELOG
- [ ] تم تحديث وثائق API أو لا حاجة لتحديثها
````

### 4.4 جدول العناصر النائبة

| العنصر النائب | إلزامي | نقاط الملء |
| --- | --- | --- |
| `{{变更说明}}` | نعم | جملة واحدة تصف التغيير، مع رقم الـ issue بصيغة `#` متبوعة بالأرقام |
| `{{破坏性变更说明}}` | نعم | يُكتب «لا يوجد» عند عدم وجود تغيير كاسر؛ وعند وجوده تُكتب خطوات الترحيل مع رابط دليل الترحيل |

تُعدّ `name` و`description` و`title` و`labels` في نماذج YAML بيانات وصفية للقالب، وتُستبدل حسب واقع المشروع؛ وتُعدَّل أنواع الحقول وقيم `required` في `body` وفق قوائم الحقول في القسمين 2 و3، ويُمنع حذف الحقول الإلزامية.

### 4.5 مثال ملء كامل

مثال على ملء تقرير العيب:

````markdown
## وصف المشكلة

بعد تنفيذ `npm run build` توقفت العملية، وكان رمز الخروج 1.

## السلوك المتوقع

نجاح البناء وإخراج مجلد `dist/`.

## خطوات إعادة الإنتاج

1. سحب الوسم v1.0.0
2. تنفيذ `npm ci`
3. تنفيذ `npm run build` وملاحظة رمز الخروج 1

## إصدار المشروع

v1.0.0

## نظام التشغيل

macOS

## السجلات أو لقطات الشاشة

```
Error: Cannot find module 'mdlint-core'
```

## تأكيد أمن المعلومات

- [x] تأكدت من عدم تضمين مفاتيح أو رموز وصول أو خصوصية شخصية
````

## 5. متطلبات الكتابة

1. تُستخدم صيغة الأمر أو الصيغة التقريرية في وصف الحقول، ويُمنع الأسلوب العامي.
2. يُقدَّم لكل حقل إلزامي مثال ملء أو متطلب صيغة.
3. توضح النصوص الإرشادية «سبب الحاجة إلى هذه المعلومة»، وتتجنب المطالب الفضفاضة.
4. تُنبِّه الحقول المتعلقة بالخصوصية إلى إخفاء البيانات (انظر [مواصفة الأمن والخصوصية](./security-and-privacy-specification.md)).
5. تُحدَّث القوالب مع تطور المشروع، وتُحذف الحقول المهجورة ولا تتراكم طويلاً.

## 6. المحظورات

1. يُمنع دمج جميع أنواع المشكلات في قالب نص حر واحد.
2. يُمنع تعيين حقول إلزامية لا علاقة لها بتحديد المشكلة.
3. يُمنع إدراج تعريف المشروع أو محتوى تسويقي في القوالب.
4. يُمنع أن يغفل قالب طلب السحب قائمة الاختبار الذاتي وبيان التغيير الكاسر.
