# مواصفة الشارات

> ما تحله هذه الوثيقة: تحدد صياغة عنوان URL للشارات (Badge) في README، ومعاملات النمط، وترميز الألوان، وانتقاء المعلومات، وترتيب العرض، والتحكم في العدد، باعتماد Shields.io تطبيقاً رئيسياً، وتقدّم أمثلة صيغة قابلة للنسخ وإعدادات معاملات موصى بها.

جميع المعاملات المذكورة في هذه الوثيقة مُتحقَّق منها وفق وثائق Shields.io الرسمية (صفحتا Static Badge وLogos، وبيان صيغة badge-maker)؛ أما بيانات معدلات الظهور فمستمدّة من إحصاء بالعيّنة أجراه هذا المشروع على ملفات README لمشاريع مفتوحة المصدر في الصدارة، ووسمت بـ«قياس فعلي».

## 1. الصياغة الأساسية

### 1.1 بنية عنوان URL للشارة الثابتة

تمرّر الشارة الثابتة معاملاتها عبر مسار عنوان URL، والبنية القياسية كما يلي:

```text
https://img.shields.io/badge/<标签>-<消息>-<颜色>?style=<样式>&<其他查询参数>
```

تُفصل المقاطع الثلاثة للعنوان بالشرطة `-`:

| المقطع | الاسم | إلزامي | البيان |
| --- | --- | --- | --- |
| المقطع 1 | التسمية (label) | لا | النص الأيسر، يوضح اسم المؤشر |
| المقطع 2 | الرسالة (message) | نعم | النص الأيمن، يعرض قيمة المؤشر |
| المقطع 3 | اللون (color) | نعم | لون الخلفية على اليمين |

الصيغة ذات المقطعين (حذف التسمية والاكتفاء بالرسالة واللون) صحيحة كذلك:

```text
https://img.shields.io/badge/<消息>-<颜色>
```

### 1.2 قواعد هروب المحارف

يجب هروب المسافات والمحارف الخاصة في مسار عنوان URL، والقواعد كما يلي:

| المحرف المُدخل | كتابته في URL | مثال |
| --- | --- | --- |
| مسافة | `_` أو `%20` | `v0.1 prototype` ← `v0.1%20prototype` |
| شرطة سفلية `_` | `__` (شرطتان سفليتان) | `my_label` ← `my__label` |
| شرطة `-` | `--` (شرطتان) | `dev-build` ← `dev--build` |

المثال النموذجي الذي قدّمه المستخدم يطابق هذه الصياغة، ويمكن استخدامه مباشرةً:

```markdown
![Status](https://img.shields.io/badge/status-v0.1%20prototype-8957e5?style=flat-square)
```

ومعناه: التسمية `status`، والرسالة `v0.1 prototype` (المسافة بـ `%20`)، واللون `8957e5` (بنفسجي ست عشري)، والنمط `flat-square`.

### 1.3 صيغة التضمين في Markdown

```markdown
![版本](https://img.shields.io/badge/version-1.2.0-blue?style=flat-square)
```

عند الحاجة إلى نقر ينقل إلى وجهة، غلّف الصورة برابط:

```markdown
[![许可证](https://img.shields.io/badge/license-MIT-blue.svg)](./LICENSE)
```

## 2. معامل النمط (style)

يحدد `style` التصميم البصري العام للشارة، ويقبل خمس قيم، وقيمته الافتراضية `flat`.

| القيمة | السمات البصرية | حالات الاستخدام | مرات الظهور المقيسة (N=120) |
| --- | --- | --- | --- |
| `flat` | زوايا قائمة، مسطّح، وهو الافتراضي في Shields.io | الخيار الأول العام، متوافق مع معظم السمات | 32 |
| `flat-square` | زوايا قائمة بلا استدارة، أكثر إحكاماً | الشاشات الأولى التي تنشد الانتظام والصرامة | 60 |
| `for-the-badge` | كبير وسميك، عالي التباين | العنصر البصري الرئيسي في الأعلى، والشارات التأكيدية | 65 |
| `social` | زوايا مستديرة، لونان يميناً ويساراً، مسطّح | الشاشات الأولى ذات الطابع الاجتماعي | 12 |
| `plastic` | تدرّج لامع، محاكاة واقعية | الطابع القديم، وهو الآن أقل استخداماً | 1 |

**الإعداد الموصى به**:

- يجب توحيد `style` في كل الشارات داخل README واحد، ويُحظر الخلط. وهذا الشرط الأول للاتساق البصري.
- يُفضّل `flat` أو `flat-square` للمشاريع العامة؛ وعند تعزيز الشاشة الأولى بهوية العلامة يُستخدم `for-the-badge` للجميع.
- الأكثر شيوعاً في القياس الفعلي `for-the-badge` (65 مرة) و`flat-square` (60 مرة)، ويمكن اعتماد أيّهما افتراضياً.

مثال الصيغة:

```markdown
![build](https://img.shields.io/badge/build-passing-brightgreen?style=for-the-badge)
![build](https://img.shields.io/badge/build-passing-brightgreen?style=flat-square)
```

## 3. معامل اللون (color / labelColor)

### 3.1 ثلاث طرق لتمثيل اللون

وفق بيان badge-maker، يدعم كلٌّ من `color` (اليمين) و`labelColor` (خلفية اليسار) الطرق الثلاث التالية:

**الطريقة الأولى: ألوان Shields.io المسمّاة**

| الدلالة | الألوان المسمّاة |
| --- | --- |
| نجاح | `brightgreen`، `green`، `success` |
| تنبيه | `yellow`، `yellowgreen`، `orange`، `important` |
| تحذير | `red`، `critical` |
| معلومات | `blue`، `informational` |
| محايد | `grey` / `gray`، `lightgrey` / `lightgray`، `inactive` |

ملاحظة: القيمة الافتراضية لـ `labelColor` هي `grey`، ولـ `color` هي `lightgrey` (وتذكر الوثائق أن `inactive` إحدى القيم الافتراضية كذلك)؛ وبعض الألوان المسمّاة تختلف قليلاً عن ألوان CSS بالاسم نفسه، ويُعتمد ما يظهر في عرض Shields.io.

**الطريقة الثانية: اللون الست عشري**

يدعم ثلاث أو ست خانات ست عشرية، ويجوز حذف البادئة `#` أو الإبقاء عليها:

```text
?color=8957e5
?color=007fff
?color=%23007fff    ← عند الإبقاء على # يجب ترميزه بـ %23
```

**الطريقة الثالثة: قيم ألوان CSS**

يدعم `rgb(...)` و`rgba(...)` و`hsl(...)` و`hsla(...)` وألوان CSS المسمّاة (مثل `aqua` و`fuchsia` و`lightslategray`)، ويجب ترميزها في عنوان URL عند الاستخدام.

### 3.2 مقابلة دلالات الألوان (الإعداد الموصى به)

| نوع المعلومة | اللون الموصى به | مثال الرسالة |
| --- | --- | --- |
| نجاح البناء ونجاح الاختبارات | `brightgreen` / `success` | `passing` |
| فشل البناء | `red` / `critical` | `failing` |
| إصدار مستقر | `blue` | `v1.2.0` |
| إصدار أولي أو نموذج تجريبي | بنفسجي مخصص `8957e5` / `orange` | `v0.1 prototype` |
| الترخيص | `blue` / `green` | `MIT` |
| حالة الوثائق | `yellowgreen` | `docs` |
| الإهمال أو التوقف عن الصيانة | `red` / `inactive` | `deprecated` |

**الإعداد الموصى به**: تُثبَّت مجموعة واحدة لألوان العلامة وأخرى لألوان الحالة داخل كل مشروع، ولا يجوز تغييرها عشوائياً؛ وتُستخدم دلالة اللون نفسها في المستودع بأكمله.

مثال الصيغة:

```markdown
![覆盖率](https://img.shields.io/badge/coverage-95%25-orange?style=flat-square)
![状态](https://img.shields.io/badge/status-v0.1%20prototype-8957e5?style=flat-square)
![许可证](https://img.shields.io/badge/license-MIT-blue?style=flat-square)
```

## 4. معاملات الأيقونة (logo / logoColor / logoSize)

### 4.1 استخدام Simple Icons

يأخذ المعامل `logo` معرّف slug للأيقونة من Simple Icons، بصيغة `?logo=<slug>`. وأكثر المعرّفات استخداماً كما يلي:

| الاستخدام | slug | مرات الظهور المقيسة (N=120) |
| --- | --- | --- |
| مستودع GitHub | `github` | 35 |
| مجتمع Discord | `discord` | 20 |
| حزمة npm | `npm` | 4 |
| منصات Apple | `apple` | 3 |
| Docker | `docker` | 3 |
| منصة التواصل X | `x` | 3 |
| حزمة Python | `pypi` | 2 |

القائمة الكاملة للمعرّفات تُعتمد من موقع Simple Icons أو من `slugs.md` في مستودع simple-icons.

### 4.2 ألوان الأيقونة وحجمها

- `logoColor`: يضبط لون أيقونة Simple Icons، ويدعم الست عشري وrgb وhsl وألوان CSS المسمّاة؛ ويعمل على أيقونات Simple Icons فقط، ولا أثر له على الأيقونات المخصصة.
- `logoSize`: عند ضبطه على `auto` تُقاس الأيقونة تلقائياً بحسب المحتوى، وهو مناسب للأيقونات العريضة؛ ويعمل كذلك على Simple Icons فقط.

مثال الصيغة:

```markdown
![repo](https://img.shields.io/badge/github-repo-blue?logo=github)
![logo 配色](https://img.shields.io/badge/logo-javascript-blue?logo=javascript&logoColor=f5f5f5)
```

يمكن تمرير أيقونة مخصصة عبر `logo=data:image/svg+xml;base64,...`، لكن عنوان URL يصبح طويلاً جداً ويصعب صيانته، ولا يُنصح به إلا عند حاجة خاصة.

## 5. معاملات استعلام أخرى

| المعامل | الوظيفة | مثال |
| --- | --- | --- |
| `label` | تجاوز النص الافتراضي على اليسار (المسافة تحتاج إلى ترميز) | `?label=healthiness` |
| `labelColor` | لون خلفية اليسار | `?labelColor=abcdef` |
| `color` | لون خلفية اليمين | `?color=fedcba` |
| `cacheSeconds` | مدة تخزين HTTP (بالثواني)، وأي قيمة أقل من الافتراضي تُهمل | `?cacheSeconds=3600` |
| `link` | تحديد وجهة النقر للنصفين الأيمن والأيسر | يعمل داخل وسم `<object>` فقط، ولا أثر له على صور Markdown |

## 6. الشارات الديناميكية

تسحب Shields.io الشارات الديناميكية من خدمات خارجية آنياً، فلا حاجة إلى تحديث القيم يدوياً. وأكثر الأنواع استخداماً:

| الفئة | نمط URL | الاستخدام |
| --- | --- | --- |
| حالة البناء | `https://img.shields.io/github/actions/workflow/status/<owner>/<repo>/<workflow>` | حالة CI |
| الإصدار | `https://img.shields.io/npm/v/<package>` | أحدث إصدار npm |
| الترخيص | `https://img.shields.io/npm/l/<package>` | رخصة الحزمة |
| عدد النجوم | `https://img.shields.io/github/stars/<owner>/<repo>` | درجة الانتشار |
| عدد الـ Issue | `https://img.shields.io/github/issues/<owner>/<repo>` | المشكلات المعلّقة |
| عدد التنزيلات | `https://img.shields.io/npm/dt/<package>` | التنزيلات التراكمية |

يمكن إضافة معاملات مثل `?style=` و`?logo=` إلى الشارات الديناميكية، بالقواعد نفسها المتبعة في الشارات الثابتة. وتتبنّى المشاريع المرجعية عادةً تركيبة «شارات ديناميكية تعرض مؤشرات حقيقية + شارات ثابتة تكمّل الحالات المخصصة».

## 7. انتقاء المعلومات وترتيب العرض

### 7.1 انتقاء المعلومات

ينبغي أن تنقل الشارات معلومات حالة «قابلة للتحقق ومفيدة للقارئ». ويُقترح الاقتصار على الفئات التالية:

1. حالة البناء / الاختبارات؛
2. الإصدار أو أحدث نشر؛
3. الترخيص؛
4. حالة الوثائق؛
5. قنوات المجتمع (Discord، منتدى النقاش)؛
6. الحالة المخصصة للمشروع (نموذج تجريبي، قيد الصيانة، مهمَل).

ولا يجوز إدراج: أعداد تنزيلات بلا مصدر، أو وسوم تسويقية لا علاقة لها بالمشروع، أو تقييمات لا يمكن التحقق منها، أو كتل ألوان زخرفية محضة.

### 7.2 ترتيب العرض

يُفضّل الترتيب «الحالة ← الإصدار ← الترخيص ← المنصة/المجتمع ← الحالة المخصصة»، بحيث تتناقص الأهمية من اليسار إلى اليمين. والسبب: حالة البناء تحدد ما إذا كان القارئ سيعتمد المشروع، والإصدار يحدد الحكم على التوافق، والترخيص يحدد إمكانية الاستخدام، وكلها معلومات تسبق القرار.

### 7.3 التحكم في العدد

- المشاريع العادية: 4–6 شارات.
- مجموعات الموارد أو مشاريع المنظومة: يمكن التوسّع إلى 8–10 شارات.
- توضع كل الشارات بعد اسم المشروع والتموضع في جملة واحدة وقبل المتن، في سطر منفرد أو حاوية موسّطة، ولا تُنثر داخل المتن.

### 7.4 شارة حالة التسليم الثابتة

التطبيق القياسي للبند 6 في الفقرة 7.1 «الحالة المخصصة للمشروع» هو شارة حالة التسليم الثابتة، يحدّث المؤلف قيمتها يدوياً، وهي مناسبة لتقدّم التسليم وحالة الصيانة عند غياب مصدر بيانات خارجي:

```text
![Status](https://img.shields.io/badge/status-4%20of%204%20delivered-brightgreen?style=flat-square)
```

1. البنية القياسية هي `badge/<标签>-<消息>-<颜色>`، وبالنمط الموحّد `?style=flat-square`؛ ومعنى المثال «تسليم 4 مخرجات كاملة».
2. تُكتب المسافة في نص الرسالة بـ `%20`، والشرطة القصيرة بـ `--`، والشرطة السفلية بـ `__`؛ ويُحظر وجود أسطر جديدة أو محارف خاصة غير مهروبة.
3. أعراف دلالة الألوان: `brightgreen` مكتمل، و`yellow` قيد التنفيذ، و`red` متعثّر، و`lightgrey` لم يبدأ.
4. عند تغيّر القيم يجب تحديث الشارة والمتن معاً، ولا يجوز أن تتأخر الشارة طويلاً عن الحالة الفعلية؛ وإذا تعذّرت المزامنة فيُنتقل إلى شارة ديناميكية.
5. يوضّح نص `alt` المعنى الفعلي، مثل `![交付状态]`؛ ويمكن ربطه بقائمة المخرجات أو بقسم الفهرس المقابل.

## 8. سهولة الوصول وملاءمة السمة

- يجب أن يوضّح نص `alt` لكل شارة معناها الفعلي، مثل `![构建状态]` لا `![badge]`.
- في السمتين الداكنة والفاتحة يمكن تبديل مصدر صورة الشارة عبر `<picture>`؛ ويحافظ استخدام `for-the-badge` مع `labelColor=000` على تباين مستقر في السمتين.
- يجب أن تكون الشارة قابلة للنقر للانتقال إلى مصدر البيانات المقابل (حالة البناء إلى CI، والإصدار إلى صفحة مدير الحزم، والترخيص إلى ملف LICENSE).
