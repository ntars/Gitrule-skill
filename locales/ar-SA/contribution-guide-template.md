# قالب دليل المساهمة

> المشكلة التي يحلها هذا الملف: يوفر قالب دليل مساهمة قابلاً للنسخ المباشر، لتوليد `CONTRIBUTING.md` للمشروع، ويغطي طرق المشاركة وتهيئة البيئة ونموذج الفروع وإطار الإيداع ومتطلبات طلب السحب ومتطلبات الاختبارات ومدونة قواعد السلوك وبيان الرخصة؛ وتغطي إرشادات التعبئة المرافقة طرق التكييف لمختلف أنواع المشاريع.

## 1. إرشادات الاستخدام

1. انسخ كامل محتوى «نص القالب» في القسم 3، وأنشئ منه ملف `CONTRIBUTING.md` في جذر المشروع.
2. استبدل العناصر النائبة وفق القسم 4؛ ويجب أن تكون جميع الأوامر أوامر حقيقية قابلة للتنفيذ مباشرةً.
3. كيّف القالب حسب الحالات في القسم 5: في المشاريع الوثائقية تُحذف فقرة أوامر الاختبار، ويُحتفظ بمسار Issue وطلب السحب.
4. الأساس التنظيمي في [مواصفة دليل المساهمة](./contribution-guide-specification.md)؛ وتفاصيل الفروع والإيداع في [مواصفة سير عمل Git والفروع](./git-workflow-and-branching-specification.md) و[مواصفة رسائل الإيداع](./commit-message-specification.md) على الترتيب.

## 2. مبادئ التخصيص

- **قابل للتنفيذ**: تُكتب الأوامر كاملة مع مجلد العمل ومتطلبات التبعيات، ويُمنع الاكتفاء بعبارة «تثبيت التبعيات» دون أمر محدد.
- **بشرط تشغيل واضح**: توضح كل خطوة متى تُنفَّذ والنتيجة المتوقعة.
- **غير فضفاض**: يُمنع الاكتفاء بعبارة «طلبات السحب مرحّب بها» دون إجراء فعلي، وفق فحص حوكمة المجتمع في [بوابة الجودة](./quality-gate.md).
- **الإحالة بدل النسخ**: تحيل قواعد الإيداع والاختبار إلى المواصفات المقابلة، ولا تُكرر نصها الكامل في هذا الملف.

## طرق المشاركة

| المساهمة بالشيفرة | إصلاح العيوب، تنفيذ الميزات | انظر المسار أدناه |
| الإبلاغ عن المشكلات | تعذر الاستخدام، إعادة إنتاج خلل | {{问题反馈入口}} |

## نموذج الفروع

- اشتق فرعاً شخصياً من {{基准分支}}، بصيغة التسمية `{{分支命名格式}}` (مثال: `feat/وصف موجز`).
- يعالج كل طلب سحب مسألة واحدة فقط؛ وعند اتساع نطاق التغيير يُرجى تقسيمه.
- يُمنع الإيداع المباشر في {{受保护分支}}، ويجب الدمج عبر طلب سحب.

## إطار الإيداع

تتبع رسالة الإيداع Conventional Commits، بصيغة `type(scope): subject`. الأنواع الشائعة: `feat` و`fix` و`docs` و`refactor` و`test` و`chore`. مثال:

```text
feat(cli): add config file support
```

القواعد الكاملة في [مواصفة رسائل الإيداع]({{提交规范链接}}).

## متطلبات طلب السحب

أكمل الفحص الذاتي التالي قبل إيداع طلب السحب:

- [ ] نطاق التغيير واحد، وله Issue أو شرح مقابل.
- [ ] رسالة الإيداع مطابقة للصيغة أعلاه.
- [ ] تنفيذ `{{测试命令}}` محلياً ينجح بالكامل.
- [ ] تحديث الوثائق بالتزامن مع الشيفرة.
- [ ] عدم إدراج مفاتيح أو مفاتيح خاصة أو معلومات حساسة.
- [ ] يوضح الوصف محتوى التغيير وسببه وطريقة التحقق منه.

## متطلبات الاختبارات

| بند الفحص | الأمر | معيار النجاح |
| --- | --- | --- |
| اختبارات الوحدة | `{{单元测试命令}}` | نجاح كامل |
| الفحص الساكن | `{{lint 命令}}` | لا أخطاء |
| التحقق من البناء | `{{构建命令}}` | نجاح البناء |

حد التغطية: {{覆盖率要求}}.

## مدونة قواعد السلوك

المشاركة في هذا المشروع تعني الموافقة على الالتزام بـ [مدونة قواعد السلوك](./CODE_OF_CONDUCT.md).

## إطار Issue

- ابحث في المسائل القائمة قبل السؤال، لتجنب التكرار.
- يجب أن يتضمن تقرير العيب: معلومات البيئة، وخطوات إعادة الإنتاج، والنتيجة المتوقعة، والنتيجة الفعلية، وسجل الأخطاء.
- يجب أن يوضح اقتراح الميزة حالة الاستخدام والبديل عند عدم اعتماده.

## بيان الرخصة

تخضع المساهمات افتراضياً لرخصة هذا المشروع {{许可证名称及 SPDX 标识符}}، والنص الكامل في [LICENSE](./LICENSE). الإيداع يعني أن لك الحق في ترخيص مساهمتك بهذه الرخصة.

## 5. إرشادات التعبئة وأشكال الحالات

| الحالة | الأقسام الإلزامية | الأقسام القابلة للحذف | نقاط التعديل |
| --- | --- | --- | --- |
| مشروع برمجي | الكل | لا شيء | يجب أن تُنفَّذ الأوامر فعلياً وتجتاز التحقق |
| مشروع وثائقي | طرق المشاركة، متطلبات طلب السحب، مدونة قواعد السلوك، الرخصة | متطلبات الاختبارات، تهيئة بيئة التطوير | حذف جدول الاختبار، والاحتفاظ بالفحص الذاتي لطلب السحب |
| مشروع فردي | طرق المشاركة، متطلبات طلب السحب، مدونة قواعد السلوك، الرخصة | يمكن اختصار تهيئة البيئة | بيان ما إذا كانت المساهمات الخارجية مقبولة |
| مشروع مؤسسي | الكل | لا شيء | إضافة رابط اتفاقية ترخيص المساهم (CLA) والمتطلبات القانونية |

مقابلة الأخطاء الشائعة:

| الكتابة الخاطئة | النتيجة | الكتابة الصحيحة |
| --- | --- | --- |
| «المساهمات بجميع أشكالها مرحّب بها» | لا مسار محدد، فيعجز المساهم عن البدء | إدراج جدول طرق المشاركة والمداخل |
| «شغّل الاختبارات فقط» | لا يُعرف الأمر ولا معيار النجاح | بيان الأمر ومعيار النجاح وحد التغطية |
| كتابة `npm install` بينما المشروع يستخدم pnpm | أمر غير قابل للتنفيذ | المطابقة مع ملف lockfile الفعلي |

## 6. مثال كامل

التالي مثال معبأ لفقرة الأوامر، للاسترشاد بالتنسيق فقط.

```bash
# استنساخ المستودع
git clone https://github.com/owner/repo.git
cd repo

# تثبيت التبعيات
pnpm install

# التشغيل المحلي
pnpm dev
```

النتيجة المتوقعة: فتح localhost:3000 وظهور الصفحة الرئيسية.
