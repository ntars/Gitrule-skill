# مواصفة إمكانية الوصول

> المشكلة التي يحلها هذا الملف: تحديد متطلبات إمكانية الوصول لوثائق المشروع وملف README وواجهة المستخدم، بحيث يكون المحتوى متاحاً بالقدر نفسه لقارئ يستخدم قارئ الشاشة أو يتنقل بلوحة المفاتيح أو لديه ظروف بصرية مختلفة.

## 1. نطاق التطبيق

1. إمكانية وصول الوثائق: ملف README، وموقع الوثائق، وأمثلة الشيفرة، والجداول، والصور.
2. إمكانية وصول الواجهة: واجهة المستخدم في التطبيقات ومشاريع الويب.
3. إمكانية وصول سطر الأوامر: نص المساعدة، ورسائل الخطأ، وتنسيق المخرجات.

## 2. إمكانية وصول الوثائق

### 2.1 الصور والوسائط

1. يجب تزويد كل صورة بنص `alt` يصف مضمون الصورة ووظيفتها؛ وتُستخدم قيمة `alt` فارغة للصور الزخرفية.
2. لا يجوز استخدام نصوص بلا معلومة مثل «صورة» أو «لقطة شاشة» أو «image» بوصفها نص `alt`.
3. يجب أن توضح صور GIF المتحركة مضمونها في نص مجاور، تجنباً لنقل المعلومة بالحركة وحدها.
4. يجب أن توفر الرسوم البيانية شرحاً نصياً أو جدول بيانات في الوقت نفسه، ولا يجوز تمييز سلاسل البيانات باللون وحده.

### 2.2 العناوين والبنية

1. تكون مستويات العناوين متتابعة، ولا يجوز تجاوز مستوى (انظر [مواصفة التنسيق البصري لملف README](./readme-visual-layout-specification.md)).
2. عنوان واحد فقط من المستوى الأول في الوثيقة كلها.
3. تُستخدم القوائم بصيغة Markdown القياسية، ليتعرف قارئ الشاشة عليها كقائمة.
4. يجب أن يتضمن الجدول صف رؤوس، ولا يجوز استخدام جداول بلا رؤوس لتخطيط الصفحات.

### 2.3 الروابط والنصوص

1. يجب أن يوضح نص الرابط هدفه بشكل مستقل، ويُحظر استخدام «اضغط هنا» أو «المزيد».
2. لا يجوز أن يكون اللون الوسيلة الوحيدة لنقل المعلومة، بل يجب أن يقترن بنص أو رمز.
3. تُحفظ المسافات عند مزج النصوص العربية والأجنبية، لضمان صحة تقسيم الكلمات والنطق.
4. يُذكر الاسم الكامل للاختصار عند ظهوره الأول.

### 2.4 الشيفرة والجداول

1. تُوسم كتل الشيفرة بلغتها، لتسهيل تعرف الأدوات المساعدة عليها (انظر [مواصفة التنسيق البصري لملف README](./readme-visual-layout-specification.md)).
2. يكون محتوى خلايا الجدول موجزاً، ويُتجنب الدمج عبر الصفوف لما يسببه من صعوبة في تحليل القارئ.
3. تُعطى الأوامر الطويلة بصيغة متعددة الأسطر، دون الاعتماد على التمرير الأفقي.

## 3. إمكانية وصول الواجهة

### 3.1 التنقل بلوحة المفاتيح

1. يمكن الوصول إلى جميع العناصر التفاعلية وتشغيلها بلوحة المفاتيح.
2. يتطابق ترتيب التركيز مع الترتيب البصري، وتكون حالة التركيز مرئية بوضوح.
3. يُوفر مدخل اختصار لتخطي المحتوى المتكرر (مثل الانتقال إلى المحتوى الرئيسي).

### 3.2 الدلالة والتسميات

1. تُستخدم وسوم دلالية للتعبير عن البنية والأدوار، ويُتجنب محاكاة عناصر التحكم بعناصر غير دلالية.
2. يجب أن يكون لعناصر التحكم في النماذج تسميات مرتبطة بها، وأن ترتبط رسائل الخطأ بالحقل المقابل.
3. تُنقل تغيرات الحالة الديناميكية إلى التقنيات المساعدة عبر تنبيهات إمكانية الوصول.

### 3.3 الظروف البصرية

1. يلبي تباين النص مع الخلفية متطلبات القراءة؛ فلا يقل تباين النص الأساسي عن 4.5:1، ولا تباين النص الكبير عن 3:1.
2. يُدعم المظهران الفاتح والداكن للنظام، ولا يغيّر تبديل المظهر بنية المعلومات (انظر [مواصفة التنسيق البصري لملف README](./readme-visual-layout-specification.md)).
3. تُتاح خيارات تقليل الحركة، ويُتجنب المحتوى عالي التردد الوميضي الذي يعمل تلقائياً.
4. يظل التخطيط قابلاً للاستخدام عند تكبير النص إلى 200%، دون اقتطاع للمحتوى.

## 4. إمكانية وصول سطر الأوامر

1. توضح رسائل الخطأ السبب والإجراء الإصلاحي الممكن، ولا يجوز الاكتفاء بإخراج رمز الخطأ.
2. تكون مخرجات `--help` واضحة التصنيف، وتدرج المعاملات الإلزامية والقيم الافتراضية.
3. يُدعم متغير بيئة لتعطيل المخرجات الملوّنة، تسهيلاً لقارئات الشاشة ومعالجة السجلات.
4. توفر المطالبات التفاعلية معاملات مكافئة غير تفاعلية، دعماً لسيناريوهات الأتمتة.

## 5. قائمة التحقق

- [ ] جميع الصور لها نص `alt` واضح المعلومة.
- [ ] مستويات العناوين متتابعة، وعنوان واحد من المستوى الأول في الوثيقة.
- [ ] نص الرابط مفهوم بشكل مستقل.
- [ ] الجداول لها رؤوس، واللون ليس حامل المعلومة الوحيد.
- [ ] كتل الشيفرة موسومة بلغتها.
- [ ] عناصر الواجهة قابلة للتشغيل بلوحة المفاتيح، والتركيز مرئي.
- [ ] التباين يلبي الحد الأدنى، والمظهران الفاتح والداكن مقروءان.
- [ ] نص المساعدة ورسائل الخطأ يرشدان إلى الخطوة التالية.

## 6. الممارسات المحظورة

1. يُحظر نقل معلومات أساسية بصور محضة دون توفير بديل نصي.
2. يُحظر التعبير عن الحالة أو الخطأ باللون وحده.
3. يُحظر استخدام نص رابط لا معنى له.
4. يُحظر إزالة نمط مؤشر التركيز دون توفير بديل.
