# القواعد المطلقة

> المشكلة التي يحلها هذا الملف: سرد القواعد غير القابلة للخرق التي يؤدي خرق أي منها إلى إيقاف الدفع، ولا يجوز معها مبدأ «نُدفع أولًا ثم نُصحّح».

## جدول القواعد المطلقة

| # | القاعدة |
|---|---|
| H1 | يجب أن يطابق اسم المستودع [مواصفة تسمية المشاريع](./project-naming-specification.md)، في جميع حالات الأحرف والمحارف والطول |
| H2 | يجب أن يوجد ملف `LICENSE`؛ فغياب الرخصة = احتفاظ افتراضي بحقوق النشر، ولا يجوز النشر العام |
| H3 | لا يجوز إيداع أي مفتاح سري أو رمز وصول أو مفتاح خاص أو ملف `.env` أو مفاتيح AK/SK لمزود السحابة أو سلاسل اتصال قواعد البيانات |
| H4 | لا يجوز إيداع نواتج البناء أو مجلدات التبعيات أو إعدادات بيئة التطوير أو ملفات النظام غير المرغوب فيها |
| H5 | لا يجوز أن يتجاوز الملف الواحد 100MB؛ وما يتجاوز 50MB يجب أن يمر عبر LFS أو يُستبعد |
| H6 | يجب أن يوجد `README.md` يتضمن: تعريف المشروع في جملة واحدة، والتركيب، وأدنى مثال قابل للتشغيل، والرخصة |
| H7 | يجب أن يكون الفرع الافتراضي محميًا، ويُحظر الدفع المباشر إلى `main`/`master` |
| H8 | يُحظر استخدام `git push --force` على الفروع العامة؛ ويُسمح في الفروع الشخصية بـ `--force-with-lease` فقط |
| H9 | يجب أن ينجح `build` و`test` قبل الدفع؛ وإذا كان التكامل المستمر أحمر فلا يجوز الدمج في الفرع الرئيسي |
| H10 | يجب أن تتبع رسالة الإيداع Conventional Commits، ويُحظر الإيداع بلا معلومات مثل `wip`/`update`/`fix bug` |
| H11 | كل وثيقة ملف مستقل بمسؤولية مستقلة؛ ويُحظر تكديس كل المحتوى في README (انظر [مصفوفة الوثائق](./document-matrix.md)) |
| H12 | متى ما دُفع مفتاح سري، يجب فورًا تدوير المفتاح وتنظيف السجل، ولا يجوز الاكتفاء بإيداع حذف |

## قيود التنفيذ

- خرق أي قاعدة يعني **إيقاف الدفع**، ولا يجوز مبدأ «نُدفع أولًا ثم نُصحّح».
- يجب أن تظهر نتيجة الحكم على H1–H12 في قائمة المشكلات ضمن [صيغة تقرير المراجعة](./audit-report-format.md)، مع دليل لكل بند (مسار:سطر / مخرجات الأمر).
- عند خرق H12 يُتبع مسار معالجة الحوادث في [مواصفة الدفع والإصدار](./push-and-release-specification.md).
