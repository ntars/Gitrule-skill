# تقرير بحث قالب README

> ما تحله هذه الوثيقة: تسجّل منهج البحث في قالب README القياسي الحالي، وحجم العينة، والنتائج الكمّية، لتوفير سند بيانات لـ [قالب README القياسي](./readme-standard-template.md) وللمواصفات المتخصصة، مع تحديد حدود المنهج وقيوده.

## 1. أهداف البحث ومنهجه

### 1.1 الأهداف

دراسة المشاريع مفتوحة المصدر الرائدة الأعلى ترتيباً في عدد النجوم، واستخلاص قواعد بنية README والوثائق المرتبطة بها، وتنظيم أقسامها، وعرضها البصري، واستخدام الشارات فيها، وصياغة مواصفة عامة وقالب قابلين لإعادة الاستخدام.

### 1.2 مصادر البيانات

- بيانات وصفية للمستودعات: GitHub GraphQL Search API، بترتيب تنازلي حسب النجوم، مع تصفية `is:public archived:false fork:false`.
- نص README: GitHub REST Contents API (نقطة النهاية `readme`)، يُجلب بصيغة base64 أو raw ثم يُحلَّل.
- معاملات الشارات: وثائق Shields.io الرسمية (صفحتا Static Badge وLogos) ووصف صيغة badge-maker.
- الممارسة في المجتمع الصيني: وثائق مشروع phodal/github (دليل التجوال في GitHub، 11,362 نجمة)، ورسائل الإيداع، وفصل الترويج، لتكميل مبادئ الكتابة وخبرات التشغيل التي لا تغطيها الإحصاءات الآلية.

### 1.3 منهج الجمع

1. **البيانات الوصفية**: يعيد GitHub Search API 1000 سجل كحد أقصى في الاستعلام الواحد. ولتوسيع العينة اعتُمد تقطيع نطاقات النجوم؛ بتحديد عتبة النجوم المقابلة لكل 1000 مرتبة بالتنصيف، ثم النزول دفعة بعد دفعة بتراكم 11 دفعة، حتى الحصول في النهاية على بيانات وصفية لـ 10,995 مستودعاً رائداً.
2. **أخذ عينات README**: أُخذت عينة طبقية حسب اللغة الأساسية داخل المستودعات الرائدة 1000، تغطي Python وTypeScript وJavaScript وRust وGo وC++ وغيرها من اللغات الرئيسية، بعدد 120 مستودعاً، ونُجح في جلب نص README الأصلي لجميعها.
3. **أساس الإحصاء**: تُحسب معدلات ظهور الأقسام ومعدلات استخدام العناصر على أساس المستودع؛ وتُحسب أنماط الشارات ومعاملات logo بحسب عدد مرات ظهورها في الروابط (URL).

### 1.4 حدود المنهج (وجوب البيان)

- يضع GitHub Search API حداً أقصى 1000 سجل للاستعلام الواحد، وقد وسّع هذا التقرير الحجم بالتقطيع التراكمي، لكن حدود التقطيع تتأثر بتساوي أعداد النجوم، فالعينة مجموعة رائدة تقريبية لا ترتيباً متصلاً صارماً.
- حجم عينة README هو 120، والنتائج تعكس اتجاهاً وسمات مشتركة، ولا تمثّل توزيعاً ذا دلالة إحصائية لكل المشاريع الرائدة.
- يستند التعرف على الأقسام إلى مطابقة كلمات مفتاحية في العناوين، فيوجد انحياز إحصائي ناتج عن اختلاف الصياغة.
- يقتصر إحصاء معاملات الشارات على المعاملات الظاهرة صراحةً في الروابط، ولا تُحتسب المعاملات الافتراضية للشارات الديناميكية.

## 6. الاستنتاجات المستخلصة

1. يجب أن يقوم القالب العام على العمود الفقري: التموضع ← التثبيت ← البدء السريع ← الوثائق ← المساهمة ← الرخصة.
2. تكون الشارات افتراضياً `flat-square` أو `for-the-badge`، موحّدة في الوثيقة كلها، بعدد 4–6 شارات.
3. الصور وكتل الكود جوهر الشاشة الأولى عالية الجذب، ويجب أن تُرفق بـ `alt` ووسم اللغة.
4. نوع المشروع يحدد انتقاء الأقسام، انظر [دليل تكييف تصنيفات README](./readme-category-adaptation-guide.md).
5. الامتثال وحوكمة المجتمع (الرخصة ودليل المساهمة) موضع توافق في المشاريع الرائدة، ويُدرجان إلزاميين.
