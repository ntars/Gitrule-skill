# بوابة الجودة

> المشكلة التي يحلها هذا الملف: تحديد شروط اجتياز البوابات الثلاث، وقالب قائمة التحقق للحكم وحقولها، بما يضمن أن يكون حكم السماح بالدفع موحّداً وقابلاً للتنفيذ وقابلاً للتحقق.

## 1. البوابات الثلاث

| الطبقة | المعنى | شرط الاجتياز |
| --- | --- | --- |
| البوابة A · بوابة الأمان | المفاتيح السرية، والخصوصية، والرخصة، والملفات الكبيرة | تصفير P0 |
| البوابة B · بوابة الجودة | البناء، والاختبارات، وlint، ومعيار رسائل الإيداع، وحماية الفروع | تصفير P0، وP1 مسجّل في قائمة المهام |
| البوابة C · بوابة الصفحة الرئيسية | README، والبيانات الوصفية، ومصفوفة الوثائق، والشارات، والروابط | تصفير P0، وP1 ≤ 3 ومجدولة |

لا يُخرَج `✅ ALLOW PUSH` إلا عند اخضرار A وB وC جميعاً. ويجب تصحيح البنود غير المجتازة أو بيان سببها، وتُكتب النتيجة في [صيغة تقرير المراجعة](./audit-report-format.md).

## 2. الحكم على 14 بنداً قبل التسليم

يُحكم على كل بند قبل تسليم الوثائق، ويجب تصحيح البند غير المجتاز أو بيان سببه.

| الرقم | البند المفحوص | معيار الحكم |
| --- | --- | --- |
| G1 | العامية والالتباس | البحث في النص كاملاً عن الألفاظ العامية والإحالات الغامضة، وعدد النتائج 0 |
| G2 | اكتمال الفصول | النسختان الصينية والإنجليزية تضمان 20 فصلاً بالترتيب نفسه |
| G3 | اتساق الوظائف وهيكل الدليل | كل وظيفة يصفها README لها وحدة مقابلة في هيكل الدليل |
| G4 | دليل الميزة | لكل ميزة دليل أو وسم بانتظار الاستكمال |
| G5 | تغطية تفاصيل التصميم | الفئات الـ 10 في القسم 8 لها بنود أو وسم «لا ينطبق» |
| G6 | اكتمال التبعيات | عدد التبعيات المباشرة وغير المباشرة مطابق لشجرة التبعيات |
| G7 | دقة الرخصة | معرّف SPDX لكل تبعية مطابق للإعلان الرسمي |
| G8 | نص الرخصة | كل رخصة تُلزم بإرفاق نصها الكامل أُرفق نصها الإنجليزي |
| G9 | إشعار حقوق النشر | إشعارات حقوق النشر للمشروع وللآخرين مكتملة |
| G10 | التزامن بين اللغتين | الفصول والجداول والمصطلحات وكتل الشيفرة متطابقة في الجانبين |
| G11 | قابلية تنفيذ الأوامر | أوامر التثبيت والبدء السريع والدفع قابلة للتنفيذ مباشرةً |
| G12 | تجميع البنود المعلّقة | جميع البنود المعلّقة مجمّعة ومواضعها قابلة للتحديد |
| G13 | مصدر المواد | لكل مادة سجل مصدر ورخصة |
| G14 | المعلومات الحساسة | لا مفاتيح سرية ولا رموز وصول ولا عناوين شبكة داخلية ولا بيانات خصوصية شخصية |

## 4. تعريف الحقول

| الحقل | إلزامي | النوع | نقاط التعبئة | مثال |
| --- | --- | --- | --- | --- |
| الحاكم | نعم | نص | فرد واحد محدد، ويُحظر «الفريق» | `وانغ وو` |
| النتيجة | نعم | تعداد | PASS / FAIL / SKIP | `PASS` |
| الدليل | نعم | نص | مسار + رقم سطر أو خرج أمر، ويُحظر الحكم بلا دليل | `gitleaks: 0 findings` |
| المستوى | إلزامي شرطياً | تعداد | إلزامي عند FAIL: P0 / P1 / P2 | `P0` |
| الإجراء | إلزامي شرطياً | تعداد | إلزامي عند FAIL: الإجراء المحدد والجهة المسؤولة | `تدوير المفاتيح وتنظيف السجل` |
| سبب SKIP | إلزامي شرطياً | نص | إلزامي عند SKIP، ويُحظر التخطي بلا سبب | `لا يوجد سكربت بناء` |
| نتيجة السماح بالدفع | نعم | تعداد | ALLOW PUSH / BLOCK PUSH | `BLOCK PUSH` |
| سبب الإيقاف | إلزامي شرطياً | نص | إلزامي عند BLOCK، بسرد بنود P0 | `A2 إصابة بمفتاح في السجل التاريخي` |

## 5. إرشادات التعبئة

1. **الدليل إلزامي**: يجب أن يكون لكل حكم دليل؛ والحكم PASS بلا دليل يُعدّ لاغياً، ويجب تغييره إلى SKIP مع بيان السبب.
2. **مقابلة المستوى**: يجب وسم مستوى FAIL؛ فـ P0 يوقف السماح بالدفع مباشرةً، وP1 يُسجَّل في قائمة المهام، وP2 يُدرَج في المقترحات.
3. **عتبة البوابة C**: لا يُخرَج PASS إلا عندما تكون P1 ≤ 3 ومجدولة؛ وما زاد يجب تخفيض درجته أو إيقافه.
4. **استخدام SKIP**: عند تعذّر الفحص يُوسم SKIP + السبب، ولا يجوز كتابة PASS؛ ويُستكمل الفحص عند توفر الشروط.
5. **الاتساق**: يجب أن يتوافق حكم البوابة مع مستويات P0/P1/P2 في [مصفوفة أبعاد المراجعة](./review-dimension-matrix.md)، ومع قواعد الإيقاف في [القواعد المطلقة](./hard-rules.md).
6. **السماح بالدفع**: لا يُخرَج `✅ ALLOW PUSH` إلا عند اخضرار البوابات الثلاث؛ وأي FAIL يُخرِج `⛔ BLOCK PUSH` مع سرد سبب الإيقاف.
7. **صيغة التسليم**: تُخرَج نتيجة الحكم وفق [صيغة تقرير المراجعة](./audit-report-format.md)؛ وبعد الاجتياز يُنفَّذ [مواصفة الدفع والإصدار](./push-and-release-specification.md).

أخطاء شائعة:

| الكتابة الخاطئة | المشكلة | طريقة التصحيح |
| --- | --- | --- |
| حكم PASS بدليل فارغ | حكم لاغٍ | إضافة الدليل أو التحويل إلى SKIP |
| كتابة ALLOW PUSH مع بقاء P0 دون تصفير | خرق القواعد المطلقة | التحويل إلى BLOCK PUSH |
| SKIP بلا سبب | اشتباه في تفويت الفحص | إضافة السبب |
| بوابة C فيها 5 بنود P1 ومع ذلك PASS | تجاوز العتبة | تخفيض الدرجة أو الإيقاف |
| نتيجة الحكم نصاً فقط بلا قائمة | غير قابلة للتحقق | التعبئة بنداً بنداً بالقالب |

## 6. مثال كامل

```markdown
# حكم البوابة: markdown-lint-cli v1.0.0

تاريخ الحكم: 2026-11-20 ｜ الحاكم: وانغ وو ｜ المستودع: example/markdown-lint-cli

## البوابة A · بوابة الأمان
| الرقم | البند المفحوص | النتيجة | الدليل | المستوى | الإجراء |
| --- | --- | --- | --- | --- | --- |
| A1 | المفاتيح السرية في مساحة العمل | PASS | gitleaks detect: 0 findings | — | — |
| A2 | المفاتيح السرية في السجل التاريخي | PASS | gitleaks --log-opts=--all: 0 findings | — | — |
| A4 | وجود LICENSE ونوعه | PASS | السطر 1 من LICENSE هو MIT | — | — |
| A5 | الملفات الكبيرة وLFS | PASS | find -size +50M: لا شيء | — | — |

النتيجة: PASS، والبنود المعلقة: لا شيء

## البوابة B · بوابة الجودة
| الرقم | البند المفحوص | النتيجة | الدليل | المستوى | الإجراء |
| --- | --- | --- | --- | --- | --- |
| B1 | نجاح البناء | PASS | run #128 | — | — |
| B2 | نجاح الاختبارات | PASS | 132/132 passed | — | — |

## الحكم الإجمالي

```
