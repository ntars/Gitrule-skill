# عقد توزيع المهام على الوكلاء الفرعيين

> المشكلة التي يحلها هذا الملف: يحدد العناصر الأربعة التي يجب كتابتها صراحةً عند توزيع مهمة على وكيل فرعي، وقيود التعاون، بما يضمن أن تكون النتائج منظمة وقابلة للتحقق وخالية من انحراف القواعد.

## 1. العناصر الأربعة للتوزيع

يجب كتابة العناصر الأربعة صراحةً في كل توزيع:

```text
TASK:    <المهمة في جملة واحدة>
INPUT:   <الملفات/السياق المطلوب، الأجزاء الضرورية فقط>
OUTPUT:  <تنسيق منظم، جدول أو JSON، دون نثر>
FAIL:    <ما يُعاد عند التعذر، بدل اختلاق النتائج>
```

## 2. القيود

- ينفذ الوكيل الفرعي مهمة واحدة في المرة الواحدة، ويُمنع «اكتب README أيضاً في أثناء ذلك».
- يقتصر الوكيل الفرعي على القراءة وإخراج المقترحات؛ **أما كتابة الملفات وعمليات git فينفذها المتحكم الرئيسي وحده**.
- يجب أن تُرفق نتيجة الوكيل الفرعي بالدليل (مسار الملف + رقم السطر / خرج الأمر)؛ والنتيجة بلا دليل تُعدّ لاغية.
- لا يتواصل الوكلاء الفرعيون مباشرةً فيما بينهم، بل تُجمَّع كل النتائج عبر المتحكم الرئيسي، تجنباً لانحراف القواعد.
