# مواصفة أدوات MCP

> المشكلة التي يحلها هذا الملف: يحدد قواعد تصميم الواجهة ووصفها عند إتاحة مجموعة المواصفات كأدوات عبر بروتوكول سياق النموذج (MCP)، بما يضمن أن يكتشف النموذج الأدوات ويستدعيها بشكل صحيح.

## 1. مبادئ تصميم الأدوات

1. مسؤولية واحدة: تؤدي الأداة مهمة واحدة، وتُجتنب الواجهات الجامعة لكل شيء.
2. وصف واضح: يوضح وصف الأداة غرضها وحالات استخدامها، ليتيسر على النموذج تقدير وقت الاستدعاء.
3. معاملات صريحة: لكل معامل نوع، وبيان الإلزام، ونطاق القيم، وشرح.
4. خرج منظم: تُعاد بيانات منظمة، وتُجتنب النصوص الطويلة.

## 2. الحقول الإلزامية

| الحقل | المتطلب |
| --- | --- |
| name | معرّف فريد، بأحرف صغيرة ونمط kebab-case |
| description | الغرض وشرط التفعيل، بصياغة محددة قابلة للحكم |
| inputSchema | أنواع المعاملات، والحقول الإلزامية، والقيود |
| القيمة المعادة | تنسيق منظم وشرح الحقول |
| الخطأ | تنسيق الإرجاع عند الفشل، ويُمنع اختلاق النتائج |

## 3. الأدوات المتصلة بمجموعة المواصفات

1. أدوات استرجاع الوثائق: تُعيد نص المواصفة حسب رمز اللغة + المعرّف (المعرّفات في [مواصفة البيانات الوصفية القابلة للقراءة آلياً](./machine-readable-metadata-specification.md)).
2. أدوات القوائم: تُعيد قائمة الوثائق المتاحة وخريطة لغاتها.
3. أدوات الفحص: تفحص اكتمال مصفوفة الوثائق (انظر [مصفوفة الوثائق](./document-matrix.md)) وحالة البوابات (انظر [بوابة الجودة](./quality-gate.md)).

## 4. قواعد ملزمة

1. لا يجوز للأداة أن تُعيد نتيجة غير قابلة للفحص بوصفها PASS، بل تُوسم SKIP مع السبب (انظر [الممارسات المحظورة](./prohibited-practices.md)).
2. يجب أن يكون الخرج قابلاً للتحليل البرمجي، وخالياً من عملية التفكير الداخلية.
3. لا يجوز تسريب المحتوى الأمني عبر الأدوات (انظر [مواصفة الأمان والخصوصية](./security-and-privacy-specification.md)).
