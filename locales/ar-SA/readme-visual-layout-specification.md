# مواصفة التنسيق البصري لـ README

> المشكلة التي يحلها هذا الملف: يحدد مستويات التنسيق في README وتنظيم الفقرات واستخدام الجداول ولقطات الشاشة وملفات GIF ومواضعها، بما يحقق التوازن بين كثافة المعلومات والجاذبية البصرية.

تأتي بيانات «القياس الفعلي» في هذا الملف من إحصاء عيّنة من ملفات README لمشاريع مفتوحة المصدر رائدة أجراه هذا المشروع (العينة N=120)؛ والممارسات المرجعية مأخوذة من فحص بنية الشاشة الأولى في عدة مشاريع عالية النجوم.

## 1. مستويات التنسيق

### 1.1 مستويات العناوين

يجب أن ينشئ README تدرّجاً واضحاً للعناوين، وفق القيود التالية:

1. يُحتفظ في النص كله بعنوان واحد من المستوى الأول (`#`)، وهو اسم المشروع، في السطر الأول من الملف.
2. العناوين من المستوى الثاني (`##`) هي الأقسام الرئيسية، ويُستحسن أن يكون عددها بين 6 و12؛ والوسيط في القياس الفعلي 7.
3. تُستخدم العناوين من المستوى الثالث (`###`) للتفريع داخل القسم، ولا تُستخدم إلا عندما يكون محتوى عنوان المستوى الثاني طويلاً.
4. لا يجوز أن يتخطى تدرّج العناوين مستوى (مثل الانتقال من `#` إلى `###` مباشرةً).
5. يكون نص العنوان موجزاً، باسم أو عبارة اسمية، دون نقطة في نهايته.

### 1.2 ترتيب بنية الشاشة الأولى

الشاشة الأولى هي ما يراه القارئ دون تمرير، وتُنظَّم بالترتيب التالي:

1. شعار أو لافتة المشروع في الوسط (اختياري)؛
2. عنوان المستوى الأول (اسم المشروع)؛
3. سطر الشارات (التفاصيل في [مواصفة الشارات](./badge-specification.md))؛
4. تحديد الموقع في جملة واحدة (بيان ما هو المشروع، ولمن، وأي مشكلة يحل)؛
5. سطر روابط تنقل الأقسام (اختياري، مناسب لـ README الطويل)؛
6. ملخص الوظائف أو الميزات الأساسية.

أدلة الممارسات المرجعية: يضع `fd` و`ripgrep` تنقل الأقسام مباشرةً بعد تحديد الموقع؛ ويفتتح `next.js` و`rust-lang/rust` بشعار ولافتة في الوسط؛ ويُدرج `vscode` لقطة شاشة للمنتج فور تحديد الموقع.

### 1.3 الفقرات والمسافات

- يُضبط كل مقطع بين 1 و4 أسطر، تجنباً للنصوص الكثيفة الطويلة.
- يُترك سطر فارغ بين المقاطع، للحفاظ على انسيابية العرض بعد التصيير.
- تُقدَّم النتائج الأساسية أولاً ويأتي الشرح بعدها.
- تُترك مسافة واحدة بين العربية والإنجليزية والأرقام؛ وتُستخدم علامات الترقيم العربية والإنجليزية وفق سياق كل منهما.

## 2. قواعد استخدام الجداول

### 2.1 حالات الاستخدام

تناسب الجداول المعلومات متعددة الأبعاد القابلة للمقارنة. استخدم 36.7% من العيّنة الجداول، وهي الصيغة الموصى بها لشرح الإعداد ومصفوفة التوافق ومقابلة الأوامر. وتشمل حالات الاستخدام:

- شرح بنود الإعداد (المفتاح، والنوع، والقيمة الافتراضية، والأثر)؛
- مصفوفة توافق المنصات / الإصدارات؛
- مقابلة الأوامر أو المعاملات؛
- مقارنة الوظائف (هذا المشروع مع حلول أخرى)؛
- خارطة الطريق والحالة.

### 2.2 موضع الإدراج

يُدرج الجدول مباشرةً بعد عنوان المستوى الثاني التابع له، مع جملة تمهيدية تشرح غرضه؛ وإذا وُجدت استثناءات بعد الجدول، تُضاف في مقطع مستقل.

### 2.3 متطلبات الكتابة

| المتطلب | الشرح |
| --- | --- |
| ضبط عدد الأعمدة | من 3 إلى 6 أعمدة، ويُنظر في التقسيم عند تجاوز 6 |
| وضوح رأس الجدول | يُعطى كل عمود رأساً اسمياً قصيراً، ويُجتنب الرأس الفارغ |
| اتساق المحاذاة | يُوحَّد نمط محاذاة الجداول في النص كله |
| إيجاز المحتوى | لا تُكتب مقاطع طويلة داخل الخلية، وعند الحاجة تُستخدم حاشية أو رابط للتوسع |
| خلوّه من الخلايا الفارغة | يُكتب «لا يوجد» أو «لا ينطبق» في موضع الفراغ |

## 3. قواعد استخدام كتل الشيفرة

### 3.1 حالات الاستخدام

تُستخدم كتل الشيفرة للأوامر والإعداد واستدعاءات API وخرج الأمثلة. احتوت 66.7% من العيّنة على كتل شيفرة، وهي عنصر إلزامي في قسم «البدء السريع»، والوسيط 2 كتل.

### 3.2 متطلبات الكتابة

1. يجب أن تحمل كل كتلة شيفرة معرّف لغتها، مثل `bash` و`json` و`python` و`javascript`، لتيسير تلوين الصياغة.
2. تُعطى أمثلة الأوامر أوامر كاملة قابلة للتنفيذ، دون إغفال الخطوات السابقة.
3. عند الحاجة إلى عرض النتيجة، تُضاف كتلة شيفرة مستقلة بمعرّف `text`، مع بيان الخرج المتوقع في النص.
4. يُترك سطر فارغ قبل كل كتلة شيفرة وبعدها.
5. يُضبط محتوى الكتلة الواحدة في حدود 20 سطراً؛ والأمثلة الأطول تُقسَّم إلى كتل متعددة أو تُنقل إلى مجلد `examples/` مع رابط.
6. عند استخدام موجّه `$` في الأوامر التفاعلية، يجب توحيده في النص كله.

مثال التنسيق:

```bash
npm install <package-name>
```

```text
✓ Installation complete
```

## 4. قواعد استخدام لقطات الشاشة وملفات GIF

### 4.1 حالات الاستخدام والموازنة

| العنصر | حالات الاستخدام | ملاحظات |
| --- | --- | --- |
| لقطة شاشة ثابتة | واجهة التطبيق، ونتائج التشغيل، والمخططات | معدل الاستخدام الفعلي 63.3%، وهو الأكثر شيوعاً |
| GIF / صورة متحركة | عرض سطر الأوامر، ومسارات التفاعل، والمقارنة قبل وبعد | حجم الملف كبير، ويجب ضغطه وضبط مدته |
| الشعار / اللافتة | الهوية البصرية، والشاشة الأولى للصفحة | تُوفَّر نسختان فاتحة وداكنة |
| مخطط توضيحي | المعمارية، والمسار، وتدفق البيانات | يجب تحديثه بالتوازي مع إصدار الوثيقة |

احتوت 63.3% من العيّنة على صور. أدلة الممارسات المرجعية: يستخدم `fd` الملف `doc/screencast.svg` عرضاً تجريبياً، ويستخدم `ripgrep` لقطة لنتائج البحث، ويستخدم `vscode` لقطة لتشغيل المنتج، ويستخدم `rust` و`next.js` لافتة شعار تتكيف مع السمتين الفاتحة والداكنة.

### 4.2 موضع الإدراج

1. الشعار / اللافتة: أعلى الملف، في الوسط.
2. لقطة شاشة المنتج: بعد تحديد الموقع في جملة واحدة، وقبل «البدء السريع»، لتكوين إدراك بصري مباشر.
3. عرض GIF: قسم مستقل «Demo / عرض»، مباشرةً بعد «الوظائف الأساسية».
4. مخطط المعمارية: يُدرج في قسم «المعمارية» أو «التصميم»، أو يُنقل إلى `docs/architecture.md` مع رابط في README.

### 4.3 متطلبات الكتابة

- يجب أن يوفر كل صورة نص `alt` يصف محتوى الصورة، ويُمنع استخدام نصوص بلا معنى مثل `image` أو `لقطة شاشة`.
- تُستخدم للصور مسارات نسبية إلى موارد المستودع، أو عنوان URL مطلق مستقر؛ ويُجتنب استخدام روابط مؤقتة محدودة الصلاحية.
- للصور التي تحتاج تكيّفاً مع السمة، يُستخدم HTML `<picture>` مع `prefers-color-scheme` لتوفير نسختين فاتحة وداكنة.
- يُضبط حجم الصور: تُفضَّل WebP أو PNG محسَّن للقطات الشاشة، ويُفضَّل تحويل GIF إلى فيديو قصير أو صورة متحركة مضغوطة.
- يُضبط عرض الصورة: بخاصية `width` أو حاوية خارجية، تجنباً لكسر تخطيط الصفحة.

## 5. الروابط والتنقل

### 5.1 تنقل الأقسام

عندما يتجاوز README 200 سطر، يُضاف في الشاشة الأولى سطر روابط تنقل يشير إلى الأقسام الرئيسية:

```markdown
[التثبيت](#التثبيت) · [البدء السريع](#البدء-السريع) · [الوثائق](#الوثائق) · [المساهمة](#المساهمة)
```

### 5.2 أولوية الروابط النسبية

تُستخدم المسارات النسبية دائماً للوثائق والصور والرخصة داخل المستودع، لتبقى صالحة عند التفرّع والقراءة دون اتصال. ويجب أن تكون الروابط الخارجية من مصادر موثوقة (الوثائق الرسمية، وصفحة مدير الحزم، وصفحة CI).

## 6. قائمة تنفيذ الجمالية والجاذبية

1. تحمل الشاشة الأولى شعاراً أو عنواناً واضحاً ينقل موقع المشروع في 3 ثوانٍ.
2. الشارات بنمط موحد وألوان دلالية وعدد معتدل.
3. عنوان المستوى الأول واحد، وعناوين المستوى الثاني بين 6 و12، دون تخطي مستويات.
4. مثال شيفرة واحد على الأقل قابل للنسخ والتشغيل.
5. لقطة شاشة أو عرض تجريبي واحد على الأقل يعبّر عن قيمة المنتج.
6. تُستخدم الجداول للمعلومات المقارنة، بعدد أعمدة مضبوط ورأس واضح.
7. لكل صورة `alt`، ولكل كتلة شيفرة معرّف لغة.
8. الوثائق الطويلة تحمل تنقلاً بين الأقسام.
9. الصور والشارات مقروءة في السمتين الفاتحة والداكنة.
