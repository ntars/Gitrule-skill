# مواصفة النشر والتراجع

> المشكلة التي يحلها هذا الملف: تحديد قوالب قائمة النشر وطلب التغيير وخطة التراجع وحقولها ومعايير تنفيذها، بما يضمن إمكانية التحكم في الإطلاق، وتتبّع الحالة، والاستعادة السريعة من الأعطال.

## 1. أحكام المواصفة

1. يجب قبل النشر اجتياز CI ومراجعة الشيفرة وبوابة الجودة (انظر [بوابة الجودة](./quality-gate.md)).
2. يُبنى النشر على إصدار موسوم بـ tag، ولا تُستخدم إيداعات غير موسومة (انظر [مواصفة إدارة الإصدارات](./version-management-specification.md)).
3. يُفصل إعداد البيئة عن الشيفرة، وتُحقن الإعدادات الحساسة عبر إدارة الإعدادات، ولا تُودَع في المستودع (انظر [مواصفة الأمن والخصوصية](./security-and-privacy-specification.md)).
4. تُنفَّذ تغييرات بنية قاعدة البيانات عبر سكربتات الترحيل، ويجب أن تحقق التوافق مع الإصدارات السابقة (انظر [مواصفة تصميم قواعد البيانات](./database-design-specification.md)).
5. يجب في كل عملية نشر تسجيل رقم الإصدار والوقت والمنفّذ ومحتوى التغيير؛ ويُعدّ النشر بلا سجل نشراً غير ممتثل.
6. يجب إعداد خطة تراجع مسبقاً لكل إصدار، ولا يجوز الإطلاق دون خطة تراجع جاهزة.
7. يجب بعد النشر تنفيذ فحص السلامة والتحقق الأولي، ولا ينتهي الإصدار إلا بنجاح الاثنين معاً.

## 2. قالب قائمة النشر

```markdown
# قائمة النشر: {{项目名称}} {{版本号}}

الإصدار: {{vX.Y.Z}} ｜ tag: {{vX.Y.Z}} ｜ البيئة الهدف: {{预发布 / 生产}} ｜ الوقت المخطط: {{YYYY-MM-DD HH:MM}}

## الفحوص المسبقة
- [ ] CI أخضر بالكامل، رابط تشغيل سير العمل: {{URL}}
- [ ] اجتازت مراجعة الشيفرة، المعتمِد: {{姓名}}
- [ ] بوابات الجودة A/B/C كلها PASS
- [ ] سجل التغييرات وRelease Notes جاهزان
- [ ] خطة التراجع مُراجَعة، انظر نهاية هذا القسم
- [ ] سكربت ترحيل قاعدة البيانات مُراجَع ومتوافق مع الإصدارات السابقة
- [ ] قائمة تغييرات الإعدادات مؤكدة (البنود المحقونة غير المودعة)

## محتوى التغيير
| بند التغيير | النوع | نطاق التأثير | المتطلب المرتبط | طريقة التحقق |
| --- | --- | --- | --- | --- |
| {{功能 / 配置 / 数据迁移}} | {{新增 / 修改 / 移除}} | {{受影响模块}} | {{REQ-NNN}} | {{如何确认}} |

## خطوات التنفيذ
1. {{步骤，含具体命令或平台操作}}
2. {{灰度比例与观察时长}}
3. {{全量放量条件}}

## فحص السلامة والتحقق الأولي
| بند الفحص | شرط الحكم | طريقة التنفيذ | النتيجة |
| --- | --- | --- | --- |
| بقاء الخدمة | {{HTTP 200}} | {{命令}} | {{通过 / 未通过}} |
| المسار الحرج | {{主流程完成}} | {{命令}} | {{通过 / 未通过}} |
| نسبة الأخطاء | {{< X%}} | {{监控面板}} | {{通过 / 未通过}} |

## سجل النشر
| البند | القيمة |
| --- | --- |
| وقت النشر الفعلي | {{YYYY-MM-DD HH:MM}} |
| المنفّذ | {{姓名}} |
| المعتمِد | {{姓名}} |
| رقم الإصدار الفعلي | {{vX.Y.Z}} |
| النتيجة | {{成功 / 回滚 / 中止}} |

## خطة التراجع
- إصدار التراجع المستهدف: {{vX.Y.Z}}
- شرط التفعيل: {{错误率 > X% 持续 N 分钟 / 冒烟失败 / 数据异常}}
- صاحب القرار: {{姓名}}
- خطوات التراجع: {{具体命令或操作}}
- توافق البيانات: {{是否需要数据回滚；如果需要，说明方式}}
```

## 3. قالب سجل النشر

```markdown
## {{YYYY-MM-DD}} {{vX.Y.Z}} → {{环境}}

- رقم الإصدار: {{vX.Y.Z}}
- tag: {{vX.Y.Z}}
- الوقت: {{HH:MM}}
- المنفّذ / المعتمِد: {{姓名 / 姓名}}
- ملخص التغيير: {{一句话}}
- فحص السلامة: {{通过 / 未通过}}
- النتيجة: {{成功 / 回滚}}
- الإصدار المرتبط: {{Release Notes URL}}
- ملاحظات: {{异常与处理记录；无则写「无」}}
```

## 4. تعريف الحقول

| الحقل | إلزامي | النوع | نقاط التعبئة | مثال |
| --- | --- | --- | --- | --- |
| tag | نعم | نص | مطابق تماماً لـ tag في [مواصفة إدارة الإصدارات](./version-management-specification.md) | `v1.2.0` |
| البيئة الهدف | نعم | تعداد | ما قبل الإنتاج / الإنتاج، ويُحظر خلط الإعدادات | `الإنتاج` |
| بند التغيير.النوع | نعم | تعداد | إضافة / تعديل / إزالة | `تعديل` |
| المتطلب المرتبط | نعم | قائمة | رقم REQ، ويُكتب «لا يوجد» عند عدم وجود تغيير متطلب | `REQ-007` |
| نسبة الإطلاق التدريجي | لا | نسبة مئوية | إلزامية عند الإطلاق التدريجي المرحلي | `10% → 50% → 100%` |
| شرط الحكم | نعم | عتبة | قابل للمراقبة والحكم | `HTTP 200` |
| رقم الإصدار الفعلي | نعم | نص | يجب بيان السبب عند اختلافه عن الإصدار المخطط | `v1.2.1` |
| شرط تفعيل التراجع | نعم | عتبة + مدة | يُحظر التعبير من نوع «الإحساس بخلل» | `نسبة الأخطاء >1% لمدة 5 دقائق` |
| توافق البيانات | نعم | نص | تحديد واضح لضرورة تراجع البيانات | `لا حاجة لتراجع البيانات` |

## 5. تعليمات التعبئة

1. **الفحوص المسبقة**: تُؤشَّر بنداً بنداً، ويُحظر التأشير على المقطع كاملاً دفعة واحدة؛ ويُوقَف النشر عند إنجاز أي بند.
2. **محتوى التغيير**: يجب ربط كل بند برقم REQ؛ ويُكتب «لا يوجد» للتغييرات التشغيلية البحتة بلا متطلب، مع بيان أساس التغيير.
3. **فحص السلامة**: يجب أن يكون شرطاً قابلاً للحكم الآلي؛ وعبارة «الخدمة تبدو طبيعية» غير مقبولة.
4. **شرط تفعيل التراجع**: يجب إعطاء العتبة والمدة معاً، لتجنّب التفعيل الخاطئ بسبب التذبذب اللحظي.
5. **الإطلاق التدريجي**: يجب بعد كل مرحلة إطلاق انتظار المدة المقررة وتسجيل نتيجة المراقبة قبل الانتقال إلى المرحلة التالية.
6. **سجل النشر**: يُضاف حسب الزمن ولا يغطي التاريخ السابق؛ ويجب توافق رقم الإصدار مع الدفع وtag وRelease Notes.
7. **تنفيذ التراجع**: يُستخدم `git revert` لإنتاج إيداع معاكس لتراجع الشيفرة، ولا يُدفع قسرياً إلى تاريخ سبق إتاحته (انظر [مواصفة الدفع والإصدار](./push-and-release-specification.md)).

الأخطاء الشائعة:

| الصياغة الخاطئة | المشكلة | طريقة التصحيح |
| --- | --- | --- |
| النشر بإيداع غير موسوم بـ tag | الإصدار غير قابل لإعادة الإنتاج | وسم tag أولاً ثم النشر |
| كتابة «نتراجع عند وجود مشكلة» في خطة التراجع | لا شرط تفعيل ولا خطوات | إضافة العتبة وصاحب القرار والخطوات |
| تغيير قاعدة البيانات غير متوافق مع الإصدار السابق | البيانات غير صالحة للاستخدام بعد التراجع | اعتماد منهج التوسيع والترحيل والتقليص بثلاث خطوات |
| كتابة سجل النشر بأثر رجعي | الحالة غير موثوقة | التسجيل الفوري وقت النشر |
| فحص السلامة يقتصر على الصفحة الرئيسية | المسار الحرج غير متحقق | إضافة حالات التحقق الأولي للمسار الرئيسي |

## 6. مثال كامل

```markdown
# قائمة النشر: markdown-lint-cli v1.0.0

الإصدار: v1.0.0 ｜ tag: v1.0.0 ｜ البيئة الهدف: الإنتاج ｜ الوقت المخطط: 2026-11-20 10:00

## الفحوص المسبقة
- [x] CI أخضر بالكامل: https://github.com/example/markdown-lint-cli/actions/runs/123
- [x] اجتازت مراجعة الشيفرة، المعتمِد: Li Si
- [x] بوابات الجودة A/B/C كلها PASS
- [x] سجل التغييرات وRelease Notes جاهزان
- [x] خطة التراجع مُراجَعة
- [x] لا يوجد ترحيل لقاعدة البيانات
- [x] قائمة تغييرات الإعدادات مؤكدة: لا يوجد

## محتوى التغيير
| بند التغيير | النوع | نطاق التأثير | المتطلب المرتبط | طريقة التحقق |
| --- | --- | --- | --- | --- |
| قاعدة المسافة بين النص الصيني والإنجليزي | إضافة | محرك القواعد | REQ-001 | تنفيذ TC-001 |
| مخرجات تقرير CLI | تعديل | وحدة التقرير | REQ-007 | تنفيذ TC-012 |

## خطوات التنفيذ
1. سحب tag v1.0.0 والتحقق من المجموع الاختباري
2. إطلاق تدريجي بنسبة 10%، ومراقبة لمدة 10 دقائق
3. بعد انخفاض نسبة الأخطاء إلى أقل من 0.1% يُرفع الإطلاق إلى 100%

## فحص السلامة والتحقق الأولي
| بند الفحص | شرط الحكم | طريقة التنفيذ | النتيجة |
| --- | --- | --- | --- |
| بقاء الخدمة | HTTP 200 | curl /healthz | ناجح |
| المسار الحرج | اكتمال فحص 50 وثيقة | سكربت shell | ناجح |
| نسبة الأخطاء | أقل من 0.1% | لوحة المراقبة | ناجح |

## خطة التراجع
- إصدار التراجع المستهدف: v0.9.3
- شرط التفعيل: نسبة الأخطاء >1% لمدة 5 دقائق
- صاحب القرار: Li Si
- خطوات التراجع: تبديل وسم النشر إلى v0.9.3 وتنفيذ فحص توافق البيانات
- توافق البيانات: لا تغيير في قاعدة البيانات، ولا حاجة لتراجع البيانات
```
