# مواصفة الأمن والخصوصية

> المشكلة التي يحلها هذا الملف: تحديد حماية المعلومات الحساسة، وقائمة الخصوصية للبيانات، وقالب SECURITY.md، وحقول الإبلاغ عن الثغرات، بما يضمن عدم وجود تسريب قبل النشر العام، وامتثال معالجة البيانات، وإمكانية الوصول إلى قناة الثغرات.

## 1. نصوص المواصفة

1. لا يجوز إيداع المفاتيح السرية والرموز والمفاتيح الخاصة وملفات `.env` ومفاتيح AK/SK لدى مزودي السحابة وسلاسل اتصال قواعد البيانات (يقابل القاعدة المطلقة H3).
2. يجب أن يغطي فحص المفاتيح السرية مساحة العمل والتاريخ الكامل، وأن يُنفَّذ قبل الدفع (انظر [مواصفة الدفع والإصدار](./push-and-release-specification.md)).
3. يجب تنظيف النطاقات الداخلية وعناوين IP والمعلومات الشخصية وبقايا السجلات قبل النشر العام (يقابل البُعد D1).
4. إذا كان المفتاح السري قد دُفع بالفعل، يجب تدويره فوراً وتنظيف التاريخ، ولا يجوز الاكتفاء بإيداع حذف (يقابل H12).
5. بيان البيانات التي تُجمَع وأغراض جمعها وموقع تخزينها ومدة الاحتفاظ بها؛ وتشفير النقل والتخزين، وإخفاء الهوية عند العرض.
6. يتبع نموذج الأذونات مبدأ الحد الأدنى الضروري؛ وتُقيَّم البيانات العابرة للحدود تقييماً منفصلاً.
7. توفير قناة إبلاغ عن الثغرات تصل مباشرة إلى المشرفين، مع الالتزام بالسرية وحدود زمنية للاستجابة؛ وبيان المخاطر المعروفة بصدق، دون التعهد بأمان مطلق.

## 2. قالب الفحص الذاتي للمعلومات الحساسة

```markdown
# الفحص الذاتي للمعلومات الحساسة: {{项目名称}}

تاريخ الفحص: {{YYYY-MM-DD}} ｜ المنفذ: {{姓名}} ｜ تغطية التاريخ: {{是 / 否}}

| بند الفحص | الأداة / الأمر | النتيجة | الإجراء |
| --- | --- | --- | --- |
| مفاتيح مساحة العمل | {{扫描工具}} | {{命中数}} | {{已清理 / 无}} |
| مفاتيح الإيداعات التاريخية | {{扫描工具 --all}} | {{命中数}} | {{已轮换 / 无}} |
| `.env` وملفات بيانات الاعتماد | `git ls-files \| grep -E ...` | {{文件数}} | {{已移除 / 无}} |
| النطاقات الداخلية / IP | {{检索命令}} | {{命中数}} | {{已替换 / 无}} |
| المعلومات الشخصية | {{检索命令}} | {{命中数}} | {{已脱敏 / 无}} |
| بقايا السجلات واللقطات | {{检查命令}} | {{命中数}} | {{已清理 / 无}} |

الخلاصة: {{通过 / 不通过}}
- قائمة المفاتيح المدوَّرة: {{无 / 列出}}
- المراجع: {{姓名}}
```

## 4. قالب SECURITY.md

```markdown
# سياسة الأمن

## الإصدارات المدعومة
| الإصدار | هل تُقبل تقارير الأمن |
| --- | --- |
| {{最新主版本}} | نعم |
| {{旧版本}} | لا / المشكلات الجسيمة فقط |

## قناة الإبلاغ
- المفضلة: {{私密渠道，如 GitHub Security Advisories}}
- الاحتياطية: {{加密邮箱}}
- لا يجوز الإبلاغ عن الثغرات عبر Issue عام.

## التعهد بالاستجابة
| المرحلة | المدة |
| --- | --- |
| تأكيد الاستلام | {{2 个工作日}} |
| التأكيد المبدئي | {{5 个工作日}} |
| الإصلاح والإفصاح | {{视严重程度，目标 30 天}} |

## مسار المعالجة
الاستلام → التأكيد → الإصلاح → الإفصاح → الإعلان

## المخاطر المعروفة
{{如实说明当前已知风险；无则写「暂无已知风险」，不得承诺绝对安全}}
```

## 5. تعريف الحقول

| الحقل | إلزامي | النوع | نقاط التعبئة | مثال |
| --- | --- | --- | --- | --- |
| تغطية التاريخ | نعم | تعداد | يجب اختيار «نعم» للحكم بالنجاح | `نعم` |
| بند الفحص.النتيجة | نعم | رقمي | يُكتب عدد المطابقات، ويُمنع «لا يوجد على الأرجح» | `0` |
| قائمة المفاتيح المدوَّرة | إلزامي شرطياً | قائمة | إلزامية عند مطابقة مفاتيح، وتُدرج بيانات الاعتماد المدوَّرة | `API_KEY تم تدويره` |
| بند البيانات.مدة الاحتفاظ | نعم | نص | مدة محددة، ولا يجوز كتابة «طويل الأمد» | `30 يوماً بعد حذف الحساب` |
| بند البيانات.المشاركة مع أطراف ثالثة | نعم | نص | إن لم توجد تُكتب «لا يوجد» | `لا يوجد` |
| الإصدارات المدعومة | نعم | جدول | تحديد الإصدارات التي تقبل التقارير | `2.x: نعم` |
| قناة الإبلاغ | نعم | نص | قناة واحدة غير عامة على الأقل | `Security Advisories` |
| المدة الزمنية للاستجابة | نعم | مدة | قيمة عددية لكل مرحلة | `2 يوم عمل` |

## 6. إرشادات التعبئة

1. **الفحص التاريخي**: يجب أن يشمل فحص المفاتيح السرية تاريخ git الكامل؛ ولا يُعتد بفحص مساحة العمل وحدها.
2. **مطابقة المفتاح السري**: عند اكتشاف مفتاح دُفع بالفعل، يُدوَّر أولاً ثم يُنظَّف التاريخ، ولا يجوز عكس الترتيب (يقابل H12).
3. **إخفاء الهوية**: يجب إخفاء الحقول الحساسة الظاهرة في العرض والسجلات؛ ويُمنع طباعة الرموز وأرقام الهوية وأرقام الهواتف كاملة.
4. **مدة الاحتفاظ**: «الاحتفاظ طويل الأمد» غير مقبول، ويجب تحديد مدة صريحة أو حدث يُطلق الحذف.
5. **الإصدارات المدعومة**: تُدرج الإصدارات الرئيسية الحالية على الأقل؛ وعند عدم دعم إصدارات قديمة يجب كتابة ذلك صراحةً لتجنب إبلاغ المستخدمين خطأً.
6. **قناة الإبلاغ**: يجب أن تكون قناة غير عامة؛ فالإفصاح عن ثغرة في Issue عام يوسّع الخطر.
7. **المخاطر المعروفة**: تُدرج بصدق؛ وعبارة «هذا النظام آمن تماماً» من العبارات المحظورة.

أخطاء شائعة:

| الصياغة الخاطئة | المشكلة | طريقة التصحيح |
| --- | --- | --- |
| حذف الإيداع فقط دون تدوير المفتاح | مخالفة H12 | التدوير أولاً ثم تنظيف التاريخ |
| فحص مساحة العمل فقط في الفحص الذاتي | تفويت تسريبات التاريخ | إضافة الفحص التاريخي |
| كتابة «دائم» لمدة احتفاظ البيانات | بلا حد | تحديد مدة صريحة |
| إبلاغ الثغرات عبر Issue عام | توسيع سطح التعرض | التحويل إلى قناة خاصة وإدراجها في SECURITY.md |
| التعهد بـ«أمان مطلق» | عبارة غير صحيحة | التعديل إلى بيان المخاطر المعروفة بصدق |

## 7. مثال كامل

```markdown
## الفحص الذاتي للمعلومات الحساسة: markdown-lint-cli

تاريخ الفحص: 2026-11-18 ｜ المنفذ: وانغ وو ｜ تغطية التاريخ: نعم

| بند الفحص | الأداة / الأمر | النتيجة | الإجراء |
| --- | --- | --- | --- |
| مفاتيح مساحة العمل | gitleaks detect | 0 | لا يوجد |
| مفاتيح الإيداعات التاريخية | gitleaks detect --log-opts=--all | 0 | لا يوجد |
| `.env` وملفات بيانات الاعتماد | git ls-files | 0 | لا يوجد |
| النطاقات الداخلية / IP | بحث بتعابير نمطية | 0 | لا يوجد |

الخلاصة: ناجح
- قائمة المفاتيح المدوَّرة: لا يوجد
- المراجع: لي سي
```
