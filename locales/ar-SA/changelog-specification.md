# مواصفة سجل التغييرات

> المشكلة التي يحلها هذا الملف: تعريف قالب سجل تغييرات الإصدارات الموجَّه إلى المستخدمين، وحقوله وطريقة كتابته، بما يضمن أن يكون كل تغيير قابلًا للتتبع، وأن يقابل رقم الإصدار تغييرًا فعليًا، وأن يمكن الحكم على مسار الترقية.

## 1. بنود المواصفة

1. يتبع سجل التغييرات بنية Keep a Changelog، ويتبع رقم الإصدار الإصدار الدلالي في [مواصفة إدارة الإصدارات](./version-management-specification.md).
2. يجب أن يكون لكل إصدار تاريخ إصدار بصيغة `YYYY-MM-DD`؛ ويوضع المحتوى غير المُصدَر في قسم `Unreleased`.
3. تُجمَّع البنود في ست فئات: `Added` إضافة / `Changed` تغيير / `Deprecated` إهمال / `Removed` إزالة / `Fixed` إصلاح / `Security` أمان.
4. كل تغيير موجَّه إلى المستخدم، ويجب بيان أثره وطريقة الترحيل، ولا تُكتب تفاصيل إعادة الهيكلة الداخلية.
5. يجب وسم التغييرات الكاسرة بـ `BREAKING CHANGE:` مع إعطاء خطوات الترحيل (انظر [مواصفة دليل الترحيل](./migration-guide-specification.md)).
6. يجب أن يتطابق رقم الإصدار مع tag ومع Release Notes؛ ويجب أن يقابل التغيير الكاسر `feat!:` أو `BREAKING CHANGE:` في رسالة الإيداع.

## 2. قالب سجل التغييرات

```markdown
# سجل التغييرات

يسجّل هذا الملف جميع التغييرات الموجَّهة إلى المستخدم. تستند الصيغة إلى Keep a Changelog، ويتبع الإصدار الإصدارَ الدلالي.

## [Unreleased]

### Added
- {{新增能力，说明对使用者的价值}}

### Changed
- {{行为变更，说明影响范围}}

### Deprecated
- {{即将移除的能力，说明替代方案与移除版本}}

### Removed
- {{已移除的能力，说明迁移路径}}

### Fixed
- {{缺陷修复，说明触发条件}}

### Security
- {{安全修复，说明影响与升级建议}}

## [{{X.Y.Z}}] - {{YYYY-MM-DD}}

### {{类型}}
- {{变更条目}}
- {{BREAKING CHANGE: 原行为 → 新行为；迁移步骤见链接}}

[Unreleased]: https://github.com/{{owner}}/{{repo}}/compare/v{{X.Y.Z}}...HEAD
[{{X.Y.Z}}]: https://github.com/{{owner}}/{{repo}}/compare/v{{prev}}...v{{X.Y.Z}}
```

## 3. قالب البند

```markdown
- {{动词开头的一句话变更描述}} ({{关联 REQ 编号}})
  - الأثر: {{哪些使用者或场景受影响}}
  - الترحيل: {{需要执行的动作；无则省略此行}}
  - المرجع: {{Issue / PR 链接}}
```

## 4. تعريف الحقول

| الحقل | إلزامي | النوع | نقاط التعبئة | مثال |
| --- | --- | --- | --- | --- |
| رقم الإصدار | نعم | `X.Y.Z` | مطابق تمامًا لـ tag، ويجوز بلا سابقة `v`، لكن بتوحيد في الملف كله | `1.2.0` |
| تاريخ الإصدار | نعم | `YYYY-MM-DD` | يُعتمد تاريخ وسم tag | `2026-11-18` |
| نوع التجميع | نعم | تعداد | واحد من الفئات الست؛ ويُحذف القسم كله عند غياب بنود من هذا النوع | `Fixed` |
| وصف التغيير | نعم | نص | يبدأ بفعل، موجَّه إلى المستخدم، ويبيّن القيمة | `إضافة فحص لجداول GFM` |
| الأثر | إلزامي شرطيًا | نص | إلزامي عند تغيير السلوك أو الإهمال أو الإزالة أو التغيير الكاسر | `يجب إعادة تسمية ملف الإعداد القديم` |
| الترحيل | إلزامي شرطيًا | نص | إلزامي عند التغيير الكاسر، ويشير إلى دليل الترحيل | `انظر دليل الترحيل v1.0` |
| BREAKING CHANGE | إلزامي شرطيًا | وسم | إلزامي عند التغيير الكاسر، ويوضع في بداية البند | `BREAKING CHANGE:` |
| رابط المقارنة | نعم | URL | يجب توفير رابط compare لكل قسم إصدار | `compare/v1.1.0...v1.2.0` |
| المتطلب المرتبط REQ | لا | قائمة | لتسهيل المقابلة مع مصفوفة تتبع المتطلبات | `REQ-007` |

## 5. تعليمات التعبئة

1. **حجم البند**: يصف البند الواحد نتيجة واحدة يمكن للمستخدم إدراكها؛ وتُفصل النتائج المتعددة إلى بنود متعددة.
2. **البدء بفعل**: تُستخدم «إضافة» و«دعم» و«إصلاح» و«إزالة» و«إهمال» و«تعديل»، ولا تُستخدم «حدَّثنا» و«أُجريت بعض التعديلات».
3. **المحتوى المحظور**: بنود بلا تاريخ، وإعادة الهيكلة الداخلية، وخطط التطوير، ومحتوى خارطة الطريق، والصياغات الغامضة («تحسين التجربة»، «إصلاح عدة مشكلات»).
4. **التغيير الكاسر**: يجب أن يجتمع فيه وسم `BREAKING CHANGE:` وبيان الأثر وخطوات الترحيل ورابط دليل الترحيل، ولا يجوز الإخلال بأحدها.
5. **بنود الإهمال**: يجب كتابة البديل ورقم الإصدار المخطط للإزالة، مثل «سيُزال في v2.0».
6. **Unreleased**: يُسجَّل فور الدمج، ولا يُؤجَّل إلى يوم الإصدار.
7. **الاتساق**: يجب أن يتوافق رقم الإصدار وتاريخ الإصدار في ثلاثة مواضع: tag وRelease Notes وسجل النشر؛ وعند الاختلاف يُعتمد tag وتُصحَّح المواضع الثلاثة الأخرى.

أخطاء شائعة:

| الصيغة الخاطئة | المشكلة | طريقة التصحيح |
| --- | --- | --- |
| «إعادة هيكلة بنية الوحدات الداخلية» | تفصيل داخلي لا يلمسه المستخدم | حذفه، أو إعادة صياغته إلى أثر ملموس |
| «إصلاح عدة مشكلات» | غير قابل للحكم | سرد ما أُصلح بندًا بندًا |
| قول «يوجد تغيير» فقط في التغيير الكاسر | لا مسار ترحيل | إضافة الأثر وخطوات الترحيل ورابط الدليل |
| اختلاف رقم الإصدار عن tag | انقطاع علاقة المقابلة بين الإصدارات | توحيده على أساس tag |
| غياب رابط compare | تعذّر عرض الفروق | إضافة رابط compare على GitHub |

## 6. مثال كامل

```markdown
## [1.0.0] - 2026-11-20

### Added
- إضافة قاعدة فحص المسافات بين النص الصيني والإنجليزي (REQ-001)، مع دعم الاستدعاء المباشر من سطر الأوامر.
- إضافة إخراج تقرير JSON لتسهيل الربط بإحصاءات التكامل المستمر.

### Changed
- BREAKING CHANGE: تغيّر اسم ملف الإعداد من `.mdlint.json` إلى `.mdlintrc.json`. لن يُقرأ الملف القديم بعد الآن؛ وخطوات الترحيل في [دليل الترحيل](./migration-guide-specification.md).

### Deprecated
- ستُزال المعلمة `--format=table` في v2.0، يُرجى استخدام `--reporter=table` بدلًا منها.

### Fixed
- إصلاح الإبلاغ الخاطئ عند تجاور علامات الترقيم الصينية مع كلمة إنجليزية.

### Security
- إصلاح إمكانية تجاوز مسار تحميل إضافة القواعد بإدخال خارجي؛ ويُنصح جميع المستخدمين بالترقية إلى v1.0.0.

[1.0.0]: https://github.com/example/markdown-lint-cli/compare/v0.9.3...v1.0.0
```
