# مواصفة استدعاء الوكيل والصياغة التوجيهية

> المشكلة التي يحلها هذا الملف: يحدد عقد التوزيع وطريقة كتابة الصياغة التوجيهية عند استدعاء الوكيل لمجموعة المواصفات، بما يضمن أن يكون الاستدعاء قابلاً للتحقق وغير متجاوز لصلاحياته وغير منحرف عن القواعد.

## 1. مبادئ الاستدعاء

1. مسؤولية واحدة: يؤدي الاستدعاء الواحد مهمة واحدة، ويُمنع إنجاز مهام أخرى «في أثناء ذلك».
2. فصل القراءة عن الكتابة: يقتصر الوكيل الفرعي على القراءة والتحليل، ويتولى المتحكم الرئيسي كتابة الملفات وعمليات git (انظر [عقد توزيع المهام على الوكلاء الفرعيين](./sub-agent-dispatch-contract.md)).
3. متطلب الدليل: يجب أن تُرفق النتيجة بالدليل (المسار + رقم السطر / خرج الأمر)، والنتيجة بلا دليل تُعدّ لاغية.
4. عدم التواصل: لا يتواصل الوكلاء الفرعيون مباشرةً، بل تُجمَّع كل النتائج عبر المتحكم الرئيسي.

## 2. بنية الصياغة التوجيهية

يجب أن تتضمن الصياغة التوجيهية للاستدعاء العناصر الأربعة:

```text
TASK:    <المهمة في جملة واحدة>
INPUT:   <السياق اللازم، الأجزاء المطلوبة فقط>
OUTPUT:  <تنسيق خرج منظم، جدول أو JSON، دون نثر>
FAIL:    <اتفاق الإرجاع عند التعذر، دون اختلاق>
```

## 3. طريقة الكتابة

1. تُستخدم اللغة الفصيحة والجمل الأمرية، بمعلومات كاملة دون الاعتماد على استنتاج السياق (انظر [المواصفة العامة للكتابة](./general-writing-specification.md)).
2. يُحدَّد تنسيق الخرج وإرجاع الفشل صراحةً، تجنباً لانحراف النموذج.
3. عند الإحالة إلى مواصفة، يُذكر مسار الملف (انظر [مواصفة البيانات الوصفية القابلة للقراءة آلياً](./machine-readable-metadata-specification.md)).
4. تُوحَّد صيغة القوالب والعناصر النائبة (انظر [جمع المعلومات والقوالب](./information-collection-and-templates.md)).

## 4. قواعد ملزمة

1. لا يجوز مطالبة الوكيل باختلاق نتائج الفحص؛ وتُوسم البنود غير القابلة للفحص بـ SKIP + السبب.
2. لا يجوز إدراج عملية التفكير الداخلية في المُخرَجات (انظر [الممارسات المحظورة](./prohibited-practices.md)).
3. يُعالج المحتوى الأمني وفق [مواصفة الأمان والخصوصية](./security-and-privacy-specification.md).
