# مواصفة تسمية المشاريع

> المشكلة التي يحلها هذا الملف: يحدد القواعد المطلقة للمحارف وحالة الأحرف والتقطيع والطول والدلالة في اسم المستودع، مع صيغة التسمية واللواحق الاصطلاحية ومسار الفحص ومتطلبات البيانات الوصفية المرافقة.

## 1. القواعد المطلقة

| القاعدة | المتطلب | مثال مخالف |
|---|---|---|
| مجموعة المحارف | `a-z` و`0-9` و`-` فقط | `My_Proj`، `我的项目` |
| حالة الأحرف | أحرف صغيرة فقط | `MyProject` |
| التقطيع | kebab-case، بوصل بـ`-` | `myproject`، `my_project` |
| الطول | من 2 إلى 25 محرفاً | اسم مركّب مفرط الطول |
| النهاية | اسم أو لاحقة صيغية | الانتهاء بـ`-project` أو `-test` |
| الإصدار | لا يتضمن رقم إصدار ولا سنة ولا تاريخاً | `tool-v2`، `app2024` |
| خلوّه من الكلمات غير المفيدة | يُمنع `my`/`demo`/`test`/`new`/`tmp` | `my-new-demo` |
| التفرّد | يُفحص مرة في كل من GitHub وnpm وPyPI | التشابه مع مكتبة معروفة |
| الدلالة | يُقرأ من الاسم نفسه «ماذا يفعل» | `xyz`، `abc123` |

## 2. صيغة التسمية (اختيار واحدة من أربع)

```text
<التقنية>-<الكائن>             vue-virtual-table      go-ratelimit
<الكائن>-<الصيغة>              note-cli   image-api   config-loader
<الفعل>-<الكائن>               parse-markdown   sync-dotfiles
<المجال>-<المجال-الفرعي>       web-ui-kit   data-pipeline
```

## 3. اللواحق الاصطلاحية

`-cli` أداة سطر أوامر / `-sdk` مكتبة عميل / `-api` `-server` خدمة خلفية / `-template` `-boilerplate` هيكل بدء / `-loader` `-parser` برمجية وسيطة / `-kit` مجموعة مكونات / `-notes` `-guide` وثائق / `dotfiles` مستودع إعدادات / `awesome-xxx` تجميعة موارد.

## 4. مسار التسمية

1. اكتب في جملة واحدة «لمن يحل المشروع أي مشكلة».
2. خذ الاسم الجوهري + الصيغة من هذه الجملة، وطبّق إحدى صيغ القسم 2.
3. أنتج 3 مرشحات، وافحص تشابه الأسماء في كل منها.
4. اختر المرشح الذي يُفهم دون الرجوع إلى README.
5. لا يُكتب الاسم العربي في اسم المستودع، بل في README بعد عنوان السطر الأول.

## 5. البيانات الوصفية المرافقة

### 5.1 وصف المستودع (description)

- من أصل اسم المستودع ذاته، بصيغة: `<ماذا يفعل> for <لمن>`.
- صيغة مدمجة ثنائية اللغة: `اللغة الوطنية | الإنجليزية`، تُكتب النسخة باللغة الوطنية أولاً، ثم خط عمودي بنصف عرض (بمسافة على كل جانب)، ثم النسخة الإنجليزية. مثال لمشروع عربي:

```text
أداة سطر أوامر عربية خفيفة لمعالجة JSON | A lightweight Arabic CLI for JSON processing
```

- الطول: بما لا يتجاوز 120 محرفاً لكل من اللغة الوطنية والإنجليزية، وبما لا يتجاوز 350 محرفاً للمجموع (حد GitHub).
- عند تجاوز مجموع اللغتين الحد: يُضغط النص الإنجليزي أولاً لا النص باللغة الوطنية — فكثافة المعلومات في العربية أعلى، وضغط العربية يفقد معلومات أكثر؛ وعند الضغط تُحذف أولاً النعوت والتقييدات المكررة، ثم تُدمج الصيغ المتكافئة، ثم يُحتفظ بالبنية الكاملة للمسند والمسند إليه في كل نسخة لغوية.
- لا يتضمن أسطراً جديدة ولا صيغة Markdown ولا رموزاً تعبيرية؛ ويُوحَّد نمط علامة النهاية في اللغتين (إضافة نقطة في كلتيهما أو حذفها من كلتيهما).

### 5.2 الموضوعات (topics)

- تُكتمل 20 موضوعاً (حد GitHub)، بتغطية كاملة دون فراغات.
- تُستخدم الإنجليزية جميعها، ولا يجوز استخدام العربية أو أي لغة أخرى؛ بأحرف صغيرة، موصولة بـ`-`، دون مسافات أو محارف خاصة.
- تُغطى الفئات الخمس: اللغة، والمجال، والصيغة، والمنظومة، والسيناريو، ويجوز إضافة كلمات عامة مثل documentation وopen-source.
- تُضبط عند إنشاء المستودع، ولا تُترك فارغة؛ وتُراجَع مرة واحدة بعد تغيير الاسم أو إعادة تحديد التوجه.
