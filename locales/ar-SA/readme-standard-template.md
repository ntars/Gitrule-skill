# قالب README القياسي

> ما تحله هذه الوثيقة: تقدّم قالب README عاماً قابلاً للنسخ المباشر والتطبيق بمجرد استبدال العناصر النائبة، يغطي عرض الصفحة الرئيسية على مدى دورة حياة المشروع كاملة، ويُرفق بجدول العناصر النائبة وبيان الأقسام الاختيارية وقائمة تحقق قبل التسليم، ليتسنّى لأي مطوّر تخصيصه بسرعة وفق مشروعه.

## 1. تعليمات الاستخدام

1. انسخ كامل محتوى «نص القالب» في القسم 3، وأنشئ منه ملف `README.md` في جذر المشروع.
2. استبدل كل `{{...}}` بنداً ببند وفق جدول العناصر النائبة في القسم 4؛ وتُحذف العناصر غير المستخدمة مع سطرها أو قسمها بأكمله.
3. تقابل أقسام القسم 3 الفصول الـ 20 في [مواصفة أقسام README](./readme-sections-specification.md)، ومرتّبة بترتيب دورة الحياة من الداخل إلى الخارج؛ وعند حذف فصل ما يجب حذف الرابط المقابل له في تنقل الشاشة الأولى كذلك.
4. وحّد نمط الشارات وألوانها وعددها وفق [مواصفة الشارات](./badge-specification.md)؛ وافحص مواضع لقطات الشاشة والجداول وكتل الكود وفق [مواصفة التخطيط البصري لـ README](./readme-visual-layout-specification.md).
5. اقتطع الأقسام بحسب نوع المشروع وفق [دليل تكييف تصنيفات README](./readme-category-adaptation-guide.md).
6. نفّذ قائمة التحقق في القسم 6 قبل الإيداع، وتأكد من عدم بقاء أي عنصر نائب.

## 2. مبادئ التخصيص

- **الحقول الإلزامية**: اسم المشروع، ووصف المستودع، والتموضع في جملة واحدة، والتثبيت، والبدء السريع، والترخيص.
- **ترتيب ثابت**: يوافق ترتيب الأقسام [مواصفة أقسام README](./readme-sections-specification.md)، وتتقابل النسختان العربية والإنجليزية فصلاً بفصل.
- **الأدلة أولاً**: يجب أن تقدّم الوظائف الأساسية والأداء والمقايضات الهندسية أدلة قابلة للمراجعة، ويُحظر الإطراء الوصفي.
- **الإفصاح الشفاف**: يجب سرد الحالات غير الملائمة والقيود والمشكلات المعروفة والوظائف غير المنفّذة صراحةً، ولا يجوز إخفاؤها.
- **لا التزام**: تُوسم خارطة الطريق بـ«غير ملزِمة»، ولا تُكتب تواريخ تسليم محددة.
- **المصداقية**: يجب أن تكون كل الأوامر والأمثلة والروابط والشارات صالحة فعلياً؛ ووسائل الاتصال وقنوات الإبلاغ حقيقية وقابلة للوصول.

## 3. نص القالب

ينظّم هذا القسم بحسب دورة حياة المشروع «من الداخل إلى الخارج»، ويضم 20 قسماً تقابل الفصول الـ 20 في [مواصفة أقسام README](./readme-sections-specification.md) واحداً بواحد. والنص داخل كتلة الكود في كل قسم هو المتن القابل للنسخ.

وفيما يلي مقابلة الأقسام بمراحل دورة الحياة، لتسهيل تحديد الموضع بحسب الحاجة:

| مرحلة دورة الحياة | الأقسام المقابلة | محور العرض |
| --- | --- | --- |
| بدء المشروع | 3.1–3.2 | التموضع، والخلفية، والحالات الملائمة والقيود |
| تحليل المتطلبات | 3.2–3.3 | حدود الوظائف، والحالات الملائمة، والحالات غير الملائمة |
| تصميم البنية | 3.5–3.6، 3.11 | المقايضات الهندسية، وحزمة التقنيات، وبنية المجلدات |
| التنفيذ التطويري | 3.3–3.4، 3.9–3.10 | الوظائف، والخصائص، والإعداد، وAPI |
| التحقق بالاختبار | 3.8، 3.12 | مثال البدء السريع، وأدلة الأداء |
| النشر والإطلاق | 3.7، 3.14 | التثبيت والنشر، ومصفوفة التوافق |
| التشغيل والمراقبة | 3.13، 3.15 | الأمن والخصوصية، والمشكلات المعروفة والقيود |
| الصيانة التكرارية | 3.15–3.17 | الوظائف غير المنفّذة، وسجل التغييرات، وخارطة الطريق |

بيان: README هو الصفحة الرئيسية للمشروع، ووثائق عمليات كل مرحلة (السجلات الكاملة للمتطلبات والتصميم والاختبار والنشر والتشغيل) تحملها المواصفات المقابلة، انظر [مصفوفة الوثائق](./document-matrix.md)؛ وهذا الفصل يعرض فقط النتائج المرئية للمستخدم.

## 4. جدول العناصر النائبة

يسرد الجدول كل العناصر النائبة الواردة في نص القالب. وهو مرتّب بحسب ترتيب الأقسام، وتُحذف العناصر غير المستخدمة مع سطرها.

| `{{LOGO_LIGHT_URL}}` | عنوان شعار السمة الفاتحة | `media/logo-light.svg` | لا |

## 5. بيان الأقسام الاختيارية

قدّم القسم 3 المتن القابل للنسخ للفصول الـ 20. وفيما يلي بيان تكميلي للإضافة والحذف بحسب نوع المشروع، وعند حذف فصل يجب حذف رابط تنقل الشاشة الأولى كذلك.

| الفصل | أنواع المشاريع الموصى بالاحتفاظ بها | شرط الحذف |
| --- | --- | --- |
| الخصائص الأساسية | الكل | يمكن الحذف عند غياب أدلة قابلة للمراجعة، ولا يجوز استبدالها بوصف نوعي |
| تفاصيل التصميم والمقايضات الهندسية | أطر العمل، والتطبيقات، والخدمات | يمكن الحذف عند غياب مقايضات جوهرية |
| حزمة التقنيات وقائمة التبعيات | المكتبات، وأطر العمل | يمكن الحذف عند غياب تبعيات خارجية |
| الأداء | أدوات سطر الأوامر، والمكتبات، والخدمات | يمكن الحذف عند غياب بيانات اختبار، ويُحظر تقدير الأرقام |
| الأمن والخصوصية | الخدمات، والتطبيقات، والمشاريع التي تعالج بيانات شخصية | يمكن اختصاره في الأدوات المحلية المحضة |
| بيان التوافق | المكتبات، وحزم SDK، والتطبيقات متعددة المنصات | يمكن اختصاره عند وجود بيئة تشغيل واحدة |
| سجل التغييرات | الكل | يُستبدل بخلاصة تغييرات مدمجة فقط عند غياب CHANGELOG |
| خارطة الطريق | الكل | يمكن الحذف عند غياب خطة معلنة |
| بيان امتثال NOTICE | ما يتضمن تبعيات طرف ثالث | يمكن الحذف عند غياب تبعيات طرف ثالث |

## 6. قائمة التحقق قبل التسليم

- [ ] لا توجد عناصر نائبة `{{...}}` متبقية.
- [ ] تضم الشاشة الأولى وصف المستودع 【صيني | إنجليزي】 ووسوم المواضيع، وكلاهما متسق مع البيانات الوصفية للمستودع.
- [ ] لا يزيد وصف المستودع الصيني ولا الإنجليزي على 120 حرفاً لكل منهما.
- [ ] وسوم المواضيع مكتملة 20 وسم، كلها إنجليزية صغيرة موصولة بـ `-`.
- [ ] التموضع في جملة واحدة يتضمن كلمة الفئة، ولا يزيد على 60 حرفاً بالصينية و25 كلمة بالإنجليزية.
- [ ] كل خاصية أساسية تضم البنية الخماسية ولها دليل قابل للمراجعة.
- [ ] المزايا والقيود مفصولة، والقيود تشمل نطاق التأثير وأسلوب التحايل.
- [ ] المشكلات المعروفة تشمل رابط متابعة؛ والوظائف غير المنفّذة تشمل السبب وحالة الخطة.
- [ ] خارطة الطريق موسومة بـ«غير ملزِمة» وبلا تواريخ تسليم محددة.
- [ ] الحالات غير الملائمة والبنود غير المدعومة صراحةً مدرجة.
- [ ] العنوان من المستوى الأول واحد، ومستويات العناوين من المستوى الثاني متصلة، وترتيب الفصول يوافق الفصول الـ 20 في المواصفة.
- [ ] نمط الشارات موحّد، والروابط صالحة، ونص `alt` واضح.
- [ ] أمر التثبيت ومثال البدء السريع مُختبران وقابلان للتشغيل.
- [ ] كل كتل الكود موسومة باللغة، وكل الصور لها نص `alt`.
- [ ] المسارات النسبية صالحة في النسخ المتشعّبة (Fork) وفي وضع عدم الاتصال.
- [ ] ملف LICENSE موجود، ومعرّف SPDX متسق مع README.
- [ ] ترتيب فصول النسختين الصينية والإنجليزية متقابل واحداً بواحد.
