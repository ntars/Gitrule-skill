# مواصفة تصميم API

> المشكلة التي يحلها هذا الملف: يحدد مبادئ واتفاقيات اتساق تصميم الواجهات، بما يضمن أن تكون API سهلة الاستخدام وقابلة للتنبؤ وقابلة للتطور.

## 1. مبادئ التصميم

1. اتساق التسمية: تُستخدم قواعد تسمية موحدة للموارد والعمليات من النوع نفسه.
2. قابلية التنبؤ: العمليات ذات الدلالة نفسها لها البنية نفسها.
3. التصريح أولى من الإضمار: يجب أن تكون القيم الافتراضية والحقول الإلزامية وسلوك الأخطاء واضحة.
4. التوافق الخلفي: تُفضَّل التغييرات المتوافقة، والتغييرات الكاسرة يجب أن تُرقَّم إصدارياً (انظر [مواصفة إدارة الإصدارات](./version-management-specification.md)).

## 2. الاتفاقيات الإلزامية

1. **التسمية**: قواعد تسمية الموارد والطرق والحقول.
2. **المعاملات**: النوع، والإلزام، والقيمة الافتراضية، ونطاق القيم.
3. **الأخطاء**: بنية خطأ موحدة، ورموز الأخطاء، وحالة HTTP أو آلية مكافئة.
4. **التصفح والتصفية**: اتفاقيات التصفح والترتيب والتصفية في الحالات ذات الحجم الكبير من البيانات.
5. **العملية المتكررة بلا أثر جانبي**: ضمان عدم تغيّر النتيجة عند تكرار عمليات الكتابة.
6. **تحديد المعدل والحصص**: حدود التكرار والاستجابة عند تجاوزها.
7. **الإصدار**: استراتيجية إصدار API وطريقة تطورها.

## 3. قواعد ملزمة

1. يجب أن تتضمن استجابة الخطأ رمز خطأ قابلاً للتحديد وشرحاً، دون كشف تفاصيل التنفيذ الداخلية.
2. يجب أن تُرفَع نسخة التغيير الكاسر مع توفير فترة ترحيل (انظر [مواصفة سجل التغييرات](./changelog-specification.md)).
3. يجب أن يكون للواجهة وثيقة مقابلة بحقول كاملة (انظر [مواصفة توثيق API](./api-documentation-specification.md)).
