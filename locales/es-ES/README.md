## Rutas de lectura

- **Delimitar el alcance aplicable**: Guía de selección de especificaciones → Tabla de correspondencia del ciclo de vida → archivos de especificación de la fase correspondiente.
- **A lo largo de todo el ciclo de vida**: Tabla de correspondencia del ciclo de vida → Especificación de inicio de proyecto y requisitos → Especificación de la matriz de trazabilidad de requisitos → Especificación de documentos de arquitectura → Especificación de pruebas → Especificación de despliegue y reversión → Especificación de observabilidad → Especificación de retrospectiva de iteración.
- **Push rápido**: Reglas absolutas → Puerta de calidad → Especificación de push y publicación → Formato del informe de revisión.
- **Crear documentación desde cero**: Roles y responsabilidades → Proceso de ejecución → Recopilación de información y plantillas → Matriz de documentación → Especificación de secciones del README → Especificación de cumplimiento de código abierto → Puerta de calidad.
- **Redactar el README**: Informe de investigación de plantillas README → Especificación de maquetación visual del README → Especificación de insignias → Guía de adaptación del README por categoría → Plantilla estándar de README.
- **Revisión completa**: Matriz de dimensiones de revisión → Contrato de asignación de subagentes → Reglas absolutas → Puerta de calidad → Formato del informe de revisión.
- **Integración programática**: Especificación de metadatos legibles por máquina → Especificación de creación de Skills / Especificación de herramientas MCP / Especificación de invocación de agentes y prompts.
- **Riesgo y límites de responsabilidad**: Exención de responsabilidad → Plantilla de exención de responsabilidad → Plantilla de SECURITY → Especificación de seguridad y privacidad → Especificación de cumplimiento de código abierto.
- **Crear los archivos de gobernanza comunitaria**: Plantilla de guía de contribución → Plantilla de código de conducta → Plantilla de SECURITY → Plantilla de exención de responsabilidad.

## Convenciones de lenguaje

- **debe / no debe**: requisito obligatorio.
- **debería / no debería**: recomendación o prohibición; toda desviación exige justificación.
- **puede**: opcional.
- **P0 / P1 / P2**: P0 bloquea el push; P1 debe resolverse antes del push o registrarse obligatoriamente como tarea; P2 es una optimización recomendada.
