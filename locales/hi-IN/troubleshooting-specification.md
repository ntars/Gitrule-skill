# समस्या निवारण विनिर्देश

> यह फ़ाइल कौन-सी समस्या हल करती है: समस्या निवारण दस्तावेज़ (Troubleshooting / FAQ) की संरचना, प्रविष्टि लेखन-शैली और रखरखाव तंत्र को परिभाषित करना, ताकि उपयोगकर्ता लक्षण के आधार पर कारण पहचान सकें और सामान्य समस्याएँ स्वयं हल कर सकें।

## 1. लागू परिदृश्य

निम्नलिखित स्थितियों में समस्या निवारण दस्तावेज़ अवश्य प्रदान किया जाना चाहिए:

1. इंस्टॉल या निर्माण विफलता के अनेक सामान्य कारण होते हैं।
2. कॉन्फ़िगरेशन विकल्पों के बीच टकराव है, तथा त्रुटि संदेश समाधान स्पष्ट करने के लिए पर्याप्त नहीं है।
3. किसी विशिष्ट प्लेटफ़ॉर्म या संस्करण में ज्ञात सीमाएँ हैं।
4. उपयोगकर्ता बार-बार एक ही प्रकार के प्रश्न पूछते हैं, तथा उत्तर मानकीकृत किए जा सकते हैं।

## 2. फ़ाइल स्थान और नामकरण

1. सामग्री कम होने पर इसे README के एक अनुभाग के रूप में रखें, शीर्षक “सामान्य प्रश्न” या “समस्या निवारण” हो।
2. सामग्री अधिक होने पर अलग से `docs/troubleshooting.md` या `FAQ.md` बनाएँ, तथा README में प्रवेश लिंक बनाए रखें।
3. प्रश्नों को विषय के अनुसार समूहित करें, जैसे “इंस्टॉल”, “कॉन्फ़िगरेशन”, “रन”, “प्रदर्शन”, “नेटवर्क”।

## 3. दस्तावेज़ संरचना

1. **आरंभिक विवरण**: यह दस्तावेज़ किन सामान्य समस्याओं को आवृत करता है तथा कौन-से संस्करणों पर लागू है।
2. **प्रश्न अनुक्रमणिका**: विषय के अनुसार प्रश्न शीर्षक सूचीबद्ध करें, ताकि तेज़ी से कूदा जा सके।
3. **प्रश्न प्रविष्टियाँ**: एकरूप संरचना के अनुसार प्रत्येक प्रविष्टि क्रमशः विस्तार से लिखें।
4. **अभी भी हल न हो सके तो**: issue, चर्चा क्षेत्र आदि सहायता माध्यमों की ओर संकेत करें।

## 4. प्रविष्टि संरचना

प्रत्येक प्रश्न प्रविष्टि में निम्नलिखित भाग अवश्य शामिल होने चाहिए:

| भाग | सामग्री | आवश्यकता |
| --- | --- | --- |
| लक्षण | उपयोगकर्ता को दिखने वाला ठोस रूप | पूर्ण त्रुटि संदेश सहित, केवल “त्रुटि” लिखना निषिद्ध है |
| उत्प्रेरक शर्त | कब प्रकट होता है | संस्करण, प्लेटफ़ॉर्म और क्रिया स्पष्ट करें |
| कारण | मूल कारण | तंत्र समझाएँ, केवल निष्कर्ष न दें |
| समाधान | निष्पादन-योग्य चरण | क्रमांकित रूप में सूचीबद्ध करें, कमांड या कॉन्फ़िगरेशन सहित |
| सत्यापन | पुष्टि कैसे करें कि ठीक हो गया | अपेक्षित आउटपुट दें |
| संबंध | संबंधित दस्तावेज़ या issue लिंक | वैकल्पिक |

## 5. प्रविष्टि लेखन का उदाहरण

```markdown
### इंस्टॉल के समय `EACCES: permission denied` संदेश आना

**लक्षण**: `npm install -g <package>` निष्पादित करते समय अनुमति अपर्याप्त होने का संदेश आता है।

**उत्प्रेरक शर्त**: Linux या macOS पर सामान्य उपयोगकर्ता के रूप में वैश्विक पैकेज इंस्टॉल करना।

**कारण**: वैश्विक इंस्टॉल निर्देशिका की लेखन अनुमति सिस्टम प्रशासक के पास है, वर्तमान उपयोगकर्ता को लिखने का अधिकार नहीं है।

**समाधान**:

```bash
mkdir -p ~/.npm-global
npm config set prefix '~/.npm-global'
export PATH=~/.npm-global/bin:$PATH
npm install -g <package>
```

**सत्यापन**: `<package> --version` निष्पादित करने पर संस्करण संख्या आउटपुट होना ही सफलता है।

## 6. लेखन आवश्यकताएँ

1. प्रश्न शीर्षक में वही अभिव्यक्ति प्रयोग करें जो उपयोगकर्ता खोजता है, आंतरिक शब्दावली नहीं।
2. त्रुटि संदेश जैसा है वैसा ही रखें, ताकि उपयोगकर्ता मिलान कर सके; संवेदनशील जानकारी का मुखौटाकरण अवश्य करें (देखें [सुरक्षा और गोपनीयता विनिर्देश](./security-and-privacy-specification.md))।
3. समाधान में पूर्ण कमांड दें, यह न मानें कि उपयोगकर्ता ने पर्यावरण चर पहले से सेट कर रखे हैं।
4. एक प्रविष्टि में केवल एक समस्या हल करें, अनेक कारणों को न मिलाएँ।
5. ज्ञात दोष का मामला होने पर प्रभाव-क्षेत्र और बचाव-उपाय बताएँ, सुधार का समय निश्चित न करें।
6. माइग्रेशन से संबंधित प्रश्नों को माइग्रेशन मार्गदर्शिका से लिंक करें (देखें [माइग्रेशन मार्गदर्शिका विनिर्देश](./migration-guide-specification.md))।

## 7. रखरखाव तंत्र

1. एक ही प्रश्न तीन बार से अधिक दोहराया जाने पर नई प्रविष्टि जोड़ना या मौजूदा प्रविष्टि पुनर्लेखित करना अवश्य है।
2. संस्करण उन्नयन के बाद सभी प्रविष्टियों की पुनः जाँच करें तथा अमान्य सामग्री हटाएँ।
3. प्रत्येक प्रविष्टि में अंतिम सत्यापित संस्करण अंकित किया जा सकता है, ताकि यह निर्धारित हो सके कि वह अब भी लागू है या नहीं।
4. प्रविष्टियों की वृद्धि या कमी के साथ प्रश्न अनुक्रमणिका भी समकालिक रूप से अद्यतन करें।

## 8. निषिद्ध प्रथाएँ

1. समस्या निवारण दस्तावेज़ को सुविधा-परिचय के रूप में लिखना निषिद्ध है।
2. केवल “पुनः आरंभ करके देखें” जैसे निदान-मूल्य-रहित उत्तर लिखना निषिद्ध है।
3. त्रुटि संदेश और उत्प्रेरक शर्त छोड़ना निषिद्ध है।
4. पहले से ठीक हो चुकी या अमान्य प्रविष्टियाँ बनाए रखना निषिद्ध है।
