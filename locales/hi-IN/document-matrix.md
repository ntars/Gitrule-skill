# दस्तावेज़ मैट्रिक्स

> यह फ़ाइल कौन-सी समस्या हल करती है: प्रत्येक परिदान दस्तावेज़ की अनन्य ज़िम्मेदारी, उसमें सख़्ती से न रखी जाने वाली सामग्री और विभाजन-बाध्यताएँ परिभाषित करना, ताकि एक फ़ाइल की एक ही ज़िम्मेदारी सुनिश्चित हो और विलय निषिद्ध रहे।

## 1. फ़ाइलें और ज़िम्मेदारियाँ

| फ़ाइल | अनन्य ज़िम्मेदारी | सख़्ती से न रखें |
|---|---|---|
| `README.md` | मुख्य पृष्ठ: यह क्या है, कैसे इंस्टॉल करें, कैसे चलाएँ, विवरण कहाँ देखें | पूर्ण API, योगदान प्रक्रिया, परिवर्तन लॉग |
| `LICENSE` | लाइसेंस का पूर्ण पाठ | कोई भी व्याख्या-पाठ |
| `CHANGELOG.md` | उपयोगकर्ता-केंद्रित संस्करण परिवर्तन | आंतरिक पुनर्संरचना का विवरण, विकास योजना |
| `CONTRIBUTING.md` | बाहरी योगदानकर्ताओं की प्रक्रिया और विनिर्देश | परियोजना की विशेषता-व्याख्या |
| `CODE_OF_CONDUCT.md` | आचरण संहिता | तकनीकी सामग्री |
| `SECURITY.md` | भेद्यता रिपोर्टिंग चैनल और प्रतिक्रिया नीति | ज्ञात भेद्यताओं की सूची |
| `docs/api.md` | पूर्ण API संदर्भ | ट्यूटोरियल |
| `docs/architecture.md` | संरचना और मॉड्यूल सीमाएँ | उपयोग के उदाहरण |
| `docs/naming.md` | नामकरण विनिर्देश | अन्य विनिर्देश |
| `docs/release.md` | रिलीज़ प्रक्रिया और संस्करण नीति | परिवर्तन अभिलेख |
| `.github/PULL_REQUEST_TEMPLATE.md` | PR स्व-जाँच सूची | परियोजना का परिचय |
| `.github/ISSUE_TEMPLATE/*.yml` | संरचित issue फ़ॉर्म | मुक्त पाठ |
| `.github/workflows/*.yml` | CI/CD | व्याख्या-दस्तावेज़ीकरण |

> नोट: `docs/naming.md` का विनिर्देश मूल पाठ देखें [परियोजना नामकरण विनिर्देश](./project-naming-specification.md); `docs/release.md` का विनिर्देश मूल पाठ देखें [पुश और रिलीज़ विनिर्देश](./push-and-release-specification.md)।

## 2. बाध्यताएँ

- एकल फ़ाइल 300 पंक्तियों से अधिक होने पर उसे अनिवार्यतः `docs/` में विभाजित करें, README में केवल सारांश + लिंक रखें।
- फ़ाइल नाम निश्चित रूप से बड़े अक्षरों में, पथ निश्चित, स्वयं नई निर्देशिका-स्तर न बनाएँ।
- प्रत्येक दस्तावेज़ के आरंभ में एक वाक्य में “यह फ़ाइल कौन-सी समस्या हल करती है” लिखें, और अंत में संबंधित फ़ाइलों के क्रॉस-लिंक दें।
