# MCP उपकरण विनिर्देश

> यह फ़ाइल कौन-सी समस्या हल करती है: विनिर्देश-संग्रह को मॉडल संदर्भ प्रोटोकॉल (MCP) के माध्यम से उपकरणों के रूप में उजागर करते समय इंटरफ़ेस डिज़ाइन और विवरण-नियम परिभाषित करना, ताकि उपकरण मॉडल द्वारा सही ढंग से खोजे और आह्वान किए जा सकें।

## 1. उपकरण डिज़ाइन के सिद्धांत

1. एकल दायित्व: एक उपकरण एक ही कार्य करे, सर्वग्राही इंटरफ़ेस से बचें।
2. स्पष्ट विवरण: उपकरण का विवरण उसका उद्देश्य और उपयुक्त परिदृश्य बताए, जिससे मॉडल सहजता से तय कर सके कि कब आह्वान करना है।
3. स्पष्ट पैरामीटर: प्रत्येक पैरामीटर के लिए प्रकार, अनिवार्यता, मान-सीमा और विवरण अवश्य हो।
4. संरचित आउटपुट: संरचित डेटा लौटाएँ, लंबे गद्य से बचें।

## 2. अनिवार्य फ़ील्ड

| फ़ील्ड | आवश्यकता |
| --- | --- |
| name | अद्वितीय पहचानकर्ता, लोअरकेस kebab-case |
| description | उद्देश्य और ट्रिगर-शर्तें, ठोस और निर्णय-योग्य |
| inputSchema | पैरामीटर प्रकार, अनिवार्य फ़ील्ड, बाधाएँ |
| लौटाया गया मान | संरचित प्रारूप और फ़ील्ड विवरण |
| त्रुटि | विफलता पर लौटाया जाने वाला प्रारूप, परिणाम गढ़ना निषिद्ध |

## 3. विनिर्देश-संग्रह से संबंधित उपकरण

1. दस्तावेज़ पुनर्प्राप्ति: भाषा कोड + पहचानकर्ता के आधार पर विनिर्देश सामग्री लौटाएँ (पहचानकर्ता देखें [मशीन-पठनीय मेटाडेटा विनिर्देश](./machine-readable-metadata-specification.md))।
2. सूची: उपलब्ध दस्तावेज़ों की सूची और उनका भाषा-मानचित्रण लौटाएँ।
3. सत्यापन: दस्तावेज़ मैट्रिक्स की पूर्णता (देखें [दस्तावेज़ मैट्रिक्स](./document-matrix.md)) और द्वार की स्थिति (देखें [गुणवत्ता द्वार](./quality-gate.md)) जाँचें।

## 4. अनिवार्य नियम

1. उपकरण ऐसे परिणाम को PASS के रूप में न लौटाए जिसकी जाँच संभव न हो, SKIP और कारण अवश्य अंकित करे (देखें [निषिद्ध प्रथाएँ](./prohibited-practices.md))।
2. आउटपुट प्रोग्राम द्वारा पार्स करने योग्य हो, उसमें आंतरिक विचार-प्रक्रिया शामिल न हो।
3. सुरक्षा-संबंधी सामग्री उपकरण के माध्यम से उजागर न हो (देखें [सुरक्षा और गोपनीयता विनिर्देश](./security-and-privacy-specification.md))।
