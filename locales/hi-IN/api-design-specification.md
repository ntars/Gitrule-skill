# API डिज़ाइन विनिर्देश

> यह फ़ाइल कौन-सी समस्या हल करती है: इंटरफ़ेस डिज़ाइन के सुसंगत सिद्धांतों और परिपाटियों को परिभाषित करती है, ताकि API उपयोग में सरल, पूर्वानुमेय और विकासशील बनी रहे।

## 1. डिज़ाइन सिद्धांत

1. नामकरण में सुसंगति: समान प्रकार के संसाधनों और संक्रियाओं के लिए एकसमान नामकरण नियम।
2. पूर्वानुमेयता: समान अर्थ वाली संक्रियाओं की संरचना समान होती है।
3. स्पष्टता अंतर्निहितता से श्रेष्ठ है: डिफ़ॉल्ट मान, अनिवार्य फ़ील्ड और त्रुटि व्यवहार स्पष्ट होने चाहिए।
4. पश्च-संगतता: परिवर्तनों में संगतता बनाए रखना प्राथमिक है, विघटनकारी परिवर्तनों का संस्करणीकरण अवश्य हो (देखें [संस्करण प्रबंधन विनिर्देश](./version-management-specification.md))।

## 2. अनिवार्य परिपाटियाँ

1. **नामकरण**: संसाधनों, विधियों और फ़ील्ड के नामकरण के नियम।
2. **पैरामीटर**: प्रकार, अनिवार्यता, डिफ़ॉल्ट मान, मान-सीमा।
3. **त्रुटियाँ**: एकसमान त्रुटि संरचना, त्रुटि कोड, HTTP स्थिति या समतुल्य तंत्र।
4. **पेजिनेशन और फ़िल्टरिंग**: अधिक डेटा वाले परिदृश्यों के लिए पेजिनेशन, क्रमण और फ़िल्टरिंग की परिपाटियाँ।
5. **इडेम्पोटेंसी**: लेखन संक्रियाओं की इडेम्पोटेंट गारंटी।
6. **दर सीमन और कोटा**: आवृत्ति सीमा और सीमा-अतिक्रमण पर प्रतिक्रिया।
7. **संस्करण**: API संस्करण रणनीति और विकास की विधि।

## 3. पूर्ण नियम

1. त्रुटि प्रतिक्रिया में पहचान योग्य त्रुटि कोड और विवरण शामिल होना चाहिए, आंतरिक कार्यान्वयन विवरण उजागर न किए जाएँ।
2. विघटनकारी परिवर्तनों में संस्करण बढ़ाना और माइग्रेशन अवधि देना अवश्य है (देखें [परिवर्तन लॉग विनिर्देश](./changelog-specification.md))।
3. इंटरफ़ेस का संबंधित दस्तावेज़ीकरण होना चाहिए और फ़ील्ड पूर्ण होने चाहिए (देखें [API दस्तावेज़ीकरण विनिर्देश](./api-documentation-specification.md))।
