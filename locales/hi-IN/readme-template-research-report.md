# README टेम्पलेट सर्वेक्षण रिपोर्ट

> यह फ़ाइल कौन-सी समस्या हल करती है: इस बार के मानक README टेम्पलेट के सर्वेक्षण की विधि, नमूना आकार और मात्रात्मक निष्कर्ष दर्ज करती है, [README मानक टेम्पलेट](./readme-standard-template.md) तथा विभिन्न विशिष्ट विनिर्देशों के लिए डेटा आधार प्रदान करती है, और विधि की सीमाओं तथा बाध्यताओं को स्पष्ट करती है।

## 1. सर्वेक्षण का लक्ष्य और विधि

### 1.1 लक्ष्य

star संख्या में अग्रणी शीर्ष ओपन-सोर्स परियोजनाओं का सर्वेक्षण करके उनके README तथा संबंधित दस्तावेज़ों की संरचना, अनुभाग संगठन, दृश्य प्रस्तुति और बैज उपयोग के नियमों को संक्षेपित करना, तथा पुनः उपयोग योग्य सामान्य विनिर्देश और टेम्पलेट तैयार करना।

### 1.2 डेटा स्रोत

- रिपॉज़िटरी मेटाडेटा: GitHub GraphQL Search API, star के अवरोही क्रम में, फ़िल्टर `is:public archived:false fork:false`।
- README मूल पाठ: GitHub REST Contents API (`readme` एंडपॉइंट), base64 अथवा raw रूप में प्राप्त करके पार्स किया गया।
- बैज पैरामीटर: Shields.io के आधिकारिक दस्तावेज़ (Static Badge, Logos पृष्ठ) तथा badge-maker के प्रारूप विवरण।
- चीनी समुदाय का अभ्यास: phodal/github (“GitHub भ्रमण मार्गदर्शिका”, 11,362 star) की परियोजना दस्तावेज़, कमिट संदेश और प्रचार अनुभाग, जो मशीन-पठनीय सांख्यिकी से आच्छादित न होने वाले लेखन सिद्धांतों और संचालन अनुभव की पूर्ति करते हैं।

### 1.3 संग्रह विधि

1. **मेटाडेटा**: GitHub Search API की एक क्वेरी अधिकतम 1000 प्रविष्टियाँ लौटाती है। नमूना विस्तारित करने के लिए star अंतराल विभाजन अपनाया गया — द्विभाजन विधि से प्रत्येक 1000 के संगत star सीमा निर्धारित की गई, क्रमशः 11 बैच नीचे की ओर बढ़ाए गए, और अंततः 10,995 अग्रणी रिपॉज़िटरी का मेटाडेटा प्राप्त हुआ।
2. **README नमूनाकरण**: अग्रणी 1000 रिपॉज़िटरी के भीतर मुख्य भाषा के आधार पर स्तरीकृत नमूनाकरण किया गया, जिसमें Python, TypeScript, JavaScript, Rust, Go, C++ आदि प्रमुख भाषाएँ सम्मिलित हैं, 120 रिपॉज़िटरी का नमूना लिया गया और सभी के README मूल पाठ सफलतापूर्वक प्राप्त हुए।
3. **सांख्यिकीय मानक**: रिपॉज़िटरी को इकाई मानकर अनुभाग उपस्थिति दर तथा तत्व उपयोग दर की गणना की गई; बैज शैली और logo पैरामीटर URL में उनकी उपस्थिति संख्या के अनुसार गिने गए।

### 1.4 विधि की सीमाएँ (स्पष्ट होना आवश्यक)

- GitHub Search API की प्रति क्वेरी 1000 प्रविष्टियों की ऊपरी सीमा है, यह रिपोर्ट विभाजन जोड़कर पैमाना बढ़ाती है, किंतु विभाजन की सीमाएँ star की बराबरी से प्रभावित होती हैं, अतः नमूना एक निकटतम अग्रणी समुच्चय है, कठोर क्रमिक रैंकिंग नहीं।
- README का नमूना आकार 120 है, निष्कर्ष प्रवृत्तियों और साझा विशेषताओं को दर्शाते हैं, संपूर्ण अग्रणी परियोजनाओं के सांख्यिकीय रूप से महत्वपूर्ण वितरण का प्रतिनिधित्व नहीं करते।
- अनुभाग पहचान शीर्षक के कीवर्ड मिलान पर आधारित है, शब्दावली के अंतर से सांख्यिकीय विचलन संभव है।
- बैज पैरामीटर की गणना URL में स्पष्ट रूप से उपस्थित पैरामीटरों पर आधारित है, गतिशील बैज के डिफ़ॉल्ट पैरामीटर सम्मिलित नहीं किए गए।

## 6. संक्षिप्त निष्कर्ष

1. सामान्य टेम्पलेट का मुख्य ढाँचा “स्थिति → इंस्टॉल → त्वरित शुरुआत → दस्तावेज़ → योगदान → लाइसेंस” होना चाहिए।
2. बैज डिफ़ॉल्ट रूप से `flat-square` अथवा `for-the-badge` रखें, पूरे दस्तावेज़ में एकरूपता रखें, संख्या 4–6 हो।
3. चित्र और कोड ब्लॉक आकर्षक होमपेज का केंद्र हैं, इनके साथ `alt` और भाषा टैग आवश्यक हैं।
4. परियोजना का प्रकार अनुभागों के चयन का निर्धारण करता है, देखें [README श्रेणी अनुकूलन मार्गदर्शिका](./readme-category-adaptation-guide.md)।
5. अनुपालन और समुदाय-शासन (लाइसेंस, योगदान मार्गदर्शिका) अग्रणी परियोजनाओं की सहमति है, इन्हें अनिवार्य रखा गया है।
