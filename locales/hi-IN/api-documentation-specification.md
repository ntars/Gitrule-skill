# API दस्तावेज़ीकरण विनिर्देश

> यह फ़ाइल कौन-सी समस्या हल करती है: पूर्ण API संदर्भ दस्तावेज़ीकरण की संरचना और फ़ील्ड को परिभाषित करती है, जो docs/api.md लिखने का आधार है, और ट्यूटोरियल-प्रकार की सामग्री से पूर्णतः पृथक रहती है।

## 1. अनिवार्य संरचना

प्रत्येक API प्रविष्टि में निम्नलिखित सम्मिलित होना चाहिए:

| फ़ील्ड | आवश्यकता |
| --- | --- |
| इंटरफ़ेस हस्ताक्षर | मेथड, पथ या फ़ंक्शन प्रोटोटाइप, पूर्ण रूप से प्रतिलिपि-योग्य |
| पैरामीटर | नाम, प्रकार, अनिवार्यता, डिफ़ॉल्ट मान, मान-सीमा, विवरण |
| वापसी मान | प्रकार और संरचना का विवरण |
| त्रुटि कोड | त्रुटि कोड, ट्रिगर की शर्तें, निवारण विधि |
| कॉल उदाहरण | चलाने योग्य न्यूनतम उदाहरण, भाषा अंकित |
| दर सीमा और कोटा | कॉल आवृत्ति सीमा, कोटा, सीमा-अतिक्रमण पर प्रबंधन |

## 2. पूर्ण नियम

1. पैरामीटर और वापसी मान के प्रकार तथा प्रतिबंध स्पष्ट रूप से लिखे जाएँ, डिफ़ॉल्ट मान न छोड़े जाएँ।
2. त्रुटि कोड पूर्ण रूप से सूचीबद्ध किए जाएँ, केवल “त्रुटि संभव है” न लिखा जाए।
3. कोड ब्लॉक में भाषा पहचानकर्ता अंकित हो, उदाहरण स्वतंत्र रूप से चल सके।
4. इस फ़ाइल में केवल संदर्भ जानकारी रखी जाए, ट्यूटोरियल, पृष्ठभूमि, डिज़ाइन विवरण न लिखे जाएँ (ट्यूटोरियल और पृष्ठभूमि देखें [README अनुभाग विनिर्देश](./readme-sections-specification.md))।

## 3. संगतता आवश्यकताएँ

API दस्तावेज़ीकरण में इंटरफ़ेस हस्ताक्षर कोड के वास्तविक कार्यान्वयन से मेल खाने चाहिए; पैरामीटर नामकरण [सामान्य लेखन विनिर्देश](./general-writing-specification.md) की सटीकता-आवश्यकताओं के अनुरूप होना चाहिए; पद देखें [शब्दावली सूची](./glossary.md)।
