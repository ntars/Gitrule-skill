# परियोजना नामकरण विनिर्देश

> यह फ़ाइल कौन-सी समस्या हल करती है: भंडार के नाम के वर्ण, केस, शब्द-विभाजन, लंबाई और अर्थ जैसे पूर्ण नियम, तथा नामकरण सूत्र, परंपरागत प्रत्यय, खोज प्रक्रिया और साथ के मेटाडेटा की माँगें परिभाषित करना।

## 1. पूर्ण नियम

| नियम | आवश्यकता | प्रतिकूल उदाहरण |
|---|---|---|
| वर्ण-समुच्चय | केवल `a-z`, `0-9`, `-` | `My_Proj`, `我的项目` |
| केस | पूर्णतः लोअरकेस | `MyProject` |
| शब्द-विभाजन | kebab-case, `-` से जोड़ें | `myproject`, `my_project` |
| लंबाई | 2–25 वर्ण | अत्यधिक लंबा जोड़ा गया नाम |
| अंत | संज्ञा या आकार-प्रत्यय पर समाप्त | `-project`, `-test` पर समाप्त |
| संस्करण | संस्करण संख्या, वर्ष, तिथि शामिल न हों | `tool-v2`, `app2024` |
| सूचना-रहित शब्द | `my`/`demo`/`test`/`new`/`tmp` निषिद्ध | `my-new-demo` |
| विशिष्टता | GitHub / npm / PyPI पर एक-एक बार खोजें | प्रसिद्ध लाइब्रेरी से नाम टकराना |
| अर्थ | नाम से ही “क्या करता है” पढ़ा जा सके | `xyz`, `abc123` |

## 2. नामकरण सूत्र (चार में से एक)

```text
<तकनीक>-<वस्तु>          vue-virtual-table      go-ratelimit
<वस्तु>-<आकार>          note-cli   image-api   config-loader
<क्रिया>-<वस्तु>          parse-markdown   sync-dotfiles
<क्षेत्र>-<उपक्षेत्र>        web-ui-kit   data-pipeline
```

## 3. परंपरागत प्रत्यय

`-cli` कमांड लाइन / `-sdk` क्लाइंट लाइब्रेरी / `-api` `-server` सर्वर-पक्ष / `-template` `-boilerplate` स्कैफ़ोल्ड / `-loader` `-parser` मिडलवेयर / `-kit` कंपोनेंट सेट / `-notes` `-guide` दस्तावेज़ीकरण / `dotfiles` कॉन्फ़िग भंडार / `awesome-xxx` संसाधन संग्रह।

## 4. नामकरण प्रक्रिया

1. एक वाक्य में लिखें कि “परियोजना किसके लिए कौन-सी समस्या हल करती है”।
2. इस वाक्य से मुख्य संज्ञा + आकार लें, और अनुभाग 2 के किसी एक सूत्र को लागू करें।
3. 3 उम्मीदवार बनाएँ, और एक-एक करके नाम-टकराव की खोज करें।
4. वह चुनें जिसे README देखे बिना सबसे अधिक आसानी से समझा जा सके।
5. चीनी नाम भंडार के नाम में न लिखें, उसे README की पहली पंक्ति के शीर्षक के बाद लिखें।

## 5. साथ का मेटाडेटा

### 5.1 भंडार परिचय (description)

- भंडार के नाम के साथ एक ही स्रोत से, वाक्य-रूप: `<क्या करता है> for <किसके लिए>`।
- द्विभाषी संयुक्त प्रारूप: `राष्ट्रीय भाषा | अंग्रेज़ी`, पहले राष्ट्रीय भाषा वाला संस्करण लिखें, फिर अर्ध-चौड़ाई की खड़ी रेखा (दोनों ओर एक-एक स्पेस), और अंत में अंग्रेज़ी संस्करण। चीनी परियोजना का उदाहरण:

```text
हल्का Go कमांड-लाइन JSON प्रोसेसिंग उपकरण | A lightweight Go CLI for JSON processing
```

- लंबाई: राष्ट्रीय भाषा और अंग्रेज़ी में से प्रत्येक 120 वर्णों से अधिक न हो, द्विभाषी कुल 350 वर्णों से अधिक न हो (GitHub की ऊपरी सीमा)।
- द्विभाषी कुल सीमा पार होने पर चयन: राष्ट्रीय भाषा संस्करण के बजाय अंग्रेज़ी संस्करण को पहले संक्षिप्त करें — चीनी का सूचना-घनत्व अधिक है, चीनी को संक्षिप्त करने पर अधिक सूचना की हानि होती है; संक्षिप्त करते समय पहले विशेषण और दोहराए गए सीमांकक हटाएँ, फिर समानार्थी अभिव्यक्तियाँ मिलाएँ, अंत में दोनों भाषा-संस्करणों की अपनी-अपनी पूर्ण कर्ता-क्रिया संरचना बनाए रखें।
- इसमें नई पंक्ति, Markdown सिंटैक्स और Emoji शामिल न हों; दोनों भाषाओं की अंतिम विराम-चिह्न शैली एक समान रहे (दोनों में पूर्ण विराम लगाएँ या दोनों में न लगाएँ)।

### 5.2 विषय (topics)

- 20 पूरे करें (GitHub की ऊपरी सीमा), पूर्ण कवरेज, कोई स्थान खाली न छोड़ें।
- सभी अंग्रेज़ी में, चीनी या किसी अन्य भाषा का प्रयोग न करें; पूर्णतः लोअरकेस, `-` से जोड़ें, स्पेस और विशेष वर्ण शामिल न हों।
- भाषा, क्षेत्र, आकार, पारिस्थितिकी और परिदृश्य — पाँचों श्रेणियों को पूर्णतः कवर करें, इसके अतिरिक्त documentation, open-source जैसे सामान्य शब्द जोड़े जा सकते हैं।
- भंडार बनाते समय ही सेट करें, खाली न छोड़ें; भंडार का नाम बदलने या उसे पुनः परिभाषित करने के बाद एक बार पुनः जाँचें।
