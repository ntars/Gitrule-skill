# README दृश्य लेआउट विनिर्देश

> यह फ़ाइल कौन-सी समस्या हल करती है: README का लेआउट पदानुक्रम, अनुच्छेद संगठन, तालिकाओं, स्क्रीनशॉट तथा GIF के उपयोग परिदृश्य और उनका स्थान परिभाषित करना, ताकि दस्तावेज़ सूचना-घनत्व और दृश्य आकर्षण के बीच संतुलन बना सके।

इस दस्तावेज़ का “मापा गया” डेटा इस परियोजना द्वारा शीर्ष ओपन-सोर्स परियोजनाओं के README के नमूना सांख्यिकी (नमूना N=120) से लिया गया है; आदर्श प्रथाएँ कई उच्च-स्टार परियोजनाओं की प्रथम-स्क्रीन संरचना के साक्ष्य से ली गई हैं।

## 1. लेआउट पदानुक्रम

### 1.1 शीर्षक स्तर

README को स्पष्ट शीर्षक पदानुक्रम स्थापित करना चाहिए, निम्नलिखित बाधाओं का पालन करते हुए:

1. पूरे दस्तावेज़ में केवल एक प्रथम-स्तरीय शीर्षक (`#`) रखें, अर्थात् परियोजना का नाम, जो फ़ाइल की पहली पंक्ति पर हो।
2. द्वितीय-स्तरीय शीर्षक (`##`) मुख्य अनुभाग हैं, इनकी संख्या 6–12 उपयुक्त है; मापा गया माध्यक 7 है।
3. तृतीय-स्तरीय शीर्षक (`###`) अनुभाग के भीतर उपविभाजन के लिए हैं, इनका प्रयोग केवल तब करें जब द्वितीय-स्तरीय शीर्षक की सामग्री लंबी हो।
4. शीर्षक स्तरों में छलांग नहीं होनी चाहिए (जैसे `#` से सीधे `###` पर जाना)।
5. शीर्षक पाठ संक्षिप्त हो, संज्ञा या संज्ञा वाक्यांश का प्रयोग करें, अंत में पूर्ण विराम न लगाएँ।

### 1.2 प्रथम-स्क्रीन संरचना क्रम

प्रथम स्क्रीन का अर्थ है वह सामग्री जो बिना स्क्रॉल किए दिखाई देती है, इसे निम्नलिखित क्रम में व्यवस्थित करें:

1. केंद्रित लोगो या परियोजना बैनर (वैकल्पिक);
2. प्रथम-स्तरीय शीर्षक (परियोजना का नाम);
3. बैज पंक्ति (विवरण हेतु [बैज विनिर्देश](./badge-specification.md) देखें);
4. एक-वाक्य स्थिति-निर्धारण (यह बताना कि परियोजना क्या है, किसके लिए है, कौन-सी समस्या हल करती है);
5. अनुभाग नेविगेशन लिंक पंक्ति (वैकल्पिक, लंबे README के लिए उपयुक्त);
6. मुख्य सुविधाओं या विशेषताओं का सार।

आदर्श साक्ष्य: `fd` और `ripgrep` स्थिति-निर्धारण के तुरंत बाद अनुभाग नेविगेशन रखते हैं; `next.js` और `rust-lang/rust` केंद्रित लोगो और बैनर से शुरुआत करते हैं; `vscode` स्थिति-निर्धारण के बाद तुरंत उत्पाद स्क्रीनशॉट डालता है।

### 1.3 अनुच्छेद और रिक्त स्थान

- प्रत्येक अनुच्छेद को 1–4 पंक्तियों में रखें, घने पाठ के बड़े खंडों से बचें।
- अनुच्छेदों के बीच एक खाली पंक्ति छोड़ें, ताकि रेंडरिंग के बाद साँस लेने का एहसास बना रहे।
- मुख्य निष्कर्ष पहले रखें, व्याख्या बाद में।
- चीनी और अंग्रेज़ी या अंकों के बीच एक स्थान रखें; चीनी और अंग्रेज़ी विराम-चिह्न अपने-अपने संदर्भ के अनुसार प्रयोग करें।

## 2. तालिका उपयोग विनिर्देश

### 2.1 उपयोग परिदृश्य

तालिकाएँ बहु-आयामी, तुलनीय सूचना के लिए उपयुक्त हैं। मापन में 36.7% नमूनों ने तालिकाओं का उपयोग किया; ये कॉन्फ़िगरेशन विवरण, संगतता मैट्रिक्स और कमांड तुलना के लिए अनुशंसित रूप हैं। उपयुक्त परिदृश्यों में शामिल हैं:

- कॉन्फ़िगरेशन आइटम का विवरण (कुंजी नाम, प्रकार, डिफ़ॉल्ट मान, उद्देश्य);
- प्लेटफ़ॉर्म / संस्करण संगतता मैट्रिक्स;
- कमांड या पैरामीटर तुलना;
- सुविधा तुलना (यह परियोजना बनाम अन्य समाधान);
- रोडमैप और स्थिति।

### 2.2 स्थान

तालिका अपने द्वितीय-स्तरीय शीर्षक के तुरंत बाद आती है, उससे पहले एक मार्गदर्शक वाक्य में तालिका का उद्देश्य बताएँ; यदि तालिका के बाद अपवाद हों, तो अलग अनुच्छेद में पूरक जानकारी दें।

### 2.3 लेखन आवश्यकताएँ

| आवश्यकता | विवरण |
| --- | --- |
| स्तंभ संख्या नियंत्रण | 3–6 स्तंभ, 6 से अधिक होने पर विभाजन पर विचार करें |
| स्पष्ट शीर्ष-पंक्ति | प्रत्येक स्तंभ को संक्षिप्त संज्ञा शीर्षक दें, खाली शीर्षक से बचें |
| एकसमान संरेखण | पूरे दस्तावेज़ में तालिका संरेखण एक समान रहे |
| संक्षिप्त सामग्री | कोशिकाओं में लंबे अनुच्छेद न लिखें, आवश्यकता होने पर फ़ुटनोट या लिंक से विस्तार करें |
| रिक्त कोशिका नहीं | जहाँ सामग्री न हो वहाँ “कोई नहीं” या “लागू नहीं” लिखें |

## 3. कोड ब्लॉक उपयोग विनिर्देश

### 3.1 उपयोग परिदृश्य

कोड ब्लॉक कमांड, कॉन्फ़िगरेशन, API कॉल और नमूना आउटपुट के लिए उपयोग होते हैं। मापन में 66.7% नमूनों में कोड ब्लॉक थे; ये “त्वरित प्रारंभ” अनुभाग के अनिवार्य तत्व हैं, माध्यक 2 है।

### 3.2 लेखन आवश्यकताएँ

1. प्रत्येक कोड ब्लॉक में भाषा अवश्य अंकित करें, जैसे `bash`, `json`, `python`, `javascript`, ताकि सिंटैक्स हाइलाइटिंग हो सके।
2. कमांड उदाहरण में पूर्ण निष्पादन-योग्य कमांड दें, पूर्व-आवश्यक चरणों को न छोड़ें।
3. परिणाम दिखाने की आवश्यकता हो तो अलग कोड ब्लॉक में `text` अंकित करें, और पाठ में अपेक्षित आउटपुट स्पष्ट करें।
4. कोड ब्लॉक के पहले और बाद में एक-एक खाली पंक्ति छोड़ें।
5. एकल ब्लॉक की सामग्री 20 पंक्तियों के भीतर रखें, अत्यधिक लंबे उदाहरणों को कई ब्लॉकों में विभाजित करें या `examples/` निर्देशिका में ले जाकर लिंक दें।
6. इंटरैक्टिव कमांड में `$` प्रॉम्प्ट का उपयोग पूरे दस्तावेज़ में एक समान रहे।

प्रारूप उदाहरण:

```bash
npm install <package-name>
```

## 4. स्क्रीनशॉट और GIF उपयोग विनिर्देश

### 4.1 उपयोग परिदृश्य और चयन

| तत्व | उपयुक्त परिदृश्य | ध्यान देने योग्य बातें |
| --- | --- | --- |
| स्थिर स्क्रीनशॉट | अनुप्रयोग इंटरफ़ेस, रन परिणाम, चार्ट | मापा गया उपयोग दर 63.3%, सर्वाधिक प्रयुक्त |
| GIF / एनिमेशन | कमांड-लाइन प्रदर्शन, इंटरैक्शन प्रवाह, पहले-बाद का तुलना | फ़ाइल आकार बड़ा, संपीड़न आवश्यक, अवधि नियंत्रित करें |
| लोगो / बैनर | ब्रांड पहचान, प्रथम-स्क्रीन मुखपृष्ठ | हल्के और गहरे रंग के दो संस्करण दें |
| आरेख | संरचना, प्रवाह, डेटा प्रवाह | दस्तावेज़ संस्करण के साथ समकालिक रूप से अद्यतन करें |

मापन में 63.3% नमूनों में चित्र थे। आदर्श साक्ष्य: `fd` डेमो के रूप में `doc/screencast.svg` का उपयोग करता है, `ripgrep` खोज परिणाम का स्क्रीनशॉट उपयोग करता है, `vscode` उत्पाद के रनिंग स्क्रीनशॉट का उपयोग करता है, और `rust` तथा `next.js` हल्के-गहरे रंग के अनुकूली लोगो बैनर का उपयोग करते हैं।

### 4.2 स्थान

1. लोगो / बैनर: फ़ाइल के सबसे ऊपर, केंद्रित।
2. उत्पाद स्क्रीनशॉट: एक-वाक्य स्थिति-निर्धारण के बाद और “त्वरित प्रारंभ” से पहले, सहज समझ स्थापित करने के लिए।
3. GIF डेमो: पृथक “डेमो / प्रदर्शन” अनुभाग, “मुख्य सुविधाओं” के तुरंत बाद।
4. संरचना आरेख: “संरचना” या “डिज़ाइन” अनुभाग में रखें, या `docs/architecture.md` में ले जाएँ और README में लिंक दें।

### 4.3 लेखन आवश्यकताएँ

- प्रत्येक चित्र के लिए `alt` पाठ अवश्य दें, जो चित्र की सामग्री का वर्णन करे; `image`, `स्क्रीनशॉट` जैसे अर्थहीन पाठ का उपयोग न करें।
- चित्र भंडार के भीतर के संसाधनों को सापेक्ष पथ से संदर्भित करें, या स्थिर निरपेक्ष URL का उपयोग करें; समय-सीमित अस्थायी लिंक से बचें।
- थीम-अनुकूलन आवश्यक चित्रों के लिए HTML `<picture>` के साथ `prefers-color-scheme` का उपयोग करके हल्के और गहरे दोनों संस्करण दें।
- चित्र का आकार नियंत्रित करें: स्क्रीनशॉट के लिए WebP या अनुकूलित PNG को प्राथमिकता दें, GIF को लघु वीडियो या संपीड़ित एनिमेशन में बदलने को प्राथमिकता दें।
- चित्र की चौड़ाई अनुकूलित करें: `width` विशेषता या बाहरी कंटेनर सीमा का उपयोग करें, ताकि पृष्ठ का लेआउट न टूटे।

## 5. लिंक और नेविगेशन

### 5.1 अनुभाग नेविगेशन

जब README 200 पंक्तियों से अधिक हो, तो प्रथम स्क्रीन में नेविगेशन लिंक पंक्ति जोड़ें, जो मुख्य अनुभागों की ओर संकेत करे:

```markdown
[इंस्टॉल](#इंस्टॉल) · [त्वरित प्रारंभ](#त्वरित-प्रारंभ) · [दस्तावेज़ीकरण](#दस्तावेज़ीकरण) · [योगदान](#योगदान)
```

### 5.2 सापेक्ष लिंक को प्राथमिकता

भंडार के भीतर के दस्तावेज़, चित्र और लाइसेंस सभी सापेक्ष पथ का उपयोग करें, ताकि फ़ोर्क और ऑफ़लाइन पढ़ने के दौरान भी वे काम करें। बाहरी लिंक प्रामाणिक स्रोत होने चाहिए (आधिकारिक दस्तावेज़ीकरण, पैकेज प्रबंधक पृष्ठ, CI पृष्ठ)।

## 6. सौंदर्य और आकर्षण के लिए कार्यान्वयन सूची

1. प्रथम स्क्रीन में लोगो या स्पष्ट शीर्षक हो, जो 3 सेकंड में परियोजना की स्थिति बता दे।
2. बैज एकसमान शैली, अर्थपूर्ण रंग-योजना और संतुलित संख्या में हों।
3. प्रथम-स्तरीय शीर्षक एकमात्र हो, द्वितीय-स्तरीय शीर्षक 6–12 हों, स्तरों में कोई छलांग न हो।
4. कम-से-कम एक प्रतिलिपि-योग्य, चलाने-योग्य कोड उदाहरण हो।
5. कम-से-कम एक स्क्रीनशॉट या डेमो हो जो उत्पाद का मूल्य दर्शाए।
6. तालिकाएँ तुलनात्मक सूचना के लिए हों, स्तंभ नियंत्रित और शीर्ष-पंक्ति स्पष्ट हों।
7. सभी चित्रों में `alt` हो, सभी कोड ब्लॉक में भाषा अंकन हो।
8. लंबे दस्तावेज़ों में अनुभाग नेविगेशन हो।
9. हल्के और गहरे थीम में चित्र और बैज दोनों पठनीय हों।
