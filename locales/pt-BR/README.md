## Caminhos de leitura

- **Delimitar o escopo aplicável**: Guia de seleção de especificações → Tabela de correspondência do ciclo de vida → arquivos de especificação da fase correspondente.
- **Ao longo de todo o ciclo de vida**: Tabela de correspondência do ciclo de vida → Especificação de iniciação do projeto e requisitos → Especificação da matriz de rastreabilidade de requisitos → Especificação de documentos de arquitetura → Especificação de testes → Especificação de implantação e reversão → Especificação de observabilidade → Especificação de retrospectiva de iteração.
- **Push rápido**: Regras absolutas → Portão de qualidade → Especificação de push e publicação → Formato do relatório de revisão.
- **Criar documentação do zero**: Papéis e responsabilidades → Processo de execução → Coleta de informações e modelos → Matriz de documentação → Especificação de seções do README → Especificação de conformidade de código aberto → Portão de qualidade.
- **Redigir o README**: Relatório de pesquisa de modelos de README → Especificação de layout visual do README → Especificação de selos → Guia de adaptação do README por categoria → Modelo padrão de README.
- **Revisão completa**: Matriz de dimensões de revisão → Contrato de despacho de subagentes → Regras absolutas → Portão de qualidade → Formato do relatório de revisão.
- **Integração programática**: Especificação de metadados legíveis por máquina → Especificação de criação de Skills / Especificação de ferramentas MCP / Especificação de invocação de agentes e prompts.
- **Risco e limites de responsabilidade**: Isenção de responsabilidade → Modelo de isenção de responsabilidade → Modelo de SECURITY → Especificação de segurança e privacidade → Especificação de conformidade de código aberto.
- **Criar os arquivos de governança comunitária**: Modelo de guia de contribuição → Modelo de código de conduta → Modelo de SECURITY → Modelo de isenção de responsabilidade.

## Convenções de linguagem

- **deve / não deve**: requisito obrigatório.
- **deveria / não deveria**: recomendação ou proibição; toda divergência exige justificativa.
- **pode**: opcional.
- **P0 / P1 / P2**: P0 bloqueia o push; P1 deve ser resolvido antes do push ou obrigatoriamente registrado como tarefa; P2 é uma otimização recomendada.
