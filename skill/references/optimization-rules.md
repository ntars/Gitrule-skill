# Gitrule 优化规则

## 问题类型与判定

| 类型 | 判定依据 | 是否自动修复 |
| --- | --- | --- |
| missing-purpose | 文件开头 600 字符内无「本文件解决什么问题」或「What this file solves」 | 否 |
| missing-related | 无「## 相关文件」或「## Related Files」 | 否 |
| bare-code-fence | 代码围栏开口未标注语言 | 是，补 `text` |
| unclosed-code-fence | 代码围栏未配对 | 否，需人工定位 |
| broken-link | 站内相对 Markdown 链接目标不存在（外部链接、页内锚点、`//` 协议相对地址不参与校验） | 否 |
| orphan | 除索引外未被任何其他文档引用 | 否 |
| index-count | 索引域计数合计与表格条目数不一致 | 否 |
| index-declaration | 索引声明合计与表格条目数不一致 | 否 |
| unregistered-placeholder | README 模板正文占位符未登记到对照表 | 否 |

## 跨语种问题类型（`xcheck`）

以参考语种为基准，通过比对各语种索引页 `README.md` 的链接顺序建立篇目一一映射，逐篇比对以下各轴：

| 类型 | 判定依据 | 是否自动修复 |
| --- | --- | --- |
| cross-heading | 标题（`#`~`######`）数量与参考语种不同 | 否 |
| cross-fence | 代码围栏数量不同 | 否 |
| cross-link | Markdown 链接数量不同（索引页允许目标比参考多 1，用于语言切换） | 否 |
| cross-ordered | 有序列表项数量不同 | 否 |
| cross-unordered | 无序列表项数量不同 | 否 |
| cross-table-rows | 表格数据行数不同 | 否 |
| cross-table-columns | 某张表格某行的列数与参考语种不同 | 否 |
| cross-placeholder | 占位符集合不同（按多重集比对，含名称与出现次数） | 否 |

映射建立阶段的错误（早于逐篇比对）：

| 类型 | 判定依据 | 是否自动修复 |
| --- | --- | --- |
| cross-missing-language | 目标语种目录 `locales/<lang>/` 不存在 | 否 |
| cross-no-reference | 参考语种索引页取不到任何规范链接，无法建立映射基准 | 否 |
| cross-index-count | 目标索引页的规范链接数与参考语种不同；命中后该语种不再逐篇比对 | 否 |
| cross-broken-index | 索引页列出了某篇，但该语种目录里没有这个文件 | 否 |
| cross-missing-reference | 参考语种索引列出了某篇，但参考语种目录里缺这个文件 | 否 |
| cross-unreadable | 某篇文件存在但读取失败（编码错误、权限不足） | 否 |

注意：`cross-missing-reference` 是参考语种自身的完整性缺陷，因逐语种独立比对，同一个缺失会在 N 个语种上各报一条（12 语种时 11 条）。修复时应改参考语种的索引或文件，不要逐条改目标语种。

## 术语矩阵问题类型（termcheck）

术语表含「多语言译名矩阵」时启用。检查方向是**单向的：矩阵 → 正文**，即核对表里登记的译名是否真的在正文用上了。

| 类型 | 判定依据 | 是否自动修复 |
| --- | --- | --- |
| term-not-in-corpus | 矩阵里某语种某术语的译名，在该语种正文（排除术语表与索引页）中一次都没出现 | 否 |
| term-doubtful-stem | 变格语言的矩阵值与代码登记的检索词干对不上，无法据此校验正文 | 否 |
| term-no-matrix | 该语种术语表存在，但里面找不到译名矩阵 | 否 |
| term-missing-language | 该语种目录 `locales/<lang>/` 不存在 | 否 |

判定细节：

- **语料范围**：拼接该语种全部规范正文，但**排除术语表本身**（否则表证明表，形成自证循环）与 `README.md`（导航页只有链接）。
- **变格语言按词干检索**：俄语、德语等语言正文中术语会变格（`семантическое` → `семантического`、`semantische` → `semantischen`），严格全字匹配会误报「无实证」。此类语言在代码的 `TERM_STEMS` 中登记词干，命中即视为出现。
- **只做单向核对**：不检查「正文某篇未出现某术语」。技术规范按主题分篇，某篇不涉及某术语属正常，强行要求出现会产生大量误报。
- **同义异写自动检测未纳入**：曾尝试用「全称（缩写）」展开式反查同义写法，但自然语言短语边界无法可靠切分，且单复数、冠词差异（`décision d'architecture` vs `des décisions d'architecture`）造成误报率高于价值，已主动移除。

修复原则：

1. `term-not-in-corpus`：先在正文检索该概念的**实际写法**，用实际写法回填矩阵；若正文确实未用该术语，则从矩阵删格，不为了填表而在正文硬塞译名。反向操作（照矩阵改正文）会让全语种趋同于一个生造词。
2. `term-doubtful-stem`：先判断是矩阵值填错还是正文用法不同源，再改矩阵值或补登词干，不要直接放宽匹配条件。
3. `term-no-matrix`：按参考语种补齐矩阵三节结构，译名逐语种取证后再填。
4. 新增语种时，先按矩阵补齐译名，再跑 `xcheck` 校结构、`termcheck` 校用词。

## 人工修正规则

1. `broken-link`：确认目标文件是否改名或跨语言路径是否写错；修正链接路径，不删除链接。
2. `orphan`：在相关规范或索引中补一条引用，说明该文件的使用场景；不删除孤立文件。
3. `index-count` / `index-declaration`：以磁盘文件数为准，统一域计数、表格条目与声明合计。
4. `unregistered-placeholder`：将占位符登记到对照表，写明含义、示例与是否必填；不得删除正文占位符。
5. `missing-purpose` / `missing-related`：在文件开头补职责句、结尾补相关文件区，保持一文件一职责。
6. `cross-placeholder`：**占位符名称必须与参考语种逐字一致**，不得本地化、音译或意译；仅占位符之外的说明文字可翻译。定位时按出现顺序对齐，不可全文按序批量替换——同名占位符在译文中被合并或拆分会导致错位。
7. 其余 `cross-*`：以参考语种为结构基准补齐或删除多余标题、列表项、表格行列；不得为凑数添加无实质内容的条目。
8. `cross-unreadable`：先按提示修复文件编码（统一 UTF-8）或权限，再重跑；不要删除该篇以绕过报错。

## 自动修复的边界（`optimize`）

`optimize` 只做一件事：给**裸代码围栏**补语言标识，其余问题一律只报告。

- 任意长度的反引号围栏都会处理，补齐后保留原长度——四重围栏仍是四重，不会与其内嵌的三重围栏混淆。
- 修改前后**文件行数不变**，只改开口那一行，不动代码块内容。
- 同一文件的多处裸围栏一次性修完，每个文件只备份一次（`--backup` 生成 `.bak`）。
- 报告里每项带「仅报告 / 已修复」标记：`--fix` 未开启时全部为「仅报告」，开启后按实际写入情况标记，不再出现「计划 2 条、已修复 1 条」这种对不上的情况。

## 修复后复验

每次修复后重新执行 `check` 与 `xcheck`，要求问题数均为零；若仍有残留，按问题类型逐条人工核对。

仓库含术语译名矩阵时，再执行一次 `termcheck`，确认矩阵与正文用词自洽。
